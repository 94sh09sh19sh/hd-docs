# 軟體需求規格書 5.4 對外揭露（0910 新增，對應新增任務一之 4）

上層文件：《[軟體需求規格書](../srs.md)》第 5 章

| 編號 | 需求描述 | 優先權 |
|---|---|---|
| FR-X01 | 對外報表產生功能：獨立模組，具備自己的權限控制，是資料離開院內的唯一合法管道。**1017 補**：分組多「依月份」；可勾「附基準」（寫出量測期間、方法、份數、背書人）；報表頁與取出的檔案都有圖，CSV 之外多一份可列印版，同樣要核准才取得；可對外的指標見補充說明 1017 | P1 |
| FR-X02 | 對外報表僅輸出聚合值；樣本數少於門檻（預設 5）的分組不呈現；禁止欄位（姓名、病歷號、床號、工作 ID、精確時間戳）於產生時即排除。**1017 補**：**互減算得回的分組也不呈現**——同一份裡有一組拿掉時，件數類指標連同次小的一組一起拿掉；與已核准的報表互減得出被拿掉的分組時整份不產生；都在產生階段做 | **P0**（只要 FR-X01 做，這條就必須同時做） |
| FR-X03 | 對外報表須經指定核准角色確認後方可取出 | P0 |
| FR-X04 | 每一次對外報表的產生與核准均寫入稽核軌跡：誰產生、給誰、包含哪些指標、核准者 | P0 |
| FR-X05 | 對外展示環境：獨立機器、獨立資料庫檔案、資料全為合成，與正式環境無任何連線 | P2 |

**設計說明**：對外揭露真正有說服力的素材是工程證據（架構、治理規範、測試手冊）與可操作的展示環境，這兩者本來就不含病人資料。成效數字（FR-X01～X04）是補充，不是主體。

**FR-M05、M06、M08～M13、FR-X01、X02、FR-S18 補充說明（1017）**：

分析、每一個資料的意義、圖表的選擇與示意圖、七題答覆寫在《[管理儀表板、獎勵制度與對外揭露的更新與修正](../../notes/management-rewards-disclosure-update.md)》；三者逐筆蒐集與展示了什麼在子文件《之一》。這裡只寫要求。

- **圖的共同規則**：一張圖回答一個問題；不用雙軸、圓餅、立體；資料用圖表色，**不用介面的四種語意色**；線尾標名稱、線型不同、柱頂寫數字，顏色不單獨說話；一天少於 5 件的點畫空心、不連線，期間超過 31 天改每週、超過 120 天改每月；只有「有基準、量的是同一件事、樣本夠」才畫基準線；每張圖可切回表格。自己畫，不引入圖表套件
- **不進儀表板**：「想起某個人」、狀態評估彙整與任何病人層級的資料、遊戲的分數與花了多久、回貼圖分護理師、判斷輔助提示的件數與採用率
- **到床邊的中位數**：手持裝置的開關關著時寫明「這段期間沒有到達時間」，不寫樣本不足
- **迭代 25 之後**：「確認」改叫「接手」並記定義變更；「事件記錄事後補寫」不算求助處置紀錄，求助處置紀錄另列
- **獎勵制度不畫圖**：個人數字畫成圖就是比較與排名；唯一的全單位數字「未指名的比例」用數字方塊
- **計分事件**：求助處置紀錄完成（臨床組求助的求助處置紀錄有簽核，歸處理者）、護理紀錄簽核（求助處置以外）、衛教審閱、跑馬燈內容審閱、追蹤事項完成，**一律歸指名的人**；沒有指名的不計分；名冊身分的事件照記，帳號核准前不計分，核准後還沒結算的期間照常計分、已結算的不重算。不算：回應速度、接手件數、回貼圖、收到的花、遊戲、判斷輔助的採用與否、病人的臨床結果
- **一個開關**：「獎勵制度（含處理者身分）」預設關閉，開啟要填核准依據；取代「獎勵計分」開關。關閉時已記下的保留、進行中的期間照樣可以結算
- **可以對外的指標**：迭代 19 的 9 個、平板覆蓋率、三種任務的完成率、求助類別（只給兩類）、處理結果（只給三類）、再求助比例、求助處置紀錄、遊戲使用率。**不可以**：工作量、追蹤事項、測驗依主題答對率、AI、SOP、院方資料抓取、平板連線、送花、小撇步、回貼圖；**獎勵、處理者、名冊、未指名比例一律不可以**
- **平板連線紀錄**（FR-S18）：只記平板、斷線的起訖、那時配著哪一次療程，不記病人；從上線那一天起記，之前的期間寫「還沒開始記」
