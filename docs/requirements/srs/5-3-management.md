# 軟體需求規格書 5.3 管理與營運（0910 新增，對應新增任務一之 1～3）

上層文件：《[軟體需求規格書](../srs.md)》第 5 章

本節全部為新增。設計原則見《[FDE 評估報告](../fde-assessment.md)》第五章，資料分級與存取限制見《[資料庫使用規範](../database-policy.md)》第 11 條。

| 編號 | 需求描述 | 優先權 | 資料級別 |
|---|---|---|---|
| FR-M01 | 護理師班表建立、檢視與匯入（支援手動建立與檔案匯入兩種方式） | P0 | L2 |
| FR-M02 | 當班床位分配：指定每位當班護理師負責的床位 | P0 | L2 |
| FR-M03 | 臨時調動：有人請假時，依技能標記、連續工時、近期負荷產生候補人選排序供護理長選擇 | P1 | L3 |
| FR-M04 | 勞動條件硬性檢查：連續工時、班距、單日時數上限違反時**擋下儲存**並說明違反哪一條，非僅提示 | **P0** | L2 |
| FR-M05 | 工作量實測儀表板：依既有稽核軌跡呈現各班次的求助件數、回應時間分布、尖峰時段。**1017 補**：各班有配平板的療程數與每 100 次療程的件數、急迫度、星期 × 鐘點、同一時間在等的最大值、文書與審閱件數；**每位當班護理師平均件數要用班表，跟著班表開關，班表關著不計算、不出現**；以圖呈現、可切回表格（補充說明 1017）。**1123 補**：倒數開著時加「還沒選的比例」與其結案結果的分布、開啟到點類別秒數的第 90 百分位（調倒數用）；全單位、每月，不做個人排名 | P1 | L2 |
| FR-M06 | 成效儀表板（L1）：單位聚合指標，供醫院管理層唯讀存取。**1017 補**：件數一律附「每 100 次有配平板的療程」；補平板覆蓋率、求助類別與處理結果、再求助比例、追蹤事項、三種任務的完成率、測驗依主題的答對率、求助處置紀錄、AI 的採用與退回、遊戲使用、院方資料與平板連線的可靠度；指標定義改了要記下並在走勢圖上標出；以圖呈現、可切回表格（補充說明 1017） | P1 | L1 |
| FR-M07 | 成效基準建檔：提供介面讓護理長輸入系統啟用前的人工量測結果，作為 FR-M06 的對照基準 | **P0** | L1 |
| FR-M08 | 獎勵指標定義：計分規則可於管理介面設定，設定內容對全體護理師公開可查。**1017 補**：計分事件**一律算給指名的處理者**（FR-M13），不得算給登入的帳號；預設規則改為求助處置紀錄完成、護理紀錄簽核（求助處置以外）、衛教審閱、跑馬燈內容審閱、追蹤事項完成，仍全部是草稿 | P1 | L2 |
| FR-M09 | 觀察期模式：獎勵指標可設為「只計算不計分」，用於上線初期驗證資料無系統性偏差。**1017 補**：每一期列出全單位「未指名」的比例；觀察期最早只能從「獎勵制度」開關開啟起算；計分期要至少結算過一個觀察期、至少一條已公告的規則才建得出（取代原本的「獎勵計分」開關） | P1 | L2 |
| FR-M10 | 個人自我檢視：每位護理師可查閱自己的計分明細與原始事件，並提出更正申請。**1017 補**：另列這一期沒有指名的事件（只有時間與種類），可以認領，認領就是「少算了一筆」的更正申請 | P1 | L3（限本人） |
| FR-M11 | L3 總開關：個人層級績效資料預設關閉，開啟與關閉均寫入稽核軌跡，且需記錄核准依據。**1017 補**：看別人的個人層級要這個開關**與**「獎勵制度」開關都開著 | **P0** | — |
| FR-M12 | 簡報模式：一頁式成效摘要（含基準對照與未達成事項），供會議與訪視使用。**1017 補**：數字方塊與兩張縮小的圖；未達成事項多「定義改過」「到床邊的開關關著」兩種；黑白列印讀得出來 | P2 | L1 |
| **FR-M13** | **處理者指名**：「獎勵制度」開關開著時，接手緊急通報的當下指名處理者——**名字本身就是「我接手」**，名單只列最近 12 小時接手過或被指名過的人（最多 6 位、依姓名筆畫），「其他人…」展開全部，**永遠有「先接手」**，之後在結案或簽核時補；簽核護理紀錄、審閱衛教與跑馬燈內容、完成追蹤事項確認時同樣指名。**不預選、不從登入帳號推、不用排班資料**；不加個人密碼。未註冊的用護理長建立的「名冊身分」（只有姓名與工作 ID、登不進去），或事後按「我不在名單上」登記、護理長確認；註冊核准後併進帳號。每一次指名寫稽核（當時登入的帳號、指名誰、時間、哪一步）。開關預設關閉，關著時沒有任何名字按鈕、「獎勵制度」頁不存在 | P1 | L3 |

**FR-M04 是本節唯一的 P0 硬性擋下項**：其餘功能給的是建議，護理長可以不採納；但系統不得產出違反勞動法規或醫院規定的班表。

**FR-M07 的時效性警告**：成效基準只能在系統正式啟用前取得。一旦紙本流程消失，就再也無從量測。這一項的實作優先權因此高於它的複雜度所暗示的順序。

**禁止事項（實作時的硬性界線）**：

- 不得建立「護理師×病人臨床結果」的關聯評分
- 不得產生公開的個人排名
- 不得將績效彙整結果回寫至臨床資料表
- 不得以回應速度作為自動派工的依據
- **1017**：不得以登入的帳號作為計分的歸屬（FR-M13）；不得以班表推定「這個時段是誰做的」
