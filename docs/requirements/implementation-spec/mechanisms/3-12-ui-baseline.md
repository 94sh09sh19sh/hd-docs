# 實作規格書 3.12 介面設計基準（0919 新增）

上層文件：《[實作規格書](../../implementation-spec.md)》第 3 章

**不是一次性修正。** 使用者於 2026-09-19 指示：介面重新設計之後，**日後所有介面工作都要依同一份基準做**。

| 文件 | 給誰 | 內容 |
|---|---|---|
| 《[介面設計基準](../../../notes/uiux-design-baseline.md)》 | 人 | 兩個族群的分析、設計原則、設計系統、驗收清單 |
| `.claude/skills/hd-uiux/` | agent | 同一份基準的可執行版：設計語彙的實際數值、檢查腳本、提交前流程 |

**Agent 行為規則**：

1. **動任何介面程式碼之前先讀 skill。** 這一條與「呼叫語言模型一律透過 `LlmProviderPort`」同級，不是建議
2. **新增畫面或元件時，找不到對應的設計語彙就先補進基準文件**，不要就地發明一個新的顏色或字級
3. **不得引入任何指向院外網域的執行期相依**——字型、圖示、樣式表、分析工具一律自帶（FR-S07，零院外連線盤點會擋下）
4. 外部設計系統只當參考，**不整套搬進來**

**兩個必須做到的結構性修正**（理由見基準文件 2.3 與 3.3）：

| 修正 | 硬性要求 |
|---|---|
| 病人端求助按鈕 | 改成整個應用程式共用的**固定底部區域**，內容區的可用高度先扣掉它。**「蓋住」必須在結構上不可能發生**，不是靠調整堆疊層級或猜卡片高度 |
| 護理端導覽列 | 主列最多 7 項，順序照一天的工作流程，其餘收進選單或關閉 |

**0926：基準的方向改為極簡，而且要先改基準、再改畫面。** 使用者於 2026-09-26 指示介面完全重新設計，四條依序套用（SRS 第 6 章「可用性（極簡）」）：

1. 能用圖示就不要用文字
2. 能用框線與顏色區隔功能，就不要用文字，也不要把不同功能混在一起
3. 不影響功能的字全部刪掉
4. 頁面能不上下捲動就不捲動

| 範圍 | 做什麼 |
|---|---|
| 病人端 | 全部重做。首頁只有基本資訊、輪播內容、緊急回報三區（FR-P14）；問卷與衛教依時點全螢幕出現（FR-P15） |
| 護理端簡易版 | **新做**，每次登入預設開啟。六項功能合併成一個以床位圖為中心的工作台，拖曳與顏色分區，一步完成（FR-N14～N16） |
| 護理端專業版 | **不更動**。即 0919 的完整介面，導覽版位規則（3.13）只適用於它 |

**Agent 行為規則（0926 追加）**：

5. **先改《介面設計基準》與 `.claude/skills/hd-uiux/` 兩份，再動任何畫面。** 極簡是方向變更，不是微調——照舊基準做新畫面，做完一定被自己的檢查腳本擋下，或更糟，沒被擋下
6. **圖示一律自帶**（不得引用院外圖示庫），每個圖示在基準裡登記一次意思，同一個圖示不得在兩處代表不同的事
7. **狀態色一律配圖示形狀**，顏色不能是唯一的訊號
8. 刪字的判準寫在 SRS 5.1：刪掉之後使用者還能不能完成那個動作。法規要求的標示（「僅供參考，非診斷結果」）不得刪
9. 拖曳一律有「點來源、點目的地」的替代做法；拖錯要能一步復原
