# 實作規格書 4.22 迭代 22：遊戲化之三——麻將連連看、狀態評估彙整、社工與醫師（1010 新增）

上層文件：《[實作規格書](../../implementation-spec.md)》第 4 章

> **2026-10-11 完成。** 手動測試在《[迭代 22 分冊](../../../testing/iteration-22.md)》（`af1`～`af30`）。兩個開關見 3.7，兩個角色見 3.1。沒有外部依賴；兩個開關照預設關著。開給病人之前要長者在病床的距離實際看過牌面（決定 5.3「看不看得清」）。

**1011 開發端的判斷**（使用者要推翻時改右欄那一處即可）：

| 判斷 | 理由 | 寫在哪 |
|---|---|---|
| 狀態評估彙整**讀的時候才算、不另建表**（規格書的兩個選項之一「沿用心情問卷的做法」） | 心情問卷的趨勢偏離本來就沒有資料表，是讀的時候由固定算式算；另存陳述會多一份會過期的拷貝。算式版本與計算時間隨回應一起給、寫進調閱的稽核 | `PatientDetailService.gameTrends`、`@hd/shared` 的 `evaluateMahjongTrends` |
| 一桌最多 **4 列 × 8 行**（遊戲化分析 7.2 寫「最多約 4 × 12」） | 4 × 12 只算了橫放；直放 800px 寬放 8 行剛好是 80px 一張。8 行在兩種方向都放得下、不捲動、不必轉向重排（重排會改變連線的路）。**1014 定固定橫放後，下週放寬**，難度五級跟著調 | `MAHJONG_LEVELS`、`--tile-min-w` |
| 難度五級：4×4、4×6 只要兩張一樣；4×4、4×6、4×8 要連線。**連續兩桌沒要提示加一級、連續兩桌每桌提示兩次以上退一級** | 「前幾桌兩張一樣就能消」至少要順利四桌才碰到連線；退回只看提示（點錯不算，點錯多半是手不穩，不是不會） | `MAHJONG_LEVEL_STREAK`、`MAHJONG_STRUGGLE_HINTS` |
| 一桌裡每一對是**不同的牌**（一張牌只有一個伴） | 長輩不必猜要配哪一張；也讓「倒著排」保證有解的做法簡單（不會因為配錯伴而卡住） | `dealMahjongBoard` |
| **保證有解**：倒著排（最後消的那一對先放，每一對都要在已放好的牌之間連得起來）；重排先試放回原位，試不出來就**每一對左右相鄰**（照任何順序都消得完） | 驗收第 2 條「任何一桌都不會卡死」要兩道保險；腳本以一千次發牌加窮舉、一千桌亂玩、兩百次刻意卡住的重排實際驗 | `placeSolvable`、`placeAdjacent` |
| **今日牌局**：同一班當天同一桌（種子只看日期與班別，**由伺服器依當下這一次療程決定**，平板不傳）；大小固定 4×6，**要不要連線照各人的級數** | 「同一桌」是牌與位置一樣；規則照各人程度，才不會讓還在前兩級的人第一次就碰到連線 | `mahjongDailySeed`、`MAHJONG_DAILY_SHAPE` |
| 今日牌局的人數句只在**完成那一桌之後**、要連線時出現；分母是這一班今天開過今日牌局的人；取消的療程不算 | 遊戲化決定 3.3；開了沒做完的人也是「沒做到」，所以才有反面的門檻 | `MahjongService.dailyPeers` |
| 每一步的操作紀錄由平板量（找到一對的時間、點的位置），後端只夾範圍不改值；**時間從開這一桌、上一對、提示、回到牌局起算**，提示框起來的那一對不算進「找一對的時間」 | 被任務打斷、睡著回來的那一段不該算成「找很久」；上限 10 分鐘 | `MahjongGame` 的 `mark`、`MAHJONG_ELAPSED_MAX_MS` |
| 點的位置以「牌心到角落」為 1000 的千分比記 | 平板大小、牌的大小不同時仍能比；鍵盤按下（沒有座標）記 null | `tapOffset` |
| 「遊戲的養分」：這一次療程**完成過至少一桌**（任何一桌） | 「獎勵的是做了」；開了沒完成不給，才不會變成點一下就拿 | `GardenRepository.nutrientsDone` |
| 「病人詳細資訊」是新的一頁（選單），**相關開關都關著時整頁不存在**；送花那一格留在病人趨勢 | 九個全關時護理端要與 17.7 一樣（4.4）；送花的回覆（「謝謝你的花」）是寫入，社工、醫師不能做，搬過來反而要再擋 | `NAV_ITEM_DEFINITIONS` 的 `anyFeatureFlags` |
| 病人詳細資訊**不預先帶第一位病人**，選了才調閱；病人清單本身不寫稽核 | 每一次調閱都寫稽核，不該替使用者調閱沒要看的人 | `PatientDetailPage` |
| 「差距達設定幅度」只在句尾多一行灰字，**不用紅色或警示樣式** | 附錄 C.7「不自動觸發任何動作」；那一行是事實（差了多少），不是結論 | `PatientDetailPage`、`GAME_TREND_CHANGE_*` |
| 白板自己畫藍框（來源那一張是空白牌） | 長輩看到空白牌會以為缺了圖；台灣的白板多半是藍框 | 牌面目錄的 `SOURCE.md` 第 5 點 |
| 消掉的那一對 0.3 秒淡出與連線是病人端**第一個點擊後的動畫** | 遊戲化分析 7.2、介面設計基準 4.4 的遊戲例外；減少動態效果時元件不畫、樣式也拿掉 | 介面設計基準 2.8、4.4 |

**Schema 變更（實作結果）**：沒有新表。`game_events` 加 12 個可為空的欄位（第幾桌、今日牌局、兩張牌的格子、哪一種牌、找到一對的時間、兩次點的位置、是不是提示的那一對、完成了這一桌、這一步之後重排、級數）與一個索引；麻將的存檔沿用 `game_saves`（`game_code` 多 `MAHJONG`）。角色是 `nurses.role` 的兩個新值（字串，合法值在 `@hd/shared`）。遷移 `20261013090000_iteration22_mahjong_trends`，只做加法，`check:migration` 無發現。後端路由 197 → 203 條（平板 3、病人詳細資訊 3）。

**驗收現況（1011）**：`verify:iteration22`（新增，12 步，不需要後端；每一級一千次發牌加窮舉、一千桌亂玩、陳述逐句比對 27 個字詞實際跑）與 `verify:iteration22:api`（新增，8 步；30 桌合成的操作紀錄以資料庫直接寫入、結束時刪掉）全部通過；`verify:acceptance`、`verify:iteration3`、`4`、`6`、`9`、`17:api`、`19:api`、`20:api`、`21:api` 對著後端通過，`verify:iteration8`、`11`、`12`、`14`、`14-1`～`14-5`、`15`、`16`、`17`、`17-1`、`17-2`、`17-4`～`17-8`、`18`、`18-1`、`19`、`20`、`21`、`check:all` 全綠，其中 `verify:iteration9:api`、`20`、`20:api`、`21` 依 1.1 第十五次改寫。另修 `check:egress` 的 W3C 命名空間例外（結尾多了斜線，從來沒對上；牌面的 SVG 檔第一次帶進 `xmlns` 才發現）。以無頭 Chrome 在 1280×800 與 800×1280 走過一輪病人端（遊戲選單、開一桌、選起來、提示、4×8 一桌、一路消到「完成了」），沒有捲軸、求助區位置不變、4×8 直放一張剛好 80×104px；護理端以社工帳號與護理長帳號看過病人詳細資訊（1366×768）。

**後端回歸的環境**：開發機原本那支後端（上一輪留下、佔著開發用資料庫）這次沒有停，回歸是對著另一支以新程式啟動的後端（3022 埠）與開發用資料庫的副本跑的；兩邊程式只差這一次的改動。

**沒有驗的**：兩個開關全關時的截圖比對（驗收第 1 條；腳本逐一確認入口都掛在開關後面、端點與導覽都擋下）；長者在床上看牌面「看不看得清」「萬字改深棕接不接受」（決定 5.3、遊戲化分析第 11 節）；真的在兩台實體平板上同一班開今日牌局；實機拔網路再接上。

**目標**：狀態評估資料最乾淨的一款，順便把遊戲資料到護理端的管線做起來。依據是遊戲化決定 5.1 的階段 3、5.3、3.4。

**Schema 變更（只做加法）**：`game_events` 沿用並補麻將需要的數值欄位；`patient_trend_statements`（病人、指標代號、期間、陳述文字、算式版本、計算時間）或沿用心情問卷趨勢偏離的同一張表（開工時依現有程式決定，擇一）；角色常數加兩個。

**驗收標準**：

1. 開關 6、7 關閉時與迭代 17.7 一模一樣（開關 7 關閉時操作紀錄照樣寫入）
2. 任何一桌都不會卡死；連續一千次隨機發牌都可解（自動測試）
3. 畫面上沒有紅色；沒有計時、沒有級數、沒有花了多久
4. 狀態評估的每一句都是「比自己過去的中位數多／少多少」的事實陳述，**逐句檢查沒有任何認知或情緒的結論字眼**；前 10 桌不產生任何陳述
5. 社工、醫師登入只看得到病人詳細資訊與狀態評估彙整；所有寫入端點擋下；每一次調閱在稽核軌跡
6. 牌面檔案旁有來源網址、commit、授權全文；SVG 裡沒有腳本、事件屬性與外部參照
