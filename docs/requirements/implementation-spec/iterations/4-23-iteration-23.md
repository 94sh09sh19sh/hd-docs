> **23.1 開發端的判斷**（詳見子文件與切分文件第 2 節）：選項是大字按鈕、**不配圖**（下表工作第 1 列的「三個圖文選項」改讀成「一張大圖配三個字的選項」——配圖就變成看圖配對）；起始先上 60 張（開開關的門檻），遊戲化決定 5.2 的「約 200 張」改成開開關後每季一包、第二年過 200；飲食主題只畫器具、不畫食物（透析病人的鉀、磷與水分限制）；圖是程式產生的向量圖，白名單比小花園多 `polygon`、`polyline`、`line` 與同檔的漸層。

> **2026-10-11 迭代 23 完成（23.3）。** 手動測試在《[迭代 23 分冊](../../../testing/iteration-23.md)》（`ag1`～`ag30`）。開關見 3.7。沒有外部依賴；開關照預設關著。開給病人之前要社工看主題與避開的題材、護理部看一句說明、長者在病床上看圖認不認得（子文件第 10 節）。

**1011 23.3 開發端的判斷**（使用者要推翻時改右欄那一處即可）：

| 判斷 | 理由 | 寫在哪 |
|---|---|---|
| 圖卡是**四張表**：`album_cards`、每一版 `album_card_versions`、選項 `album_card_options`、作答 `album_responses`（規格書列兩張） | 3.14 第 3 條要「改動即產生新版本、每一份作答記它當時的版本」，版本要還原得出當時的字才有用；選項不能用 JSON 欄位（《資料庫使用規範》6.1 第 2 條）。題庫、問卷也是同一種拆法 | schema、資料字典第二十六節 |
| **版本是一張一張的**，不是整份題庫一個版本 | 圖卡彼此獨立；改一張的說明不該讓另外 59 張也跳一版 | `AlbumService.updateCard` |
| 預設圖卡**只補資料表裡還沒有的代號**，已經有的一律不碰 | 3.14 第 5 條「首次啟動寫入、之後以資料表為準」；每一季新加的圖卡照同一份常數往下加，下一次啟動自動補進來，護理端改過的字、下架的不會被蓋回去 | `AlbumService.onApplicationBootstrap` |
| 平板拿著**舊版**送來：照收，記下它看的是第幾版（題庫是擋下） | 選項代號建立後不改、改的只有字，答案用代號比對，拿舊版的字解讀不會對錯；擋下等於把病人剛剛的回憶丟掉。對錯（`correct`）照收到時的那一版算，只進紀錄不顯示 | `AlbumService.submitEvents` |
| **下架隨時可以**，就算因此不到 60 張；開關照開著 | 社工覺得會讓人難過的圖卡要能馬上拿掉，不能被門檻卡住；關掉之後要補到 60 張才開得回來（開關中心寫出原因） | `updateCard`、開關的開啟條件 |
| 出卡**沒有亂數**：同一份紀錄、同一份圖卡排出來一樣 | 平板斷線時自己排、連線時伺服器排，兩邊要一樣；同一班今天看的是同幾張，「共同記憶」的人數句才湊得起來 | `@hd/shared` 的 `pickAlbumRound` |
| 每看完一張是一步，**這一次的幾張隨每一步一起送**；第一張的那一步開這一次 | 換一台平板也接得起來（存檔裡有這一次、看到第幾張）；看到一半的那一張不算一步，下次從那一張接著看 | `applyAlbumStep`、`AlbumStep` |
| 這一次還沒看完的幾張，**下架了也照樣給平板** | 病人已經翻開的那一次要看得完，不能看到一半那一張不見了 | `DeviceAlbumState.roundCards` |
| 相簿的序號與 clientId 在 `album_responses`，**不寫 `game_events`** | 每一步就是一張的作答，另寫一份是兩份同樣的紀錄；存檔照樣用 `game_saves`（`game_code = ALBUM`） | schema |
| 共同記憶的分母是**這一班今天看過這一張（沒跳過）的其他病人**，人數也只數其他病人 | 跳過的人沒有回答，不算「沒說有」；問的人自己還沒送出（翻開時就問），算進去反而會因為送出的先後而變 | `AlbumRepository.peerCounts` |
| 人數句在**翻開答案之後**才問、才出現 | 先看到「5 個人家裡也有」會影響自己的回答 | 病人端 `AlbumGame` |
| 翻開之後答案那一個用**一般色的粗框**，不打勾、不寫「答對」；「你家以前有沒有？」翻開後不列選項 | 子文件第 5 節「答錯時」；沒有對錯的題目框起病人選的那一個，看起來會像「這個才對」 | 病人端 `AlbumGame`、介面設計基準 2.9 |
| 護理端「可以聊的話題」一張表：主題、看過幾張、說過家裡有的、用過的、想起某個人的；**沒有答對率** | 「當聊天話題用，不是作業」；對錯只進紀錄 | 護理端 `PatientDetailPage` |
| 圖卡管理只有**看與改**，不能新增 | 新的圖卡要有圖，圖由開發端畫好隨版本更新加進來（子文件第 9 節） | 護理端 `SystemContentPanel` |
| AI 起草說明**不做，之後也不做**（1011 使用者決定） | 起草出來要護理師一張一張核准，等於多一份工作；起始 60 張與之後每一季加的圖卡，說明全由開發端寫好、經用語把關後隨版本帶入；護理長在系統管理改說明的功能照樣保留（1011 確認） | 子文件第 5 節 |
| 字型子集重做時**不掃用語把關的簡體字對照表** | 那份表有約 5,900 個簡體字，掃進來字檔多五百多 KB；那些字不會畫在畫面上 | `scripts/subset-font.py` |

**Schema 變更（實作結果）**：四張新表（`album_cards`、`album_card_versions`、`album_card_options`、`album_responses`），不動任何既有的表；相簿的存檔沿用 `game_saves`（`game_code` 多 `ALBUM`）。`album_responses` 的三個貼紙、跳過、看的是第幾版、第幾次第幾張、看完一次、選了哪一個、有沒有選到答案都是正規欄位；**沒有任何護理師欄位**。遷移 `20261014090000_iteration23_memory_album`，只做加法，`check:migration` 無發現。後端路由 203 → 209 條（平板 3、圖卡管理 2、病人詳細資訊 1）。

**驗收現況（1011）**：`verify:iteration23`（新增，12 步，不需要後端；出卡順序實際跑 12 次與跳過、想起某個人的邊界，快照的格式與大小、門檻的六種組合）與 `verify:iteration23:api`（新增，8 步）全部通過，`:api` 連跑兩次都過（改過的圖卡結束時以資料庫改回）；`verify:iteration23-1`、`23-2` 照樣通過。`verify:acceptance`、`verify:iteration3`、`4`、`6`、`9`、`17:api`、`19:api`、`20:api`、`21:api`、`22:api` 對著後端通過，`verify:iteration8`、`11`、`12`、`14`、`14-1`～`14-5`、`15`、`16`、`17`、`17-1`、`17-2`、`17-4`～`17-8`、`18`、`18-1`、`19`、`20`、`21`、`22`、`check:all` 全綠，其中 `verify:iteration20`、`20:api`、`21`、`22` 依 1.1 第十六次改寫。兩端的正式建置照樣通過。以無頭 Chrome 在 1280×800 與 800×1280 走過一輪病人端（遊戲選單、相簿封面、題目、翻開、點貼紙、跳過、看完回封面），沒有捲軸、求助區位置不變、可點的最小 64px；護理端以護理長帳號看過病人詳細資訊與「記憶相簿的圖卡」（1366×768）。

**後端回歸的環境**：與迭代 22 同一個做法——開發機原本那支後端（佔著開發用資料庫）沒有停，回歸是對著另一支以新程式啟動的後端（3023 埠）與開發用資料庫的副本（`hd-dev-i23.db`，已套迭代 22、23 兩份遷移）跑的。**開發用資料庫本身還沒有套迭代 22、23 的遷移**，下一次重新啟動開發機的後端前要先 `npm run prisma:deploy -w @hd/api`。

**沒有驗的**：開關全關時的截圖比對（驗收第 1 條；腳本逐一確認入口都掛在開關後面、端點與導覽都擋下）；社工看主題與避開的題材、護理部看一句說明、長者在床上看圖「認不認得」「像不像給小孩玩的」（子文件第 10 節；驗收第 4 條的「逐張檢查」是開發端做的那一次）；真的在兩台實體平板上同一班看同一張；實機拔網路再接上。


**目標**：心理支援最強的一款，讓長輩當「懂的人」。依據是遊戲化決定 5.1 的階段 4、5.2。

**前置（開工第一件事）**：照遊戲化決定 5.2 寫《透析中的遊戲化之三：記憶相簿的主題》子文件（主題分類、每類畫哪些物件、要避開的題材與「可能讓人難過」的判斷準則、選項與說明文字的寫法、第一年之後每一季加什麼），再依它由 AI 畫起始的圖卡（寫實不幼稚、不畫真人、只畫物件不畫商標）。

**Schema 變更（只做加法）**：`album_cards`（代號、主題、圖檔、題型、選項、說明、上架狀態、版本）、`album_responses`（病人、療程、圖卡、題目作答、貼紙、是否跳過、時間）。

**起始的量**：決定 5.2 寫「起始約 200 張」。**開給試辦那一班的最低門檻**是四週不重複：每次 5 張 × 每週 3 次 × 4 週 = 60 張，而且每個主題都有；不到 60 張不開開關 8。

**驗收標準**：

1. 開關 8 關閉時與迭代 17.7 一模一樣
2. 病人端沒有任何「錯」的顯示；沒有打字的地方；每張都跳得過
3. 「想起某個人」在任何彙總、任何護理端統計數字裡都不出現（護理端只在那位病人的回應主題裡看得到）
4. 圖卡沒有可辨識的真人、沒有商標；避開題材照子文件逐張檢查過
5. 共同記憶的人數句照最低人數門檻；湊不到就不顯示
