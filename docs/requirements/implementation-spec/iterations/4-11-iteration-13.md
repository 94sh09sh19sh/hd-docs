> **與原定計畫不同、或規格沒寫到而補上的四處**：
>
> 1. **`HttpLlmProvider` 改了一處**（見 3.4 的 0927 補）：`LLM_MODEL_ID` 可以留空，否則驗收 3 做不到。
> 2. **`config.yaml` 改檔即生效，改壞了不沿用舊設定。** 閘道每個請求比對檔案的修改時間；改壞時回「設定有誤」、`/health` 不通過，後端健康檢查跟著不通過，AI 總開關開不起來——院內範本因此可以把位址與模型留空，閘道照樣起得來，只是明確說出還缺什麼。
> 3. **`/v1/models` 會去探推論端點**（只讀模型清單，不載入、不管理）。後端的健康檢查只問這一個端點，閘道若只照抄設定檔， SSH 轉送斷了或模型被移走時健康檢查照樣通過。
> 4. **映像檔裡裝了 `curl`**，因為規範要求在容器內以 `curl` 確認連線；**明寫關閉 LangSmith 追蹤**，它一開就把呼叫內容送往院外。

**目標**：照實驗室規範串接實驗室 GPU 伺服器，讓 AI 功能以真的模型跑一次；並把架構做成日後換成正式 GPU API 只改設定檔。

**Schema 變更**：無。`ai_invocations` 已記錄供應者與模型，閘道實際使用的模型名稱照實回傳。

**驗收標準**：

1. 以合成病人跑通至少一項 AI 草擬（護理記錄或衛教），`ai_invocations` 記下的模型是實驗室上的實際模型
2. 帶真實病人標記的請求在 `lab` 下被擋下並記錄（沿用 FR-S06 驗收）
3. **只改 `config.yaml` 就換得了模型**（實驗室上換成另一個可用模型即可驗），後端不重建
4. 把 `config.yaml` 的 `provider` 在規範的兩種方法之間切換，兩種都跑得通
5. 閘道停掉時 AI 功能顯示暫時無法使用，主線功能完全正常（DEP-24）
6. repo 與文件裡搜不到實驗室的位址、連接埠、帳號與密碼
7. 實驗室個人資料夾以外沒有留下任何本專案的檔案

**外部依賴**：Q-08（實驗室 API，**規範已取得，剩使用期限與可用模型的繁中表現**）。Q-07（正式 GPU API）不擋本迭代。
