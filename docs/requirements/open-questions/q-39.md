# 尚待確認事項清冊 Q-39 研究與後續計畫的資料取出：核准流程與取出之後的去處

上層文件：《[尚待確認事項清冊](../open-questions.md)》第 3 章

| | |
|---|---|
| **問誰** | 資訊室、法務（研究承辦人一起） |
| **急迫度** | B |
| **卡住** | 對真實資料執行取出（SRS FR-S19、《資料庫使用規範》第 20 條）。迭代 28 的實作不受阻，全部用合成資料驗收 |
| **狀態** | 待提出（1026 新增） |

**背景**

- 院方要求系統蒐集的資訊日後要全部取得出來，供後續計畫做資料分析與模型訓練；使用者 1026 定：現在就寫好取法、照文件手動做得完不靠模型、只能在院內主機上操作
- 規劃（《[蒐集資料的完整取出](../../notes/data-extraction-plan.md)》）：只讀的取出指令、三種範圍、完整與假名化兩級、取出紀錄進稽核；取出檔只寫到主機的匯出目錄
- 系統做得到「取得出來、取得完整、留下紀錄」；**誰可以取、取了能去哪裡，是院方的決定**

**不確認的後果**

指令做好了也不能對真實資料執行；或執行了卻沒有核准依據，取出紀錄上的「核准文號」欄只能空著。到期刪除機制若先上線，刪掉的資料就再也取不出來（第 3 題）。

**具體要問的**

| # | 問句 |
|---|---|
| 1 | 研究與模型訓練用的取出，院方的核准流程是什麼、誰簽、要不要倫理審查文號？ |
| 2 | 完整級的取出可不可以離開主機、搬到院內分析機器？可以的話是哪一台、誰管？ |
| 3 | 留存期限到期刪除前，要不要先封存一份研究用取出（規範 8.2 與第 20 條的衝突；與 Q-05 一起答）？ |
| 4 | 假名化級預設移除自由文字欄（護理紀錄內文、AI 提示與輸出），院方同不同意？ |
| 5 | 匯出檔在主機上可以留多久、誰負責刪？ |
| 6 | 後續計畫若要把資料帶出院（例如交給合作學校訓練模型），院方要走的去識別化流程由誰做？ |

**現況／暫代做法**

迭代 28 照規劃做：用途、核准文號、經手人缺一不跑，系統不驗文號真偽；手冊寫明沒有院方核准不得執行。答覆之前：取出只在開發機對合成資料做；到期刪除照規範 8.2 只標記不刪；假名化級照預設移除自由文字欄。
