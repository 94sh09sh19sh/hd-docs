# 尚待確認事項清冊 Q-31 介面改版的現場試用人選

上層文件：《[尚待確認事項清冊](../open-questions.md)》第 4 章

| | |
|---|---|
| **問誰** | 護理長 |
| **急迫度** | D |
| **卡住** | 介面設計改動的驗收 |
| **狀態** | 待提出（0919 新增） |

**背景**

0919 起兩端介面全面重新設計，依據是《[介面設計基準](../../notes/uiux-design-baseline.md)》裡的族群分析。**但族群分析是開發端寫的，它需要被現場的人打臉過至少一次才算數。**

**不確認的後果**

介面在開發機上看起來好看，到了現場才發現護理師的操作順序跟設計假設不同、或病人根本看不清楚某個字級。這種問題改起來不貴，但**發現得晚會讓首波試用的使用者留下壞印象**，而第一印象很難修。

**具體要問的**

1. 能不能指定一到兩位護理師，在首波試用前先看過新介面並試著操作？
2. 能不能找一位真實病人（或家屬）在平板上試按一次求助與問卷？**這一題比上一題重要**——護理師會替病人猜，猜不準
3. 護理師一天之中真正會用到的功能有哪些？現在放在導覽列上的那幾個對不對？
4. 治療區的光線、病人的姿勢（多半是躺著、單手）有沒有開發端沒想到的限制？
5. 護理站電腦的螢幕尺寸與解析度為何？從護理師站的位置看得清楚嗎？
6. （1005 新增）能不能請三位左右的病人，在病床上看一次跑馬燈，回答「看得清嗎、跟得上嗎、看了累不累或煩不煩」？**跑馬燈開啟前一定要做**（SRS FR-P10）：速度是開發端訂的預設值，只有長者本人說得準
7. （1010 新增）緊急回報的圖示改成畫出症狀本身（迭代 17.8）：能不能請病人**把字遮起來**看一次，說出每個圖示是什麼症狀？說不出來的那幾個再改
8. （1010 新增）遊戲（透析小花園、麻將連連看、記憶相簿）開給病人前，能不能請幾位長者在病床上實際玩一次，回答「看得清嗎、點得到嗎、玩了累不累或煩不煩、會不會覺得是給小孩玩的」？任一題有人說不行就改了再試（遊戲化分析 12.2）
9. （1015 新增）花園與相簿擴充（迭代 24）的新內容，跟第 8 題同一批看：**新的 24 種花、24 種小訪客、60 張圖卡**請社工看主題與要避開的題材、護理部看每一句說明、長者在病床上看圖認不認得；另請社工判斷兩件事——**貓、狗要不要收進訪客**（想起過世寵物的風險，跟「家裡也養過」的親切感哪個大），以及**粉紅康乃馨會不會讓母親已過世的人難過**（《[透析中的遊戲化之四](../../notes/dialysis-gamification-expansion.md)》第 9 節）

**現況／暫代做法**

導覽列的版位可在系統設定調整（FR-S11），因此第 3 題答錯的代價很低——改的是設定，不是程式。**第 2、4、6 題沒有暫代做法**，只能實際看。第 6 題在院內還沒機會之前，開發端先找同齡的人試看一輪，但那只能當起點，不能取代病人。

**1005 迭代 16 已做完跑馬燈**，「跑馬燈」功能開關因此**預設關閉**、等第 6 題的結果才開。試看的步驟與記錄表在《[迭代 16 分冊](../../testing/iteration-16.md)》§16.10：速度、開頭靜止、兩則間隔都是營運參數，有人說不行就當場調慢重看；最後採用的速度連同試看結果寫在那個參數的修改理由裡（只記代號與年齡層，不記姓名）。
