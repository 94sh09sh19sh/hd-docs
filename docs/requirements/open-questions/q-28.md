# 尚待確認事項清冊 Q-28 輪播第二層的衛教與公告內容

上層文件：《[尚待確認事項清冊](../open-questions.md)》第 5 章

| | |
|---|---|
| **問誰** | 護理部 |
| **急迫度** | D |
| **卡住** | 迭代 6 第二層的開關。第一、三層不受影響。**1005 起**：跑馬燈的開關 |
| **狀態** | **部分已回覆（1007）**：第 3 題所有護理師都可以核准；剩第 4 題多語言。0912 新增；**1005 改問法**：見本節末；**1005 迭代 17 已實作** |

**背景**

閒置輪播的第二層是「靜態衛教與中心公告」——中心自己要放的內容，不是系統既有資料，也不是院方給的數值。管理介面已完成（護理端「輪播內容」頁可新增、排序、設定上下架時間），但**內容本身只有護理部寫得出來**。

**不確認的後果**

第二層開關開不起來（開啟條件就是「至少有一則在架上的內容」），輪播只播第一、三層。這不影響上線，只是少了一個現成的衛教管道。

**具體要問的**

| # | 問句 |
|---|---|
| 1 | 中心現在有哪些貼在牆上或發給病人的衛教單張？可以直接改寫成輪播卡片嗎？ |
| 2 | 一張卡片只放得下一句話與一段說明，優先放哪幾則？ |
| 3 | 公告（例如消毒日、休診日）由誰負責上架與下架？需不需要排定期限？ |
| 4 | 需不需要多語言版本？若要，誰提供譯文？ |

**現況／暫代做法**

**沒有暫代內容，這是刻意的**——開發端自己編的衛教文字會直接被病人看到，那不是可以「先擺著之後再改」的東西。開關的開啟條件因此直接判定有沒有在架上的內容：沒有內容就開不起來，不會出現空白的輪播。

**1005 新版需求**：輪播第二層改為跑馬燈，以「標題：內容」整則慢速跑過、不必點開；**標題與內容由 AI 生成、護理師只核准**，拿掉「一句話」（SRS FR-P10、FR-N17）。「開發端自己編的文字會直接被病人看到」那個顧慮，改由**核准**這一道把關：沒有核准的草稿病人端收不到。上面四題因此改成：

| # | 1005 起 |
|---|---|
| 1 | 現有的衛教單張可以當 AI 的參考來源，但不再是必要條件；衛教主題以附錄 C.6（院方已授權）為範圍 |
| 2 | **作廢**：沒有「一句話」了 |
| 3 | 改問：**誰有權核准跑馬燈的內容**？所有護理師，還是只有護理長？公告的事由由誰輸入？ **1007 答覆：所有護理師都可以** |
| 4 | 照舊 |

**1005 迭代 17 實作後的暫代做法**（實作規格書 4.15）：

- **誰能核准（第 3 題）**：~~暫代為~~ **有「跑馬燈內容」權限的人都能核准**——與迭代 6 起上架內容的權限相同（一般護理師以上）。 **1007 答覆所有護理師都可以，暫代就是答案，不必改程式**；公告的事由用的也是同一個權限。每一次核准都在稽核軌跡記下是誰。
- **院內推論端點就位之前（Q-07）**：衛教草稿隨版本帶入（七個主題各兩則），首次啟動時是「待核准」；公告由護理師在專業版寫，一樣要核准。 **這一版的草稿不是實驗室模型寫的**：實驗室的連線資訊不在開發機上，第一版由開發端所用的模型依相同的主題與寫作要求生成，生成的模型寫在資料檔與每一則的匯入稽核裡；實驗室可以連的時候以 `npm run marquee:bundle` 重新生成。
- 跑馬燈開關仍預設關閉，開啟條件仍是長者試看速度（Q-31 第 6 題），不因為有了內容而改變。
