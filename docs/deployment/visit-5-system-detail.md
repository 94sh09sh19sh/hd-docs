### SY-03 防毒排除

想知道防毒有沒有在跑（系統管理員身分）：

```powershell
Get-CimInstance -Namespace root/SecurityCenter2 -ClassName AntivirusProduct | Select-Object displayName, @{n='hex';e={'{0:X6}' -f $_.productState}}
```

`hex` 中間兩碼 `10` 或 `11` 是正在運作，`00`、`01` 是裝了沒在跑。1001 是 `061100`（Defender 正在運作）。1029 看排除清單是空的。

| 症狀 | 處置 |
|---|---|
| `Must be an administrator to view exclusions` | 不是系統管理員身分，重開一個（開始 → 打 `powershell` → `Ctrl+Shift+Enter`） |
| `Invalid namespace` | 這台是 Windows Server，改打 `Get-MpComputerStatus`，看 `AMRunningMode`、`AntivirusEnabled` |
| 資訊室當天加不了 | **照樣往下，讀檔照開**（1116 改）；不加也能跑，出現下表的現象再加。交接紙「防毒」那一列寫「未加」，現象照抄下表 |

**為什麼 1116 起不擋讀檔**（舊第二十冊寫的是「加不了就不啟用讀檔」、交接紙寫「沒加之前不得輸入真實病人資料」，1116 改掉）：

- 資料庫放在 Docker 的具名資料卷裡，實體是 Docker 資料夾裡的一個虛擬磁碟檔（`ext4.vhdx`）。Defender 的即時掃描只看得到這一整個檔，看不到裡面的 `hd.db`、`-wal`、`-shm`。所以舊冊（《[第一次進院（0922）· 部署本系統之一：進院當天詳細版](visit-1-system-onsite.md)》H-14、《[現場疑難排解](ref-troubleshooting.md)》X-14）講的「SQLite 被掃描鎖住、間歇性 `database is locked`」，在容器路線不會因為防毒發生
- 這是照架構推的，**沒有在開著即時掃描的主機上實測過**
- Defender 看得到的是主機上本系統的資料夾：`config`、`backups`、`export`、第一階段的 `C:\API_Fetch\IDH_interface`，以及換版時的 `repo`

**沒排除時可能看到的現象**（交接紙照抄）：

| 在哪 | 會看到 | 傷不傷資料 | 怎麼確認 |
|---|---|---|---|
| Docker 資料夾 | 整體變慢，資訊室排的全機掃描時段特別明顯；開機後 Docker Desktop 比平常久才起來 | 不傷 | 問資訊室全機掃描排在幾點，對時間 |
| `backups` | 「系統管理 → 資料庫與備份」的備份歷程出現失敗，「最近一次成功備份」不是今天；極少數是備份檔被判成可疑、被隔離而不見 | 資料庫不受影響，但那一天沒有可還原的備份 | Windows 安全性 → 病毒與威脅防護 → 保護歷程記錄，看有沒有那個檔 |
| `C:\API_Fetch\IDH_interface` | 抓取腳本寫檔時被佔用，「系統管理 → 院方資料同步」卡停在舊時間 | 不會寫壞，只是沒更新 | 抓取腳本那邊的紀錄（《[院方 API 抓取腳本的維運](ref-fetch-script.md)》） |
| `repo`（換版時） | `git checkout` 或建置偶爾說檔案被佔用 | 不傷 | 重打一次就過 |

**出現任何一種**：請資訊室把 Docker 資料夾加進排除清單；是備份那一列，再加 `backups`。只排這兩個資料夾，不排整顆磁碟、不排 `node.exe`。看到 `database is locked` 不要先怪防毒：先看是不是換版、還原或資料取出的一次性容器還在跑（`docker compose --env-file $cfg ps -a`）。

### SY-11 第一輪怎麼驗

- 床號為什麼有 `1A`～`3D` 與 `99`（1029 探測）：院方資料的床號有三種寫法。`A1`～`E9` 是大多數；`1A`～`3D` 共 12 床，跟 `A1` 那些是**不同的床**、不是倒過來寫，成大現有系統的床位圖也沒有它們；`99` **不是一張床**，一天約 10 次透析、同一時間好幾位病人，斗六分院的程式叫它「暫存床」。「院方床位轉床號的方式」維持 `0`（原樣），清單裡看到 `1A`、`99` 是預期的；**不要改成 `1`**，`1A` 會被轉成 `A1`，兩床的病人併成一床。這幾種是哪裡的床、什麼情況填 `99`，現場問學長與護理長（《[上線準備清單](visit-5-system-prep.md)》A-07、第 3 節）。🧪 模擬資料只有字母開頭的床號
- 🏥 清單最前面有 `01`～`15`（1116 現場看到）：那是 1005 以前的版本在全新資料庫自動建的 15 床預設床位（院內資料庫是 1001 建的），不是院方的床。這一趟**不要拿掉**，交接紙寫「`01`～`15` 是舊的預設床位，接上院方資料後由護理長在『床位清單』拿掉」；拿掉只是停用、不刪紀錄，有病人或平板在那一床時拿不掉。院方的床接在後面：`2A`～`3D`、`99`、`A1`～`E9`（沒有 4 號床）、`I1`、`I2`，跟學長答的一致；`1A`～`1D` 這幾床今天沒人透析就不會出現，正常
- 即時總覽要對的是讀檔檢查的「姓名欄含「〇」：N 列（M 位病人）」的 M，不是「透析次數（依病歷號＋開始時間分組）：K 次」：同一位病人預排與實際開始時間不同會算成兩次，所以 K 比 M 多幾次正常。即時總覽隔一輪多 1、2 位也正常（剛來的病人）。1116 現場：讀檔檢查 89 位病人、95 次；即時總覽 89，下一輪 90。數字對得上、格式不符 0 就算檔案與系統一致；護理師很忙時「問現在在洗幾床」可以不問，紀錄寫「未問，以讀檔檢查與即時總覽一致、SY-12 首波那一床對上代替」
- 即時總覽的「療程進行中」是 0：那一格算的是有平板綁定的療程，不是讀檔的「透析中」；還沒綁平板就是 0，正常（1116 現場）
- 病人數差很多：讀檔檢查算的是整個月份檔，卡片同步的是今天；差幾位正常，差一半以上就抄下兩個數字，停用也可以（B 級）
- 稽核軌跡有「院方資料格式不符，該次透析未寫入」（整次透析被擋下）：抄原因（不含病歷號）。多半是床號或療程欄位對不上，回來看
- 🧪 模擬每一輪那 1 筆格式不符是模擬辛：模擬資料故意放的壞資料，每列少兩欄；所以簡易版看不到模擬辛
- 簡易版只顯示平板編號與病人姓名，看不到床號，床號一律看「床位清單」卡（1116 模擬實測）
- 稽核軌跡很多筆「院方 API：整批未寫入，共 1 處問題。第 1 列 value：目標脫水量超出可接受的範圍 0～8000 mL」（1116 現場看到）：**不擋、不停用**。被擋的只有那位病人那一次的四個數值（理想體重、目標脫水量、結束體重、實際脫水量），療程、床位、生命徵象照常寫；每 3 分鐘重讀一次就再記一筆，所以很多筆。查是負的還是太大（只印次數與最小最大，不印病人）：

```powershell
docker compose --env-file $cfg exec -T api node -e "const f=require('./apps/api/dist/modules/hospital-sync/hospital-files.js'),p=require('./apps/api/dist/modules/hospital-sync/hospital-api.format.js');(async()=>{const d=await f.readDialysisDay(process.env.HOSPITAL_DIALYSIS_LIST_DIR,p.hospitalLocalDate(new Date()));const v=p.validateRows(f.mergeDialysisSegments(d.segments)).dialyses.map(x=>x.ufTargetMl).filter(x=>x!==null);console.log('dialyses',v.length,'negative',v.filter(x=>x<0).length,'over8000',v.filter(x=>x>8000).length,'min',Math.min(...v),'max',Math.max(...v))})()"
```

- 上面那一行：`dialyses` 是今天有目標脫水量的透析次數，`negative`、`over8000` 是超出範圍的次數，`min`、`max` 單位 mL。整行抄進紀錄，回開發端看要不要改範圍；首波那一位若被擋，「本次透析」面板先不開。**1116 現場結果**：96 次、沒有負的、3 次超過 8000、最小 500、最大 74600——74.6 公升不可能是脫水量，像是院方那幾筆的目標脫水量欄填成了體重（74.6 公斤）；範圍檢查擋得對，不是本系統的錯，不必改程式（請學長確認：院方 API 介接之二 E-5）
- 🏥 卡片最上面出現「目前接的是模擬院方 API」：掛到模擬的資料，**馬上停用**（《[讀檔：啟用、檢查、停用](ref-dialysis-files.md)》）
