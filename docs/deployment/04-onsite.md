# 第四冊 · 進院當天

版本：v0.1　文件狀態：草案　編號：`H-xx`　**這一冊要印出來帶進去**

> 從走進醫院大門，到走出醫院大門。**照順序做，不要跳。**
> 每一步做完在紙上打勾並寫下時間——那張紙就是部署紀錄。

## 0. 當天的形狀

**建議約在上午**，理由有三個：出事還有一整個下午可以處理、資訊室的人白天在、透析班次通常上午最滿（要避開）。

| 時段 | 做什麼 | 編號 |
|---|---|---|
| 出門前 30 分鐘 | 最後檢查 | `H-01` |
| 第 0～30 分 | 報到、找到人、開場與問答 | `H-02`～`H-04` |
| 第 30～60 分 | 掃毒、進到主機前面、認識這台機器 | `H-05`～`H-07` |
| 第 60～75 分 | **路線 A**（預期失敗，取證據） | `H-08` |
| 第 75～150 分 | **路線 B**（正式安裝） | `H-09`～`H-13` |
| 第 150～180 分 | Windows 五件事、防火牆 | `H-14`～`H-15` |
| 第 180～210 分 | 冒煙測試、備份還原實測 | `H-16`～`H-17` |
| 第 210～240 分 | 總覽螢幕、平板（若有） | `H-18`～`H-19` |
| 第 240～270 分 | 教學與交接 | `H-20`～`H-21` |
| 離院前 30 分鐘 | 收尾、清除隨身碟、最後確認 | `H-22`～`H-23` |
| 當天晚上 | 寫紀錄 | `H-24` |

**合計約 5 小時，而且這是順利的版本。** 用[第二冊](02-dry-run.md) R-22 量到的時間去調整。
**不要排在同一天做別的事。**

## 1. 出門前

### H-01 最後檢查（30 分鐘，在家裡做完）

照[第五冊](05-carry-in-out.md)的打包清單逐項確認。**最容易漏的五樣**：

1. 隨身碟（而且裡面只有兩個檔案）
2. 印出來的五份文件＋交付單＋指令小抄
3. **空白筆記本與兩支筆**
4. 手機（充飽電，要當碼表與臨時筆記）
5. 寫著 `JWT_SECRET`、服務帳號密碼、初始管理員密碼的那張紙

**可能怎麼壞、怎麼處理**

| 症狀 | 處置 |
|---|---|
| 想「檔案都在雲端，到時候下載就好」 | **院內沒有網路。** 下載不了，這是整件事的前提 |
| 想用手機拍下文件代替列印 | 可以當備援，但**現場要一邊看一邊打字**，手機很難用。而且院內可能不允許拍照 |

## 2. 抵達

### H-02 報到

**做什麼**

依院方規定報到、領識別證、簽訪客登記。

**可能怎麼壞、怎麼處理**

| 症狀 | 處置 |
|---|---|
| 要求登記隨身物品，包含筆記型電腦與隨身碟 | 照實登記。**這也是 Q-29 的答案之一**，記下來 |
| 說要事先申請才能帶資訊設備進去 | 這種情形代表 Q-29 沒問清楚。**當天多半補辦不了**——改成純情報蒐集的行程（[第五冊](05-carry-in-out.md)） |

---

### H-03 找到那個有權限的人

**做什麼**

找到資訊室的聯絡人，先確認一件事：**「待會兒操作那台主機的時候，您會全程在旁邊嗎？」**

**可能怎麼壞、怎麼處理**

| 症狀 | 處置 |
|---|---|
| 「我把管理員帳密給你，你自己弄」 | **不要接受**。你不該持有院方的管理員憑證，出事說不清。請對方在旁邊，由他輸入密碼 |
| 「我等一下有會，你先弄」 | 問清楚**幾點回來**，並把需要他的步驟（H-12 建帳號、H-14 防毒、H-15 防火牆）排在那之後或之前 |
| 找不到人 | 停在這裡。**沒有這個人，H-12 之後全部做不了** |

---

### H-04 開場三句話，然後把問題問完

**做什麼**

先講清楚今天要做什麼（三句話）：

> 「今天要在那台 Windows 工作站上裝一套離線的照護輔助系統，**全程不需要對外網路**。
> 它自帶執行期，不會動到機器上的任何全域設定。
> 大約三到四小時，需要您協助的是**建一個服務帳號、加防毒排除、開三個連接埠**。」

然後**把問題一次問完**（這些理想上 D-14 就寄出去了，但現場一定要再確認一次）：

**Q-27 那九題（主機）**

| # | 問題 | 答案寫這裡 |
|---|---|---|
| 1 | 這台機器我們有沒有系統管理員權限？ | |
| 2 | 服務要用哪個帳號跑？本機還是網域？密碼誰保管？會不會定期強制更換？ | |
| 3 | 資料庫與備份放哪一顆 SSD 的哪個路徑？權限怎麼設？這台機器上還有哪些專案、誰有登入權限？ | |
| 4 | **防毒是哪一套？誰能加排除清單？** | |
| 5 | 可以用哪幾個連接埠？能不能確保其他專案不會佔用？防火牆要怎麼開讓護理站與平板連得進來？ | |
| 6 | 開機自動啟動要不要設？重開機後誰確認服務有起來？ | |
| 7 | 系統更新政策？重新啟動時段會不會落在透析班次中？這些設定被別的專案改掉時誰通知我們？ | |
| 8 | 備份要送到院內哪一台機器？存取方式與保管責任？ | |
| 9 | **「資源足夠」具體是多少？** 記憶體額度、磁碟保留空間、誰監看？ | |

**Q-29 那六題（交付流程）**

| # | 問題 | 答案寫這裡 |
|---|---|---|
| 1 | 允許用隨身碟嗎？要報備嗎？有沒有指定的加密碟？ | |
| 2 | 有沒有指定的掃毒站？結果要不要留存、留在哪？ | |
| 3 | 裝軟體要不要走變更申請？流程多久、誰核准？ | |
| 4 | 數百 MB 的包掃一次大約多久？今天做得完嗎？ | |
| 5 | **日後每次更新都要重走一次嗎**，還是第一次核准後可沿用？ | |
| 6 | 可接受的部署與更新時段？ | |

**另外三題（這次特別要問）**

| 問題 | 為什麼現在問 |
|---|---|
| **主機的固定位址（DNS 名稱或 IP）是什麼？** | [第三冊](03-tablet-shell.md) K-01：它決定憑證、APK 與安裝包的建置 |
| 平板採購到哪一步？型號與 Android 版本決定了嗎？ | 決定下次進院的時間 |
| 允不允許外來筆記型電腦接上院內網路？ | 位址與預期不同時，這是唯一的補救路徑 |

> **這一段不要省。** 問題問完要 20～30 分鐘，看起來很花時間，
> 但**沒問到的每一題，都會變成下一次再跑一趟的理由**。

## 3. 進到主機前面

### H-05 掃毒（DEP-26 第二次）

**做什麼**

依院方指示把隨身碟送掃描站，或在主機上用院方防毒掃一次。

**怎麼知道成功了**

結果乾淨，**並且留存**（拍照不行的話，請對方給一份紙本或記下單號）。

**可能怎麼壞、怎麼處理**

| 症狀 | 原因 | 處置 |
|---|---|---|
| 報出可疑檔案 | 多半是 `runtime/node.exe` 或引擎被啟發式判定 | 你在 [P-12](01-dev-machine.md#p-12-開發端掃毒dep-26-第一次) 已經先遇過一次，把當時記下的判定名稱拿出來說明 |
| 掃描要一小時以上 | 2 萬多個檔案 | 利用這段時間做 H-06、H-07 |
| 掃描站把檔案「清理」了 | 防毒直接刪了或改了 | **後面核對雜湊時一定會發現**。這時要回頭談排除規則，不要用被動過的包硬裝 |
| 院方根本不允許外接隨身碟 | Q-29 第 1 題沒問到 | **今天裝不成**。改成情報蒐集，並當場談出下次的傳入管道 |

### H-06 確認這是對的那台機器

**做什麼**

```powershell
hostname
systeminfo | Select-String "OS 名稱","OS 版本","系統類型","實體記憶體總數"
Get-TimeZone
Get-Volume
```

**怎麼知道成功了**

| 看什麼 | 應該是 |
|---|---|
| 架構 | x64 |
| 記憶體 | 64GB 等級 |
| 磁碟 | 兩顆 SSD，且**兩顆都有足夠可用空間** |
| 時區 | `Taipei Standard Time` |

**可能怎麼壞、怎麼處理**

| 症狀 | 處置 |
|---|---|
| 規格與說好的差很多 | **先問清楚是不是同一台**。裝錯機器是最難救的錯誤 |
| 時區不是台北 | 請資訊室當場改。改不了就**停手**（[總覽](index.md#6-什麼情況下當場停手)） |
| 磁碟快滿了 | 記下可用空間。低於 `DB_DISK_MIN_FREE_MB` 的話，**更新流程會直接停下**，而那是刻意的 |
| 只有一顆磁碟 | 資料庫與備份要重新規劃。備份的最終落點本來就必須是**院內另一台機器**（DEP-06） |

### H-07 盤點這台機器上原本有什麼

**做什麼**

```powershell
Get-NetTCPConnection -State Listen | Select-Object LocalPort,OwningProcess | Sort-Object LocalPort
Get-ScheduledTask | Where-Object { $_.State -ne "Disabled" } | Select-Object TaskName,State
node -v
```

**怎麼知道成功了**

你知道了三件事：**哪些埠已經被佔用**、機器上還有哪些常駐工作、**有沒有全域 Node.js**。

**可能怎麼壞、怎麼處理**

| 症狀 | 意義 | 處置 |
|---|---|---|
| 你打算用的埠已經被佔走 | DEP-37 第 2 項 | **當場換一個**，和資訊室一起登記下來。`.env` 與 `CORS_ORIGINS` 要一起改 |
| 有全域 Node.js | 別的專案裝的 | **不要用它，也不要動它**。我們自帶執行期，正是為了不受它影響 |
| 有一堆別的專案的常駐工作 | 共用主機的正常樣子 | 記下來。**日後「服務莫名停掉」時，這張清單是第一個要查的地方** |

## 4. 路線 A（預期失敗，目的是取證據）

### H-08 讓它失敗，並把失敗記下來（DEP-25）

**做什麼**（每一步都計時）

```powershell
git clone https://github.com/<repo>.git
npm install
```

**怎麼知道「成功」了**

**每一步都失敗，而且你抄下了錯誤原文與耗時。**

要填的欄位（演練紀錄 §1.3）：

| 欄位 | 值 |
|---|---|
| 日期／時間 | |
| 執行者 | |
| 主機 | |
| `git clone` 的錯誤原文 | |
| 耗時 | |
| `npm install` 的錯誤原文 | |
| 耗時 | |
| 有沒有人提議「開一下網路就好」、怎麼回應的 | |

**可能怎麼壞、怎麼處理**

| 症狀 | 處置 |
|---|---|
| **`git clone` 成功了** | **先不要往下跑。** 翻[第七冊](07-git-clone.md)，從 G-01 做起 |
| **有人說「我開一下網路給你」** | **婉拒，並把這件事記下來。** 零院外連線是這套系統能放病人資料的前提，第一天就自己破壞它，之後沒有人會再認真看待這條 |
| 機器上連 git 都沒有 | 更好——那本身就是證據。記下來 |
| 錯誤訊息很長 | **抄開頭那幾行就夠**，重點是錯誤碼與主機名稱。另外**一定要記耗時**：開發端量到的是 71 秒，而它連第一個套件的中繼資料都還沒拿到 |
| 覺得這一步沒必要、想跳過 | 這份紀錄有兩個用途：向資訊室解釋「為什麼不能用一般方式部署」時它比任何說明都有效；日後有人提議「直接在主機上更新就好」時，它是現成的答案 |

## 5. 路線 B（正式安裝）

### H-09 解壓並核對雜湊（DEP-27）

**做什麼**

```powershell
Expand-Archive -Path <隨身碟>:\hd-tablet-care-<版本>-<commit>.zip -DestinationPath C:\hd\hd-tablet-care-<版本>-<commit>
cd C:\hd\hd-tablet-care-<版本>-<commit>
Get-FileHash -Algorithm SHA256 .\CHECKSUMS.txt
```

壓縮檔裡**沒有最上層資料夾**，`-DestinationPath` 要寫到有版本號的那一層。

與交付單上那一串**逐字比對**。

**可能怎麼壞、怎麼處理**

| 症狀 | 處置 |
|---|---|
| **雜湊不一樣** | **停下來。** 重新複製再比一次。還是不同就是路上壞了或被掃描站動過——今天不要裝 |
| `cd` 找不到路徑，檔案全散在 `C:\hd\` 底下 | 解壓目的地少寫了版本號那一層。清掉散出來的檔案，照上面的指令重解，不要用搬的 |
| 路徑太長導致解壓失敗 | 解到很短的路徑（`C:\hd\`），不要放在桌面或使用者資料夾深處 |
| 解壓很慢 | 2 萬多個檔案，幾分鐘是正常的 |
| 不知道要解到哪 | 問資訊室指定的安裝路徑。**要記得它必須與資料庫、備份目錄分開**（DEP-08） |

### H-10 建立 `.env`

**做什麼**

```powershell
Copy-Item .\.env.範本 ..\.env
notepad ..\.env
```

照[第二冊](02-dry-run.md) R-08 那張表填。**把你在演練時填的那份拿出來照抄**，只換四種值：
主機位址、連接埠、路徑、密碼。

**可能怎麼壞、怎麼處理**

| 症狀 | 處置 |
|---|---|
| 忘了 `DEPLOYMENT_ENV=production` | 時區檢查不會擋、開發用遷移指令不會擋。**一定要填** |
| `CORS_ORIGINS` 還是 localhost | 護理站電腦一連就被擋，而且錯誤只在瀏覽器主控台看得到 |
| `API_PORT` 沒填 | 正式環境會直接拒絕啟動。**這是刻意的**：逼出「埠要先登記」這件事 |
| 密碼裡有特殊字元 | 整串加引號，或改用不含引號與 `#` 的密碼 |

### H-11 套用既有遷移（DEP-31）

**做什麼**

```powershell
.\runtime\node.exe .\app\api\scripts\prisma-cli.mjs migrate deploy --schema .\app\api\prisma\schema.prisma
```

**怎麼知道成功了**

列出套用了哪幾個遷移，資料庫檔案出現在你指定的目錄。

**可能怎麼壞、怎麼處理**

| 症狀 | 處置 |
|---|---|
| `ENOTFOUND binaries.prisma.sh` | `PRISMA_ENGINES_DIR` 沒指好。**注意：這不是網路問題，不要因此去要網路** |
| `Error code 14: Unable to open the database file` | 目錄不存在或沒有寫入權限。先建目錄 |
| 拒絕啟動，說路徑在共用位置 | 換一個專屬路徑（DEP-37 第 3 項） |
| 有人建議用開發用那支遷移指令「比較快」 | **絕對不可以**：它可能直接重建整個資料庫 |

### H-12 建立服務帳號（**需要資訊室**）

**做什麼**

請資訊室建立一個專用的低權限帳號，並告訴你帳號名稱（密碼由他們輸入，你不要知道）。

**可能怎麼壞、怎麼處理**

| 症狀 | 處置 |
|---|---|
| 「用我的帳號跑就好」 | 不行。那個人改密碼或離職的那天服務就停了 |
| 「用 SYSTEM 跑」 | 不行。權限過大，且違反 DEP-12 |
| 網域帳號有密碼到期政策 | **當場問清楚多久到期、到期時誰來改**。這是日後服務突然停掉的頭號原因，寫進交接文件 |

### H-13 註冊服務並啟動

**做什麼**

```powershell
.\scripts\service-install.ps1 -Account "<網域或機器名>\<服務帳號>" -DataDir "<資料目錄>" -BackupDir "<備份目錄>" -LockDownDataDir
.\scripts\service-start.ps1
.\scripts\service-status.ps1
```

**怎麼知道成功了**

排程工作 Running、**執行身分是服務帳號**、3 個行程、存活檢查 HTTP 200。

**可能怎麼壞、怎麼處理**

| 症狀 | 處置 |
|---|---|
| 執行原則擋下 `.ps1` | `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass`。**先問過資訊室** |
| 資訊室堅持要 `services.msc` 看得到的服務 | 目前是排程工作（Q-27 第 6 題）。**今天先用排程工作把系統跑起來**，把需求記下來，回去換那一支腳本 |
| 行程數 0 | 用前景跑一次看錯誤：`.\runtime\node.exe .\scripts\run-all.mjs` |
| 資料目錄被擋（在安裝包目錄之內） | **正確行為**（DEP-08）。換一個路徑 |

## 6. 主機的環境設定

### H-14 Windows 五件事（**需要資訊室**）

| # | 要做的事 | 怎麼確認 | 不做會怎樣 |
|---|---|---|---|
| 1 | **資料庫目錄加入防毒排除清單** | 請對方開啟防毒主控台，**當場看到那條規則** | 即時掃描會在 SQLite 寫入時開啟同一個檔案，造成**間歇性、不固定重現**的鎖定失敗。這是最難查的一類錯誤 |
| 2 | **確認資料庫目錄不在雲端同步資料夾底下** | 看該路徑有沒有同步圖示；`Get-Item <路徑> \| Select-Object FullName` 確認實體位置 | 醫院電腦常把「文件」重新導向到雲端，而路徑上看不出來。那等於把資料庫送出院外，同時毀掉檔案鎖 |
| 3 | **確認不是對應網路磁碟機的代號** | `net use` 看有沒有那個代號 | 看起來像本機，行為是網路檔案系統 |
| 4 | 關閉自動休眠 | `powercfg /change standby-timeout-ac 0` | 半夜備份跑不到、平板連不上 |
| 5 | 確認系統更新的重新啟動時段不落在透析班次 | 群組原則或 Windows Update 設定 | 更新重新啟動落在治療中，病人端整區斷線 |

**這五件事都要寫下「是誰設的、由誰保管、改動前要知會誰」。**
主機是共用的，別的專案的維運人員一樣改得動，而改掉之後本系統不會收到任何通知。
依據是《部署規範》DEP-21，對應 26 條清單第 3、4、10 條。

**可能怎麼壞、怎麼處理**

| 症狀 | 處置 |
|---|---|
| 防毒排除清單今天加不了（要走申請） | **停手或降級**：可以先把服務跑起來驗證，但**不要讓護理師開始輸入真實資料**，直到排除清單生效 |
| 對方說「排除清單不安全，不能加」 | 說明範圍只有一個資料夾，且該資料夾只有服務帳號寫得進去。談不成就記下來，回去評估別的做法 |

#### H-14 自己做的時候（資訊室把系統管理員權限交給你）

**動手之前先確認兩件事**，任何一件不成立就不要自己改，回到上面那張表請資訊室做：

1. 資訊室**明確同意**你自己改這五項，並記下是誰同意的。
2. 這幾項設定**有沒有被群組原則集中管理**。有的話，本機改了會在下次套用原則時被蓋回去，
   而你改的當下看起來完全正常。每一項底下都有一行檢查指令。

以下指令一律在**以系統管理員身分開啟的 PowerShell** 裡執行。先把資料目錄指定好，後面都會用到：

```powershell
$dataDir = "<資料目錄>"      # 與 H-13 的 -DataDir 同一個值，例如 D:\hd-care\data
```

##### ① 資料庫目錄加入防毒排除清單

**先看主機上是哪一套防毒在當家**：

```powershell
Get-CimInstance -Namespace root/SecurityCenter2 -ClassName AntiVirusProduct | Select-Object displayName
Get-MpComputerStatus | Select-Object AMRunningMode, RealTimeProtectionEnabled
```

| 看到的結果 | 代表 | 怎麼做 |
|---|---|---|
| 只有 Windows Defender（Microsoft Defender），`AMRunningMode` 是 `Normal` | Defender 是主要防毒 | 照下面的指令加 |
| 出現其他產品（趨勢、賽門鐵克、卡巴斯基等），或 Defender 是 `Passive Mode` | 第三方防毒在當家，Defender 加了也沒用 | 這類產品幾乎都由**中央主控台**統一派送設定，裝在本機的那一端通常鎖住、改不了。**這一項只能請資訊室從主控台加**，你做不到 |

**Defender 的做法**：

```powershell
Add-MpPreference -ExclusionPath $dataDir
```

- 排除的是**整個資料夾**，不是資料庫那一個檔案。SQLite 寫入時會在旁邊產生 `-wal`、`-shm` 等暫存檔，只排除主檔等於沒排除。
- **只排除資料目錄**，不要排除整顆磁碟、不要排除安裝包目錄、不要排除 `node.exe`。

**怎麼知道成功了**

```powershell
(Get-MpPreference).ExclusionPath
```

清單裡看得到 `$dataDir` 那一行。

**確認沒有被集中管理蓋掉**：

```powershell
Get-ItemProperty "HKLM:\SOFTWARE\Policies\Microsoft\Windows Defender" -ErrorAction SilentlyContinue
```

什麼都沒印出來，代表沒有群組原則管 Defender，本機設定會留著。
印出了 `DisableLocalAdminMerge` 且值為 `1`，代表**本機加的排除會被忽略**，一定要資訊室從群組原則加。
隔天回來再跑一次 `(Get-MpPreference).ExclusionPath`，那一行還在才算數。

##### ② 確認資料庫目錄不在雲端同步資料夾底下

**選路徑的原則**：直接放在磁碟根目錄底下的專屬資料夾（例如 `D:\hd-care\data`），
**不要放在 `C:\Users\` 底下的任何地方**——「文件」「桌面」最常被重新導向到 OneDrive。

**檢查**：

```powershell
$env:OneDrive; $env:OneDriveCommercial
Get-Item $dataDir | Select-Object FullName, LinkType, Target, Attributes
Get-Process | Where-Object { $_.Name -match 'OneDrive|GoogleDrive|Dropbox|Synology|Nextcloud|Box' } | Select-Object Name
```

**怎麼知道成功了**

| 檢查 | 要看到 |
|---|---|
| 第一行印出的 OneDrive 路徑 | `$dataDir` **不在**那個路徑底下（沒印出任何東西也算通過） |
| `LinkType`、`Target` | **都是空的**。有值代表這個資料夾是捷徑或連結，實際位置在別處，要順著 `Target` 再查一次 |
| `Attributes` | **沒有** `ReparsePoint` |
| 第三行 | 有同步軟體在跑的話，開啟它的設定，確認同步範圍不含 `$dataDir` 所在的磁碟或資料夾 |
| 檔案總管 | 開啟 `$dataDir`，**狀態欄沒有雲朵或綠色勾勾圖示** |

##### ③ 確認不是對應網路磁碟機的代號

```powershell
$drive = Split-Path $dataDir -Qualifier
Get-CimInstance Win32_LogicalDisk -Filter "DeviceID='$drive'" | Select-Object DeviceID, DriveType, ProviderName
subst
Get-Partition -DriveLetter $drive.TrimEnd(':') | Get-Disk | Select-Object FriendlyName, BusType
```

**怎麼知道成功了**

| 檢查 | 要看到 | 看到別的代表 |
|---|---|---|
| `DriveType` | `3`（本機固定磁碟） | `4` 是網路磁碟機、`2` 是抽取式磁碟，**都不行** |
| `ProviderName` | 空的 | 印出 `\\伺服器\分享` 就是網路磁碟機 |
| `subst` | 沒有列出這個代號 | 列出來的話，這個代號是別的資料夾的替身，要照實際路徑重查 |
| `BusType` | `NVMe`、`SATA`、`RAID` 之類 | `USB` 是外接碟、`iSCSI` 是走網路的儲存設備，**都不行** |
| `$dataDir` 本身 | 以磁碟代號開頭 | 以 `\\` 開頭是網路路徑，**直接換路徑** |

另外注意：網路磁碟機的對應是**跟著登入者走的**。你看得到的 `Z:`，服務帳號看不到；
就算硬要用，服務一啟動就會找不到路徑。

##### ④ 關閉自動休眠

```powershell
powercfg /change standby-timeout-ac 0
powercfg /change hibernate-timeout-ac 0
```

螢幕關閉不影響服務，**不用動** `monitor-timeout`。

**怎麼知道成功了**

```powershell
powercfg /query SCHEME_CURRENT SUB_SLEEP STANDBYIDLE
powercfg /query SCHEME_CURRENT SUB_SLEEP HIBERNATEIDLE
```

兩段輸出裡「目前的 AC 電源設定索引」都是 `0x00000000`。

**確認沒有被集中管理蓋掉**：

```powershell
Get-ChildItem "HKLM:\SOFTWARE\Policies\Microsoft\Power" -ErrorAction SilentlyContinue
```

什麼都沒印出來才代表本機設定會留著。有東西的話，電源設定由群組原則控制，要請資訊室改。
**隔天回來再跑一次查詢**，值還是 `0` 才算數。

##### ⑤ 系統更新的重新啟動時段不落在透析班次

先要有透析班次的起訖時間（Q-27 第 7 題、第五冊 `C-20`），例如 `06:00–23:00`。

**先看更新是不是被集中管理**：

```powershell
Get-ItemProperty "HKLM:\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate" -ErrorAction SilentlyContinue
Get-ItemProperty "HKLM:\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate\AU" -ErrorAction SilentlyContinue
```

| 看到的結果 | 代表 | 怎麼做 |
|---|---|---|
| 兩行都沒印出東西 | 更新由這台機器自己決定 | 照下面設「使用時段」 |
| 印出 `WUServer`、`AUOptions`、`ScheduledInstallTime` 等值 | 院方用群組原則或 WSUS 統一管更新，**本機設定會被蓋掉** | 把這些值抄下來，請資訊室把這台的安裝與重新啟動時間排在透析班次以外。**你做不到** |

**沒有集中管理時的做法**：

1. 設定 → Windows Update → 進階選項 → **使用時段**。
2. 選「手動」，把開始與結束時間設成涵蓋整段透析班次。
3. 有「根據活動自動調整」的選項就**關掉**，否則 Windows 會自己改掉你設的時間。

**使用時段最長只能設 18 小時。** 班次加前後準備超過 18 小時，就蓋不住整段，
要請資訊室改用群組原則排定安裝時間。「暫停更新」不是解法，它只是把問題往後推。

**怎麼知道成功了**

```powershell
Get-ItemProperty "HKLM:\SOFTWARE\Microsoft\WindowsUpdate\UX\Settings" | Select-Object ActiveHoursStart, ActiveHoursEnd
```

兩個數字是小時（`6` 代表 06:00、`23` 代表 23:00），跟你設的一致。

##### 自己做完之後

| 要做 | 為什麼 |
|---|---|
| 五項的檢查輸出**抄在部署紀錄上**，寫明「由誰設、何時設、資訊室哪一位同意」 | 日後設定被改掉時，才分得出是誰動的、原本是什麼 |
| 在交接文件寫下「這五項改動前要知會誰」 | 主機是共用的，別的專案的人不會知道這五項跟本系統有關 |
| **隔天或下次進院時**，把 ①④⑤ 的檢查指令再跑一次 | 群組原則通常在重新開機或每 90 分鐘左右重新套用，當下看起來成功不代表會留著 |

### H-15 防火牆與從護理站連進來

**做什麼**

請資訊室開三個埠的輸入規則，然後**到護理站那台電腦上**開護理端網址。

**怎麼知道成功了**

**在護理站的電腦上**看得到登入畫面，**而且登得進去**。

**可能怎麼壞、怎麼處理**

| 症狀 | 原因 | 處置 |
|---|---|---|
| 畫面出得來但登入沒反應 | **PWA 裡的 API 位址是 localhost** | 見[第二冊](02-dry-run.md) R-08 的警告框。**這是今天最可能卡死的一點**：唯一的當場補救是帶開發機進來重新產生安裝包 |
| 主控台出現 CORS 錯誤 | `CORS_ORIGINS` 沒填對 | 改 `.env`，重新啟動服務 |
| 完全連不上 | 防火牆或網段隔離 | 先在主機上 `curl.exe http://localhost:<API_PORT>/api/health` 確認服務本身活著，再談網路 |
| 護理站電腦的瀏覽器太舊 | 醫院電腦常見 | 記下瀏覽器與版本。**這是要帶回來的情報之一** |

## 7. 驗證

### H-16 冒煙測試

**做什麼**

在護理站的電腦上走一次主線：登入 → 強制改密碼 → 建病人 → 建排班 → 指派平板 → 解除綁定 → 稽核查得到。

**怎麼知道成功了**

每一步都如《[完整手動測試手冊](../testing/manual-test-guide.md)》§02、§03 所述。

**可能怎麼壞、怎麼處理**

| 症狀 | 處置 |
|---|---|
| 沒有任何帳號可登入 | `SUPER_ADMIN_*` 沒填。補進 `.env` 重新啟動，**資料庫不必重建** |
| 建病人時猶豫要不要用真實資料 | **首波試用可以用真實病人資料**（這是正式環境），但今天的測試資料要用虛構的，並在交接時說明哪幾筆是測試資料、誰負責清掉 |
| 某個功能不見了 | 首波功能開關關閉（DEP-29），**正確行為** |

### H-17 備份與還原實測（**這一條最常被跳過**）

**做什麼**

1. 執行一次備份到指定的備份目錄
2. **把它還原到另一個檔案，確認還原得起來**
3. 確認備份的最終落點是**院內另一台機器**（DEP-06）

**怎麼知道成功了**

還原後雜湊相符、完整性檢查 ok、筆數對得上。

**可能怎麼壞、怎麼處理**

| 症狀 | 處置 |
|---|---|
| 備份目錄寫不進去 | 權限或路徑。**現在不修，第一次要用備份的時候才發現就來不及了** |
| 沒有第二台機器可以放備份 | 記下來，並明講：**同一台機器上的兩顆磁碟不是備援**，整機故障或被勒索軟體加密時一起沒 |
| 「之後再設定備份」 | **不要接受。** 沒有備份的系統不該開始收病人資料 |

### H-18 常駐總覽螢幕（FR-N12）

**做什麼**

在指定位置的螢幕上開啟護理端總覽，確認它**不會進入休眠**。

**可能怎麼壞、怎麼處理**

| 症狀 | 處置 |
|---|---|
| 螢幕還沒到位 | 記下位置與硬體需求（Q-10），列入帶回情報 |
| 螢幕會自己暗掉 | 調整該台電腦的電源設定 |
| 總覽顯示斷線 | 看 SSE 心跳。超過約兩倍心跳沒收到訊息就會判定斷線並重連 |

### H-19 平板（**這次多半跳過**）

平板到位且 APK 備妥時，照[第三冊](03-tablet-shell.md) K-10～K-16，**只佈建兩三台**。

沒到位的話，這一段改成情報蒐集（[第三冊](03-tablet-shell.md) 第 3 節），
並**用手機在每個床位測一次 Wi-Fi 訊號**——這件事不需要平板就能做，而且非到現場不可。

## 9. 離院前

### H-22 收尾清單（離院前 30 分鐘，**一定要留這段時間**）

- [ ] 護理站電腦上實際登入過
- [ ] 備份做過一次並還原成功
- [ ] 《部署規範》第 9 章那 26 條**每一條都有結果**（通過／未通過／不適用，不要留空白）
- [ ] 交接文件已交付並有人簽收
- [ ] H-04 的問題清單**每一題都有答案**（答不出來的要寫「未答覆」與對方是誰）

### H-23 清除隨身碟（DEP-28）

**做什麼**

當場格式化隨身碟，在部署紀錄寫明「已清除」、時間與執行者。

**可能怎麼壞、怎麼處理**

| 症狀 | 處置 |
|---|---|
| 想把紀錄檔拷出來「回去慢慢看」 | **不行。** 不是備份、不是紀錄檔、不是截圖。要帶的資訊用手抄，而且不得含病人資料 |
| 想留著安裝包「以防下次要用」 | 開發機上有一模一樣的一份，雜湊值也在交付單上 |
| 忘了清除就離開 | 回去補不了。**所以它要排在離院前 30 分鐘那段，不是最後一分鐘** |

### H-24 當天晚上就寫紀錄

**做什麼**

## 10. 隨時可以停手

[總覽第 6 節](index.md#6-什麼情況下當場停手)那六種情形，任何一種出現就停。
停手時做三件事：**把服務停掉**、**把現況寫進紀錄**、**當場講清楚下一次需要什麼**。

**不要留一個「好像可以用」的狀態給別人。** 半成品比沒有東西更糟：
護理師會開始用它，然後把問題當成系統的正常行為。
