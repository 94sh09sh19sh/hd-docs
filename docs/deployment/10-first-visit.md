## 0. 先講結論

### 0.1 一句話

**院方要求以容器部署，這正是[第九冊](09-docker.md)的情境；但當天沒有照第九冊的方式做，
而是先手動開了一個通用的 Python 容器、在容器裡 `git clone`，再在容器「裡面」照第九冊從頭執行。**
第九冊的每一條指令都是寫給**主機上的 PowerShell** 下的，在容器裡一條都不成立，之後就全部亂掉了。

### 0.2 失敗原因，由重到輕

| # | 原因 | 屬於 | 詳見 |
|---|---|---|---|
| F-01 | 在自己開的容器**裡面**照第九冊做，第九冊本身卻就是在教怎麼**建出**容器 | 現場操作 | [第 2 節](#f-01-在容器裡面照第九冊做) |
| F-02 | `-v /c:/app` 把**整顆 C 槽**掛進了容器 | 現場操作，**有資料與資安風險** | [第 2 節](#f-02-整顆-c-槽被掛進容器) |

**即使 F-01～F-03 都沒有發生，照第九冊做也會在 D-14 或 D-18 倒下**：F-04 讓院方拿到的是修正前的
`Dockerfile`（沒有 OpenSSL、`/data` 屬於 root、compose 只接受繫結掛載），第九冊 0.3 節那三個問題會原樣重演。
所以這一次的失敗有兩層，**現場那一層很顯眼，準備那一層更根本**。

### 0.3 院方到底要求什麼（還沒釐清）

現場筆記的原話是：「院方要求部署在 container 內，**但似乎又允許鏡像到 docker 外**。」這句話有兩種讀法，結果差很多：

| 讀法 | 意思 | 對應 |
|---|---|---|
| 甲 | 服務要跑在容器裡；連接埠、備份目錄這些**對應到容器外**是允許的 | 就是[第九冊](09-docker.md)：程式在映像檔裡、資料在具名資料卷、備份掛主機目錄 |
| 乙 | 資料（資料庫檔案）也可以**直接放在 Windows 目錄**，用繫結掛載給容器讀寫 | **違反 DEP-23**。《部署規範》3.1 當初改掉容器，理由正是這種放法的 SQLite 檔案鎖不可靠 |

**下一次進院前要拿到書面答案**（[F-20](#8-下一次進院前)）。若院方的意思是乙，那不是手冊能開的例外，
要回到《[部署規範](../requirements/deployment-spec.md)》3.3 談。

兩條路線的逐項比較、以及不用容器也能與同機其他專案隔離的理由，整理在《[部署路線比較](../notes/deployment-route-comparison.md)》，詢問院方時帶著它去。

## 2. 為什麼會失敗

### F-01 在容器裡面照第九冊做

**發生了什麼**：先 `docker run` 出一個 `python` 容器，再進去照第九冊做。

**為什麼不成立**：第九冊的形狀是「**主機**上有 Docker → 在**主機**上 `git clone` → 在**主機**上
`docker build` 把原始碼建成映像檔 → `docker compose up` 由映像檔**開出**三個容器」。
容器是這一整串的**產物**，不是起點。在容器裡面做，每一步都少了它要的東西：

| 第九冊的步驟 | 在 `python` 容器裡會怎樣 |
|---|---|
| D-07 `docker version`、`docker compose version` | 容器裡沒有 `docker` 指令，也碰不到主機的 Docker |
| D-09 `Get-LocalGroupMember` | 容器裡沒有 PowerShell，那是 Linux |
| D-11 `New-Item`、`C:\hd` | 同上；路徑也不存在 |
| D-14 `docker build` | 沒有 `docker`，建不出映像檔 |
| D-16 產生 `JWT_SECRET`、D-18 套用遷移 | 都要先有映像檔；`python` 映像檔裡也沒有本專案要的 Node.js 20 |
| D-19 `docker compose up -d` | 同 D-14 |

**下一次怎麼做**：**不要自己先開任何容器。** 在主機的 PowerShell 視窗裡，從 D-05 開始照第九冊做；
容器會在 D-19 由 `docker compose up -d` 自己出現，名字是 `api`、`nurse-web`、`patient-web`。

### F-02 整顆 C 槽被掛進容器

**發生了什麼**：`-v /c:/app` 在 Docker Desktop 上的意思是「把主機的 `C:\` 掛到容器的 `/app`」。
（這一點要在主機上用 [F-10](#f-10-那個容器與它掛進去的東西) 的指令確認，見下。）

**為什麼嚴重**：

- 容器裡預設是 root。**容器裡的任何指令，都能讀寫主機整顆 C 槽**——包含同一台主機上另一個專案的檔案、
  Windows 使用者資料夾、Docker 自己的虛擬磁碟所在的 `AppData`。這是 DEP-37 共用主機隔離的反面
- **在容器裡對 `/app` 做的任何刪除，刪的是主機上的真檔案。** 在容器裡下一句 `rm -rf /app/*`，就是清空 C 槽
- 在 `/app` 底下 `git clone`，原始碼就落在主機 C 槽的根目錄底下，**而且是在一個沒人預期的位置**
- 若之後把資料庫也放在 `/app` 底下，就是 0.3 讀法乙，違反 DEP-23

**下一次怎麼做**：第九冊這條路線上，**只有一個主機目錄會被掛進容器：備份目錄**（`HD_BACKUP_DIR`，掛到 `/backups`）。
其餘一律不掛。這件事由 `docker-compose.yml` 決定，**不要自己下 `-v`**。

### F-03 連接埠對應兩頭都不對

**發生了什麼**：`-p 3000:8000` 是「主機的 3000 → 容器的 8000」。

**為什麼不成立**：

| 端 | 問題 |
|---|---|
| 主機的 3000 | 現場的連接埠清單裡，**3000 已經有行程在聽**，而且與 9000 是同兩個行程——很可能是同機另一個專案的 Docker 轉送，也可能是這個容器自己開的（**要用 [F-09](#f-09-3000-埠是誰的) 確認**）。無論是哪一種，本系統都不能再用 3000 |
| 容器的 8000 | 本系統的後端在容器裡聽的是 3000、護理端 8080、病人端 8081，**沒有任何東西聽 8000** |

**下一次怎麼做**：[D-13](09-docker.md#d-13-決定位址與三個連接埠) 那三個埠要避開 3000 與 9000。
現場清單上 8080、8081 是空的；後端埠要另外挑一個空的、向資訊室登記，寫進 `.env` 的 `HD_API_PORT`，
**也寫進 D-14 的 `VITE_API_BASE_URL`**（兩處要一致，否則要重建映像檔）。

### F-04 要被 clone 的那一版根本不在 `master` 上

**發生了什麼**（事後在開發端查到的）：

| 分支 | 最新 commit | 有沒有第九冊 | 有沒有 0921 三處容器修正 |
|---|---|---|---|
| `origin/master`（GitHub 預設分支） | `c4109fa`（第八冊） | **沒有** | **沒有** |
| `origin/docker-route` | `70b5de5` | 有 | 有 |

`git clone` 不指定分支時拿到的是 `master`。院方當天 clone 到的若是 `master`，拿到的就是
**第九冊 0.3 節說「不修會在院內直接倒下」的那一版**：沒有 OpenSSL、`/data` 屬於 root、compose 只接受繫結掛載。

**為什麼會這樣**：第九冊 [D-01](09-docker.md#d-01-確認要被-clone-的那一版) 就是在防這件事——
「本機與 `origin/master` 的 commit 一模一樣」。這一步在進院前沒有做到：修正推上了 `docker-route` 分支，沒有合回 `master`。

**當天實際 clone 到哪一版不知道**：只記到 `git remote -v`（有 `origin`），沒有記 `git log -1 --oneline`。
這一版在容器裡、也在主機 C 槽上（F-02），[F-10](#f-10-那個容器與它掛進去的東西) 可以查到。

**下一次怎麼做**：進院前把 `docker-route` 合回 `master` 並推上去，**然後**才做 D-01 的比對；
交付單上寫 commit，現場 D-12 用 `git log -1` 逐字核對。

### F-05 進院前的 D-02～D-04 沒有到位

| 第九冊 | 應該在進院前 | 這次 |
|---|---|---|
| D-02 | 在一台**乾淨的** Windows 機器上把 D-11～D-23 完整走一次 | 沒有。開發機上的演練（0.3 節）與這台主機差很多：主機 3000 埠被佔、有 RAM 磁碟、Docker Desktop 從 Microsoft Store 更新 |
| D-03 | 兩週前把 9 題 Docker 問題清單寄給資訊室 | 沒有。第 2、3 題（Docker Desktop 授權、重新開機後有沒有人登入）到現在仍無答案 |
| D-04 | 準備一把唯讀、會過期的權杖 | **不確定當天 clone 用的是哪一把憑證**，見 [F-11](#f-11-clone-用的憑證) |

第九冊寫的是「院方要求容器的話翻這一冊」，但院方的要求是**當天才知道的**，準備工作排不進去。
這條教訓要寫回總覽：**院方有可能臨時改要求，進院前就要把第九冊的準備做完，不管用不用得到。**

### F-06 院方的要求沒有當場釐清

0.3 那一句話有兩種讀法，現場沒有問清楚就動手。第九冊 [D-05](09-docker.md#d-05-開場時說清楚這條路線的代價)、
[D-06](09-docker.md#d-06-取得書面例外) 本來就是要在動手前把這件事講清楚、簽下來的一步；這次跳過了。

### F-07 主機當天連得到院外

這不是失敗原因，但是**這一趟最重要的發現之一**：當天 `docker run ... python` 能把 `python` 映像檔從 Docker Hub 拉下來、
容器裡 `git clone` 能從 GitHub 拿到私有 repo，表示**這台主機當時有對外連線**。

- 這與部署規範「零院外連線」的前提不一致，要問清楚：**是一直都開著，還是當天為了部署臨時開的？誰開的、誰會關？**
  （第九冊 D-03 第 7 題、D-24）
- 第四冊 [H-08](04-onsite.md#h-08-讓它失敗並把失敗記下來dep-25) 預期路線 A「每一步都失敗」，這台主機上不成立
- 在這個問題有書面答案之前，**不得輸入任何真實病人資料**（與第九冊 D-24 同一條）

| 埠 | 現況 | 對本系統的意義 |
|---|---|---|
| **3000** | **已被佔用**（兩個行程） | 本系統預設的後端埠，**不能用**（F-03） |
| **9000** | **已被佔用**（與 3000 同兩個行程） | 很可能是同一個東西開的兩個埠；避開 |
| 8080、8081 | 沒有人在聽 | 護理端、病人端的預設埠**可以用**，但要向資訊室登記 |
| 其餘 | Windows 系統服務與動態埠 | 完整清單見原始照片（不上站） |

C-09 的回答是「沒在使用的都可以使用」——**這還不算登記**。登記要有人記下「這幾個埠是這個系統的」，
否則下一個專案一樣會以為「沒在用就能用」（[F-20](#8-下一次進院前)）。

### 3.5 版本控制

`git remote -v` 顯示 `origin` 指向 GitHub 的 https 網址（fetch 與 push 各一行）。
這是在**容器裡**下的，不代表主機上有 Git；主機上有沒有 Git（第九冊 D-03 第 8 題）**沒有記到**。

## 5. 帶回來之後才看清楚的幾件事

### F-08 電源不穩，而且無人看管

這是**比這次部署失敗更大的問題**，它決定這台主機能不能跑照護系統，不論走哪一條路線：

- **主機稍微被碰到就會斷電，要有人手動開機**；主機放在護理站（C-27），被碰到的機會不低
- **無人看管**，重新開機之後誰去確認服務有起來，答案是沒有人（C-35）
- Docker Desktop **要有人登入 Windows 才會啟動**（3.3）。斷電 → 有人按開機 → **還要有人登入** → Docker 才起來 → 容器才回來。這條鏈上任何一環沒人做，服務就停著，而且沒人知道
- SQLite 已經以 `WAL` 加 `synchronous FULL` 設定，對突然斷電的承受度是它能做到的上限；但**反覆硬斷電**仍然是資料庫最不想遇到的事，備份又只在同一台主機上（C-14）

第九冊 [D-26](09-docker.md#d-26-重新開機測試這一條決定這條路線能不能用) 寫過：
「沒人登入就不會起來，而院方也不會安排人登入——**這條路線就不適合 24 小時運作的照護系統**。」
這台主機現在就是這個情形。**要由院方決定**，手冊不替院方決定：

| 可以問院方的方向 | 解決哪一段 |
|---|---|
| 加一台不斷電系統（UPS），主機移到不會被碰到的位置 | 斷電本身 |
| 主機的 BIOS 設成「恢復供電後自動開機」 | 斷電後沒人按開機 |
| 改用 WSL2 裡的 Docker Engine 由開機排程工作啟動，或回到安裝包路線（排程工作不需要有人登入） | 開機後沒人登入 |
| 指定一個人負責「每班確認一次服務有在跑」 | C-35 |

### F-09 3000 埠是誰的

要在主機上查清楚：

```powershell
Get-NetTCPConnection -State Listen -LocalPort 3000, 9000 | Select-Object LocalPort, OwningProcess
Get-Process -Id <上一行的 OwningProcess> | Select-Object Id, ProcessName, Path
docker ps --format "{{.Names}}  {{.Ports}}"
```

- 若行程是 `com.docker.backend` 或 `wslrelay`，那是 Docker 在轉送某個容器的埠；第三行會告訴你是哪個容器
- 若那個容器是 `dialysis_system_v0`，就是 F-03 自己佔的，F-10 收掉之後就會空出來——**但本系統仍不要用 3000**，同機另一個專案的 9000 旁邊還是容易撞
- 若是另一個專案的容器，**登記下來**，那就是 DEP-37 第 2 項要的登記

### F-10 那個容器與它掛進去的東西

`dialysis_system_v0` **很可能還在主機上**（`-d` 讓它在背景跑；主機斷電後它不會自己回來，但容器本身仍在）。
它掛著整顆 C 槽，裡面有一份 clone 下來的原始碼，也可能有憑證（F-11）。**下一次進院第一件事就是收掉它，而且順序不能錯**：

**① 先看，不要動**

```powershell
docker ps -a --filter name=dialysis_system_v0
docker inspect dialysis_system_v0 --format "{{json .Mounts}}"
docker inspect dialysis_system_v0 --format "{{.HostConfig.RestartPolicy.Name}}"
```

第二行會印出掛載的來源（`Source`）與目的地（`/app`）——這是 F-02「整顆 C 槽」的證據，抄下來。

**② 查 clone 下來的那一份在哪、是哪一版**

```powershell
docker start dialysis_system_v0
docker exec dialysis_system_v0 sh -c "ls /app; find /app -maxdepth 3 -name .git -type d 2>/dev/null"
docker exec dialysis_system_v0 sh -c "cd <上一行找到的目錄的上一層> && git log -1 --oneline && git remote -v && git config --list --show-origin | grep -i credential"
```

`git log -1` 就是 F-04 那個「當天實際 clone 到哪一版」的答案。**`git remote -v` 的網址裡若有權杖，那把權杖已經外洩，照 F-11 處理。**

> ⚠️ **在這個容器裡絕對不要對 `/app` 下任何刪除、移動、改權限的指令。**
> `/app` 就是主機的 C 槽，`rm -rf` 下去刪的是主機上的真檔案，包含另一個專案的東西。

**③ 收掉容器**

```powershell
docker stop dialysis_system_v0
docker rm dialysis_system_v0
docker ps -a --filter name=dialysis_system_v0
```

最後一行什麼都沒印才算完成。**`docker rm` 只刪容器，不會刪到主機 C 槽上的檔案**——這是對的。

**④ 收掉主機 C 槽上那一份 clone**

②找到的目錄，在主機上是 `C:\` 底下同名的資料夾。**確認路徑無誤、確認資訊室同意之後**，用檔案總管刪除
（不要在容器裡刪）。這條路線要的原始碼目錄是 `C:\hd\hd-tablet-care\`，那是下一次在主機上重新 clone 的（D-11）。

**⑤ `python` 映像檔**

```powershell
docker image ls python
```

它是當天為了 F-01 拉下來的，本系統用不到。**要不要刪問過資訊室**：同機另一個專案有可能也在用同一個映像檔。

### F-11 clone 用的憑證

本專案的 repo 是私有的，容器裡的 `git clone` 成功了，表示**當天有一把能讀這個 repo 的憑證被輸入到容器裡**。
不知道是哪一把：

| 若當天用的是 | 要做的 |
|---|---|
| 事先準備的唯讀、會過期的權杖（D-04） | 仍然**今天就作廢**，不要等它過期（D-25） |
| **個人的 GitHub 權杖或密碼**（有寫入權限、不會過期） | **立刻作廢並重發**。那把憑證留在一個掛著整顆 C 槽、任何能登入主機的人都進得去的容器裡 |
| 寫在網址裡 clone 的 | 同上，而且它會出現在 F-10 ② 的 `git remote -v` 裡 |

### F-12 帳號與權限

- `docker-users` 群組裡只有一個本機帳號，而那也是平常登入這台主機的帳號
- 那個帳號就是最高權限（C-10、C-11）
- 帳號的其他現況**不寫在公開文件**，留在院外筆記，下一次當面交給資訊室

合起來的意思是：**能坐到這台主機前面的人，就能讀到資料卷裡的全部照護資料**，不需要知道任何本系統的密碼。
這正是第九冊 D-09 說「最容易被忽略的一條」。這一條**不在我們能決定的範圍**，要當面告訴資訊室這代表什麼、
請院方決定，並寫進交接文件。在院方給出答案之前，這台主機**不得輸入真實病人資料**。
