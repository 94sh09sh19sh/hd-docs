### GO-05 下載、補 `.env`、建置、更新資料庫（＝W-19、J-15～J-18）

**做什麼**

1. 下載新版：

   ```powershell
   git fetch --tags
   git checkout <新 tag>
   git describe --tags
   ```

   `git describe` **正好是** `<新 tag>`，後面沒有尾巴。
2. `notepad $cfg`：`HD_IMAGE_TAG` 改成 `<新 tag>`；照 `deploy\hospital.env.example` 的「院方資料：讀抓取腳本存下的檔」那一段，補這四行（**都先留空，`COMPOSE_FILE` 那一行維持註解**）：

   ```
   HD_DIALYSIS_LIST_DIR=
   HD_LAB_DIR=
   # COMPOSE_FILE=docker-compose.yml;docker-compose.dialysis-files.yml
   HOSPITAL_LAB_FIELD_MAP=
   ```

   `HOSPITAL_API_BASE_URL` 維持空白。
3. 建置（主機有快取，一分鐘內；看到 `Built` 就算有建）：

   ```powershell
   docker compose --env-file $cfg build
   docker images hd-tablet-care
   ```

   看得到 `v0.4.0` 與 `<新 tag>` **兩個**。`v0.4.0` 的不要刪（附錄二要用）。
4. 停後端、更新資料庫（第三行是一整行）：

   ```powershell
   $tag = git describe --tags
   docker compose --env-file $cfg stop api
   docker compose --env-file $cfg run --rm --no-deps api node apps/api/scripts/db-update.mjs --note "v0.4.0 → $($tag)（第五次進院）"
   ```

**怎麼知道成功了**：最後印出「**更新完成。接下來的三件事是人要做的**」。往上找第 3 段，**把更新前備份的檔名（`hd-before-update-<時間>.db`）與 SHA-256 抄下來**，附錄二要用。

| 症狀 | 處置 |
|---|---|
| `Permission denied (publickey)` | 部署金鑰被拿掉了。`ssh -T github-hd-tablet-care` 看一下，打電話給開發端 |
| `error: pathspec '<新 tag>' did not match` | tag 沒推上去或打錯字 |
| `no such host`（建置時） | 再打一次 → 工作列 Docker 圖示右鍵 Restart → 找資訊室看 DNS |
| `更新中止：後端服務還在執行` | 再打一次 `stop api`。**不要加 `--allow-running`** |
| 其他任何「中止」 | 資料庫沒被動到。整段抄下來，`HD_IMAGE_TAG` 改回 `v0.4.0`、`git checkout v0.4.0`、`docker compose --env-file $cfg up -d`，打電話給開發端 |

### GO-11 填兩個資料夾、重建 `api`、讀檔檢查（＝A-13 第 3 步、V-30a、第十五冊之一 1.12）

## 附錄二：新版出問題，退回 `v0.4.0`（＝W-20、第十八冊附錄二）

**什麼時候用**：GO-05 之後，新版 `api` 起不來或主線壞掉，現場解不開。**越早越好**：退回會把資料庫換回 GO-05 的更新前備份，更新之後寫進去的資料（含啟用讀檔後同步進來的）會一起消失。

**做什麼**（`<備份檔名>`、`<雜湊>` 是 GO-05 抄的 `hd-before-update-<時間>.db`）

1. `git checkout v0.4.0`；`notepad $cfg`：`HD_IMAGE_TAG` 改回 `v0.4.0`，`HD_DIALYSIS_LIST_DIR` 清空、`COMPOSE_FILE` 那一行改回註解（`v0.4.0` 不認讀檔）。
2. 停後端、把新版的資料庫移到旁邊、還原（第二、三條各是一整行）：

   ```powershell
   docker compose --env-file $cfg stop api
   docker compose --env-file $cfg run --rm --no-deps --entrypoint sh api -c "mkdir -p /data/before-rollback && mv /data/hd.db /data/hd.db-wal /data/hd.db-shm /data/before-rollback/ 2>/dev/null; ls -l /data/before-rollback"
   docker compose --env-file $cfg run --rm --no-deps api node_modules/.bin/ts-node --project apps/api/tsconfig.json apps/api/scripts/restore-backup.ts --from /backups/<備份檔名> --to /data/hd.db --sha256 <雜湊>
   docker compose --env-file $cfg up -d
   ```

**怎麼知道成功了**：`完整性檢查：ok`；`docker ps` 三個服務是 `hd-tablet-care:v0.4.0`；護理站 Ctrl＋F5 後登得進去。抓取腳本不受影響、照跑。`/data/before-rollback/` 那份先留著，帶回給開發端。
