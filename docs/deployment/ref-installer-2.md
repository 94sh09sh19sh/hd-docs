# 安裝包路線（歷史）（第 2 份，K-05～K-12、C-01～C-05）

上層文件：[《安裝包路線（歷史）》](ref-installer.md)

> **狀態：歷史**（路線 0926 撤除），只當紀錄、不再照做，指令照抄跑不起來；現行部署照[《從零部署本系統》](ref-fresh-install.md)，外殼 APK 與平板照[《平板與外殼 App》](ref-tablet.md)。改寫來源見[第 1 份](ref-installer.md)開頭。編號：`K-xx`、`C-xx`，沿用原編號。

## 摘要

- 外殼 App 原本在開發機上自產院內 CA、自建 keystore、自編 APK、側載（K-01～K-07、K-09、K-12，第 1 節）；0927 起改由院內主機上的 `shell-builder` 建置與簽章、平板從下載頁安裝
- 第 1 節後半：K-05 把 CA 放進外殼 App、K-06 建 keystore 並編譯 release APK、K-07 在模擬器上跑一次（平板沒到也能驗掉八成）、K-09 寫進交付單、K-12 側載 APK
- 1.2 平板到貨前的完成條件（0923）
- 隨身碟、交付單、轉接頭、筆記型電腦要帶，隨身碟裡只放兩個檔案，離院前清除（C-01、C-02、C-05 的安裝包列，第 2 節）
- 第 2 節：C-01 實體、C-02 隨身碟裡放什麼、C-03／C-04 紙上的值與不帶進去的、C-05 帶出來的實體（安裝包路線的列）
- K-01～K-04 在第 1 份；進院當天（H-08～H-13）與出錯處置（X-01～X-04）在[第 3 份](ref-installer-3.md)

## 1. 平板與外殼 App：0927 被取代的部分（`K-xx`，續）

### K-05 把 CA 放進外殼 App

**做什麼**

1. 把 `certs/hospital-ca.pem` 複製到 `apps/kiosk-shell/app/src/main/res/raw/hospital_ca.pem`
2. 開啟 `app/src/main/res/xml/network_security_config.xml`，確認 `<domain>` 是 K-01 那個位址

**怎麼知道成功了**

`res/raw/` 底下有 `hospital_ca.pem`（目前那裡只有一個 `README.md`）， `network_security_config.xml` 裡的網域與 K-01 一致。

**可能怎麼壞、怎麼處理**

| 症狀 | 處置 |
|---|---|
| 位址是 IP 不是網域名稱 | `network_security_config.xml` 的 `<domain>` 也可以寫 IP，但**憑證的主體別名必須含同一個 IP** |
| 忘了放 pem | App 會出現憑證錯誤，而且 **Service Worker 會被整個停用**——離線能力當場消失 |

---

### K-06 建立 keystore 並編譯 release APK

**做什麼**

```bash
keytool -genkeypair -v -keystore hd-kiosk.jks -keyalg RSA -keysize 4096 \
  -validity 10000 -alias hd-kiosk
cd apps/kiosk-shell && ./gradlew assembleRelease
```

**怎麼知道成功了**

`app/build/outputs/apk/release/` 底下有一個已簽名的 APK。

**可能怎麼壞、怎麼處理**

| 症狀 | 原因 | 處置 |
|---|---|---|
| **keystore 遺失** | | **無法補救**（DEP-35）：再也發不出更新版，只能換套件名重新側載 15 台。建立後**立刻**照 K-03 備份 |
| Gradle 建置失敗，缺 SDK 元件 | 第一次建置 | 依提示安裝，需要網路 |
| 不知道 keystore 密碼要設多長 | | 和 CA 私鑰同級對待。**寫在交接文件裡，不要只存在你腦袋裡** |
| 想先用 debug 版測 | 可以 | `./gradlew assembleDebug`。但**正式佈建一定要用 release 簽名版**——debug 簽名的 App 之後換成 release 版時必須先解除安裝，等於白做一次 |

---

### K-07 在模擬器上跑一次（**平板沒到也能驗掉八成**）

**做什麼**

1. Android Studio 開一台 API 34 的模擬器
2. 安裝剛才的 APK
3. 讓它連到 R-xx 那台演練機（[《安裝包路線之三》](ref-installer-build-3.md)；模擬器用 `10.0.2.2` 指向主機）
4. 輸入測試用的序號與金鑰

**怎麼知道成功了**

| 要驗的 | 應該看到 |
|---|---|
| 憑證 | 沒有任何憑證警告 |
| 網址列 | **不存在**（外殼沒有網址列，病人看不到金鑰） |
| 首次佈建 | 輸入序號與金鑰後進入病人端畫面 |
| 金鑰不外露 | 網址上的 `serial`／`key` 參數被網頁立刻移除 |
| 前景回報 | 護理端裝置清單 15 秒內變成**固定中** |
| 離開前景 | 切到別的 App，護理端 **30 秒內**變成**已跳出** |
| 外部連結 | 點測試用的外部連結**不會開啟** |
| 長按文字 | **不會**出現選字選單 |
| 離線 | 關掉模擬器網路後重新整理，**畫面照樣出得來** |

**可能怎麼壞、怎麼處理**

| 症狀 | 原因 | 處置 |
|---|---|---|
| 憑證警告 | pem 沒放、網域對不上、或主機根本沒開 TLS | 見第 1.1 節的警告框 |
| 離線時一片空白 | Service Worker 沒註冊 | **九成是因為連的是 HTTP**（非安全來源）。這正是第 1.1 節那個缺口 |
| 護理端一直顯示「尚未回報」 | App 沒裝成或連不到後端 | **「尚未回報」與「已跳出」是兩件事**：前者是沒裝 App，後者才是跳出 Kiosk |
| 模擬器連不到 `10.0.2.2` | 演練機防火牆 | 回 R-13 開輸入規則（[《安裝包路線之五》](ref-installer-build-5.md)） |

> **模擬器驗不到的只有三件事**：螢幕固定、開機自動啟動的實機行為、實體 Wi-Fi 的穩定度。其餘全部可以在平板到貨前驗完——**這就是「下次去只做最少工作」的實際做法**。

0927 起的驗法改成開發手機從下載頁安裝（[《平板與外殼 App》第 2 份](ref-tablet-2.md)第 8 節、[迭代 12 測試分冊](../testing/iteration-12.md)）。

### K-12 側載 APK

**做什麼**

用隨身碟或 USB 線把 APK 複製到平板，點開安裝。

**可能怎麼壞、怎麼處理**

| 症狀 | 原因 | 處置 |
|---|---|---|
| 「未安裝應用程式」 | 簽名衝突（之前裝過 debug 版）或架構不符 | 先解除安裝舊的再裝 |
| 系統的安全掃描擋下 | 部分機型內建 | 依提示選擇仍要安裝。擋死就換方式傳檔 |
| 平板沒有檔案管理員 | 部分精簡韌體 | 用 `adb install`（要開啟開發人員選項與 USB 偵錯） |

0927 起由 Y-11（平板瀏覽器從院內下載頁安裝）取代。

**K-13 原文的憑證警告原因**：K-13 的步驟現在在[《平板與外殼 App》第 3 份](ref-tablet-3.md)。0923 原表的「憑證警告」一列寫的是安裝包時代的原因：pem 沒打包、網域對不上、主機沒開 TLS，處置「見開頭警告框」（第 1.1 節）。

### 1.2 平板到貨前的完成條件（0923）

- [ ] `K-01` 主機位址定下來，且不會再變
- [ ] `K-02` CA 與伺服器憑證已產生，主體別名涵蓋該位址
- [ ] `K-03` CA 私鑰已異地備份**並驗證過**
- [ ] `K-06` keystore 已建立並備份，release APK 編得出來
- [ ] `K-07` 模擬器上九項全過（離線那一項要等 HTTPS 缺口處理完）
- [ ] `K-08` 採購規格已交出（[《平板與外殼 App》第 3 份](ref-tablet-3.md)）
- [ ] HTTPS 缺口有結論（第 1.1 節的警告框）

## 2. 隨身碟與帶進去（`C-xx`）

原本「這一冊要印出來帶進去」；前提是**假設這次會失敗**：萬一失敗要帶回哪些東西，下一次才不會再失敗。情報蒐集、帶出來的規則、離院前十問、回家 24 小時照舊有效，在[《進院通則》](ref-visit-rules.md)。

### C-01 實體

| # | 帶什麼 | 為什麼 | 漏了會怎樣 |
|---|---|---|---|
| 1 | **隨身碟**（裡面只有安裝包壓縮檔與 `verify-package.mjs`） | 唯一的交付管道 | 今天什麼都做不了 |
| 2 | **備用隨身碟**（同樣內容） | 第一支被擋、壞掉或被扣留 | 多帶一支的成本是零，少帶一支的成本是再跑一趟 |
| 5 | **交付單**（版本、commit、兩個 SHA-256） | 核對雜湊唯一的對照來源 | **核對不了**，等於沒有 DEP-27 |
| 6 | 指令小抄（P-15，[《安裝包路線之二》](ref-installer-build-2.md)） | 指令打錯的代價在正式主機上很貴 | 打錯字、用錯遷移指令 |
| 8 | 寫著三組機密值的那張紙（C-03，[《進院通則》](ref-visit-rules.md)） | 現場產不出來 | 卡在建 `.env` 那一步 |
| 11 | USB-A 與 USB-C 轉接頭 | 主機可能只有其中一種孔 | 隨身碟插不上去 |
| 12 | **筆記型電腦（條件性）** | 位址與預期不同時，唯一的當場補救是重新產生安裝包 | 卡在 H-15（[《第一次進院之二：進院當天詳細版》](visit-1-system-onsite-2.md)）無解 |

> **第 12 項要先問過**：院方允不允許外來筆記型電腦帶進去、能不能接院內網路（Q-29）。不能接網路也還是值得帶——**重新產生安裝包不需要網路**，只需要開發機上那份 `node_modules`。但**它不得接上院內網路，也不得從院內複製任何東西出來**。

C-01 其餘的列（第 3 列印出來的手冊、第 4 列 26 條清單、第 7 列筆記本、第 9 列手機、第 10 列識別證）不分路線，在[《進院通則》](ref-visit-rules.md)。

**離家前的最後三個確認**（第三個「手機電量 100%」在《進院通則》）：

- [ ] 隨身碟插上電腦，親眼看到裡面只有兩個檔案
- [ ] 交付單上的雜湊值看得清楚（不是手寫潦草）

### C-02 隨身碟裡放什麼

| 放 | 不放 |
|---|---|
| 安裝包壓縮檔（`.zip`） | `.env`（任何一份） |
| `scripts/verify-package.mjs` | 資料庫檔案、備份 |
| | 原始碼、`node_modules` |
| | 舊版安裝包 |
| | 任何其他專案的檔案 |
| | 個人資料、照片、音樂 |

**理由**：碟上每多一個檔案，掃描站就多一件要解釋的事，離院時也多一件要清除的東西。

### C-03、C-04 紙上的值與不帶進去的

C-01 第 8 列那張紙寫哪三組值（`JWT_SECRET`、初始最高權限帳號、服務帳號的密碼）與紙的處理（C-03），以及絕對不帶進去的（C-04），不分路線，在[《進院通則》](ref-visit-rules.md)。

### C-05 帶出來的實體（安裝包路線的列）

| 帶出來 | 狀態 |
|---|---|
| 隨身碟 ×2 | **已當場清除**，並在紀錄寫明時間與執行者（DEP-28；H-23） |
| 掃毒結果的紙本或單號 | DEP-26 要求留存 |

C-05 其餘的列（筆記本、26 條檢查清單、交接文件的副本）在[《進院通則》](ref-visit-rules.md)。

隨身碟相關的情報題（C-16 隨身碟政策、C-17 掃毒站、C-21 外來筆記型電腦）與離院前十問的第 8 題（隨身碟清乾淨了嗎）在[《進院通則》](ref-visit-rules.md)；清除隨身碟的步驟 H-23 在[《第一次進院之三：進院當天詳細版》](visit-1-system-onsite-3.md)。
