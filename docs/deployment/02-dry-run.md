# 第二冊 · 開發端的測試部署

版本：v0.1　文件狀態：草案　編號：`R-xx`　建議時點：**D-2**

> 這一冊做的是**彩排**：在一台什麼都沒有的機器上，把院內那一整套從頭到尾走一次。
> 終點是——你已經做過一次，所以進院那天不是第一次。

---

## 0. 為什麼這一步不能省

迭代 10 在開發機上建好安裝包、所有靜態檢查全綠之後，**把它真的跑起來，當場出現兩個缺陷**：

| # | 症狀 | 真正的原因 |
|---|---|---|
| 1 | 後端起不來，說「找不到專案根目錄」 | 資料庫路徑檢查往上找帶 workspaces 的 `package.json`，**安裝包裡沒有那個東西** |
| 2 | 套用遷移時找不到 Prisma CLI | 指令外套只認得開發機的兩種版面，**安裝包的版面少一層** |

**兩個都不是設定寫錯，是「開發機的版面與安裝包的版面不一樣」**——而所有靜態檢查都只看得到前者。

這就是 DEP-22 的意思：**在開發機上解壓來測，測到的是開發機，不是安裝包。**

預計耗時：**半天**。第一次做會更久，而那正是它的價值——這些時間你遲早要花，
在自己家裡花比在醫院裡花便宜得多。

## 1. 先找一台「乾淨」的機器

「乾淨」的定義：**沒有開發環境、沒有全域安裝的 Node.js、沒有這個專案的任何殘留。**

沒有第二台實體機也有替代品，但**可信度差很多**，要知道自己在用哪一種：

| 方案 | 可信度 | 說明 |
|---|---|---|
| **另一台實體 Windows 機器** | ★★★ | 最接近院內主機。借一台、或用家裡那台不寫程式的 |
| **全新安裝的 Windows VM**（Hyper-V／VirtualBox） | ★★★ | 幾乎等價，而且可以照快照重來。**強烈建議用這個** |
| 同一台機器上新增一個本機使用者帳號 | ★ | **驗不到 DEP-22**：Node.js 裝在系統層，新帳號一樣看得到它。只能拿來驗權限那幾項 |
| 開發機上直接解壓來測 | ✗ | **不算數**。這正是 DEP-22 明文要擋的 |

> **建議做法**：開一台 Windows VM，裝完系統之後**先拍一個快照**。
> 每練一次就還原快照，你可以練很多次，而每一次都是真正的「第一次安裝」。

## 2. 把包送進去並驗收

### R-03 用隨身碟複製（順便演練交付動作）

**做什麼**

把 [P-13](01-dev-machine.md#p-13-準備隨身碟) 那支隨身碟插上去，把兩個檔案複製到機器上，例如 `C:\hd\`。

| 症狀 | 原因 | 處置 |
|---|---|---|
| 複製到一半失敗 | 隨身碟品質或檔案系統問題 | 換一支。**這件事在院內發生會很難看**——順便確認你的碟是 exFAT 或 NTFS，FAT32 放不下 4GB 以上的檔案 |
| 防毒把壓縮檔擋下 | 即時掃描 | 記下判定名稱。院內掃描站會遇到同一件事 |

### R-04 解壓並核對雜湊（DEP-27）

**做什麼**

```powershell
Expand-Archive -Path C:\hd\hd-tablet-care-<版本>-<commit>.zip -DestinationPath C:\hd\hd-tablet-care-<版本>-<commit>
cd C:\hd\hd-tablet-care-<版本>-<commit>
Get-FileHash -Algorithm SHA256 .\CHECKSUMS.txt
```

壓縮檔裡**沒有最上層資料夾**，所以 `-DestinationPath` 一定要寫到有版本號的那一層，不能只寫 `C:\hd\`。

拿輸出的雜湊值與[交付單](01-dev-machine.md#p-11-寫交付單)上那一個逐字對照。

**怎麼知道成功了**

兩串完全相同。**逐字比對，不要只看頭尾四碼。**

**可能怎麼壞、怎麼處理**

| 症狀 | 原因 | 處置 |
|---|---|---|
| **雜湊不一樣** | 檔案在路上壞了，或被防毒動過手腳，或你拿錯版本 | **停下來。** 重新複製一次再比。還是不一樣就回開發機整包重做。不要「應該只是小問題」硬著頭皮往下 |
| `cd` 說找不到路徑，`C:\hd\` 底下直接出現 `runtime`、`CHECKSUMS.txt` 等一堆檔案 | 解壓目的地只寫了 `C:\hd\`，壓縮檔沒有最上層資料夾 | 把 `C:\hd\` 底下除了壓縮檔與 `verify-package.mjs` 以外的東西刪掉，照上面的指令重解一次。**不要用搬的**，搬漏一個檔案就要到 R-05 才會發現 |
| 解壓很慢或失敗 | 2 萬多個檔案 | 正常會花幾分鐘。失敗就看磁碟空間 |
| `Expand-Archive` 說路徑太長 | Windows 的路徑長度上限 | **把解壓目的地換成很短的路徑**（例如 `C:\hd\`），不要放在桌面底下好幾層。這一條在院內一樣會遇到 |

### R-05 驗收五項（DEP-22 的正本）

**做什麼**

```powershell
.\runtime\node.exe ..\verify-package.mjs --dir .
```

**怎麼知道成功了**

五項全綠。**這一次的輸出才是 DEP-22 的交付物**——整段抄進演練紀錄 §3.2。

**可能怎麼壞、怎麼處理**

| 症狀 | 原因 | 處置 |
|---|---|---|
| 說找不到 `runtime/node.exe` | 路徑或解壓不完整 | 確認你在安裝包目錄裡 |
| 第 3 項倒在 `ENOTFOUND binaries.prisma.sh` | 引擎沒帶到或沒指好 | **這就是整個演練要抓的東西**。在開發機上永遠看不到它，因為那裡早就下載過了 |
| 第 5 項有連線紀錄 | 有東西在偷連外 | **不得交付**。記下哨兵抓到的主機名稱 |
| 全綠 | | 恭喜，DEP-22 這一條過了。**把整段輸出抄下來或拍照**（拍自己的機器可以，院內不行） |

## 3. 模擬院內主機的設定

從這裡開始，**把這台機器當成院內那台**。每一步都照你打算在院內做的方式做。

### R-06 決定三個目錄

**做什麼**

在紙上先寫死，三個目錄**互相不得包含**：

| 用途 | 這次演練用 | 院內要填什麼 |
|---|---|---|
| 安裝包目錄 | `C:\hd\hd-tablet-care-<版本>-<commit>\` | 資訊室指定的路徑 |
| **資料庫目錄** | `D:\hd-data\` | **必須在安裝包目錄之外**（DEP-08） |
| **備份目錄** | `D:\hd-data\backups\`（演練用；院內第一落點可用第二顆 SSD） | **最終落點必須是院內另一台機器**（DEP-06） |

**可能怎麼壞、怎麼處理**

| 想法 | 為什麼不行 |
|---|---|
| 「資料庫放在安裝包裡比較好找」 | 某一次「把舊資料夾整個刪掉再解壓新版」就會把資料庫一起刪掉。**這種事不會發生在第一次更新，會發生在第五次、由另一個人執行的那一次**（DEP-08） |
| 「放在『文件』底下就好」 | 醫院電腦常把「文件」重新導向到雲端同步資料夾，而路徑上看不出來。那等於把資料庫送出院外，同時毀掉檔案鎖（DEP-21） |
| 「用網路磁碟機的代號，反正看起來像本機」 | 看起來像本機，行為是網路檔案系統。**後端會拒絕啟動**，這是《資料庫使用規範》7.2 明文要擋的 |

---

### R-07 建立專用低權限帳號

**做什麼**（以系統管理員身分開啟 PowerShell）

```powershell
net user svc-hdcare <一組夠長的密碼> /add
net localgroup Users svc-hdcare /add
```

**怎麼知道成功了**

`net user svc-hdcare` 查得到這個帳號，且**不在 Administrators 群組裡**。

**可能怎麼壞、怎麼處理**

| 症狀 | 處置 |
|---|---|
| 想用自己的帳號跑就好 | **不行**（DEP-12）。主機是共用的，同一台機器上別的專案的維運人員也有登入權限，而他們不該讀得到病人資料 |
| 院方是網域環境，本機帳號可能不適用 | 這是 Q-27 第 2 題。**D-14 就要問**：本機帳號還是網域帳號、密碼由誰保管、會不會定期強制更換（會的話服務要跟著改） |
| 密碼要多複雜 | 照院方政策。**寫在紙上帶進去，不要存在手機裡** |

---

### R-08 建立 `.env`

**做什麼**

把包內的 `.env.範本` 複製到**安裝包目錄的上一層**，改名為 `.env`：

```powershell
Copy-Item .\.env.範本 ..\.env
notepad ..\.env
```

**正式環境的必填欄位**（其餘留空即用預設值）：

| 變數 | 填什麼 | 填錯會怎樣 |
|---|---|---|
| `DEPLOYMENT_ENV` | `production` | 留空的話，時區檢查不擋、開發用遷移指令不擋、`synchronous` 可被放寬。**正式主機一定要填** |
| `DATABASE_URL` | `file:D:/hd-data/hd.db`（**絕對路徑、正斜線**） | 相對路徑直接拒絕啟動 |
| `BACKUP_DIR` | `D:/hd-data/backups` | 沒填就無法備份，而**更新流程會停在備份那一步** |
| `JWT_SECRET` | 一串隨機值（見下） | 留空拒絕啟動 |
| `API_PORT` | 資訊室登記過的埠 | **正式環境沒填就拒絕啟動**（DEP-37 第 2 項） |
| `NURSE_PORT`／`PATIENT_PORT` | 另外兩個登記過的埠 | 靜態站起不來 |
| `CORS_ORIGINS` | `http://<院內主機>:<NURSE_PORT>,http://<院內主機>:<PATIENT_PORT>` | **填成 localhost 的話，護理站電腦一連就被擋** |
| `PRISMA_ENGINES_DIR` | 安裝包的 `engines\` 絕對路徑 | 留空會去找 `node_modules`，找不到就連外下載 |
| `SUPER_ADMIN_WORK_ID`／`SUPER_ADMIN_INITIAL_PASSWORD`／`SUPER_ADMIN_DISPLAY_NAME` | 第一個最高權限帳號 | 不填也起得來，但**資料庫裡不會有任何帳號，護理端登不進去** |
| `TZ` | `Asia/Taipei` | 見 R-09 |
| `MDM_KIOSK_BASE_URL` | `http://<院內主機>:<PATIENT_PORT>` | 平板佈建時的位址 |
| `LLM_PROVIDER` | `mock`（首波 AI 關閉，DEP-29） | — |

`JWT_SECRET` 的產生方式（**在開發機上先產好寫在紙上**，院內那台沒有方便的產生工具）：

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"
```

**可能怎麼壞、怎麼處理**

| 症狀 | 原因 | 處置 |
|---|---|---|
| 存檔後中文變亂碼 | 記事本以系統預設編碼頁存檔 | `.env` 只填英數字與路徑，避免中文。要編輯就用 UTF-8 存檔 |
| 後端說找不到 `.env` | 放錯位置 | 它要在**安裝包目錄的上一層**，不是包裡面（DEP-13）。也可以用 `HD_ENV_FILE` 指定位置 |
| 路徑寫成 `D:\hd-data\hd.db` | 反斜線 | `DATABASE_URL` 一律用正斜線：`file:D:/hd-data/hd.db` |
| 不知道院內主機位址 | **Q-27 沒問到** | 見下方的警告框 |

> ### ⚠ 位址必須在建置安裝包之前就知道
>
> **兩個 PWA 呼叫後端的位址是在建置時寫進產物裡的**（`VITE_API_BASE_URL`），
> 不是啟動時才讀的。預設值是 `http://localhost:3000`——
> 在護理站那台電腦上開啟護理端時，`localhost` 指的是**那台電腦自己**，不是主機。
>
> 也就是說：**院內主機的位址必須在 [P-04](01-dev-machine.md#p-04-建置三個產物) 建置之前就決定**，
> 建置前把 `VITE_API_BASE_URL=http://<院內主機>:<API_PORT>` 填進開發機的 `.env` 再 `npm run build`。
>
> 這件事與憑證的主體別名是同一個位址（[第三冊](03-tablet-shell.md) K-01），**兩邊必須一致**。
>
> **R-13 就是專門用來抓這個問題的**：一定要從另一台機器連進來測，不要只在主機本機上開。
> 位址到現場才知道的話，唯一的補救是帶著開發機進院重新產生安裝包——
> 那要先確認院方允許外來筆記型電腦接上院內網路（Q-29）。

## 4. 安裝與啟動

### R-10 套用既有遷移（DEP-31）

**做什麼**

```powershell
.\runtime\node.exe .\app\api\scripts\prisma-cli.mjs migrate deploy --schema .\app\api\prisma\schema.prisma
```

**怎麼知道成功了**

列出套用了哪幾個遷移，最後說資料庫已同步。`D:\hd-data\hd.db` 出現了。

**可能怎麼壞、怎麼處理**

| 症狀 | 原因 | 處置 |
|---|---|---|
| `getaddrinfo ENOTFOUND binaries.prisma.sh` | Prisma CLI 找不到引擎，跑去連外下載 | 確認 `.env` 的 `PRISMA_ENGINES_DIR`；確認你用的是 `prisma-cli.mjs` 這個外套，不是直接呼叫 prisma |
| `Error code 14: Unable to open the database file` | 目錄不存在或沒有寫入權限 | 先手動建出 `D:\hd-data\` |
| 拒絕啟動，說資料庫路徑在共用位置 | 你把它放在暫存／公用／桌面／文件／下載底下 | 換一個自己的路徑（DEP-37 第 3 項） |
| 有人建議改用開發用的遷移指令 | | **絕對不可以。** 那一支在偵測到資料庫與遷移歷史對不上時，會提議或直接**重建整個資料庫**（DEP-31） |

---

### R-11 註冊服務

**做什麼**（系統管理員身分）

先**故意做錯一次**，確認它擋得住：

```powershell
.\scripts\service-install.ps1 -Account "<機器名>\svc-hdcare" -DataDir ".\data" -BackupDir "D:\hd-data\backups"
```
→ 應該被擋下，說**資料目錄不得位於安裝包目錄之內（DEP-08）**。

再做對的那一次：

```powershell
.\scripts\service-install.ps1 -Account "<機器名>\svc-hdcare" -DataDir "D:\hd-data" -BackupDir "D:\hd-data\backups" -LockDownDataDir
```

**怎麼知道成功了**

印出「已註冊」，並列出接下來的三件事。中途會要你輸入那個帳號的密碼（不會顯示、不會寫進檔案）。

**可能怎麼壞、怎麼處理**

| 症狀 | 原因 | 處置 |
|---|---|---|
| 「這一支要以系統管理員身分執行」 | 權限不足 | 以系統管理員身分重新開啟 PowerShell |
| 密碼輸入後說帳號或密碼錯誤 | 帳號格式 | 本機帳號寫 `<機器名>\svc-hdcare`，網域帳號寫 `<網域>\svc-hdcare` |
| 沒加 `-LockDownDataDir` | 會出現警告 | **要加**。不加的話資料目錄沿用繼承來的權限，同機其他登入者可能讀得到病人資料（DEP-12） |
| 執行原則擋下 `.ps1` | Windows 預設 | `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` 之後再跑。**這一條在院內要先問過資訊室** |
| 資訊室要求必須是 `services.msc` 看得到的服務 | 目前用的是排程工作 | 這是 Q-27 第 6 題。排程工作在「服務」清單裡看不到，要到工作排程器看。**要換的話只換 `service-install.ps1` 這一支** |

### R-12 啟動並確認

**做什麼**

```powershell
.\scripts\service-start.ps1
.\scripts\service-status.ps1
```

**怎麼知道成功了**

三件事同時成立：

1. 排程工作 `Running`，**執行身分是 `svc-hdcare`**，不是你
2. 本安裝包底下 **3 個行程**（後端、護理端、病人端）
3. 存活檢查 **HTTP 200**

**可能怎麼壞、怎麼處理**

| 症狀 | 原因 | 處置 |
|---|---|---|
| 只有 1 或 2 個行程 | 有一個倒了 | **啟動器的設計是任何一個倒下就三個一起停**，所以看到 1～2 個多半是正在收尾。看紀錄檔找真正的錯 |
| 存活檢查連不上 | 服務沒起來，或埠與 `.env` 的 `API_PORT` 不一致 | `.\scripts\service-status.ps1 -ApiPort <埠>` 指定埠再試 |
| 行程數是 0 | 排程工作跑起來就死 | 多半是 `.env` 有問題。**直接用前景跑一次看錯誤**：`.\runtime\node.exe .\scripts\run-all.mjs` |
| 說連接埠被佔用 | 這台機器上有別的東西在用 | 換一個埠，並記下來——**院內十之八九也會遇到**（DEP-37 第 2 項） |

---

### R-13 ⚠ 從另一台機器連進來（**最容易被跳過、也最會出事的一步**）

**做什麼**

用**另一台**電腦（不是主機本身）的瀏覽器開 `http://<主機 IP>:<NURSE_PORT>`，試著登入。

**怎麼知道成功了**

畫面出得來，**而且登得進去**。

**可能怎麼壞、怎麼處理**

| 症狀 | 原因 | 處置 |
|---|---|---|
| 畫面出得來，但登入沒反應／一直轉 | **`VITE_API_BASE_URL` 是 localhost**，護理端在向那台電腦自己要資料 | 見 R-08 的警告框。要用院內主機位址重新產生安裝包 |
| 瀏覽器主控台出現 CORS 錯誤 | `.env` 的 `CORS_ORIGINS` 沒填院內位址 | 補上護理端與病人端兩個來源，重新啟動服務 |
| 整個連不上 | Windows 防火牆 | 要開三個埠的輸入規則。在演練機上先練一次：<br>`New-NetFirewallRule -DisplayName "HD API" -Direction Inbound -LocalPort <埠> -Protocol TCP -Action Allow` |
| 只有主機自己開得起來 | 同上 | **院內的護理端是開在護理站的電腦上，不是主機上。主機自己開得起來完全不代表能用** |

---

### R-14 權限反向測試

**做什麼**

用**一般登入者**的帳號（不是管理員、也不是 `svc-hdcare`）開啟 `D:\hd-data\`。

**怎麼知道成功了**

**拒絕存取。**

**可能怎麼壞、怎麼處理**

| 症狀 | 處置 |
|---|---|
| 看得到裡面的檔案 | `-LockDownDataDir` 沒生效。重跑 R-11，或手動收權限：`icacls D:\hd-data /inheritance:r` 再逐一授權 |
| 沒有第二個帳號可以測 | 建一個臨時的：`net user tester <密碼> /add`。**測完刪掉** |

---

### R-15 重新開機

**做什麼**

把機器重新啟動，**不要登入**，等兩分鐘，再登入查狀態。

**怎麼知道成功了**

`.\scripts\service-status.ps1` 顯示 Running、3 個行程、存活檢查 200。

**可能怎麼壞、怎麼處理**

| 症狀 | 原因 | 處置 |
|---|---|---|
| 服務沒起來 | 排程工作的觸發條件是「開機時」，但帳號密碼可能失效 | 到工作排程器看「上次執行結果」。常見原因是服務帳號沒有「以批次工作登入」的權限 |
| 要登入才會起來 | 註冊時的設定不對 | 重跑 R-11 |
| 起來了但連不上 | 開機時另一個專案先佔走了埠 | **這正是 DEP-37 第 2 項在講的事**，而且它只會在重新開機時發作。記下來，回報資訊室 |

---

### R-16 在服務執行帳號底下確認時區與執行身分

**做什麼**

護理端 → 系統管理 → 維運狀態。

**怎麼知道成功了**

四件事都對：

| 看什麼 | 應該是 |
|---|---|
| 伺服器時區 | `Asia/Taipei` |
| **執行身分** | `svc-hdcare`，**不是你現在登入的帳號** |
| 連接埠 | 你在 `.env` 填的那個，且標示為「來自主機設定」而非程式預設值 |
| 資料庫磁碟可用空間 | 綠的，高於 `DB_DISK_MIN_FREE_MB` |

> **主機時區正確，不代表服務執行帳號取得的時區正確**（DEP-15）。這一頁是唯一看得到後者的地方。

## 5. 功能面的冒煙測試

### R-17 走一次主線

**做什麼**

照《[完整手動測試手冊](../testing/manual-test-guide.md)》§02 冒煙測試與 §03 主線 A：
登入 → 改密碼 → 建病人 → 建排班 → 指派平板 → 病人端顯示 → 解除綁定 → 稽核查得到。

**怎麼知道成功了**

每一步都如手冊所述。**這一段走不完，就不要進醫院。**

**可能怎麼壞、怎麼處理**

| 症狀 | 原因 | 處置 |
|---|---|---|
| 登入頁出得來但沒有任何帳號 | `SUPER_ADMIN_*` 沒填 | 補進 `.env`，重新啟動服務。**資料庫不必重建** |
| 平板端顯示「裝置尚未佈建」 | 正常。那是給佈建用的畫面 | 在護理端「裝置管理」註冊一台，拿到金鑰再連 |
| 某個功能整個不見 | 首波功能開關關閉（DEP-29） | **這是正確行為**：關閉的功能連後端端點一起擋下，不以灰色按鈕呈現（DEP-34） |

---

### R-18 病人端斷網仍開得出畫面

**做什麼**

用另一台裝置開病人端、等畫面出來之後，**把那台裝置的網路斷掉**，重新整理。

**怎麼知道成功了**

畫面照樣出得來；求助區在原來的位置、原來的大小，**而且明確顯示現在通知不到護理師**。

**可能怎麼壞、怎麼處理**

| 症狀 | 原因 | 處置 |
|---|---|---|
| 斷網後一片空白 | Service Worker 沒註冊成功 | 看 [P-04](01-dev-machine.md#p-04-建置三個產物)：產物裡有沒有 `sw.js`。**這一條不成立，選 PWA 的唯一理由就沒了** |
| 求助按鈕按得下去但沒有任何提示 | 離線狀態沒顯示 | 記成缺陷。**能按而沒有回應是最糟的那一種** |

詳細項次見[迭代 10 分冊](../testing/iteration-10.md) `t16`–`t22`。

## 6. 更新與回退，在這台機器上各做一次

### R-19 停止服務並確認停乾淨

**做什麼**

```powershell
.\scripts\service-stop.ps1
.\scripts\service-status.ps1
```

**怎麼知道成功了**

行程數 **0**。

**為什麼要確認「都」停了**：剩下任何一個還開著資料庫檔案，接下來的備份就是在一個還在被寫入的檔案上做的（DEP-10）。

---

### R-20 更新演練

**做什麼**

用一個新版本的安裝包（可以只是把 [P-06](01-dev-machine.md#p-06-建置安裝包) 再跑一次），照這七步：

| 順序 | 動作 | 跳過會怎樣 |
|---|---|---|
| 1 | 停止服務 | 資料庫還有寫入時做的備份不可靠 |
| 2 | 備份，**並驗證它還原得起來** | 「有備份」和「備份能用」是兩件事 |
| 3 | **舊版目錄改名，不要刪** | 沒有可以退回去的東西 |
| 4 | 解壓新版到新目錄 | |
| 5 | 套用遷移（R-10 那一支） | |
| 6 | 啟動，確認主線功能 | |
| 7 | 寫進更新紀錄 | 半年後沒有人答得出資料是哪一次更新弄壞的 |

**可能怎麼壞、怎麼處理**

| 症狀 | 處置 |
|---|---|
| 想直接把舊目錄刪掉再解壓 | **不要。** 第 3 步是回退唯一的依靠 |
| 新版的 `.env` 要重寫嗎 | 不用。`.env` 在安裝包目錄之外，整包換掉也不會被蓋掉——**這正是 DEP-08 那條界線的用處** |

---

### R-21 回退演練

**做什麼**

把 R-20 那次更新前的備份還原到另一個檔案，再把舊版目錄換回來。

**怎麼知道成功了**

雜湊相符、完整性檢查 ok、筆數與更新前一致；還原出來的那份**沒有**這次遷移新增的欄位。

> **程式可以退版，資料庫不行退版。** 動過 schema 的版本要回退，是**還原備份再換回舊版程式**，
> 不是把遷移倒回去。
