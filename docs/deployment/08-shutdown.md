# 第八冊 · 把服務關乾淨

版本：v0.1　文件狀態：草案　編號：`S-xx`　**這一冊要印出來帶進去**

> [總覽第 6 節](index.md#6-什麼情況下當場停手)、[第四冊第 10 節](04-onsite.md#10-隨時可以停手)、
> [第六冊 X-36](06-troubleshooting.md#x-36-今天做不完要怎麼乾淨地撤退) 都說「把服務停掉」，但沒有說怎麼停、停到什麼程度、
> 怎麼證明真的停了。這一冊補上這三件事。
>
> 會用到它的情形不只撤退：備份與還原、資料修補、換版、主機維護與重新開機、試用結束要撤除，都要先關服務。

---

## 0. 先講結論

**「關乾淨」有四條判準，四條都成立才算數**，腳本印出「已停止」不算：

| # | 判準 | 為什麼要看這一條 |
|---|---|---|
| 1 | 排程工作 `HD-TabletCare` 不是 `Running` | 它還在跑，一分鐘內就可能把行程重新帶起來 |
| 2 | **本安裝包底下**的 `node.exe` 行程是 0 個 | 排程工作停的只是啟動器，三個子行程要另外確認（DEP-12 落實方式） |
| 3 | 三個連接埠（`API_PORT`、`NURSE_PORT`、`PATIENT_PORT`）沒有任何行程在聽 | 行程名稱對不上時的第二道確認 |
| 4 | 資料庫檔案可以被獨占開啟 | **這一條才是備份與還原真正在乎的**。還有人開著它，備份就是在一個還在被寫入的檔案上做的（DEP-10） |

**關服務有三種深度，先想清楚要哪一種：**

| 深度 | 做什麼 | 重新開機後 | 什麼時候用 |
|---|---|---|---|
| **一、暫停** | 停掉行程 | **會自己起來**（排程工作的觸發條件是開機時） | 備份、還原、資料修補、換版（[第二冊 R-20](02-dry-run.md#r-20-更新演練) 第 1 步） |
| **二、停用** | 暫停 ＋ 停用排程工作 | 不會起來，要手動恢復 | 主機維護、系統更新要重新開機；[總覽第 6 節](index.md#6-什麼情況下當場停手)的停手撤退；問題查清楚前不准再有人用 |
| **三、撤除** | 停用 ＋ 移除排程工作與主機上的設定 | 不會起來，也沒有東西可以恢復 | 試用結束、院方書面要求移除 |

> **三種深度都不刪資料庫與備份。** 病人資料的去向是院方的決定，不是部署的人在現場的決定。
> 撤除也一樣：資料交給院方，由院方決定留存或銷毀（見 [S-09](#s-09-資料與備份交給院方)）。

**拿不定主意時選「停用」。** 停用多做的只有一行指令，恢復也只要一行；
暫停卻會在下一次重新開機時，讓一個你以為關掉的系統悄悄回來，而護理師會開始用它。

## 1. 關之前

### S-01 先告訴病房

**做什麼**

找護理長或當班的負責護理師，講清楚四件事：

1. **什麼時候開始停、預計停多久**
2. **停機期間照原本的紙本流程做**，恢復之後要不要補登由護理長決定
3. **病人平板上的「求助」按鈕停機期間通知不到護理站**——平板會告訴病人「目前無法即時通知護理站」，但護理師要知道這件事，改用床邊的原有叫人方式
4. 症狀回報會先存在平板上，**恢復連線後自動補傳**，不必重填（撤除的情形例外，見 [S-07](#s-07-撤除前先讓平板把資料送完)）

**怎麼知道成功了**

對方複述得出「幾點到幾點、這段時間用紙本、求助按鈕沒用」。

**可能怎麼壞、怎麼處理**

| 症狀 | 處置 |
|---|---|
| 正在透析班次中，找不到空檔 | **能等就等到班次之間。** 不能等（例如資料有問題必須立刻停）就停，但一定要先講完第 3 點 |
| 「停一下而已，不用講吧」 | 要講。**求助按鈕沒有反應、而護理師不知道**，是這一冊裡唯一會直接傷到病人的情形 |
| 找不到任何護理人員可以告知 | 寫在紙上貼在護理站，並記進紀錄。**不要默默停** |

---

### S-02 確認要關的是哪一包，並先看一眼會被收掉的行程

**做什麼**

以**系統管理員身分**開 PowerShell：

```powershell
cd C:\hd\hd-tablet-care-<版本>-<commit>
.\scripts\service-status.ps1
Get-CimInstance Win32_Process -Filter "Name = 'node.exe'" | Select-Object ProcessId, CommandLine | Format-List
```

**怎麼知道成功了**

- `service-status.ps1` 列出排程工作、執行身分、行程數；**抄下來**，這是停之前的樣子
- 下面那張清單裡的每一個 `node.exe`，你都說得出它是誰的。本系統的三個，命令列裡都有**這一包的路徑**

**可能怎麼壞、怎麼處理**

| 症狀 | 處置 |
|---|---|
| 清單裡有**別的專案**的 `node.exe`，命令列裡剛好有 `dist\main.js`、`static-server.js` 或 `run-all.mjs` | **不要跑 `service-stop.ps1`**，改走 [S-03](#s-03-停止服務) 的「共用主機」做法。那支腳本是靠命令列裡的這幾個字串找行程的，**會把別人的行程一起收掉** |
| 主機上有兩包本系統（新舊版並存） | 只有一包該有行程在跑。`service-status.ps1` 會從它自己那一包算行程數，**在正在跑的那一包底下執行** |
| 開不了系統管理員身分的 PowerShell | 這一冊的每一步都需要。請資訊室的人來，或由他操作、你在旁邊唸 |

## 2. 深度一：暫停

### S-03 停止服務

**做什麼**

一般情形：

```powershell
.\scripts\service-stop.ps1
```

共用主機、而 S-02 看到有別人的行程會被誤收時，改成只收這一包底下的行程：

```powershell
$pkg = (Get-Location).Path
Stop-ScheduledTask -TaskName HD-TabletCare
Start-Sleep -Seconds 2
Get-CimInstance Win32_Process -Filter "Name = 'node.exe'" | Where-Object { $_.CommandLine -like "*$pkg*" } | ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
```

**怎麼知道成功了**

腳本印出「已停止」只是開始，**接著做 S-04**。

**可能怎麼壞、怎麼處理**

| 症狀 | 處置 |
|---|---|
| `Stop-Process` 說存取被拒 | 不是系統管理員身分。行程屬於服務帳號，一般身分收不掉它 |
| 有人想直接在工作管理員裡把 `node.exe` 結束掉 | **不要。** 只結束其中一個，啟動器會把其餘兩個一起收掉並以失敗結束，排程工作一分鐘後就重試——等於重新啟動 |
| 想先把 `.env` 改壞讓它起不來 | 不要。那是讓它每分鐘失敗一次，不是停止；要它不起來請用 [S-05](#s-05-停用排程工作) |

---

### S-04 驗證四條判準

**做什麼**

照 [第 0 節](#0-先講結論)的四條，一條一條看。`<…>` 換成 `.env` 裡的值：

```powershell
# 1. 排程工作
Get-ScheduledTask -TaskName HD-TabletCare | Select-Object TaskName, State

# 2. 本安裝包底下的行程
$pkg = (Get-Location).Path
Get-CimInstance Win32_Process -Filter "Name = 'node.exe'" | Where-Object { $_.CommandLine -like "*$pkg*" } | Select-Object ProcessId, CommandLine

# 3. 三個連接埠
Get-NetTCPConnection -State Listen -LocalPort <API_PORT>, <NURSE_PORT>, <PATIENT_PORT> -ErrorAction SilentlyContinue

# 4. 資料庫檔案能否獨占開啟
$db = "<資料目錄>\<資料庫檔名>"
try { $fs = [IO.File]::Open($db, 'Open', 'ReadWrite', 'None'); $fs.Close(); "沒有人開著它" } catch { "仍被佔用：$($_.Exception.Message)" }
```

**怎麼知道成功了**

| # | 應該看到 |
|---|---|
| 1 | `State` 是 `Ready`（停用過則是 `Disabled`），**不是 `Running`** |
| 2 | 什麼都沒印 |
| 3 | 什麼都沒印 |
| 4 | `沒有人開著它` |

再到護理站電腦重新整理護理端：**畫面可能還出得來**（PWA 會用快取的頁面），但登入或讀資料會失敗。這是對的。

**可能怎麼壞、怎麼處理**

| 症狀 | 原因 | 處置 |
|---|---|---|
| 第 1 條還是 `Running` | 排程工作沒停成 | 再跑一次 `Stop-ScheduledTask`；還是一樣就到工作排程器裡對它按「結束」 |
| 第 2 條有行程、第 1 條是 `Ready` | 子行程沒跟著收掉 | 照 S-03 共用主機那一段，只收這一包底下的 |
| 過一兩分鐘又冒出行程 | 有人在工作管理員裡結束過行程，失敗重試被觸發了 | 做 [S-05](#s-05-停用排程工作)，再回頭做 S-03 |
| 第 3 條有東西，但第 2 條是空的 | 那個埠被**別的程式**佔著 | 看它的 `OwningProcess` 是誰。**不是本系統的就不要動它**，記下來，下次啟動時會撞埠 |
| 第 4 條「仍被佔用」，但第 2、3 條都是空的 | 防毒即時掃描、備份軟體，或有人用其他工具開著資料庫 | [第六冊 X-14](06-troubleshooting.md#x-14-database-is-locked)。**九成是防毒**，就是 H-14 ① 沒做 |
| 資料目錄裡還有 `-wal`、`-shm` 兩個檔 | **正常。** 行程是被強制結束的，最後一段寫入還在 `-wal` 裡，下次啟動會自動併回主檔 | **不要刪。** 要搬、要備份，三個檔一起（DEP-09） |

---

### 恢復

```powershell
.\scripts\service-start.ps1
.\scripts\service-status.ps1
```

排程工作 `Running`、3 個行程、存活檢查 HTTP 200，**再告訴病房已經恢復**。

## 3. 深度二：停用

### S-05 停用排程工作

**做什麼**

先做完 S-03、S-04，再：

```powershell
Disable-ScheduledTask -TaskName HD-TabletCare
Get-ScheduledTask -TaskName HD-TabletCare | Select-Object TaskName, State
```

**怎麼知道成功了**

`State` 是 `Disabled`。重新開機後再跑一次 S-04，四條仍然成立。

**可能怎麼壞、怎麼處理**

| 症狀 | 處置 |
|---|---|
| 主機要重新開機，但來不及驗證開機後的狀態 | 至少在紀錄裡寫「已停用，重新開機後未驗證」，並請資訊室開機後代跑 `service-status.ps1` |
| 停手撤退、下一次不知道什麼時候 | **一定用停用，不要只暫停。** 你走之後主機一重新開機，一個半成品就會自己跑起來 |

### 恢復

```powershell
Enable-ScheduledTask -TaskName HD-TabletCare
.\scripts\service-start.ps1
.\scripts\service-status.ps1
```

## 4. 深度三：撤除

**撤除要有院方的書面指示**（誰要求、哪一天、資料怎麼處理）。口頭說「這個不用了，拆掉吧」不夠：
撤除之後就沒有回頭路，而資料的去向必須有人負責。

### S-06 撤除前的最後一次備份

**做什麼**

服務還在跑的時候，照 [第四冊 H-17](04-onsite.md#h-17-備份與還原實測這一條最常被跳過) 做一次備份，
**還原到另一個檔案驗證過**，並確認它落在院內另一台機器（DEP-06）。

**怎麼知道成功了**

還原後雜湊相符、完整性檢查 ok、筆數對得上。這一份就是交給院方的最終版本。

**可能怎麼壞、怎麼處理**

| 症狀 | 處置 |
|---|---|
| 備份失敗 | **撤除停在這裡。** 沒有驗證過的最終備份，不要往下走 |
| 院方說「資料不要了」 | 仍然要做這一份。「不要了」要寫進書面指示，由院方決定銷毀，不是由你決定不備份 |

---

### S-07 撤除前先讓平板把資料送完

**做什麼**

平板上暫存、還沒補傳的症狀回報，服務一撤除就再也送不出去。
**最後一次備份之前**，讓每一台還在用的平板都連上過一次，等它自動補傳。

**怎麼知道成功了**

每一台平板都在連線狀態下停留過幾分鐘，護理端看得到那段期間的回報。

**可能怎麼壞、怎麼處理**

| 症狀 | 處置 |
|---|---|
| 某一台平板找不到或沒電 | 記下平板編號，寫進交接：**那一台上可能有沒送出的回報** |
| 平板已經先被收走了 | 同上。之後就算找回來，也沒有伺服器可以收 |

> 求助不會暫存（送不出去就當場告訴病人），所以這一步只跟症狀回報有關。

---

### S-08 移除排程工作與主機上的設定

**做什麼**

依序做完 S-01、S-03、S-04、S-05，然後：

| # | 要收的東西 | 誰做 | 怎麼做 |
|---|---|---|---|
| 1 | 排程工作 | 你 | `.\scripts\service-uninstall.ps1`，再 `Get-ScheduledTask -TaskName HD-TabletCare` 應該找不到 |
| 2 | 三個埠的防火牆輸入規則 | **資訊室**（當初由他們開的，[H-15](04-onsite.md#h-15-防火牆與從護理站連進來)） | 請他們關掉，並當場確認 |
| 3 | 防毒排除清單裡的資料庫目錄 | 資訊室或你（[H-14 ①](04-onsite.md#h-14-windows-五件事需要資訊室)） | **資料目錄清空或交出之後才移除**。排除清單留著一個已經不用的目錄，是給別人留了一個防毒不看的地方 |
| 4 | 服務帳號 | **資訊室**（[H-12](04-onsite.md#h-12-建立服務帳號需要資訊室)） | 請他們停用或刪除 |
| 5 | `.env` | 你 | 刪除。**裡面有密碼與金鑰**，它在安裝包目錄的上一層，刪安裝包不會帶走它 |
| 6 | 安裝包目錄（含改名保留的舊版） | 你 | 排程工作移除之後才刪 |
| 7 | 休眠、系統更新時段（H-14 ④⑤） | 資訊室 | 這兩項是整台主機的設定，**要不要改回來由資訊室決定**，不要自己改 |

**怎麼知道成功了**

- `Get-ScheduledTask -TaskName HD-TabletCare` 找不到
- S-04 第 3 條什麼都沒印
- 安裝包目錄與 `.env` 都不在了
- 上表每一列都有人、有時間，寫進紀錄

**可能怎麼壞、怎麼處理**

| 症狀 | 處置 |
|---|---|
| 刪安裝包目錄時說檔案被使用中 | 還有行程沒收掉，回 S-04 第 2 條 |
| 資訊室當天沒空關防火牆、停帳號 | 記下來，約好時間，**寫進交接文件的待辦**。埠開著但沒人聽不危險，帳號留著不用才危險 |

---

### S-09 資料與備份交給院方

**做什麼**

資料目錄、備份目錄、S-06 那一份最終備份，**一律不在現場刪除**。
照書面指示交給院方指定的人，當面說清楚：

1. 檔案在哪裡、哪一份是最終版、雜湊是多少
2. `-wal`、`-shm` 與主檔是一組，要搬三個一起搬（DEP-09）
3. 要銷毀的話，由院方人員執行，並依院方的病歷資料銷毀規定留紀錄

**怎麼知道成功了**

交接文件上有對方簽名，寫明收下了哪些目錄、最終備份的雜湊。

**可能怎麼壞、怎麼處理**

| 症狀 | 處置 |
|---|---|
| 「你幫我們刪一刪就好」 | 不行。請院方人員自己按刪除，你在旁邊確認路徑對不對 |
| 想帶一份回去「以防萬一」 | **絕對不可以。** 病人資料不得離院，與 DEP-28 清除隨身碟是同一件事 |

---

## 5. 關完要寫下來

不管哪一種深度，都寫進《[部署演練紀錄](../notes/deployment-drills.md)》或更新紀錄：

- [ ] 哪一種深度、為什麼要關、誰同意的
- [ ] 開始與結束的時間；告知了病房的誰（S-01）
- [ ] S-04 四條判準的結果，**有任何一條不是一次就過的，寫下原因**
- [ ] 誰負責恢復、預計什麼時候恢復（暫停與停用）
- [ ] S-08 那張表的每一列、S-09 交給了誰（撤除）

> **沒有寫下來的停機，下一個人只會看到「系統壞了」。** 半年後有人重新開機發現它沒起來，
> 紀錄是唯一能告訴他「這是故意停用的，要先問過誰」的東西。
