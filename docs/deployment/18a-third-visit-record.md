## 3. 發現

### O-01 1001 的名單是對的

J-07 抄到三樣，第十五冊之三 3.2 節那張判斷表落在第三列：

| 抄什麼 | 1001 留下的值 |
|---|---|
| `.env` 的 `CORS_ORIGINS` | `http://<名稱>:18080` |
| 執行中後端的日誌最後一行（10/01 17:11 啟動） | `允許的前端來源：http://<名稱>:18080` |
| 護理端網頁裡寫死的後端位址 | `http://<名稱>:13000`，與 `.env` 的 `HD_PUBLIC_API_URL` 一致 |

- **不是可能 A（名單寫錯），也不是可能 B（改完沒 `up -d`）**；網頁裡的位址也不是舊的（3.3 節第二個坑排除）
- 剩下的嫌疑是 3.3 節第一個坑（網址列用 `localhost` 開，1001 的 17:45 問過）或**護理站查不到 `<名稱>`**。1029 換成 IP 之後護理站直接登得進去，這兩者已經無法再分辨
- 對之後的意義：**主機位址一律用 IP**，名稱在院內不一定查得到

### O-02 `v0.4.0` 沒通過第十七冊的判定就帶進院

第十七冊 1029 第一輪的判定是「`v0.4.0` 還不能帶進院」：I-13～I-15（模擬院方 API、三支 `verify --live`、退回 `v0.3.0` 演練）沒做。這次沒有補演練就照第十八冊進院。實際上 J-15～J-21 都順利，但**退回舊版這一條路在院內從來沒演練過**。下一個 tag 進院前，第十七冊整輪做完、判定通過才帶。

### O-03 重新開機測試不被允許

同機另一個專案不能停，主機上還有其他程式在作業，院方不允許關機。J-25 跳過，冒煙測試第 9 列寫「未驗」。影響：斷電之後服務會不會自己回來、紅框幾分鐘消失，都還不知道。要請院方排一個另一個專案也能停的時段，或請資訊室確認那個專案能不能接受重新開機。

### O-04 防毒排除仍是空的

與 1001 相同（M-05），這次查到之後**沒有跟資訊室提**。第十八冊的規則照舊：**排除清單加上之前，這台主機不得輸入真實病人資料**。下一次要帶著 Docker 資料夾的路徑去找資訊室。

### O-05 該問院方的都沒問

- J-02 的八題一題都沒問。第 1 題由現場判斷：主機 IP 與透析室另一個系統相同，判斷沒選錯；第 8 題：暫用平板是透析室的舊平板，到透析室自動連上院內網路（不是訪客網路），醫師同意裝 App
- J-22 第 4 步「備份資料夾由誰、多久送往另一台機器」沒問
- J-32 第 2 步「Git 是誰裝的」「`C:\hd` 院方同不同意」仍空白（1001 的 M-02、M-03 也還空著）

### O-06 沒有交接

J-31 沒做，交接紙沒寫。**管理者帳號的密碼目前由開發端保管**（第十八冊寫由護理長決定、保管），平板的 PIN 也在開發端。下一次進院把兩者移交給護理長，由護理長自己改密碼。

### O-07 冒煙測試在部署主機上做

- J-14 在護理站登入成功：護理站的電腦要 Windows 密碼，開發端不知道，由附近的護理師輸入；用的是護理站其中一台，螢幕會休眠

### O-08 J-18 在透析時段停了後端

15:41 停後端時透析室正在治療（J-26 的探測顯示 16:23 有 34 次透析進行中），沒有跟護理站講。這次系統還沒有人在用、病人 0，沒有影響。**系統開始使用之後，J-18 一定排在沒有透析的時段，並先告知護理站**（第十八冊第 4 節開頭已寫，這次沒照做）。

### O-09 院方 API 的位址與報備

位址取自同一位醫師先前另一個計畫用的 API，醫師說過可以參考並直接使用。可以直接用、還是要走院方流程（Q-35），這次沒談，下次開會問清楚。位址照第十八冊只在 `Read-Host` 當場輸入，做完 `Remove-Variable u`；不寫進 `.env`。

### O-10 院方 API 的實際長相

完整輸出在《[部署演練紀錄](../notes/deployment-drills.md)》第 12.1 節，要點：

- 主機連得到院方 API：HTTP 200、一次成功、1.7 秒、回應約 270 KB；沒有模擬標頭
- `data_list` 601 列，每列 51 欄，**與預期的 51 欄相符**；依病歷號＋開始時間分組是 89 次透析，格式不符 0 次
- **回應的第一個 `{` 之前有 25 個字元，是一個 `<meta>` 標籤**：JSON 前面夾了 HTML，探測工具照樣解析成功；正式同步要確認也會跳過
- 床位有三種樣式：`A9`（字母＋數字）429 列、`9A` 90 列、`99`（兩位數字）82 列
- 姓名欄 601 列都含「〇」（遮罩），88 位病人
- 16:23 有 34 次透析進行中：結束體重是空字串；其中 2 次已有結束時間、還沒有結束體重
- 結束收縮壓、結束舒張壓、膜上壓各有 162 列是 `0`，結束體重、實際脫水量各有 162 列是空字串；列數相同，推測是同一批還沒有結束值的列——「沒有值」有 `0` 與空字串兩種寫法，判定下機時要兩種都當成「還沒結束」
- 交給開發端對照實作規格書 4.19 的假設（下機怎麼判定、床號長什麼樣）
