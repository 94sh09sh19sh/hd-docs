## 摘要

- 院內現況（1116）：外殼 `v0.3.0`（`services/shell-builder/shell.pin` 釘的，契約第 1 版）；APK 與金鑰 1001 在院內主機上建好；暫用平板 1 台（Galaxy Tab S6 Lite，序號 `TB-00`）1029 佈建、1116 帶回，**已註冊、固定中，放在醫師桌上，還沒指派病人**（第 0.1 節）
- 外殼 APK 在院內主機上由一次性容器 `shell-builder` 離線建置與簽章，平板從病人端的院內下載頁安裝；私鑰全程不離開主機（第 0.2、0.3 節）
- 主機這一層：外殼 repo 的部署金鑰與 clone、`.env` 三項、建映像檔、建 APK、備份金鑰、病人端改走 HTTPS、平板連得進來（Y-01～Y-08）

- 金鑰每年核對一次備份；資料卷壞了從備份還原，**不要重新產生**（第 7 節）
- 平板採購規格、到貨後每台的檢查與紀錄、平板還沒到要問什麼、交給護理師的每日一頁、守不住什麼（第 10～14 節，`K-xx`）
- 與《從零部署本系統》的對應：Y-02～Y-13 ＝ V-20～V-28（[《從零部署本系統》](ref-fresh-install.md)）；1029 現場照做的版本是 J-27～J-29（[《第三次進院之一：詳細版》](visit-3-system-detail.md)）

規則的真本是《[部署規範](../requirements/deployment-spec.md)》第 7、8 章；外殼與系統之間的介面見《[病人端外殼 App 契約](../reference/kiosk-shell-contract.md)》。這一份只寫手指要按什麼、每一步會怎麼壞。

### 0.2 這一份做什麼

| 步驟 | 在哪裡做 | 產生什麼 |
|---|---|---|
| 取外殼原始碼 | 主機：以外殼 repo 的部署金鑰 clone | `$root\hd-kiosk-shell\` |
| 建 APK | 主機：`shell-builder`（一次性容器，**執行時沒有網路**） | 院內 CA、伺服器憑證、簽章金鑰（**只在第一次**）、APK、下載頁 |
| 病人端改走 HTTPS | 主機：重新啟動 `patient-web` | 病人端以院內 CA 簽的伺服器憑證提供 HTTPS |
| 裝到平板 | 平板：瀏覽器開院內下載頁 | 平板上的「透析照護平板」 |

**私鑰全程不離開主機**：CA 與簽章金鑰在 `shell-builder` 裡產生、存在資料卷 `hd-tablet-care-keys`，備份時寫到備份目錄、隨資料庫備份一起送往院內另一台機器（DEP-35）。

### 0.3 東西放在哪裡（本系統之外多出來的）

| 東西 | 位置 | 為什麼 |
|---|---|---|
| 外殼原始碼 | `$root\hd-kiosk-shell\`（`git clone` 下來的，**不必切 tag**） | `shell-builder` 自己從這份 clone 取出本系統釘住的那一版（`services\shell-builder\shell.pin`） |
| 院內 CA、伺服器憑證、簽章金鑰、下載頁 | 資料卷 `hd-tablet-care-keys` | 私鑰不離開主機；病人端靜態服務唯讀掛它，只讀得到伺服器憑證與下載頁 |
| 金鑰備份 | `$root\backups\keys\` | **裡面有私鑰**，與資料庫備份一樣送往院內另一台機器，不得出院 |

`$root` 🏥 是 `C:\hd\hd-tablet-care`（1001 起；0927 原文寫的 `D:\hd-tablet-care` 沒用上，院內主機的 D 槽空間不夠）；🧪 開發機演練是 `C:\hd-sim`。

### 0.4 開工三行

所有指令都在主機的 PowerShell、`$root\repo` 底下下。每開一個新的 PowerShell 視窗先打（與 [《從零部署本系統》](ref-fresh-install.md) V-09 相同）：

```powershell
$root = "C:\hd\hd-tablet-care"          # 🧪 開發機演練改成 C:\hd-sim
$cfg  = "$root\config\.env"
cd $root\repo
```

看到 `couldn't find env file`，十次有九次是忘了這三行。

### 0.5 先接受的一件事

**平板第一次下載 APK 走的是 HTTP。** 那時平板還不信任院內 CA，下載頁若只有 HTTPS，平板的瀏覽器會先跳一個「連線不是私人連線」給拿平板的人看。因此病人端的埠同時接 HTTP 與 HTTPS，**HTTP 只留下載頁**，其餘一律轉到 HTTPS。下載頁上列出 APK 與簽章憑證的 SHA-256，要核對可以對照 Y-05 的輸出；Android 本身也會擋下簽章不同的覆蓋安裝。

## 2. 主機這一層

### Y-02 外殼 repo 的部署金鑰與 clone（DEP-43）

**一把部署金鑰只能對應一個 repo**，外殼 repo 另產生一把。做法與本系統 repo 的部署金鑰相同（[《從零部署本系統之一：容器路線的原冊》](ref-fresh-install-detail.md) W-09），只是名稱不同：

```powershell
ssh-keygen -t ed25519 -C "hd-kiosk-shell@$(hostname)" -f $HOME\.ssh\hd-kiosk-shell -N '""'
Get-Content $HOME\.ssh\hd-kiosk-shell.pub
```

把印出來的那一行交給 repo 管理者，登記到**外殼 repo**（`hd-kiosk-shell`）的 **Settings → Deploy keys**，**不要勾 Allow write access**。 `$HOME\.ssh\config` 再加一段：

```
Host github-hd-kiosk-shell
    HostName github.com
    User git
    IdentityFile ~/.ssh/hd-kiosk-shell
    IdentitiesOnly yes
```

然後 clone（**不必 checkout tag**）：

```powershell
ssh -T github-hd-kiosk-shell
git clone git@github-hd-kiosk-shell:94sh09sh19sh/hd-kiosk-shell.git $root\hd-kiosk-shell
git -C $root\hd-kiosk-shell tag
```

**怎麼知道成功了**：`ssh -T` 印出 `Hi <帳號>/hd-kiosk-shell!…`（**是 `hd-kiosk-shell`，不是 `hd-tablet-care`**）；`git tag` 列得出 Y-01 的那一版。以前的版本也會一起列出來（1001 是 `v0.2.0`、`v0.3.0` 兩行），這是正常的：`shell-builder` 只取 `shell.pin` 釘住的那一個。

| 症狀 | 處置 |
|---|---|
| `ssh -T` 印出的是 `hd-tablet-care` 而不是 `hd-kiosk-shell` | `config` 裡兩段的 `IdentityFile` 寫反，或少了 `IdentitiesOnly yes` |
| `Permission denied (publickey)` | 公鑰登記到本系統的 repo 去了。一把金鑰只能給一個 repo |

### Y-03 `.env` 補三項

```powershell
notepad $cfg
```

| 變數 | 填什麼 |
|---|---|
| `HD_SHELL_SRC_DIR` | 外殼 clone 的位置：🏥 `C:\hd\hd-tablet-care\hd-kiosk-shell`；🧪 `C:\hd-sim\hd-kiosk-shell` |
| `HD_SHELL_SIGNING` | 🏥 院內主機填 `hospital`（範本預設就是）；🧪 開發機演練填 `dev` |
| `MDM_KIOSK_BASE_URL` | **`https://`**`<平板要連的主機名稱或 IP>:<病人端埠>`（🏥 `https://<IP>:18081`；🧪 開發機的區網 IP，手機要連得到，`localhost` 不行）。伺服器憑證就簽這個名字，**擇一之後不要再換**（要換照[《護理站登不進去與主機位址》](ref-login.md)） |

`KIOSK_SHELL_MIN_VERSION` 先留白（用程式內建的預設值）。每一行的完整填法見[《`.env` 怎麼填》](ref-env.md)。

**怎麼知道成功了**：`docker compose --env-file $cfg config --quiet` 沒有輸出。

| 症狀 | 處置 |
|---|---|
| `required variable HD_SHELL_SRC_DIR is missing a value` | **每一條 compose 指令都會檢查它**，不只 `shell-builder` 那幾條。填上 |

> `MDM_KIOSK_BASE_URL` 從 `http://` 改成 `https://` 之後，護理端註冊平板時顯示的網址也跟著變。它只寫在 `api` 的環境變數裡，**不必重建映像檔**，`docker compose --env-file $cfg up -d api` 即可。

## 3. 建置

### Y-04 建置 `shell-builder` 的映像檔

```powershell
docker compose --env-file $cfg --profile shell build shell-builder
```

第一次要下載 Android SDK、Gradle 與外殼的全部建置相依（約 1.5 GB）。**這一步可以連外、而且必須連外**；它不掛任何資料卷（DEP-14）。建置時會核對：外殼 clone 裡有沒有釘住的 tag、tag 裡的版本與契約版本對不對、外殼原始碼裡有沒有指向院外的網址。

**怎麼知道成功了**：輸出最後幾行有「✓ 外殼 v0.x.x（…，契約第 1 版）已準備好，相依已下載」（`v0.x.x` 是 `shell.pin` 釘的那一版，1001 起是 `v0.3.0`）。

| 症狀 | 處置 |
|---|---|
| `外殼 repo 的 clone 裡沒有 tag vX.Y.Z` | `git -C $root\hd-kiosk-shell fetch --tags`，再建一次 |
| `tag … 裡的 gradle.properties 宣告的版本是 …，兩者要相同` | 外殼那一版的 tag 打錯了。**開發端的問題**，不在現場修 |
| `外殼 … 實作契約第 N 版，本系統 shell.pin 要的是第 M 版` | 本系統與外殼的版本沒配對。回開發端，不在現場修 |
| `外殼原始碼裡有指向院外的網址` | 同上。這是刻意擋的（FR-S07） |
| 下載 `dl.google.com`、`services.gradle.org`、`maven.google.com` 逾時 | 對外連線被擋。照[《從零部署本系統之一：容器路線的原冊》](ref-fresh-install-detail.md) W-06 查；外殼建置要連的網域完整清單在 Q-32（0930 院方答覆：對外連線是常態、沒有限制） |
| `failed to resolve source metadata for docker.io/library/eclipse-temurin`，後面有 `lookup production.cloudfront.docker.com: no such host` | 下載基底映像時查不到 Docker Hub 的下載站（DNS，1001 院內遇過）。先重跑；`Resolve-DnsName production.cloudfront.docker.com` 查得到就重新啟動 Docker Desktop；主機也查不到、改用 `-Server 8.8.8.8` 才查得到，就是院內 DNS 的問題，找資訊室。單獨測這一段：`docker pull eclipse-temurin:17-jdk-jammy` |
| 停在 `gradle.zip` 那一步很久沒有進度 | 網路太慢或連線卡住。Dockerfile 已設「60 秒內低於 1 KB/s 就中斷並重試五次」，失敗會自己結束；再跑一次 Y-04，已完成的層不會重下載 |

### Y-05 建 APK（第一次會產生金鑰）

```powershell
docker compose --env-file $cfg --profile shell run --rm shell-builder
```

**怎麼知道成功了**：第一次執行印出「這一次新產生：院內 CA 伺服器憑證（<主機>） APK 簽章金鑰（院內）」，接著是 APK 檔名與三個 SHA-256（檔案、簽章憑證、院內 CA）。**把三個 SHA-256 抄進交接文件**（交接紙「外殼」那一列，[《院內主機現況與未完成事項之一：交接紙》](ref-status-handover.md)）。

**再執行一次**，要看到「**金鑰全部沿用，這一次沒有產生任何新的金鑰**」，簽章憑證的 SHA-256 與第一次相同。這是 DEP-35 的核心：`shell-builder` 絕不覆蓋既有的 CA 與簽章金鑰。

沒抄到也查得到，不必重跑：`http://localhost:<病人端埠>/shell/`（🏥 `http://localhost:18081/shell/`）下載頁最下面的「版本資訊」列著三個 SHA-256，同一個資料夾的 `shell.json` 也有； `patient-web` 每次都即時讀檔，不必先做 Y-07。每跑一次建置，APK 就會換成新的一份，**交接文件的檔案 SHA-256 以下載頁上的為準**。 `keys-info` 只列得出院內 CA 與簽章金鑰的指紋，格式是大寫、以冒號分隔，對照時去掉冒號、大小寫不計。

| 症狀 | 處置 |
|---|---|
| `HD_SHELL_SIGNING 要填 dev（開發機）或 hospital（院內主機）` | Y-03 沒填 |
| `這個金鑰資料卷是「dev」用的，設定卻是「hospital」` | **資料卷是開發機那一份**，或 `.env` 抄了開發機的。**停手**：院內主機不該有開發用的金鑰 |
| `MDM_KIOSK_BASE_URL 要以 https:// 開頭` | Y-03 |
| `有 CA 憑證卻沒有私鑰`、`有簽章金鑰卻沒有它的密碼檔` | 資料卷不完整。**不要刪掉重來**——那等於換 CA、換簽章金鑰，所有平板都要重裝。從 Y-06 的備份還原，見第 7 節 |

### Y-06 備份金鑰，並核對還原得回來（DEP-35）

```powershell
docker compose --env-file $cfg --profile shell run --rm shell-builder keys-backup
docker compose --env-file $cfg --profile shell run --rm shell-builder keys-verify
```

**怎麼知道成功了**：第一條印出「已備份：備份目錄/keys/hd-keys-<時間>.tar.gz」；第二條逐項 ✓，最後「還原得回來」。 `$root\backups\keys\` 底下看得到那份檔案。

> 📍 **1001 院內**：`keys-verify` 印出 `ca/ca.key`、`ca/ca.crt`、`signing/shell-signing.p12`、`signing/keystore.pass`、「備份裡的簽章金鑰以備份裡的密碼打得開」「備份裡的 CA 私鑰完整」，最後「`hd-keys-<時間>.tar.gz` 還原得回來」，全部 ✓。

**這份檔案裡有 CA 與簽章的私鑰。** 與資料庫備份一樣由院方送往院內另一台機器，不得出院、不得寄給開發端。送過去之後，在那一台上也要能取回——每年核對一次（第 7 節）。

### Y-07 讓病人端改走 HTTPS

```powershell
docker compose --env-file $cfg restart patient-web
docker compose --env-file $cfg logs patient-web --tail 5
```

**怎麼知道成功了**：記錄裡有「靜態資源已提供於連接埠 8081（HTTPS；HTTP 只留外殼下載頁）」。主機的瀏覽器開 `http://<主機>:<病人端埠>/shell/` 看得到下載頁；開 `http://<主機>:<病人端埠>/` 會被轉到 `https://` 並跳出憑證警告——**這是對的**，主機的瀏覽器不信任院內 CA，平板上的外殼才信任。

`--tail 5` 常常跨到重新啟動之前那一次，所以「找不到伺服器憑證」與「HTTPS」可能同時出現，以最後一次啟動的那幾行為準。記錄裡的 `8081`、`http://api:3000` 是容器裡面的埠，對應主機上的 `HD_PATIENT_PORT`、`HD_API_PORT`（🏥 `18081`、`13000`）；`api:3000` 是 `patient-web` 經容器之間的網路找後端的位址，不經過主機。平板一律連 `HD_PATIENT_PORT`。

| 症狀 | 處置 |
|---|---|
| **最後一次**啟動的記錄是「找不到伺服器憑證…暫以 HTTP 提供」 | Y-05 還沒跑成功，或跑完沒有重新啟動 `patient-web` |
| 下載頁顯示「外殼 App 尚未建置」 | 同上 |

> **伺服器憑證換過之後也要做這一步**：`shell-builder` 發現主機位址變了、或憑證 30 天內到期時會重新簽一張， `patient-web` 要重新啟動才讀得到。CA 沒變，平板不受影響。

### Y-08 平板連得進來

平板與主機之間要能連到病人端的埠。在主機上：

```powershell
Get-NetFirewallRule -Direction Inbound -Enabled True | Where-Object DisplayName -like "*Docker*" | Select-Object DisplayName, Profile
```

**怎麼知道成功了**：拿一台平板（或手機）連上**與平板實際使用時相同的 Wi-Fi**，瀏覽器開 `http://<主機>:<病人端埠>/shell/` 看得到下載頁。

| 症狀 | 處置 |
|---|---|
| 主機自己開得到，平板開不到 | Windows 防火牆擋了連入，或平板那個 Wi-Fi 網段到不了主機。**找資訊室**（Q-27），不要自己關防火牆 |
| 平板開不到，手機在同一個 Wi-Fi 開得到 | 平板的 Wi-Fi 連錯了 |
| 🧪 開發機上手機開不到 | 開發機的網路設定檔類型要是「私人」；仍不行，只對私人網路開放病人端那一個埠的做法在[《從零部署本系統》](ref-fresh-install.md) V-25 |

## 4. 平板（每台各做一次）

照《部署規範》8.2。**首波只佈建實際會用到的兩三台**（DEP-36）；院內現況只有一台暫用平板（第 0.1 節）。

### Y-09 在護理端註冊平板

護理端 → **新增裝置**（1007 以前叫裝置管理） → **註冊新平板**。畫面出現**佈建 QR code** 與文字網址（迭代 14.1 起）， **兩者只顯示一次**：這個畫面先不要關，拿著平板照 Y-10～Y-12 做完、掃完再離開。平板沒有相機、或這一頁非關不可時，才把序號與金鑰抄在佈建單上，佈建完就銷毀那張單子。顯示的網址要以 `https://` 開頭（🏥 `https://<IP>:18081`）；不是的話回 Y-03（外殼會拒收 `http://` 的 QR code），改好後 `up -d api` 再重新註冊。

序號建議與床號對應（例如 `TB-01` 對 1 號床），英數字與連字號，3–32 字元；暫用平板是 `TB-00`。

### Y-10 平板的系統設定

1. 設定裝置 PIN（**護理師才知道的那一組**），關閉「新增使用者」。🏥 暫用平板（One UI 5.1.1）的設定裡**找不到**「關閉新增使用者」（1029），找不到就跳過：平板只有一個使用者，解除螢幕固定要 PIN，佈建不受影響
2. 設定 → 安全性 → 螢幕固定：開啟，勾選「解除固定前要求 PIN」。🏥 One UI 5.1.1 的路徑是：設定 → 安全性與隱私權 → 其他安全性設定 → 釘選應用程式
3. 允許瀏覽器安裝不明來源的應用程式（安裝時系統會問）
4. 🏥 字型大小：系統預設不是 1.0 時，WebView 會跟著放大字，病人端可能被撐破。暫用平板是 1.1，醫師答覆維持 1.1、1029 看過等待畫面沒有被截斷；要調回就到「設定 → 顯示螢幕 → 字體大小與樣式 → 字型大小」（《[暫用平板](../notes/interim-tablet.md)》第 3 節）

### Y-11 從下載頁安裝

平板的瀏覽器開 `http://<主機>:<病人端埠>/shell/`（🏥 `http://<IP>:18081/shell/`），按「下載 App」，安裝。

| 症狀 | 處置 |
|---|---|
| 「應用程式未安裝」「套件與現有套件衝突」 | 這台平板裝過**另一把金鑰簽的版本**（例如開發用的）。先解除安裝再裝 |
| 「應用程式未安裝」，而且沒裝過 | 版本往下覆蓋，或下載不完整。重新下載一次 |

### Y-12 首次啟動與釘選

1. 開啟「透析照護平板」，按「**掃描 QR code**」（外殼 0.3.0 起），允許相機，對準 Y-09 畫面上的 QR code（🏥 暫用平板第一次開 App 會先跳三星的全螢幕手勢提示，按「確定」）。三欄一次填好，**核對序號與這台平板的標籤一致**（沒貼就現在貼一張，寫序號）。沒有相機時照舊手動輸入：主機位址填 `https://<主機>:<病人端埠>` （與 `MDM_KIOSK_BASE_URL` 相同），序號與金鑰填 Y-09 的
2. 按「儲存並啟動」，系統跳出「要固定這個應用程式嗎」，按「確定」

**怎麼知道成功了**：畫面是病人端的等待畫面，橫的，沒有任何憑證警告；按上一頁、首頁、多工鍵都離不開。

| 症狀 | 處置 |
|---|---|
| 「主機位址要以 https:// 開頭」 | 照填 |
| 掃了 QR code 出現「主機位址不是 https:// 開頭」 | `MDM_KIOSK_BASE_URL` 還是 `http://`。回 Y-03 改好，重新註冊這一台（舊的那張 QR code 已經不能用） |
| 掃了 QR code 出現「這不是平板佈建用的 QR code」 | 掃到別的東西了。對準 Y-09 畫面上那一張 |
| 佈建畫面沒有「掃描 QR code」 | 裝的是 0.3.0 以前的外殼。手動輸入照樣可以；要掃描就照 Y-14 換成 0.3.0（重建 `shell-builder` 映像檔，Y-04、Y-05）再從下載頁重裝 |
| 一片空白或「網頁無法使用」 | 位址打錯、或 Y-07 沒做。到系統設定 → 應用程式 → 透析照護平板 → 儲存空間 → **清除資料**，重新填 |
| 有憑證警告 | 主機位址跟伺服器憑證不符（🏥 `<IP>` 跟憑證對不上）。打電話給開發端；位址換過的話照[《護理站登不進去與主機位址》](ref-login.md) |
| 畫面上方出現琥珀色提示列「……版本不相容」 | 下載頁上的 APK 與系統的契約版本對不上。見第 6 節；抄下原文回開發端，平板先解除固定、交給護理長保管 |

### Y-13 核對護理端

護理端 → 新增裝置，15～30 秒內：

| 欄位 | 應該是 |
|---|---|
| 固定狀態 | 固定中 |
| 外殼版本 | 版本正常，底下一行版本號 |

把序號與床號的對應記下來。**解除一次固定**（輸入 PIN），30 秒內護理端要變成「已跳出」。

**釘回去**：解鎖後 App 還停在畫面上，但已經沒有釘住，直接點它沒用。按多工鍵把「透析照護平板」**從多工畫面滑掉**，再從桌面開啟，系統再問一次「要固定這個應用程式嗎」，按「確定」。護理端 15～30 秒內回到「固定中」（1029 暫用平板量到約 11 秒）。沒跳出確認框就重新開機，App 開機後會自己起來並詢問。

## 5. 平板要重新佈建時（已經佈建過的平板）

`TB-00` 1029 已佈建過，正常不必做。護理端看不到平板或「已跳出」，先在平板上把 App 從多工畫面滑掉、從桌面重開，系統問要不要固定選「確定」；仍不行、或出現空白頁、或固定不回來，才做這一節。要 1 小時左右，時間不夠就交接寫「平板未佈建」。

1. 平板：**不要原廠重設**（會把 WebView 退回 2023 年的出廠版本，院內沒辦法再更新）。設定 → 應用程式 → 透析照護平板 → 儲存空間 → 清除資料
2. 護理站的電腦：護理端 → **新增裝置** → **註冊新平板**。畫面出現佈建 QR code 與一行網址，**只顯示一次**，做完第 4 步再關。網址要以 `https://<IP>:18081` 開頭，不是的話 `.env` 的 `MDM_KIOSK_BASE_URL` 不對
3. App 不見了才要重裝：平板瀏覽器開 `http://<IP>:18081/shell/` →「下載 App」→ 安裝（允許瀏覽器安裝不明來源的 App）。「套件與現有套件衝突」是裝過開發版，先解除安裝再裝；「應用程式未安裝」是下載不完整，重下載
4. 開「透析照護平板」→「掃描 QR code」→ 允許相機 → 對準 QR code（第一次開會先跳三星的手勢提示，按「確定」）→ 核對序號與平板背面的標籤 →「儲存並啟動」→ 系統問要不要固定 →「確定」
5. 護理端「新增裝置」等 15～30 秒，變成「固定中」。釘選要 PIN：設定 → 安全性與隱私權 → 其他安全性設定 → 釘選應用程式，勾「解除固定前要求 PIN」（One UI 5.1.1 的路徑）

「主機位址不是 https:// 開頭」：回第 2 步看網址。平板畫面要是橫的、沒有任何憑證警告；有憑證警告就是 `<IP>` 跟憑證不符，打電話給開發端。

## 6. 換外殼版本、調高最低可用版本

### Y-14 換外殼版本（改 APK 的時候）

外殼改版是**開發端**的事：外殼 repo 打新 tag，本系統的 `shell.pin` 改成它，本系統打新 tag。主機上：

```powershell
git -C $root\hd-kiosk-shell fetch --tags
# 本系統照《本系統換版與退回》換到新 tag（shell.pin 跟著換）
docker compose --env-file $cfg --profile shell build shell-builder
docker compose --env-file $cfg --profile shell run --rm shell-builder
```

本系統換版的步驟在[《本系統換版與退回》](ref-upgrade.md)（W-19）。下載頁換成新版之後，**平板要逐台重新安裝**（覆蓋安裝即可，序號與金鑰會留著）。排在非透析時段（DEP-32）。 **只改網頁不必做這一段**——那是絕大多數的更新，平板下次載入就是新版。換版前先看新 tag 的 `shell.pin` 有沒有變；沒變就不必做（`v0.3.0` 到 `v0.5.0` 都沒變）。

### Y-15 調高最低可用版本

所有平板都換上新版之後，把舊版標成「外殼過舊」，下次有人沒換到就看得出來：

```powershell
notepad $cfg          # KIOSK_SHELL_MIN_VERSION=<新版本>
docker compose --env-file $cfg up -d api
```

**不必重建映像檔。** 護理端「新增裝置」的平板清單 15 秒內就會標出版本低於它的平板。

## 7. 金鑰：每年一次，以及遺失時

| 什麼時候 | 做什麼 |
|---|---|
| 每年 | `keys-verify <那一份備份的檔名>`，對院內另一台機器上取回的那一份做（DEP-35）；不給檔名就核對最新的一份 |
| 伺服器憑證快到期（825 天） | 直接再跑 Y-05，它會自己重新簽，然後 Y-07 |
| 主機位址換了 | 同上：Y-05 發現位址變了會重簽伺服器憑證，然後 Y-07、Y-06 重新備份；CA 沒變，平板不必重裝，但 `MDM_KIOSK_BASE_URL` 變了平板要重新佈建（第 5 節）。完整步驟在[《護理站登不進去與主機位址》](ref-login.md) |
| 金鑰資料卷壞了或被刪了 | **不要重新產生**。`docker volume create hd-tablet-care-keys` 建一個空的，再 `docker compose --env-file $cfg --profile shell run --rm shell-builder keys-restore hd-keys-<時間>.tar.gz`（只准還原到沒有金鑰的資料卷，還原完自動核對），然後 Y-05、Y-07 |
| 備份也沒了 | CA 與簽章金鑰都補不回來：重新產生、**每一台平板解除安裝後重裝**。這就是 DEP-35 說的「遺失即無法補救」 |

## 11. 平板到貨之後（每台一次，`K-10`～`K-16`）

> **首波只佈建實際會用到的兩三台**（DEP-36）。跑完一個完整班次沒問題，再做其餘。 15 台一次做完，等於把佈建的錯誤一次放大 15 倍。

0923 寫的 K-xx 是外殼路線之前的版本；**步驟本身以 Y-09～Y-13 為準**，這一節留 K-xx 才有的檢查與紀錄。對應：K-10 ≈ Y-09、K-11 ≈ Y-10、K-12（側載）由 Y-11 取代（原文在[《安裝包路線（歷史）》](ref-installer.md)）、K-13 ≈ Y-12、K-14 ≈ Y-10 第 2 步與 Y-12、K-15 ≈ Y-13。

### K-10 護理端先註冊這台裝置

護理端 → 新增裝置（1007 以前叫裝置管理） → 註冊，填序號（英數字與連字號，3–32 字元，例如 `TB-01`）。畫面顯示一組金鑰，**金鑰只顯示一次**（迭代 14.1 起同時顯示 QR code，Y-09）。

| 症狀 | 處置 |
|---|---|
| 金鑰沒抄到（或 QR code 的畫面關掉了） | 解除佈建後重新註冊一次即可，**不必重發 APK** |
| 序號要怎麼編 | 建議與床號對應（`TB-01` 對 1 號床），並在紙上記下對應表 |

### K-11 平板基本設定

1. 設定裝置 PIN（**護理師才知道的那一組**）
2. 關閉「新增使用者」（🏥 One UI 5.1.1 找不到，跳過，Y-10）
3. 開啟「允許安裝不明來源應用程式」
4. 連上透析區 Wi-Fi
5. 關閉自動更新、關閉自動休眠（或把螢幕逾時拉到最長）

| 症狀 | 處置 |
|---|---|
| 找不到「允許安裝不明來源」 | Android 8 起改成**按 App 授權**：從檔案管理員或瀏覽器安裝時才會跳出來 |
| 平板要求登入 Google 帳號 | **不需要，跳過**。整條路線刻意不依賴任何 Google 服務（暫用平板目前沒有任何 Google 帳號，不會卡重設保護） |
| Wi-Fi 連不上或訊號弱 | 記下床位與訊號強度（Q-12）。**這是要帶回來的情報之一** |

### K-13 首次啟動與佈建

開啟 App → 掃 QR code 或輸入主機位址、序號、金鑰（Y-12）。

**怎麼知道成功了**：進入病人端畫面，**沒有網址列**，**沒有憑證警告**。

| 症狀 | 原因 | 處置 |
|---|---|---|
| 憑證警告 | 主機位址與伺服器憑證不符、或病人端還沒改走 HTTPS | Y-07；位址換過照[《護理站登不進去與主機位址》](ref-login.md) |
| 「裝置尚未佈建」 | 序號或金鑰打錯 | 重新輸入。注意大小寫 |
| 一直轉圈 | 連不到主機 | 在平板的瀏覽器直接開 `http(s)://<主機>:<病人端埠>` 試，分清楚是網路問題還是 App 問題 |

### K-14 開啟螢幕固定

設定 → 安全性 → 螢幕固定 → 開啟，**勾選「解除固定前要求 PIN」** → 回到 App 並釘住。

**怎麼知道成功了**：病人退不出去；要解除必須輸入 PIN。

| 症狀 | 處置 |
|---|---|
| 找不到螢幕固定 | Android 版本太舊（需 5.0 以上），或廠商改了選單名稱（可能叫「應用程式鎖定」；One UI 5.1.1 叫「釘選應用程式」，在「安全性與隱私權 → 其他安全性設定」） |
| 沒勾「要求 PIN」 | **一定要勾**。不勾的話長按導覽列的上一頁鍵就解得開，Kiosk 形同虛設 |
| 重新開機後固定不見了 | **已知取捨**。App 會自動啟動，但螢幕固定不會自動恢復——列入每日交班檢查（第 13 節） |

### K-15 核對護理端

護理端 → 新增裝置，看這一台的「固定狀態」。

**怎麼知道成功了**：15 秒內變成**固定中**。把平板切走，30 秒內變成**已跳出**；關機等 90 秒，變成**失去回報**。

> **三種狀態要分得開**：尚未回報＝還沒裝 App；已跳出＝平板自己說它離開前景了；失去回報＝它不說話了（多半是關機或斷網）。護理師要做的處置完全不同。

### K-16 記錄對應關係

在紙上填一列（同時填進演練紀錄 §6.1）：

| 序號 | 床號 | Android 版本 | App 安裝完成 | 序號金鑰輸入 | 螢幕固定＋PIN | 護理端清單核對 | 備註 |
|---|---|---|---|---|---|---|---|

（0923 原表第四欄是「側載完成」，0927 起改從下載頁安裝。）

## 12. 如果進院時平板還沒到

**那就把佈建整段跳過，改成蒐集情報**。要帶回來的（情報蒐集表見[《進院通則》](ref-visit-rules.md)）：

| 要問到 | 為什麼 |
|---|---|
| 平板的採購進度與預計到貨日 | 決定下一次進院的時間 |
| 最後決定的型號與 Android 版本 | 決定螢幕固定可不可行、WebView 版本 |
| **院方允不允許安裝不明來源的 App**（0923 寫的是側載） | 不允許的話整條路線要重新決策 |
| 透析區各床位的 Wi-Fi 訊號 | 用手機在每個床位測一次，記下格數 |
| Wi-Fi 的認證方式（是否需要帳號、憑證、MAC 登記） | 平板連不上網就全盤皆輸 |
| 床位編號與實際位置 | 序號與床號的對應表 |
| 平板要放哪裡、怎麼充電、怎麼消毒 | 支架與電線的採購（Q-22） |

**這幾題問到了，下一次進院平板佈建就是純執行，不再有任何未知。**

> 📍 **1029**：暫用平板是透析室的舊平板，到透析室自動連上院內網路（不是訪客網路），醫師同意裝 App（[《第三次進院紀錄》](record-3-1029.md)）。

## 13. 交給護理師的一頁（每日）

印一張貼在護理站：

1. **前一天有重新開機的平板要重新釘選**：開啟 App → 最近使用 → 長按釘選圖示（或把 App 從多工畫面滑掉、從桌面重開，系統問要不要固定選「確定」，Y-13）。App 會自己起來，但螢幕固定不會自動恢復
2. 交班時看護理端裝置清單的「固定狀態」，**不必逐台目視**
3. 顯示**已跳出** → 去把螢幕固定釘回來
4. 顯示**失去回報** → 去看看那台平板還在不在、有沒有沒電
5. 治療結束照既有流程解除綁定，系統會自動清除該台的本地暫存

## 14. 守不住什麼（要先講清楚，不要等人發現）

| 破口 | 處置 |
|---|---|
| 重新開機後螢幕固定解除 | 人工重釘，已列入每日交班檢查 |
| 病人自己解開固定 | 靠前景回報變成「看得見」，不是「防得住」 |
| 還原原廠設定、改 Wi-Fi 設定 | 擋不住。屬物理接觸風險，治療區全程有護理師在場；原廠重設還會把 WebView 退回出廠版本 |
| 簽章金鑰或 CA 私鑰遺失（0923 寫的是 keystore） | **無法補救**，只能重新產生、每台平板解除安裝後重裝（第 7 節） |
| WebView 版本凍結 | 離線環境無法更新。已知取捨，與零連外一起接受 |
| 只有一台暫用平板 | 沒有備品，壞了病人端就停；護理端不受影響 |
