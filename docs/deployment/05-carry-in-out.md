# 第五冊 · 帶進去與帶出來

版本：v0.1　文件狀態：草案　編號：`C-xx`　**這一冊要印出來帶進去**

> **這一冊的前提是：假設這次會失敗。**
>
> 不是消極，是算術。第一次進院有太多事不在你手上——權限、防毒、連接埠、變更流程、
> 平板、位址——其中任何一項不成立，今天就裝不完。
>
> 所以這一冊要回答的不是「怎麼成功」，而是：**萬一失敗，要帶回哪些東西，
> 才能讓下一次不可能再失敗。**
>
> 判準只有一句：**離開醫院之後，院內的任何資訊你都再也拿不到。沒問到的，就是真的沒有了。**

---

## 1. 帶進去

### 1.1 實體（C-01）

| # | 帶什麼 | 為什麼 | 漏了會怎樣 |
|---|---|---|---|
| 1 | **隨身碟**（裡面只有安裝包壓縮檔與 `verify-package.mjs`） | 唯一的交付管道 | 今天什麼都做不了 |
| 2 | **備用隨身碟**（同樣內容） | 第一支被擋、壞掉或被扣留 | 多帶一支的成本是零，少帶一支的成本是再跑一趟 |
| 3 | 印出來的[第四冊](04-onsite.md)、[第五冊](05-carry-in-out.md)、[第六冊](06-troubleshooting.md) | **院內沒有網路，查不到文件** | 只能憑記憶做事 |
| 4 | 印出來的《部署規範》第 9 章 26 條清單 | 逐條打勾，打完就是部署紀錄 | 交不出檢查結果 |
| 5 | **交付單**（版本、commit、兩個 SHA-256） | 核對雜湊唯一的對照來源 | **核對不了**，等於沒有 DEP-27 |
| 6 | 指令小抄（[P-15](01-dev-machine.md#p-15-把要用的指令抄成一張小抄)） | 指令打錯的代價在正式主機上很貴 | 打錯字、用錯遷移指令 |
| 7 | **空白筆記本 ＋ 兩支筆** | 這一冊第 3 節要填滿它 | **情報帶不回來，這趟就白跑了** |
| 8 | 寫著三組機密值的那張紙（見 1.3） | 現場產不出來 | 卡在建 `.env` 那一步 |
| 9 | 手機（充飽電）＋行動電源 | 當碼表、測 Wi-Fi 訊號、臨時筆記 | 量不到訊號、記不了時間 |
| 10 | 識別證／名片／在職證明 | 報到 | 進不去 |
| 11 | USB-A 與 USB-C 轉接頭 | 主機可能只有其中一種孔 | 隨身碟插不上去 |
| 12 | **筆記型電腦（條件性）** | 位址與預期不同時，唯一的當場補救是重新產生安裝包 | 卡在 [H-15](04-onsite.md#h-15-防火牆與從護理站連進來) 無解 |

> **第 12 項要先問過**：院方允不允許外來筆記型電腦帶進去、能不能接院內網路（Q-29）。
> 不能接網路也還是值得帶——**重新產生安裝包不需要網路**，只需要開發機上那份 `node_modules`。
> 但**它不得接上院內網路，也不得從院內複製任何東西出來**。

**離家前的最後三個確認**：

- [ ] 隨身碟插上電腦，親眼看到裡面只有兩個檔案
- [ ] 交付單上的雜湊值看得清楚（不是手寫潦草）
- [ ] 手機電量 100%

---

### 1.2 隨身碟裡放什麼（C-02）

| 放 | 不放 |
|---|---|
| 安裝包壓縮檔（`.zip`） | `.env`（任何一份） |
| `scripts/verify-package.mjs` | 資料庫檔案、備份 |
| | 原始碼、`node_modules` |
| | 舊版安裝包 |
| | 任何其他專案的檔案 |
| | 個人資料、照片、音樂 |

**理由**：碟上每多一個檔案，掃描站就多一件要解釋的事，離院時也多一件要清除的東西。

---

### 1.3 寫在紙上帶進去的三組值（C-03）

現場沒有方便的工具產生這些，**一定要先在開發機上產好**：

| # | 值 | 怎麼產 | 注意 |
|---|---|---|---|
| 1 | `JWT_SECRET` | `node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"` | 一長串，抄的時候**每五個字元空一格**比較不會抄錯 |
| 2 | 初始最高權限帳號的工作 ID 與密碼 | 自己決定 | 首次登入會強制變更，**現場要當場請護理長改掉** |
| 3 | 服務帳號的密碼 | **由資訊室決定與輸入，你不要知道** | 只記帳號名稱 |

**紙的處理**：離院前把第 1、2 項那張紙**交給院方**或**自己帶走並事後銷毀**，
不要留在主機旁邊，也不要拍照存在手機裡。

---

### 1.4 絕對不帶進去的（C-04）

| 不帶 | 為什麼 |
|---|---|
| 開發機的 `.env` | 裡面有開發機的路徑與金鑰，而且它不該出現在院內任何地方 |
| 任何真實病人資料 | 顯然 |
| 未經掃毒的任何檔案 | DEP-26 |
| 會自動連外的工具（同步軟體、雲端硬碟程式） | **零院外連線**是整套系統的前提，連你自己的電腦也一樣 |
| 一份「應該可以用」但沒驗收過的安裝包 | 驗收沒過就不是交付物 |

## 2. 帶出來

### 2.1 實體（C-05）

| 帶出來 | 狀態 |
|---|---|
| 隨身碟 ×2 | **已當場清除**，並在紀錄寫明時間與執行者（DEP-28） |
| 筆記本 | 寫滿了第 3 節那些答案 |
| 26 條檢查清單 | **每一條都有結果**，沒有空白 |
| 掃毒結果的紙本或單號 | DEP-26 要求留存 |
| 交接文件的副本 | 上面有對方簽收 |

---

### 2.2 絕對不帶出來的（C-06）

| 不帶 | 包含 |
|---|---|
| 任何檔案 | 備份、資料庫、紀錄檔、設定檔、匯出的表格 |
| 任何截圖或照片 | 螢幕、病歷、白板、床位標示 |
| 任何真實病人資料 | 姓名、病歷號、床號對應到的人、任何一筆症狀回報 |

> **紀錄可以帶，資料不能帶。** 兩者的分界線是：
> **紀錄描述系統與流程**（「服務在第 137 分鐘啟動成功」），
> **資料描述病人**（「3 號床的王先生回報頭暈」）。
>
> 手抄也一樣受這條規範約束。筆記本上出現任何一個真實姓名或病歷號，那本筆記本就成了要管制的東西。

---

### 2.3 要帶出來的資訊，分兩級（C-07）

**A 級：沒有它，下一次一定會再失敗。**
**B 級：沒有它，下一次會卡住但救得回來。**

離院前逐條看一次：**A 級有任何一項空白，就回頭去問**，不要離開。

---

## 3. 情報蒐集表（這趟真正的交付物）

**印出來，一題一題填。** 空白的格子比錯誤的答案更危險——錯的答案會被發現，空白的會被遺忘。

### 3.1 主機與權限（A 級）

| # | 要問到 | 為什麼沒有它會再失敗 | 答案 |
|---|---|---|---|
| `C-08` | 主機的**固定位址**（DNS 名稱或 IP） | 憑證、APK、**安裝包建置時寫死的 API 位址**三樣都靠它。不知道就只能再跑一趟 | |
| `C-09` | 本專案可用的**三個連接埠**，且已登記 | 正式環境沒填埠就拒絕啟動 | |
| `C-10` | 服務執行帳號的**名稱與網域**、密碼由誰保管、**多久到期** | 密碼到期那天服務會停，而沒有人知道為什麼 | |
| `C-11` | 有沒有系統管理員權限、由誰代為操作 | 註冊服務、改權限、改防毒都要它 | |
| `C-12` | **防毒是哪一套、誰能加排除清單、流程多久** | 沒有排除清單就會出現間歇性的資料庫鎖定失敗 | |
| `C-13` | 資料庫與備份的**指定路徑**（哪一顆磁碟、哪個資料夾） | 路徑決定了 `.env`，也決定了 DEP-08 成不成立 | |
| `C-14` | 備份的**院內第二台機器**：位址、存取方式、誰保管 | 備份只落在同一台機器等於沒有備份 | |
| `C-15` | 磁碟保留空間的門檻、誰監看 | 磁碟寫滿時 SQLite 是直接寫入失敗，不會先變慢 | |

### 3.2 交付流程（A 級）

| # | 要問到 | 為什麼 | 答案 |
|---|---|---|---|
| `C-16` | 隨身碟政策：允不允許、要不要報備、有沒有指定加密碟 | **這是唯一一種「全部做對了還是進不去」的失敗** | |
| `C-17` | 指定掃毒站的位置、經手人、結果留存方式 | 下次可以直接約時間，不必現場找人 | |
| `C-18` | 變更申請流程：要不要、多久、誰核准 | 要走申請的話，**下次要提前兩週送件** | |
| `C-19` | **日後每次更新都要重走一次嗎** | 決定更新的節奏是「隨時」還是「每季一次」 | |
| `C-20` | 可接受的部署與更新時段 | 要避開透析班次（DEP-32） | |
| `C-21` | 外來筆記型電腦：能不能帶、能不能接院內網路 | 位址不如預期時唯一的補救路徑 | |

### 3.3 網路與現場（A 級）

| # | 要問到／要量到 | 怎麼做 | 答案 |
|---|---|---|---|
| `C-22` | 護理站電腦**連得到主機嗎**（實測） | 在護理站電腦上開主機網址 | |
| `C-23` | 護理站電腦的**瀏覽器與版本** | 說明 → 關於 | |
| `C-24` | 透析區**每個床位的 Wi-Fi 訊號**（用手機測） | 一床走一次，記格數或 dBm | |
| `C-25` | Wi-Fi 的 SSID 與**認證方式**（開放／密碼／企業級／要登記 MAC） | 問資訊室 | |
| `C-26` | 透析區與護理站是不是**同一個網段** | 問資訊室 | |
| `C-27` | 常駐總覽螢幕的位置與硬體現況（Q-10） | 現場看一眼 | |

### 3.4 平板（A 級，若平板尚未到貨）

| # | 要問到 | 為什麼 | 答案 |
|---|---|---|---|
| `C-28` | 採購進度與**預計到貨日** | 決定下一次進院的時間 | |
| `C-29` | 決定的**型號與 Android 版本** | 低於 5.0 就沒有螢幕固定，整個方案要重想 |  |
| `C-30` | **院方允不允許側載 APK** | 不允許的話整條路線要重新決策（Q-11） | |
| `C-31` | 自簽 CA 符不符合院方資安規範；院方要不要自己簽發 | 決定 APK 裡打包哪一張憑證 | |
| `C-32` | 床位編號與實際位置、平板放哪、怎麼充電、怎麼消毒 | 序號對床號的表、支架採購（Q-22） | |

### 3.5 人與流程（B 級）

| # | 要問到 | 為什麼 | 答案 |
|---|---|---|---|
| `C-33` | 資訊室聯絡人的姓名、分機、信箱 | 下次直接聯絡 | |
| `C-34` | 護理長與首波試用的護理師是誰 | 介面試用人選（Q-31） | |
| `C-35` | 重開機後**誰負責確認服務有起來** | 沒有這個人，某天服務停了沒人知道 | |
| `C-36` | 出事時的通報路徑 | 交接文件要寫 | |
| `C-37` | 下一次可以進院的時間 | 當場約，不要事後再約 | |

### 3.6 這一趟的過程紀錄（B 級，但只有現在寫得出來）

| # | 記什麼 | 用在哪 |
|---|---|---|
| `C-38` | 路線 A 每一步的**錯誤原文與耗時** | 演練紀錄 §1.3（DEP-25），這是交付物本身 |
| `C-39` | 每一個步驟的實際耗時 | 下次的時間預算 |
| `C-40` | 卡住的每一件事：卡在哪、為什麼、怎麼繞過或沒繞過 | 下次的準備清單 |
| `C-41` | 有沒有人提議「開一下網路」、你怎麼回應的 | 日後同樣的提議再出現時，有前例可循 |
| `C-42` | 現場任何人說過的「這樣不行」「我們這裡都是…」 | **這些是沒有寫在任何文件上的限制**，只有現場聽得到 |

## 4. 離院前的十個自我提問

**站在門口，一題一題問自己。答不出來就回頭。**

1. 主機的固定位址是什麼？（`C-08`）
2. 我拿到三個連接埠了嗎？（`C-09`）
3. 防毒排除清單加了沒？沒加的話誰要加、什麼時候？（`C-12`）
4. 備份會落在院內哪一台機器？（`C-14`）
5. 下次要不要再走一次變更申請？（`C-19`）
6. 平板什麼時候到、是哪一款？（`C-28`、`C-29`）
7. 每個床位的 Wi-Fi 我測過了嗎？（`C-24`）
8. 隨身碟清乾淨了嗎？（[H-23](04-onsite.md#h-23-清除隨身碟dep-28)）
9. 26 條清單有沒有任何一條是空白的？
10. **如果今天完全失敗，我帶回去的東西夠不夠讓下一次一定成功？**

**第 10 題答「不夠」的話，回頭去把 A 級那幾張表補完。**
補完要花 20 分鐘；不補，就是再花一整天跑一趟。
