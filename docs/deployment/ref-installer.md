> 1117 從五份舊冊改寫：《進院當天》的 H-08～H-13（路線 A 與路線 B 的安裝包步驟）；《帶進去與帶出來》的隨身碟部分（C-01 第 1、2、5、6、8、11、12 列、C-02、C-05 的隨身碟與掃毒列）；《現場疑難排解》的 A 類（X-01～X-04）；《平板與外殼 App》0927 起被外殼路線取代的部分（盤點裡安裝包那幾列、HTTPS 缺口、K-01～K-07、K-09、K-12，以及 K-13 原文的憑證警告原因）；以及總覽裡安裝包路線的說明。

## 摘要

- 安裝包路線：開發機上建一份離線安裝包（內含 Node 執行期與 Prisma 引擎）→ 乾淨機器上彩排 → 隨身碟帶進院 → 掃毒、解壓、核對雜湊 → 建 `.env`、套用遷移 → 低權限服務帳號、註冊成排程工作啟動（第 0 節）
- 0926 院方要求容器部署、不准用隨身碟，整條路線撤除；0922 第一次進院走的是這條路線的準備，結果見[《第一次進院紀錄》](record-1-0922.md)
- 子文件：建置與開發端彩排（`P-xx`、`R-xx`）在[《安裝包路線之一》](ref-installer-build.md)；`git clone` 意外成功時的岔路（`G-xx`）在[《安裝包路線之二》](ref-installer-git-clone.md)
- 外殼 App 原本在開發機上自產院內 CA、自建 keystore、自編 APK、側載（K-01～K-07、K-09、K-12，第 1 節）；0927 起改由院內主機上的 `shell-builder` 建置與簽章、平板從下載頁安裝
- 原本的 HTTPS 缺口（安裝包只有 HTTP，Service Worker 註冊不了）0927 由病人端自己終止 TLS 解決（第 1.1 節）
- 隨身碟、交付單、轉接頭、筆記型電腦要帶，隨身碟裡只放兩個檔案，離院前清除（C-01、C-02、C-05 的安裝包列，第 2 節）
- 進院當天：路線 A 讓 `git clone`／`npm install` 失敗並記下（H-08），路線 B 解壓核對雜湊、建 `.env`、遷移、服務帳號、註冊啟動（H-09～H-13，第 3 節）
- 安裝包與雜湊的出錯處置（X-01～X-04，第 4 節）

## 1. 平板與外殼 App：0927 被取代的部分（`K-xx`）

原本的建議時點：**D-10 ～ D-7**（平板到貨後另一段）。0923 寫的時候**平板還沒買、外殼 App 還沒編譯過**，因此分成兩半：上半是現在就做得完的（做完，下次進院只剩側載那幾分鐘）；下半是平板到貨才做得了的（現在在[《平板與外殼 App》](ref-tablet.md)第 11 節）。

### 1.1 當時的盤點與 HTTPS 缺口

| 項次 | 0923 的現況 | 誰擋住誰 |
|---|---|---|
| 外殼 App 原始碼 | **在**（`apps/kiosk-shell/`：`MainActivity.kt`、`ProvisioningActivity.kt`、`BootReceiver.kt`、`network_security_config.xml`）；0927 搬到另一個私人 repo `hd-kiosk-shell` | — |
| 編譯環境（Android Studio、JDK 17、SDK 34） | **未安裝** | 擋住 K-06 |
| 院內 CA 與伺服器憑證 | **未產生**（工具已備：`npm run cert:hospital-ca`） | 擋住 K-05、K-06 |
| APK 簽名金鑰（keystore） | **未建立** | 擋住 K-06 |
| 平板實體 | 見[《平板與外殼 App》](ref-tablet.md)第 10 節 | — |
| 主機的 HTTPS | **安裝包目前只提供 HTTP**，見下方警告 | **擋住離線能力** |

> ### ⚠ 一個必須先解決的缺口：病人端要離線，就必須是 HTTPS
>
> Service Worker（病人端離線能力的全部依靠）**只在安全來源底下才會註冊**。 `http://localhost` 算安全來源，`http://<院內主機 IP>:<埠>` **不算**——平板連的正是後者，於是 `navigator.serviceWorker` 根本不存在，註冊會**靜悄悄地跳過**，不出錯、不提示，直到有一天網路斷了才發現畫面是空白的。
>
> 而目前**安裝包裡沒有任何東西在做 TLS**：後端與兩個靜態站都是純 HTTP。自簽 CA 產生的 `server.crt`／`server.key` 現在**沒有地方可以掛**。
>
> 三條路，建議第一條：
>
> | 方案 | 代價 | 評估 |
> |---|---|---|
> | **① 讓安裝包自己終止 TLS**（後端與兩個靜態站讀 `server.crt`／`server.key`） | 改動不大，全在自己的程式碼裡 | **建議**。不新增任何要過資安審查的第三方執行檔 |
> | ② 加一個反向代理（nginx／IIS） | 多一個要送進院內、另外過一次資安審查的元件 | 與當初捨棄服務包裝器的理由相同，能免則免 |
> | ③ 首波先跑 HTTP，不要離線能力 | 「選 PWA 而非純網頁的唯一理由」當場消失 | **不建議**，但若只為了驗主機這一段，可以當成過渡 |
>
> **這一條在 D-7 之前要有結論**，否則平板佈建做不完整。現況已記在這裡，不要到現場才發現。

**結論（0927）**：走的是第一條的方向——病人端的靜態服務自己以院內 CA 簽的伺服器憑證提供 HTTPS，HTTP 只留外殼下載頁（[《平板與外殼 App》](ref-tablet.md) Y-07）。

### K-01 決定院內主機的位址（**所有事情的上游**）

**做什麼**

向資訊室要一個**固定**的位址，二擇一：

- 院內 DNS 名稱，例如 `hd.<院內網域>`
- 固定 IP，例如 `192.0.2.10`

**為什麼這是上游**

同一個位址同時決定四件事，**改了任何一次都要重做一輪**：

| 誰用到它 | 改了會怎樣 |
|---|---|
| 伺服器憑證的主體別名 | 要重簽憑證 |
| **PWA 建置時寫死的 API 位址**（`VITE_API_BASE_URL`） | 要**重新產生安裝包**（見[《安裝包路線之一》](ref-installer-build.md) R-08 的警告） |
| `.env` 的 `CORS_ORIGINS`、`MDM_KIOSK_BASE_URL` | 改設定重新啟動 |
| 外殼 App 的 `network_security_config.xml` | **15 台平板全部要重發 APK** |

**可能怎麼壞、怎麼處理**

| 症狀 | 處置 |
|---|---|
| 資訊室說「IP 可能之後會變」 | **要一個不會變的**。會變的 IP 等於每次變動都要重發 15 台的 APK |
| 只給得出 IP，給不出 DNS 名稱 | 可以，但寫進紀錄：**這個 IP 從此不能換** |
| 到 D-7 還沒有答覆 | 那這次進院的目標降為 B 級（三種結果見[《進院通則》](ref-visit-rules.md)），平板整段延後 |

> **之後的演變**：容器路線把位址的決定放在[《從零部署本系統》](ref-fresh-install.md) V-08；1007 Q-27 答覆院內主機的 IP 是固定的，1029 由名稱換成 IP。現在位址要換，影響的是 `HD_PUBLIC_API_URL`（要重建網頁）、`CORS_ORIGINS`、`MDM_KIOSK_BASE_URL` 與伺服器憑證（`shell-builder` 自動重簽，CA 不變），步驟在[《護理站登不進去與主機位址》](ref-login.md)。

### K-02 產生院內 CA 與伺服器憑證

**做什麼**

```bash
npm run cert:hospital-ca -- --host <K-01 決定的主機名稱> --ip <K-01 決定的 IP>
```

**怎麼知道成功了**

`certs/` 底下出現五個檔案，並印出 CA 指紋與有效期：

| 檔案 | 用途 |
|---|---|
| `hospital-ca.key` | **CA 私鑰。遺失無法補救，也絕不出院** |
| `hospital-ca.crt` | CA 憑證 |
| `hospital-ca.pem` | 給外殼 App 打包的那一份（內容同 `.crt`） |
| `server.key` / `server.crt` | 伺服器憑證 |

**可能怎麼壞、怎麼處理**

| 症狀 | 原因 | 處置 |
|---|---|---|
| 說找不到 openssl | 開發機沒有 openssl | Git for Windows 自帶（`C:\Program Files\Git\usr\bin\openssl.exe`）。把它加進 PATH，或用 Git Bash 執行 |
| 再跑一次被擋下 | 腳本不會覆蓋既有的 CA | **正確行為。** 換 CA 等於 15 台平板都要重發 APK |
| 主體別名裡沒有平板實際要連的位址 | `--host`／`--ip` 填錯 | 刪掉 `certs/` 重產。**現在改沒有代價，發出 APK 之後改代價是 15 倍** |
| 有效期太短 | | 根憑證預設 10 年，免得日後頻繁重發 APK |

0927 起由 `shell-builder` 在院內主機上產生（Y-05），私鑰不離開主機。

### K-03 把 CA 私鑰異地備份（**DEP-35，做完 K-02 立刻做**）

**做什麼**

1. 把 `hospital-ca.key` 與 keystore（K-06）複製到**另一個實體位置**
2. **院內，不出院**——這兩樣東西的備份不得放到任何雲端
3. 在交接文件寫下：放在哪、誰保管、誰有權限取

**怎麼知道成功了**

備份存在，而且**你實際從備份還原過一次**（複製回來、用它簽一次測試憑證）。

> **只備份不驗證等於沒備份。** 這一條每年要重做一次（平板管控方案 6.3）。

**可能怎麼壞、怎麼處理**

### K-06 建立 keystore 並編譯 release APK

**做什麼**

```bash
keytool -genkeypair -v -keystore hd-kiosk.jks -keyalg RSA -keysize 4096 \
  -validity 10000 -alias hd-kiosk
cd apps/kiosk-shell && ./gradlew assembleRelease
```

**怎麼知道成功了**

`app/build/outputs/apk/release/` 底下有一個已簽名的 APK。

**可能怎麼壞、怎麼處理**

| 症狀 | 原因 | 處置 |
|---|---|---|
| **keystore 遺失** | | **無法補救**（DEP-35）：再也發不出更新版，只能換套件名重新側載 15 台。建立後**立刻**照 K-03 備份 |
| Gradle 建置失敗，缺 SDK 元件 | 第一次建置 | 依提示安裝，需要網路 |
| 不知道 keystore 密碼要設多長 | | 和 CA 私鑰同級對待。**寫在交接文件裡，不要只存在你腦袋裡** |
| 想先用 debug 版測 | 可以 | `./gradlew assembleDebug`。但**正式佈建一定要用 release 簽名版**——debug 簽名的 App 之後換成 release 版時必須先解除安裝，等於白做一次 |

| 憑證 | 沒有任何憑證警告 |
| 網址列 | **不存在**（外殼沒有網址列，病人看不到金鑰） |
| 首次佈建 | 輸入序號與金鑰後進入病人端畫面 |
| 金鑰不外露 | 網址上的 `serial`／`key` 參數被網頁立刻移除 |
| 前景回報 | 護理端裝置清單 15 秒內變成**固定中** |
| 離開前景 | 切到別的 App，護理端 **30 秒內**變成**已跳出** |
| 外部連結 | 點測試用的外部連結**不會開啟** |
| 長按文字 | **不會**出現選字選單 |
| 離線 | 關掉模擬器網路後重新整理，**畫面照樣出得來** |

**可能怎麼壞、怎麼處理**

| 症狀 | 原因 | 處置 |
|---|---|---|
| 憑證警告 | pem 沒放、網域對不上、或主機根本沒開 TLS | 見第 1.1 節的警告框 |
| 離線時一片空白 | Service Worker 沒註冊 | **九成是因為連的是 HTTP**（非安全來源）。這正是第 1.1 節那個缺口 |
| 護理端一直顯示「尚未回報」 | App 沒裝成或連不到後端 | **「尚未回報」與「已跳出」是兩件事**：前者是沒裝 App，後者才是跳出 Kiosk |
| 模擬器連不到 `10.0.2.2` | 演練機防火牆 | 回 R-13 開輸入規則（[《安裝包路線之一》](ref-installer-build.md)） |

> **模擬器驗不到的只有三件事**：螢幕固定、開機自動啟動的實機行為、實體 Wi-Fi 的穩定度。其餘全部可以在平板到貨前驗完——**這就是「下次去只做最少工作」的實際做法**。

0927 起的驗法改成開發手機從下載頁安裝（[《平板與外殼 App》](ref-tablet.md)第 8 節、[迭代 12 測試分冊](../testing/iteration-12.md)）。

## 2. 隨身碟與帶進去（`C-xx`）

### C-01 實體

|---|---|---|---|
| 1 | **隨身碟**（裡面只有安裝包壓縮檔與 `verify-package.mjs`） | 唯一的交付管道 | 今天什麼都做不了 |

| 12 | **筆記型電腦（條件性）** | 位址與預期不同時，唯一的當場補救是重新產生安裝包 | 卡在 H-15（[《第一次進院之一：進院當天詳細版》](visit-1-system-onsite.md)）無解 |

C-01 其餘的列（第 3 列印出來的手冊、第 4 列 26 條清單、第 7 列筆記本、第 9 列手機、第 10 列識別證）不分路線，在[《進院通則》](ref-visit-rules.md)。

- [ ] 隨身碟插上電腦，親眼看到裡面只有兩個檔案
- [ ] 交付單上的雜湊值看得清楚（不是手寫潦草）

### 3.1 路線 A（預期失敗，目的是取證據）

### H-08 讓它失敗，並把失敗記下來（DEP-25）

**做什麼**（每一步都計時）

```powershell
git clone https://github.com/<repo>.git

```

**怎麼知道「成功」了**

| 欄位 | 值 |
|---|---|
| 日期／時間 | |
| 執行者 | |
| 主機 | |
| `git clone` 的錯誤原文 | |
| 耗時 | |
| `npm install` 的錯誤原文 | |
| 耗時 | |
| 有沒有人提議「開一下網路就好」、怎麼回應的 | |

**可能怎麼壞、怎麼處理**

| 症狀 | 處置 |
|---|---|
| **`git clone` 成功了** | **先不要往下跑。** 翻[《安裝包路線之二》](ref-installer-git-clone.md)，從 G-01 做起 |

| **有人說「我開一下網路給你」** | **婉拒，並把這件事記下來。** 零院外連線是這套系統能放病人資料的前提，第一天就自己破壞它，之後沒有人會再認真看待這條 |
| 機器上連 git 都沒有 | 更好——那本身就是證據。記下來 |
| 錯誤訊息很長 | **抄開頭那幾行就夠**，重點是錯誤碼與主機名稱。另外**一定要記耗時**：開發端量到的是 71 秒，而它連第一個套件的中繼資料都還沒拿到 |
| 覺得這一步沒必要、想跳過 | 這份紀錄有兩個用途：向資訊室解釋「為什麼不能用一般方式部署」時它比任何說明都有效；日後有人提議「直接在主機上更新就好」時，它是現成的答案 |

### 3.2 路線 B（正式安裝）

### H-09 解壓並核對雜湊（DEP-27）

**做什麼**

```powershell
Expand-Archive -Path <隨身碟>:\hd-tablet-care-<版本>-<commit>.zip -DestinationPath C:\hd\hd-tablet-care-<版本>-<commit>
cd C:\hd\hd-tablet-care-<版本>-<commit>
Get-FileHash -Algorithm SHA256 .\CHECKSUMS.txt
```

壓縮檔裡**沒有最上層資料夾**，`-DestinationPath` 要寫到有版本號的那一層。

與交付單上那一串**逐字比對**。

**可能怎麼壞、怎麼處理**

| 症狀 | 處置 |
|---|---|
| **雜湊不一樣** | **停下來。** 重新複製再比一次。還是不同就是路上壞了或被掃描站動過——今天不要裝（X-01） |
| `cd` 找不到路徑，檔案全散在 `C:\hd\` 底下 | 解壓目的地少寫了版本號那一層。清掉散出來的檔案，照上面的指令重解，不要用搬的 |
| 路徑太長導致解壓失敗 | 解到很短的路徑（`C:\hd\`），不要放在桌面或使用者資料夾深處（X-02） |
| 解壓很慢 | 2 萬多個檔案，幾分鐘是正常的 |
| 不知道要解到哪 | 問資訊室指定的安裝路徑。**要記得它必須與資料庫、備份目錄分開**（DEP-08） |

### H-10 建立 `.env`

**做什麼**

```powershell
Copy-Item .\.env.範本 ..\.env
notepad ..\.env
```

照 R-08 那張表填（[《安裝包路線之一》](ref-installer-build.md)）。**把你在演練時填的那份拿出來照抄**，只換四種值：主機位址、連接埠、路徑、密碼。

**可能怎麼壞、怎麼處理**

| 症狀 | 處置 |
|---|---|
| 忘了 `DEPLOYMENT_ENV=production` | 時區檢查不會擋、開發用遷移指令不會擋。**一定要填** |
| `CORS_ORIGINS` 還是 localhost | 護理站電腦一連就被擋，而且錯誤只在瀏覽器主控台看得到 |
| `API_PORT` 沒填 | 正式環境會直接拒絕啟動。**這是刻意的**：逼出「埠要先登記」這件事 |
| 密碼裡有特殊字元 | 整串加引號，或改用不含引號與 `#` 的密碼 |

```powershell
.\runtime\node.exe .\app\api\scripts\prisma-cli.mjs migrate deploy --schema .\app\api\prisma\schema.prisma
```

### H-12 建立服務帳號（**需要資訊室**）

**做什麼**

請資訊室建立一個專用的低權限帳號，並告訴你帳號名稱（密碼由他們輸入，你不要知道）。

**可能怎麼壞、怎麼處理**

| 症狀 | 處置 |
|---|---|

### H-13 註冊服務並啟動

**做什麼**


**怎麼知道成功了**

| 症狀 | 處置 |

## 4. 安裝包與雜湊的出錯處置（`X-01`～`X-04`）

舊《現場疑難排解》的 A 類；其餘各類在[《現場疑難排解》](ref-troubleshooting.md)。

### X-01 雜湊值對不上

| | |
|---|---|
| **你會看到** | `Get-FileHash` 出來的字串與交付單上不同 |
| **可能原因** | 複製時中斷；防毒「清理」過檔案；拿錯版本；解壓不完整 |
| **先查** | 是不是拿錯壓縮檔（檔名裡的 commit）；隨身碟上那一份的雜湊對不對 |
| **處置** | 重新複製、重新解壓、再比一次。**還是不同就今天不要裝** |
| **不要做** | 「差一點應該沒關係」——雜湊沒有「差一點」 |

### X-02 解壓失敗，說路徑太長

| | |
|---|---|
| **可能原因** | Windows 的路徑長度上限，加上 `node_modules` 本來就很深 |
| **處置** | 解到極短的路徑，例如 `C:\hd\`。不要放在桌面或使用者資料夾深處 |

### X-03 驗收腳本第 5 項抓到對外連線

| | |
|---|---|
| **你會看到** | 連線哨兵列出一個院外主機名稱 |
| **處置** | **不得交付**。記下那個主機名稱帶回去，用 `npm run check:egress` 對照 |
| **不要做** | 當成誤判跳過。這一條是整套系統能放病人資料的前提 |

### X-04 掃描站把檔案刪掉或隔離了

| | |
|---|---|
| **你會看到** | 雜湊對不上，或解壓後少了某個檔案 |
| **處置** | 請對方加例外並重新複製一份；同時記下判定名稱與檔案路徑 |
| **不要做** | 用被動過的包硬裝。那份包已經不是你驗收過的那一份 |
