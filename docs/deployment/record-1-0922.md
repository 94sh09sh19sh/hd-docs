## 0. 先講結論

### 0.1 一句話

**院方要求以容器部署，這正是《[git clone＋Docker 路線詳細版](visit-1-system-docker.md)》的情境；但當天沒有照那一冊的方式做，而是先手動開了一個通用的 Python 容器、在容器裡 `git clone`，再在容器「裡面」照那一冊從頭執行。** 那一冊的每一條指令都是寫給**主機上的 PowerShell** 下的，在容器裡一條都不成立，之後就全部亂掉了。

## 2. 為什麼會失敗

### F-01 在容器裡面照 git clone＋Docker 路線做

**發生了什麼**：先 `docker run` 出一個 `python` 容器，再進去照那一冊做。

**為什麼不成立**：那一冊的形狀是「**主機**上有 Docker → 在**主機**上 `git clone` → 在**主機**上 `docker build` 把原始碼建成映像檔 → `docker compose up` 由映像檔**開出**三個容器」。容器是這一整串的**產物**，不是起點。在容器裡面做，每一步都少了它要的東西：

| 那一冊的步驟 | 在 `python` 容器裡會怎樣 |
|---|---|
| D-07 `docker version`、`docker compose version` | 容器裡沒有 `docker` 指令，也碰不到主機的 Docker |
| D-09 `Get-LocalGroupMember` | 容器裡沒有 PowerShell，那是 Linux |
| D-11 `New-Item`、`C:\hd` | 同上；路徑也不存在 |
| D-14 `docker build` | 沒有 `docker`，建不出映像檔 |
| D-16 產生 `JWT_SECRET`、D-18 套用遷移 | 都要先有映像檔；`python` 映像檔裡也沒有本專案要的 Node.js 20 |
| D-19 `docker compose up -d` | 同 D-14 |

**下一次怎麼做**：**不要自己先開任何容器。** 在主機的 PowerShell 視窗裡，從 D-05 開始照那一冊做；容器會在 D-19 由 `docker compose up -d` 自己出現，名字是 `api`、`nurse-web`、`patient-web`。

### F-02 整顆 C 槽被掛進容器

**發生了什麼**：`-v /c:/app` 在 Docker Desktop 上的意思是「把主機的 `C:\` 掛到容器的 `/app`」。（這一點要在主機上用 F-10 的指令確認，見下。）

**為什麼嚴重**：

- 容器裡預設是 root。**容器裡的任何指令，都能讀寫主機整顆 C 槽**——包含同一台主機上另一個專案的檔案、 Windows 使用者資料夾、Docker 自己的虛擬磁碟所在的 `AppData`。這是 DEP-37 共用主機隔離的反面
- **在容器裡對 `/app` 做的任何刪除，刪的是主機上的真檔案。** 在容器裡下一句 `rm -rf /app/*`，就是清空 C 槽
- 在 `/app` 底下 `git clone`，原始碼就落在主機 C 槽的根目錄底下，**而且是在一個沒人預期的位置**
- 若之後把資料庫也放在 `/app` 底下，就是 0.3 讀法乙，違反 DEP-23

**下一次怎麼做**：這條路線上，**只有一個主機目錄會被掛進容器：備份目錄**（`HD_BACKUP_DIR`，掛到 `/backups`）。其餘一律不掛。這件事由 `docker-compose.yml` 決定，**不要自己下 `-v`**。

### F-03 連接埠對應兩頭都不對

**發生了什麼**：`-p 3000:8000` 是「主機的 3000 → 容器的 8000」。

**為什麼不成立**：

| 端 | 問題 |
|---|---|
| 主機的 3000 | 現場的連接埠清單裡，**3000 已經有行程在聽**，而且與 9000 是同兩個行程——很可能是同機另一個專案的 Docker 轉送，也可能是這個容器自己開的（**要用 F-09 確認**）。無論是哪一種，本系統都不能再用 3000 |
| 容器的 8000 | 本系統的後端在容器裡聽的是 3000、護理端 8080、病人端 8081，**沒有任何東西聽 8000** |

**下一次怎麼做**：D-13 那三個埠要避開 3000 與 9000。現場清單上 8080、8081 是空的；後端埠要另外挑一個空的、向資訊室登記，寫進 `.env` 的 `HD_API_PORT`， **也寫進 D-14 的 `VITE_API_BASE_URL`**（兩處要一致，否則要重建映像檔）。

### F-04 要被 clone 的那一版根本不在 `master` 上

**發生了什麼**（事後在開發端查到的）：

| 分支 | 最新 commit | 有沒有《git clone＋Docker 路線詳細版》 | 有沒有 0921 三處容器修正 |
|---|---|---|---|
| `origin/master`（GitHub 預設分支） | `c4109fa`（《[備份、還原與關服務](ref-backup-shutdown.md)》前身那一冊） | **沒有** | **沒有** |
| `origin/docker-route` | `70b5de5` | 有 | 有 |

`git clone` 不指定分支時拿到的是 `master`。院方當天 clone 到的若是 `master`，拿到的就是 **《git clone＋Docker 路線詳細版》0.3 節說「不修會在院內直接倒下」的那一版**：沒有 OpenSSL、`/data` 屬於 root、compose 只接受繫結掛載。

**為什麼會這樣**：那一冊的 D-01 就是在防這件事——「本機與 `origin/master` 的 commit 一模一樣」。這一步在進院前沒有做到：修正推上了 `docker-route` 分支，沒有合回 `master`。

**當天實際 clone 到哪一版不知道**：只記到 `git remote -v`（有 `origin`），沒有記 `git log -1 --oneline`。這一版在容器裡、也在主機 C 槽上（F-02），F-10 可以查到。

**下一次怎麼做**：進院前把 `docker-route` 合回 `master` 並推上去，**然後**才做 D-01 的比對；交付單上寫 commit，現場 D-12 用 `git log -1` 逐字核對。

### F-05 進院前的 D-02～D-04 沒有到位

| 步驟 | 應該在進院前 | 這次 |
|---|---|---|
| D-02 | 在一台**乾淨的** Windows 機器上把 D-11～D-23 完整走一次 | 沒有。開發機上的演練（《git clone＋Docker 路線詳細版》0.3 節）與這台主機差很多：主機 3000 埠被佔、有 RAM 磁碟、Docker Desktop 從 Microsoft Store 更新 |
| D-03 | 兩週前把 9 題 Docker 問題清單寄給資訊室 | 沒有。第 2、3 題（Docker Desktop 授權、重新開機後有沒有人登入）到現在仍無答案 |
| D-04 | 準備一把唯讀、會過期的權杖 | 沒有。當天是**臨時建了一把 classic 權杖**，已於 0922 刪除，見 F-11 |

那一冊寫的是「院方要求容器的話翻這一冊」，但院方的要求是**當天才知道的**，準備工作排不進去。這條教訓要寫回總覽：**院方有可能臨時改要求，進院前就要把那一冊的準備做完，不管用不用得到。**

### F-06 院方的要求沒有當場釐清

0.3 那一句話有兩種讀法，現場沒有問清楚就動手。D-05、D-06 本來就是要在動手前把這件事講清楚、簽下來的一步；這次跳過了。

### F-07 主機當天連得到院外

這不是失敗原因，但是**這一趟最重要的發現之一**：當天 `docker run ... python` 能把 `python` 映像檔從 Docker Hub 拉下來、容器裡 `git clone` 能從 GitHub 拿到私有 repo，表示**這台主機當時有對外連線**。

- 這與部署規範「零院外連線」的前提不一致，要問清楚：**是一直都開著，還是當天為了部署臨時開的？誰開的、誰會關？** （D-03 第 7 題、D-24）
- 《[進院當天詳細版](visit-1-system-onsite.md)》H-08 預期路線 A「每一步都失敗」，這台主機上不成立
- 在這個問題有書面答案之前，**不得輸入任何真實病人資料**（與 D-24 同一條）

### 3.4 連接埠（DEP-37 第 2 項）

| 埠 | 現況 | 對本系統的意義 |
|---|---|---|
| **3000** | **已被佔用**（兩個行程） | 本系統預設的後端埠，**不能用**（F-03） |
| **9000** | **已被佔用**（與 3000 同兩個行程） | 很可能是同一個東西開的兩個埠；避開 |
| 8080、8081 | 沒有人在聽 | 護理端、病人端的預設埠**可以用**，但要向資訊室登記 |
| 其餘 | Windows 系統服務與動態埠 | 完整清單見原始照片（不上站） |

C-09 的回答是「沒在使用的都可以使用」——**這還不算登記**。登記要有人記下「這幾個埠是這個系統的」，否則下一個專案一樣會以為「沒在用就能用」（F-20）。
