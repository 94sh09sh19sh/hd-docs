## 最近三週

### [1014 — 規則引擎、護理紀錄、管理儀表板、平板遊戲化、透析小花園與麻將連連看完成，四條規則的門檻請醫師確認（迭代 17.8～22）](weekly/2026-10-14.md) · 修訂中

進度：

- **1009～1010 遊戲化寫成兩份其他文件**，需求寫進 SRS（73 → 81 條），排成迭代 20～23
- **1010 迭代 17.8**：護理紀錄**簽核後複製、貼進院內的正式紀錄**（DART 預設、SOAP 可切），緊急回報的圖示畫出症狀本身；血壓圖加正常區間判斷不做
- **1010 迭代 18**：風險分層提示、療程中預警、劑量調整參考加上 Kt/V 趨勢推估，**一律由固定規則計算、不經 AI**，只在護理站專業版；書面確認沒登記之前真實病人一律不比對
- **1010 迭代 18.1**：書面確認閘門**改放進系統管理**；**四條規則換成依指引與研究查的建議門檻，1014 請醫師確認**；迭代 18 漏收的文件（進度報告、架構圖、測試手冊附錄）補齊
- **1010 迭代 19**：**成效與工作量**（全單位的數字對照上線前的基準，沒有基準照實寫；各班工作量；一頁式簡報含還沒做到的），醫院管理層只看得到這一頁；**獎勵制度**只算流程上的事、沒有排名，每位護理師看得到自己的每一筆並可提出更正，看別人的要護理部同意、規則公告、觀察期跑完才開得起來；**對外報表**樣本少於 5 不出、要另一人核准；**對外展示環境**一條指令建出全是虛構資料的另一套
- **1010 迭代 20（遊戲化之一）**：問卷、衛教做完有一個安靜的「**完成了**」與一句感謝（與答案無關）；測驗**不再給病人看錯幾題**，答對的主題收進「**我的衛教小本子**」；**病友小撇步**只能選、不能打字，核准才播；跑馬燈多「**你知道嗎**」；護理師可以**回一張貼圖**，病人下次透析看到，**護理端沒有未讀數與待辦**；三個開關都關時跟以前一樣
- **1010 迭代 21（遊戲化之二）**：先寫《小花園的植物》子文件（12 種台灣常見的花、**避開有喪葬聯想與紅色的花**、24 張月份背景），插畫由程式產生；**透析小花園**每來透析一次就長大一點、不會枯，養分只看任務做了沒；開好的花可以**送給護理站**——總覽螢幕角落「今天的花瓶」，**有求助時讓位、不記哪位護理師收到**；也可以種進**同一班的大家的花園**，只看得到花、沒有人數；換平板、斷線都接得上；三個開關預設關，**開給病人前要長者看過插畫**
- **1011 迭代 22（遊戲化之三）**：**麻將連連看**——點兩張一樣的就消、熟練之後要連線，**沒有計時、沒有分數、不會卡住**，紅色改深棕；同一班當天的**今日牌局**，三人以上做完才說人數；遊戲紀錄整理成**狀態評估彙整**（只跟自己過去比、前 10 桌不說、只寫事實），在護理端新的「**病人詳細資訊**」頁；**社工、醫師各有唯讀帳號，只看得到這一頁**，每一次調閱記稽核；兩個開關預設關，**開給病人前要長者看過牌面**
- **1011 迭代 23.1（遊戲化之四，三次子迭代的第一次）**：先寫《記憶相簿的主題》——六個主題、**避開戰爭、政治、病與死、祭祀與透析病人要限制的吃喝**，起始 60 張的題目與說明；**第一批 30 張圖畫好**（不畫人、不畫商標、沒有紅色），第二批與程式在 23.2、23.3
- **1011 迭代 23.2（三次子迭代的第二次）**：**第二批 30 張圖畫好，起始 60 張全部畫完**（碗公、平交道、收音機、尪仔標、舞獅、打穀機……）；火車票與日曆的字一律以色塊代替，戲偶與獅頭只畫物件。程式與畫面在 23.3

### [1007 — 第二次進院部分成功，院方 API 取代手動輸入（迭代 15～17）](weekly/2026-10-07.md)

進度：

- **1001 第二次進院：B 級部分成功**。服務在院內主機上起來、外殼 APK 建好，**護理端登不進去**（後端不放行護理端的來源）；部署手冊改寫成第十五冊，另寫之三（為什麼登不進去）、之四（主機位址改用 IP）
- **1004～1005 讀了同院 IDH 系統的程式**，使用者逐項決定：直接用院方透析清單 API、抽血數值暫定拿不到（相關功能預設關閉）、低血壓門檻與處置直接套用、主機位址改用 IP
- **1005 新版需求，同日完成迭代 15～17**：院方 API 判斷得出來的事不再要護理師做；病人平板中間改成血壓與脫水量的折線圖加一條跑馬燈；**跑馬燈內容由 AI 寫、護理師只核准**。規則引擎與管理儀表板順延為迭代 18、19
- **1006 迭代 17.1**：簡易版改成把病人拖到平板（每次透析配，床號由院方資料補）；平板停用移到系統管理；護理端改名「公告與院內衛教」「結束與離院衛教」；一條指令就看得到病人平板透析到一半的樣子
- **1007 迭代 17.2～17.6**：簡易版**中間改成平板**，把病人拖上去就配好、平板右上角自動出現床號，病人框多一顆重新整理、**剛上機的病人排最上面**；**系統裡所有 AI 生成的內容禁用簡體字與中國大陸用語**，查到就請 AI 重寫，最後一次仍不合格也照樣交出，畫面上看不出這道把關；**病人平板加回病人姓名與現在時間**（病歷號仍不上首頁）；**透析一律以開始後四小時結束**（院方規定，不管院方資料有沒有預計結束時間），病人平板、簡易版、專業版的進度與「待確認下機」都照這一條；簡易版公告與院內衛教的**草稿可以換到後面幾則**；專業版**拿掉「病人」那一頁**（病人一律由院方 API 建立），「裝置管理」改成「**新增裝置**」只管註冊新平板，解除佈建移到系統管理，排班與指派的病人選單與簡易版同一個順序、有重新整理
- **1007 迭代 17.7**：「**護理師自己新增病人**」做成開關、**預設關閉**，開了專業版排班與指派、簡易版病人框同時出現（院方資料缺人時的備援）；系統管理「平板停用」改叫「**平板管理**」；簡易版**公告與院內衛教拖到平板就只在那台播，有病人配著就放得上**（原本要有床號）；開發用的床號改成醫院的寫法（A1、A2…，沒有 4 號床）
- **1007 待決事項有了答案**：院內主機的 **IP 是固定的**（Q-27 第 12 題，第三次進院照換）；斷電後由護理長重新登入；所有護理師都可以核准跑馬燈內容；院方資料沒有預計結束時間時一律以四小時計。新增 Q-36（衛教要不要維持三種）、Q-37（護理紀錄現在是什麼形式、系統的記錄怎麼接上現有作業）；跑馬燈開啟前仍要請長者在床上看過速度
