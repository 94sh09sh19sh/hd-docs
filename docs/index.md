# 血液透析中心平板照護輔助系統 — 進度首頁

**現在到哪**：**本週要做第一次正式部署**，需求文件已依部署前的六項變更改版——正式主機改為院內另一台 Windows 工作站（與其他專案共用、院方確保資源足夠，DGX Spark 退為 API 端點）、平板管控改走免 MDM、病人臨床資料確定走院方 API、選項與題庫由院方授權採用、護理端導覽只留每日必用、介面全面重新設計。部署前的修正排成迭代 7～10，原迭代 7、8 順延為 11、12（下週）。**迭代 7 已完成（0919）**：解除綁定找不到入口已修、離線安裝的 Prisma 引擎與版本鎖定已處理，版本更新一律先備份並實際驗證還原得起來，備份沒做成就不往下走；主機是共用的，連接埠沒登記、資料或備份放到人人碰得到的目錄、磁碟快滿了，這三種情形一律在啟動或更新前就擋下。
**迭代 8 已完成（0919）**：兩端介面依設計基準重做——求助區改成版面固定的一列（輪播因此**不可能**蓋住它，不再靠疊放順序閃避）、病人端字級與觸控目標拉到族群需要的下限、顏色不再是唯一線索；護理端總覽最上面直接寫出「現在需要我嗎」的答案，破壞性動作要按兩下且第二下說出後果。
**迭代 9 已完成（0919）**：「哪些功能出現、出現在哪裡、選項有哪些」全部變成資料——護理端主列收到 7 項、其餘收進「更多」，班表／成效基準／離院衛教首波關閉，**而「關閉」是連後端端點一起擋下**，不是把連結藏起來；院方授權採用的求助類別、透析前問卷、衛教題庫與回饋題目全部搬進資料表，護理長線上改、立刻生效，**改過題目會產生新版本，舊的作答仍指向舊版本**；畫面上不再出現需求編號、英文列舉值或開關識別字。
**迭代 10 已完成（0920）**：系統變成一份帶得進院內的離線安裝包——自帶執行期與資料庫引擎、自帶服務註冊與啟停腳本、逐檔附雜湊值，**解壓、套用遷移、啟動全程不連外**（有一支連線哨兵在旁邊記錄，有一筆就不得交付）；病人端補上離線快取，**拔掉網路仍開得出畫面**，求助區照樣在原位並明說現在通知不到護理師；平板跳出 Kiosk 時護理端裝置清單 30 秒內看得見，**而「沒裝 App」「已跳出」「失去回報」是三種不同的狀態**；更新與回退各實際演練一次，過程中抓到兩個只有把安裝包真的跑起來才會現形的缺陷（安裝包裡找不到專案根目錄而拒絕啟動、更新腳本自己擋住自己的遷移），都已修正。**乾淨機器上的全程離線安裝與實機平板佈建仍待現場執行**，表格已備在《[部署演練紀錄](notes/deployment-drills.md)》。
⏰ **成效基準的數字仍然沒有**，改排下週量測——首波只開放少數護理師與病人，紙本流程仍在跑，時機還沒過。
