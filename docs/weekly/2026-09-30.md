### 迭代 11：部署改為 Docker ＋ `git clone`（0926）

- compose 改寫：專案名稱固定、**繫結掛載只剩備份與設定兩個目錄**、資料與金鑰兩個資料卷標為 external（`down -v` 刪不掉）、映像檔標籤必帶版本號
- 新增 `check:container`，把「compose 不准怎麼寫」逐條變成檢查——0922 那個掛整顆 `C:\` 的容器就是它要擋的
- 正式環境設定下選用實驗室 AI，後端直接拒絕啟動
- **實測抓到兩個只有在容器裡才會現形的缺陷**：更新腳本在一次性容器裡以為服務已停（服務開著也照樣更新）；還原腳本在映像檔裡跑不起來。都已修正

| 開發機實測 | 結果 |
|---|---|
| 全新 clone ＋全新資料卷，只用 Git 與 Docker 從零部署 | 通過 |
| `down -v` 之後資料還在 | 通過 |
| 更新（新 tag、備份並驗證還原、套用遷移）／回退（舊 tag、舊映像檔、還原備份） | 各一次，通過 |

紀錄在《[部署演練紀錄](../notes/deployment-drills.md)》第 8 節。

## 待決事項

**本週取得的答覆**：

- Q-27：主機的 Docker 版本 0922 進院時已記下（Docker 29.3.1、Compose v5.1.1）；連接埠定為後端 `13000`、護理端 `18080`、病人端 `18081`

**要問資訊室的兩項 Docker Desktop 設定**（清冊記為 Q-27 第 9、10 題。這台 Docker 同時在跑別的專案，兩項都是整台主機的設定，要資訊室同意才能改）：

- [ ] **Send usage statistics 能不能關？**（0922 看到是開著的）
  不關的影響：Docker Desktop 會持續把它自己的使用情形送往 Docker 公司，服務執行期間主機就多一條常駐的院外連線。
  本系統的程式不經過這條線，但送出什麼由 Docker 公司決定、會隨版本改變，開發端無法逐項擔保；
  文件裡「服務執行時沒有任何一條線跨出醫院」（FR-S07、DEP-39）也要改寫成「有一條 Docker Desktop 自己的例外」
- [ ] **Microsoft Store 的自動更新能不能改成手動？** 這台的 Docker Desktop 是從市集裝的，更新由市集決定（F-16）；市集的設定管的是整台主機的所有 App。
  不改的話，Docker Desktop 可能在透析班中自己更新、重新啟動，容器全部中斷——護理端會跳斷線紅框、病人端約 11 秒後改成「請按床邊呼叫鈴」（迭代 14.3），新版也可能改變 compose 的行為

**不擋進院，但要在首波試用前有答案**：

- [ ] Q-33：目標平板的型號與解析度——「整頁不捲動」要在那台平板上重驗
