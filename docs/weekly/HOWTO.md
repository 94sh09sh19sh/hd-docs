# 每週紀錄維護流程（人用）

這頁寫給隔了一週回來、細節已經忘光的自己。從「這週做完了」到「別人點得到」，全部步驟在這裡。給 AI agent 執行的精簡版在 [AGENT.md](AGENT.md)。

## 摘要

- 真本在 repo 的 `docs/`，對外是 GitHub Pages 文件站；一律先改 repo 再 `docs:sync`，不要回頭改鏡像或站台
- 週中改到哪推到哪、首頁標「修訂中」；週三定版才補版本歷程，**先 `docs:sync` 再 `docs:freeze`**
- 三個網址：現行版（永遠最新）、凍結版（每週定版，之後不變）、鏡像 repo（只有工具在用）
- 舊站 HackMD 只在你明確開口時才同步
- 「踩過的坑」是一張症狀、原因、解法對照表，出事先查這裡
- 新增文件、子文件、分冊、截圖、改介面基準、改維護流程各有固定做法（「什麼時候不只是加一篇週報」）
- md 格式照全域省 token 規則：一段一行、表格不補空白、長文件開頭要有摘要（2026-10-23 起）
- 首頁只有四塊、兩張表列序固定，不准長回去

## 一次講完的全貌

文件的**真本在 repo**（`docs/`），對外看得到的是 **GitHub Pages 文件站**。所有內容都先改 repo，再同步過去，不要反過來去改鏡像 repo 或站台——同步是整份覆蓋。

```
週中  改 docs/<文件>.md
      首頁那幾列標「0909 · 修訂中」
        ↓  npm run docs:preview        本機先看長什麼樣（可略）
        ↓  npm run docs:sync           讀者看得到進行中的內容
        ↓
週三  寫 docs/weekly/2026-09-16.md
      首頁拿掉修訂中、日期換 0916、最近三週插一段
      改過的文件補版本歷程一列        ← 只有這天做
        ↓  npm run docs:sync           先把內容推上去
        ↓  npm run docs:freeze          再凍結，建立該週凍結版
        ↓
GitHub Pages                            別人看到的
```

**順序不能顛倒：先 `docs:sync` 再 `docs:freeze`。** 凍結版是在鏡像上打一個週次 tag， tag 釘住的是當下那個 commit——內容沒先推上去，凍到的就是舊的。（HackMD 時代是相反的，別照舊記憶做事；腳本會擋，但別靠它擋。）

## 三個網址，各自負責一件事

| | 網址 | 內容 | 誰在用 |
|---|---|---|---|
| **現行版** | `…/hd-docs/latest/` | 永遠是最新的 | 首頁的連結、你給別人的連結 |
| **凍結版** | `…/hd-docs/0916/` | 0916 那天定版的樣子，之後不再變 | 回頭對帳「當初談定的是哪一版」 |
| **鏡像 repo** | `github.com/94sh09sh19sh/hd-docs` | 站台的原始內容 | 只有工具在用，人不必進去 |

站台右上角有**版本下拉選單**，讀者可以自己在各週定版之間切換。凍結版只會往回指：它凍的是當時的內容，當時還不存在的後續版本，它的版本歷程裡自然沒有那一列。要從舊版跳到新版，用那個選單。

> **凍結版住在鏡像 repo，本地只留現行版。**
>
> 每一版 = 鏡像 `main` 上的一個週次 tag（內容來源）＋ `gh-pages` 裡建好的 `/<週次>/`。 **本地 repo 不再收任何舊版目錄**——同一份內容擺兩處，遲早有人改了其中一處，之後就分不出哪一份才是當初定版的那一份。
>
> 要看某一版，開站上的 `/<週次>/`；要原始檔，從鏡像的 tag 取： `git -C .docs-mirror show <週次>:docs/<路徑>`。首頁只掛現行版，所以**你給出去的連結永遠不會過期**，也不必每週重發。

**公開範圍**：鏡像 repo 是 public、站台是公開網址，知道網址就看得到（跟以前的 HackMD 自訂網址一樣）。 `robots.txt` 擋掉搜尋引擎收錄。程式碼、`README.md`、`.env` 都留在私有 repo，同步腳本只複製 `docs/` 與 `docs-site/` 兩個目錄，這條界線是結構上的，不是靠記得。

## 一次性設定

做過就不必再做。

1. **鏡像 repo**（只做一次）：

   ```bash
   gh repo create hd-docs --public --description "血液透析平板照護輔助系統 文件鏡像"
   npm run docs:sync
   ```

   第一次 `docs:sync` 會把鏡像 clone 到 `.docs-mirror/`（已 gitignore），之後每次沿用。

2. **GitHub Pages 來源**：第一次 `docs:freeze` 或 `docs:sync` 跑完，Actions 會建出 `gh-pages` 分支。到鏡像 repo 的 Settings → Pages，Source 選 `Deploy from a branch`、分支選 `gh-pages` / `(root)`。這一步只做一次，之後都自動。

3. **本機預覽用的工具**（可略，不預覽就不必裝）：

   ```bash
   pip install -r docs-site/requirements.txt
   ```

**新站不需要任何 API 權杖**，同步走的是 `git push`，沒有每月額度這回事。 `.env` 裡的 `HACKMD_API_TOKEN` 刻意留著——舊站還在，你開口時還要用它同步（見下一段）。

## 舊站（HackMD）

換到新站之後，HackMD 不再是每週流程的一部分，但**沒有廢掉**：

| | |
|---|---|
| 什麼時候同步 | **只有你明確開口時**。每週例行流程只推新站 |
| 指令 | `npm run docs:hackmd` 產生 `.hackmd-build/` → `npm run docs:hackmd:push` 推上去（加 `-- --dry-run` 先看清單）。要出凍結版再跑 `npm run docs:hackmd:freeze` |
| 權杖 | `HACKMD_API_TOKEN` 留在 `.env`，不要刪，也不要貼進任何文件、截圖或訊息 |
| 額度 | 免費方案每月 400 次，**目前已用盡**，訊息裡寫 `Resets at 2026-10-01`。收到 `429 quota_exceeded` 就停手，重試只會再吃掉配額 |
| 凍結版 | 0909 那批已取回並發佈到新站（只存在於鏡像 repo，本地不留），版本歷程一律指向新站，**不再依賴舊站**；0916 那批因額度用盡沒有推成功，不影響新站 |

手貼舊站時**一律貼 `.hackmd-build/` 底下的檔案，不要貼 `docs/` 原始檔**——兩者肉眼難辨，貼錯不會有任何錯誤訊息，但那篇的內部連結會全部變成死連結。分辨法：build 版第一行一定是 `---`，原始檔第一行一定是 `#`。

## 每週怎麼走

分兩段：**週中隨時改、週三收成定版**。差別只有一件事——版本歷程與 `docs:freeze` 只在定版日做。

### 週中：改到哪推到哪

1. 改 `docs/` 底下的文件。
2. 首頁標上修訂中，讓讀者知道這幾份正在動：
   - 頂部改成 `**本週定版**：0909｜**0916 修訂中**`
   - 表格裡**動過的那幾列**，定版欄改成 `0909 · 修訂中`（沒動的維持原樣）。全新的文件還沒有過第一次定版，那一欄先寫 `新增 · 修訂中`
3. 進度多的時候，該週週報可以**週中就先建起來當草稿維護**，不必等到週三一次補寫。檔名照樣用該週的星期三，檔頭狀態寫「進行中（…週中草稿，MMDD 定版時收尾）」，首頁「最近三週」那段標題後面加 ` · 修訂中`。**版本歷程與 `docs:freeze` 一樣不能碰。**
4. `npm run docs:sync`

> 交給 agent 改的話，這一步它會自己跑完再回報清單，不會停下來等你點頭（2026-09-10 起）。定版日建立凍結版那次仍會先問，因為凍下去改不回來。

想先看長什麼樣就跑 `npm run docs:preview`，瀏覽器開 <http://127.0.0.1:8000>，存檔會自動重整，按 Ctrl+C 結束。預覽完全在本機，不會推任何東西出去。

讀者這時點進去看到的是進行中的內容，但表格明白標著修訂中，不會被日期誤導。

> ⚠️ **週中絕對不要補版本歷程那一列，也不要跑 `npm run docs:freeze`。** 一旦打了 tag，那一週的凍結版就定型了，而凍結版建立後不再更新，救不回來。定版是週三的事。

### 週三：收成定版

#### 1. 開一份新的週報

```bash
cp docs/weekly/_template.md docs/weekly/2026-09-16.md
```

檔名用**該週開會日（星期三）的 ISO 日期**。開會日就是報告日，這樣檔案列表的排序就是時間序。內容照範本填。第一行 `# MMDD 週報 — 一句話標題` 很重要，它會成為站上那一頁的標題。

#### 2. 首頁收尾

開啟 `docs/index.md`：

1. 頂部改回單一週次：`**本週定版**：0916`，把「修訂中」整段拿掉
2. 兩張表格：這週動過的那幾列，`0909 · 修訂中` 換成 `0916`；沒動過的維持原樣
3. 「最近三週」最上方插入一段（新的排在上面），檔案裡有註解標出插入點：

   ```markdown
   ### [0916 — 一句話標題](weekly/2026-09-16.md)

   進度：

   - 三到五條重點
   ```

   插完如果超過三段，把**最舊的那一段整段刪掉**，同時在 `docs/weekly/archive.md` 的表格最上方補一列。首頁永遠只有三週，這是這套結構最需要自律的地方。

#### 3. 新的一頁要進側欄

站台側欄的列序寫在 `docs-site/mkdocs.yml` 的 `nav`。**新增一篇週報或一份文件，這裡要跟著加一列**，否則站上點不到（頁面仍會建出來，但沒有入口）。列序照首頁那兩張表的讀者思考順序，不要重排。

這一步取代了 HackMD 時代「在對應表裡加一行網址」。差別是：現在忘了加只是側欄少一列，不會像以前那樣整篇連結失效。

#### 4. 改過的文件補版本歷程

這週動過的每份文件末尾都有「版本歷程」表，在**最上面**加一列：

```markdown
| 0916 | 2026-09-16 | 補上 FR-N08 的離線重送規則 |
```

第一欄只寫四位數週次，**不要寫網址**——同步時會自動換成該週凍結版的連結。異動摘要寫「改了什麼」，不是「改了哪一節」，這一欄是給半年後的人看的。

#### 5. 先同步，再凍結

```bash
npm run docs:sync     # 內容先推上去，現行版更新
npm run docs:freeze   # 再打週次 tag，建立凍結版
```

`docs:freeze` 會掃過所有文件的版本歷程，把出現過、鏡像上還沒有同名 tag 的週次建出來。已經存在的一律不動，它只會印一行「凍結版已存在，不動」。

不確定會做什麼就先看：`npm run docs:freeze -- --dry-run`。只想處理某一週：`npm run docs:freeze -- 0916`。

凍結版建好之後**再跑一次 `npm run docs:sync`**：版本歷程第一欄的週次，要等該週凍結版真的存在，同步時才會換成連結；還不存在的維持純文字，不留死連結。

#### 6. Commit

```bash
git add docs docs-site scripts package.json && git commit -m "docs: 週報 0916" && git push
```

`.docs-mirror/` 與 `.docs-preview/` 已經 gitignore，不會進版控——它們隨時可以重新產生。

## 踩過的坑

| 症狀 | 原因 | 解法 |
|---|---|---|
| 站上看不到剛加的那一頁 | `docs-site/mkdocs.yml` 的 `nav` 沒加那一列 | 補一列再 `docs:sync`。頁面其實建出來了，只是側欄沒有入口 |
| 凍結版的內容是舊的 | 先跑了 `docs:freeze` 才跑 `docs:sync` | 順序一律是先 sync 再 freeze。腳本會擋下沒同步就凍結的情況，但別靠它 |
| 週次 tag 打錯了 | 版本歷程那一欄寫錯週次 | **趁還沒 push 才救得回來**。已經建出去的凍結版視為既成紀錄，要修正就在新的一週寫明 |
| 改了 `docs/` 但站上沒變 | 只改了 repo，沒跑 `docs:sync`。**`git push` 不會更新公開站**——站台只看鏡像，私有 repo 推了也沒用 | 跑 `npm run docs:sync`。跑完 Actions 還要一兩分鐘才建完。交給 agent 時，它的收尾順序寫在 AGENT.md「git：docs 改完就 commit、push」 |
| `docs:sync` 說找不到鏡像 repo | 鏡像還沒建立 | `gh repo create hd-docs --public`，再跑一次 |
| 在鏡像 repo 或站台上改的字不見了 | 同步是整份覆蓋，鏡像是單向的 | 內容一律改 `docs/`，鏡像只當展示 |
| 預覽起不來，說找不到 mkdocs | 本機沒裝建站工具 | `pip install -r docs-site/requirements.txt`。只影響預覽，不影響同步 |
| 版本歷程的週次沒有連結 | 那一週的凍結版還沒建立 | 跑 `npm run docs:freeze`。沒有對應凍結版時刻意維持純文字，不留死連結 |
| 想知道 0909 那一版是怎麼來的 | 換站之前它發佈在 HackMD 上，repo 裡只有當天的 commit 樹，兩者不一定相同 | 已用 `node scripts/snapshot-import.mjs 0909 --from-commit <sha>` 從舊站取回發佈出去的那一份，推成 `snapshot/0909` 分支＋`0909` tag 建成新站的該版。取回的檔案不留在本地 |
| 想在本地找某一版的原始檔 | 本地只有現行版，凍結版的家在鏡像 repo | `git -C .docs-mirror show <週次>:docs/<路徑>`；或直接開站上的 `/<週次>/` |
| 想補建更早的週次 | 那幾週的內容不在鏡像的 main 上 | **不要用 `docs:freeze`**——它會把 main（今天的內容）打上舊週次。照上一列的做法匯入該週真正發佈出去的版本 |
| PowerShell 讀出來的中文是亂碼 | 系統預設編碼頁是 big5 | 讀檔一律 `Get-Content -Raw -Encoding UTF8`，省略 `-Encoding` 就會壞 |
| 改了介面，但下一個人又改回去 | 只改了程式，沒改設計基準；或只改了文件，沒改 skill | 兩份一起改（見下方清單）。基準沒更新，下次就會再發明一組新的顏色與字級 |
| 編輯某一行時被支語 hook 擋下，但那行看起來沒問題 | 詞庫收了一些在醫學與公文語境屬正常用法的詞，整行寫入就會被擋；兩個詞相連時也會跨詞湊出一個詞庫裡的詞 | 縮小編輯範圍，只改那個片段；或在專案特例檔 `lab_project/.claude/zhiyu-allow.txt` 加一行 `!詞組` 窄放行（全域詞庫 `~/.claude/zhiyu-check/zhiyu-words.txt` 不改） |
| 改系統的支語詞庫（`packages/shared/zh-tw/words.txt`）時被 hook 擋下 | 那份詞庫本來就寫滿支語，hook 只放過自己的檔案（`~/.claude/zhiyu-check/` 底下、檔名 `zhiyu-` 開頭）（2026-10-07，迭代 17.3） | 詞庫不是文件，不必繞：要放行的詞**以行號註解**（`sed -i '<行號>s/^/# 放行：/'`），要補的詞若含 hook 詞庫裡的詞就先不補、告訴使用者。改完一定 `npm run zh-tw:data`，`verify:iteration17-3` 步驟 1 會抓忘了產生的 |
| 文件與程式裡寫「血壓不正常」這類舉例被 hook 擋下 | 舉例本身含詞庫裡的詞 | 文件裡不舉支語的實例，改寫成「描述檢查結果的正常句子」這類說法；驗收腳本要違規樣本時從字表本身取（`verify:iteration17-3` 的做法） |
| `verify:iteration17-3` 步驟 3 不通過，指到某一份文件 | 那一步拿 `docs/` 全部與兩端的文案當「不能誤擋」的語料；**hook 不擋台灣不這樣寫的字形**，文件裡舉例寫了那種字形，hook 放行、這一步卻抓得到（1007 寫 17.3 修正紀錄時就踩了一次） | 文件裡不寫那些字形本身，改寫成「另一種字形」或指向 `packages/shared/zh-tw/variants.txt`；真的是詞庫誤擋就放行那個詞，不是改文件 |
| `verify:iteration17-3` 步驟 7 說兩端原始檔出現用語把關的字樣，或新的清單列出了「輸出含簡體字或中國大陸用語」 | 使用者 1007 規定：**任何時候都不能讓前端出現 AI 用語把關的痕跡或訊息**。退回的紀錄資料庫照記，只靠查詢時濾掉 | 畫面文案不提這道把關；新增任何會把 `ai_invocations` 或稽核回給前端的查詢，都要套 `apps/api/src/common/zh-tw-retry.ts` 的條件、提示用 `withoutZhTwRetryNote` |
| 測試分冊開頭「主手冊 §13」的連結點了不會跳到索引 | §13 的標題帶迭代範圍（1018 迭代 27 起是「迭代 3-27 分冊」），每多一本分冊改一次標題，錨點就跟著變；迭代 3～7 分冊的連結停在 `3-14`、主手冊開頭停在 `3-16`，1005 才發現 | 改 §13 標題時，`grep -rn '#13--' docs` 把所有錨點一起改 |

## 什麼時候不只是加一篇週報

- **週中改了需求文件或進度報告** → 首頁那一列標修訂中 → `docs:sync`。**不要碰版本歷程與 `docs:freeze`**
- **週三定版** → 拿掉修訂中、版本歷程加一列 → `docs:sync` → `docs:freeze`，缺一步凍結版就不會出現
- **新增一種文件**（不是週報）→ 建檔（文末要有「版本歷程」表）→ 首頁表格加一列（**照下面的列序放進去，不要一律加在最後**；定版欄先寫 `新增 · 修訂中`） → `docs-site/mkdocs.yml` 的 `nav` 加一列 → `docs:sync`
- **新增一份「其他文件」**（不屬於需求、報告、參考、測試、部署五類的單篇方案評估、決策紀錄或修正紀錄，放 `docs/notes/`） → **掛到《其他文件總表》（`docs/notes/index.md`），不動首頁**（2026-10-07 起）。總表分兩張：**一般文件**、**小迭代文件**（9.1、14.1、17.2 這類非整數迭代的修正紀錄）；定版欄先寫 `新增 · 修訂中` → `nav`「其他文件」底下對應的那一組加一列 → `docs:sync`
- **某份文件有一大段在條列**（2026-10-15 起）→ 收進子文件、掛在原處，母文件留連結，連結上方或下方寫明收入方式與怎麼維護。收入分兩種：**永久收入**是那張表一直往下長、新的一筆也寫進子文件（測試手冊的路由表、實作規格書 1.1 的改動紀錄）； **一次性收入**是做完的階段搬走、新的階段照舊寫在母文件（實作規格書的迭代 3～23、兩份進度報告的已完成部分）。搬的時候節號與標題一律不動，別處寫的「實作規格書 4.21」才找得到。子文件有版本歷程、不上首頁、`nav` 裡和母文件收成一組。細節與目前五份的清單在 [AGENT.md](AGENT.md) 的「大段條列收進子文件」
- **改架構圖** → 改 `requirements/architecture-diagrams.src.html`（不要單獨修 PNG）→ 照 `architecture-diagrams.md` 文末的指令重新產生 PNG → `docs:sync`。 **圖片走 repo 相對路徑，不必再另外上傳、不必換任何網址**（這是換掉 HackMD 之後少掉的一整條規則）
- **週報要附截圖**（2026-10-07 起）→ PNG 放 `docs/weekly/images/<週次>/`，週報最後加一節「附錄：截圖」，每張圖上面一句話說是誰、哪個尺寸、看什麼。公開站看得到，**只能是模擬資料的畫面**（`demo:patient` 的虛構病人）；截圖前確認沒有網址列、平板金鑰、院內位址。**病人平板只截橫放 1280×800**（2026-10-14 起）：院內平板實際是橫放使用，直放的畫面不是病人會看到的樣子，不放進週報
- **測試手冊又長出一個迭代** → 在 `docs/testing/` 開一本 `iteration-N.md`，內容只寫該迭代新增的部分，共用的環境與主線留在主手冊，再到主手冊最後一章的分冊索引補一列，並在 `nav` 加一列。 **不要把分冊掛到首頁**——三十九本分冊各占一列，首頁就從入口變成目錄了；讀者要動手驗收時點進主手冊，第一眼就看得到索引。項次編號跨冊不重複，抽出既有章節時沿用原編號，因為那些編號已經寫進週報與驗收紀錄。單一字母到迭代 16 的 `z` 用完了，迭代 17 起改兩個字母（`aa`、`ab`…），照字母順序往後接，一看就知道排在 `z` 後面。細節規則在 [AGENT.md](AGENT.md) 的「測試手冊的分冊」
- **部署流程又多一段**（現場多了一類出錯、多了一個要先問的問題）→ 改 `docs/deployment/` 對應那一冊， **不要在首頁加列**：各冊從總覽的索引進去。規則本身若變了，要改的是《部署規範》而不是手冊——手冊只寫「手指要按什麼」。第十五冊（1001 取代第十四冊）是第十一～十三冊的新手導讀版，指令是抄過去的：改了那三冊的指令，第十五冊對應的步驟要一起改；改了 `deploy/hospital.env.example`，第十五冊之一、之二兩本 `.env` 子手冊要一起改。進院回來寫的紀錄（第十冊、第十四冊之四）只記錄不改寫，被它取代的舊版手冊只在開頭標明已取代。細節規則在 [AGENT.md](AGENT.md) 的「部署手冊的分冊」
- **改了介面設計基準** → `docs/notes/uiux-design-baseline.md` 與 `.claude/skills/hd-uiux/` **兩份一起改**。前者寫給人看（為什麼這樣設計），後者寫給 AI agent 看（實際數值與檢查步驟）。 skill 不在 `docs/` 底下，所以不上站、不出凍結版，但它才是動介面時真正被讀的那一份
- **改了維護流程本身**（這頁講的規矩變了、文件多一份少一份、npm 指令改名、又踩到新的坑） → 這頁與 [AGENT.md](AGENT.md) **兩份一起改**。詳細的判斷表在 AGENT.md 的「改完文件，回頭檢查這兩份指南」。這兩份沒有版本歷程、不出凍結版，改完只要 `docs:sync`
- **寫或整理文件的格式**（2026-10-23 起）→ 照全域的 md 省 token 規則：一段一行、表格不補空白、超過 80 行的文件開頭寫 `## 摘要`。格式整理不算改寫已發佈的紀錄，也不補版本歷程；首頁不加摘要。細節在 [AGENT.md](AGENT.md) 的「md 格式」
- **那週沒進度** → 不要建空頁，首頁直接跳過該週。時間序有斷點沒關係，硬湊出來的空白紀錄才難讀

## 首頁不准長回去

首頁在 2026-09-10 從 100 行砍到 51 行，砍掉的是目錄結構與附錄——那些是維護者的東西，不是讀者要的。**行數本身不是上限**（之後新增文件、換新的一週都會讓它長短變動），真正不准破的是下面這幾條。想加東西之前先讀一次：

- **只有四塊**：最近三週／實作文件／需求文件／其他文件。不要再開新的一塊，也不加開頭摘要。「實作文件」原叫「我要找…」，2026-10-23 依你的指示改名，表頭與列序不變。原本最上面還有一塊「現在到哪」，2026-09-22 拿掉了——它寫的全是週報已經寫過的事，越堆越長。 **要速看進度，看「最近三週」每段底下的「進度」條列**；頂部只留「本週定版」那一行，不要把現況摘要加回去。「其他文件」是 2026-09-19 加的，放不屬於前四塊的單篇方案評估（檔案在 `docs/notes/`）。它是**刻意留的小出口**，免得每有一份技術決策就要硬塞進需求文件、或是沒地方放就不寫；但正因為是出口，最容易長歪——**果然長歪了**：到 2026-10-07 已經十三份，每多一個小迭代就多一列，比其他三塊都長。使用者當天指示**收進一份總表**（`docs/notes/index.md`，分成一般文件與小迭代文件兩張表）， **首頁那一塊保留標題、只剩一行連結**。之後新增 `notes/` 底下的文件只改總表，首頁那一行不再變長；不要再把個別文件掛回首頁
- **兩張表的列序是照讀者的思考順序排的，不要動**（2026-09-10 定）：
  - 「實作文件」：臨床端進度報告 → 技術端進度報告 → 架構圖 → 資料字典 → 這套系統是用什麼蓋的 → 病人端外殼 App 契約 → 完整手動測試手冊 → 部署手冊。先知道進度到哪，再看系統長什麼樣、蒐了哪些資料，然後是名詞解釋與外殼的介面（0927 加，參考文件排在一起），最後兩列才是動手的兩份——先驗收，再部署。 **測試手冊的迭代分冊與部署手冊的各冊（十五冊與八本子手冊）都不另占一列**：它們從各自的索引進去，理由見下一段
  - 「其他文件」在首頁只有一行連結，沒有列序。總表裡兩張表（目前四十一份）：
    - 一般文件沒有閱讀動線，新增的排在表尾（目前二十三份：平板管控、介面設計基準、部署演練紀錄、部署路線比較、同院 IDH 系統參考調查、三種衛教的 AI 生成、透析中的遊戲化、透析中的遊戲化之一、之二、之三、之四、之五、之五附錄、緊急通報的處理流程與護理紀錄連動、管理儀表板、獎勵制度與對外揭露的更新與修正、之一：三者蒐集與展示的資料、暫用平板、緊急求助的語音說明、之一：開源專案與模型的選型、之二：根本判斷、之三：鏡頭能做到哪些事、之四：完整流程、蒐集資料的完整取出）。 **子文件例外**（1010 起）：緊接在上層文件那一列下面、名稱前加 `↳`，側欄裡和上層文件收成一組
    - 小迭代文件依迭代編號排（目前十八份：迭代 9.1 修正清單、迭代 14.1～14.5 修正紀錄、迭代 17.1～17.8 修正紀錄、迭代 18.1 修正紀錄、迭代 23 的三次子迭代、迭代 27.1 修正紀錄、迭代 27.2 修正紀錄）
  - 「需求文件」：FDE 數位化評估報告 → SRS → 資料庫使用規範 → 實作規格書 → 部署規範 → 尚待確認事項清冊。前五份是從為什麼要做，讀到做什麼、資料怎麼管、怎麼實作，最後是怎麼部署；第六份（清冊）是進行中的問題總表，不在這條動線上，固定排最後一列。 **這不是優先權順序**——衝突時仍以實作規格書為準，優先權寫在「角色」欄，不要拿列序去推
- 每週紀錄**最多三段**，每段三到五條
- 細節一律留在週報或該文件裡，首頁只放連結與一句話
- 維護用的說明（本頁與 AGENT.md）只准出現在最後一行

首頁一旦開始長內容，累積半年後就沒人讀得下去了，那時再砍要花的力氣是現在的十倍。
