## 完成內容

### 1. 照醫師建議，護理端放了意見表單連結

| 看什麼 | 結論 |
|---|---|
| 護理師看到的 | 護理端畫面右上角（專業版在「系統管理」旁；簡易版在登出旁）多一項「意見」，點了在新分頁開表單，30 秒填完；不跳視窗、沒有紅點 |
| 不收什麼 | 不帶病人、床號、帳號；表單開頭寫「請不要寫病人姓名、病歷號或床號」 |
| 院內的電腦 | 網址由系統管理者填，沒填就不出現；系統本身不連外，是護理站電腦的瀏覽器去開。**護理站電腦開不開得了外部表單還沒試過**，表單建好後請醫師或護理師點一次 |
| 現在 | 程式 1125 做完；跟下一個版本一起院內換版，換版後系統管理者填網址才出現 |

細節：《[1202 週報之一](2026-12-02-detail.md)》第 1 節

### 2. 開發端判斷：紙卡先併行，連結上線滿一個月再決定留不留

| 看什麼 | 結論 |
|---|---|
| 為什麼併行 | 連結要等院內換版，首波可能先開始；護理站電腦未必開得了外部表單；共用電腦旁邊有人，怕被看到的人寧可寫紙卡；印卡加一個意見箱，不必開發 |
| 護理師的負擔 | 不寫就沒有任何負擔；不另外指定護理師收卡 |
| 之後 | 連結上線滿一個月，紙卡一個月少於 2 張就收掉意見箱，只留表單 |
| 請醫師答 | 紙卡誰收：醫師每週三開會前拍一次意見箱的照片（不必整理，開發端整理），還是開發端進院時才收 |

細節：《[1202 週報之一](2026-12-02-detail.md)》第 2 節

### 3. 回饋要用在論文：問卷、訪談、跟班紀錄先送審，核准前收的只用來改系統

| 看什麼 | 結論 |
|---|---|
| 要送審的 | 第 2、4 週的短問卷（SUS 正式中文版＋3 題）、訪談、跟班觀察紀錄；表單與紙卡的回應要引用在論文，也寫進送審範圍 |
| 核准前 | 表單與紙卡照收，只用來改系統、不寫進論文；問卷不發，第 2、4 週改成核准後第 2、4 週 |
| 請醫師答 | 要不要與錄音的同意書（病人、護理人員）併成母計畫倫理審查的同一次修正——同一個計畫、同一批護理人員，開發端建議併成一次 |

細節：《[1202 週報之一](2026-12-02-detail.md)》第 3 節

### 4. 斷電重開、護理長登入之後，服務會自己回來

| 看什麼 | 結論 |
|---|---|
| 之前 | 1116 進院前演練發現：主機上的 Docker 關掉再開，本系統不會自己回來，要有人下指令；院內的版本照帶、當已知限制 |
| 現在 | 1126 改成會自己回來，開發機實測 Docker 起來後十幾秒服務就好了；跟下一個版本一起院內換版才生效 |
| 沒變的 | 斷電後還是要護理長到主機以平常的帳號登入（Docker 要有人登入才會啟動）；院內真的重新開機還沒驗過，要院方准、挑不影響同機另一個專案的時段 |

細節：《[1202 週報之一](2026-12-02-detail.md)》第 4 節
