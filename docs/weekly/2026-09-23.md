## 附錄 A · 容器路線的技術問答（0923）

> 0922 進院後整理的問答，回答的是「**如果院方堅持用容器，會碰到什麼**」。
> 這裡的做法與指令**都還沒有在乾淨的機器上演練過**，是下一次演練的題目，不是已驗證的步驟。
> 兩條路線怎麼選，看《[部署路線比較](../notes/deployment-route-comparison.md)》。

### A.1 斷電重開後，服務能不能自己起來

可以，但三環都要接上，少一環就停著：

| 環節 | 做法 | 現況 |
|---|---|---|
| 恢復供電後自動開機 | BIOS 的「Restore on AC Power Loss」設為開機 | 沒問過（第十冊 F-20 第 2 題） |
| 開機後 Docker 要啟動 | 看下表，取決於用哪一種 Docker | **卡在這裡**（F-08） |
| 容器要自己回來 | compose 設 `restart: unless-stopped` | 第九冊已有 |

| 路線 | 開機後要不要有人登入 Windows |
|---|---|
| Docker Desktop（這台主機現在裝的） | **要**。它是登入後才開啟的桌面程式，不能當成開機就跑的服務 |
| WSL2 裡另裝 Docker Engine，由開機排程工作啟動 | 不用 |
| 離線安裝包，由排程工作啟動 | 不用 |

### A.2 在 Windows 上用 Docker Engine：WSL2 就是那台 Linux

Docker Engine 一定要跑在 Linux 上，但不用另外架一整套虛擬化軟體——**WSL2 本身就是 Windows 內建的輕量 Linux 虛擬化環境**。
Docker Desktop 本來就跑在 WSL2 上，所以這台主機 BIOS 的虛擬化已經開著。

做法：

1. 裝一個 WSL2 發行版（例如 Ubuntu），在裡面裝 Docker Engine。
2. `/etc/wsl.conf` 開啟 systemd，讓 Docker 隨這台 Linux 啟動。
3. Windows 建排程工作：觸發條件「開機時」、勾「不論使用者是否登入都要執行」，指令 `wsl -d Ubuntu -- sleep infinity`。

要注意的地方：

| 問題 | 說明 |
|---|---|
| 排程工作要綁一個帳號 | WSL 發行版跟著 Windows 使用者註冊，不能用 SYSTEM 跑，要指定帳號並存它的密碼 |
| WSL 閒置會自己關 | 沒有程式掛著就會關，所以第 3 步用 `sleep infinity` 讓它一直開著 |
| 護理站可能連不進來 | WSL2 預設只有主機自己連得到；要讓區網連進來，得開鏡像網路（`networkingMode=mirrored`，Windows 11 22H2 以上或新版 Server），或用 `netsh portproxy` 轉接 |
| 院內沒有網路 | Ubuntu 映像檔、Docker 的 .deb 套件、容器映像都要事先打包帶進去 |
| 與 Docker Desktop 衝突 | 兩者一起跑會搶 Docker 的連線與連接埠，要先停用 Docker Desktop |

這條路走得通，但比安裝包路線麻煩；安裝包路線用排程工作一樣能開機自動啟動，沒有網路轉接與授權問題。

### A.3 Docker Desktop 的授權

Docker Desktop 是商業軟體。免費使用只限個人、教育、非商業開源專案，
或員工少於 250 人**而且**年營收低於 1,000 萬美元的組織；其餘要按人數買付費方案。
醫院幾乎一定超過門檻，所以要確認院方有沒有買、願不願意買（第十冊 F-20 第 4 題）。
沒有授權就裝，法律責任在院方。條款以 Docker 官方公告為準。

Docker Engine 本身是開源、免費的；改走 A.2 的路線，授權問題一起消失。

### A.4 微軟自動更新對服務的影響

| 更新 | 影響 |
|---|---|
| 市集更新 Docker Desktop（這台是從 Microsoft Store 裝的，F-16） | Docker 重新啟動，容器全部短暫中斷；新版的行為可能改變（compose、WSL 整合） |
| Windows Update 重新開機 | 回到 A.1「要有人登入」的問題，沒人登入就一直停著 |
| WSL 核心更新 | 整個 WSL 重新啟動，容器全部停掉 |
| 資料 | 具名資料卷不會因為更新而消失 |

對策：關掉市集對 Docker Desktop 的自動更新；Windows Update 設使用時段並延後重新開機。兩項都要資訊室同意。

### A.5 資料與備份的保護

**資料庫放在容器裡**：

- 容器裡是 Linux 的檔案權限，不是 NTFS 權限，而且擋不住人：**能下 `docker` 指令的人，就能進容器或把資料卷掛出來讀**。
- SQLite 的檔案鎖是處理同時寫入用的，不是安全機制。
- 所有具名資料卷都存在**同一個** vhdx 虛擬磁碟檔裡，位於那個使用者的 `AppData` 底下。
  NTFS 只能鎖整個檔案，**所有專案共用一把鎖**，而且鎖的是 Windows 使用者，不是專案。
- 真的要防讀取，要靠加密（SQLCipher 或 BitLocker）。

**想分專案而改用 bind mount**（每個專案掛到各自的 Windows 資料夾、各自設 NTFS 權限），有兩個限制：

- 只擋 Docker 外面的 Windows 使用者。容器存取那些資料夾時用的是執行 Docker Desktop 的帳號，
  能下 `docker` 指令的人照樣能把那個帳號讀得到的資料夾掛進自己的容器。在 Docker 裡面，還是同一把鎖。
- **SQLite 不適合放在 bind mount 的 Windows 資料夾**：跨系統檔案共享上的檔案鎖不可靠，資料庫可能損毀。第九冊把資料放具名資料卷就是這個原因。

**備份掛在 Windows 目錄**：

- 只掛備份用的子資料夾，而且只掛給備份容器；**絕不再掛整顆 `C:\`**（0922 的錯誤，F-10）。
- NTFS 權限拿掉繼承，只留 Administrators、SYSTEM 與執行 Docker 的那個帳號。
- 備份檔本身加密（例如 7z 的 AES），檔案被拷走也讀不到。
- 至少另存一份到別的機器或媒體，並驗證雜湊值。這台主機本身不可靠，同機備份等於沒有備份。
- 可以請院方開 Defender 的「受控資料夾存取」防勒索軟體。

### A.6 Docker 做不到專案層級的權限隔離

只要能連上 Docker 引擎（`docker-users` 群組或管理員），就能看、停、進入**所有**容器，讀**所有**資料卷——等於本機管理員。

和 Windows 權限的連動只有入口這一層：「能不能用 Docker」由 Windows 的 `docker-users` 群組決定，Docker 裡面沒有更細的權限。
要做到「沒權限的人讀不到」，只能：

- 嚴格控管 `docker-users` 與 Administrators 的成員
- 每個專案的資料各自加密、金鑰分開
- 由應用程式自己的帳號權限把關
- 或直接分開主機

### A.7 Administrator 與 SYSTEM

| | Administrator | SYSTEM |
|---|---|---|
| 性質 | 使用者帳號（或 Administrators 群組成員） | 作業系統自己跑服務用的身分 |
| 能不能登入 | 能 | 不能 |
| 受不受 UAC 限制 | 受 | 不受 |
| 權限 | 很高 | 本機最高，能碰 SAM 等管理員預設碰不到的地方 |

管理員隨時能提升成 SYSTEM（例如用排程工作），實務上兩者差不多等價。

**這台主機兩個都沒有密碼**：

- **Administrator 應該設密碼。** 空密碼帳號預設擋網路登入，但坐到主機前就能直接進去；這台無人看管，等於誰碰到誰就有全部權限。
  這是院方的主機，要由資訊室設定並講好密碼由誰保管，**不要自己改**。
- **SYSTEM 不能設、也不需要設**，它本來就沒有密碼、不能登入。
- 若改用自動登入，要用另一個**非管理員**帳號，不要讓 Administrator 自動登入。

### A.8 主機上自己查得到的情報

大部分不需要管理員權限，下次進院可以當場查、當場抄：

| 要查的 | 指令 | 查不到、要問資訊室的部分 |
|---|---|---|
| 固定 IP（C-08） | `ipconfig /all`；「DHCP 已啟用：否」代表手動設定的固定 IP | 顯示「是」時仍可能是院方在 DHCP 伺服器保留的位址，主機上看不出來 |
| 防毒軟體（C-12） | `Get-CimInstance -Namespace root/SecurityCenter2 -ClassName AntiVirusProduct`；若是 Defender，再用 `Get-MpPreference` 看排除清單 | 趨勢這類集中管理的產品，排除清單設在院方的管理主控台，本機管理員通常看不到也改不了 |
