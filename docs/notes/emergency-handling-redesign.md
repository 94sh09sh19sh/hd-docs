# 緊急通報的處理流程與護理紀錄連動：重新設計規畫

版本：v0.1　文件狀態：草案（2026-10-15 開立）　適用讀者：護理部、FDE 工程團隊

---

## 0. 本文件的定位

1015 使用者實際操作護理端之後，對緊急通報提出四件事：兩個頂端橫幅不消失的小問題，以及兩個設計上的問題——護理師去床邊之前看不到病人的背景、護理紀錄要事後回想才填得出來。這一份把四件事查清楚，寫下重新設計的規畫。

**這一份不是需求文件。** 需求文件一條都還沒改；要改的條文列在第 6 節，待決定的事列在第 8 節，使用者決定之後再一次改齊需求文件、排進迭代。與需求文件衝突時，以需求文件為準。

**1015 只改文件，程式沒有動**（使用者 1010 的規定：叫更新文件就只改文件）。

### 0.1 前提：護理師手上沒有平板或手機

這是整份規畫的出發點，見《尚待確認事項清冊》[Q-30](../requirements/open-questions.md#q-30-護理師的行動裝置)。護理端只開在護理站的一兩台電腦上，所以：

- 護理師**離開護理站之前**是唯一能看資料的時間，到了床邊什麼都看不到
- 護理師**回到護理站之後**才能登記，床邊發生的事一律是「回來才記」
- 「我到床邊了」這顆按鈕（FR-N10）跟著「需要特定裝置才用得到的功能」開關關著，到達時間是空的

使用者 1015 認為目前「看到警報 → 去處理 → 回來選處理方式結案」的操作本身沒有問題，要改的是**離開前多看一眼**與**回來那一下同時把護理紀錄寫好**。

## 1. 1015 提出的四件事

| # | 使用者看到的 | 查出來的原因 | 處理 |
|---|---|---|---|
| 1 | 專業版從頂端橫幅「前往處理」到緊急通報頁，按「我接手」之後，**頂端的橫幅沒有消失** | 與第 2 件同一個原因（第 2.3 節） | 第 2 節 |
| 2 | 簡易版處理完（結案），專業版緊急通報頁那一筆消失了，**頂端橫幅沒有消失** | 橫幅只認得「已接手」，**結案或取消之後反而會冒回來**（第 2.2 節） | 第 2 節 |
| 3 | 簡易版點緊急通報，出現的是**處理方式**，不是病人前幾次的通報、生理數值與透析前問卷 | 簡易版點一下即確認通報並展開處理方式（SRS 5.2、FR-N16），背景摘要只在專業版有，而且專業版也沒有院方量測 | 第 3 節 |

## 2. 兩個小問題：頂端橫幅為什麼不消失

**結論：兩個都不正常，是同一個錯誤。**

### 2.1 現在的規則（迭代 14.4）

專業版每一頁上緣的求助橫幅（`App.tsx` 的 `HelpRequestAlerts`），清單是這一頁開著期間收到的每一則求助，只有兩種情形會拿掉：

1. 按了那一則的「前往處理」或「稍後」
2. 即時快照裡那一則的狀態**明確不是「待處理」**（迭代 14.4 加的：別處接起來的不佔位置）

而且 14.4 刻意定了一條安全規則：**快照裡找不到的一律留著**——輪詢補的快照可能比求助事件還舊，找不到不代表已經處理。

### 2.2 漏掉的地方：結案之後快照裡就找不到了

即時快照每一床的 `pendingHelpRequests` 只收**還沒結案**的求助（待處理、已接手）。一則求助走完一輪，橫幅的變化是這樣：

| 時點 | 快照裡那一則 | 橫幅 |
|---|---|---|
| 病人按下求助 | 待處理 | 出現 |
| 任何地方按「我接手」 | 已接手 | **藏起來**（第 2 種情形） |
| 任何地方結案或取消 | **找不到** | **又出現**（「找不到的一律留著」） |
| 按「稍後」或重新整理頁面 | — | 才消失 |

《迭代 14.4 修正紀錄》2.3 寫的是「直接結案而沒有經過接起來的那一則……仍然留著」，只說對一半：**接起來再結案的也一樣會冒回來**，而且結案之後才冒回來，正好是最不該出現的時候。

### 2.3 第一個問題怎麼對上

照程式，按「前往處理」那一則當下就從清單拿掉，不會再出現；同一則就算沒按「前往處理」，在緊急通報頁按「我接手」之後也會在下一次狀態推送時藏起來。

所以按「我接手」之後還留在上面的，最可能是**同一頁開著期間、更早幾次測試已經結案或取消的求助**——它們照第 2.2 節的表冒了回來，只是剛好在這個時候被看到。橫幅清單只存在這一頁的記憶體裡，不重新整理就一直累積。

另一個可能是導覽列「緊急通報」旁邊的數字：它算的是**還沒結案**的件數，接手之後、結案之前本來就還在，這是照設計。

> **待重現**：以上是讀程式碼查出來的，還沒有在測試機上重現。照第 2.5 節的步驟跑一次就能確認；改法（第 2.4 節）不論是哪一種情形都涵蓋得到。

### 2.4 改法

**橫幅只畫「還在等人接」的那幾則**，判斷「找不到」時加一個時間條件：

- 伺服器在這則求助**送到之後**才產生的狀態裡找不到它，就表示已經結案或取消，拿掉。「之後產生的狀態」指同一次療程的狀態推送，或之後才產生的整份快照
- 比這則求助**還舊**的快照找不到它，照舊留著——14.4「寧可多留一則，也不能漏掉一則」的安全方向不變
- 比較的兩個時間（求助的「伺服器收到時間」與狀態推送、快照的「伺服器時間」）都是伺服器的時鐘，不受護理站電腦時間不準影響。兩者現在都已經有，不必改後端

修剪放在 `realtime-context.tsx` 收到狀態推送、開場快照、輪詢補位快照的地方，整個護理端只有這一處；橫幅元件本身照舊。這是 FR-N14「專業版不動」的**第四個例外**（前三個是 14.3 斷線示警、14.4 橫幅上限、17.6 專業版的四件事），範圍同樣壓在最小。

### 2.5 驗收

1. 專業版開著，病人端按一次求助，橫幅出現
2. 簡易版點那一格確認，專業版橫幅消失
3. 簡易版點一個處理方式結案，**專業版橫幅不再出現**
4. 再按一次求助，在專業版緊急通報頁直接「取消」，橫幅不再出現
5. 拔掉網路線讓串流斷掉，期間病人按求助；接回來之後橫幅照樣出現（舊快照找不到不拿掉）
6. 迭代 14.4 的驗收腳本照樣全綠

## 3. 簡易版：去床邊之前先看到背景

### 3.1 現況

| | 簡易版 | 專業版緊急通報頁 |
|---|---|---|
| 這一次求助（類別、附註、時間、急迫度） | 只有類別文字 | 有 |
| 同一類別近期再發與前次處理（FR-N11） | 沒有 | 有 |
| 本次療程的透析前問卷 | 沒有 | 有（一行） |
| 近期症狀趨勢摘要 | 沒有 | 有（要展開） |
| 待追蹤事項（前次結案勾的） | 沒有 | 有 |
| **院方量測（血壓、脈搏、脫水量）** | 沒有 | **沒有** |
| **這幾次療程的求助紀錄（不分類別）** | 沒有 | **沒有** |

簡易版點紅框或床格上的求助，**點一下即確認通報**，格子接著展開處理方式的圖示列（SRS 5.2、FR-N16「一步完成」）。這一步把「接起來」和「結案」放在同一個位置，對手上有裝置、站在床邊的人是順的；對手上沒有裝置的護理師，展開的那一排處理方式要等回來才用得到，**真正在離開前需要的東西反而不在畫面上**。

### 3.2 新的流程

```
看到紅框 ─▶ 點一下：確認通報＋開啟「床邊前速覽」 ─▶ 看幾秒、關掉 ─▶ 走去床邊處理
                                                                    │
結案（照舊）◀─ 點一個處理方式 ◀─ 點那一格：展開處理方式（照舊） ◀─ 回到護理站
```

- **點一下仍然是確認通報**，確認時間照舊不能復原（基準 3.5）。不同的只是展開的東西：從處理方式換成速覽
- 已接手的格子，點下去展開處理方式，與現在相同；格子上多一個小圖示，點它重新開啟速覽（回來之後想再看一次，或者換人接手）
- 結案仍然是點一個處理方式，處理結果預設「已解決」、8 秒內可改，與現在相同
- 一次兩床以上緊急，各自的速覽各自開，紅框列照舊黏在最上面，速覽不得蓋住它

### 3.3 速覽的內容

由上而下，一個畫面放得下、**不捲動**（簡易版的硬規則）：

| 區塊 | 內容 | 沒有資料時 |
|---|---|---|
| 這一次 | 類別、病人的附註、按下時間與「幾分鐘前」、急迫度 | — |
| 院方量測 | **最近 3 筆**血壓與脈搏（每一筆附時間）；累積脫水量與設定脫水量；透析前體重 | 「院方資料沒有這位病人這次的量測」 |
| 透析前問卷 | 本次療程問卷裡**有症狀**的題目與答案 | 全答「沒有」寫一句；還沒填寫一句 |
| 近期求助 | 本次療程稍早的與**前 3 次療程**的每一則：時間、類別、處理方式、處理結果；同類別的標「同類別」 | 「前 3 次療程沒有求助」 |
| 待追蹤 | 前幾次結案時勾的追蹤事項（例如「下次透析前先量血壓」） | 不出現這一塊 |

**不放的東西與理由**：

- **不上色、不畫正常範圍、不加任何判讀**：數值照院方給的原樣列出，讀到 0 不顯示。理由與 SRS FR-P11 補充說明「1010：血壓不畫正常區間」相同，也守 FR-N03「分級依據不得摻入模型推論」
- **不放風險分層、療程中預警**：迭代 18 的規則輸出只在專業版，簡易版維持不出現
- **不放 AI 摘要**：速覽是事實的排列，AI 沒接、沒開時照樣完整
- **不把求助類別翻成病名**：「頭暈、冒冷汗、快昏倒」就寫這幾個字，不寫「透析中低血壓」（附錄 C.2 第 2 點）

### 3.4 專業版

緊急通報頁每一筆補上「院方量測」與「近期求助」兩塊，其餘照舊。兩邊吃同一支後端資料，內容一樣、排法各依各的版面。

### 3.5 後端

新增一支「求助的床邊前背景」讀取端點（或把 `HelpRequestDetail` 擴充），資料全部是現有的表：院方量測（`dialysis_vital_records`）、症狀問卷（`symptom_reports`）、求助（`help_requests`）、追蹤事項。**不新增資料表**。權限沿用「看病人」。

## 4. 護理紀錄跟處理當下同步

### 4.1 現況的問題

一則求助從發生到寫進護理紀錄，現在要填兩次：

| | 求助結案 | 護理紀錄（事件記錄） |
|---|---|---|
| 什麼時候填 | 回到護理站當下 | 不一定，通常是之後 |
| 在哪裡填 | 簡易版點處理方式，或專業版結案登記 | 護理紀錄頁：選日期、選療程、選範本、逐項勾選 |
| 時間 | 系統自己記（按下、接手、結案） | **「事件時間」欄預設是填寫的現在**，要護理師自己改成發生的時間 |
| 處置的詞彙 | 附錄 C.3 處理方式、C.4 處理結果 | 範本自己的「處置」「處置後情形」 |
| 院方量測 | — | 依「事件時間」往前找最近一筆；時間沒改對，帶進來的數值就跟著錯 |
| 兩者的連結 | **沒有** | **沒有** |

結果是：同一件事填兩次、用兩套詞彙；時間靠回想，預設值本身就是錯的；量測跟著錯的時間走；事後要查「這一筆護理紀錄是哪一次求助」對不起來。

### 4.2 原則

**結案那一下就是「處理當下的回報」。** 護理師剛從床邊回來，記憶最新；系統在這一刻把護理紀錄的草稿一起建好，時間與數值用求助本身記下的時間取，不靠回想。之後護理師只做審閱、補充、簽核、複製（FR-N05「審閱簽核取代重新輸入」原本就是這個意思）。

### 4.3 自動建立的規則

- **時機**：結案時（簡易版點處理方式、專業版結案登記），與結案寫在同一個交易裡，建立一筆**事件記錄草稿**，關聯到那一則求助。一則求助最多一筆
- **哪些會建**：臨床組類別的求助（附錄 C.2 臨床組十類）。非臨床組（上廁所、口渴、冷熱、機器一直叫、其他）與處理結果為「病人自行取消」的不建；取消的求助不建
- **事件時間**：病人按下求助的時間，不是結案時間，也不是填寫時間
- **補改結果**：簡易版 8 秒內補改處理結果、或事後在已結案標記上補改，草稿還沒簽核就跟著更新；已簽核的不動（規範第 14 條）
- **誰建立的**：結案的那位護理師；稽核照現有的「護理紀錄建立」記一筆

### 4.4 段落怎麼組

沿用 FR-N18 的兩種格式與既有的組段規則（時間 24 小時制、數值附單位與量測時間、讀到 0 不帶、不帶姓名與病歷號），內容改從求助取：

| 格式 | 段落 | 從求助取什麼 |
|---|---|---|
| **DART** | D 資料 | 病人自述：「14:05 病人以平板求助：頭暈、冒冷汗、快昏倒」加病人的附註；本次透析前問卷有症狀的題目（標明病人自述）；**按下求助前最近一筆院方量測** |
| | A 處置 | 時間線：按下求助、接手（有到達時間就加上）；處理方式**依點選順序**，照附錄 C.3 的文字，「依醫囑」照舊帶 |
| | R 反應 | 處理結果（附錄 C.4 的文字）；**按下求助之後**、到結案當下為止已經有的院方量測。之後才進來的，簽核前照舊按「帶入處置後數值」補上 |
| | T 衛教 | 追蹤事項勾了「需加強衛教」就帶一句；沒有就留空 |
| **SOAP** | S 主觀 | 病人自述（同 DART 的 D 前半） |
| | O 客觀 | 院方量測（每一筆附時間）、透析前問卷 |
| | A 評估 | **留空**。只放護理師自己選的事件類別，系統不從求助類別推出任何評估 |
| | P 計畫／措施 | 時間線、處理方式、處理結果、追蹤事項 |

**到達床邊時間關著時不寫、不補**：Q-30 的開關沒開，A 段的時間線只有「按下」與「接手」，不拿接手時間或結案時間頂替到達時間（與 FR-N10 的設計一致）。

### 4.5 範本怎麼接

兩條路：

| | 做法 | 好處 | 代價 |
|---|---|---|---|
| **甲（建議）** | 求助產生的記錄用一個新的記錄類型「求助處置」，處置與結果直接用附錄 C.3、C.4 的文字 | **一套詞彙、一次輸入**；處理方式的選項在系統管理改了，護理紀錄自動跟著 | 護理紀錄多一種類型 |
| 乙 | 用對照表把附錄 C.3 的處理方式對到既有範本的處置 | 記錄類型不變 | 多一張要維護的對照表；兩套分得粗細不同（「給藥（依醫囑）」對不到「口服 Midodrine（依醫囑）」），對不上的只能落成「其他」 |

選甲的話，草稿上可以讓護理師**改套「透析中低血壓處置」這類範本**再補勾，事件時間與帶進來的量測保留不動。這一步是護理師自己選的，系統不自動判斷該套哪一個（守附錄 C.2 第 2 點）。

### 4.6 護理紀錄頁

- 每一筆記錄卡片上標「來自 14:05 的求助」，點了到那一則求助
- 「依病人自報預填」旁邊多一塊「依求助建立」，列出這次療程**已結案但沒有記錄**的求助（這個機制上線之前結案的、或非臨床組但護理師想記的），一鍵建立，規則同第 4.4 節
- 手動的「新增事件記錄」保留給不是由求助引起的事件（例如巡床時發現的），事件時間欄的提示改成「請改成發生的時間」

### 4.7 邊界照舊

不寫入院方資料庫（Q-37）、AI 只是潤飾而且沒有照樣能用、簽核後不能改、複製貼上交給院內的正式紀錄——迭代 17.8 的規則一條都不動。

資料面：護理紀錄加一欄「來源求助」（可空、唯一），記錄類型多一個值；草稿組好的是文字，本來就是當下凍結的，之後院方量測再更新也不會改到已組好的段落。

## 7. 建議的實作順序

1. **橫幅修正**（第 2 節）：只動護理端一處，不動後端，可以先做成一個小迭代
2. **床邊前速覽**（第 3 節）：後端一支讀取端點，簡易版一個面板，專業版補兩塊
3. **護理紀錄連動**（第 4 節）：遷移加一欄，結案時建立草稿，護理紀錄頁的兩處調整

第 3 步組段落用得到第 2 步那一支背景端點的同一份資料，照順序做比較省。
