## 0. 本文件的定位

1015 使用者實際操作護理端之後，對緊急通報提出四件事：兩個頂端橫幅不消失的小問題，以及兩個設計上的問題——護理師去床邊之前看不到病人的背景、護理紀錄要事後回想才填得出來。這一份把四件事查清楚，寫下重新設計的規畫；同日使用者答覆了第 8 節的七題，規畫照答覆改定。

**這一份不是需求文件。** 需求寫在 SRS FR-N03、N04、N05、N10、N14、N16 的 1015 改寫與「FR-N03、N10、N16 補充說明（1015）」，實作寫在實作規格書 4.25（迭代 25）；與需求文件衝突時，以需求文件為準。

**1015 只改文件，程式沒有動**（使用者 1010 的規定：叫更新文件就只改文件）。**1018 迭代 25 照本文件做完**，實作結果、開發端判斷五條與驗收現況寫在實作規格書 4.25；與本文件不同的地方在各節以「1018」標出。

### 0.1 前提：護理師手上沒有平板或手機

這是整份規畫的出發點，見《尚待確認事項清冊》[Q-30](../requirements/open-questions.md#q-30-護理師的行動裝置)。護理端只開在護理站的一兩台電腦上，所以：

- 護理師**離開護理站之前**是唯一能看資料的時間，到了床邊什麼都看不到
- 護理師**回到護理站之後**才能登記，床邊發生的事一律是「回來才記」
- 「我到床邊了」這顆按鈕（FR-N10）跟著「需要特定裝置才用得到的功能」開關關著，到達時間是空的

使用者 1015 認為目前「看到警報 → 去處理 → 回來選處理方式結案」的操作本身沒有問題，要改的是**離開前多看一眼**與**回來那一下同時把護理紀錄寫好**。

## 2. 兩個小問題：頂端橫幅為什麼不消失

**結論：兩個都不正常，是同一個錯誤。**

### 2.1 現在的規則（迭代 14.4）

專業版每一頁上緣的求助橫幅（`App.tsx` 的 `HelpRequestAlerts`），清單是這一頁開著期間收到的每一則求助，只有兩種情形會拿掉：

1. 按了那一則的「前往處理」或「稍後」
2. 即時快照裡那一則的狀態**明確不是「待處理」**（迭代 14.4 加的：別處接起來的不佔位置）

而且 14.4 刻意定了一條安全規則：**快照裡找不到的一律留著**——輪詢補的快照可能比求助事件還舊，找不到不代表已經處理。

### 2.2 漏掉的地方：結案之後快照裡就找不到了

即時快照每一床的 `pendingHelpRequests` 只收**還沒結案**的求助（待處理、已接手）。一則求助走完一輪，橫幅的變化是這樣：

| 時點 | 快照裡那一則 | 橫幅 |
|---|---|---|
| 病人按下求助 | 待處理 | 出現 |
| 任何地方按「我接手」 | 已接手 | **藏起來**（第 2 種情形） |
| 任何地方結案或取消 | **找不到** | **又出現**（「找不到的一律留著」） |
| 按「稍後」或重新整理頁面 | — | 才消失 |

《迭代 14.4 修正紀錄》2.3 寫的是「直接結案而沒有經過接起來的那一則……仍然留著」，只說對一半：**接起來再結案的也一樣會冒回來**，而且結案之後才冒回來，正好是最不該出現的時候（1015 已在該節補註）。

### 2.3 第一個問題怎麼對上

照程式，按「前往處理」那一則當下就從清單拿掉，不會再出現；同一則就算沒按「前往處理」，在緊急通報頁按「我接手」之後也會在下一次狀態推送時藏起來。

所以按「我接手」之後還留在上面的，最可能是**同一頁開著期間、更早幾次測試已經結案或取消的求助**——它們照第 2.2 節的表冒了回來，只是剛好在這個時候被看到。橫幅清單只存在這一頁的記憶體裡，不重新整理就一直累積。

另一個可能是導覽列「緊急通報」旁邊的數字：它算的是**還沒結案**的件數，接手之後、結案之前本來就還在，這是照設計（第 8 節第 6 題：不改）。

> **1018 重現結果**：開發機上把護理端換回 25 以前的版本、開著專業版跑第 2.5 節第 1～4 步——**結案之後橫幅冒回來、取消之後也留著**，對上第 2.2 節；接手的當下橫幅照 14.4 藏起來，所以第一個現象就是第 2.3 節推論的「更早幾次已經結案、冒回來的那幾則」。換回新版四步都不再出現。

### 2.4 改法

**橫幅只畫「還在等人接」的那幾則**，判斷「找不到」時加一個時間條件：

- 伺服器在這則求助**送到之後**才產生的狀態裡找不到它，就表示已經結案或取消，拿掉。「之後產生的狀態」指同一次療程的狀態推送，或之後才產生的整份快照
- 比這則求助**還舊**的快照找不到它，照舊留著——14.4「寧可多留一則，也不能漏掉一則」的安全方向不變
- 比較的兩個時間（求助的「伺服器收到時間」與狀態推送、快照的「伺服器時間」）都是伺服器的時鐘，不受護理站電腦時間不準影響。兩者現在都已經有，不必改後端

修剪放在 `realtime-context.tsx` 收到狀態推送、開場快照、輪詢補位快照的地方，整個護理端只有這一處；橫幅元件本身照舊。**1018 實作補兩條**：只看這份狀態涵蓋的療程（跨過午夜換成隔天的快照不算找不到）；求助送到後 5 秒內的狀態不拿來修剪（後端寫進資料庫到快取更新之間有幾毫秒，那段時間發出的快照時間已晚於送到時間、裡面卻還沒有它）。這是 FR-N14「專業版不動」的**第四個例外**（前三個是 14.3 斷線示警、14.4 橫幅上限、17.6 專業版的四件事），範圍同樣壓在最小；使用者 1015 同意。

### 2.5 驗收

1. 專業版開著，病人端按一次求助，橫幅出現
2. 簡易版開速覽、按「我接手」，專業版橫幅消失
3. 簡易版點一個處理方式結案，**專業版橫幅不再出現**
4. 再按一次求助，在專業版緊急通報頁直接「取消」，橫幅不再出現
5. 拔掉網路線讓串流斷掉，期間病人按求助；接回來之後橫幅照樣出現（舊快照找不到不拿掉）
6. 迭代 14.4 的驗收腳本照樣全綠

## 3. 簡易版：去床邊之前先看到背景

### 3.1 現況

| | 簡易版 | 專業版緊急通報頁 |
|---|---|---|
| 這一次求助（類別、附註、時間、急迫度） | 只有類別文字 | 有 |
| 同一類別近期再發與前次處理（FR-N11） | 沒有 | 有 |
| 本次療程的透析前問卷 | 沒有 | 有（一行） |
| 近期症狀趨勢摘要 | 沒有 | 有（要展開） |
| 待追蹤事項（前次結案勾的） | 沒有 | 有 |
| **院方量測（血壓、脈搏、脫水量）** | 沒有 | **沒有** |
| **這幾次療程的求助紀錄（不分類別）** | 沒有 | **沒有** |

簡易版點紅框或床格上的求助，**點一下即確認通報**，格子接著展開處理方式的圖示列（SRS 5.2、FR-N16「一步完成」）。這一步把「接起來」和「結案」放在同一個位置，對手上有裝置、站在床邊的人是順的；對手上沒有裝置的護理師，展開的那一排處理方式要等回來才用得到，**真正在離開前需要的東西反而不在畫面上**。

### 3.2 新的流程：看是看、接是接

```
看到紅框 ─▶ 點一下：開啟「床邊前速覽」 ─▶ 看完按「我接手」 ─▶ 走去床邊處理
              （還沒接，紅框照舊）             （這一刻才是確認時間）     │
                                                                          ▼
結案（照舊）◀─ 點一個處理方式 ◀─ 點那一格：展開處理方式（照舊） ◀─ 回到護理站
```

**1015 使用者決定（第 8 節第 1 題）：開啟速覽不算確認通報。** 看不等於接——護理長巡一眼、另一位護理師順手點開看看，都不該把這一則變成「已接手」；確認時間要是**真的決定去處理的那一刻**，FR-N10 的時間紀錄才有意義。

- 點紅框、或床格上還沒人接的求助：**開啟速覽**，狀態不變，紅框照舊閃
- 速覽最上面一顆「**我接手**」：按下才確認通報，確認時間照舊不能復原（基準 3.5）。按完速覽自己關掉
- 沒按就關掉：仍是待處理，別人也看得到、接得起來
- 已接手的格子：點下去展開處理方式，與現在相同；格子上多一個 `id-card` 小圖示，點它重新開啟速覽（回來之後想再看一次、或交班）
- 結案仍然是點一個處理方式，處理結果預設「已解決」、8 秒內可改，與現在相同
- 一次兩床以上緊急：一次開一份速覽，紅框列照舊黏在最上面，速覽不得蓋住它

接緊急通報因此從「一次點選」變成「開速覽、按我接手」兩次點選，FR-N16 照這一條改寫（1015）。

### 3.3 速覽照參考系統的病人簡介排

**1015 使用者決定（第 8 節第 3 題）**：模仿同院 IDH 系統（`ref_project`，見《[同院 IDH 系統參考調查](idh-reference-survey.md)》）點床位跳出來的病人簡介；**資料能展現的就展現，不能的就拿掉；適合用折線圖觀察的就畫折線圖**。

參考畫面（成大版 `interface/templates/index.html` 的 `#modal`）是左右兩欄：左欄是床號姓名、「護理師處置」按鈕、下小時透析低血壓預測機率與人形圖、標準體重與輕重長條；右欄是最新一筆的血壓、體溫、脈搏、飲食與輸液量，透析液 Ca、傳導度、透析液溫度，血液流速、透析液流速、目標脫水量（配高中低圖示），一張收縮壓、脈搏、靜脈壓的折線圖（收縮壓 ≤ 90 的時段塗黃底），最下面 Heparin、透析器、血管通路、透析次數；另外一個隱藏的 50 欄完整表格。

逐項判斷：

| 參考畫面上的東西 | 速覽 | 理由 |
|---|---|---|
| 床號＋姓名 | **留** | 簡易版本來就顯示姓名 |
| 「護理師處置」按鈕 | **改成「我接手」** | 參考系統在這裡填處置；本系統處置在回來結案時登記（第 4 節），去之前要按的是接手 |
| 下小時透析低血壓預測機率、人形圖 | **拿掉** | 本系統沒有這個模型；預測屬高風險功能（FR-P03／P05、SRS 5.6），不得出現在簡易版。另外，參考程式在部分條件下顯示的是 40～60 之間的亂數，不是模型輸出，更不能照搬 |
| 標準體重（理想體重）與差距 | **留理想體重、透析前體重與兩者的差**（文字，例如「多 2.3 kg」） | 院方資料第 13、14 欄都有；差是兩個院方數值相減，不是判讀 |
| 輕重長條與紅綠色 | **拿掉** | 長條的刻度與顏色等於替數值分好壞，守「不上色、不判讀」 |
| 收縮壓／舒張壓、脈搏 | **留**（最新一筆，附量測時間） | 已在收（第 36～38 欄） |
| 體溫 | **留** | 第 11 欄，一次透析一個值；「發冷、發抖、覺得發燒」的求助特別需要。要新收 |
| 飲食／輸液量 | **留**，併進脫水那一列：「設定脫水量 2.8 L（目標 2.3＋輸液 0.3＋食物 0.2）」 | 第 15～17、19 欄；一列就看得出設定量怎麼來的。輸液、食物要新收 |
| 透析液 Ca、傳導度、透析液溫度 | **留** | 第 30、31、47 欄。參考程式的傳導度寫死成 13.9，本系統用院方資料的真值。要新收 |
| 血液流速、透析液流速 | **留數字** | 第 40、41 欄。要新收 |
| 流速的高中低圖示 | **拿掉** | 以 150、250 ml/min 分三級是門檻判讀 |
| 目標脫水量 | **留**（併在脫水那一列） | 已在收（`UF_TARGET`） |
| 收縮壓、脈搏、靜脈壓折線圖 | **留成折線圖，補舒張壓**；靜脈壓要新收（第 42 欄） | 透析中的變化要看走勢；病人端面板也畫收縮與舒張 |
| 收縮壓 ≤ 90 塗黃底 | **拿掉** | 門檻判讀；理由同 SRS FR-P11「1010：血壓不畫正常區間」 |
| Heparin、透析器、血管通路 | **留** | 第 27、32、33 欄；血管通路與 Heparin 對「打針的地方流血、腫、痛」「其他地方流血止不住」直接有關。要新收 |
| 透析次數（本院） | **拿掉** | 這一欄的意義還不確定（參考調查第 9.2 節） |
| 最後更新時間 | **留** | 院方資料最後一筆的時間；院方資料停更時照舊有「已 N 分鐘未更新」 |
| 50 欄完整表格 | **拿掉** | 簡易版不捲動；要看完整紀錄到院方系統 |

參考畫面沒有、使用者 1015 第一輪指定要的，**加上**：這一次求助（類別、附註、按下時間與幾分鐘前、急迫度）、透析前問卷、近期求助、待追蹤。參考畫面沒有的院方欄位（呼吸、ESA、凝血情況、膜上壓等）**不加**。

### 3.5 兩張折線圖

| 圖 | 畫什麼 | 不畫什麼 |
|---|---|---|
| 本次透析的血壓與脈搏 | 橫軸是這次透析開始到現在；收縮壓、舒張壓、靜脈壓共用 mmHg 軸，脈搏用右邊的次/分軸；**按下求助的時間畫一條直的虛線，標「求助」** | 正常範圍、警戒線、低於門檻塗色、預測延伸 |
| 本次透析的累積脫水量 | 累積脫水量一條線，設定脫水量一條橫的虛線（與病人端面板 FR-P11 同一種畫法）；同樣標求助時間 | 「進度落後」這類判斷 |

- 每一條線同時用線型與線尾的文字區分，**顏色不是唯一的線索**；讀到 0 的點不畫（與面板同一條規則）
- 自己畫的 SVG，沿用護理端 `trend-chart.tsx` 的做法，**不引入圖表套件**
- **跨療程的數值不畫成折線**：院方量測只收「這次療程有配平板」的病人（《資料庫使用規範》第 13 章最小蒐集），前幾次療程常常沒有，點數不齊的趨勢線會誤導。跨療程的只列近期求助

### 3.6 不放的東西

- **不上色、不畫正常範圍、不加任何判讀**：數值照院方給的原樣列出，讀到 0 不顯示。守 FR-N03「分級依據不得摻入模型推論」
- **不放風險分層、療程中預警**：迭代 18 的規則輸出只在專業版，簡易版維持不出現
- **不放 AI 摘要**：速覽是事實的排列，AI 沒接、沒開時照樣完整
- **不把求助類別翻成病名**：「頭暈、冒冷汗、快昏倒」就寫這幾個字，不寫「透析中低血壓」（附錄 C.2 第 2 點）

### 3.7 專業版

緊急通報頁每一筆多一顆「病人簡介」，開的是**同一份速覽**（同一個元件、同一支後端資料），其餘照舊；「我接手」那一顆照舊在卡片上，速覽裡的「我接手」也能用。

### 3.8 後端與資料

- 新增一支「求助的床邊前背景」讀取端點，一次帶齊第 3.3 節要的東西；權限沿用「看病人」
- **院方 API 多收幾欄**：每一筆紀錄多收血流速（第 40 欄）、透析液流速（41）、靜脈壓（42）、透析液溫度（47）；每次透析一個值的多收體溫（11）、輸液量與食物重量（16、17）、透析器（27）、透析液 Ca（30）、傳導度（31）、血管通路（32）、Heparin（33）
- 收的範圍照舊：**只收這次療程有配平板的病人**（最小蒐集），會發出求助的本來就只有他們
- 帶小數的數值照《資料庫使用規範》6.2 換成整數最小單位，不用浮點數；透析器、血管通路、Heparin 是院方的文字，照原樣存

## 4. 護理紀錄跟處理當下同步

### 4.1 現況的問題

一則求助從發生到寫進護理紀錄，現在要填兩次：

| | 求助結案 | 護理紀錄（事件記錄） |
|---|---|---|
| 什麼時候填 | 回到護理站當下 | 不一定，通常是之後 |
| 在哪裡填 | 簡易版點處理方式，或專業版結案登記 | 護理紀錄頁：選日期、選療程、選範本、逐項勾選 |
| 時間 | 系統自己記（按下、接手、結案） | **「事件時間」欄預設是填寫的現在**，要護理師自己改成發生的時間 |
| 處置的詞彙 | 附錄 C.3 處理方式、C.4 處理結果 | 範本自己的「處置」「處置後情形」 |
| 院方量測 | — | 依「事件時間」往前找最近一筆；時間沒改對，帶進來的數值就跟著錯 |
| 兩者的連結 | **沒有** | **沒有** |

結果是：同一件事填兩次、用兩套詞彙；時間靠回想，預設值本身就是錯的；量測跟著錯的時間走；事後要查「這一筆護理紀錄是哪一次求助」對不起來。

### 4.2 原則

**結案那一下就是「處理當下的回報」。** 護理師剛從床邊回來，記憶最新；系統在這一刻把護理紀錄的草稿一起建好，時間與數值用求助本身記下的時間取，不靠回想。之後護理師只做審閱、補充、簽核、複製（FR-N05「審閱簽核取代重新輸入」原本就是這個意思）。

### 4.3 自動建立的規則

- **時機**：結案時（簡易版點處理方式、專業版結案登記），與結案寫在同一個交易裡，建立一筆**事件記錄草稿**，關聯到那一則求助。一則求助最多一筆
- **哪些會建**（第 8 節第 4 題）：臨床組類別的求助（附錄 C.2 臨床組十類）。非臨床組（機器一直叫、上廁所、冷熱、口渴、其他）與處理結果為「病人自行取消」的不建；取消的求助不建
- **事件時間**：病人按下求助的時間，不是結案時間，也不是填寫時間
- **補改結果**：簡易版 8 秒內補改處理結果、或事後在已結案標記上補改，草稿還沒簽核就跟著更新；已簽核的不動（規範第 14 條）
- **誰建立的**：結案的那位護理師；稽核照現有的「護理紀錄建立」記一筆

### 4.4 段落怎麼組

沿用 FR-N18 的兩種格式與既有的組段規則（時間 24 小時制、數值附單位與量測時間、讀到 0 不帶、不帶姓名與病歷號），內容改從求助取：

| 格式 | 段落 | 從求助取什麼 |
|---|---|---|
| **DART** | D 資料 | 病人自述：「14:05 病人以平板求助：頭暈、冒冷汗、快昏倒」加病人的附註；本次透析前問卷有症狀的題目（標明病人自述）；**按下求助前最近一筆院方量測** |
| | A 處置 | 時間線：按下求助、接手（有到達時間就加上）；處理方式**依點選順序**，照附錄 C.3 的文字，「依醫囑」照舊帶 |
| | R 反應 | 處理結果（附錄 C.4 的文字）；**按下求助之後**、到結案當下為止已經有的院方量測。之後才進來的，簽核前照舊按「帶入處置後數值」補上 |
| | T 衛教 | 追蹤事項勾了「需加強衛教」就帶一句；沒有就留空 |
| **SOAP** | S 主觀 | 病人自述（同 DART 的 D 前半） |
| | O 客觀 | 院方量測（每一筆附時間）、透析前問卷 |
| | A 評估 | **留空**。只放護理師自己選的事件類別，系統不從求助類別推出任何評估 |
| | P 計畫／措施 | 時間線、處理方式、處理結果、追蹤事項 |

**到達床邊時間關著時不寫、不補**：Q-30 的開關沒開，A 段的時間線只有「按下」與「接手」，不拿接手時間或結案時間頂替到達時間（與 FR-N10 的設計一致）。第 3.2 節把接手改成「看完才按」之後，「接手」更接近護理師真的動身的時間，但它仍然不是到達時間，不得寫成到達。

### 4.5 範本怎麼接：新的記錄類型「求助處置」

**1015 使用者決定（第 8 節第 5 題）：用新的記錄類型（甲）。**

| | 做法 | 好處 | 代價 |
|---|---|---|---|
| **甲（採用）** | 求助產生的記錄用一個新的記錄類型「求助處置」，處置與結果直接用附錄 C.3、C.4 的文字 | **一套詞彙、一次輸入**；處理方式的選項在系統管理改了，護理紀錄自動跟著 | 護理紀錄多一種類型 |
| 乙（不採用） | 用對照表把附錄 C.3 的處理方式對到既有範本的處置 | 記錄類型不變 | 多一張要維護的對照表；兩套分得粗細不同（「給藥（依醫囑）」對不到「口服 Midodrine（依醫囑）」），對不上的只能落成「其他」 |

草稿上可以讓護理師**改套「透析中低血壓處置」這類範本**再補勾，事件時間與帶進來的量測保留不動。這一步是護理師自己選的，系統不自動判斷該套哪一個（守附錄 C.2 第 2 點）。

### 4.6 護理紀錄頁

- 每一筆記錄卡片上標「來自 14:05 的求助」，點了到那一則求助
- 「依病人自報預填」旁邊多一塊「依求助建立」，列出這次療程**已結案但沒有記錄**的求助（這個機制上線之前結案的、或非臨床組但護理師想記的），一鍵建立，規則同第 4.4 節
- 手動的「新增事件記錄」保留給不是由求助引起的事件（例如巡床時發現的），事件時間欄的提示改成「請改成發生的時間」

### 4.7 邊界照舊

不寫入院方資料庫（Q-37）、AI 只是潤飾而且沒有照樣能用、簽核後不能改、複製貼上交給院內的正式紀錄——迭代 17.8 的規則一條都不動。

資料面：護理紀錄加一欄「來源求助」（可空、唯一），記錄類型多一個值；草稿組好的是文字，本來就是當下凍結的，之後院方量測再更新也不會改到已組好的段落。
