# 迭代 17.2：簡易版中間改成平板、病人框重新整理與排序

版本：v0.1　文件狀態：已完成（2026-10-07 開立）　適用讀者：FDE 工程團隊

---

## 0. 本文件的定位

本文件不是需求文件，是一份**修正紀錄**：2026-10-07 使用者看了 1006 的簡易版截圖，指示歸在迭代 17.2 處理兩件事——

1. **簡易版中間改成平板**。護理師要做的是把病人拖到平板，平板右上角自動出現床號；右邊只留「病人」與「公告與院內衛教」兩區
2. **病人框加一顆重新整理按鈕**：病人多，護理師找人找很久。按下去立即抓一次院方資料，把剛上機的病人推到最上面——
   **正在透析的病人在最上面，越晚開始的越上面；沒有在透析的在下面，依姓名第一個字的筆畫排**

本文件記錄每一件改了什麼、開發端做的判斷，以及影響到哪些既有規則。

- 功能需求來源仍是《[軟體需求規格書](../requirements/srs.md)》；本次改寫 FR-N15 的「以床位為中心」與 5.2 補充說明的表（SRS 自己的版本歷程定版日補）
- 範圍與技術選型仍以《[實作規格書](../requirements/implementation-spec.md)》為準（4.15.2 節是本文件的摘要；1.1 記下**第五次**刻意改動既有驗收腳本）
- 介面規則仍以《[介面設計基準](uiux-design-baseline.md)》為準；本次改 3.5（新增 3.5.3）、4.6、4.7、4.8、4.10、6.2、6.4
- 與需求文件衝突時，以需求文件為準

**為什麼叫 17.2 而不是迭代 18。** 兩件事都是改既有畫面的版面與順序，沒有新增需求；迭代 18（規則引擎）的內容一項都沒動。

## 1. 使用者的問題與答覆

1007 使用者看了截圖問：為什麼畫面中間還是床？畫面中心應該是平板，護理師只要把病人與平板配起來就好。

答覆：迭代 17.1 只把放置的目標從床位換成平板，版面沒動——SRS FR-N15 寫的是「以床位為中心」，那一條沒改。
結果是每次透析都要做的配對，擠在右邊兩個小框之間；中間最大的一塊反而不能拿來配。使用者因此指示本次的第 1 件。

拖的方向照使用者 1007 的指示：**把病人拖到平板**（與 1006 的決定相同）。

## 3. 逐項說明

### 3.1 中間改成平板（第 1 件）

**畫面**：

```
┌──────────────────────────────────────────────────┬──────────────┐
│ ⛔ B1 胸悶胸痛（紅框，緊急時才出現）        ⇄ 專業版 │ 👤 病人        │
├──────────────────────────────────────────────────┤ ⟳ 模擬戊 ◆    │
│ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐ │   模擬丁 ◆    │
│ │◆DEMO-01 🛏B1│ │▭DEMO-02 🛏A2│ │▭DEMO-03     │ │▭DEMO-04     │ │   模擬子 模擬己│
│ │模擬戊 ▓▓░  │ │模擬乙 ▓░░  │ │（空著，虛線）│ │（空著，虛線）│ │ ⌛ 候床 ⇥ 下機│
│ └──────────┘ └──────────┘ └──────────┘ └──────────┘ ├──────────────┤
│   …（平板依序號排，位置不跳）                        │ 📣 公告與院內衛教│
└──────────────────────────────────────────────────┴──────────────┘
```

- **一格一台平板**：沒停用的全部（停用的就是不能用，17.1 起不出現），依序號排（序號裡的數字照大小排）。
  平板的位置不會因為配了誰、空了而跳——護理師記得住「DEMO-03 在第三格」
- **整格是放置區**：拿著病人時，能配的平板（有佈建、沒停用、沒在服務別人）整格亮起來，拖上去或點一下即配好。動作與 17.1 相同（`pairPatient` → `createBinding`），復原也相同
- **右上角是床號**（使用者 1007 指示），字級與原本床位格的床號相同（`--t-bed-no`）：
  - 接了院方資料：**正在服務病人的平板標院方資料的那一床**。配好的當下後端就把平板放到療程的床（17.1 的 `followSessionBed`），床號跟著出現；
    院方資料說病人換床，平板照樣跟著走。沒在用的平板不標床號（它的床號是上一位病人的，17.1 的判斷沿用）
  - 沒接院方資料：平板設在哪一床就標哪一床。床號是一顆按鈕，點了在格子上長出床號列，再點一床就換（那一床原本有平板就對調）；
    還沒設床的平板只畫床的圖示。要有裝置管理權限才點得動，沒有就只顯示
- **左上角是狀態圖示與平板序號**，後面接平板本身的警示（離線、尚未佈建、跳出固定畫面、版本）。沒在用的平板叫「**空著**」、畫平板、虛線框
  （原本的「空床」畫床——格子代表的東西換了）
- 格子裡其餘的東西與床位格一樣：病人（拖到候床或下機）與進度條、待確認下機、求助（點一下確認、展開處理方式、結案、補改結果）、
  院方床位有問題的圖示、只在這一床播的內容數
- 公告與院內衛教：草稿卡或已核准的內容卡拖到一台**有床號的平板**＝只在它那一床播；拖到「全部」照舊
- 緊急紅框裡寫床號；沒有床號（沒接院方資料、平板還沒設床）就寫平板序號。結案的復原列同樣是「B1 床結案」或「平板 DEMO-01 結案」
- 一台平板都沒有時，中間寫「還沒有平板，請到專業版『裝置管理』註冊」

**拿掉的東西**：

| 拿掉 | 原本做什麼 | 之後在哪做 |
|---|---|---|
| 床位圖（床位格） | 一格一床，畫病人、平板、護理師、求助 | 平板格（病人、求助、內容）。空床看不到了——接了院方資料時病人在哪一床由院方決定，護理師不必看空床 |
| 平板框 | 不在床上的平板；17.1 起是放病人的地方 | 平板全部在中間 |
| 當班護理師框 | 把護理師拖到床位＝床位分配 | **專業版「排班與指派」**。導覽版位裡「班表」首波預設關閉，簡易版原本就看不到這一框 |
| 把平板拖到另一床（換床） | 裝置管理 | 接了院方資料用不到（平板跟著院方的床）；沒接時點床號換床 |
| 沒有平板、正在透析的病人畫在床上 | 迭代 15：院方資料說正在透析的病人，沒有平板也畫在他那一床 | **病人框的最上面**，角落標「治療中」（`activity`）；拖得到「下機」。過了預計結束很久的改標「待確認下機」（`clock-alert`），拖到下機就是確認 |

### 3.2 病人框重新整理與排序（第 2 件）

**順序**（`model.ts` 的 `trayOrder`，兩種環境都是）：

1. **正在透析的在上面，越晚開始的越上面**。「正在透析」看療程的狀態是進行中；開始時間是院方資料的透析開始時間（沒接院方資料時是配平板的時間）。
   剛上機、還沒配平板的病人因此就在第一個——護理師要找的通常就是他
2. **沒有在透析的在下面，依姓名筆畫**：第一個字筆畫少的在前，同筆畫再比下一個字。用瀏覽器內建的台灣中文筆畫排序（`Intl.Collator('zh-TW-u-co-stroke')`），不自帶筆畫表

病人框放哪些人沒有變：接了院方資料是「今天要透析、還沒配平板」的病人，沒接是還沒配平板的病人。配好平板就從框裡消失。

**附帶一提**：使用者以為原本是依病歷號排，其實 17.1 的病人框已經是依姓名排（`localeCompare(…, 'zh-Hant')`，瀏覽器的預設就是筆畫）。
1006 截圖裡的「模擬丁、模擬子、模擬己、模擬丑、模擬壬、模擬丙、模擬甲、模擬庚、模擬癸」就是第二個字的筆畫順序（2、3、3、4、4、5、5、8、9 畫）。
這次改的是讓正在透析的排到最上面，並明確指定筆畫規則。

**重新整理**：

- 病人框左邊、框的圖示底下一顆 `refresh-cw`。按下去立即抓一次院方資料、接著重取畫面；抓的時候按鈕先停用。
  院方資料這次沒抓到，上面那一條錯誤訊息寫「院方資料這次沒有抓到（原因），畫面是上一次的資料」
- 它只是**把排程提早跑一次**：抓的資料、寫的東西、稽核與排程（預設 3 分鐘一次）完全相同。不按也會照排程更新，按了只是不必等
- 沒接院方資料時**沒有這顆按鈕**：沒有東西可抓，畫面本來就每 15 秒重取一次（N-6：關掉的功能就是不存在）
- 端點與專業版系統管理「院方資料同步」卡的「立即同步」是同一支。**權限放寬**：原本要「營運參數調整」（護理長以上），
  改成「看即時總覽」（一般護理師就有）——見第 4 節
- 同時按的人再多，後端也只抓一次：`HospitalSyncService.run` 在抓的時候，後來的請求共用進行中的那一次（迭代 15 就有，不是這次加的）

**順序的實際例子**（`verify:iteration17-2` 步驟 3 用的假資料）：7:30、7:40、7:50 開始透析的林志強、李阿土、黃美玲，
加上還沒開始的陳大明、王小美、丁一——病人框依序是黃美玲、李阿土、林志強、丁一、王小美、陳大明。

## 4. 開發端在實作時做的判斷

使用者要推翻時改右欄那一處即可。

| 判斷 | 理由 | 寫在哪 |
|---|---|---|
| 平板依序號排，不依「有沒有在用」或床號排 | 位置不跳，護理師記得住哪一台在哪一格；依床號排的話，配好一台它就跳到別的位置 | `model.ts` 的 `shownTablets` |
| 接了院方資料時，沒在用的平板不標床號 | 17.1 的判斷沿用：床號是上一位病人的，標出來反而讓人以為它還在那一床 | `model.ts` 的 `tabletBed` |
| 病人框的順序**隨時**套用，不是按了重新整理才排 | 使用者說的是「目前在透析的病人名字會在最上面」——那是一條常態的規則；按鈕是讓剛上機的人立刻出現，不必等排程 | `Workbench.tsx` 的 `trayPatients` |
| 「今天有排班的排前面」（沒接院方資料）、「院方床位有問題的排前面」（接了）**不再影響順序** | 使用者把順序講完整了，只有兩條；兩者的框線與圖示留著，看得出來 | `Workbench.tsx` |
| 重新整理一般護理師也能按（`POST /hospital-sync/run` 權限從「營運參數調整」改成「看即時總覽」） | 按鈕是給每天配平板的護理師用的；它不改任何設定，只是把排程提早跑一次，後端也不會因為多人同時按而多抓 | `hospital-sync.controller.ts` |
| 沒接院方資料時，點床號、再點一床設定平板的床 | 中間沒有床位圖可以拖了；專業版也沒有設定平板床位的畫面，不給一個地方設，沒接院方資料的環境（開發機、進院前）就配不出病人在哪一床。用的是原本的加法端點 `setDeviceBed`，能一步復原 | `TabletCell.tsx`、`actions.tsx` 的 `setTabletBed` |
| 一般護理師也看得到中間的平板（原本平板框要有裝置管理權限才出現） | **17.1 的缺陷**：配平板只要「指派平板」權限，平板框卻要「裝置管理」權限，一般護理師在接了院方資料時找不到平板可以配。平板移到中間，人人看得到；能不能配仍由後端權限決定 | `Workbench.tsx` |
| 公告與院內衛教拖到沒有床號的平板不亮 | 播放範圍是床，沒有床號就沒有「那一床」 | `model.ts` 的 `accepts` |
| 「空床」改叫「空著」、圖示改畫平板 | 格子是平板不是床；「空床」放在平板格上意思不對 | `status-visuals.ts` 的 `BED_STATE_VISUALS` |
| 平板格沿用床位格的樣式類別（`.bed`、`.bed-head`、`.bed-panel`…） | 長相、狀態的畫法、面板翻轉的規則都一樣；改名要動到四支驗收腳本的選擇器，沒有好處 | `workbench.css` |
| `PATIENT` 拖曳的 `fromBed` 改名 `fromTablet` | 中間不是床了；它記的是病人從哪一台平板格拿起來 | `model.ts` |
| 平板框與護理師框的底色（`--c-zone-tablet`、`--c-zone-nurse`）一起拿掉 | 沒有人用了；對比度搭配清單同步拿掉那四列 | `design-tokens.css`、`check-ui-design.mjs` |
