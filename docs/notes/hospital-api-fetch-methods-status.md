## 摘要

- 1106～1107 使用者與負責 IDH 系統的學長在 LINE 上談院方 API；這一份整理學長說了什麼、還缺什麼、接下來怎麼做
- **介接方式要改**：學長要求本系統**不要自己打院方 API**，改成讀主機上腳本抓下來的檔；腳本照原本的 `.py` 存檔、存在 Drive 文件寫的位置，另一組（APP 組）也讀同一份
- 學長要的兩件事：①本系統改成直接讀資料的形式；②改寫 IDH 的 `fetch_API`，不靠 Django、固定時間抓、頻率可調；使用者先用每 3 分鐘
- 主機上有一套 IDH 系統＋抓取腳本，**IDH 系統沒在用**，腳本是舊版；歷史 txt 學長已搬到指定位置，「再來只需要處理腳本」
- 下次進院：**1109（一）15:30 左右**部署；使用者預估分兩次進院完成
- 沒答案的：醫師授權（A-02／Q-35）、IRB 影片、`hb` 那支 API 的範例、腳本由誰維護、留底的格式與編碼、資料夾會不會被 OneDrive 同步（第 3 節）
- 「先做第一種」與「只需要處理腳本」兩句可能指不同做法，要再對一次（第 4.3 節）
- 建議：**週一只讓獨立腳本跑起來，本系統先不碰**（改本系統要換版、整輪重做第十七冊）；讀檔模式排到第二次進院（第 4、8 節）

## 4. 介接方式要怎麼改

### 4.1 改之前與改之後

```
現在（迭代 15，院內位址還沒填）
   院方 dialysislist.php ←─ 本系統 api 容器（每 3 分鐘）→ 本系統資料庫

學長要的
   院方 dialysislist.php ←─ 主機上的獨立腳本（固定頻率，可調）
                               └─ 附加到 API_Fetch\IDH_interface\YYYY-MM.txt
                                     ├─ 本系統讀檔 → 本系統資料庫
                                     └─ APP 組讀檔
```

### 4.2 三種做法比較

使用者 1107 晚上提的兩種，加上現況：

| 比較 | 現況：本系統直接打 | 第一種：本系統打、順便寫檔 | 第二種：獨立腳本寫檔、本系統讀檔 |
|---|---|---|---|
| 誰呼叫院方 API | 本系統 | 本系統 | 腳本 |
| 合不合學長的要求 | 不合 | 部分合：APP 組有檔可讀，但「本系統改成讀資料」沒做到 | **合** |
| APP 組的資料靠什麼 | 沒有 | 靠本系統的容器活著；本系統停機、退版、撤除（第八冊）就斷 | 靠腳本，與本系統無關 |
| 本系統要改的程式 | 不用 | 加寫檔功能 | 加讀檔模式（第 7 節） |
| 本系統要多掛的資料夾 | 不用 | 掛一個**可寫**的院內資料夾 | 掛一個**唯讀**的院內資料夾 |
| 部署規範 | 合 | 牴觸 DEP-37 第 3 條（只准掛備份與設定兩個目錄，而且要在本系統自己的路徑底下）；還要寫明文個資到本系統以外 | 同樣牴觸 DEP-37 第 3 條，要改規範；但只讀、不寫 |
| 週一前做不做得完 | — | 改程式就要出新版，**新 tag 要整輪重做第十七冊**（《第十八冊之二》摘要、O-02） | 腳本週一前做得完；本系統的讀檔模式不必週一做 |
| 寫壞了的影響 | — | 本系統的寫檔一出錯，可能拖到同步 | 腳本出錯只影響檔；本系統看得到「資料過期」 |

### 4.3 「第一種」與「只需要處理腳本」要再對一次

- 使用者 22:19 說「先照學長說的做第一種」，第一種照 22:05 的定義是「本系統加功能、把資料存到學長說的資料夾」
- 但學長 15:08 說的是第二種（改寫 `fetch_API` 成獨立腳本＋本系統讀檔），22:23 又說「你再來就只需要處理腳本」
- 兩邊可能指不同做法；**下次跟學長對話時先確認**，再決定週一做哪一種

### 4.4 建議

| 時程 | 做什麼 | 理由 |
|---|---|---|
| 1109 第一次進院 | **只讓獨立腳本跑起來**，寫進指定位置；本系統維持位址空白、不碰 | 學長與 APP 組要的是檔，腳本就夠；本系統還被《第十八冊之二》的 A-01～A-03 擋著，本來就不能接真實資料；不必換版 |

## 5. 資料夾與個資

- 指定位置是某台電腦 `OneDrive\Old data\桌面\API_Fetch\` 底下（完整路徑不寫進公開文件）
- 留底 txt 是**院方回應的原文**：全中心當天所有病人的姓名、病歷號、生日、生命徵象，明文
- 若那台電腦的 OneDrive 有登入且在同步，這個資料夾的內容就會**離開醫院**；週一要先看同步狀態，有在同步就請學長改位置，或確認那個帳號是院方核可的
- 誰讀得到這個資料夾（Windows 權限）、留多久、誰刪，都沒有規定；本系統的《資料庫使用規範》管不到本系統以外的檔
- 本系統讀檔時只讀、不搬、不刪；讀完的內容照舊只進本系統資料庫

## 6. 新腳本的建議規格

以成大版為底（上層第 5 節），寫成一支不依賴 Django 的 Python：

| 事 | 建議 | 為什麼 |
|---|---|---|
| 執行方式 | `--once` 跑一輪就結束，交給 Windows 工作排程器每 N 分鐘叫一次；或程式裡自己迴圈 | 學長要頻率可調；工作排程器改頻率不用改程式，主機重開後也會自己回來 |
| 設定 | 一個設定檔：端點、輸出資料夾、頻率；**端點不寫死在程式** | 斗六搬過來只改設定 |
| 逾時與重試 | 30 秒、3 次（斗六版） | 成大版沒有，院方一慢就卡住 |
| 留底格式 | `YYYY-MM.txt`，一次抓取寫兩行：`Date: YYYY-MM-DD HH:MM:SS`、原始回應（去掉 `<meta>` 後的 JSON） | 與成大版、歷史 txt 相同，`refetch_from_txt.py` 讀得回來 |
| 編碼 | **明確指定**，與已搬過去的歷史 txt 相同（先量；若歷史是 cp950，要跟學長決定要不要從新的月份起改 UTF-8） | 上層第 4 節 |
| 寫檔 | 一次抓取組成一整段字串、一次寫入並 `flush`；路徑用設定檔的輸出資料夾，不用目前目錄 | 讀的人才不會讀到寫一半的行 |
| 去 `<meta>` | 從第一個 `{` 開始 | 上層第 4 節 |
| 失敗時 | 不寫任何東西、不蓋掉舊檔；結束碼非零，排程器看得到 | `API_script` 版會把 `temp.csv` 蓋成空的 |
| 主控台 | 只印成功、筆數、失敗原因；不印網址、不印回應 | 成大版會把整包個資印到主控台 |
| 檢查 | 回應解析得出 `data_list` 才寫；不丟任何列（床位數字開頭的也留） | 丟列是 IDH 系統自己的處理，讀檔的人各自決定 |
| `temp.csv` | 不寫，除非學長或 APP 組要 | 那是 Django 匯入用的中間檔（U-5） |
| 測試 | 先 `--once` 一次，對照檔尾兩行；再開排程 | — |

**檔案會越長越大**：每次都附加當天全部列，3 分鐘一次、24 小時不停的話，一天要附加 480 次。週一先量歷史 txt 的大小，再決定是否只在透析時段抓、或內容沒變就不附加（這兩件都會改到「跟原本一樣」，要學長同意）。

## 7. 本系統之後要改的（第二次進院前）

### 7.1 讀檔模式

| 事 | 做法 |
|---|---|
| 設定 | 新增一個「院方資料檔資料夾」的設定，與 `HOSPITAL_API_BASE_URL` 二選一；兩個都填就拒絕啟動 |
| 掛載 | 指定位置以**唯讀**繫結掛載進 `api` 容器；路徑有空白與中文，compose 要測 |
| 讀什麼 | 當月 `YYYY-MM.txt` 的最後一段完整的 `Date:`＋JSON；檔尾沒換行就當寫到一半，讀前一段 |
| 讀大檔 | 從檔尾往回找，不整個讀進記憶體 |
| 去重 | 與上一次讀到的內容雜湊相同就跳過；抓取紀錄照寫 |
| 過期 | 以 `Date:` 的時間判斷資料多舊；沿用「院方資料多久沒更新就示警」的營運參數 |
| 解析與同步 | `parseHospitalApiBody()` 之後全部照用（它本來就從第一個 `{` 開始） |
| 頻率參數 | 「抓取頻率」改成「讀檔頻率」；真正打院方的頻率在腳本 |
| 檔案變更通知 | WSL2 的 Windows 掛載收不到檔案變更事件，用定時讀 |

### 7.2 要跟著改的文件（決定做第二種之後才改）

### 7.3 Q-35 的問法要改

- 原本問「本系統每 3 分鐘呼叫一次院方 API，要不要報備」
- 改成問「主機上的腳本每 N 分鐘呼叫一次、存成檔，本系統與 APP 組讀這些檔；這樣的使用要不要報備、存檔的位置與留存期限要不要院方核可」

## 8. 1109 進院的順序

1. 看主機：學長說的「那台」是哪一台（U-3）、Python 版本、現有腳本是哪一版、指定資料夾在不在、歷史 txt 的檔名、大小、最後一筆時間、編碼（U-6）
2. 看 OneDrive 有沒有在同步那個資料夾（U-7）；有在同步就停在這一步，先問學長
3. 放新腳本、填設定、`--once` 跑一次，看檔尾兩行對不對、編碼對不對
4. 開工作排程器，3 分鐘一次；看兩三輪都有附加
5. 本系統**維持位址空白**；《第十八冊之二》的 A-01～A-03 沒有答案前不接真實資料
6. 把問題清單（第 9 節）交給學長

## 9. 給學長的問題清單（草稿）

1. 週一接資料，醫師那邊算授權了嗎？要不要書面？（U-1）
2. IRB 影片的平台、時數、承認課程（U-2）
3. 「那台主機」是本系統所在的那一台嗎？（U-3）
4. 新腳本之後由誰維護？放在主機哪裡？（U-4）
5. 「跟原本一樣存」是指成大版的 `YYYY-MM.txt` 嗎？`temp.csv` 要不要？（U-5）
6. 已搬過去的歷史 txt 是哪一版寫的？（U-6）
7. 指定資料夾在 OneDrive 底下，有在同步嗎？可以換到不同步的位置嗎？（U-7）
8. 每天整天每 3 分鐘附加一次，檔案會很大；可以只在透析時段抓、或內容沒變就不附加嗎？（第 6 節）
9. `hb` 那支 API 的 `.json` 範例；是不是另一支端點、要不要一起排程？（U-9）
10. 我們 22:05 說的「第一種」「第二種」，學長的意思是哪一種？（第 4.3 節）
