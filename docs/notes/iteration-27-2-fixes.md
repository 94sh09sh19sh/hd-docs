## 摘要

- 進度條補三樣：**剩餘時間**（「剩 2 小時 19 分」）、**結束時間**（「13:25 結束」）、**每小時一條刻度**。兩句字放在進度條底下一行，左邊剩餘、右邊結束（對齊進度條右端）；列高不變（第 1 節）。
- 不補的：開始時間、已經過幾分鐘、百分比、刻度上的時間字（第 1.2 節）。
- 寬度：在 27.1 的最壞組合下，剩餘時間一定留，結束時間放不下就先不畫；進度條前的時鐘圖示拿掉，把位置讓給字。
- **順帶查出 27.1 的寬度算錯**：27.1 第 1.4 節寫最壞組合「餘約 10px」，照同樣的組合重量是**差 40px**（床號 A12）。27.2 一併修：基本資訊區的欄距 32px → 24px（第 1.4 節）。~~27.1 還沒實作，兩個一起做。~~ 1027 欄距隨 27.1 先做，進度條的字同日隨 27.2 做完。
- 剩餘時間改成「結束時刻的分 − 現在時刻的分」，畫面上的 13:25 − 11:06 與「剩 2 小時 19 分」永遠對得上；現行共用函式無條件進位，開始時間帶秒時會差 1 分（第 1.5 節）。
- 血壓圖標題旁補單位**毫米汞柱**，與脫水量的「公斤」、脈搏的「次／分」同一種寫法（第 2 節）。
- **1027 實作完成**：第 3 節的檔案都改了；照實作的元件在無頭 Chrome 量，最壞組合（A12）進度條區塊 159px、剩餘那一句 131px，列高 95px 不變。實作時定的判斷與驗收現況在實作規格書 4.27.2。

## 1. 進度條

### 1.1 現況

- 基本資訊區：時鐘圖示加一條進度條，沒有任何字（`HomeScreen.tsx`）。進度＝（現在 − 開始）÷ 四小時，終點是 `@hd/shared` 的 `plannedDialysisEndMs`（迭代 17.5）。
- 1007 以前刻意不放字：2.4 把「時段」「開始時間」列為刪掉的字（M-3），SRS FR-P14 補充說明寫「療程進度（圖形，不是文字時間表）」。
- 結果：病人看得出「過了一半多」，答不出 SRS 寫的那一句「幾點可以下機」，也答不出「還要多久」——病人只能拿面板橫軸右端的 13:25 自己減現在時間，而那個 13:25 沒寫是什麼。

### 1.2 要補什麼

| 放什麼 | 補不補 | 理由 |
|---|---|---|
| 剩餘時間 | **補** | 病人最常問的就是「還要多久」；不必自己減 |
| 結束時間 | **補** | 「幾點可以下機」，家屬幾點來接、幾點吃飯都看它 |
| 每小時一條刻度（三條） | **補** | 透析一律四小時，四格就是四個小時，一眼數得出「還剩一格多」；不佔寬度 |
| 開始時間 | 不補 | 病人不會拿它做任何事；0926 刪掉的理由仍成立。面板橫軸左端本來就有 |
| 已經過幾分鐘 | 不補 | 與剩餘時間是同一件事的另一面，兩句都放只是多讀一句 |
| 百分比 | 不補 | 病人想的是時間，不是比例 |
| 刻度上的時間字（10:25、11:25…） | 不補 | 進度條最窄只有約 135px，放不下；有結束時間就夠 |
| 剩下不到幾分鐘時變色或閃 | 不補 | 狀態色各有意思（基準 4.7），快結束不是「要注意」；也會讓人一直盯著看 |

### 1.3 長什麼樣

```
┌────────────────────────────────────────────────────────────────┐
│ 🛏 B2  模擬己   ━━━━━━━━━━━┃━━━━━━━━━━┃━━━━░░░░░┃░░░░░░░░░░   11:06 │
│                 剩 2 小時 19 分                      13:25 結束        │
└────────────────────────────────────────────────────────────────┘
```

- 進度條在上、一行字在下；整塊在列裡垂直置中，**列高不變**（量測 95px，與現在相同）。
- 字用 `--t-meta`（20px）、`--c-ink-2`、等寬數字。床號（56px）、姓名與現在時間（48px）仍是一眼先看到的。
- 「13:25 結束」靠右、對齊進度條右端：進度條的終點就是那個時刻，與面板橫軸兩端標時間是同一種讀法。
- 刻度：2px 寬、`--c-ink-2`，比軌道上下各凸出 6px，填色與未填處都看得到；不標字。
- 用「結束」不用「下機」：四小時到是透析結束，回血、拔針、止血還要一段時間，寫「下機」病人會以為那一刻就能走。

### 1.4 寬度

量法：照 `styles.css` 與 `design-tokens.css` 原樣做一頁，字型用自帶的 Noto Sans TC，圖示保留尺寸，無頭 Chrome 以 1280×800 量每一個元素。基本資訊區內可用寬度 1148px。最壞組合沿用 27.1 第 1.4 節：姓名 4 個字、1 個任務、遊戲、「護理師收到了」，進度條放到最窄。

| 排法 | 欄距 | 床號 A12 | 床號 B2 |
|---|---|---|---|
| 27.1（時鐘圖示＋進度條最窄 100px） | 32px | **差 40px** | 差 2px |
| 27.2（拿掉圖示，最窄＝剩餘時間那一句，約 135px） | 32px | 差 27px | 餘 11px |
| 27.2 | **24px** | **餘 21px** | 餘 59px |
| 27.2，字改 24px | 24px | 差 6px | 餘 32px |

- **27.1 寫的「餘約 10px」不對**；27.1 的量測頁沒留下來，差在哪裡沒追。這次的量測頁照實作時的樣式重做一次即可重現。
- 改法：基本資訊區的欄距從 `--pad`（32px）改成 `--touch-gap` 的兩倍（24px）。任務與遊戲兩顆按鈕之間仍遠大於最小間距 12px。
- 字級只能用 20px：24px 在最壞組合放不下。
- 結束時間什麼時候會被收掉（欄距 24px、進度條區塊要 243px 才放得下兩句）：

| 組合 | 進度條區塊 | 結束時間 |
|---|---|---|
| 床號 B2、姓名 3 個字、遊戲，沒有狀態與任務 | 約 564px | 有 |
| 同上，加「已處理」與 1 個任務 | 約 313px | 有 |
| 床號 B2、姓名 3 個字、1 個任務、遊戲、「護理師收到了」 | 約 242px | **收掉** |
| 床號 A12、姓名 4 個字、1 個任務、遊戲、「已處理」 | 約 227px | **收掉** |

收掉的都是頂列最擠、有狀態要看的時候；狀態一消失就回來。剩餘時間不收。「已處理」的寬度是照字數推的，其餘是量的。

### 1.5 規則

| # | 規則 | 理由 |
|---|---|---|
| 1 | 剩餘時間寫法：60 分以上「剩 2 小時 19 分」，整點「剩 2 小時」；不到 60 分「剩 45 分」 | 不寫「2:19」——會被看成時刻 |
| 2 | 剩餘分鐘＝結束時刻的分 − 現在時刻的分（兩者先捨去秒），夾在 0～240 | 畫面上的「13:25 結束」「11:06」與「剩 2 小時 19 分」要對得上。現行 `dialysisProgress` 用無條件進位：09:25:40 開始、11:06:10 看，算出 140，畫面上減出來是 139 |
| 3 | 結束時刻＝`plannedDialysisEndMs(開始)`，用 `clock.ts` 的 `TIME` 格式化 | 迭代 17.5：五處療程進度同一個終點；面板橫軸右端是同一個值 |
| 4 | 過了結束時刻還沒下機：進度條滿格，**剩餘時間那句不顯示**，「13:25 結束」照留 | 不寫「超過幾分」：下機要等護理師，病人看到超時只會焦慮，也不是病人能做什麼的事 |
| 5 | 擠的時候先收結束時間，剩餘時間一定留；以容器查詢判斷（進度條區塊放不下兩句加間距就不畫結束時間） | 第 1.4 節。「還要多久」比「幾點」更常被問；結束時間在面板橫軸右端還看得到 |
| 6 | 進度條區塊最窄＝剩餘時間那一句的寬（約 135px），取代 27.1 的「最窄 100px」 | 字不能被截 |
| 7 | 拿掉進度條前的時鐘圖示（`clock`） | 有字之後它不再說明任何事；省下的 48px 用來放字。病人端不再用 `clock`，從圖示登記拿掉 |
| 8 | 進度條的無障礙標籤加 `aria-valuetext`：「剩 2 小時 19 分，13:25 結束」 | 數值只有百分比，報讀出來沒有意思 |
| 9 | 每 30 秒跟著現在時間一起更新（`useMinuteClock`），不另開計時器 | 與現在時間同一拍，不會一邊換了一邊還沒換 |

**順帶看到的**：面板橫軸右端是 `max(四小時, 最後一筆量測)`，過了四小時還有量測時會比「13:25 結束」晚幾分鐘。橫軸要包得住所有點，照舊；兩者只在過了結束時刻之後才會不同。

**`dialysisProgress` 改了誰會受影響**：後端即時總覽送給護理端的 `remainingMinutes` 跟著改成同一種算的方式；護理端目前沒有畫面顯示它。`verify:iteration17-5` 的三個例子（136、240、0）改了之後結果相同，不必改。

## 2. 血壓的單位

| 寫法 | 判斷 |
|---|---|
| **毫米汞柱** | **採用**。面板上的單位都是中文：脫水量與體重「公斤」、脈搏「次／分」 |
| mmHg | 不用。面板上唯一的英文縮寫；長者多半不唸英文字母 |

- 位置與脫水量相同：標題右邊、較小一級（`LineChart` 本來就有 `unit`，脫水量用的就是它）。
- 線尾的兩個數字（138、81）照舊不加單位，與脫水量線尾的 1.2 一樣。
- 字都在自帶字型的子集裡（已查：剩、還、小時、分、結束、毫米汞柱）。

## 5. 驗收

**新增 `verify:iteration27-2`**（不需要後端）：

1. 剩餘時間寫法：240 → 剩 4 小時；139 → 剩 2 小時 19 分；120 → 剩 2 小時；45 → 剩 45 分；1 → 剩 1 分；0 → 不顯示。
2. `dialysisProgress`：09:25:40 開始、11:06:10 看 → 剩 139；開始前 → 240；超過四小時 → 0。
3. 首頁：進度條沒有 `clock` 圖示；三條刻度在 25%、50%、75%；結束時刻來自 `plannedDialysisEndMs`；`aria-valuetext` 兩句都在。
4. 樣式：`.home-info` 欄距 24px；進度條區塊最窄是剩餘時間那一句；結束時間有容器查詢；字級 `--t-meta`。
5. 血壓圖有 `unit="毫米汞柱"`；`clock` 已從圖示登記拿掉，病人端沒有任何地方再用它。

**截圖**：無頭 Chrome 1280×800，平常、第 1.4 節的最壞組合（A12）、過了結束時刻各一張；三張都是一列、字沒有被截。

**既有腳本**：`verify:iteration17-5`、`verify:iteration17-4`、`verify:iteration27` 不必改，照跑。

## 6. 考慮過、沒採用的

| 做法 | 為什麼不採用 |
|---|---|
| 進度條自己一列，放在基本資訊區底下 | 違反 27.1 的「固定一列」；面板少一截高度 |
| 字寫在進度條裡面（加粗成一條帶子） | 填色會從字中間經過，一半深底一半淺底，看不清；最窄時也放不下 |
| 結束時間放在現在時間底下 | 兩個時刻疊在一起，最容易看錯哪個是現在 |
| 只寫「13:25」不寫「結束」 | 列上已經有一個 11:06；不寫清楚就要病人自己猜 |
| 字級 24px | 最壞組合差 6px（第 1.4 節） |
