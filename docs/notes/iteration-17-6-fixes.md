# 迭代 17.6：公告草稿換則、新增裝置、拿掉病人頁、排班頁的病人順序

版本：v0.1　文件狀態：已完成（2026-10-07 開立）　適用讀者：FDE 工程團隊

---

## 0. 本文件的定位

本文件不是需求文件，是一份**修正紀錄**：2026-10-07 使用者一次交代了五件事，歸在迭代 17.6 處理——

> 簡易版公告與院內衛教無法切換到後面，目前只能選擇第一則，修正一下。
> 專業版把裝置管理的解除佈建移到系統管理跟停用同個區域；目前裝置管理中的目前有效綁定功能，跟排班與指派重複了，拿掉；
> 裝置管理名稱改成新增裝置，唯一功能就是註冊新平板；下面一樣要列出目前所有平板狀態。
> 專業版拿掉病人功能，新增病人功能現在都是直接 API 新增。
> 專業版排班與指派功能，病人的下拉選單中，病人的排序方式要跟簡易版一樣，一樣要有重新整理按鈕。

本文件記錄改了什麼、開發端做的判斷。

- 功能需求來源仍是《[軟體需求規格書](../requirements/srs.md)》；病人頁拿掉補在 SRS 院方 API 取代表「新增病人」那一列
- 範圍與技術選型仍以《[實作規格書](../requirements/implementation-spec.md)》為準（4.15.6 節是本文件的摘要；1.1 記下**第八次**改動既有驗收腳本）
- 介面規則同步在《[介面設計基準](uiux-design-baseline.md)》3.3（主列）與 3.5.3（簡易版）
- 與需求文件衝突時，以需求文件為準

**為什麼叫 17.6 而不是迭代 18。** 全部是護理端畫面的調整：沒有新的端點、資料表一欄都沒動，後端只有導覽項的定義變了；迭代 18（規則引擎）的內容一項都沒動。

**「專業版維持 0919 版面，不動」的例外。** 《介面設計基準》0.1 節說專業版不動；這五件裡有四件是使用者直接指示改專業版，與 0929 的斷線示警、求助橫幅上限一樣算例外，基準 3.3 已改。

## 1. 改了什麼

| # | 改什麼 | 檔案 |
|---|---|---|
| 1 | **簡易版公告與院內衛教：草稿可以換到後面幾則**。原本草稿卡固定放第一則（待核准的最早一則），旁邊只寫總數、點不動，後面幾則要先核准或退回前面的才看得到。改成不只一則時卡底下一列 ‹ 第幾則／共幾則 ›，換到哪一則，核准、退回、拖到平板都是那一則；處理完那一則不見了，同一個位置就是下一則 | `apps/nurse-pwa/src/simple/Trays.tsx` 的 `ContentTray`；樣式 `workbench.css` 的 `.draft-pager` |
| 2 | **「＋」（要 AI 寫一份草稿）移到框左欄圖示底下**，與病人框的重新整理同一處。截圖時發現：草稿卡長高之後下面的已核准清單只剩一格高，「＋」佔掉那一格，已核准的第一則被切掉一半 | 同上 |
| 3 | **「裝置管理」改名「新增裝置」**：唯一的動作是註冊新平板（含佈建 QR code），底下照樣列出所有平板的狀態（綁定、可否指派、固定狀態、外殼版本、佈建、最後連線）。**「目前有效綁定」拿掉**（解除綁定與下機在排班與指派做，兩處重複）；平板清單的「裝置操作」欄拿掉 | `apps/nurse-pwa/src/pages/DevicesPage.tsx`；導覽名稱在 `packages/shared/src/navigation.ts` |
| 4 | **解除佈建移到系統管理的「平板停用」**，與停用同一張表。解除佈建的平板照樣列在那裡，可以重新「登記佈建」（原本也在裝置管理） | `apps/nurse-pwa/src/pages/SystemTabletsCard.tsx` |
| 5 | **專業版拿掉「病人」那一頁**：導覽項、路由、元件一起拿掉。病人主檔一律由院方 API 建立 | `navigation.ts` 拿掉 `PATIENTS`；`App.tsx`；刪除 `pages/PatientsPage.tsx` |
| 6 | **排班與指派的病人下拉選單**：順序與簡易版病人框相同（正在透析的在上面、越晚開始越上面；其餘依姓名筆畫），**用的是同一支 `trayOrder`**；旁邊一顆「重新整理」（`refresh-cw` 加字），立即抓一次院方資料再重取這一頁，**只在接了院方資料時出現**（與簡易版相同） | `apps/nurse-pwa/src/pages/ConsolePage.tsx`；`simple/model.ts` 的 `trayOrder` 參數改成只要療程清單 |
| 7 | 畫面上提到「裝置管理」的字一併改：排班頁的跨日綁定提示（原本叫人去「目前有效綁定」）、沒有可指派平板的提示、簡易版沒有平板時的提示 | `ConsolePage.tsx`、`simple/Workbench.tsx` |

主列從 7 項變 6 項：即時總覽 → 緊急通報 → 排班與指派 → **新增裝置** → 公告與院內衛教 → 總覽螢幕模式。

## 2. 開發端的判斷

| 判斷 | 理由 |
|---|---|
| 第 1 項解讀成「草稿卡只放得出第一則」 | 簡易版那一框能「選」的有兩種：草稿卡與已核准的清單。已核准的清單本來就有 ‹ ›；草稿卡固定是第一則、沒有任何辦法看第二則，符合「無法切換到後面、只能選擇第一則」。順手修掉的第 2 項是截圖時看到的另一個「只看得到一則」 |
| 草稿換則放在卡底下一整列，不放在核准、退回那一直排 | 那一直排再加三樣東西會比卡上的字還高；放在底下一列不擠到草稿的字（草稿卡不截字是迭代 17 的規則） |
| 換則與清單分頁用同一組圖示（`chevron-left`、`chevron-right`） | 一個圖示只代表一件事：換頁。沒有新增圖示 |
| 「目前有效綁定」拿掉之後，跨日的綁定要先跳日期才解得掉 | 那份清單是迭代 7 為「跨午夜的綁定在排班頁解不掉」加的（實作規格書 3.15 修法 1）。排班頁本來就有修法 2 的提示：列出不在這一天的有效綁定、按一下跳到那一天解除，所以照樣解得掉，只是多按一下；3.15 寫的「不改日期就解除」在畫面上不再成立。後端的不依日期清單照留（排班頁的提示就是用它），`verify:iteration7` 照樣通過 |
| 「登記佈建」跟著解除佈建一起搬 | 註冊新平板時後端就自動佈建，新增裝置那一頁用不到它；它只在解除佈建之後才用得到，放在同一處 |
| 解除佈建**不比照停用擋下正在服務病人的平板** | 原本裝置管理就沒擋，使用者這次只要求搬位置；要不要擋是另一件事。按鈕仍要確認（N-5） |
| 系統管理那一頁的分頁名稱仍叫「平板停用」 | 使用者說的是「跟停用同個區域」；改分頁名稱會動到迭代 17.1 的驗收腳本，沒有必要 |
| 病人頁的導覽識別碼（`PATIENTS`）一併拿掉，資料表裡舊環境留下的那一列不刪 | 後端載入版位時本來就略過認不得的識別碼；只做加法的資料庫規範下，不為一列設定寫遷移 |
| 病人清單的後端端點、`createPatient` 端點都不動 | 簡易版、排班與指派、其他頁都要讀病人；簡易版**沒接院方資料時**的「新增病人」（開發機用）仍呼叫 `createPatient`。使用者這次指示的是專業版 |
| 專業版的重新整理是「圖示＋字」，不是只有圖示 | 專業版維持文字按鈕的寫法；圖示與簡易版相同，讓兩邊看得出是同一件事 |
| 排班頁的病人順序用「目前選的那一天」的療程判斷誰正在透析 | 排班頁本來就是一天一天看；選今天時與簡易版完全相同 |

**在瀏覽器實際看過**（`npm run demo:patient`，無頭 Chrome 1366×768）：
簡易版要了三份草稿之後共 14 則待核准，草稿卡底下「‹ 1／14 ›」，按 › 換成第二則「磷結合劑跟著飯吃」，整頁沒有捲軸；「＋」在框左欄、已核准的第一則整格看得到。
專業版主列六項、「新增裝置」只有註冊新平板與平板清單；系統管理「平板停用」對 DEMO-04 按解除佈建 → 確認 → 狀態變「未佈建」、按鈕變「登記佈建」→ 按下去回到「可使用」。
排班與指派的病人下拉選單：模擬庚、模擬己、模擬戊、模擬丁、模擬丙、模擬乙、模擬甲（正在透析，越晚開始越上面），接著模擬子、模擬丑、模擬壬、模擬癸（筆畫），與簡易版病人框同序；按重新整理之後順序不變、沒有錯誤。

**沒有驗的**：一般護理師帳號（沒有裝置管理權限）看新增裝置那一頁——權限沒有改，照舊是 `BINDING_MANAGE` 或 `DEVICE_MANAGE` 任一個就看得到。
