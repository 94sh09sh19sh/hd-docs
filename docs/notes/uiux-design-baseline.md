## 0. 本文件的定位

本文件不是需求文件，是一份**設計基準**：它規定「這套系統的介面長什麼樣、為什麼長這樣、下一次改的時候要遵守什麼」。

- 功能需求來源是《[軟體需求規格書](../requirements/srs.md)》，介面相關的硬性要求在第 6 章非功能性需求與 FR-P13、FR-S10、FR-S11
- 與需求文件衝突時，**以需求文件為準**
- 待確認事項指回《[尚待確認事項清冊](../requirements/open-questions.md)》，本文件不另立清單

**這份文件不是一次性的改版說明。** 使用者於 2026-09-19 指示：介面重新設計之後，**日後所有介面工作都要依這份基準做**。因此它寫的是可重複套用的規則，不是這一次改了哪幾個畫面。

> **給 AI agent**：對應的可執行版本在專案的 `.claude/skills/hd-uiux/`。動任何介面程式碼前先讀那一份；本文件是它的理由書與人類可讀版。兩者若有出入，**以本文件為準並回報 skill 已過時**。

### 0.1 0926 方向變更：極簡

使用者於 2026-09-26 指示介面完全重新設計，四條依序套用（SRS 第 6 章「可用性（極簡）」）：

| # | 規則 | 在這份基準裡落在哪 |
|---|---|---|
| M-1 | **能用圖示就不要用文字** | 4.6 圖示表：每個圖示登記一次意思 |
| M-2 | **能用框線與顏色區隔功能，就不要用文字，也不要把不同功能混在一起** | 4.7 狀態色與形狀；2.4、3.5 的分區 |
| M-3 | **不影響功能的字全部刪掉** | 判準：刪掉之後使用者還能不能完成那個動作。法規要求的標示不得刪 |
| M-4 | **頁面能不上下捲動就不捲動** | 內容多時改分頁，不改捲動；4.10 目標解析度 |

**適用範圍**：病人端全部畫面、護理端簡易版。**護理端專業版維持 0919 版面**，第 3.3 節的導覽列規則只適用於它。

**這四條與 0919 的原則怎麼相處**：0919 的族群分析（第 1～3 章）一條都沒有被推翻——病人還是躺著、一隻手在打針，
護理師還是被切碎的時間。極簡是在同一群人身上**再往前推一步**：字級、對比、觸控目標的下限不動，
改的是「畫面上放什麼」。兩者衝突時，**下限贏**——不能為了不捲動把字縮到 20px 以下，要改分頁。

## 1. 為什麼要先分析族群

上一版介面的問題不是「不好看」，是**沒有預設的使用者**。兩端共用同一套版面假設：一樣的字級邏輯、一樣的卡片密度、一樣的資訊層級。但這兩群人的使用情境幾乎沒有一處相同：

| | 病人端 | 護理端 |
|---|---|---|
| 姿勢 | **躺著**，視線斜向上 | 站著或半坐，視線平視 |
| 手 | **常常只有一隻手能動**（另一隻在打針） | 兩隻手，但常拿著東西 |
| 時間 | 四小時，非常多 | **被切碎**，每次幾十秒 |
| 注意力 | 低，可能想睡、不舒服 | 高但被分散，同時盯多床 |
| 動機 | 打發時間、身體不舒服時求救 | 完成手上的事，不漏掉任何一床 |
| 熟悉度 | 每週三次，**但多半不熟數位介面** | 每天用，會變得很熟 |
| 犯錯的代價 | 按錯 → 護理師白跑一趟 | 看漏 → **病人沒有被處理** |

**同一套版面同時服務這兩群人，只會兩邊都做不好。** 下面兩節分別描述它們。

## 2. 族群一：透析病人（病人端平板）

### 2.1 這群人的事實

台灣血液透析族群的組成有幾項結構性事實，它們直接決定介面怎麼做：

| 事實 | 對介面的意思 |
|---|---|
| **年齡偏高**，多數為中老年 | 老花是常態。**字級不是偏好問題，是能不能看到的問題** |
| **糖尿病腎病變是最大宗病因** | 糖尿病視網膜病變常見，對比度與色彩辨識能力可能下降。**不得用顏色作為唯一的資訊載體** |
| 每週固定三次、每次四小時 | 這個介面他們會看**幾百次**。一個小小的煩人之處會被放大幾百倍 |
| 治療中一隻手固定不能動 | **所有操作必須單手可完成**，而且是在畫面的下半部 |
| 躺著，平板多半架在床邊支架上 | 視距約 40～70 公分，角度傾斜。**畫面上半部反光最嚴重** |
| 可能虛弱、想睡、注意力低 | 任何需要「讀完一段話才知道怎麼做」的設計都會失敗 |
| 不舒服的時候才最需要它 | **求助這條路徑必須在最糟的狀態下也走得通** |

### 2.2 六條設計原則

| # | 原則 | 具體規則 |
|---|---|---|
| P-1 | **求助永遠在同一個地方，而且永遠在下半部** | 固定版位，任何畫面、任何狀態、輪播中或非輪播中，位置與尺寸一律相同 |
| P-2 | **一個畫面一件事** | **0926 起首頁只有三區：基本資訊、輪播內容、緊急回報**（見 2.4）。問卷與衛教不再是首頁的按鈕，改由療程時點帶出來。不要因為「還有空間」就多放東西 |
| P-3 | **字要大到躺著看得清楚** | 內文最小 20px，數值與按鈕文字更大；行高寬鬆 |
| P-4 | **顏色不是唯一線索** | 每一個用顏色區分的狀態都要同時有文字或圖形 |
| P-5 | **不要有需要精準的操作** | 觸控目標最小 64×64px，彼此間距至少 12px；沒有長按、沒有滑動手勢、沒有雙擊 |
| P-6 | **不確定的時候，說人話** | 不寫「已提交」寫「護理師收到了」；不寫「同步中」寫「正在送出」 |

> **0920 調整（迭代 9.1）**：首頁的動作由三個增為四個，加上求助區共五個目標。
> 新增的是「看今天的資訊」——輪播原本只有「靜置到門檻」一個入口，病人想主動看就沒有辦法，
> 而病人端不得有長按、滑動、雙擊（P-5），能做的入口只剩一顆看得見的按鈕。
> 同一次調整把首頁的求助狀態由最多六列收成一列，首頁在平板上因此不必捲動就看得完。
> 理由與完整清單見《[迭代 9.1 修正清單](iteration-9-1-fixes.md)》第 2.4、2.5 節。
>
> **0926 再調整（迭代 14）**：四個動作全部拿掉。「看今天的資訊」不需要了——輪播本來就在首頁上播；
> 問卷、衛教、心情改由療程時點帶出來（FR-P15），首頁只剩三區（FR-P14）。

### 2.3 這一次修掉的具體問題：緊急按鈕蓋住輪播的字

**症狀**：閒置輪播開始後，求助按鈕蓋住輪播卡片的文字。

**原因不是「按鈕太大」。** 原本的做法是：輪播是一個覆蓋整個畫面的圖層，而求助按鈕在底下那個首頁版面的正常文件流裡，輪播開始時把它的**堆疊層級抬高**，讓它浮到輪播之上。

這個做法有兩個問題：

1. **按鈕的位置由首頁版面決定，不是由畫面決定。** 它是首頁四個按鈕中的第二個，實際落在哪裡取決於上面有多少內容、螢幕多高。輪播那一層只能「猜」它在下半部，然後把卡片往上推——猜錯就蓋住。
2. **「位置固定」被實作成「層級固定」。** FR-P13 要的是版位固定，兩者不是同一件事。

**修法：把求助按鈕從版面裡拿出來，做成整個應用程式共用的固定底部區域。**

```
┌─────────────────────────┐
│                         │
│   內容區                 │  ← 首頁、問卷、衛教、輪播都畫在這裡
│   （輪播卡片也在這裡）     │     這一區的高度 = 畫面高度 − 求助區高度
│                         │
├─────────────────────────┤
│   ★ 我需要協助           │  ← 固定區。永遠在這裡，永遠一樣大
└─────────────────────────┘     內容區永遠畫不到這裡
```

三個要點：

- **求助區是版面的一部分，不是浮在上面的東西。** 內容區的可用高度先扣掉它，因此「蓋住」在結構上不可能發生
- **輪播卡片的高度以內容區為基準計算**，不是以整個畫面為基準
- **非輪播時求助區也在**，位置與尺寸完全相同——這才是 FR-P13 所說的「位置固定」

**驗收方式**：在輪播進行中截圖，量求助區的位置與尺寸；退出輪播再截一次。**兩張圖上那塊區域必須一模一樣，而且輪播卡片的任何一個字都不得落在那塊區域裡。**

### 2.4 0926 起的病人端版面：首頁三區、任務依時點出現

**首頁**（FR-P14）由上而下三區，以框線與底色分開，整頁不捲動：

```
┌─────────────────────────┐
│ 🛏 05   ▓▓▓▓▓░░░   📋 📖  │  ← 基本資訊：床號、療程進度（圖形）、待完成任務的圖示
├─────────────────────────┤
│                         │
│   輪播內容               │  ← 首頁上就在播，不必等閒置
│   （卡片、資料時間）       │
│                         │
├─────────────────────────┤
│   🔔 我需要協助           │  ← 緊急回報：2.2 的固定區，位置與大小不變
└─────────────────────────┘
```

| 區 | 放什麼 | 不放什麼 |
|---|---|---|
| 基本資訊 | 床號、療程進度條、待完成任務的圖示（點了就繼續）、求助狀態與離線狀態各一個圖示加一句話 | **姓名與病歷號**（首頁與輪播同屬鄰床可見的畫面）、時段與開始時間的文字、平板序號 |
| 輪播內容 | 輪播三層內容，點卡片看說明，說明頁逾時自動退回 | 操作說明（「觸碰螢幕任一處…」）、功能介紹 |
| 緊急回報 | 2.2 的求助區 | 任何其他按鈕 |

**任務畫面**（FR-P15）：透析前問卷、心情問卷、衛教在各自的時點**自動以全螢幕出現**，一題一頁：

```
┌─────────────────────────┐
│ 📋  ● ● ○ ○ ○        🏠 │  ← 任務圖示、第幾題（圓點）、回首頁
│                         │
│   最近有沒有頭暈？        │  ← 題目本身是必要的字，不刪
│                         │
│  ┌────┐ ┌────┐ ┌────┐   │  ← 圖示選項，選項文字是必要說明
│  │ ○  │ │ ▮  │ │ ▮▮ │   │
│  │沒有│ │輕微│ │中等│   │
│  └────┘ └────┘ └────┘   │
│   ‹                  ›  │  ← 上一題／下一題（單選題點了選項就自動往下）
├─────────────────────────┤
│   🔔 我需要協助           │  ← 任務畫面也有，版位相同
└─────────────────────────┘
```

| 任務 | 什麼時候出現 | 完成的判準 |
|---|---|---|
| 透析前問卷 | 綁定一成立（本次療程還沒回報過），或距上次回報超過問卷到期間隔 | 送出（離線時暫存也算） |
| 心情問卷 | 綁定後經過營運參數「心情問卷出現時點」（預設 120 分鐘） | 本次療程已送出 |
| 衛教 | 綁定後經過營運參數「衛教出現時點」（預設 180 分鐘） | 護理師核可的內容都按過「看完了」，而且本次療程做過一次測驗（沒有題目就免） |

- **自動出現只有一次。** 病人按回首頁就回首頁，任務改成基本資訊區的一個圖示，點圖示接著做
- 任務畫面閒置超過閒置門檻（FR-P09，預設 60 秒）自動回首頁——病人睡著了，平板不該一直停在第 3 題
- **內容多到一頁放不下時分頁，不捲動**（M-4）。衛教內文以欄分頁（`PagedText`），版面尺寸變了自動重算頁數
- **求助的類別也一樣**（0929，迭代 14.2）：依畫面實際大小分頁，一個框放不完就接到下一頁，框照樣分開畫（M-2）；
  每一格同高，一頁放幾列才算得出來。只做到「不捲動」而不分頁，結果是放不下的類別被切掉、病人看不到
- **「其他」那一框（如廁、環境、口渴、機器）是功能開關，預設關閉**（0929）：關閉時只剩「不舒服」一框，
  組尾接非臨床組的「其他，請有人過來一下」。按鈕少一半；要上廁所、機器在叫，仍然有一顆送得出去
- 為什麼時點是營運參數不是寫死：療程長度因人而異，四小時是常態不是規定，護理部要能改

**這一版刪掉的字**（M-3 的判準：刪掉之後病人還能不能完成動作）：「您好」「病歷號」「療程時段」「開始時間」
「平板序號」「觸碰螢幕任一處即可回到主畫面」「點一下看說明」（改成 💡 圖示）、各按鈕底下的副標、
問卷頁頂的「第 N / M 頁・已勾選 K 題」（改成圓點）。**沒有刪的**：題目、選項文字、「僅供參考，非診斷結果」一類法規要求的標示、
離線時「請按床邊呼叫鈴」——少了這一句病人不知道要改用什麼。

## 3. 族群二：透析室護理師（護理端）

### 3.1 這群人的事實

| 事實 | 對介面的意思 |
|---|---|
| **忙，而且是被打斷的那種忙** | 每次看畫面只有幾十秒。**要能一眼看出「現在有沒有事」** |
| 同時負責多床 | 總覽的密度要高，但**重要的東西要跳出來** |
| 站著或走動中操作 | 目標不能太小；但不像病人端那麼極端 |
| 每天用同一套介面 | 會變熟。**熟了之後最在意的是「要點幾下」** |
| 首波只有護理站的一兩台電腦 | 螢幕不小，但**不是隨身的**。需要走回護理站才能操作 |
| 漏看一則通報的代價很高 | 通知不能只靠一個數字角標 |

**最重要的一條**：護理師不是「使用者」，是**在工作中順便用這個工具的人**。介面每多一個步驟、每多一個要讀的字，都是從照顧病人的時間裡扣掉的。

### 3.2 六條設計原則

| # | 原則 | 具體規則 |
|---|---|---|
| N-1 | **一眼看出有沒有事** | 進畫面 2 秒內要能回答「現在需要我嗎」。待處理通報要用顏色＋數字＋位置三重強調 |
| N-2 | **每天用到的才放在主列** | 導覽列只放每日必用；其餘收進選單或關閉（FR-S11） |
| N-3 | **順序照工作流程，不照功能分類** | 交班 → 指派 → 盯著 → 處理 → 收工。不是「病人相關／裝置相關／設定相關」 |
| N-4 | **不要讓護理師讀系統的內部用語** | 狀態一律中文，開關一律中文名稱（FR-S10） |
| N-5 | **破壞性動作要有阻力，日常動作不要有** | 解除綁定要確認；標記已讀不要確認 |
| N-6 | **關掉的功能就是不存在** | 不放灰色按鈕、不放「敬請期待」（DEP-34） |

### 3.3 導覽列重新編排

**原本 17 條連結一字排開**，沒有層級、沒有順序邏輯，每天用的跟半年用一次的並列在一起。

**新編排分三層（版位可在系統設定調整，FR-S11）**：

**主列——每日必用，順序照一天的工作流程：**

| 順位 | 項次 | 為什麼在這裡 |
|---|---|---|
| 1 | 即時總覽 | 預設畫面，一天中看最多次 |
| 2 | 緊急通報 | 有事的時候第一個要去的地方，帶未處理數 |
| 3 | 排班與指派 | 每個班次開始時做一次 |
| 4 | 裝置管理 | 平板有狀況時；也是看 Kiosk 逸出狀態的地方 |
| 5 | 病人 | 新病人或資料要改的時候 |
| 6 | 輪播內容 | 內容維護。**這一項是主列裡最邊緣的，若護理長覺得用不到，改設定收進選單** |
| 7 | 總覽螢幕模式 | 開護理站那台大螢幕用，一天按一次 |

**選單（「更多」下拉）——用得到，但不是每天：**

帳號審核、護理紀錄、衛教、SOP 查詢、臨床數值、病人趨勢、稽核軌跡

**關閉——首波不提供：**

班表、成效基準、離院衛教，以及所有需手持裝置才能用的功能（DEP-29）

**最右側固定**：系統管理（只有具權限者看得到）、使用者名稱與登出。

**三條規則**：

1. **主列最多 7 項。** 超過就不是「每日必用」了，是把選單攤開
2. **順序是工作流程，不得改成字母或功能分類**
3. **版位改動寫入稽核軌跡**——半年後有人問「這個功能什麼時候不見的」要答得出來

### 3.4 移除介面上的內部技術識別（FR-S10）

**現況盤點**（實際出現在護理師看得到的畫面上）：

| 問題 | 出現在哪一類地方 |
|---|---|
| 卡片標題帶需求編號，例如「功能開關中心（FR-S08）」 | 系統管理、SOP 查詢、趨勢、衛教、護理紀錄的區塊標題 |
| 提示文字帶待確認編號，例如「待資訊室確認（Q-09）」 | 臨床數值匯入、成效基準 |
| 直接印出列舉常數，例如排班狀態、帳號狀態 | 排班與指派的狀態欄、帳號審核的狀態欄 |
| 開關清單印出開關識別字與需求編號 | 功能開關 |
| 說明文字帶介面層類別名 | 臨床數值 |
| 說明文字提到迭代編號，例如「將於迭代 8 提供」 | 唯讀帳號的空狀態 |

**處理原則**：

- **每一個列舉值都要有中文顯示名稱**，由共用常數提供，不在畫面上臨時拼
- **需求編號、待確認編號、迭代編號一律移除**；要說明「這個還沒好」就直接說人話，或依 DEP-34 整個不顯示
- **程式碼註解不動。** 這條規範管的是使用者看得到的字，不是原始碼——需求編號留在註解與文件裡，那是可追溯性的來源
- 新增一支檢查腳本掃描前端原始碼中會被繪製出來的字串，**把它納入驗收**，不靠人工複查

### 3.5 0926 起的護理端簡易版：一張床位圖

**簡易版每次登入預設開啟**，右上角一顆按鈕切到專業版（FR-N14）。專業版就是 3.3 那一套，不動。
簡易版只給有「看病人」權限的帳號；稽核這類不看病人的角色直接進專業版。

```
┌──────────────────────────────────────────────┬──────────────┐
│ ⛔ 05 床 胸悶胸痛（紅框，緊急時才出現）      ⇄ 專業版 │              │
├──────────────────────────────────────────────┤  👤 病人       │
│ ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐ │  ＋ 新增      │
│ │01 ◆治療│ │02  空 │ │03 ▲待處│ │04 ◆治療│ │05 ⬣緊急│ │  ⌛ 候床  ⇥下機│
│ │王○○ ▓▓░│ │      │ │李○○   │ │…     │ │…     │ ├──────────────┤

│                                              ├──────────────┤
│                                              │  📣 輪播內容 ▦全部│
└──────────────────────────────────────────────┴──────────────┘
```

**分區**：床位圖在左，四種可以拖上去的東西在右，**各自一個框、各自一個底色**（M-2），不混在一起：
病人（含新增、候床、下機兩個放置區）、護理師、平板（含停用區）、輪播內容（含新增與「全部床位」放置區）。

**框裡的清單**（0929，迭代 14.2）：格子同寬同高，每頁幾格依框的實際大小算，**不寫死**；分頁的 ‹ › 排在框底下放置區那一列的最前面，
不另起一列（框只放得下一列時，另起的分頁列會被切掉）。**停用的平板回到平板清單**，排在備用的後面、帶鎖頭——
兩者的用法一樣（拖到床上就用），停用區只是放置區，不放任何東西。
**蓋在床位格上的面板**（新增病人、處理方式）超出畫面時往上或往左長，不能有一顆按鈕在畫面外。

**九項一步操作**（SRS 5.2 補充說明的表）：

| 任務 | 拖曳 | 不拖曳的替代做法 | 復原 |
|---|---|---|---|
| 看全部病人現況 | —（床位格底色＋圖示即狀態） | — | — |
| 接緊急通報 | — | 點床位格一下即確認 | 不提供（見下） |
| 結案 | — | 點處理方式圖示；結果預設「已解決」，8 秒內點其他結果即改 | 8 秒內按復原即不送出 |
| 新增病人 | 拖「＋」到空床 | 點「＋」、再點空床 | 復原＝解除綁定並取消排班 |
| 新增衛教或公告（0929） | 拖輪播內容框的「＋」到床位或「全部」 | 點「＋」、再點目的地 | 復原＝下架（輪播內容沒有刪除） |
| 指派平板與病人 | 拖病人到床位 | 點病人、再點床位 | 復原＝解除綁定 |
| 解除指派 | 拖病人到「候床」 | 點床上病人、再點「候床」 | 復原＝重新綁定 |
| 排班與床位分配 | 拖護理師到床位 | 點護理師、再連點多床 | 復原＝還原那幾床原本的負責人 |
| 推送輪播內容 | 拖內容卡到床位或「全部」 | 點內容卡、再點床位 | 復原＝還原原本的播放範圍 |
| 裝置管理 | 拖平板到另一床（換床）或停用區 | 點平板、再點目的地 | 復原＝搬回原床／解除停用 |

另有「下機」：拖病人到「下機」即正常下機結束。下機會把療程標成已完成、回不去，**所以它延後 8 秒才送出**，
8 秒內按復原就當作沒發生——這是「一步復原」在不可逆動作上的做法，結案用的是同一個機制。
**8 秒之後才發現拖錯**（0929）：把病人拖回床上就好，今天這個時段的療程會重新開啟，不必到專業版處理；下機與重新開啟各留一筆稽核。

**「接緊急通報」為什麼不提供復原**：確認通報是一個時間戳記，記的是「護理師什麼時候知道了」。
撤掉它等於改寫那個時間，而那正是成效指標要用的資料（SRS FR-N10 的「確認時間與到達時間分開」）。
按錯的代價是一筆早了幾秒的確認，比可以被撤掉的確認時間小得多。

**一步完成不得以犧牲紀錄換取**（SRS 5.2）：簡易版呼叫的是**專業版同一支端點**，稽核軌跡與結構化欄位完全相同；
權限檢查也相同——沒有裝置管理權限的帳號，平板框與停用區根本不出現（N-6）。
**導覽版位也相同**：「班表」在導覽版位裡是關閉的（首波預設）時，簡易版不出現護理師框，「排班與床位分配」那一項也就不在——
關閉的功能就是不存在，不會因為換了一個畫面就繞過去（實作規格書 3.13）。

**床位清單是資料**（預設 15 床，系統管理 → 營運參數 → 床位清單）。**有病人正在治療的床拿不掉**：
病人在哪一床是看他那台平板在哪一床，床從床位圖上消失，那位病人就從簡易版上消失了。
專業版才有的功能（AI 草稿審閱簽核、系統設定、報表）不出現在簡易版。

**簡易版刪掉的字**：表頭、欄名、「病歷號」、統計數字塊（改由床位格底色直接表達）、「重新整理」按鈕（即時串流本來就會更新）。
**留下的字**：床號、病人姓名（護理站不是鄰床可見的畫面）、求助類別、處理方式的名稱（圖示底下一行小字，
十六種處理方式光靠圖示分不清，這是必要說明）。

## 4. 共用的設計系統

兩端各有各的版面，但底層的語彙要一致——同一個顏色在兩邊代表同一件事，否則維護的人會混亂。

### 4.1 顏色

**只有四種語意色，而且每一種都必須搭配文字或圖形**（P-4）：

| 語意 | 用在哪 | 搭配 |
|---|---|---|
| 一般 | 預設狀態、可點擊的東西 | — |
| 注意 | 待處理、進行中 | 文字標籤 |
| 警示 | 緊急通報、勞動條件違反、斷線 | 文字標籤＋圖形 |
| 完成 | 已處理、成功 | 文字標籤 |

**求助按鈕用警示色，而且只有它用。** 病人端畫面上不得有第二個紅色的東西，否則它就不再是「那顆紅色的」。

**兩端都必須通過對比度檢查**：內文對背景至少 4.5:1，大字與圖形至少 3:1。病人端因為糖尿病視網膜病變常見，**目標值提高到內文 7:1**。

**病人端是白底**（0930，迭代 14.5）：醫師說透析室很暗，病人端背景改成白底，框與按鈕是白底上的淺灰。
白底上要過 7:1，四種語意色都是同色相的**深色系**（深青、深褐、深紅、深綠）；疊在語意色上的字是白色。
紅色仍只給求助——求助區是深紅底白字，注意色是深褐而不是紅。
**夜裡不另做一套深色主題**，夜裡靠夜間模式調暗（4.5）。護理端維持原本的配色，常駐總覽螢幕仍是深色。
0919～0929 病人端是深色底，改版的理由與色碼對照見《[迭代 14.5 修正紀錄](iteration-14-5-fixes.md)》2.1。

### 4.2 字級

| | 病人端 | 護理端 |
|---|---|---|
| 內文最小 | **20px** | 15px |
| 主要按鈕文字 | **28px** | 16px |
| 數值（體重、時間） | **36px 以上** | 20px |
| 輪播卡片主文 | **40px 以上**（要從床上看得清楚） | — |

字級一律以相對單位定義並隨畫面寬度縮放，但**下限就是上表的數字，不得被縮到更小**。

### 4.3 觸控與點擊目標

| | 病人端 | 護理端 |
|---|---|---|
| 最小尺寸 | **64×64px** | 40×40px |
| 目標間距 | 至少 12px | 至少 8px |
| 手勢 | **只有「點一下」。** 無長按、無滑動、無雙擊 | 可有鍵盤快速鍵，但不得是唯一路徑 |

### 4.4 動態

- **病人端不做任何會自己動的裝飾。** 閒置輪播的換卡是功能，不是裝飾；除此之外不要有呼吸燈、不要有位移動畫
- 護理端的新通報可以有一次性的進場強調，**但不得持續閃爍到令人疲勞**——會被忽略的警示等於沒有警示
- 兩端都要尊重作業系統的「減少動態效果」設定
- **斷線示警**（0929，迭代 14.3）：護理端專業版每一頁與簡易版，與伺服器的連線一斷，整個畫面外圍一圈閃爍的紅框（不擋點擊），
  加上一條紅底白字、帶 `wifi-off` 圖示的橫幅，寫明「畫面上的資料不會更新，新的求助可能看不到」。
  兩版共用同一個元件（`connection-status.tsx`），**新畫面不必、也不要自己畫斷線狀態**。常駐總覽螢幕維持它自己那一套。
  簡易版的橫幅獨占一列、床位圖讓出高度，整頁仍然不捲動。這是「專業版不動」（FR-N14）的例外，出自使用者 0929 的指示

  為什麼要遍及每一頁：以前只有常駐總覽螢幕會大聲示警，其他頁面停在最後一刻的資料、看起來一切正常，
  護理師要等到按下操作、送出失敗才知道。**看起來正常的斷線，是最危險的斷線。**
- **求助橫幅有上限**（0929，迭代 14.4）：專業版上緣的求助橫幅最多三條完整的，其餘收成一列「還有 N 則求助」，附「全部查看」到緊急通報頁。
  緊急的排在前面；收掉的裡面有緊急時，那一列用警示色並寫出「其中 N 則緊急」。別處（另一台護理站、簡易版）已經接起來的不再佔位置，
  但快照裡找不到的一律留著——寧可多留一則，也不能漏掉一則。**不要改成限制高度加捲軸**：黏在上緣的小框裡再捲一次，藏起來的等於看不到。
  這是「專業版不動」（FR-N14）的第二個例外，出自使用者 0929 的回報：大量求助湧入時，一則一條、沒有上限的橫幅疊得比畫面還高，
  每一頁都被蓋住。**真的需要它的時候，它反而讓整個畫面不能用。**

### 4.5 暗色與夜間

- 病人端已有夜間模式（晚班調暗），**調暗不得改變版面與字級**，只改亮度
- **被調暗的區塊自己要有底色**（0930）：白底上，沒有底色的區塊被調暗的只有字，白底照樣全亮。輪播區因此有自己的底色
- 病人端按下去的回饋是**變暗**（0930）：白色的按鈕再調亮也還是白色，看不出按到
- 護理端常駐總覽螢幕整夜開著，**要能調暗但仍看得清楚**；不得用降低字級的方式節省空間

| 平板尚未佈建 | 注意 | `wrench`（扳手） | 護理端平板標籤（床位格與平板框） |

- **病人端「紅色只給求助」這一條不變**。病人端的求助區是唯一的警示色；其他狀態用注意色與完成色
- 護理端的緊急床位格有**一次性**的進場強調（三次閃爍後停住），之後靠紅框與八角形持續示警（4.4）

### 4.8 拖曳（0926 新增，只用於護理端簡易版）

**病人端仍然禁止拖曳**（2.3 禁止清單不變）：躺著、一隻手在打針的人，拖曳是所有操作裡最難的一種。

護理端簡易版的拖曳用 **dnd-kit**，四條規則：

1. **每一個拖曳都有不拖曳的替代做法**：點來源（選起來，框線加粗）、再點目的地。份量同樣是一步。按 Esc 或再點一次來源取消
2. **鍵盤也做得到**：Tab 移到來源、空白鍵拿起、方向鍵移動、空白鍵放下
3. **拖錯了一步復原**：每個動作完成後畫面下緣出現一條「復原」列，8 秒內按一下即還原；不可逆的動作（下機、結案）改成延後 8 秒才送出
4. **放得下的地方才亮**：拿起一張病人卡，只有空床與候床、下機區會亮；拿起平板，只有床位與停用區會亮。放不下的地方不亮，放了也沒反應

### 4.9 字型（0926 新增）

**Noto Sans TC 自帶**，不依賴平板內建字型（實作規格書 4.12「開工前已拍板」）。
完整字檔 12MB，`scripts/subset-font.py` 只留 Big5 常用字、符號與程式碼裡實際出現的字（約 5,900 字、1.6MB），轉成 woff2 放進兩端的 `src/assets/fonts/`。
放在 `src` 底下而不是 `public`：樣式表以相對路徑引用它，建置時成為產物，病人端的 Service Worker 因此自動把它列進離線快取。
授權是 SIL Open Font License 1.1，全文隨字檔放在同一個目錄。介面或預設內容新增了罕用字要重跑一次，否則那個字改用系統字型畫出來。

### 4.10 目標解析度（0926 新增；0930 平板確定為 10 吋）

**0930 院方確定平板是 10 吋**（[Q-33](../requirements/open-questions.md#q-33-目標平板的型號與解析度) 部分回覆），型號與面板解析度仍待回覆。
尺寸確定就夠決定 CSS 尺寸：外殼會隱藏狀態列與導覽列（《[平板管控方案](mdm-offline-plan.md)》），
而 10 吋 Android 平板不論面板是 1280×800、1920×1200 還是 2560×1600，瀏覽器看到的**短邊都是 800 CSS 像素**：

| 方向 | CSS 像素 | 用來驗什麼 |
|---|---|---|
| 橫式 | 1280 × 800（5:3 的面板約 1334 × 800） | 病人端首頁與每一個任務畫面不出現捲軸 |
| 直式 | 800 × 1280 | 同上 |
| 護理站 | 1366 × 768 與 1920 × 1080 | 簡易版床位圖不出現捲軸 |

**病人端的字級、選項圖示與邊距以畫面短邊（`vmin`）縮放**（0930）：同一台平板橫放直放字一樣大——
手指與眼睛沒有變，字不該因為轉向就小一號（0929 以前以寬度縮放，直放時每一級都掉到 4.2 的下限）。
每一項在短邊 800 時剛好等於上限，比 10 吋小的畫面才往下限縮；**下限就是 4.2 那張表，不因此改變**。
求助區高度是例外，仍依畫面高度：它吃的是高度，直放時求助按鈕大一點沒有壞處。

10 吋平板上 1 CSS 像素約 0.17 公釐：觸控目標 64px 約 11 公釐，內文 24px 約 4 公釐。

**型號一確定，就在那台平板上重跑一次截圖驗收**（迭代 14.5 分冊 `x150`）。短邊若不是 800（少數面板的縮放倍率不同），回來改這張表，不要硬塞。

## 5. 這份基準怎麼被持續使用

**這是最重要的一節，因為一次性的改版三個月後就會被稀釋回去。**

| 時機 | 要做什麼 |
|---|---|
| 動任何介面程式碼**之前** | 讀 `.claude/skills/hd-uiux/`（本文件的可執行版） |
| 新增一個畫面或元件 | 對照第 4 章的設計系統；找不到對應的語彙就**先在這裡補一條**，不要就地發明 |
| 改動導覽列 | 對照 3.3 的三條規則；主列超過 7 項要說明理由 |
| 提交前 | 跑介面檢查腳本（技術識別字串、對比度、觸控目標尺寸） |
| 每次迭代結束 | 用瀏覽器自動化在兩種畫面尺寸下截圖，人工看一遍 |

**允許使用外部設計知識庫與前端視覺工具**（使用者 2026-09-19 授權），但有兩條界線：

1. **不得引入任何指向院外網域的執行期相依**——字型、圖示、樣式表、分析工具一律自帶（FR-S07、零院外連線盤點會擋）
2. 外部設計系統只當**參考**，實際採用的語彙一律落在第 4 章，不直接把整套元件庫搬進來

## 6. 驗收清單

介面改動要能逐條回答，不能只說「看起來比較好了」。

### 6.1 病人端

- [ ] 求助區在所有畫面、所有狀態下的位置與尺寸完全相同
- [ ] 輪播進行中，**沒有任何一個字落在求助區裡**
- [ ] 內文字級 ≥ 20px，輪播主文 ≥ 40px
- [ ] 所有可點擊目標 ≥ 64×64px，間距 ≥ 12px
- [ ] 沒有長按、滑動、雙擊
- [ ] 每一個用顏色表示的狀態都有文字
- [ ] 內文對比度 ≥ 7:1
- [ ] 單手在畫面下半部可完成所有主線操作
- [ ] 夜間模式只改亮度，不改版面與字級；**（0930）白底上調暗的區塊真的變暗了**
- [ ] **（0926）首頁只有三區**，沒有其他常駐入口；首頁與輪播都看不到姓名與病歷號
- [ ] **（0926）首頁與每一個任務畫面在 4.10 的兩個尺寸下都沒有捲軸**；（0930）兩個方向的字一樣大
- [ ] **（0930）病人端是白底**，沒有另做深色區塊；按下去看得出按到
- [ ] **（0926）任務畫面一題一頁**，閒置逾時自動回首頁；按回首頁後任務變成基本資訊區的圖示

### 6.2 護理端

- [ ] 主列項次 ≤ 7，順序與 3.3 一致
- [ ] 待處理通報在進畫面 2 秒內看得出來
- [ ] **畫面上找不到任何需求編號、待確認編號、迭代編號、資料表或欄位名、列舉常數、開關識別字**
- [ ] 所有狀態都是中文
- [ ] 關閉的功能完全不出現入口，後端端點也擋下
- [ ] 破壞性動作有確認，日常動作沒有
- [ ] 內文對比度 ≥ 4.5:1
- [ ] **（0926）每次登入預設簡易版**，一次點選切到專業版；專業版的畫面沒有被改動
- [ ] **（0926）簡易版的九項任務每一項都是一個動作**，都有不拖曳的替代做法，都能一步復原（「接緊急通報」除外，理由見 3.5）
- [ ] **（0926）簡易版與專業版做同一件事，稽核軌跡與結構化欄位完全相同**
- [ ] **（0926）簡易版在護理站的解析度下沒有捲軸**
- [ ] **（0929）斷線時專業版每一頁與簡易版都看得到閃爍紅框與紅底橫幅**；剛開頁面、換頁時不會誤閃；簡易版出現橫幅時仍沒有捲軸
- [ ] **（0929）專業版一次湧入很多則求助時，上緣最多三條加一列「還有幾則」**，緊急的排前面，頁面本身一直看得到

### 6.3 兩端共通

- [ ] 沒有任何指向院外網域的資源（字型、圖示、樣式表）
- [ ] 尊重作業系統的減少動態效果設定
- [ ] 在目標裝置的實際尺寸下截圖檢查過，不是只在開發機的視窗裡看過
- [ ] **（0926）灰階截圖時每一種狀態仍分得出來**（4.7）
- [ ] **（0926）用到的圖示都在 4.6 登記過**，沒有一個圖示代表兩件事；字型與圖示都自帶

## 6.4 這份基準落在程式碼的哪裡（0919 迭代 8 實作後補）

前面五章講的是規則，這一節講**規則現在住在哪一個檔案裡**。
下一個要改介面的人從這張表開始看，比從任何一章開始都快。

| 規則 | 落在哪 | 怎麼被擋住 |
|---|---|---|
| 4.1 顏色、4.2 字級、4.3 觸控 | `apps/patient-pwa/src/design-tokens.css`、`apps/nurse-pwa/src/design-tokens.css` | **色碼與字級只能出現在這兩個檔裡。** 樣式表裡出現任何裸色碼（含 `rgba()`）`npm run check:ui:design` 就會紅 |
| 4.1 對比度門檻 | 同上＋`scripts/check-ui-design.mjs` 的搭配清單 | 腳本直接從色碼算 WCAG 對比度。**半透明的顏色算不出來，所以一律不准用** |
| 2.2 求助區的版面契約 | `apps/patient-pwa/src/PatientShell.tsx` | `npm run verify:iteration8` 驗結構：兩列的 grid、輪播是 `absolute` 不是 `fixed`、求助按鈕規則裡沒有 `z-index`、求助按鈕只有一個出處 |
| N-5 破壞性動作的阻力 | `apps/nurse-pwa/src/components.tsx` 的 `ConfirmButton` | 驗收腳本檢查它有被用到，而且沒有人改用瀏覽器的 `confirm` |
| 4.5 常駐總覽螢幕的字級 | `--wall-scale`（護理端語彙） | 整面牆的字級相對這一個倍率。觀看距離確定後（Q-10）改一個數字 |
| 2.4 首頁三區、任務畫面（0926） | `apps/patient-pwa/src/HomeScreen.tsx`、`TaskFrame.tsx`、`tasks/` | `npm run verify:iteration14`：首頁只有三區、首頁沒有姓名與病歷號、每個任務畫面包在 `TaskFrame` 裡 |
| 3.5 簡易版工作台（0926） | `apps/nurse-pwa/src/simple/` | `verify:iteration14`：簡易版只呼叫專業版已有的端點（另加三支加法端點）、每個拖曳有替代做法、有復原列 |
| 4.6 圖示（0926） | `scripts/sync-icons.mjs` 的登記表 → 兩端的 `src/icon-data.ts` | `verify:iteration14`：畫面用到的每個圖示名稱都在登記表裡；登記表沒有重複 |
| 4.7 狀態色配形狀（0926） | 兩端的 `src/status-visuals.ts` | `verify:iteration14`：每一種狀態都同時有語意色與圖示 |
| 4.9 字型（0926） | `src/assets/fonts/NotoSansTC-subset.woff2`、`scripts/subset-font.py` | `check:egress` 擋院外字型；`verify:iteration14` 確認兩端的 `@font-face` 指向自帶檔案 |
| 4.4 斷線示警（0929） | 護理端 `src/connection-status.tsx`；樣式在 `styles.css` 的 `.conn-lost`、`workbench.css` 的 `.wb:has(> .conn-lost)` | `verify:iteration14-3`：專業版掛在主框架、簡易版獨占一列、紅框不擋點擊、剛開頁面不誤報 |
| 4.1 病人端白底、4.5 夜間調暗要有底色、4.10 以短邊縮放（0930） | `apps/patient-pwa/src/design-tokens.css`；`styles.css` 的 `.carousel` 與 `:active` | `verify:iteration14-5`：背景白色、語意色過 7:1、輪播有底色、按下變暗、字級以 `vmin` 縮放且下限不變、求助區契約不變 |
| 4.4 求助橫幅有上限（0929） | 護理端 `src/App.tsx` 的 `HelpRequestAlerts` 與 `MAX_ALERT_TOASTS` | `verify:iteration14-4`：最多三條、其餘收成一列、緊急在前、快照裡找不到的不拿掉 |

**新增一組顏色或一個字級時，順序是**：先在本文第 4 章補一條語彙 → 再加到 `design-tokens.css` →
若它是「某個字疊在某個底色上」，**回到 `scripts/check-ui-design.mjs` 的搭配清單補一列**。
漏掉第三步，那組顏色就沒有被任何人檢查過——腳本推不出來誰疊在誰上面，那份清單是人維護的契約。

**兩個刻意的決定，寫下來免得日後被當成疏漏：**

1. **斷線時的紅框仍然持續閃爍**（常駐總覽螢幕；0929 起護理端每一個畫面），雖然 4.4 說「不得持續閃爍到令人疲勞」。
   那一條講的是**新通報的進場強調**——那種東西閃久了會被學會忽略。斷線不是通報，
   是一個持續存在的故障狀態：它一直在，示警就應該一直在。畫面上另有一條「連線中斷」的橫幅，
   顏色不是唯一線索；開了「減少動態效果」時閃爍會停，紅框仍然留著。
2. **病人端未指派時沒有求助區。** 平板還沒指派給任何人，求助送出去護理站不知道是誰按的。
   那個畫面改成直接寫「需要護理人員時，請按床邊的呼叫鈴」——
   **一顆按了會失敗的按鈕，比沒有按鈕更糟。**
