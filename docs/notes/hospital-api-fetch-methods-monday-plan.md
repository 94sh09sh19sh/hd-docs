### 3.1 抓取腳本的規格

**只用 Python 標準函式庫**（`urllib`、`json`、`hashlib`），不需要 `pip install`，主機上有 Python 3.8 以上就能跑。

| 事 | 做法 |
|---|---|
| 執行 | `--once` 跑一輪就結束，交給工作排程器每 3 分鐘叫一次；另有 `--config <路徑>`、`--dry-run`（只印會寫幾列，不寫檔） |
| 設定檔 | `config.json`：端點、輸出資料夾、狀態檔路徑、去重狀態資料夾、逾時、重試次數、`encrypt`（預設 `false`）、`dedup`（預設 `"row"`） |
| 抓什麼 | `?date=今天`，「今天」固定以 +08:00 算 |
| 逾時與重試 | 30 秒、3 次 |
| 同時只跑一次 | 鎖檔；上一輪還沒結束就跳過這一輪，狀態檔記「跳過」 |
| 去 `<meta>` | 從第一個 `{` 開始解析；解析不出 `data_list` 就算失敗 |
| 逐列去重 | 每一列算一個鍵＝病歷號＋透析開始時間＋紀錄時間，存「鍵 → 整列內容的雜湊」；鍵沒看過或內容變了才寫。狀態存在 `state/YYYY-MM-DD.json`，**只存雜湊，鍵也雜湊過，不存病歷號明文**；保留 3 天 |
| 寫什麼 | 這一輪有要寫的列：附加 `Date: YYYY-MM-DD HH:MM:SS` 一行＋`{"data_list":[只有新的或變了的列]}` 一行；沒有就不寫。兩行組成一個字串一次寫入、`flush` |
| 編碼 | UTF-8，換行固定 `\n` |
| 失敗時 | 留底不寫；狀態檔寫失敗原因；結束碼非零 |
| 狀態檔 | 每輪覆寫：最後一次嘗試的時間、結果（成功／失敗／跳過）、失敗原因、回應列數、寫入列數、最後一次成功的時間；不放病人資料。先寫暫存檔再改名，讀的人不會讀到一半 |
| 主控台 | 只印時間、結果、列數；不印網址、不印回應 |
| 加密 | 保留斗六版加密病歷號與姓名的寫法，`encrypt: false` 時不執行；金鑰不進 repo |
| 不做的 | 不寫 `temp.csv`、不丟任何列、不碰 IDH 的資料庫 |
| 排程 | `install-task.ps1`：用目前登入的帳號建工作，「只在使用者登入時執行」、每 3 分鐘、上一個還在跑就不再開新的；`uninstall-task.ps1` 移除。頻率是參數，之後學長自己改 |

**留底格式要學長在現場點頭（之二 W-6）**：上面的寫法保留「`Date:` 一行＋JSON 一行」，`refetch_from_txt.py` 照樣讀得回來，差別是 JSON 裡只有新的或變了的列。學長說的「逐行寫入」如果是指一列寫一行，現場改設定 `line_format` 即可，兩種都先寫好。

### 3.2 轉碼工具的規格

| 事 | 做法 |
|---|---|
| 預設 | 預演：列出每個檔的大小、行數、`Date:` 段數、判斷出的編碼（先試 UTF-8，不行再試 cp950，都不行列出第一個出錯的行號），不改任何檔 |
| 實轉 | `--apply`：先把整個資料夾的 txt 複製到 `_backup_YYYYMMDD-HHMM\`，再逐檔轉成 UTF-8；已經是 UTF-8 的跳過 |
| 比對 | 轉完每個檔的行數、`Date:` 段數要與原檔相同，每一行 JSON 要解析得出來（`API_script` 版的混寫行另外列出，不算失敗） |
| 還原 | `--restore <備份資料夾>` |
| 不做的 | 不刪備份、不改檔名；混到兩種編碼的檔不轉，列出來由學長決定 |

### 3.3 測試

| # | 情境 | 期待 |
|---|---|---|
| 1 | 模擬院方 API 正常回應，連跑兩輪、中間資料沒變 | 第一輪寫整天的列，第二輪不寫；狀態檔兩輪都更新 |
| 2 | 第二輪前改了一位病人的一筆 | 只寫那一列 |
| 3 | 姓名有罕用字 | 正常寫入 UTF-8 |
| 4 | 模擬服務關掉 | 重試 3 次後失敗、留底沒有多一行、狀態檔寫原因、結束碼非零 |
| 5 | 回應是空的 `data_list` | 不寫留底，狀態檔「成功、0 列」 |
| 6 | 回應不是 JSON | 失敗，留底不動 |
| 7 | 兩支同時跑 | 第二支跳過 |
| 8 | 跨日 | 新的一天用新的去重狀態；跨月寫進新的 `YYYY-MM.txt` |
| 9 | 讀回來 | 用成大版 `refetch_from_txt.py` 的讀法與本系統的 `parseHospitalApiBody()` 都解析得出寫出的每一段 |

## 6. 本系統要跟著改的（第二次進院前，不是週一）

- 逐列去重後，一段 `Date:` 不再是當天的完整清單。讀檔模式要讀**當天所有段落**，同一個鍵以後面的為準，合起來才是完整清單；《之一》第 7.1 節「讀什麼」改掉
- 資料多舊改看狀態檔的「最後一次成功的時間」，不看最後一段的 `Date:`；《之一》第 7.4 節第 10 項的誤報顧慮因此沒有了
- 讀檔模式的設定要多一個狀態檔路徑
