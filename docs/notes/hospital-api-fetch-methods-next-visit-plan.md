# 院方 API 的四種抓取方式之四：下一次進院的工作規劃（兩支都跑起來）

版本：v0.1　文件狀態：草案（2026-11-09 開立）　適用讀者：使用者本人、接手做事的 agent、負責 IDH 系統的學長

上層文件：《[院方 API 的四種抓取方式](hospital-api-fetch-methods.md)》　前一份：《[之三：1109 進院前的工作規劃](hospital-api-fetch-methods-monday-plan.md)》　問題清單：《[之二](hospital-api-fetch-methods-questions.md)》

## 摘要

- **1109 晚上使用者定：下一次進院的目標是兩支都跑起來**——透析清單（`hd-hospital-fetch`，從第十九冊 B-16 接）與檢驗資料（學長的 `hb_online_v2.py`＋`collector_common.py`）
- 檢驗資料那支照透析清單同一套：GitHub Release 帶進主機、跑 `.py`、工作排程器 `--once`，但**另開一個排程、每 6 小時**，輸出在 `Hb_API_Fetch`，兩支不共用設定（第 1 節）
- 兩支的差別在第 2 節：學長的程式沒有狀態檔、靠工作目錄找相對路徑、`pythonw` 跑時什麼都不印、現有月份檔有一行壞掉就整支停
- 進院前要有答案的 `hb` 題目 6 題：A-5、I-2、I-6、I-8、I-10、I-11（第 3 節），都改排到《之二》的「B-16 前」
- 進院前開發端要做 T-7～T-14（第 4 節）；**學長的程式原樣不改**，要加的東西都包在外面
- 現場先做完透析清單 B-16～B-19，再做 `hb`；時間從 30 分鐘改成約 60 分鐘（第 5 節）
- **`hb` 卡住不擋透析清單**：端點沒答、主機上已有程式在跑、現有月份檔有壞行，`hb` 就延後，透析清單照做（第 6 節）

## 1. 目標與已定的事

| 事 | 結論 | 來源 |
|---|---|---|
| 目標 | 兩支都裝好排程、各跑過一輪、學長知道怎麼停與怎麼看 | 使用者 1109 晚上 |
| 優先順序 | 透析清單先；`hb` 卡住就只做透析清單 | 本文件第 6 節 |
| 帶進主機 | 同一次 Release 下載，`hb` 的檔收在 `hd-hospital-fetch` 的 `hb/` 底下（待學長同意，I-11） | 照第十九冊 B-09～B-11 |
| 跑法 | `.py`（主機有 Python 3.13）；`hb` 只用標準函式庫，不必裝套件 | 之二之一 W-3；《[參考調查之一](idh-reference-survey-api-script.md)》第 4.1 節 |
| 排程 | 兩個工作：`hd-hospital-fetch`（每 3 分鐘）、`hd-hospital-fetch-hb`（每 360 分鐘）；都用醫師的帳號、只在使用者登入時執行 | 之三第 1 節；`hb` 設定的預設 6 小時 |
| 輸出 | 透析清單寫指定資料夾（`IDH_interface`）；`hb` 寫 `Hb_API_Fetch\hospital_dataset`，兩邊不交叉 | Drive 的 `API raw data address.docx` |
| 本系統 | 這一次照舊不動；讀檔模式（含讀 `hb`）排之後 | 之三第 6 節 |

## 2. 兩支的差別（照同一套做時要補的）

| 地方 | 透析清單 `fetch_dialysis.py` | 檢驗資料 `hb_online_v2.py` | 要補什麼 |
|---|---|---|---|
| 誰的程式 | 開發端寫的，有測試 | 學長的，原樣不改 | 收進 repo 時註明來源，不動內容（T-7） |
| 路徑 | 設定檔給絕對路徑 | `patients_file`、`output_dir` 是相對路徑，跟著**工作目錄**走 | 排程的工作目錄設成 `Hb_API_Fetch`，或設定改填絕對路徑（T-9） |
| 狀態檔 | 每輪寫 `fetch-status.json` | 沒有；只用 `print` 印計數 | 包一層寫狀態檔（T-8） |
| 用 `pythonw` 跑 | 有寫檔，看得到結果 | `print` 全部消失，失敗了也看不出來 | 同上 |
| 一輪失敗 | 狀態檔記失敗，下一輪照跑 | 任何一位查詢失敗就回結束碼 1；不重試 | 排程器看結束碼；狀態檔記錯誤種類與次數 |
| 舊資料 | 接著寫既有月份檔 | 啟動時讀完全部 `raw_txt`，**任何一行壞掉就整支停** | 裝之前先只讀檢查一遍（T-10） |
| 同時寫 | 鎖檔，上一輪沒完不開新的 | 沒有鎖；程式註明不能兩支同寫一個資料夾 | 排程設「上一輪還在跑就不開新的」；先查主機上有沒有別的程式在寫（I-10） |
| 位址 | 院方透析清單，`http` | 範本是佔位字；預設只打 `https`，`http` 要設 `allow_approved_http` | I-8 |
| 要查誰 | 全中心一次查 | `active_patients.txt` 逐一查 | I-2；沒人維護就從透析清單產生（T-11） |

## 4. 進院前開發端的工作（另開對話照這張表做）

編號接《之三》的 T-1～T-6。都在 `hd-hospital-fetch` 做，v0 只改文件。

| # | 做什麼 | 估時 | 完成條件 |
|---|---|---|---|
| T-7 | `hb/` 底下原樣放 `hb_online_v2.py`、`collector_common.py`，`config.json` 改名 `config.example.json`（位址照舊是佔位字）；README 寫來源、取得日期、雜湊，註明「學長的程式，不改內容」 | 0.3 時 | 三個檔與 Drive 原檔逐位元相同（設定檔除外） |
| T-8 | 包一層 `hb/run_hb.py`：切到設定檔所在的資料夾、呼叫 `hb_online_v2.poll`、每輪寫 `hb-status.json`（開始與結束時間、新／重複／空／錯誤四個數、錯誤種類，不寫病歷號與網址），並保留最近幾輪的紀錄檔 | 1 時 | 用假的院方回應跑：成功、空、錯誤、多出欄位四種都寫對狀態檔 |
| T-9 | 排程：`install-task.ps1` 加參數（工作名稱、要跑的程式、工作目錄），或另寫 `install-hb-task.ps1`；預設工作名稱 `hd-hospital-fetch-hb`、每 360 分鐘、上一輪還在跑就不開新的；移除腳本一起改 | 0.5 時 | 開發機裝上、手動觸發一次、狀態檔有更新、移除乾淨；透析清單那個工作不受影響 |
| T-10 | `hb/check_hb_store.py`：**只讀**檢查既有 `raw_txt`，每個月份檔印行數與壞掉的行號，不印內容；另寫「預演」的做法：把 `hospital_dataset` 複製一份、設定的 `output_dir` 指過去跑一輪 | 0.5 時 | 用自己造的好檔、壞檔、多欄位檔各跑一次，結果對 |
| T-11 | 病人清單（I-2 答「沒人維護」才做）：`hb/make_patients.py` 從透析清單當月 txt 取出病歷號寫成 `active_patients.txt`，只印人數 | 0.5 時 | 用模擬院方 API 的留底產生，人數對、沒有重複 |
| T-12 | 測試：本機起一個假的檢驗 API（Python 內建的 HTTP 伺服器），涵蓋一筆、空、陣列、包成字串、ID 不符、日期超出、多出欄位、逾時 | 1 時 | 全過；`allow_approved_http` 只在測試設定設成 `true` |
| T-13 | 部署手冊第十九冊之三（`hb` 的安裝，新手版），編號 `BH-xx`；現場排在第十九冊 B-19 之後、B-20 之前；出錯對照可併進第十九冊之一 | 1 時 | 每一步有指令、會看到什麼、斷點；與 T-8～T-11 的輸出原文一致 |
| T-14 | 出新版 Release（`.py`；`.exe` 用不用由學長定）；文件收尾 | 0.3 時 | Release 頁有新版；`docs:check` 通過、推上公開站 |

## 5. 現場順序（約 60 分鐘）

1. 透析清單：第十九冊之二第 6.3 節——B-16 前的檢查一、檢查二，K-1 查清；B-16 跑一輪 → B-17 裝排程 → B-18 看三輪 → B-19 教學長（約 30 分鐘）
2. `hb` 看現況（I-10）：`Hb_API_Fetch` 底下有哪些檔（只列檔名與時間）、工作排程器與正在跑的 Python 有沒有它；有在跑就停在這裡、只記錄
3. 帶進：新版 Release 已在 B-09 一起下載的話直接用；沒有就照 B-09～B-11 再下載一次
4. 填設定：端點、`active_patients.txt`（或 T-11 產生）；設定檔不進 repo
5. 只讀檢查既有 `raw_txt`（T-10）；有壞行就停，備份交學長
6. 預演：輸出指到 `hospital_dataset` 的複本跑一輪，看狀態檔的四個數
7. 正式跑一輪 → 裝排程 → 手動觸發一次看狀態檔（等不了 6 小時）→ 教學長怎麼停、怎麼看狀態檔
8. 第十九冊 B-20 記錄（兩支都寫進私人紀錄）→ B-21 收工

## 6. 什麼情況 `hb` 延後、透析清單照做

- I-8 沒答，主機上也找不到實際設定
- I-10 查出主機上已有程式在寫 `Hb_API_Fetch`（不新裝，記下來問學長）
- 既有 `raw_txt` 有壞行（第 5 節第 5 步）
- 端點是 `http`，學長沒說可以
- 透析清單做完已超過約 40 分鐘，或學長要先走

學長不能陪同：兩支都延後，跟之三第 5 節一樣。

## 7. 對本系統

- 這一次不動本系統
- 之後讀 `hb`：讀 `raw_txt` 不讀 CSV、同名異欄、同一天改過的檢驗有兩筆，見《[參考調查之一](idh-reference-survey-api-script.md)》第 8 節；讀檔模式的設定要多 `hb` 的資料夾與狀態檔路徑
