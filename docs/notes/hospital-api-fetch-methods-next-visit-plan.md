## 2. 兩支的差別（照同一套做時要補的）

| 地方 | 透析清單 `fetch_dialysis.py` | 檢驗資料 `hb_online_v2.py` | 要補什麼 |
|---|---|---|---|
| 誰的程式 | 開發端寫的，有測試 | 學長的，原樣不改 | 收進 repo 時註明來源，不動內容（T-7） |
| 路徑 | 設定檔給絕對路徑 | `patients_file`、`output_dir` 是相對路徑，跟著**工作目錄**走 | 排程的工作目錄設成 `Hb_API_Fetch`，或設定改填絕對路徑（T-9） |
| 狀態檔 | 每輪寫 `fetch-status.json` | 沒有；只用 `print` 印計數 | 包一層寫狀態檔（T-8） |
| 用 `pythonw` 跑 | 有寫檔，看得到結果 | `print` 全部消失，失敗了也看不出來 | 同上 |
| 一輪失敗 | 狀態檔記失敗，下一輪照跑 | 任何一位查詢失敗就回結束碼 1；不重試 | 排程器看結束碼；狀態檔記錯誤種類與次數 |
| 舊資料 | 接著寫既有月份檔 | 啟動時讀完全部 `raw_txt`，**任何一行壞掉就整支停** | 裝之前先只讀檢查一遍（T-10） |
| 同時寫 | 鎖檔，上一輪沒完不開新的 | 沒有鎖；程式註明不能兩支同寫一個資料夾 | 排程設「上一輪還在跑就不開新的」；先查主機上有沒有別的程式在寫（I-10） |
| 位址 | 院方透析清單，`http` | 範本是佔位字；預設只打 `https`，`http` 要設 `allow_approved_http` | I-8 |
| 要查誰 | 全中心一次查 | `active_patients.txt` 逐一查 | I-2；沒人維護就從透析清單產生（T-11） |

## 5. 現場順序（約 60 分鐘）

第 2～7 步的指令在《[第十九冊之三](../deployment/19c-hb-fetch.md)》BH-03～BH-10。

1. 透析清單：第十九冊之二第 6.3 節——B-16 前的檢查一、檢查二，K-1 查清；B-16 跑一輪 → B-17 裝排程 → B-18 看三輪 → B-19 教學長（約 30 分鐘）
2. `hb` 看現況與盤點（約 10 分鐘）：照《第十九冊之一》3.1 查檔案時間、排程與正在跑的 Python（I-10），再照 3.2～3.3 跑盤點、抄第 5 段結論；有程式在跑就停在這裡、只記錄（盤點照樣可以跑）
3. 帶進：InPrivate 視窗下載 v0.2.0，只把 `hb\` 搬進腳本資料夾（主機上已是 v0.1.0，不重新解壓整包）
4. 填設定：端點、`active_patients.txt`（或 T-11 產生）；設定檔不進 repo
5. 只讀檢查既有 `raw_txt`（T-10）；**一律要做**：第 2 步盤點的「壞」只看是不是 JSON，比學長的程式寬鬆（1110 改）。有壞行就停，備份交學長
6. 預演：輸出指到 `hospital_dataset` 的複本跑一輪，看狀態檔的四個數
7. 正式跑一輪 → 裝排程 → 手動觸發一次看狀態檔（等不了 6 小時）→ 教學長怎麼停、怎麼看狀態檔
