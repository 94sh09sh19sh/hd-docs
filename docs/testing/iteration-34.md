# 迭代 34 手動測試 — 「其他」按住說話與語音閘道

> 《[完整手動測試手冊](manual-test-guide.md)》的分冊之一，對應《實作規格書》4.34 節。共用的環境準備、啟動與疑難排解都在主手冊，這一冊只寫迭代 34 的部分。設計與理由在《[緊急求助的語音說明](../notes/emergency-voice-help.md)》第 3.2、5 節；需求是 SRS FR-P20、FR-N22（病人的那一半）、FR-S20。一點送出與倒數在《[迭代 33 分冊](iteration-33.md)》，按住說話接在它後面。**對真實病人錄音前要有院內辨識端點（Q-07）、同意書格式（Q-41 第 2 題）**；之前只在開發機、對開發團隊照腳本錄的語料測。

## 摘要

這一冊驗六件事（項次 `ar1`～`ar20`，自動化另跑 `npm run verify:iteration34` 與 `npm run verify:iteration34:api`）：

- 開關「按住說話」預設關；語音閘道不通、「求助倒數自動送出」沒開都開不起來
- 錄音同意：護理端排班與指派頁登記、撤回；沒登記的病人看不到按鈕、後端也不收
- 病人端：「其他」兩類送出之後說明框旁多「按住說話」；按住才錄、放開送出，最長 30 秒、最多 3 次，碰一下不算；轉寫進說明框、護理端同一則換字
- 原音一秒一段存在資料庫、轉寫完不刪；稽核不寫轉寫的字
- 語音閘道：不含模型、不開埠、只連院內辨識端點；故障時求助照常
- 外殼 0.4.0：只對病人端放行麥克風、不放行鏡頭（APK 要重建、平板要重裝）

| 標記 | 意思 |
|---|---|
| 📱 **病人端** | 已配給今天透析中病人的平板（或開發機瀏覽器 1280×800 開病人端，瀏覽器會問麥克風）；`npm run demo:patient` 最快 |
| 🖥 **護理端** | 以系統管理者登入；錄音同意在專業版「排班與指派」最下面 |
| 🛠 **開發機** | 遷移 `iteration34_push_to_talk`（`npm run prisma:deploy -w @hd/api`，後端要先關）；`.env` 設 `SPEECH_GATEWAY_URL`；看資料表用 SQLite 檢視工具 |

## §34.1 語音閘道與開關

- [ ] `ar1` **［開發機］** 🛠 在 `services/speech-gateway` 建映像檔（`docker compose --profile ai build speech-gateway`）。 → 建置最後一步印「自我測試通過」；映像檔裡沒有任何模型檔與推論套件。
- [ ] `ar2` **［開發機］** 🛠 設定目錄放 `speech-gateway/config.yaml`（照 `config.example.yaml`），`base_url` 填一個公開網址。 → 閘道 `/health` 回 503「設定有誤」：只准院內位址（送的是可識別的原音）。改回院內位址後恢復。
- [ ] `ar3` **［護理端］** 🖥 系統管理 → 功能開關。 → 「病人端畫面」那一組多一列「按住說話」，預設關閉；開啟條件寫語音閘道健康檢查與「求助倒數自動送出」兩件事；畫面上沒有識別字與需求編號。
- [ ] `ar4` **［護理端］** 🖥 `SPEECH_GATEWAY_URL` 空白（或閘道停掉）時開「按住說話」。 → 開不起來，說明寫「語音閘道健康檢查未通過」與原因（哪一個辨識端點不通）；記一筆「開關切換遭拒」。
- [ ] `ar5` **［護理端］** 🖥 語音閘道通、但「求助倒數自動送出」關著時開。 → 開不起來，說明寫要先開倒數。兩者都成立才開得起來。

## §34.2 錄音同意

- [ ] `ar6` **［護理端］** 🖥 開關開著，專業版「排班與指派」。 → 最下面多一張「錄音同意（按住說話）」：選病人、簽同意書的時間（預設現在）、同意書編號（選填）、「登記同意」；底下列出已登記的病人與登記人。開關關著時整張不出現。
- [ ] `ar7` **［病人端］** 📱 病人**沒有**登記時按「我需要協助」→「身體其他地方不舒服」。 → 送出之後說明框旁**沒有**「按住說話」，說明框照舊可以打字。
- [ ] `ar8` **［護理端］** 🖥 登記這位病人。 → 「已登記」；稽核軌跡多一筆「登記病人的錄音同意」，寫簽的時間與同意書編號。再登記一次被擋下（已經登記過了）。
- [ ] `ar9` **［護理端］** 🖥 選已登記的病人按「登記撤回」。 → 跳確認，寫明撤回之後平板不再出現按鈕、已收下的照同意書處理；確定後記一筆稽核。病人平板下一次更新首頁按鈕就不見。

## §34.3 按住說話

- [ ] `ar10` **［病人端］** 📱 已登記的病人點「身體其他地方不舒服」。 → 立刻送出（「已經通知護理站」）；說明框右邊一顆大按鈕「按住說話」（麥克風圖示）；1280×800 不捲動。點「頭暈」這類不是「其他」的類別**沒有**這顆按鈕；「其他，請有人過來一下」也有。
- [ ] `ar11` **［病人端］** 📱 按住按鈕說「左邊肩膀很痛」再放開。 → 按著的時候按鈕變深綠實底、字換成「正在聽，說完就放開」，**沒有聲音、不閃**；放開後底下一句「正在把你說的寫下來」，幾秒後轉寫出現在說明框，不必再按送出。
- [ ] `ar12` **［護理端］** 🖥 看緊急通報頁與頂端橫幅。 → 同一則的附註換成轉寫的字，沒有多一則、沒有重響；稽核「病人在平板上改了求助」寫附註。
- [ ] `ar13` **［病人端］** 📱 只點一下按鈕就放開。 → 底下寫「要一直按著說話，說完再放開」；**不算次數**。
- [ ] `ar14` **［病人端］** 📱 按住不說話（或只有背景聲）再放開。 → 「沒有聽清楚，可以再按住說一次，或用打的」，說明框不動，算一次。說滿三次之後按鈕變灰、寫「已經說過三次了，還要補充請用打的」。按住超過 30 秒自動當成放開。
- [ ] `ar15` **［病人端］** 📱 把語音閘道停掉再按住說話。 → 「現在沒辦法寫下來，請用打的；護理師已經在過來的路上」；求助本身照常、護理端照常示警。

## §34.4 原音與稽核

- [ ] `ar16` **［開發機］** 🛠 看 `help_voice_recordings`、`help_voice_chunks`、`help_voice_segments`。 → 每按一次一列（狀態：已轉寫、沒有聽到說話、太短、轉寫失敗），原音一秒一段 BLOB（每段最多 32000 位元組）、**每一種狀態的原音都留著**；轉寫的句子在 segments。稽核「病人在『其他』按住說話」只寫第幾次、幾秒、結果與採用的模型，**不寫轉寫的字**。資料取出的假名化級裡原音換成代號（直接識別）。

## §34.5 外殼與平板實機

- [ ] `ar17` **［病人端］** 📱 舊外殼（0.3.0）的平板。 → 不出現「按住說話」（說明框照舊可以打字），其他都正常。
- [ ] `ar18` **［病人端］** 📱 換上外殼 0.4.0 的 APK（1124 已打 `v0.4.0`、契約仍是第 1 版，`shell.pin` 已改釘）。 → 第一次開啟跳一次麥克風權限，護理師按允許；之後病人按住說話不再跳任何系統框；網頁要鏡頭一律被拒。長者實際按住、說台語與華語各試一次，看得懂按著的樣子、知道要放開。

## §34.6 辨識的準度與自動化驗收

- [ ] `ar19` **［開發機］** 🛠 院內辨識端點（或實驗室 3090 上的 whisper.cpp，1124 使用者定先在那裡量，1124 學長同意）接上之後，辨識端點要開 VAD 選項，照《語音說明》第 6 節的腳本錄語料（台語、華語、混著講、小聲、背景有機器聲）。 → 台語與華語分開記：靜音與雜音段生出句子 0 次、詞庫用語有沒有出現、每一次放開到字出現幾秒。**這一項要人與端點，開發機的假閘道不算**。
- [ ] `ar20` **［開發機］** 🛠 跑 `npm run verify:iteration34`（不需要後端，八步：數字與轉寫怎麼接、外殼版本、開關與首頁欄位、病人端畫面與自帶字型、後端、語音閘道與 compose、外殼原始碼、匯出登記與既有檢查）與 `npm run verify:iteration34:api`（要 Prisma，不需要開發機的後端，八步：開啟條件、錄音同意、只收「其他」、一次完整的按住說話、重送放開、碰一下與沒有說話、閘道故障與次數、格式與撤回）。 → 兩支都全部通過。
