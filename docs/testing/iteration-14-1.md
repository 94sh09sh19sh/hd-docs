# 迭代 14.1 手動測試 — 日期時差與平板佈建

> 《[完整手動測試手冊](manual-test-guide.md)》的分冊之一，對應《實作規格書》4.12.1 節與《[迭代 14.1 修正紀錄](../notes/iteration-14-1-fixes.md)》。
> 共用的環境準備、啟動與疑難排解都在主手冊，這一冊只寫迭代 14.1 的部分。
> 操作端色籤（**護理端**／**病人端**／**終端機**／**資料庫**）的意思見主手冊 §00。
> 項次接著迭代 14 分冊編（`x57`～`x84`），兩冊合起來是迭代 14 的完整紀錄。

> **1006（迭代 17.1）起**：`x67` 的「遠端鎖定／解除鎖定」改在專業版系統管理的「平板停用」做，按鈕叫「停用／解除停用」（《[迭代 17.1 分冊](iteration-17-1.md)》§17.1.4）；要驗的「後端重新啟動後平板停得了、解得開」不變。

**這一冊驗五件事**：凌晨時各畫面講的是同一天、開發環境不必手動佈建、後端重新啟動後平板不會卡住、註冊平板後可以掃 QR code 佈建、簡易版看得出哪台平板尚未佈建。

| 標記 | 意思 |
|---|---|
| 🖥 **開發機** | 平常的開發環境，`npm run dev` |
| 🌙 **凌晨** | 要在台北時間 00:00～08:00 之間做（UTC 還是前一天的那段時間） |
| 📱 **開發手機** | 裝了外殼 App 的開發手機或平板，主機是 `https://` 的環境（部署手冊第十二冊） |

## 14.1.1 · 凌晨時各畫面是同一天（修正紀錄 2.1）🖥 🌙

白天做不出這個症狀（UTC 與台北同一天）。白天只能跑 `x57`；`x58`～`x60` 要在凌晨做，或留給值夜班的人順手做。

- [ ] `x57` **［終端機］** 後端開著，`npm run verify:iteration14-1:api`，看步驟 1、2。
  → 台北 09-27 23:59:59 算成 09-27、09-28 00:00 與 01:17 算成 09-28；總覽的日期等於本機今天。
- [ ] `x58` **［護理端］** 🌙 專業版「即時總覽」看標題的日期。
  → 是**今天**，與「排班與指派」右上角的日期相同。修正前這裡會是昨天。
- [ ] `x59` **［護理端］** 🌙 簡易版把一位病人拖到一張有平板的床。
  → 病人立刻出現在那一床、從右側清單消失。修正前床位圖一片空、病人還在清單裡。
- [ ] `x60` **［護理端］** 🌙 切到專業版，分別看「即時總覽」「排班與指派」「裝置管理 → 目前有效綁定」。
  → 三個畫面都有 `x59` 那一筆，病人、平板、時段一致。

## 14.1.2 · 開發環境自動納管（修正紀錄 2.2）🖥

- [ ] `x61` **［終端機］** 停掉後端再 `npm run dev:api`，看啟動紀錄。
  → 若有尚未納管的平板，出現一行「開發環境：模擬 MDM 已自動納管 N 台平板（TB-…）。正式環境不會這樣做。」；都已納管時不出現。
- [ ] `x62` **［護理端］** 專業版「裝置管理」看平板清單。
  → TB-01～TB-15 全部是已納管，**沒有按過任何一次「MDM 註冊」**。
- [ ] `x63` **［護理端］** 簡易版把病人拖到放著 TB-03（或任何一台 seed 平板）的床。
  → 拖得上去。修正前除了手動納管過的那幾台，其他床都不會亮。
- [ ] `x64` **［護理端］** 專業版「稽核軌跡」篩「平板 MDM 註冊」。
  → 自動納管的每一台各一筆，操作者是系統，說明寫著「開發環境啟動時由模擬 MDM 自動納管」。
- [ ] `x65` **［終端機］** 以 `NODE_ENV=production` 啟動一次（或讀 `devices.service.ts` 的 `onApplicationBootstrap`）。
  → 正式環境**不會**自動納管；未納管的平板仍要到「裝置管理」逐台註冊。

## 14.1.3 · 後端重新啟動後平板不會卡住（修正紀錄 2.3）🖥

- [ ] `x66` **［終端機］** 停掉後端再啟動（開發時改任何一個後端檔案也會觸發）。
- [ ] `x67` **［護理端］** 專業版「裝置管理」對一台已納管、沒在服務病人的平板按「遠端鎖定」，再按「解除鎖定」。
  → 兩次都成功。修正前重新啟動之後會回「找不到」，而且再按「MDM 註冊」會被「已在 MDM 納管中」擋下。
- [ ] `x68` **［護理端］** 簡易版把一台平板拖到停用區，再從停用區拖回床上。
  → 兩個動作都成功（走的是鎖定與解除鎖定）。

## 14.1.4 · 佈建 QR code 與外殼 0.3.0（修正紀錄 2.4）🖥 📱

- [ ] `x69` **［護理端］** 專業版「裝置管理」註冊一台新平板。
  → 出現 QR code，右邊是說明與文字網址；網址內容與 QR code 相同。切到暗色模式，QR code 仍是**白底黑點**。
- [ ] `x70` **［終端機］** 開發者工具 → Network，重新註冊一次。
  → 畫 QR code 沒有任何對外請求（在瀏覽器裡自己畫）。
- [ ] `x71` **［病人端］** 🖥 用一般手機的相機掃開發機上的 QR code。
  → 手機瀏覽器開出病人端畫面、進入這台平板的身分（開發機是 `http://`，一般瀏覽器照樣能開；外殼 App 則會拒收，見 `x74`）。
- [ ] `x72` **［病人端］** 📱 清除外殼 App 的資料（或新裝 0.3.0），開啟。
  → 佈建畫面最上面有「掃描 QR code」；安裝時**沒有**要求相機權限。
- [ ] `x73` **［病人端］** 📱 按「掃描 QR code」，對準 `https://` 環境裡護理端剛註冊出來的 QR code。
  → 這時才問相機權限；掃到後三欄一次填好，跳出「已填入 TB-…，核對序號…」；**沒有自動儲存**，要按「儲存並啟動」才進病人端畫面。
- [ ] `x74` **［病人端］** 📱 掃開發機（`http://`）畫出來的 QR code。
  → 拒收，說明主機位址不是 `https://`，三欄不變。
- [ ] `x75` **［病人端］** 📱 掃一個無關的 QR code（例如商品條碼網址）。
  → 拒收，「這不是平板佈建用的 QR code」。
- [ ] `x76` **［病人端］** 📱 佈建完成後，系統設定 → 應用程式 → 透析照護平板 → 權限。
  → 只有相機（與原本的網路、開機啟動）；病人端網頁裡任何要用相機的操作都拿不到。
- [ ] `x77` **［護理端］** 另一台仍是外殼 0.2.0 的平板，看「裝置管理」的外殼版本欄。
  → 版本正常，**不是**「版本不相容」（契約沒有加版號）。

## 14.1.5 · 簡易版的「尚未佈建」圖示（修正紀錄 2.5）🖥

開發環境一啟動就全部自動納管（§14.1.2），要先自己弄出一台尚未佈建的平板。項次接在 `x80` 之後。

- [ ] `x81` **［護理端］** 專業版「裝置管理」對一台沒在服務病人的平板按「解除佈建」，切到簡易版。
  → 那台平板的標籤（在右側平板框或床位格上都一樣）多一個 🔧（`wrench`，注意色）；滑鼠停在上面或讀螢幕念得出「尚未佈建」。
- [ ] `x82` **［護理端］** 把它放上一張空床，再拿起病人框裡的一位病人。
  → 那一床**不亮**（尚未佈建不能指派），有 🔧 就看得出為什麼。
- [ ] `x83` **［護理端］** 回專業版對它按「登記佈建」（或停掉後端再啟動，讓開發環境自動納管）。
  → 🔧 消失，那一床可以放病人。
- [ ] `x84` **［護理端］** 灰階截圖（`document.body.style.filter = 'grayscale(1)'`），同時有尚未佈建、離線、跳出固定、版本過舊的平板。
  → 扳手與斜線 Wi-Fi、盾牌、向上箭頭形狀都不同（基準 4.7）。

  → 全綠（迭代 14 的既有驗收沒有被動到）。
