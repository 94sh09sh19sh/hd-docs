# 迭代 13 手動測試 — AI 閘道與實驗室實際測試

> 《[完整手動測試手冊](manual-test-guide.md)》的分冊之一，對應《實作規格書》4.11 節。
> 共用的環境準備、啟動與疑難排解都在主手冊，這一冊只寫迭代 13 的部分。
> 操作端色籤（**護理端**／**病人端**／**終端機**／**資料庫**）的意思見主手冊 §00；本冊另加 **［實驗室］**。

**這一冊驗的是「換推論端點、換模型，只改閘道的一個設定檔」。** 後端所有 AI 請求都經 `services/ai-gateway`，
閘道照實驗室規範以 LangChain 呼叫推論端點；推論端點、模型與參數全部寫在閘道的 `config.yaml`。
過渡期接實驗室的 GPU 伺服器（院外，只准合成資料），正式接院內 GPU API。
步驟見《[部署手冊](../deployment/index.md)》第十三冊，閘道本身見 repo 的 `services/ai-gateway/README.md`。

| 標記 | 意思 |
|---|---|
| 🖥 **開發機** | 平常的開發環境（有 Node.js 與 Docker），不需要實驗室 |
| 🔬 **實驗室** | 要連上實驗室的 GPU 伺服器（第十三冊第 1～4 節）。**校外連不到** |
| 🐳 **開發機，只用 Git 與 Docker** | 院內那一份閘道的部署實測 |

## 13.1 · 閘道本體（FR-S13）🖥

- [ ] `w1` **［終端機］** 看 `services/ai-gateway/`。
  → 有 `gateway/`（`app.py`、`config.py`、`llm_factory.py`、`selftest.py`）、`Dockerfile`、`requirements.txt`、兩份設定範本；**沒有 `config.yaml`**。
- [ ] `w2` **［終端機］** 開 `gateway/app.py`，找所有 `@app.` 開頭的行。
  → 只有 `GET /health`、`GET /v1/models`、`POST /v1/chat/completions` 三個。**沒有任何下載、刪除、載入模型的端點**。
- [ ] `w3` **［終端機］** 開 `gateway/llm_factory.py`。
  → `provider: ollama` 建 `ChatOllama`、`provider: openai` 建 `ChatOpenAI`——規範的兩種方法，其他 `provider` 一律拒絕。
- [ ] `w4` **［終端機］** 開 `requirements.txt`。
  → 每一行都是 `套件==版本`，含間接相依。
- [ ] `w5` **［終端機］** `docker build -t hd-ai-gateway-test services/ai-gateway`
  → 建置過程最後有七段自我測試、全部 ✓，印出 `全部通過`。**這一步不需要任何推論端點**。
- [ ] `w6` **［終端機］** `docker run --rm hd-ai-gateway-test id`
  → `uid=10001(gateway)`：不是 root。
- [ ] `w7` **［終端機］** `docker run --rm hd-ai-gateway-test env | Select-String TRACING`
  → `LANGSMITH_TRACING=false`、`LANGCHAIN_TRACING_V2=false`。
- [ ] `w8` **［終端機］** 在 `apps/` 與 `packages/` 裡搜 `langchain`、`ollama`。
  → 找不到（DEP-41：後端不直接連推論端點）。

## 13.3 · 實驗室：連線與個人容器（DEP-42）🔬

照第十三冊 Z-01～Z-10 做，每一步對照下列結果。

- [ ] `w15` **［終端機］** `ssh -G hd-lab`
  → 位址、埠、帳號都對；這些值只在 `%USERPROFILE%\.ssh\config` 與專案目錄外的 `lab.env` 裡。
- [ ] `w16` **［實驗室］** `ssh hd-lab` 登入後 `ls -la ~/.ssh`。
  → 與登入前一樣：**沒有為了省打密碼去改共用帳號的設定檔**。
- [ ] `w17` **［實驗室］** `ls <指定路徑>/<個人資料夾>/hd-ai-gateway`
  → 只有 Z-05 傳上去的五樣，加上 Z-07 的 `config.yaml`。
- [ ] `w18` **［實驗室］** 容器外 `ollama list`。
  → 列得出模型；挑定的那一個與備用的那一個記在開發機的筆記，**不寫進 repo**。
- [ ] `w19` **［實驗室］** `docker build` 的輸出結尾。
  → `全部通過`：套件裝在映像檔裡，沒有裝在實驗室伺服器上。
- [ ] `w20` **［實驗室］** `docker port <個人前綴>-hd-ai-gateway`
  → `8000/tcp -> 127.0.0.1:<閘道埠>`：**只綁本機介面**。（host 網路的起法沒有這一行，改看 `ss -ltn | grep <閘道埠>` 只有 `127.0.0.1`）
- [ ] `w21` **［實驗室］** 從實驗室伺服器的**另一個網路介面**連閘道：`curl -m 3 http://<伺服器的區網位址>:<閘道埠>/health`
  → 連不上。別人的機器連不到你的閘道。
- [ ] `w22` **［實驗室］** 容器內 `curl` Ollama 的 `/api/tags`（Z-08）。
  → 印出模型清單。**這是規範第 4 項「容器內以 curl 確認連線」**。
- [ ] `w23` **［實驗室］** 填好 `config.yaml` 存檔，**不重新啟動容器**，`docker exec … curl -s 127.0.0.1:8000/health`
  → `"status":"ok"`、`"model"` 是剛填的那一個。
- [ ] `w24` **［終端機］** 開著 Z-10 的轉送，`curl.exe -s http://127.0.0.1:18000/health`
  → 同一行 JSON，在開發機上看到。
