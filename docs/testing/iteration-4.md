# 迭代 4 手動測試 — AI 輔助內容與護理記錄

> 《[完整手動測試手冊](manual-test-guide.md)》的分冊之一，對應《實作規格書》v2.0 4.2 節。
> 共用的環境準備、啟動與疑難排解都在主手冊，這一冊只寫迭代 4 的部分。
> 操作端色籤（**護理端**／**病人端**／**終端機**／**資料庫**）的意思見主手冊 §00。

迭代 4 做的是「生成與草擬輔助」性質的 AI 功能：個人化衛教、離院衛教重點與適性測驗、情緒與滿意度回饋、事件記錄範本與 AI 草擬、透析適足性計算、SOP 查詢，全部在模擬供應者下就能完整操作。
**AI 不取代簽核，也不做臨床判斷**：每一處 AI 產出都要有非診斷標示，每一次呼叫都要留得下紀錄。

## 4.1 · AI 總開關關閉時

- [ ] `n1` **［護理端］** 開關關閉時，依序開啟「護理記錄」「衛教」「SOP 查詢」。
  → 看不到「AI 草擬初稿」按鈕與「產生 AI 衛教內容」區塊；SOP 查詢照樣可用，結果標示「僅列出文件原文」；事件記錄照樣能建立，並可從預填文字簽核。
- [ ] `n2` **［病人端］** 開關關閉時點「衛教與小測驗」。
  → 沒有任何 AI 內容，只有「開始小測驗」。
- [ ] `n28` **［終端機］** 開關關閉時，直接打 AI 產生類的端點（例如要求產生個人化衛教）。
  → **404**。介面不出現、端點一併消失，兩者是同一條規則（實作規格書 3.7）。
- [ ] `n29` **［護理端］** 把總開關開起來，重新整理護理端。
  → 上述按鈕與區塊出現，不必重新登入、不必重新部署。

## 4.2 · 護理記錄（FR-N04／N05）

- [ ] `n3` **［護理端］** 「護理記錄」選今天、選一位已排班的病人，範本選「病人不適處置」，只勾「頭暈」就按「建立事件記錄」。
  → 紅色橫幅「請勾選：處置、處置後情形」。
- [ ] `n4` **［護理端］** 補齊勾選，在補充說明寫一段文字後建立。
  → 下方出現一筆「草稿（未簽核）」，預填文字就是剛才的勾選內容，並注明「不經 AI」。
- [ ] `n5` **［護理端］** 按「AI 草擬初稿」。
  → 出現藍色進度列：「背景佇列排隊中…」→「AI 產生中…」，一兩秒後 AI 初稿出現，下方有「本內容由 AI 產生，僅供決策輔助，非診斷結果。AI 初稿只是起點…」標示。
- [ ] `n6` **［護理端］** 按「以 AI 初稿開始」，不修改直接「簽核送出」。
  → 狀態變「已簽核」，註明「原樣採用 AI 初稿」；草擬與簽核按鈕都消失。
- [ ] `n7` **［病人端］→［護理端］** 病人端送出一份症狀問卷（頭暈選「中等」），護理端在「依病人自報預填」按「以這份自報建立預填草稿」。
  → 預填文字寫著「病人於…在平板自述（PRE-DIALYSIS-v1）：頭暈（中等）…」。
- [ ] `n8` **［護理端］** 請 AI 草擬後，改按「以預填文字開始」並簽核。
  → 簽核成功，註明「未採用 AI 初稿」。
- [ ] `n30` **［護理端］** 拉開「範本」下拉式選單。
  → 五種：病人不適處置、管路或穿刺處滲血、機器警報處理、跌倒或滑倒、其他事件。每一種的必填欄位不同，換範本時下方勾選項跟著換。
- [ ] `n31` **［護理端］** 選一位**今天沒有排班**的病人。
  → 顯示「這一天沒有排班」，不能建立事件記錄 — 護理記錄掛在療程時段上，沒有療程就沒有可掛的地方。
- [ ] `n32` **［護理端］** 建立一筆記錄時把「事件時間」改成稍早的時刻，補充說明留空。
  → 建得起來（補充說明是選填，不取代上方勾選）；清單上同時看得到事件時間與建立時間。
- [ ] `n33` **［護理端］** 在已簽核的那一筆上找修改的入口。
  → 沒有。畫面明寫「簽核後不能再修改」，要更正只能另立一筆。
- [ ] `n34` **［護理端］** 在一份**未簽核**的草稿上連按兩次「請 AI 重新草擬」。
  → 每次都排進背景佇列並更新初稿，舊初稿被新的取代；預填文字始終不變 — 它是勾選內容組出來的，不受 AI 影響。
- [ ] `n35` **［護理端］** 以一般護理師 `N001` 做一次 `n4`～`n6`。
  → 全部可用。護理記錄的建立、草擬與簽核，護理師以上皆可（SRS 4.2）。

## 4.3 · 衛教與測驗（FR-P04／P07）

- [ ] `n9` **［護理端］** 「衛教」選一位已綁定平板的病人，主題選「血管通路（瘻管）照護」、語言選繁體中文，按「產生個人化衛教」。
  → 綠色提示「已排入背景佇列…」；下方內容卡片顯示進度，完成後狀態變「待護理師審閱」，內文下方有非診斷標示。
- [ ] `n10` **［病人端］** 同一位病人的平板點「衛教與小測驗」。
  → 還看不到剛才那一份（核可前病人看不到）。
- [ ] `n11` **［護理端］** 按「核可（病人端可見）」，病人端回主畫面再進衛教頁。
  → 看得到那一份，內文下方有「已經護理師審閱…僅供決策輔助，非診斷結果」。
- [ ] `n12` **［病人端］** 按「我看完了」。
  → 按鈕變「已看完 ✓」；護理端「病人端紀錄 → 衛教完成紀錄」出現這一筆。
- [ ] `n13` **［護理端］** 再產生一份，不填備註。
  → 「退回」按鈕不能按；填了原因後退回，狀態變「已退回」，病人端看不到。
- [ ] `n14` **［病人端］** 按「開始小測驗」，故意答錯第一題、其餘答對，送出。
  → 結果頁「答對 4／5 題」，答錯的那題列出您選的、正確答案與說明。
- [ ] `n15` **［護理端］→［病人端］** 護理端看知識點表，病人端再開一次小測驗。
  → 答錯那題的主題為「需加強」；病人端的第一題就是上次答錯的那一題。
- [ ] `n16` **［護理端］** 「離院衛教重點」選今天的班按產生，完成後核可。
  → 病人端看得到「今天回家要注意的事（日期）」。
- [ ] `n36` **［護理端］** 「內容語言」拉開來看，選「English（英語）」再產生一份。
  → 四種語言可選（繁體中文、英語、越南語、印尼語）；產出的內容是所選語言，非診斷標示照樣在。
- [ ] `n37` **［護理端］** 看頁面上方的病人摘要與「衛教主題（知識點）」表。
  → 顯示「透析史（本系統內）：共 N 次療程」與最早一次的日期；知識點表列出主題、狀態、已作答題數與最近作答時間，並註明「主題內任何一題最近一次答錯即列為需加強」。
- [ ] `n38` **［護理端］** 對**今天沒有排班**的病人按「離院衛教重點」。
  → 顯示「這位病人今天沒有排班，無法產生離院衛教重點」。離院重點依當天的自述症狀、求助紀錄與測驗結果整理，沒有當天的班就沒有依據。
- [ ] `n39` **［護理端］** 在「衛教完成紀錄」看 `n12` 那一筆。
  → 記得下病人讀完的時間與次數（同一份讀第二次會累加），這份資料之後是輪播第一層「衛教完成度」卡片的來源。
- [ ] `n40` **［病人端］** 換一台**沒有任何核可內容**的平板進「衛教與小測驗」。
  → 顯示「目前沒有護理師為您準備的衛教內容／可以先做小測驗，看看自己記得多少」，測驗照樣做得了。
- [ ] `n41` **［病人端］** 拔掉平板網路後進同一頁。
  → 「目前沒有網路連線，衛教內容與測驗暫時無法使用」。衛教不進離線佇列 — 症狀回報與求助才是不能漏的那兩件（見主手冊 §05）。
- [ ] `n42` **［病人端］** 做一次全部答對的測驗。
  → 結果頁顯示「全對」，沒有需要複習的題目；護理端「測驗作答」那一列也標「全對」。

## 4.4 · 心情與滿意度（FR-P08／N08）

- [ ] `n17` **［病人端］** 點「心情與滿意度」。
  → 5 題、每題 5 個選項；還沒答完時送出鍵顯示「請先回答每一題」。
- [ ] `n18` **［病人端］** 答完送出，回主畫面後再點一次。
  → 送出後顯示「謝謝您的回饋」；再進去顯示今天這次療程已經填過。
- [ ] `n19` **［護理端］** 「病人趨勢 → 心理社會趨勢」。
  → 列出這位病人，規則比對為「資料不足」；下方寫著「目前有 1 份回饋，至少需要 6 份…」並有非診斷標示。
- [ ] `n43` **［病人端］** 送出時「還有其他想說的嗎？」留白。
  → 送得出去，文字意見是選填。填了的話護理端在「這位病人的回饋」看得到原文。
- [ ] `n44` **［病人端］** 累積到 6 份以上回饋（可用不同療程或先前的資料），其中情緒相關題目都選低分。
  → **［護理端］** 該病人的「暫定規則比對」由「資料不足」變成「符合，供評估是否轉介社工」，並列出情緒相關題目平均與滿意度平均。**要不要轉介由護理師判斷，系統只呈現數值與事實。**
- [ ] `n45` **［病人端］** 回饋送出後，在平板上找有沒有任何分數、比對結果或建議。
  → **沒有**。病人端只有「謝謝您的回饋」，趨勢比對只出現在護理端。

## 4.5 · 透析適足性（FR-N07）

- [ ] `n20` **［護理端］** 以護理長或管理者到「臨床數值」，為同一位病人輸入同一次療程的五項：透析前 BUN `70`、透析後 BUN `20`、透析後體重 `60.0`、本次實際脫水量 `2500`、本次透析時間 `240`，資料時間都選今天稍早。
  → 整批寫入成功。
- [ ] `n21` **［護理端］** 「病人趨勢」的可計算數值組出現今天那一列，按「計算」。
  → 顯示 URR 71.4%、spKt/V 1.50；趨勢圖出現一個點，圖上沒有任何目標線或正常範圍。
- [ ] `n22` **［護理端］** 以一般護理師登入看同一頁。
  → 看得到結果與趨勢圖，但計算處顯示「由護理長或管理者計算」。
- [ ] `n46` **［護理端］** 只輸入其中四項，回到「病人趨勢」。
  → 那一天標「缺少數值」，「計算」按不下去，並指出還缺哪一項。**五項齊全（各取當天最新的現行版本）才算一組。**
- [ ] `n47` **［護理端］** 看計算結果下方的公式說明與「輸入值」欄。
  → 兩條公式與代入的數字都列出來，可以自己拿計算機驗一次；「輸入值」欄列出這次用到的五項與各自的資料時間。
- [ ] `n48` **［護理端］** 回「臨床數值」把透析後 BUN 改成 `18`（覆蓋並保留前一版），再回「病人趨勢」。
  → 先前那筆結果標「輸入值事後已被更正，這筆結果需重新確認」，**不會自己重算**。臨床數值改了就該有人回頭看一眼。
- [ ] `n49` **［護理端］** 若院方也提供 Kt/V，趨勢圖看兩條線。
  → 「本系統計算的 spKt/V」與「院方提供的 Kt/V」分開呈現，不合併、不互相取代。
- [ ] `n50` **［護理端］** 「稽核軌跡」查最近紀錄。
  → 查得到「透析適足性計算」，內容含 URR 與 spKt/V 的值。

## 4.6 · SOP 查詢（FR-N09）

- [ ] `n23` **［護理端］** 「SOP 查詢」問「透析中低血壓怎麼處置？」。
  → 綠色「已依文件回答」；回答含 `[S1]` 這類出處標記並附非診斷標示；下方列出原文段落，被引用的標「回答引用」，全部標「虛構範例」。
- [ ] `n24` **［護理端］** 問「員工停車證怎麼申請？」。
  → 藍色「查無資料：目前收錄的文件中沒有與此問題相符的段落…」，沒有任何回答文字；「系統管理 → 模型供應者」的 AI 呼叫紀錄沒有因這次查詢多出一筆。
- [ ] `n51` **［護理端］** 把 AI 總開關關掉再問 `n23` 那一題。
  → 照樣查得到段落，但結果標「僅列出文件原文」，沒有 AI 整理過的回答。**查文件不需要模型，整理才需要。**
- [ ] `n52` **［護理端］** 以一般護理師 `N001` 用 SOP 查詢。
  → 可用。這是護理師的日常工具（`sop:query`）。

## 4.7 · 背景佇列、AI 呼叫紀錄與稽核

- [ ] `n25` **［護理端］** 在「衛教」連續快速按四次「產生個人化衛教」，同時用平板送一份症狀問卷。
  → 每次按下都立即回應，卡片分別顯示「前面還有 N 件」並依序完成；總覽照常即時出現那份問卷。
- [ ] `n26` **［終端機］** 產生途中停掉後端再啟動。
  → 那一件顯示「AI 產生失敗：後端重新啟動，工作中斷，請重新送出」，卡片狀態「產生失敗」。
- [ ] `n27` **［護理端］** 「系統管理 → 模型供應者」與「稽核軌跡」。
  → AI 呼叫紀錄的「功能」欄出現個人化衛教、離院衛教重點、護理記錄草擬、SOP 查詢回答；稽核軌跡查得到要求產生、核可、簽核、SOP 查詢等事件。
- [ ] `n53` **［護理端］** 隨便挑一份 AI 產出的衛教內容，回頭在呼叫紀錄裡找到對應的那一列。
  → 找得到，且該列有供應者、模型、耗時與是否去識別化。**每一筆 AI 產出都追得回一次呼叫**（4.2 驗收 2）。
- [ ] `n54` **［護理端］** 看背景工作執行期間的臨床寫入。
  → `n25` 那次的症狀問卷、求助與護理記錄都照常即時完成 — 生成類工作不得阻擋請求，也不在資料庫交易中呼叫模型。
- [ ] `n55` **［護理端］** 逐一看 AI 產出出現的每一個位置。
  → 護理記錄初稿、個人化衛教、離院衛教重點、SOP 回答、心理社會趨勢，五處都有「僅供決策輔助，非診斷結果」的標示（4.2 驗收 7）。

## 4.8 · 切換供應者與真實病人資料閘門

這兩條驗收標準（4.2 驗收 3、4）驗的是迭代 3 建起來的模型供應者介面層，測試步驟寫在《[迭代 3 分冊](iteration-3.md)》：

| 要驗的事 | 去哪裡 |
|---|---|
| 切換 provider 只改設定，不改任何一行程式 | 迭代 3 分冊 `l28` |
| `LLM_PROVIDER=lab` 時，帶真實病人資料標記的請求被擋下並留紀錄 | 迭代 3 分冊 `l26`、`l29` |

那兩步**不需要真的有一台模型伺服器**：`LLM_ENDPOINT` 填一個本機不會有人接的位址即可，擋下的判斷發生在呼叫端點之前。實際的值與注意事項寫在迭代 3 分冊 `l28`。
