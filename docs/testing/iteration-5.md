# 迭代 5 手動測試 — 求助處理紀錄、班表與成效基準

> 《[完整手動測試手冊](manual-test-guide.md)》的分冊之一，對應《實作規格書》v2.0 4.3 節。
> 共用的環境準備、啟動與疑難排解都在主手冊，這一冊只寫迭代 5 的部分。
> 操作端色籤（**護理端**／**病人端**／**終端機**／**資料庫**）的意思見主手冊 §00。

**FR-N10 求助處理結果登記、FR-N11 再發標示、FR-P12 結果回饋、FR-M01／M02 班表與床位分配、FR-M04 勞動條件硬性檢查、FR-M07 成效基準建檔。**

這個迭代有三處「暫定值，日後改設定即可」（Q-13、Q-14、Q-15）：求助處理的選項清單、勞動條件的各項上下限、護理師班別與起訖時間。**驗這一冊時請順便驗那三處真的改得動** — 外部答覆回來的那天，要改的應該是設定畫面上的幾個欄位，不是程式碼。

## 5.1 · 求助結案的結構化登記（FR-N10）

- [ ] `o1` **［病人端］** 按「我需要協助」，選「身體不舒服」＋「不太舒服，請盡快過來」送出。
  → 護理端「緊急通報」出現這一筆。
- [ ] `o2` **［護理端］** 在那筆通報上按「結案登記」，**只填自由文字補充**，不選處理方式與處理結果。
  → 「送出結案登記」是**灰的按不下去**，下方提示「處理方式與處理結果為必填，只填自由文字無法結案」。
- [ ] `o3` **［護理端］** 選「現場處置」＋「已解決」，不勾需追蹤，送出。
  → 該筆從待處理清單消失，畫面顯示「已結案 ⋯⋯ 的求助」。
- [ ] `o4` **［護理端］** 「稽核軌跡」查最近的「緊急通報處理完成」。
  → 內容包含「處理完成：現場處置／已解決」，不是只有「處理完成」四個字。
- [ ] `o51` **［護理端］** 拉開「處理方式」與「處理結果」兩個下拉式選單，數一下預設值。
  → 處理方式八項（現場處置、通知醫師、調整機台設定、提供物品、協助如廁、心理安撫、轉介、其他）、處理結果六項（已解決、部分緩解、持續觀察、升級處理、病人自行取消、無法處理）。這是待護理部確認的暫定清單（Q-13）。

## 5.2 · 到達床邊時間與確認時間分開（FR-N10）

**這一節是本迭代最容易被誤會成「多此一舉」的設計，請照順序走完再判斷。**

- [ ] `o5` **［病人端］** 再按一次求助（任意類型）。
- [ ] `o6` **［護理端］** 按「我接手」，**先不要**按「我到床邊了」。
  → 卡片上那一行時間變成「確認 ⋯⋯（N 分）・到床邊 尚未登記」。
- [ ] `o7` **［護理端］** 等一分鐘以上，再按「我到床邊了」。
  → 提示「已登記到達床邊（按下求助後 N 分鐘）」，該行同時顯示確認與到床邊兩個時間，**兩個數字不一樣**。
- [ ] `o8` **［護理端］** 再按一次「我到床邊了」。
  → 按鈕已經不在了。若以 API 直接再送一次，回應 400「此通報已於 ⋯⋯ 登記過到達床邊時間」。
- [ ] `o9` **［病人端］** 再按一次求助，**護理端直接按「我到床邊了」**，跳過「我接手」。
  → 兩個時間都會被填上，但確認時間是**按下的當下**、到達時間是登記的時間，兩者不互相填補。

> 為什麼要這樣：只記確認時間的話，一旦這個數字被拿去看反應速度，
> 最省力的做法就會變成「先按確認再慢慢走過去」。分開記錄讓這種情況在資料上看得出來。

## 5.3 · 後續追蹤（FR-N10）

- [ ] `o10` **［護理端］** 結案時勾「需後續追蹤」但**不填追蹤事項**。
  → 送出按鈕是灰的。
- [ ] `o11` **［護理端］** 填入追蹤事項後送出。
  → 頁面下方「待追蹤事項」多一筆，顯示內容、建立者與時間。
- [ ] `o12` **［護理端］** 按「已完成」。
  → 該筆從清單消失；稽核軌跡查得到「結束求助後續追蹤事項」。
- [ ] `o52` **［護理端］** 再建一筆追蹤事項，這次按「取消追蹤」而不是「已完成」。
  → 提示「已取消追蹤事項」，該筆一樣離開清單，但記的是取消而不是完成。**沒做的事不要記成做完了。**

## 5.4 · 近期再發標示（FR-N11）

- [ ] `o13` **［病人端］** 用**同一位病人**再按一次求助，類型選**與 `o3` 相同**的「身體不舒服」。
  → 護理端該筆卡片出現紅色「近期再發」標籤，並顯示
  「近 72 小時內同類別已發生 N 次，前次（⋯⋯）處理方式：現場處置／已解決」。
- [ ] `o14` **［病人端］** 再按一次，這次選**不同類型**（例如「需要上廁所」）。
  → 那一筆**沒有**「近期再發」標籤 — 比對的是同一類別，不是同一個病人。
- [ ] `o15` **［護理端］** 「系統管理 → 營運參數與選項清單」把「求助再發判定期間」改成 `1` 小時（理由必填），回到緊急通報。
  → `o13` 那筆的再發提示消失或次數變少，文字也跟著變成「近 1 小時內」。**改完記得改回 72。**

## 5.5 · 結果回饋給病人（FR-P12）

- [ ] `o16` **［病人端］** 求助被結案之後回到主畫面。
  → 出現「**已處理**：現場處置，已解決」與時間。
- [ ] `o17` **［病人端］** 確認畫面上**沒有**護理師填的自由文字補充，也沒有護理師的工作 ID。
  → 補充是寫給護理端看的，不會出現在病床旁的畫面上。

## 5.6 · 選項清單可設定（Q-13）

- [ ] `o18` **［護理端］** 護理長帳號進「系統管理 → 營運參數與選項清單」，在下方新增一個處理方式（例如代號 `TEST_OPTION`、文字「測試選項」）。
  → 立刻出現在清單中。
- [ ] `o19` **［護理端］** 回到「緊急通報」，開一筆通報的結案登記。
  → 「處理方式」下拉式選單裡有「測試選項」。**沒有重新部署、沒有改程式。**
- [ ] `o20` **［護理端］** 回設定頁把它「停用」，再回結案畫面。
  → 選單中不再出現，但先前用它結案的紀錄仍顯示原本的文字。
- [ ] `o21` **［護理端］** 以**一般護理師**帳號進「系統管理」。
  → 看不到「營運參數與選項清單」分頁；直接打 API 回應 403。
- [ ] `o53` **［護理端］** 新增選項時代號填 `test option`（小寫加空白）。
  → 被擋下，代號限大寫英數與底線。
- [ ] `o54` **［護理端］** 改一個營運參數但**理由留空**。
  → 送不出去；填了理由送出後，稽核軌跡查得到「調整營運參數」與「調整求助處理選項清單」，內容含前後值與理由。

## 5.7 · 班表建立與檢視（FR-M01）

- [ ] `o22` **［護理端］** 護理長進「班表」，在「手動建立班次」選一位護理師、選一個**下個月**的日期、班別「白班」，按「排定」。
  → 表格出現那一筆，時數 8.0 小時、時間 07:00～15:00、來源「手動」。
- [ ] `o23` **［護理端］** 同一人、同一天、同一班別再排一次。
  → 紅字「⋯⋯ 已排班」（HTTP 409）。
- [ ] `o24` **［護理端］** 以**一般護理師**帳號進「班表」。
  → 標題是「我的班表」，只看得到自己的班，沒有「手動建立班次」與「班表檔案匯入」兩張卡片。
  提示文字說明「班表屬班次層級資料，一般護理師只看得到自己的班」。
- [ ] `o55` **［護理端］** 拉開「班別」下拉式選單，各排一筆看預設時間。
  → 三種：白班 07:00～15:00、小夜班 15:00～23:00、大夜班 23:00～07:00（跨日）。起訖時間留白時就採該班別的預設值（Q-15 確認前為暫定值，改在「系統管理」）。
- [ ] `o56` **［護理端］** 排一筆並填「備註」（例如「代 N003」）。
  → 備註跟著顯示在該列上，匯入進來的班次也一樣看得到。
- [ ] `o57` **［護理端］** 用上方的期間查詢切到**上個月**。
  → 只列出該期間的班；沒有資料時顯示「這段期間沒有班表」，不是空白畫面。
- [ ] `o58` **［護理端］** 在一筆未來的班次按「取消班次」。
  → 該列轉為**已取消**而不是從表上消失；稽核軌跡查得到「取消護理師班次」。

## 5.8 · 勞動條件硬性檢查（FR-M04）

**這是本冊唯一「擋下儲存」的功能，請確認它擋得住、而且說得清楚。**

- [ ] `o25` **［護理端］** 在 `o22` 那個人、那一天，再排一個「小夜班」（15:00～23:00）。
  → **紅色區塊列出違反的條文**，至少包含
  「【兩班之間最短間隔】兩班之間至少須間隔 11 小時，這一筆與前後班次只隔 0 小時。」
  以及「【單日工時上限】⋯⋯當日工時上限為 12 小時，加上這一筆會到 16 小時。」
- [ ] `o26` **［護理端］** 重新整理班表。
  → **那一筆沒有存進去**，當天仍只有白班一筆。
- [ ] `o27` **［護理端］** 排一個起訖時間 07:00～20:00 的班次。
  → 被擋下，訊息指出「【單一班次連續工時上限】⋯⋯上限為 12 小時，這一筆為 13 小時。」
- [ ] `o28` **［護理端］** 連續排七天同一人的白班（第七天會被擋）。
  → 第七筆被擋，訊息指出「【連續出勤日數上限】⋯⋯上限為 6 日⋯⋯會變成連續 7 日。」
- [ ] `o29` **［護理端］** 「稽核軌跡」篩選最近的紀錄。
  → 查得到「班次儲存遭擋下：違反勞動條件」，且內容寫出違反的是哪一條。**被擋下的嘗試也要留紀錄。**
- [ ] `o30` **［護理端］** 「系統管理 → 營運參數」把「兩班之間最短間隔」改成 `1` 小時（理由必填），再做一次 `o25`。
  → 這次存得進去（其他規則若仍違反則仍會被擋）。**確認完請改回 11。**
- [ ] `o59` **［護理端］** 在連續七日之內湊到超過 46 小時（例如六天各 8 小時再加一筆長班）。
  → 被擋下，訊息指出「【連續七日工時上限】⋯⋯上限為 46 小時⋯⋯」。這是第五條規則，前面四項各測過了，這一條也要走一次。
- [ ] `o60` **［護理端］** 排一筆大夜班（23:00～07:00），隔天早上再排白班（07:00～15:00）。
  → 被擋下：跨日班次的結束時間算在隔天，兩班之間的間隔是 0 小時。**跨日不是漏洞。**

## 5.9 · 班表檔案匯入（FR-M01）

- [ ] `o31` **［護理端］** 在「班表檔案匯入」的文字框貼上下面內容，把 `N001`／`N002` 換成實際存在的工作 ID，日期改成未來的空日期：

  ```
  工作ID,日期,班別,開始時間,結束時間,負責床位,備註
  N001,2026-10-21,MORNING,07:00,15:00,A01 A02 A03,
  N002,2026-10-21,AFTERNOON,15:00,23:00,A04 A05,代班
  ```

  → 「已匯入 2 筆班次（批次 NS-⋯⋯）」，表格出現兩列，來源顯示「匯入 NS-⋯⋯」，負責床位已帶入。
- [ ] `o32` **［護理端］** 再貼一次同樣內容，但把第二列的工作 ID 改成不存在的值。
  → 紅色區塊逐列列出原因（「第 3 列・工作ID：查無工作 ID ⋯⋯」），且**第一列也沒有被寫入** — 全有或全無。
- [ ] `o33` **［護理端］** 貼一份第一列不是標頭的內容。
  → 「第 1 列・header：第一列必須是標頭⋯⋯」。
- [ ] `o34` **［護理端］** 貼一份會讓同一人連上兩班、中間間隔不足的內容。
  → 整批被拒，逐列指出違反的勞動條件。**同一份檔案裡的其他班次也會被算進去**，不會因為分一次匯入就躲過檢查。
- [ ] `o61` **［護理端］** 貼一份班別欄寫成中文「白班」的內容。
  → 被擋下並指出是哪一列哪一欄；班別欄要用識別字 `MORNING`／`AFTERNOON`／`NIGHT`。
- [ ] `o62` **［護理端］** 匯入成功後看稽核軌跡。
  → 查得到「班表檔案匯入」與（`o32`、`o34` 那兩次）「班表檔案匯入遭拒（整批未寫入）」，含批次編號與筆數。

## 5.10 · 當班床位分配（FR-M02）

- [ ] `o35` **［護理端］** 在某一筆班次按「分配床位」，輸入 `A01 A02 A03`，儲存。
  → 「負責床位」欄顯示 A01、A02、A03。
- [ ] `o36` **［護理端］** 在**同一天同一班別**的另一位護理師身上，指派 `A01`。
  → 紅字「下列床位在同一班次已指派給別人：A01（⋯⋯）」（HTTP 409）。
- [ ] `o37` **［護理端］** 把第一位的床位改成只剩 `A02`，再重做 `o36`。
  → 這次成功 — 床位是整組取代，不是累加。
- [ ] `o63` **［護理端］** 把某一筆的床位清空後儲存。
  → 該列顯示「未分配」；同一床位這時可以指派給同班別的其他人。
- [ ] `o64` **［護理端］** 「稽核軌跡」查最近紀錄。
  → 查得到「指定當班負責床位」，含班次與床位清單。

## 5.11 · 調班申請

- [ ] `o38` **［護理端］** 以**一般護理師**帳號，在自己的班次按「申請調班」，類型「請假」，填理由送出。
  → 「調班申請已送出，等待護理長核示」，下方「調班申請」卡片出現一筆「待核示」。
- [ ] `o39` **［護理端］** 護理長帳號在同一張卡片按「核准」。
  → 狀態變「已核准」，該班次在班表上轉為**已取消**（不是消失）。
- [ ] `o40` **［護理端］** 稽核軌跡確認。
  → 查得到「提出調班申請」「核示調班申請」與「取消護理師班次」三筆。
- [ ] `o41` **［護理端］** 一般護理師嘗試對**別人的**班次提出申請（以 API 直接送）。
  → 403「只能對自己的班次提出調班申請」。
- [ ] `o65` **［護理端］** 再送一筆申請，這次護理長按「駁回」。
  → 狀態變「已駁回」，**該班次原封不動留在班表上**；稽核軌跡一樣查得到「核示調班申請」。
- [ ] `o66` **［護理端］** 以一般護理師看「調班申請」卡片。
  → 只看得到自己送出的那幾筆，核准與駁回按鈕不出現。

## 5.12 · 成效基準建檔（FR-M07）

- [ ] `o42` **［護理端］** 進「成效基準」。
  → 標題顯示「尚缺 5 項」，五條指標全部標「尚未建檔」，並出現紅色時效性警告
  「成效基準只能在系統正式啟用前取得⋯⋯」。
- [ ] `o43` **［護理端］** 在「病人按鈴到護理師到床邊」按「建檔」，數值填 `4.2`、樣本 `60`、來源「現場實測」、背書者填一個名字，送出。
  → 「已建檔 ⋯⋯＝4.2 分鐘」，該列不再是「尚未建檔」，標題變成「尚缺 4 項」。
- [ ] `o44` **［護理端］** 再建一次同一指標，數值 `4.0`。
  → 「現行基準」顯示 4.0；下方「歷次建檔紀錄」中 4.2 那筆標「已被取代」，**沒有被刪掉**。
- [ ] `o45` **［護理端］** 建一筆數值 `4.25`（超過該指標的一位小數）。
  → 紅字「⋯⋯數值格式不正確，最多 1 位小數」。**不會自作主張四捨五入。**
- [ ] `o46` **［護理端］** 建一筆但**背書者留空**。
  → 送出按鈕是灰的。沒有出處的數字禁不起追問。
- [ ] `o47` **［護理端］** 建一筆來源選「估算（非實測）」。
  → 送出前出現藍色提示「估算值不是實測值⋯⋯」；存檔後該筆帶「估算」標籤，
  上方另出現「有 N 項只有估算值。引用到文件或簡報時必須標明是估算」。
- [ ] `o48` **［護理端］** 以**一般護理師**帳號進「成效基準」。
  → 看得到內容（單位聚合資料），但每一列都沒有「建檔」按鈕；直接打 API 回應 403。
- [ ] `o67` **［護理端］** 看五條指標各自的說明欄。
  → 每一條都寫出量測方式與建議樣本數：按鈴到床邊（現場碼表抽測，60 次）、一次事件記錄從動筆到完成（護理師自記起訖，20 次）、每班口頭重複衛教次數（觀察記錄，3 班）、交班時查找病人資訊的耗時（觀察記錄，3 次）、紙本記錄事後補寫的比例（自陳問卷，1 份），以及上線後要拿什麼資料來對照。
- [ ] `o68` **［護理端］** 找「新增指標」的入口。
  → 沒有。護理長可以**停用**其中幾條，但不能自行新增 — 新增的指標沒有上線後的對照來源，會變成擺著沒用的數字。

## 5.13 · 自動化驗收

- [ ] `o49` **［終端機］** `npm run verify:iteration5`
  → 15 個步驟全部 ✓，最後顯示「驗收結果：全部通過 ✓」。
