# 迭代 30 手動測試 — 連點成畫之二：標準模式與跟自己比

> 《[完整手動測試手冊](manual-test-guide.md)》的分冊之一，對應《實作規格書》4.30 節。共用的環境準備、啟動與疑難排解都在主手冊，這一冊只寫迭代 30 的部分。設計與理由在《[透析中的遊戲化之五](../notes/dialysis-gamification-benchmark.md)》第 3.2、4、6.2 節；迭代 29 的遊戲模式在《[迭代 29 分冊](iteration-29.md)》。**1028 只做了 A 部分**：B 部分（圓、方交替）等清冊 Q-40 第 2 題，這一冊不驗 B。

## 摘要

這一冊驗五件事（項次 `an1`～`an16`，自動化另跑 `npm run verify:iteration30` 與 `npm run verify:iteration30:api`）：

- 每月第一盤、而且在透析開始後第 30～90 分鐘開始的那一盤是標準模式，病人看到的和平常一樣
- 標準模式的版面只從固定的 A1～A4 四套輪流；不合條件的照樣能玩，記成平常那一種
- 五個新的營運參數（時窗起止、練習幾盤、取前幾次、至少幾次）在系統管理改得到
- 護理端病人詳細資訊的狀態評估彙整多一段「連點成畫標準版」：前 10 盤只當練習、只寫事實、附施測時點
- 沒玩到的月份就沒有，不補、不提醒

| 標記 | 意思 |
|---|---|
| 📱 **病人端** | 平板或開發機瀏覽器 1280×800；`npm run demo:patient` 最快（要先 `PUT /feature-flags/CONNECT_DOTS` 開啟） |
| 🖥 **護理端** | 以系統管理者登入專業版；要「連點成畫」「狀態評估彙整（護理端顯示）」兩個開關都開著 |
| 🛠 **開發機** | 迭代 30 沒有遷移；看資料表用 SQLite 檢視工具開開發資料庫的 `connect_dots_boards` |

## §30.1 營運參數

- [ ] `an1` **［護理端］** 🖥 系統管理 → 營運參數與選項清單。 → 多五列：「連點成畫標準版：透析開始後第幾分鐘起」30、「……止」90、「連點成畫：前幾盤只當練習」10、「自己過去的中位數取前幾次標準版」6、「過去至少要幾次標準版」3；每一列有依據；畫面上沒有識別字。
- [ ] `an2` **［護理端］** 把「前幾盤只當練習」改成 9。 → 擋下（下限 10）；改成 12 可以，理由進稽核軌跡。改回 10。

## §30.2 標準模式那一盤

- [ ] `an3` **［病人端］** 📱 透析開始後第 30～90 分鐘、這個月這位病人還沒玩過標準版時，開始一盤。 → 畫面與平常一模一樣：同一個開始畫面、同一句「照您自己的速度，從 1 開始照順序點 1、2、3，點完會看到一幅畫」；**沒有**邀請、提示、計時、「標準」字樣。
- [ ] `an4` **［開發機］** 🛠 看 `connect_dots_boards` 最新一列。 → `mode` 是 STANDARD、`layout_code` 是 A1（這位病人的第一次）、`session_minute` 在 30～90、`path_tenths` 在 757～762。
- [ ] `an5` **［病人端］** 點完，再開一盤。 → 版面是隨機的（和剛剛那盤不同）；🛠 這一列 `mode` 是 GAME、`layout_code` R1。這個月不會再有第二盤標準版。
- [ ] `an6` **［病人端］** 標準版點到一半拔網路，點完再接上。 → 斷線時照樣點得下去、點完揭圖；接上之後 🛠 那一列有 `completion_ms`，點的位置與伺服器判斷的一樣（`hit_count` 25）。
- [ ] `an7` **［病人端→開發機］** 換一位病人，在透析開始後第 30 分鐘以前開一盤。 → 🛠 `mode` 是 GAME、`layout_code` R1；過了第 30 分鐘再開一盤才是 STANDARD。
- [ ] `an8` **［病人端→開發機］** 同一位病人到下個月第一次在時窗裡開一盤（或在開發資料庫把上一盤標準版的 `started_at` 改到上個月再開）。 → 這一盤 `layout_code` 是 A2；第五次又回到 A1。
- [ ] `an9` **［開發機］** 🛠 改營運參數「止」比「起」小（例如起 60、止 30），在透析開始後第 45 分鐘開一盤。 → 記成 GAME（這個設定下沒有時窗）。改回 30、90。

## §30.3 護理端跟自己比

- [ ] `an10` **［護理端］** 🖥 選單 →「病人詳細資訊」→ 選 `an3` 那位病人（還在第 1～10 盤之內）。 → 「狀態評估彙整（遊戲資料）」那張卡多一段「連點成畫標準版」：只有一句「這個月的標準版是這位病人的第 N 盤；前 10 盤只當練習，不比較。」底下一句說明標準版是什麼。
- [ ] `an11` **［開發機→護理端］** 🛠 在開發資料庫替一位病人補前 6 個月各一筆 `mode` STANDARD、`board_no` 11 以上、點完的標準版（`verify:iteration30:api` 的步驟 4 是範本），這個月再點完一盤標準版，然後看這位病人的病人詳細資訊。 → 兩句：「〇月〇日的標準版（透析開始後第 N 分鐘開始）點完用了 X 秒，比自己前 6 次標準版的中位數（Y 秒）多／少 Z%。」「同一盤點錯 N 次，比……多／少 N 次。」差 30% 以上、2 次以上才在句尾標「（差距達設定幅度）」。
- [ ] `an12` **［護理端］** 看 `an11` 的字。 → 沒有「退化」「受損」「注意力」「建議」這類結論字眼、沒有紅色與警示的樣式、沒有常模與百分位；指標名稱是中文，沒有識別字。
- [ ] `an13` **［護理端］** 選一位這個月沒玩到標準版的病人。 → 只有一句「這個月還沒有標準版。」，沒有補做或提醒的按鈕。
- [ ] `an14` **［護理端］** 關掉「連點成畫」再看 `an11` 那位病人。 → 那一段不見（麻將那幾句照舊）；🛠 稽核軌跡「調閱狀態評估彙整（遊戲資料）」的說明在開著時多寫連點成畫標準版幾次、幾句。

## §30.4 給護理師看

- [ ] `an15` **［人］** 🖥 請護理師看時窗「透析開始後第 30～90 分鐘」。 → 記下這段時間量血壓、處置是否特別多，要不要改營運參數（之五第 8 節第 3 題）。

## §30.5 自動化驗收

- [ ] `an16` **［開發機］** 🛠 跑 `npm run verify:iteration30`（不需要後端，八步：四套版面的規則與配平、輪替、快照第 2 版、時窗、病人畫面沒有差別、算式與用字、營運參數、只有 A 部分，加上介面檢查、零院外連線、匯出登記與迭代 22、29 的驗收）與 `npm run verify:iteration30:api`（要 Prisma，不需要開發機的後端，五步：營運參數與時窗、標準模式那一盤、不合條件記成平常、輪替與舊存檔、護理端陳述與稽核）。 → 兩支都「全部通過」；`verify:acceptance` 與全部回歸照樣通過。
