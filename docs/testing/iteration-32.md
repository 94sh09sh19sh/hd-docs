# 迭代 32 手動測試 — 院方資料改讀檔：透析清單與檢驗資料

> 《[完整手動測試手冊](manual-test-guide.md)》的分冊之一，對應《實作規格書》4.32 節與 4.32.1（迭代 32.1 三班時間，§32.8）。共用的環境準備、啟動與疑難排解都在主手冊，這一冊只寫迭代 32 的部分。院方資料同步本身（病人、床位、療程、下機、四種數值）在《[迭代 15 分冊](iteration-15.md)》；讀檔模式只換了「拿到回應」那一步。抓取腳本是私人 repo `hd-hospital-fetch`，留底檔與狀態檔的格式以它 README 的「契約」為準。

## 摘要

這一冊驗七件事（項次 `ap1`～`ap24`，自動化另跑 `npm run verify:iteration32`、`npm run verify:iteration32:api`，32.1 再加 `npm run verify:iteration32-1` 與 `:api`）：

- 設定二選一：透析清單資料夾與院方 API 的位址兩種都填，後端起不來；只填資料夾時不連院方
- 讀檔：模擬院方 API 的寫檔模式寫留底，後端讀當天的段落、照舊同步；內容沒變不寫入
- 狀態檔：抓取腳本失敗的原因護理站看得到；「院方資料已 N 分鐘未更新」看腳本最後一次成功、只在提示時段內出現
- 檢驗資料：五種抽血數值讀進來、來源「院方檢驗」；「需要抽血數值的功能」關著時任何畫面都不出現
- 探測工具只讀檢查兩個資料夾、只印結構；正式環境設定下讀到模擬標記檔整次作廢
- compose 唯讀掛載兩個資料夾（路徑有空白與中文）
- （32.1）「未更新」提示時段預設 8～23 時，舊的 0、24 換版時改掉；工作量熱圖的虛線在 12:45、17:45

| 標記 | 意思 |
|---|---|
| 🖥 **護理端** | 以系統管理者登入專業版 → 系統管理 →「院方資料同步」那張卡（營運參數表在同一頁） |
| 🛠 **開發機** | 遷移 `iteration32_hospital_files`（`npm run prisma:deploy -w @hd/api`，後端要先關）；根目錄 `.env` 的 `HOSPITAL_API_BASE_URL` 留空 |
| 🐳 **Docker** | Docker Desktop＋WSL2，照部署手冊第十一冊的模擬部署 |

**前置**：開一個空的資料夾當模擬留底（下面寫 `<模擬資料夾>`，路徑故意帶一個空白與中文），終端機一跑 `HOSPITAL_API_SIM_FILES_DIR=<模擬資料夾> npm run dev:hospital-sim`（模擬院方 API 照抓取腳本的契約每 3 分鐘寫一輪透析清單、啟動時寫一輪檢驗資料），根目錄 `.env` 加 `HOSPITAL_DIALYSIS_LIST_DIR=<模擬資料夾>/dialysis-list` 與 `HOSPITAL_LAB_DIR=<模擬資料夾>/lab`，再啟動後端。

## §32.1 設定與啟動

- [ ] `ap1` **［開發機］** 🛠 `.env` 同時填 `HOSPITAL_API_BASE_URL=http://localhost:8090/dialysislist.php` 與 `HOSPITAL_DIALYSIS_LIST_DIR`，啟動後端。 → 起不來，訊息寫「院方 API 的位址……與透析清單資料夾……只能填一種」；訊息裡沒有資料夾的路徑。拿掉 `HOSPITAL_API_BASE_URL` 再啟動。
- [ ] `ap2` **［開發機］** 🛠 看啟動日誌。 → 「院方資料同步已啟用（讀透析清單資料夾）」「院方檢驗資料讀檔已啟用（讀檢驗資料資料夾）」兩行，**沒有任何路徑**；`HOSPITAL_DIALYSIS_LIST_DIR` 改成相對路徑時起不來，訊息只說「透析清單資料夾」。

## §32.2 讀檔與同步

- [ ] `ap3` **［護理端］** 🖥 院方資料同步那張卡。 → 「資料來源：抓取腳本的檔」「每 3 分鐘讀一次」「抓取腳本最近一輪：成功」；最上面一條「目前接的是模擬院方 API」。按「立即同步」。 → 「已同步：N 次透析……」；表格多一欄「抓取腳本」寫「成功」。即時總覽出現模擬甲～模擬癸的療程，與接模擬院方 API（迭代 15 分冊 `y` 系列）時一樣。
- [ ] `ap4` **［護理端］** 不等 3 分鐘再按一次「立即同步」。 → 「已重讀：內容與上一次相同，沒有要寫入的」；紀錄那一列標「內容沒變」。
- [ ] `ap5` **［開發機→護理端］** 🛠 在 `<模擬資料夾>/dialysis-list/` 當月檔的最後面手動加一行 `Date: <今天> 23:59:00` 與一行 `{"data_list": [壞掉`（存檔時不要多換行）。按「立即同步」。 → 成功，訊息寫「1 段解析不出、略過；檔尾那一段寫到一半，下一輪再讀」，其他病人照常；下一輪模擬院方 API 補換行再寫之後，那一段變成「解析不出」、不擋後面的段落。
- [ ] `ap6` **［開發機→護理端］** 🛠 把 `<模擬資料夾>/dialysis-list` 改名，按「立即同步」。 → 結果「失敗」：「透析清單資料夾不在（沒有掛上，或主機上的位置換了）」，沒有路徑；改回來、下一輪恢復，稽核軌跡「院方資料抓取失敗」「院方資料恢復更新」各一筆。

## §32.3 狀態檔與提示時段

- [ ] `ap7` **［開發機→護理端］** 🛠 停掉模擬院方 API，把 `fetch-status.json` 的 `result` 改成 `"failed"`、`reason` 改成 `"院方伺服器回應狀態 503"`、`last_success_at` 改成 30 分鐘前，按「立即同步」（32.1 起提示時段預設 8～23 時，23:00～08:00 做這一項先照 `ap8` 把時段改成 0、24）。 → 卡片與簡易版床位圖上方：「院方資料已 30 分鐘未更新：抓取腳本最近一輪失敗：院方伺服器回應狀態 503……」。
- [ ] `ap8` **［護理端］** 營運參數表的「院方資料未更新提示的起始時刻」「結束時刻」改成不含現在的時段（例如現在 14 時，改成 15～16 時），理由填「測試」。 → 兩處的「未更新」提示都消失；卡片寫「提示時段：15 時到 16 時，現在不在提示時段內」。改回 0、24 → 卡片寫「提示時段：全天」，提示回來。做完改回 8、23（32.1 的預設）。
- [ ] `ap9` **［開發機→護理端］** 🛠 狀態檔改回 `"ok"`、`last_success_at` 改成 1 分鐘前，不動當月檔（模擬透析室一陣子沒有新量測），按「立即同步」。 → 不提示「未更新」，紀錄標「內容沒變」、沒有錯誤。
- [ ] `ap10` **［開發機→護理端］** 🛠 刪掉 `fetch-status.json`，按「立即同步」。 → 成功，紀錄寫「看不到抓取腳本的狀態」；卡片「最後一次確定是新的」退回當月檔的修改時間。重開模擬院方 API 讓它補回狀態檔。

## §32.4 檢驗資料

- [ ] `ap11` **［護理端］** 🖥 卡片下半「院方檢驗資料」。 → 「每 30 分鐘讀一次」、「需要抽血數值的功能」關著的那一句（照讀照存、不出現在任何畫面）、「檢驗資料的抓取腳本最近一輪：成功」。按「立即讀檢驗資料」。 → 「已讀檢驗資料：2 個檔有變動，寫入 N 筆、退回 M 筆」；表格那一列的說明列出退回原因，例如「白蛋白：單位不符 1 筆」「透析適足度 Kt/V：兩欄都有值而且不同 1 筆」「血紅素（Hb）：不是數值 1 筆」，沒有病歷號與檢驗值。
- [ ] `ap12` **［護理端］** 再按一次「立即讀檢驗資料」。 → 「0 個檔有變動，寫入 0 筆」（檔案大小與修改時間沒變就不重讀）。
- [ ] `ap13` **［護理端］** 選單 →「臨床數值」→ 選模擬甲。 → 只有理想體重、目標脫水量這類院方透析清單的值，**沒有**血紅素、白蛋白、Kt/V、BUN；病人趨勢的判斷輔助（劑量調整參考開著時）也沒有血紅素。
- [ ] `ap14` **［護理端］** 系統管理 → 功能開關 → 開啟「需要抽血數值的功能」（理由填「測試」），再看一次臨床數值。 → 多了血紅素等五種，來源寫「院方檢驗」、資料時間是採檢那一天；看完**關回去**。
- [ ] `ap15` **［開發機→護理端］** 🛠 在 `<模擬資料夾>/lab/hospital_dataset/raw_txt/` 當月檔加一行同一位病人、同一個 `ExecuteDate`、`FetchedAt` 比較晚、`Hb` 改過的紀錄，按「立即讀檢驗資料」。 → 「1 個檔有變動，寫入 1 筆」；開關開著時看，血紅素是新的值、前一版標「已被覆蓋」。

## §32.5 探測工具與模擬標記檔

- [ ] `ap16` **［開發機］** 🛠 `npm run probe:hospital-api`。 → 標題「院方資料讀檔檢查（只讀、只印結構……）」；兩個資料夾各寫「在、讀得到」、唯讀（開發機寫「否」）、模擬標記檔「有」、月份檔、狀態檔的結果與最後一次成功、當天段落數與往回讀了多少位元組、合起來的列數，以及與迭代 15 探測工具同一套的欄位型態分布；檢驗資料印對照表每一欄有值的筆數與「99.9 g/dL」這種樣式。整段輸出找不到路徑、姓名、病歷號與檢驗值。
- [ ] `ap17` **［Docker］** 🐳 模擬部署照 `docker-compose.hospital-files-sim.yml` 開頭的用法起（`COMPOSE_FILE` 加這個檔、`HD_SIMULATION_DEPLOYMENT=yes`），再把設定目錄 `.env` 的 `HD_SIMULATION_DEPLOYMENT` 清空、重新啟動 api，等一輪。 → 院方資料同步那張卡最新一列「拒收（正式環境收到模擬資料）」：「正式環境設定下讀到模擬院方 API 寫的檔，整次作廢……」；檢驗資料也拒收；資料庫一筆都沒多。做完改回 `yes`。

## §32.6 唯讀掛載

- [ ] `ap18` **［Docker］** 🐳 主機上建一個路徑帶空白與中文的資料夾當透析清單資料夾、另一個當檢驗資料資料夾，設定目錄 `.env` 填 `HD_DIALYSIS_LIST_DIR`、`HD_LAB_DIR` 與 `COMPOSE_FILE=docker-compose.yml;docker-compose.dialysis-files.yml;docker-compose.lab-files.yml`（範本裡那一行的註解拿掉），`docker compose --env-file <設定目錄>\.env up -d`，再 `docker compose --env-file <設定目錄>\.env exec api sh -c "ls /hospital/dialysis-list; touch /hospital/dialysis-list/x"`。 → 列得出檔；`touch` 失敗「Read-only file system」；主機上的資料夾沒有多出 `x`。
- [ ] `ap19` **［Docker］** 🐳 `COMPOSE_FILE` 那一行改回註解、兩個資料夾留空，`docker compose --env-file <設定目錄>\.env config`。 → api 沒有 `/hospital/` 的掛載，`HOSPITAL_DIALYSIS_LIST_DIR` 是空的。**`COMPOSE_FILE=` 留成空白的一行時 compose 讀不到設定檔**（1111 實測），範本因此寫成註解。

## §32.8 迭代 32.1：三班時間

> 對應《實作規格書》4.32.1：「未更新」提示時段的預設值（第 1 項）、工作量歸班的界線（第 2 項）。療程的分班界線（12、17 時）照留；四小時怎麼算（第 4 項）等清冊 Q-34 第 4 題，這一版不動。遷移 `iteration32_1_stale_alert_hours`（`npm run prisma:deploy -w @hd/api`，後端要先關）。

- [ ] `ap21` **［護理端］** 🖥 全新環境（或已套 32.1 遷移的開發機）看營運參數表與「院方資料同步」卡。 → 「院方資料未更新提示的起始時刻」8 時、「結束時刻」23 時，說明寫第一班 08:00 開始、最後一班 22:00 結束，**沒有「三班時間待 Q-34」**；卡片寫「「未更新」提示時段：8 時到 23 時」，現在在 23:00～08:00 時多一句「現在不在提示時段內」。
- [ ] `ap22` **［開發機→護理端］** 🛠 32.1 之前建的開發資料庫（兩個時刻還是 0、24）關後端、跑遷移、再啟動。 → 兩列變成 8、23，各有一筆系統寫的稽核「由 0 時 改為 8 時」「由 24 時 改為 23 時」，理由「版本更新：1111 迭代 32.1 三班時間……」；遷移前先把其中一個改成別的值（例如結束 22）再跑一次，那一個照留、沒有稽核。
- [ ] `ap23` **［護理端］** 🖥 選單 → 成效與工作量 →「各班工作量」分頁的熱圖。 → 兩條虛線畫在 12 點、17 點那一格的**中間**（不是格子的左邊線），「午班」「晚班」標在虛線旁；圖下說明寫「虛線是各班工作量的分界（12:45、17:45……）」。「文書與審閱」那張圖：17:00～17:44 簽核的護理紀錄算在午班（開發機上可在 17:20 簽一筆再看）。
- [ ] `ap24` **［開發機］** 🛠 跑 `npm run verify:iteration32-1`（不需要後端，六步：三班時間與療程的界線、工作量的界線與用到的程式、提示時段的預設與邊界、遷移的寫法、四小時照舊、介面檢查與相關驗收）與 `npm run verify:iteration32-1:api`（要 Prisma、不必開後端，七步：兩種班別換算、全新資料庫套全部遷移、四種舊值重跑遷移）。 → 兩支都全部通過。
