# 迭代 17.8 手動測試 — 護理紀錄補上線前的缺口、緊急回報的圖示

> 《[完整手動測試手冊](manual-test-guide.md)》的分冊之一，對應《實作規格書》4.15.8 節與《[迭代 17.8 修正紀錄](../notes/iteration-17-8-fixes.md)》。
> 共用的環境準備、啟動與疑難排解都在主手冊，這一冊只寫迭代 17.8 的部分。
> 操作端色籤（**護理端**／**病人端**／**終端機**／**資料庫**）的意思見主手冊 §00。
> 項次接著迭代 17.7 分冊編（`aa147` 起；17.7 用到 `aa146`），小版沿用那個迭代的字母。

**這一冊驗三件事**：護理紀錄移到專業版主列；護理紀錄依系統管理選的格式（DART 預設、SOAP）分段，事件時間與院方量測寫在段落裡，簽核後整份或逐段複製、貼進院內的正式紀錄，AI 沒開照樣走得完；緊急回報的圖示改成畫出症狀本身。
院方建議的「血壓圖加正常區間」**判斷不合理、沒有做**，理由在 SRS FR-P11 補充說明，這一冊不驗。

| 標記 | 意思 |
|---|---|
| 🛠 **開發機** | 平常的 `npm run dev`（資料庫先套用新遷移：`npm run prisma:migrate` 或 `db:update`） |
| 🏥 **院內位址** | 用主機的 IP 開護理端（`http://<IP>:<埠>`，**不是** `localhost`）——瀏覽器只在安全來源給新的剪貼簿介面，院內正是不安全來源 |
| 📐 **目標尺寸** | 護理端 1366×768；病人端 1280×800 與 800×1280 |

## §17.8.1 護理紀錄在主列

- [ ] `aa147` **［護理端］** 📐 專業版，看上方主列。
  → 七項：即時總覽、緊急通報、排班與指派、新增裝置、公告與院內衛教、總覽螢幕模式、**護理紀錄**；「更多」裡沒有護理紀錄。
- [ ] `aa148` **［護理端］** 系統管理 → 導覽版位，看護理紀錄那一列。
  → 版位「主列」。既有環境更新上來的，理由寫「版本更新：1010 院方要求護理紀錄移到常用（主列）」；全新環境沒有理由（本來就是預設）。
- [ ] `aa149` **［資料庫］** （只在要驗「護理長改過的不動」時做）更新前先在導覽版位把護理紀錄改成「關閉」並填理由，再套用新遷移。
  → 更新後照樣是關閉：遷移只動從沒被改過的那一列。

## §17.8.2 DART：分段、時間與量測寫在段落裡

- [ ] `aa150` **［護理端］** 系統管理 → 營運參數，看「護理紀錄格式」。
  → 顯示「DART（資料、處置、反應、衛教）」，不是數字 1；編輯時是下拉選單。
- [ ] `aa151` **［護理端］** 護理紀錄 → 選一位有院方量測的病人 → 快速範本「透析中低血壓處置」，勾有症狀、頭低腳高、部分緩解，事件時間選最近一筆量測之後幾分鐘 → 建立。
  → 記錄卡是 **D、A、R、T 四格**，編輯框一出現就是預填文字。
  → **D** 有事件時間（時:分）、「有無症狀：有症狀」、**事件時間前最近一筆量測**：「時:分 量測：血壓 …/… mmHg、脈搏 … 次/分、累積脫水量 … 公斤（設定 … 公斤）」。
  → **A** 是「時:分 頭低腳高」；**R** 是「部分緩解」；**T** 空著。
- [ ] `aa152` **［護理端］** 看四格的文字。
  → 沒有病人姓名、沒有病歷號；院方資料讀到 0 的那一筆不出現（模擬院方 API 的 0 值列）。

## §17.8.3 帶入處置後數值、簽核、複製

- [ ] `aa153` **［護理端］** 事件時間之後還沒有新量測時，按「帶入處置後數值」。
  → 畫面就地說「事件時間之後還沒有新的院方量測」，R 格不變。
- [ ] `aa154` **［護理端］** 等院方資料多一筆量測（模擬院方 API 每 3 分鐘），再按一次。
  → R 格後面多一句「處置後 時:分 量測：…」；再按一次不會重複。在 R 格裡先改過字也一樣，新的一句接在後面。
- [ ] `aa155` **［護理端］** 在 T 格寫「說明緩慢起身、有頭暈即按呼叫鈴」，按「整份複製（尚未簽核）」，貼到記事本。
  → 每段一行，以「D：」「A：」「R：」「T：」開頭；按鈕就地顯示「已複製」兩秒，沒有跳出任何對話框。
- [ ] `aa156` **［護理端］** 簽核送出。
  → 記錄卡變成四列，每一列右邊「複製這段」；底下「整份複製」。
- [ ] `aa157` **［護理端］** 🏥 用 `http://<IP>` 開護理端，按「複製這段」（R），貼到記事本。
  → 只有 R 那一段的文字，**沒有**「R：」；複製成功。（用 `localhost` 時兩種做法都會成功，這一項一定要用 IP 開）
- [ ] `aa158` **［護理端］** 稽核軌跡，篩「複製護理記錄（貼進院內紀錄）」。
  → 看得到整份、R（反應）段、未簽核那一次；說明裡沒有任何段落內容。

## §17.8.4 切到 SOAP

- [ ] `aa159` **［護理端］** 營運參數把護理紀錄格式改成 SOAP，理由「試 SOAP」。
  → 稽核寫「由 DART（…）改為 SOAP（…）」，不是 1 改 2。
- [ ] `aa160` **［護理端］** 以「病人不適處置」建一筆（勾頭暈、冒冷汗；調整姿勢、測量生命徵象；已緩解；補充「病人說起身時頭暈」）。
  → **S** 是時:分加病人表現；**O** 是事件前的量測與「補充：…」；**A** 只有「病人不適處置」（系統不寫任何評估）；**P** 是時:分加處置、已緩解。
- [ ] `aa161` **［護理端］** 看 §17.8.2 那一筆。
  → 仍是 D、A、R、T，複製出來也是 DART。做完把格式改回 DART。

## §17.8.5 AI 沒開也走得完

- [ ] `aa162` **［護理端］** AI 總開關關著，從建立、改字、簽核到複製走一次（§17.8.2、§17.8.3 就是在 AI 關著時做的）。
  → 畫面上沒有任何 AI 的按鈕、沒有空白的區塊、沒有錯誤。
- [ ] `aa163` **［護理端］** （可略）照迭代 3 分冊開 AI 總開關（模擬供應者），在一筆草稿按「AI 潤飾」。
  → 每一格底下出現「AI 初稿：…」；按「以 AI 初稿開始」各格換成 AI 的版本，簽核後記錄寫「原樣採用 AI 初稿」或「修改 AI 初稿後採用」。做完關回去。

## §17.8.6 緊急回報的圖示

- [ ] `aa164` **［病人端］** 📐 1280×800 開求助畫面，看類別格。
  → 每一格的圖示畫的是症狀本身：轉圈加汗的臉（頭暈）、小腿裡的閃電（抽筋）、瞇眼波浪嘴（想吐）、胸口的心（胸悶）、頭頂裂開（頭痛）、手臂上抓的痕跡（癢）、發抖的人與溫度計（發冷）、手臂上的針與血滴（打針的地方）、傷口與血滴（流血）、人與問號（其他地方）、機器與聲波（機器一直叫）、蓋被子與太陽雪花（冷熱）、杯子與飯碗（口渴肚子餓）；字照舊在圖示下方。
- [ ] `aa165` **［病人端］** 找一位沒看過對照的人，用紙把字遮住，請他看圖說出是什麼症狀。
  → 十五格至少說對十二格（實作規格書 4.15.8 驗收第 9 條）；說錯的記下是哪幾格、被說成什麼，回報開發端。
- [ ] `aa166` **［病人端］** 800×1280 再看一次。
  → 圖示沒有被切掉；畫面上紅色仍只在求助區。
