# 迭代 19 手動測試 — 管理儀表板、獎勵制度與對外揭露

> 《[完整手動測試手冊](manual-test-guide.md)》的分冊之一，對應《實作規格書》4.17 節。
> 共用的環境準備、啟動與疑難排解都在主手冊，這一冊只寫迭代 19 的部分。
> 操作端色籤（**護理端**／**病人端**／**終端機**／**資料庫**）的意思見主手冊 §00。
> 項次用 `ac`（實作規格書 4.0.5：19 用 `ac`），從 `ac1` 起。

**這一冊驗四件事**：
成效儀表板（全單位、對照上線前的基準）、各班工作量與簡報模式，醫院管理層登入只看得到這一頁；
獎勵制度（計分規則公告、觀察期只計算不計分、本人看自己的計分與每一筆原始事件、更正申請、個人層級要總開關與宣告用途）；
臨時調動候補建議；對外報表（樣本少於 5 不呈現、要另一人核准才取得出來）與對外展示環境。
**資料分級是後端擋的**（實作規格書 3.10），每一項都可以拿權杖直接打端點確認，不是只看畫面。

| 標記 | 意思 |
|---|---|
| 🛠 **開發機** | 平常的 `npm run dev`（資料庫先套用新遷移：`npm run prisma:migrate` 或 `db:update`）。**做完這一冊，「獎勵制度」「對外報表」兩頁與「班表」回到關閉，兩個績效開關回到關閉** |
| 🖥 **另一台機器** | 對外展示環境（`npm run showcase`）。開發機上也跑得起來，但正式的展示要在另一台機器上 |
| 📐 **目標尺寸** | 護理端 1366×768 |

## §19.1 成效、各班工作量、簡報模式

- [ ] `ac1` **［護理端］** 📐 以一般護理師登入 → 專業版 → 更多 → 成效與工作量。
  → 只有「成效」「簡報模式」兩個分頁（**沒有**「各班工作量」）。期間預設最近 30 天（含今天）。表格九列，每列寫「這段期間」的值與筆數、「上線前的基準」、「差多少」。
- [ ] `ac2` **［護理端］** 看「按下求助到護理師到床邊（中位數）」那一列。
  → 成效基準沒建檔時寫「基準尚未建檔」，「差多少」寫原因、**沒有數字**；有建全單位的基準（成效基準頁，「病人按鈴到護理師到床邊」、不分班）而且這段期間至少 5 筆時，寫出差多少（帶正負號與百分比）、基準的來源、筆數、量測期間、背書人；比較短是「改善」、比較長是「變差」，**沒有紅色**。基準是估算時旁邊一個「估算」小標，說明也寫「這個基準是估算值，不是實測」。
- [ ] `ac3` **［護理端］** 看「病人在平板看完衛教的次數」。
  → 基準有建「每班口頭重複衛教次數」時，基準照列，但「差多少」寫「兩者不是同一件事，只並列不相減」。表格下方「上線前量了、系統量不到的」列出交班查找病人資訊的耗時。
- [ ] `ac4` **［護理端］** 往下看「每日走勢」。
  → 最近 14 天、三欄（求助件數、到床邊中位數、護理紀錄建立到簽核），**沒有今天**（每天過完才記）。系統管理 → 稽核軌跡查「記下每日指標快照」，第一次啟動那一筆寫著補了幾天。
- [ ] `ac5` **［護理端］** 以護理長登入同一頁。
  → 多一個「各班工作量」：三個班別的求助件數與確認中位數、確認時間分組（含「還沒確認」）、哪幾個鐘點最多（橫條，一般色）、每一班一列。**整頁看不到任何一位護理師或病人的名字**。
- [ ] `ac6` **［護理端］** 按「簡報模式」→「列印」。
  → 一頁：對照上線前的基準、其他數字、**還沒做到的**（沒有基準的、量不到的、獎勵計分與個人層級還沒啟用）。列印預覽裡沒有導覽列、分頁鈕與期間欄位。

## §19.2 醫院管理層與稽核角色

- [ ] `ac7` **［護理端］** 以醫院管理層登入。
  → 直接進成效頁；導覽只有「更多」裡的「成效與工作量」，**沒有班表**（迭代 19 起，不要求權限的那幾項也不給唯讀角色）；只有「成效」「簡報模式」兩個分頁，沒有簡易版的按鈕、沒有系統管理。
- [ ] `ac8` **［終端機］** 以醫院管理層的權杖打 `GET /api/patients`、`/api/help-requests`、`/api/nursing-records`、`/api/devices`、`/api/audit-logs`、`/api/performance/workload`、`/api/rewards/me`。
  → 全部 403。`/api/performance/effectiveness` 與 `/api/performance/brief` 是 200。
- [ ] `ac9` **［護理端］** 以稽核角色登入 → 稽核軌跡。
  → 先出現「先選這一次查詢的用途」，選了（法規查核、事故追溯、系統維運、其他）才列出紀錄；選「其他」要寫一句說明。重新整理、換頁不必再選，登出再登入要重選。用途的選單**沒有**「獎勵計分審閱」。
- [ ] `ac10` **［護理端］** 用管理者看稽核軌跡，動作選「查詢稽核軌跡」。
  → 剛才稽核角色每查一次就有一筆：條件、區間、第幾頁幾筆、用途。驗收腳本沒宣告用途的那幾筆寫「未宣告用途」。

## §19.3 計分規則與觀察期

- [ ] `ac11` **［護理端］** 📐 以一般護理師開「獎勵制度」→「計分規則」。
  → 四條預設規則（求助處理紀錄完整、護理紀錄簽核、衛教內容審閱、追蹤事項完成），全是「草稿（未公告）」，每件 1 點；說明寫只算流程上的事、不看病人的臨床結果、不看誰回應得快。**沒有任何可以按的東西**。
- [ ] `ac12` **［護理端］** 以護理長開同一頁，對「護理紀錄簽核」按「以此新增一版」，點數改 2、存成草稿；在新的那一版填公告依據、按「公告」。
  → 新的一版是「已公告」，寫著誰、什麼時候公告；同代號原本公告中的那一版（若有）變「已停用」。已公告的那一版只剩「停用」（要寫理由、會問一次），沒有「公告」。一般護理師重新整理也看得到這一版。
- [ ] `ac13` **［護理端］** 護理長開「計分期間」，種類的選單只有「觀察期（只計算不計分）」。開始一個起訖都在過去的觀察期，按「結算」。
  → 問一次「標為已完成的觀察期，不產生點數」；結算後狀態「已結算」。說明裡「已結算的觀察期」加一。訖日是今天或之後的期間，結算會被擋下（「過了訖日才能結算」）。
- [ ] `ac14` **［資料庫］** 查 `reward_scores` 有沒有那一期的列。
  → 一列都沒有（觀察期只計算不計分）。系統管理 → 稽核軌跡「結算計分期間」寫著事件幾筆、幾位護理師、「觀察期只計算不計分」，**沒有任何一位的件數**。

## §19.4 我的計分與更正申請

- [ ] `ac15` **［護理端］** 📐 一般護理師開「我的計分」，選剛才的觀察期。
  → 上面一條「觀察期只計算不計分…」；表格是每一條已公告的規則算到幾件、點數「—」、單位中位數（有這件事的護理師不到五位時是「—」）。下面列出每一筆原始事件的時間與做了什麼，**沒有病人姓名與病歷號**，也看不到別人的。
- [ ] `ac16` **［護理端］** 對其中一筆按「這一筆不該算」，填原因送出。
  → 綠色訊息；那一筆多一個「更正處理中」，按鈕不見；「我的更正申請」多一列「處理中」。再對同一筆送一次（用終端機打 `POST /api/rewards/disputes`）→ 409。
- [ ] `ac17` **［護理端］** 以護理長開「更正申請」，填查證結果按「接受」。
  → 那一列變「已接受」。回到那位護理師的「我的計分」：那一筆標「不計入」、件數少一。護理長對**自己**提出的申請按接受 → 「不能處理自己提出的更正申請」。
- [ ] `ac18` **［護理端］** 按「少算了一筆」，選事件種類、寫哪一天做了什麼送出。
  → 「我的更正申請」多一列「少算了一筆」。護理長看得到，接受或不接受都只留紀錄，不自動加件數（要查證）。
- [ ] `ac19` **［護理端］** 管理者看稽核軌跡，動作選「查詢個人層級績效資料」。
  → 護理師每開一次「我的計分」就有一筆，寫著期間與「用途：本人自我檢視」。

## §19.5 個人層級總開關與臨時調動候補

- [ ] `ac20` **［護理端］** 總開關關著時，護理長的「獎勵制度」**沒有**「個人層級」分頁；班表頁核示請假時**沒有**「找候補」。終端機以護理長權杖打 `GET /api/rewards/individual?purpose=REWARD_REVIEW` → 403，稽核軌跡多一筆「個人層級績效資料查詢遭擋下」。
- [ ] `ac21` **［護理端］** 系統管理 → 功能開關，看「個人層級績效資料（L3）」與「獎勵計分」的開啟條件。
  → 還沒結算過觀察期時寫「還沒有結算過任何觀察期」；個人層級另寫「還沒有公告任何計分規則」，開不起來（409）。§19.3 做完之後都變成可以開，說明寫「開啟前請確認已取得護理部書面同意，文號寫在核准依據」。
- [ ] `ac22` **［護理端］** 開啟「個人層級績效資料」，核准依據寫「護理部書面同意 文號 手測-19」。
  → 稽核軌跡「開啟功能開關」寫著這段核准依據。護理長的「獎勵制度」多一個「個人層級」分頁。
- [ ] `ac23` **［護理端］** 「個人層級」選期間，不選用途 →「查看」按不下去；選「其他」不寫說明也按不下去。選「獎勵計分審閱」→ 查看。
  → 每位有事件的護理師一列、每條規則一欄，依工作 ID 排；**沒有總分欄、沒有排名**。稽核軌跡「查詢個人層級績效資料」寫著查了哪幾位（工作 ID）、區間、用途「獎勵計分審閱」。
- [ ] `ac24` **［護理端］** 班表頁：護理長替某位護理師排一班（未來的日子），那位護理師申請請假；回到護理長，在調班申請那一列按「找候補」，用途預設「排班與臨時調動」，按「列出候補」。
  → 候補依「相同技能標記多的在前、近 7 天時數少、接班後連續時數短」排；請假的人不在裡面；排了會違反勞動條件的列在下面「不在建議裡」並寫違反哪一條。班表頁最下面「技能標記」可以替每位護理師寫標記（用「、」分開）。稽核軌跡有這一次查詢，寫著哪一班與用途。
- [ ] `ac25` **［護理端］** 關掉「個人層級績效資料」。
  → 「個人層級」分頁與「找候補」都不見；護理師自己的「我的計分」**照樣看得到**（限本人不跟著總開關）。

## §19.6 對外報表

- [ ] `ac26` **［護理端］** 📐 以護理長開「對外報表」。
  → 上面「產生對外報表」：名稱、給誰、用途、起訖日（訖日最晚昨天）、分組（全單位／依透析班別）、九個指標的勾選框。說明寫只輸出合計、樣本少於 5 不呈現、不含姓名病歷號床號工作 ID、日期只到「日」、要另一位核准。一般護理師與醫院管理層的導覽**沒有**這一頁，打 `GET /api/external-reports` 是 403。
- [ ] `ac27` **［護理端］** 選一段有資料的期間、依透析班別、勾三個指標 → 產生。
  → 新的一張「待核准」：表格只有樣本至少 5 的那幾格，下面寫「不呈現的分組：N 組」。**產生的人看不到「核准」**，也沒有「取出」。
- [ ] `ac28` **［終端機］** 用產生者的權杖打 `GET /api/external-reports/<id>/export` → 409；打 `POST /api/external-reports/<id>/decide`（`{"approve":true,"note":"自己核准"}`）→ 403。稽核軌跡有「對外報表取出遭擋下」。
- [ ] `ac29` **［護理端］** 以管理者（暫代的核准角色之一）填說明按「核准」，再按「取出（CSV）」。
  → 下載一個 CSV：報表、期間（只到日）、分組、說明、已核准（日期），接著每一格指標、分組、值、單位、樣本數。**檔案裡沒有任何人的名字或工作 ID、沒有時:分**。稽核軌跡依序有「產生對外報表」（給誰、哪些指標、拿掉幾組）、「核准對外報表」、「取出對外報表」（第幾次取出）。
- [ ] `ac30` **［資料庫］** 查 `external_report_items`。
  → 只有呈現的那幾格；樣本不足的分組**沒有存**。

## §19.7 對外展示環境

- [ ] `ac31` **［終端機］** 🖥 `npm run showcase`。
  → 印出「已建立 …\showcase\hd-showcase.db：護理師 7 位、病人 12 位、求助 N 件、護理紀錄 M 份」、管理者帳號與一次性密碼、護理端網址（埠 5185）。資料目錄的 `showcase-ledger.log` 多一行「建立對外展示環境」。
- [ ] `ac32` **［護理端］** 開那個網址，以 SC007（醫院管理層，密碼 `showcase-1234`）登入。
  → 左下角一小塊「展示環境：所有病人、護理師與紀錄都是虛構的合成資料…」，每一頁都在、登入畫面也在；成效頁有 30 天的數字，「按下求助到護理師到床邊」對照一筆標「估算」的虛構基準。
- [ ] `ac33` **［終端機］** 讓展示模式的後端去開平常的資料庫（`SHOWCASE_MODE=true` 加平常的 `DATABASE_URL` 啟動後端）。
  → 不啟動，訊息寫「對外展示模式只能開展示腳本建的資料庫」。`SHOWCASE_MODE=true` 再設 `HOSPITAL_API_BASE_URL` 或 `LLM_PROVIDER=lab` → 也不啟動。
- [ ] `ac34` **［終端機］** `npm run showcase -- --destroy`。
  → 展示資料庫整個資料夾刪掉；`showcase-ledger.log` 多一行「銷毀對外展示環境」（展示資料庫已經不在，這一行只能記在外面）。

## §19.8 自動化驗收

- [ ] `ac35` **［終端機］** `npm run verify:iteration19`（不需要後端）；後端開著，再跑 `npm run verify:iteration19:api`。
  → 兩支都全部通過（前一支會再跑 `check:ui`、`check:ui:design`、`check:egress`、`verify:iteration14`、`verify:iteration17-8`、`verify:iteration18`；後一支結束時兩個績效開關與三頁的版位改回原狀、這次公告的規則停用。計分事件以合成資料寫在很久以前的隨機一週；「今天」的觀察期同一天只建得起一個，第二次跑會略過那一項）。
