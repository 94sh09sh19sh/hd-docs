# 迭代 3 手動測試 — 封閉網路化與資料層遷移

> 《[完整手動測試手冊](manual-test-guide.md)》的分冊之一，對應《實作規格書》v2.0 4.1 節。
> 共用的環境準備、啟動、關閉與疑難排解都在主手冊，這一冊只寫迭代 3 的部分。
> 操作端色籤（**護理端**／**病人端**／**終端機**／**資料庫**）的意思見主手冊 §00。

迭代 3 **不新增任何病人看得到的臨床功能**，做的是後面每個迭代都踩在上面的地基：資料層搬到本機 SQLite、系統不得連向院外、模型供應者與臨床資料來源兩個介面層、功能開關中心、備份與還原，以及取代推播的常駐總覽螢幕。
地基壞掉時上層功能不會出錯，只會慢慢歪掉，所以這一冊的每一項都值得走過一次。

## 3.1 · 資料層：SQLite 必開設定與資料庫位置

- [ ] `l1` **［終端機］** 啟動後端，看第一段 log。
  → 出現「已連線至 SQLite：journal_mode=WAL、foreign_keys=ON、busy_timeout=5000ms、synchronous=FULL」。四項缺一都算沒過。
- [ ] `l2` **［護理端］** 以護理站管理者進「系統管理 → 資料庫與備份」，看「資料庫運作狀態」。
  → 九格逐項顯示：`journal_mode` ✓ WAL、外鍵檢查 ✓ 開啟、忙碌等待 ✓ 5000 ms、`synchronous` ✓ FULL、統計與報表唯讀連線 ✓ `query_only`、資料庫檔案與 WAL 檔案大小、每日排程備份、最近一次成功備份。畫面上**看不到資料庫檔案的實際路徑**。
- [ ] `l3` **［護理端］** 看「統計與報表唯讀連線」那一格。
  → 值是 `query_only` 而不是「可寫入」。這條通道是給統計與報表用的，寫不進去才是對的（規範 7.1）。
- [ ] `l4` **［終端機］** 確認資料庫檔案在**專案目錄外**，且 repo 是乾淨的。
  → `.env` 的 `DATABASE_URL` 指向專案外的絕對路徑；`git status --short` 沒有任何 `.db`、`.db-wal`、`.db-shm` 冒出來（規範 7.2）。
- [ ] `l5` **［終端機］** 看 migration 目錄。
  → 五個目錄，第一個是 `20260910110540_init`、第二個是 `20260910111354_iteration3_closed_network`。遷移時整組重建過，Supabase 時期的 migration 已經不在。

```bash
grep DATABASE_URL .env
git status --short
ls apps/api/prisma/migrations
```

> **說明｜為什麼 `synchronous` 要 FULL**
>
> 開發環境放寬成 NORMAL 只影響「斷電當下那一筆」，但臨床現場的斷電不會事先通知。畫面上這一格若顯示 ✗ NORMAL，代表環境變數被改過，正式環境不得如此。

## 3.2 · 三台裝置同時操作不出現 SQLITE_BUSY

  → 全程沒有 `SQLITE_BUSY`。WAL 加上 5 秒忙碌等待就是為了這件事；真的出現就要回頭確認 `l1` 的四項設定。

## 3.6 · 模型供應者介面層（FR-S06）

- [ ] `l24` **［護理端］** 進「系統管理 → 模型供應者」。
  → 顯示目前供應者、資料是否離開院內（模擬供應者為「否」）、模型識別字、端點主機、健康檢查 ✓ 通過、可用模型。
- [ ] `l25` **［護理端］** 在「介面層連線測試」輸入一段**合成**提示（例如「請用三句話說明透析後量體重的用意」），不勾核取方塊，送出。
  → 看得到模型回應，以及「送出的提示（已去識別化，移除 N 處）」。這條測試走的是與正式功能完全相同的閘道。
- [ ] `l26` **［護理端］** 勾選「此內容含真實病人資料（用來確認閘道會擋下）」再送一次。
  → **被擋下**，不會有模型回應；下方呼叫紀錄多一列，結果欄是「已擋下」、資料類別欄是「真實病人資料」。
- [ ] `l27` **［護理端］** 看「呼叫紀錄」表頭。
  → 時間、功能、供應者／模型、結果、去識別化（是／否與處數）、資料類別、操作者、耗時共八欄；下方註明提示與輸出只存去識別化後的版本。
- [ ] `l28` **［終端機］** 把 `.env` 的 `LLM_PROVIDER` 改成 `lab`，`LLM_ENDPOINT` 與 `LLM_MODEL_ID` 照下面填，重新啟動後端，回到同一頁。
  → 後端 log 出現「模型供應者：實驗室 API（院外，僅得送合成資料）」與黃字「目前模型供應者位於院外：帶真實病人資料的請求一律擋下」。頁面上「目前供應者」跟著變，「資料是否離開院內」顯示「院外：僅得送合成資料」。**只改設定，一行程式都沒有動**（《實作規格書》4.2 驗收 3）。
- [ ] `l29` **［護理端］** 在 `lab` 之下重做 `l26`。
  → 一樣被擋，稽核軌跡查得到「AI 呼叫遭擋下：真實病人資料」（4.2 驗收 4）。確認完把三個變數改回原值（`LLM_PROVIDER=mock`，另外兩個留空）並重新啟動。

*`.env` 這兩行：本機不會有人接的位址即可，這兩步都不需要真的叫得動模型*

```bash
LLM_ENDPOINT=http://127.0.0.1:9/v1
LLM_MODEL_ID=stub-model
```

> **注意｜健康檢查顯示「失敗」是預期的**
>
> 這兩步驗的是**閘道**，不是模型：`l28` 驗「換供應者只要改設定」，`l29` 驗「真實病人資料在送出之前就被擋下」——
> 擋下的判斷發生在呼叫端點**之前**，所以端點連不連得上都不影響結果。頁面上健康檢查那一格顯示失敗、
> 可用模型是空的，都是正常的；真要在 `lab` 之下跑一次合成資料的完整呼叫，`verify:iteration4` 第 12 步
> 已經用本機假端點自動做過同一件事，不必自己架一台。

> **地雷｜這一節請只輸入合成內容**
>
> 「介面層連線測試」不是沙盒，它與正式功能共用同一條閘道，紀錄一樣會留。《資料庫使用規範》第 10 條：絕對禁止輸入任何接近真實病人的資訊。

## 3.7 · 臨床資料來源介面層：人工輸入（FR-S05）

  → 被擋下並指出是哪一列缺資料時間。每一筆都必須帶「何時量的」，病人端看到數值時會一併顯示。

  → 整批退回，**另外兩列也沒有寫進去**。臨床數值只對一半，比完全沒有更危險。
- [ ] `l33` **［護理端］** 修正後送出，接著對**同一資料時間**再送一次不同的值，勾選「同一資料時間已有數值時，覆蓋並保留前一版」。
  → 成功，清單上舊值標「已被覆蓋（保留前一版）」、新值標「現行」。舊值不會消失。
- [ ] `l34` **［護理端］** 不勾那個核取方塊，再送一次同一資料時間。
  → 被擋下並要求確認，不會默默覆蓋。
- [ ] `l35` **［護理端］** 以一般護理師 `N001` 開同一頁。

- [ ] `l36` **［護理端］** 「稽核軌跡」查最近紀錄。
  → 查得到「臨床數值匯入」與（`l32` 那次）「臨床數值匯入遭拒（整批未寫入）」，含批次編號與筆數。

## 3.9 · 常駐總覽螢幕（FR-N12，P0）

推播在 0910 需求改版時整個移除，這台螢幕因此是**唯一保證通報被看見的地方**。它的每一個失效狀態都必須大聲顯示出來，而不是默默停住。

- [ ] `l42` **［護理端］** 以具「即時總覽」權限的帳號登入 →「總覽螢幕模式」。
  → 進入前的畫面說明「按下後會啟用通報音效、進入全螢幕，並要求螢幕不休眠」，並註明瀏覽器規定音效必須由人按一下才能啟用，每次開啟這個畫面都要按一次。
- [ ] `l43` **［護理端］** 按「開始」。
  → 進入全螢幕；底部狀態列顯示「最後更新」時間、「防休眠：已啟用」與「音效：開啟」。防休眠只在 HTTPS 或 localhost 下可用，顯示「不支援」或「被拒絕」時畫面會常駐提示要改在作業系統關閉螢幕休眠與螢幕保護程式。
- [ ] `l44` **［護理端］** 按「試播一聲，確認喇叭有聲音」。
  → 聽得到提示音。聽不到就先解決喇叭或瀏覽器的音效權限，不要等到真的有通報才發現。
- [ ] `l45` **［護理端］** 看畫面配置。
  → 上半「待處理求助」、下半「療程進行中」，兩區各有筆數；字級明顯大於一般畫面，站在護理站看得清楚；每筆顯示床號、按下時間與「按下，尚未接收」，平板沒回應時另標「平板未回應」。
- [ ] `l46` **［病人端］** 用兩台平板先後按求助，其中一台選「非常緊急」。
  → 非常緊急那筆排在最前，其次是尚未有人接收的，同級依按下時間先後；每來一筆都會發出提示音（第一次載入既有的通報不會響，避免一開螢幕就大作）。
- [ ] `l47` **［護理端］** 放著不要接收，等一分鐘。
  → 未接收的通報每 60 秒再提醒一次。
- [ ] `l48` **［終端機］** 停掉後端。
  → 最慢 45 秒內整個畫面出現紅框閃爍與「連線中斷」橫幅，並顯示「正在自動重新連線（第 N 次）・請同時留意床邊呼叫鈴」。拔網路線的話另外顯示「本機網路已離線」。
- [ ] `l49` **［終端機］** 把後端啟動回來。
  → **不必手動重新整理**，橫幅自動變回「即時連線中」，「最後更新」繼續前進。
- [ ] `l50` **［護理端］** 讓登入權杖過期（或在另一個分頁登出）。
  → 全螢幕蓋住「登入已逾時，總覽螢幕已停止更新／新的通報不會再出現在這台螢幕上，請立即重新登入」，並有「重新登入」按鈕。**不會默默停在舊畫面上。**
- [ ] `l51` **［護理端］** 按「關閉音效」，再按「離開總覽螢幕」。
  → 關閉音效後畫面常駐提示「音效已關閉：新通報不會發出聲音」；離開後回到一般護理端畫面，螢幕不休眠的要求一併解除。
- [ ] `l52` **［護理端］** 看畫面上的內容有沒有做分級判斷。
  → 沒有。總覽螢幕**原樣呈現**病人自己填的內容與自選的急迫度，不標任何風險等級 — 那屬於迭代 7 的高風險功能，閘門未開。

## 3.10 · 稽核軌跡的四類新事件（FR-S02）

- [ ] `l53` **［護理端］** 「稽核軌跡」依動作篩選，確認迭代 3 新增的四類都查得到。

## 3.12 · 實機驗收（兩項尚未執行）

> **說明｜為什麼另外列**
>
> 4.1 節七條驗收標準中，第 1 條（全新環境離線建置）與第 5 條（常駐總覽螢幕連續 4 小時、拔網路示警與自動重連）需要實機與實際時間，無法由驗收腳本代勞，其餘五條已由 `verify:iteration3` 涵蓋並通過。
> **狀態（2026-09-19 更新）：驗收 1 已執行並失敗，驗收 5 已執行並通過。**
>
> - **驗收 1 失敗**：`npm run prisma:migrate` 噴
>   `request to https://binaries.prisma.sh/... failed, reason: getaddrinfo ENOTFOUND binaries.prisma.sh`。
>   原因是 **Prisma 的執行引擎不在 npm 套件裡**，是安裝套件時由安裝後腳本另外下載的（約 40MB）；
>   只要 `node_modules` 是在沒有成功下載引擎的情況下產生的，第一次用到 Prisma 指令時就會現場去下載。
>   **這不是設定錯誤，是一個「套件裝好了不代表可以用」的相依**，對策見《部署規範》DEP-30，
>   實作排在迭代 7。修好之前，這一條驗收維持「未通過」。
> - **驗收 5 通過**：連續四小時不休眠、不斷線，拔網路後出現紅框與斷線橫幅，接回後自動重連。
>
> 以下原有的說明保留（2026-09-11 當時的狀況）： 開發環境已先做過模擬：停掉後端後總覽螢幕數秒內出現紅框與斷線橫幅，後端恢復後自動回到「即時連線中」；伺服器不在時重新載入頁面，也不會掉回登入畫面。

### 驗收 1 · 全新環境只設 DATABASE_URL，全程離線建置

- [ ] `m1` **［終端機］** 在專案目錄外的一個全新位置 clone 專案並安裝相依套件。
  → 這一步需要網路（下載套件），是整個驗收唯一允許連網的步驟。
- [ ] `m2` **［終端機］** 中斷網路（拔網路線或關閉 Wi-Fi），確認真的連不出去。
  → 開瀏覽器連任何外部網站都失敗。之後的步驟全程維持離線。
- [ ] `m3` **［終端機］** 建立 `.env`，只填 `DATABASE_URL`（指向一個尚不存在、專案目錄外的檔案）、`JWT_SECRET` 與兩個 `SUPER_ADMIN_*`。
  → 其餘一律留空，採程式內預設值。
- [ ] `m4` **［終端機］** 依序執行 `build:shared`、`prisma:migrate`、`db:seed`。

  → **2026-09-19 實測：這一步失敗。** 錯誤為 `getaddrinfo ENOTFOUND binaries.prisma.sh`。

#### 0919 的新驗收方式（修好之後照這個走）

上面那份流程有一個沒被注意到的假設：**它假設「連網時裝好的東西，離線時就一定用得起來」。**
Prisma 引擎打破了這個假設——`npm install` 成功不代表引擎真的躺在 `node_modules` 裡。

正式環境的交付形態也已經改了（不再是在主機上 clone 加安裝，而是**解開一份自帶執行期的離線安裝包**，
見《部署規範》第 3、6 章），因此這條驗收要改成貼近正式流程的版本：

- [ ] 在**連網的開發機**上建置離線安裝包（含 Node.js 執行期、建置產物、**Prisma 引擎**、遷移檔）
- [ ] 把安裝包複製到**一台乾淨的 Windows 機器**——沒有開發環境、沒有全域安裝的 Node.js、沒有這個專案的殘留
- [ ] **中斷那台機器的網路**，確認真的連不出去
- [ ] 解開安裝包 → 填 `.env` → 套用既有遷移 → 啟動服務
  → 全程不出現任何一次對外請求，服務正常啟動，三個網址都開得起來
- [ ] 跑零院外連線盤點 → 0 筆

**「在開發機上解壓來測」不算通過**：那樣測到的是開發機，不是安裝包（DEP-22）。

### 驗收 5 · 常駐總覽螢幕連續 4 小時，拔網路明顯示警、恢復後自動重連

用預定放在護理站的那台螢幕或平板做（位置與硬體待 Q-10 確認；確認前可用任一台會長時間開著的電腦）。

- [ ] `m7` **［護理端］** 以具「即時總覽」權限的帳號登入 →「總覽螢幕模式」→ 按「開始」。
  → 進入全螢幕；畫面底部顯示「防休眠：已啟用」「音效：開啟」。防休眠只在 HTTPS 或 localhost 下可用，顯示「不支援」時要改在作業系統關閉螢幕休眠與螢幕保護程式。
- [ ] `m8` **［護理端］** 放置 4 小時，期間不碰這台機器。
  → 螢幕沒有休眠、沒有出現斷線橫幅，底部「最後更新」時間持續前進。
- [ ] `m9` **［病人端］** 4 小時期間，用一台已綁定的平板按一次求助。
  → 總覽螢幕在數秒內出現該筆通報並發出提示音；無人接收時每 60 秒再提醒一次。
- [ ] `m10` **［護理端］** 拔掉總覽螢幕那台機器的網路線（或關閉 Wi-Fi）。
  → 最慢 45 秒內整個畫面出現紅框閃爍與「連線中斷」橫幅，並顯示正在第幾次重新連線。
- [ ] `m11` **［護理端］** 斷線期間用平板再按一次求助，然後接回網路。
  → 十幾秒內自動回到「即時連線中」，不需要任何人操作，斷線期間的那筆通報也補上畫面。

> **注意｜登入權杖 8 小時到期**
>
> `JWT_EXPIRES_IN` 預設 8 小時。4 小時的驗收不受影響，但總覽螢幕若全天開著，到期後會出現全螢幕的「登入已逾時」提示，需要重新登入。長時間顯示帳號的做法待 Q-10 一併確認。

驗收完成後，把日期、機器、瀏覽器與結果記進當週週報，並把本節標題的「尚未執行」拿掉。
