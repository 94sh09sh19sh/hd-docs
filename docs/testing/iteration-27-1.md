# 迭代 27.1 手動測試 — 病人平板頂列一列、任務醒著才出現、午夜前後的鎖

> 《[完整手動測試手冊](manual-test-guide.md)》的分冊之一，對應《實作規格書》4.27.1 節。共用的環境準備、啟動與疑難排解都在主手冊，這一冊只寫迭代 27.1 的部分。分析、量測與理由在《[迭代 27.1 修正紀錄](../notes/iteration-27-1-fixes.md)》。

## 摘要

這一冊驗四件事（項次 `ak19`～`ak36`，自動化另跑 `npm run verify:iteration27-1`）：

- 病人平板的基本資訊區在 1280×800 任何組合都是一列；狀態一次一句、結案只寫「已處理」
- 問卷與衛教只在病人醒著時自動出現，最多 2 次，自己關掉的不再出現；時點預設衛教 150、心情問卷 180 分鐘
- 首頁資料還沒回來不跳任務，換下一位病人看不到上一位的面板
- `npm run demo:patient` 午夜前後也能跑

| 標記 | 意思 |
|---|---|
| 🛠 **開發機** | 平常的 `npm run dev`，或 `npm run demo:patient`（另一個全新的資料庫，一位透析到一半的病人已配好平板）。這一次有一個新遷移（只改兩個營運參數的值） |
| 📐 **目標尺寸** | 病人端 1280×800。瀏覽器開發者工具的裝置模擬即可 |
| 📱 **平板** | 裝了外殼的平板；沒有平板時用部署規範 DEP-22 那一輪的開發手機 |

## §27.1.1 頂列一列

最壞組合：床號 A12、姓名 4 個字、1 個任務圖示、遊戲圖示、「護理師收到了」。開發機實量餘 59px（實作規格書 4.27.1 驗收現況）。

- [ ] `ak19` **［病人端］** 🛠 📐 1280×800，病人透析超過心情問卷時點（或把時點暫改成 0，見 `ak23`），心情問卷出現後按回首頁；開一款遊戲的開關；按「我需要協助」送出一則，護理端按「收到」。 → 基本資訊區**一列**：床號、姓名、進度條、任務圖示（只有一個）、遊戲圖示、「護理師收到了」、現在時間；進度條變短，其他都沒有被擠到第二列。
- [ ] `ak20` **［病人端］** 📐 接著用開發者工具把網路切成離線，在平板上回報一次症狀。 → 狀態**只剩「沒有網路」一句**（求助那一句不見，不是兩句並排）；仍是一列。螢幕閱讀器（或開發者工具的無障礙樹）讀得到「還有 1 筆回報等網路恢復後送出」。網路恢復後那一筆自動送出，狀態回到求助那一句。
- [ ] `ak21` **［護理端］** 結案這一則求助，處理方式與結果隨便選。 → 病人端那一句變成「**已處理**」，**沒有**處理方式或結果的字；開發者工具看 `GET /device/help-requests/mine` 的回應也沒有 `outcomeSummary`。「已處理」照舊留著，直到有新的求助。
- [ ] `ak22` **［病人端］** 🛠 📐 把病人的顯示名稱改成很長的外文名（例如 `Alexander Christopher`）再看首頁。 → 姓名只顯示大約 4 個字寬、以「…」收尾；其餘照舊一列。做完改回。
- [ ] `ak23` **［病人端］** 📐 心情問卷與衛教同時到期（兩個時點都暫改成 0）、兩個都按回首頁。 → 基本資訊區**只有一個任務圖示**（時點早的那個）；做完那一個，圖示換成另一個。

## §27.1.2 任務醒著才出現

「醒著」＝最近 2 分鐘碰過平板。病人碰完平板 1.5 秒才換成任務畫面，免得手指正好落在選項上。要讓任務立刻到期，用最高權限帳號在護理端「系統管理 → 營運參數與選項清單」把「心情問卷出現時點」或「衛教出現時點」暫改成 0（做完改回）。

- [ ] `ak24` **［護理端］** 🛠 系統管理 → 營運參數與選項清單，看兩個時點。 → 預設**心情問卷 180、衛教 150** 分鐘（新的資料庫；舊的資料庫原本是 120／180 也已被遷移改成這兩個值）；填 226 存不進去，寫明上限 225。
- [ ] `ak25` **［病人端］** 🛠 病人端開著首頁，**超過 2 分鐘不碰**，再把心情問卷的時點改成 0。 → 等一分鐘以上，**任務不自動出現**，只有基本資訊區的圖示。
- [ ] `ak26` **［病人端］** 碰一下首頁任何地方（不按按鈕）。 → 約 1.5 秒後心情問卷以全螢幕出現。
- [ ] `ak27` **［病人端］** 不碰，等閒置門檻（預設 60 秒）讓它自己回首頁；再碰一下。 → 回首頁之後碰一下，**再自動出現一次**（閒置回首頁的不算病人關掉的）。
- [ ] `ak28` **［病人端］** 再一次讓它閒置回首頁，然後碰一下。 → **不再自動出現**（每個任務最多 2 次，含閒置那次）；圖示照留，點圖示接著做。
- [ ] `ak29` **［病人端］** 換衛教：時點改成 0，碰一下讓它出現，**按回首頁**（🏠）。之後持續碰平板超過 20 分鐘。 → 衛教**不再自動出現**（病人自己關掉的）；圖示照留。
- [ ] `ak30` **［病人端］** 另一項任務到期時，先按「我需要協助」送出一則，再碰平板。 → 求助還沒結案時**不自動出現**；護理端結案後 15 分鐘內也不出現，之後碰平板才出現。
- [ ] `ak31` **［病人端］** 兩項任務都到期、都還沒自動出現過，碰平板。 → 時點早的那一個先出現；做完之後另一個**至少隔 20 分鐘**才自動出現（期間只有圖示）。
- 開始後 225 分鐘起不再自動出現、圖示照留到下機：由 `verify:iteration27-1` 第 3 步餵情境驗，手動不必等四小時。

## §27.1.3 首頁資料只用這次綁定的

- [ ] `ak32` **［病人端］** 🛠 病人透析超過 180 分鐘時，開發者工具把網路切成離線再重新整理平板。 → 首頁資料拿不到的那段時間**不跳心情問卷或衛教**（不以寫死的分鐘數判斷）；網路恢復、首頁資料回來後才照規則判斷。
- [ ] `ak33` **［護理端］** 🛠 解除這台平板的綁定，配給另一位病人。 → 平板換人之後的**第一個畫面沒有上一位的面板**（數字、圖、跑馬燈都不是上一位的），姓名是新的那一位。

## §27.1.4 午夜前後

- [ ] `ak34` **［終端機］** 🛠 在 00:00～01:40 之間執行 `npm run demo:patient`。 → **照常啟動**，配得到透析中的「模擬戊」（開始時間是當天，透析了大約「現在減 00:00」那麼久，曲線短一點）。27.1 以前這段時間會說找不到人。跑著跨過午夜，清單會變空，**重開一次**即可；正式系統沒有療程跨過午夜，不受影響。
- [ ] `ak35` **［終端機］** 23:00～24:00 執行 `npm run verify:iteration24`。 → 拒跑，訊息寫出原因（跑到一半跨日、第幾次療程會對不上）與「00:00 以後再跑」；`verify:iteration15:api`、`16:api`、`25:api` 在各自的時段一樣寫出原因與幾點以後可以跑。

## §27.1.5 自動化驗收

- [ ] `ak36` **［終端機］** `npm run verify:iteration27-1`（不需要後端，要先 `npm run build:shared`）、`npm run verify:iteration27-1:api`（要 Prisma，不必開後端；暫存資料庫跑完就刪）；後端開著時 `npm run verify:iteration5`、`npm run verify:iteration14`。 → 都通過（5 與 14 的檢查隨需求改了，實作規格書之一第二十二次）。
