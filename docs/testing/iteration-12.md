# 迭代 12 手動測試 — 外殼 App 獨立 repo 與整合

> 《[完整手動測試手冊](manual-test-guide.md)》的分冊之一，對應《實作規格書》4.10 節。
> 共用的環境準備、啟動與疑難排解都在主手冊，這一冊只寫迭代 12 的部分。
> 操作端色籤（**護理端**／**病人端**／**終端機**／**資料庫**）的意思見主手冊 §00；本冊另加 **［手機］**。

**這一冊驗的是「外殼與系統只靠一份契約對得起來」。** 外殼的原始碼搬到另一個私人 repo（`hd-kiosk-shell`），
APK 由 `shell-builder` 在主機上建置與簽章，開發手機從病人端的院內下載頁安裝。
契約本身見《[病人端外殼 App 契約](../reference/kiosk-shell-contract.md)》，步驟見《[部署手冊](../deployment/index.md)》第十二冊。

| 標記 | 意思 |
|---|---|
| 🖥 **開發機** | 平常的開發環境（有 Node.js），用來做檢查與驗收腳本 |
| 🐳 **開發機，只用 Git 與 Docker** | 部署實測。這一段用到 `npm`、`node` 就不算數 |
| 📱 **開發手機** | Android 手機當平板用，與開發機在同一個 Wi-Fi |

## 12.1 · 外殼只在一個地方（DEP-45）🖥

- [ ] `v1` **［終端機］** 看 `apps/` 目錄。
  → 只有 `api`、`nurse-pwa`、`patient-pwa`；**沒有 `kiosk-shell`**。
- [ ] `v2` **［終端機］** `npm run` 列出所有指令。
  → 沒有 `cert:hospital-ca`；有 `verify:iteration12` 與 `verify:iteration12:api`。
- [ ] `v3` **［終端機］** 開外殼 repo 的 `README.md`。
  → 開頭就指向本 repo 的 `docs/reference/kiosk-shell-contract.md`，而且寫明「真本在那裡，這裡不另寫一份」。
- [ ] `v4` **［終端機］** 在外殼 repo 執行 `git log --oneline`。
  → 最早的一筆是 0921 的「迭代 10——打包、平板佈建與部署演練」：**歷史是搬過來的，不是重新開始**。

## 12.2 · 契約在後端與護理端的那一半（FR-S14）🖥

先 `npm run dev`。

- [ ] `v5` **［終端機］** `curl.exe -s http://localhost:3000/api/device/shell-contract`
  → `{"contractVersion":1,"minShellVersion":"0.2.0"}`。**不需要登入、不需要序號與金鑰**，也只有這兩個欄位。
- [ ] `v6` **［終端機］** `npm run verify:iteration12:api`
  → 全部 ✓：未回報版本、版本正常、外殼過舊、版本不相容四種狀態都出現過；只帶一半的回報回 400。
- [ ] `v7` **［護理端］** 裝置管理 → 平板清單。
  → 多了「外殼版本」欄；`v6` 建的那台 `V12-TAB-…` 標著**版本正常**，下面一行小字 `0.2.0`；其餘平板是**未回報版本**（灰）。
- [ ] `v8` **［護理端］** 稽核軌跡，動作選「平板程式版本變更」。
  → `V12-TAB-…` 有四筆，每一筆寫著「由……變為……」（未回報 → 0.2.0 → 0.1.999 → 契約第 2 版 → 契約第 1 版）；
  **同一個版本重複回報的那幾次沒有多出紀錄**。
- [ ] `v9` **［病人端］** 在一般瀏覽器開病人端，照常佈建一台平板。
  → 畫面與以前一樣；護理端那一台的「外殼版本」維持**未回報版本**（瀏覽器沒有外殼）。

## 12.3 · `shell-builder` 建出 APK，第二次不重新產生金鑰（驗收 2）🐳

以下 `$cfg` 是暫存的 `config\.env`，指令在 repo 根目錄執行。

- [ ] `v10` **［終端機］** `docker compose --env-file $cfg --profile shell build shell-builder`
  → 第一次要下載 Android SDK、Gradle 與相依，視網速十幾分鐘到半小時。最後一段印出
  「✓ 外殼 v0.2.0（…，契約第 1 版）已準備好，相依已下載」。
- [ ] `v11` **［終端機］** `docker compose --env-file $cfg --profile shell run --rm shell-builder`
  → 印出「這一次新產生：院內 CA 伺服器憑證（<IP>） APK 簽章金鑰（開發用）」，以及 APK 檔名與三個 SHA-256。
- [ ] `v12` **［終端機］** 同一個指令再跑一次。
  → 「**金鑰全部沿用，這一次沒有產生任何新的金鑰**」；三行「· 沿用既有的……」；APK 的簽章憑證 SHA-256 與 `v11` 相同。
- [ ] `v13` **［終端機］** `docker compose --env-file $cfg --profile shell run --rm shell-builder keys-info`，跑兩次。
  → 兩次輸出一模一樣：用途 `dev`、院內 CA 指紋與十年後的到期日、伺服器憑證 `IP Address:<IP>`、簽章金鑰指紋。
- [ ] `v14` ⚠ **［終端機］** `docker compose --env-file $cfg --profile shell run --rm -e SHELL_SIGNING_PROFILE=hospital shell-builder`
  → **拒絕執行**：「這個金鑰資料卷是『dev』用的，設定卻是『hospital』。開發機的金鑰不得拿到院內用……」。
- [ ] `v15` ⚠ **［終端機］** 把 `shell.pin` 的 `SHELL_TAG` 暫時改成 `v9.9.9`，重跑 `v10`。
  → 映像檔建置失敗：「外殼 repo 的 clone 裡沒有 tag v9.9.9。在主機上到外殼 repo 的目錄執行 git fetch --tags 之後重建。」
  **改回 `v0.2.0`**，再跑一次 `v10`。
- [ ] `v16` **［終端機］** `docker compose --env-file $cfg --profile shell run --rm --entrypoint sh shell-builder -c "ls -la /keys /keys/tls /keys/public; getent hosts github.com || echo 無網路"`
  → `ca/`、`signing/` 是 `drwx------`；`tls/server.key` 的擁有者是 `1000`；`public/` 有 APK、`index.html`、`shell.json`；最後一行是「無網路」。

## 12.4 · HTTPS、同一個來源與下載頁（契約第 6 節）🐳

- [ ] `v17` **［終端機］** `docker compose --env-file $cfg restart patient-web`，再 `docker compose --env-file $cfg logs patient-web --tail 5`
  → 「靜態資源已提供於連接埠 8081（HTTPS；HTTP 只留外殼下載頁）」「/api/ 轉送至 http://api:3000」「/shell/ 外殼下載頁取自 /keys/public」。
- [ ] `v18` **［病人端］** 開發機的瀏覽器開 `http://<IP>:<病人端埠>/shell/`
  → 下載頁：一顆「下載 App（版本 0.2.0）」、安裝步驟、主機位址 `https://<IP>:<病人端埠>`、**開發用簽章的黃色警示**、三個 SHA-256。沒有任何憑證警告。
- [ ] `v19` **［病人端］** 開 `http://<IP>:<病人端埠>/`
  → 被轉到 `https://…`，瀏覽器跳出「連線不是私人連線」——**這是對的**：開發機的瀏覽器不信任院內 CA，平板上的外殼才信任。
- [ ] `v20` **［終端機］** 先取出院內 CA：
  `docker compose --env-file $cfg --profile shell run --rm --entrypoint cat shell-builder /keys/ca/ca.crt > ca.crt`，
  再 `curl.exe -s --cacert ca.crt https://<IP>:<病人端埠>/api/device/shell-contract`
  → 回契約版本。**只信任院內 CA 就通**，而且 `/api/` 是從病人端的埠轉過去的。
- [ ] `v21` **［終端機］** 同上但不帶 `--cacert`。
  → `curl: (60) SSL certificate problem`。

## 12.5 · 開發手機從下載頁安裝並載入病人端（驗收 3）📱

- [ ] `v22` **［護理端］** 裝置管理 → 註冊新平板 `DEV-PHONE-01`。
  → 金鑰只顯示一次，抄下來。顯示的網址以 `https://<IP>:<病人端埠>/` 開頭。
- [ ] `v23` **［手機］** 設定 → 安全性：開啟螢幕固定，勾選「解除固定前要求 PIN」。
- [ ] `v24` **［手機］** Chrome 開 `http://<IP>:<病人端埠>/shell/`，按「下載 App」，安裝。
  → 可能要允許 Chrome 安裝不明來源的應用程式；安裝完成，桌面出現「透析照護平板」（深綠圓底白十字）。
- [ ] `v25` ⚠ **［手機］** 開啟 App，主機位址故意填 `http://<IP>:<病人端埠>`。
  → 跳出「主機位址要以 https:// 開頭」，不儲存。
- [ ] `v26` **［手機］** 改填 `https://<IP>:<病人端埠>`、序號 `DEV-PHONE-01`、`v22` 的金鑰，按「儲存並啟動」。
  → 系統跳出「要固定這個應用程式嗎」——**先按「取消」**（§12.6 再釘）。畫面載入病人端的等待畫面，**沒有任何憑證警告**；看不到金鑰。
- [ ] `v27` **［護理端］** 裝置管理，等 15 秒。
  → `DEV-PHONE-01`：固定狀態「**已跳出**」（還沒釘）、外殼版本「**版本正常**」`0.2.0`。
- [ ] `v28` **［護理端］** 把一位病人指派到 `DEV-PHONE-01`。
  → 手機出現病人畫面；送出一次透析前問卷與一次求助，護理端即時看到。**這證明 `/api/` 經病人端的埠轉送是通的。**

## 12.6 · 釘住、退不出去、跳出時護理端看得到（驗收 4）📱

- [ ] `v29` **［手機］** 把 App 從多工畫面滑掉，再開啟一次。
  → 啟動時再跳一次「要固定這個應用程式嗎」，按「確定」。
- [ ] `v30` **［護理端］** 15～30 秒內。
  → `DEV-PHONE-01` 變成「**固定中**」。
- [ ] `v31` **［手機］** 按上一頁鍵、首頁鍵、多工鍵，從上方往下滑。
  → 都離不開 App；系統列滑出來一下又自己收回去。
- [ ] `v32` **［手機］** 依手機的解除方式解除固定（多半是同時按住上一頁鍵與多工鍵）。
  → 要求輸入 PIN 才解除；輸入後回到鎖定畫面。
- [ ] `v33` **［護理端］** 從解除那一刻起計時。
  → **30 秒內**變成「**已跳出**」，底下一行「…起」。
- [ ] `v34` **［手機］** 解鎖，App 仍停在前景但**沒有釘住**。
  → 護理端維持「已跳出」（不是「固定中」）——**這一條是迭代 12 修的**：以前只看畫面可不可見，這裡會誤報成固定中。
- [ ] `v35` **［手機］** 重新開機。
  → 開機後 App 自己起來並跳出固定確認框；按「確定」後護理端回到「固定中」。

## 12.7 · 最低可用版本調高、契約不相容（驗收 5、6）🐳＋📱

- [ ] `v36` **［終端機］** 暫存 `config\.env` 的 `KIOSK_SHELL_MIN_VERSION=0.2.1`，`docker compose --env-file $cfg up -d api`（只重建 api 容器，不重建映像檔）。
- [ ] `v37` **［護理端］** 裝置管理，15 秒內（不必等手機再回報）。
  → `DEV-PHONE-01` 變成「**外殼過舊**」（琥珀色）`0.2.0`；手機上**沒有任何變化**（還能用）。
- [ ] `v38` **［終端機］** 改回空白，再 `up -d api`。
  → 回到「版本正常」。
- [ ] `v39` ⚠ **［終端機］** 做一支契約第 2 版的外殼：在外殼 repo 開一個本機分支，`gradle.properties` 改成 `hdShellVersion=0.2.1`、`hdShellContractVersion=2`，提交並打**本機** tag `v0.2.1`（不推）；本 repo 的 `shell.pin` 暫時改成 `v0.2.1`、`2`；重跑 `v10`、`v11`。
  → 建置成功，下載頁變成 0.2.1。
- [ ] `v40` **［手機］** 從下載頁下載 0.2.1 覆蓋安裝，開啟。
  → 覆蓋安裝成功（同一把開發用簽章金鑰）；**畫面上方出現琥珀色提示列**：「這台平板的程式與系統版本不相容……（平板：第 2 版／系統：第 1 版）」；**下方的求助區照常可按**。
- [ ] `v41` **［護理端］** 裝置管理。
  → `DEV-PHONE-01` 變成「**版本不相容**」（紅）`0.2.1`；稽核多一筆「平板程式版本變更」。
- [ ] `v42` **收尾**：`shell.pin` 改回 `v0.2.0`、`1`；外殼 repo 刪掉本機 tag `v0.2.1` 與那個分支；重跑 `v10`、`v11`。
  手機要**先解除安裝**再從下載頁裝 0.2.0（Android 不准版本往下覆蓋）；重新佈建後提示列消失、護理端回到「版本正常」。

## 12.8 · 金鑰備份與核對（DEP-35）🐳

- [ ] `v43` **［終端機］** `docker compose --env-file $cfg --profile shell run --rm shell-builder keys-backup`
  → 「已備份：備份目錄/keys/hd-keys-<時間>.tar.gz」、SHA-256，與一行「這份檔案裡有 CA 與簽章的私鑰……不得出院」。暫存的 `backups\keys\` 底下看得到它。
- [ ] `v44` **［終端機］** `… run --rm shell-builder keys-verify`
  → 四個檔案逐一 ✓、「簽章金鑰以備份裡的密碼打得開」、「CA 私鑰完整」、「還原得回來」。
- [ ] `v45` ⚠ **［終端機］** 把那份備份複製一份，用 7-Zip 之類的工具刪掉裡面的 `signing/keystore.pass` 再壓回去，對它跑 `keys-verify <檔名>`。
  → 「✗ 備份裡沒有 signing/keystore.pass」「這份備份不能用」，結束狀態非零。**刪掉這份壞的。**

## 12.9 · 自動化驗收 🖥

- [ ] `v46` **［終端機］** `npm run verify:iteration12 -- --shell-src <外殼 repo 的 clone>`
  → 靜態部分全部 ✓；最後列出要在別處驗的兩項。
- [ ] `v47` **［終端機］** `npm run verify:iteration12 -- --live --env-file <暫存的 config\.env>`
  → 加上 Docker 上的部分全部 ✓：兩次 build、指紋相同、換用途被拒、下載頁與 APK、HTTP 轉 HTTPS、只信任院內 CA 就連得上、不信任就連不上。
- [ ] `v48` **［終端機］** `npm run check:all`
  → 六支全綠；「容器設定」多了金鑰資料卷與 `shell-builder` 網路兩項，「零院外連線」的外殼那一節改掃 `shell-builder`。
