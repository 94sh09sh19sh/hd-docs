# 迭代 18 手動測試 — 規則引擎與三項高風險功能

> 《[完整手動測試手冊](manual-test-guide.md)》的分冊之一，對應《實作規格書》4.16 節（做法在 3.6 末段「1010 迭代 18 實作結果」、開關在 3.7）。
> 共用的環境準備、啟動與疑難排解都在主手冊，這一冊只寫迭代 18 的部分。
> 操作端色籤（**護理端**／**病人端**／**終端機**／**資料庫**）的意思見主手冊 §00。
> 項次用 `ab`（實作規格書 4.0.5 排好的字母），從 `ab1` 起。

**這一冊驗四件事**：四項判斷輔助（風險分層提示、療程中預警、劑量調整參考、透析適足性趨勢推估）由規則計算、**不經 AI**，每一則都點得開依據、旁邊有「僅供參考，非診斷結果」；
書面確認閘門沒開時**只對合成資料病人執行**，真實病人擋下並記錄；規則版本沒有書面依據標不了生效、用過就改不了；開關關掉，內容與端點一起消失。

| 標記 | 意思 |
|---|---|
| 🛠 **開發機** | 平常的 `npm run dev`（資料庫先套用新遷移：`npm run prisma:migrate` 或 `db:update`）。**開發機的 `.env` 不得填 `HIGH_RISK_WRITTEN_CONFIRMATION`** |
| 🧪 **模擬部署** | 開發機上照部署手冊第十五冊以容器部署的那一套 |
| 📐 **目標尺寸** | 護理端 1366×768 |

**前置**：`.env` 有 `SUPER_ADMIN_WORK_ID`、`SUPER_ADMIN_INITIAL_PASSWORD`；一位護理長帳號（看得到「判斷規則」、改不了）與管理者帳號（建立、標為生效）。
有東西可看要有**同一位合成病人的幾次歷史療程**（院方量測、按過的求助）、血紅素與適足性計算。最快的做法是 `ab12` 那一條：後端驗收加 `--keep`，它建一位合成病人、比對一次、把開關留著開。

## §18.1 開關全關時不存在

- [ ] `ab1` **［護理端］** 📐 四個判斷輔助開關都關著，專業版看即時總覽與病人趨勢。
  → 即時總覽底下**沒有**「判斷輔助」那一塊；病人趨勢**沒有**「判斷輔助」那張卡；畫面上沒有灰色按鈕、沒有「敬請期待」。
- [ ] `ab2` **［護理端］**／**［病人端］** 不管開關開不開，看簡易版、總覽螢幕模式、病人平板。
  → 三處都沒有任何判斷輔助的內容（只放專業版；判讀不給病人看）。
- [ ] `ab3` **［終端機］** 開關全關時，以護理師的權杖打 `GET /api/rules/outputs/pending` 與 `POST /api/rules/evaluate`。
  → 兩支都是 404「此功能未啟用」。

## §18.2 判斷規則與書面確認閘門

- [ ] `ab4` **［護理端］** 以護理長登入 → 系統管理。
  → 分頁多一個「**判斷規則**」（在功能開關後面）；看得到每一條規則與版本，**沒有**「以此版為底建立新版本」「標為生效」那幾顆。一般護理師沒有系統管理的這一頁。
- [ ] `ab5` **［護理端］** 判斷規則最上面的「書面確認閘門」。
  → 「**尚未登記**」，說明寫著只對合成資料病人執行、真實病人一律擋下、登記方式是在院內主機的設定檔填文號後重新啟動、畫面上不能改。**沒有任何開關或按鈕能改它**。
- [ ] `ab6` **［護理端］** 往下看六條規則（順序：風險分層兩條、療程中預警兩條、劑量調整參考、適足性推估）。
  → 每一條第 1 版、「草稿（只對合成資料執行）」、建立者「系統預設」。RISK-HYPO-01、ALERT-HYPO-01 的書面依據出處寫著同院 IDH 系統；其餘四條「未附（標不了生效，只對合成資料執行）」，備註寫「合成資料示範值」。
  → DOSE-HB-01 下面的條文寫著「【合成資料示範用，不是院方 protocol】…」。畫面上沒有需求編號、待確認編號。
- [ ] `ab7` **［護理端］** 以管理者登入看同一頁。
  → 沒附出處的那四條**沒有**「標為生效」；附了出處的兩條有。
  → **［終端機］** 直接打 `POST /api/rules/versions/<沒附出處的版本>/activate`（理由隨便填）→ 409「沒有書面依據出處的規則版本不能標為生效…」；稽核軌跡多一筆「判斷規則版本的變更遭拒」。
- [ ] `ab8` **［護理端］** 任一條「以此版為底建立新版本」，把「符合時的文字」改成「符合 {規則}：病人有低血壓風險，建議調整脫水量。」，填理由 → 建立新版本。
  → 擋下，逐字列出「風險」「建議」「低血壓」「病人有」，請改成只陳述數值與次數；沒有建立任何版本。範本寫了不認得的欄位（例如「{不存在}」）也一樣擋下。
- [ ] `ab9` **［護理端］** 同一個表單把文字改回來、把某個門檻改一個數字 → 建立新版本。
  → 那一條多一個「第 2 版」草稿，執行紀錄 0 筆，有「修改這個草稿」；改了再存也成功。稽核軌跡兩筆（建立、修改），寫著門檻與理由。

## §18.3 開啟開關

- [ ] `ab10` **［護理端］** 系統管理 → 功能開關，看「臨床判斷輔助（開啟前需書面確認）」那一組。
  → 四項：風險分層提示、療程中預警、劑量調整參考、**透析適足性趨勢推估**；開啟條件的說明寫著書面確認尚未登記、只對合成資料病人執行、生效中與草稿各幾個版本。開啟要填核准依據。
- [ ] `ab11` **［護理端］** 只開「透析適足性趨勢推估」、「需要抽血數值的功能」關著。
  → 病人趨勢沒有「判斷輔助」卡（適足性推估要兩個都開才看得到）；把抽血數值也開了才出現。

## §18.4 合成病人的比對、依據與檢視

- [ ] `ab12` **［終端機］** 後端開著、四個判斷輔助開關全關，跑 `npm run verify:iteration18:api -- --keep`。
  → 全部通過；最後一行說留下合成病人 `HD-TEST-V18-<六碼>` 與比對結果、四個開關開著。
- [ ] `ab13` **［護理端］** 📐 專業版即時總覽，往下捲。
  → 求助表格下面一塊「**判斷輔助：待檢視 N 則**」。每一則：功能名稱、病人姓名與病歷號、時間、「合成資料」、「待檢視」；一句以「符合 <規則代號>：」開頭的事實陳述（數值、次數、時間），**沒有**「風險」「診斷」「建議」這類字；下面一條「僅供參考，非診斷結果。」。**整塊沒有紅色**，求助表格每一列的順序與顏色沒有因此改變。
- [ ] `ab14` **［護理端］** 任一則按「看依據」。
  → 展開：規則代號與名稱・第幾版（比對時：草稿）、怎麼比對、門檻（中文名稱與單位）、**引用的資料**（每一筆的值、時間、來源）、書面依據出處（未附時寫明只對合成資料執行）、文字範本、誰按的或定時比對。再按一次收合。
- [ ] `ab15` **［護理端］** 劑量調整參考那一則。
  → 事實陳述後面接著「所依據的 protocol 條文：「…」」，括號裡與系統管理那一頁的條文**一字不差**。
- [ ] `ab16` **［護理端］** 一則按「已檢視・採納」；另一則按「已檢視・未採納」、填「病人自述今天水喝得多」→ 送出未採納。
  → 兩則都**沒有跳確認**、馬上離開待檢視，標題的則數少 2。系統管理 → 稽核軌跡查「檢視判斷輔助輸出（是否採納）」，兩筆，未採納那筆寫著原因。沒標記的那幾則**還在**，重新整理也還在。
- [ ] `ab17` **［護理端］** 病人趨勢 → 選那位合成病人。
  → 最上面「判斷輔助」：血紅素趨勢圖（只畫量測值，沒有上下限的線）、比對結果（含剛才標記過的，標「已檢視・採納／未採納（誰）」）。按「立即比對」→「比對完成，沒有新的結果（同一筆資料比對過就不再重複）」。

## §18.5 真實病人擋下

- [ ] `ab18` **［護理端］** 病人趨勢選一位病歷號**不是** `HD-TEST-` 開頭的病人（`verify:iteration18:api` 建的「王真實」那一類），按「立即比對」。
  → 紅色錯誤條「書面確認尚未登記：判斷規則只對合成資料病人執行，這位病人不比對」；比對結果仍是空的。
- [ ] `ab19` **［護理端］** 稽核軌跡查「判斷規則比對遭擋下：真實病人」。
  → 有剛才那一筆，寫著哪幾項、書面確認閘門未開。

## §18.6 用過的版本改不了

- [ ] `ab20` **［護理端］** 判斷規則，看 `ab12` 比對時用到的版本（執行紀錄大於 0）。
  → 沒有「修改這個草稿」。**［終端機］** 直接打 `PUT /api/rules/versions/<那一版>` → 409「已有 N 筆執行紀錄指向這一版，不能修改；要改門檻請以它為底建立新版本」。
- [ ] `ab21` **［護理端］** 以那一版為底建立新版本（改一個門檻），回病人趨勢按「立即比對」。
  → 那一條規則多一則新版本的比對結果；**舊的那一則看依據仍是舊版本**。新版本用過之後也沒有「修改這個草稿」了。

## §18.7 開關關閉

- [ ] `ab22` **［護理端］** 系統管理只關「劑量調整參考」（填依據），回即時總覽與病人趨勢。
  → 待檢視與比對結果裡劑量調整參考的那幾則**不見了**，血紅素趨勢圖也不見；其他三項照舊。
- [ ] `ab23` **［護理端］** 四項全關。
  → 即時總覽的「判斷輔助」與病人趨勢的卡**整個不出現**（回到 `ab1` 的樣子）；`ab3` 的兩支端點又是 404。測完記得四項都是關的。

## §18.8 院內的閘門設定

- [ ] `ab24` **［終端機］** 🧪 模擬部署設定目錄的 `.env`，確認 `HIGH_RISK_WRITTEN_CONFIRMATION=` 是空的（範本預設就是空的），重新啟動 api 後看系統管理「判斷規則」。
  → 「尚未登記」。**院內主機在 Q-02 的書面確認拿到之前不得填這一項**（部署手冊第十五冊之一）；填了文號重新啟動，這一頁會顯示「已登記（文號）」，稽核軌跡記下閘門狀態的改變。

## §18.9 臨床端逐句讀、自動化驗收

- [ ] `ab25` **［護理端］** 請醫師或護理長看系統管理「判斷規則」六條規則的文字範本，與 `ab13` 的一輪比對結果，**逐句**讀一次。
  → 讀起來是事實（數值、次數、時間），不是結論；有疑慮的字記下來，以新版本改範本（驗收第 3 條的人工那一半）。
- [ ] `ab26` **［終端機］** `npm run verify:iteration18`（不需要後端）；後端開著、四個開關關著，再跑 `npm run verify:iteration18:api`（不帶 `--keep`）。
  → 兩支都全部通過（前一支會再跑 `check:ui`、`check:ui:design`、`check:egress`、`verify:iteration14`、`17-8`；後一支結束時刪掉自己建的資料與版本、把開關改回原狀）。
