    這套系統是用什麼蓋的 — 給非技術背景的人¶

    這頁不談程式，只用「蓋房子」把技術名詞講清楚，讓沒有工程背景的人也能聽懂會議上冒出來的那幾個詞。 需要精確定義與版本決策，請看實作規格書。

    本頁 2026-10-05 更新，對應迭代 17 完成時的系統。 0926 之後有三件事跟 0923 版不一樣：交付方式又換回「貨櫃」（Docker 容器＋git clone，離線安裝包撤除）、 AI 閘道搬出機房自成一間小屋（換了一種建材），以及病人平板上的外殼 App 移到另一個 repo。 1005 再多一件：病人、床位與療程改由院方的透析紀錄 API 每幾分鐘送進來，機房裡「臨床資料匯入」那個房間換成了「院方資料同步」（第五節）。 這件事沒有多蓋任何一棟樓，也沒有用到新的建材。

    先講結論¶

    專案裡的名詞 蓋房子裡的角色 一句話
    TypeScript 主要建材 前棟、後棟機房都用這一種建材
    React 19 蓋「前棟」的工法 病人與護理師看得到、摸得到的那兩棟
    NestJS 11 蓋「後棟機房」的工法 沒有人會走進去，但全部管線與門禁都在裡面
    Prisma 6 管線轉接頭 房子接到資料庫的標準接頭，換資料庫不必重拉全屋管路
    SQLite 自家地下室的水塔 資料庫就是院內那台主機上的一個檔案，不接外面的自來水
    Vite 6 施工機具 蓋的時候用，交屋後不留在房子裡
    PWA 組合屋式的門面 用網頁技術蓋的應用程式，不必送 App Store 審核
    Docker 容器＋git clone 照同一份圖說，在對方基地上把幾間標準貨櫃屋組起來 0926 起的交付方式：院內主機自己拿圖說（git clone）、自己組貨櫃（Docker），資料放在貨櫃外面另一座上鎖的倉庫
    Python ＋ LangChain AI 閘道那間小屋的另一種建材 0927 起 AI 閘道自成一間，照實驗室的規範用這一套蓋
    外殼 App 平板上那一層防護玻璃 把病人端畫面裝進去、鎖在最上層的一支 Android 小程式，另一個 repo 維護
    院方 API 隔壁醫院大樓牆上的抄表口 1005 起本系統每 3 分鐘去抄一次院方的透析紀錄，只抄、不寫回

    一、基地上有三棟樓，外加兩間小屋¶

          ┌──────────────┐        ┌──────────────┐
      │  病人端 PWA  │        │  護理端 PWA  │   ← 前棟：有門面，人在裡面操作
      │（裝在外殼裡）│        │  護理站主控台│
      └───────┬──────┘        └──────┬───────┘
              └───────────┬──────────┘
                  ┌───────┴────────┐        ┌──────────────┐
                  │   後端 API     │───────→│   AI 閘道    │ ← 小屋：只負責轉話給 AI
                  │  （伺服器）    │        │  （Python）  │
                  └───────┬────────┘        └──────────────┘
                  ┌───────┴────────┐        ┌──────────────┐
                  │    資料庫      │        │  外殼工坊    │ ← 小屋：只在要做 App 時開門
                  └────────────────┘        └──────────────┘
    • 前棟兩棟：病人端是床邊平板的畫面（不必登入，像大樓的公共大廳）；護理端是護理站的主控台（要驗證身分，像有門禁的辦公樓層）。 護理端 0927 起分成簡易版（每次登入的預設，一張床位圖、拖一下就完成一件事）與專業版（原本那一套，不動）。
    • 後棟一棟：所有規則、驗證、稽核紀錄都在這裡執行。病人與護理師永遠不會直接碰到資料庫，一律要透過後棟轉手。
    • 資料庫：自家地下室的一座水塔。它就在後棟那台主機裡，是一個檔案，不接外面的水，外面也接不進來。理由是資料一律不出醫院（見第六節）。
    • 兩間小屋（0927 新增）：
    • AI 閘道：後棟要問 AI 時，一律把話交給這間小屋轉過去。小屋自己不藏任何 AI 模型，只知道「話要轉到哪一台機器」。 換一台 AI 機器，只改小屋牆上那張地址表（設定檔），後棟一行都不用動。
    • 外殼工坊：平時關著。要做病人平板用的那支 App 時才開門，在院內主機上把 App 做好、蓋上院內的印章（簽章）， 放到院內的下載頁讓平板來拿。做 App 的時候這間工坊是斷網的——手上拿著印章的時候，不接任何外線。

    二、建材：TypeScript，外加一種¶

    前棟、後棟三棟樓都用同一種建材，所以工程師換棟工作不必重學一種語言。

    它跟一般建材（JavaScript）的差別在於：每一根都事先裁切好、貼上尺寸標籤。

    蓋的時候，工人拿一根梁要往柱子上裝，標籤對不起來就當場被擋下來，根本裝不上去 —— 這叫「編譯時檢查」。 房子蓋完交屋時，標籤會被撕掉，真正立在那裡的還是原本的建材。

    實務上的意義：很多錯誤在還沒交給臨床端使用之前，就已經被擋掉了，而不是等病人按下去才發現。

    AI 閘道那間小屋是例外，用的是 Python。 不是工程師想換口味，而是實驗室的使用規範就是這樣寫的： 要借用實驗室的 AI 機器，就照它規定的寫法（Python 加一套叫 LangChain 的工具）來接。 小屋只有一扇門對著後棟，門口的規矩講好了（「把這段話轉給 AI、把回答帶回來」）， 所以兩邊用不同建材不會互相干擾。

    三、工法：React 19 與 NestJS 11¶

    這兩個是同一層級的東西，都叫「框架」。框架不只是規範，它還附贈一整批預鑄件——牆板、樓梯、電箱都幫你做好，你只要組。

    React 19 NestJS 11
    負責 前棟（病人端、護理端） 後棟機房
    幫你準備好的預鑄件 畫面怎麼組、按下去畫面怎麼跟著變 門禁、路由、排程、稽核掛勾
    使用者感受得到嗎 感受得到，就是操作的手感 感受不到，但它壞了全樓停擺

    一個常見的誤會¶

    很多人會把它們理解成「React 管外觀、NestJS 管內部」。這個說法會誤導。

    護理端要排班、要即時更新病人狀態、要處理呼叫，這些邏輯又多又複雜，全部發生在前棟裡，一點都不「外觀」。 比較準的講法是前棟與後棟：差別在「人走不走得進去」，不在「複不複雜」。

    四、其他會聽到的名詞¶

    • PWA（漸進式網頁應用程式） 用網頁技術做的應用程式。可以像一般 app 一樣釘在平板首頁、全螢幕開啟，但不必上架 App Store、不必逐台更新——伺服器改好，平板下次開就是新版。對院內幾十台平板來說，這省掉的是每次改版逐台更新的人力。

    • 外殼 App（平板上的防護玻璃） 病人端本身是網頁，但病人平板不能開著一般瀏覽器——病人會滑到別的地方去。所以另外做了一支很薄的 Android 程式， 它唯一的工作是把病人端畫面裝進去、鎖在最上層：全螢幕、長按沒有選單、開機自己起來，再加上 Android 內建的「螢幕固定」，病人退不出去。 0927 起它搬到另一個 repo 維護，兩邊靠一份寫好的「契約」對齊（《病人端外殼 App 契約》）： 就像大樓和門窗廠各做各的，但門框的尺寸事先講定，而且寫了版本號——哪天尺寸改了，兩邊一對就知道裝不裝得上。 0928 起平板第一次設定時，掃一下護理端畫面上的 QR code 就好，不必手打主機位址與金鑰。

    • Prisma 6（管線轉接頭） 房子接到資料庫的標準接頭。這個接頭已經證明過它的價值：測試階段資料庫本來放在雲端（在東京）， 0910 需求改版後整批搬回院內、換成 SQLite——換掉的是接頭與幾行設定，全屋管路沒有重拉。

    • SQLite（自家地下室的水塔） 資料庫的一種。與常見的「資料庫伺服器」不同，它不是一台要另外開機、另外維護的機器， 整個資料庫就是主機上的一個檔案。對一間透析中心的規模來說，這樣反而更好： 少一台機器要顧、少一個對外的門、備份就是複製一份檔案出來。 開發階段那個檔案在工程師的筆電上，正式上線後在院內主機上、貨櫃外的一座專用倉庫裡（見下一條）。

    • Docker 容器＋git clone（照圖說現場組貨櫃屋） 0926 起的交付方式。院內主機先從程式碼倉庫把圖說抄一份下來（這一步叫 git clone）， 再用 Docker 照圖說把標準貨櫃屋一間間組起來：後棟機房、兩棟前棟的門面，再加上 AI 閘道那一間；外殼工坊要用時才搭。 每間貨櫃屋裡該有的東西都照圖說放好，跟隔壁其他專案的貨櫃互不干擾。

    資料不放在貨櫃裡。 貨櫃是隨時可以拆掉重組的——換新版就是拆舊貨櫃、照新圖說組新的。 所以資料庫放在貨櫃外面另一座上鎖的倉庫（Docker 的「資料卷」），拆貨櫃不會動到它； 備份則另外放到主機上院方看得到的一個資料夾，而且每一份備份旁邊都附一張寫著「指紋」（雜湊值）的小紙條， 日後拿出來用之前，先對一下指紋，確定這一份沒有被動過。

    交付方式前後換了兩次，理由值得記下來。

    時間 做法 為什麼
    0912 貨櫃（容器） 主機是與其他專案共用的 DGX Spark，貨櫃可以互不干擾
    0919 整箱預鑄好帶進去（離線安裝包，隨身碟） 主機換成 Windows 電腦，擔心貨櫃會把資料庫藏到院方看不到、備份掃不到的地方
    0926 回到貨櫃，改成現場照圖說組 0922 第一次進院時院方要求用容器、而且不准用隨身碟

    0919 擔心的那件事沒有消失，是換了一種方式解決：資料庫放進專用倉庫、名字固定、不跟著貨櫃拆掉； 備份放到院方看得到的資料夾。同一個需求換個做法一樣達得到；前提變了就要重新算一次， 不能因為已經做了就繼續用。

    • Vite 6（施工機具） 開發時用來即時預覽、打包的工具。像工地的升降機與鷹架，交屋後不會留在房子裡。

    • 共用零件廠（packages/shared） 兩棟前棟不是各做各的。共用的按鈕、共用的資料格式定義，統一在一個地方做好，兩邊都拿去用，樣式與規則才不會走鐘。 外殼 App 的契約版本也寫在這裡：前棟和外殼要對的那個尺寸，只有一份。

    • 自帶的圖示與字型（迭代 14） 介面上的小圖示（Lucide）和中文字型（思源黑體，Noto Sans TC）都裝在房子裡，不去外面的網站拿， 也不依賴平板本身內建什麼字型。院內網路不通外面，要是靠外面拿，圖示和字就會開天窗。

    五、「幾個服務」大多在同一棟樓裡¶

    文件上會看到好幾個名字：API Gateway、裝置綁定服務、照護業務模組、營運與排班模組、 院方資料同步（1005 以前叫臨床資料匯入）、即時狀態服務、AI 閘道。

    前六個聽起來像好幾棟樓，實際上是同一棟機房裡的幾個房間（就是架構圖 圖一中間那一排）。只有 AI 閘道在 0927 搬了出去，自成第一節那間小屋。

        │  │總櫃檯  │ │平板配對│ │問卷求助│ │班表基準│ │抄表進來│      │
        │  └────────┘ └────────┘ └────────┘ └────────┘ └────────┘      │

    這樣做的理由很單純：現階段規模還小，先用隔間把職責分清楚就夠了。等哪天量體大到某個房間需要獨立的水電與樓地板，再把它拆出去蓋成獨棟（工程上叫「拆成微服務」）。因為隔間一開始就切乾淨了，將來要拆才不會牽一髮動全身——AI 閘道就是第一個真的拆出去的例子。

    各房間現況：

    房間 它在做什麼 目前狀態
    API Gateway 總櫃檯。所有請求都先到這裡，驗身分、分派、留紀錄 已完成
    裝置綁定服務 把某一台平板配到某一位病人身上，時間到自動解除；0927 起平板還記得自己擺在哪一床 已完成
    照護業務模組 問卷、求助、護理記錄、衛教、回饋；病人平板上的「本次透析」（血壓與脫水量的圖）與跑馬燈 已完成（1005 起輪播換成本次透析與跑馬燈）
    營運與排班模組 護理師班表、床位分配、成效基準，以及那些「可以改的數字」 已完成
    院方資料同步 每 3 分鐘去院方的透析紀錄抄一次：誰來透析、在哪一床、什麼時候開始與結束、體重、血壓與脈搏；人工輸入與 Excel／CSV 留著當備援 1005 完成，在開發機上用假的院方資料測過；真正的院方 API 第三次進院才看得到
    即時狀態服務 病人按了呼叫，讓護理站的畫面馬上跟著變 已完成
    AI 閘道（機房裡那一半） 要問 AI 之前，先把病人可識別資訊拿掉，並把每一次呼叫記下來 已完成
    AI 閘道（小屋那一半） 把後棟的話轉給真正的 AI 機器 0927 完成，在開發機上用假的 AI 機器測過；實驗室的真 AI 機器待接

    三個房間的變化值得單獨講¶

    推播通知服務：整間拆掉了。 0909 版這裡有一個「推播通知」的房間——就是讓護理師手機在院外也收得到 通知的那種。0910 改版後整條移除，因為那條線一定要經過院外的中繼站（Google 或 Apple 的伺服器）， 與「資料不出醫院」相抵觸。取而代之的是護理站的一台常駐總覽螢幕：它全天開著、不休眠， 通報一進來就在上面。等於把「推到每個人手機上」換成「掛在牆上大家都看得到」。

    AI 閘道：守的是院內，而且拆成兩半。 0909 版的設計是「對外的唯一關口」， 因為當時 AI 要問的是院外的服務商。現在 AI 模型跑在院內自己的機器上，機房裡那一半仍然做去識別化與呼叫紀錄， 守的問題是「哪些資料可以進 AI 流程」。0927 多出來的小屋那一半只負責轉話； 過渡期還有一條通往實驗室 AI 機器的線是院外的，程式強制那條線只准送假資料， 而且正式環境設定下選了實驗室，後棟會直接拒絕開門。

    臨床資料匯入：換成每 3 分鐘抄一次表（1005）。 以前院方的數字要有人輸入、或整批匯入檔案； 現在這個房間自己去院方的透析紀錄抄表，病人來了、上了哪一床、開始了、結束了，都照抄來的紀錄自動辦好， 護理師只要在病人第一次用平板時配一次。它辦事走的是護理師平常用的同一道門（同一套規則、同一種紀錄）， 只是紀錄上的名字寫「院方資料同步」。它只抄、不寫回院方。開發的時候抄不到真的表，就用一個做得一模一樣的假抄表口（模擬院方 API）練習； 真正營業的房子裡，接上假抄表口會被後棟直接拒絕開門。

    斷線時的紅框：從一台螢幕擴到每一個畫面（0929）。 以前只有常駐總覽螢幕在斷線時會整個閃紅框； 護理端其他畫面只有一個小標籤，或什麼都沒有——主機斷電時，畫面停在最後一刻，看起來一切正常。 現在護理端每一個畫面斷線時都會閃紅框、上緣出現紅底白字；病人平板則最多約 11 秒就改成「請按床邊呼叫鈴」。 斷線本身擋不住，但斷線不能看起來像沒事。

    六、有三件事，是這套房子跟一般房子最不一樣的地方¶

    這三件不是技術選擇，是需求端先定下的前提，技術只是配合：

    1. 水不出這棟樓。 病人的資料一律不離開醫院網路。所以資料庫搬回院內、AI 換成院內主機、 推播整條拿掉。工程上有一支可以重複執行的檢查，逐一盤點程式裡有沒有任何一條線指向院外， 目前是 0 筆。0926 起有一個例外要講清楚：院內主機在「組貨櫃」的那段時間（抓圖說、抓建材）會連出去， 組好、開始營業之後就一條對外的線都沒有。
    2. 每個開關都預設關著。 有風險或還沒談定的功能（例如依歷史資料做風險提示、 會用到護理師個人資料的績效），都各有一個開關，預設是關的， 要開必須填核准依據，而且開關動作本身也會被記下來。
    3. 每一個動作都留下紀錄。 誰、在什麼時候、對誰、做了什麼、結果如何。 這不是為了監看誰，而是出事時能重建當時的情況——這是醫療系統與一般軟體最大的差別之一。 護理端簡易版拖一下完成的事，留下的紀錄和專業版按好幾下完成的一模一樣。

    七、這個比喻到哪裡為止¶

    任何比喻都有極限，這幾點要記得：

    1. 房子蓋完就不動了，軟體會一直改。 這裡的每次改版，比較像整棟樓在正常營業的狀態下抽換管線，所以才需要那麼多測試與稽核紀錄。
    2. 兩棟前棟不是各蓋各的。 它們用同一種建材、同一批共用零件，比較像同一份設計圖蓋出來的雙胞胎，只是用途不同。
    3. 建材不會用完。 軟體的「材料」可以無限複製，成本幾乎都在設計與施工的時間上，不在材料本身。

    八、名詞速查¶

    看到這個字 就想成
    前端 / 前棟 人看得到、會操作的畫面
    後端 / 後棟 沒有畫面的伺服器，規則與資料都在這裡把關
    框架（React／NestJS） 工法規範＋一整批預鑄件
    編譯 施工前的尺寸總檢查，對不起來就不准開工
    部署 交屋，把蓋好的東西放上伺服器讓人使用
    微服務 把機房裡的某個房間拆出去，蓋成獨棟
    稽核軌跡 監視器紀錄，誰在什麼時候動了什麼，事後查得到
    repo（程式碼倉庫） 放圖說的檔案櫃。本系統一個，外殼 App 另一個
    git clone 把檔案櫃裡的圖說完整抄一份到院內主機上
    tag 圖說上蓋的版次章。院內只照有蓋章的那一版組，出問題時退回上一個章就好
    容器（Docker） 照圖說組出來的標準貨櫃屋，拆掉重組不影響倉庫裡的東西。0926 起的交付方式
    映像檔 貨櫃屋的預製模組。先做好模組，再照模組把貨櫃擺出來
    資料卷 貨櫃外面上鎖的倉庫，資料庫放在這裡，拆貨櫃不會動到它
    compose 一張總配置圖：幾間貨櫃、各自接哪條管線、倉庫在哪
    離線安裝包 把整棟預鑄好裝箱、用隨身碟帶進去。0919～0926 用過，已撤除，院方不准用隨身碟
    AI 閘道 後棟與 AI 機器之間的轉話小屋；換 AI 機器只改小屋的地址表
    LangChain AI 閘道接 AI 機器用的一套工具，實驗室規範指定的寫法
    外殼 App 把病人端畫面鎖在平板最上層的那支 Android 小程式
    APK Android App 的安裝檔，平板從院內下載頁拿
    簽章 App 上蓋的院內印章。平板只接受蓋同一個章的更新，印章（金鑰）要備份、不得出院
    契約 本系統與外殼 App 講好的門框尺寸，帶版本號
    簡易版／專業版 護理端的兩種畫面。簡易版是一張床位圖、拖一下完成一件事，每次登入預設；專業版是原本那一套
    功能開關 牆上的一排開關，每項有風險的功能一個，預設全關，誰開的都有紀錄
    去識別化 送進 AI 之前，先把姓名、病歷號這類認得出是誰的欄位拿掉
    用語把關 AI 寫回來的字，在轉話小屋（AI 閘道）門口先對一次字表：有簡體字或中國大陸的說法就退回請它重寫，寫到最後一次還是不行也照樣交出去；退回過幾次只記在資料庫，畫面上看不出來。1007 起，系統裡所有 AI 寫的字都經過這一道
    OpenCC 一套公開的兩岸中文轉換字表。本系統只在開發端用它產生「哪些字只有簡體才有」的清單，院內不需要它
    地端推論 AI 模型跑在醫院自己的機器上，資料不必送出去。0919 起那是另一台機器，本系統只透過院內網路呼叫它
    螢幕固定 Android 內建的功能，把畫面釘在單一程式上，病人退不出去，解除要輸入 PIN。本系統的平板鎖定靠它，不靠外部的裝置管理服務
    雜湊值（SHA-256） 檔案的指紋。檔案動過一個字，指紋就完全不同；備份旁邊都附一份
    院方 API 院方透析紀錄的抄表口。本系統每 3 分鐘去抄一次，只讀、不寫回
    模擬院方 API 開發用的假抄表口，格式一模一樣、內容全是假的；正式環境不准接
    探測工具 第一次去看真抄表口時用的小工具：只記下表格長什麼樣，不抄任何一個數字或名字
    SSE 後棟主動「喊一聲」給前棟的線。護理站用它收即時總覽；1005 起平板也用它聽「有新數值了」，再自己去拿
    CORS 後棟門口的放行名單：哪些網址來的請求可以進門。1001 第二次進院，護理站的網址不在名單上，所以登不進去
