    第三冊 · 平板與外殼 App¶

    版本：v0.1　文件狀態：草案　編號：K-xx　建議時點：D-10 ～ D-7（平板到貨後另一段）

    平板還沒買、外殼 App 還沒編譯過。 這一冊因此分成兩半： 上半是現在就做得完的（做完，下次進院只剩側載那幾分鐘）； 下半是平板到貨才做得了的。

    0. 現況盤點¶

    項次 現況 誰擋住誰
    外殼 App 原始碼 在（apps/kiosk-shell/：MainActivity.kt、ProvisioningActivity.kt、BootReceiver.kt、network_security_config.xml） —
    編譯環境（Android Studio、JDK 17、SDK 34） 未安裝 擋住 K-06
    院內 CA 與伺服器憑證 未產生（工具已備：npm run cert:hospital-ca） 擋住 K-05、K-06
    APK 簽名金鑰（keystore） 未建立 擋住 K-06
    平板實體 未購入，型號與 Android 版本未知 擋住 K-10 之後全部
    主機的 HTTPS 安裝包目前只提供 HTTP，見下方警告 擋住離線能力

    ⚠ 一個必須先解決的缺口：病人端要離線，就必須是 HTTPS¶

    Service Worker（病人端離線能力的全部依靠）只在安全來源底下才會註冊。 http://localhost 算安全來源，http://<院內主機 IP>:<埠> 不算—— 平板連的正是後者，於是 navigator.serviceWorker 根本不存在，註冊會靜悄悄地跳過， 不出錯、不提示，直到有一天網路斷了才發現畫面是空白的。

    而目前安裝包裡沒有任何東西在做 TLS：後端與兩個靜態站都是純 HTTP。 自簽 CA 產生的 server.crt／server.key 現在沒有地方可以掛。

    三條路，建議第一條：

    方案 代價 評估
    ① 讓安裝包自己終止 TLS（後端與兩個靜態站讀 server.crt／server.key） 改動不大，全在自己的程式碼裡 建議。不新增任何要過資安審查的第三方執行檔
    ② 加一個反向代理（nginx／IIS） 多一個要送進院內、另外過一次資安審查的元件 與當初捨棄服務包裝器的理由相同，能免則免
    ③ 首波先跑 HTTP，不要離線能力 「選 PWA 而非純網頁的唯一理由」當場消失 不建議，但若只為了驗主機這一段，可以當成過渡

    這一條在 D-7 之前要有結論，否則平板佈建做不完整。現況已記在這裡，不要到現場才發現。

    1. 現在就做得完的（不必等平板）¶

    K-01 決定院內主機的位址（所有事情的上游）¶

    做什麼

    向資訊室要一個固定的位址，二擇一：

    • 院內 DNS 名稱，例如 hd.<院內網域>
    • 固定 IP，例如 10.x.x.x

    為什麼這是上游

    同一個位址同時決定四件事，改了任何一次都要重做一輪：

    誰用到它 改了會怎樣
    伺服器憑證的主體別名 要重簽憑證
    PWA 建置時寫死的 API 位址（VITE_API_BASE_URL） 要重新產生安裝包（見第二冊 R-08 的警告）
    .env 的 CORS_ORIGINS、MDM_KIOSK_BASE_URL 改設定重新啟動
    外殼 App 的 network_security_config.xml 15 台平板全部要重發 APK

    可能怎麼壞、怎麼處理

    症狀 處置
    資訊室說「IP 可能之後會變」 要一個不會變的。會變的 IP 等於每次變動都要重發 15 台的 APK
    只給得出 IP，給不出 DNS 名稱 可以，但寫進紀錄：這個 IP 從此不能換
    到 D-7 還沒有答覆 那這次進院的目標降為 B 級（總覽），平板整段延後

    K-02 產生院內 CA 與伺服器憑證¶

    做什麼

    npm run cert:hospital-ca -- --host <K-01 決定的主機名稱> --ip <K-01 決定的 IP>

    怎麼知道成功了

    certs/ 底下出現五個檔案，並印出 CA 指紋與有效期：

    檔案 用途
    hospital-ca.key CA 私鑰。遺失無法補救，也絕不出院
    hospital-ca.crt CA 憑證
    hospital-ca.pem 給外殼 App 打包的那一份（內容同 .crt）
    server.key / server.crt 伺服器憑證

    可能怎麼壞、怎麼處理

    症狀 原因 處置
    說找不到 openssl 開發機沒有 openssl Git for Windows 自帶（C:\Program Files\Git\usr\bin\openssl.exe）。把它加進 PATH，或用 Git Bash 執行
    再跑一次被擋下 腳本不會覆蓋既有的 CA 正確行為。 換 CA 等於 15 台平板都要重發 APK
    主體別名裡沒有平板實際要連的位址 --host／--ip 填錯 刪掉 certs/ 重產。現在改沒有代價，發出 APK 之後改代價是 15 倍
    有效期太短 根憑證預設 10 年，免得日後頻繁重發 APK

    K-03 把 CA 私鑰異地備份（DEP-35，做完 K-02 立刻做）¶

    做什麼

    1. 把 hospital-ca.key 與 keystore（K-06）複製到另一個實體位置
    2. 院內，不出院——這兩樣東西的備份不得放到任何雲端
    3. 在交接文件寫下：放在哪、誰保管、誰有權限取

    怎麼知道成功了

    備份存在，而且你實際從備份還原過一次（複製回來、用它簽一次測試憑證）。

    只備份不驗證等於沒備份。 這一條每年要重做一次（平板管控方案 6.3）。

    可能怎麼壞、怎麼處理

    症狀 處置
    CA 私鑰弄丟了 無法補救。要重產 CA，並重發 15 台的 APK
    想順手放到雲端硬碟「比較保險」 不行。 那是院內資料離開醫院
    certs/ 會不會進版控 不會，已排除。但要自己確認一次：git status --short 不該出現它

    K-04 安裝編譯環境¶

    做什麼

    要裝什麼 版本
    JDK 17
    Android Studio 最新穩定版
    Android SDK API 34

    怎麼知道成功了

    用 Android Studio 開啟 apps/kiosk-shell/，Gradle 同步完成、沒有紅字。

    可能怎麼壞、怎麼處理

    症狀 原因 處置
    Gradle 同步時要下載一堆東西 正常，第一次要連外 在開發機上做完。這一整段都在院外
    JDK 版本不對 裝了 21 或 11 Gradle 設定要的是 17
    apps/kiosk-shell/ 不會被 npm run build 建置 刻意的 它是獨立的 Android 專案，本 repo 只負責契約那一部分

    K-05 把 CA 放進外殼 App¶

    做什麼

    1. 把 certs/hospital-ca.pem 複製到 apps/kiosk-shell/app/src/main/res/raw/hospital_ca.pem
    2. 開啟 app/src/main/res/xml/network_security_config.xml，確認 <domain> 是 K-01 那個位址

    怎麼知道成功了

    res/raw/ 底下有 hospital_ca.pem（目前那裡只有一個 README.md）， network_security_config.xml 裡的網域與 K-01 一致。

    可能怎麼壞、怎麼處理

    症狀 處置
    位址是 IP 不是網域名稱 network_security_config.xml 的 <domain> 也可以寫 IP，但憑證的主體別名必須含同一個 IP
    忘了放 pem App 會出現憑證錯誤，而且 Service Worker 會被整個停用——離線能力當場消失

    K-06 建立 keystore 並編譯 release APK¶

    做什麼

    keytool -genkeypair -v -keystore hd-kiosk.jks -keyalg RSA -keysize 4096 \
  -validity 10000 -alias hd-kiosk
cd apps/kiosk-shell && ./gradlew assembleRelease

    怎麼知道成功了

    app/build/outputs/apk/release/ 底下有一個已簽名的 APK。

    可能怎麼壞、怎麼處理

    症狀 原因 處置
    keystore 遺失 無法補救（DEP-35）：再也發不出更新版，只能換套件名重新側載 15 台。建立後立刻照 K-03 備份
    Gradle 建置失敗，缺 SDK 元件 第一次建置 依提示安裝，需要網路
    不知道 keystore 密碼要設多長 和 CA 私鑰同級對待。寫在交接文件裡，不要只存在你腦袋裡
    想先用 debug 版測 可以 ./gradlew assembleDebug。但正式佈建一定要用 release 簽名版——debug 簽名的 App 之後換成 release 版時必須先解除安裝，等於白做一次

    K-07 在模擬器上跑一次（平板沒到也能驗掉八成）¶

    做什麼

    1. Android Studio 開一台 API 34 的模擬器
    2. 安裝剛才的 APK
    3. 讓它連到第二冊那台演練機（模擬器用 10.0.2.2 指向主機）
    4. 輸入測試用的序號與金鑰

    怎麼知道成功了

    要驗的 應該看到
    憑證 沒有任何憑證警告
    網址列 不存在（外殼沒有網址列，病人看不到金鑰）
    首次佈建 輸入序號與金鑰後進入病人端畫面
    金鑰不外露 網址上的 serial／key 參數被網頁立刻移除
    前景回報 護理端裝置清單 15 秒內變成固定中
    離開前景 切到別的 App，護理端 30 秒內變成已跳出
    外部連結 點測試用的外部連結不會開啟
    長按文字 不會出現選字選單
    離線 關掉模擬器網路後重新整理，畫面照樣出得來

    可能怎麼壞、怎麼處理

    症狀 原因 處置
    憑證警告 pem 沒放、網域對不上、或主機根本沒開 TLS 見本冊開頭的警告框
    離線時一片空白 Service Worker 沒註冊 九成是因為連的是 HTTP（非安全來源）。這正是開頭那個缺口
    護理端一直顯示「尚未回報」 App 沒裝成或連不到後端 「尚未回報」與「已跳出」是兩件事：前者是沒裝 App，後者才是跳出 Kiosk
    模擬器連不到 10.0.2.2 演練機防火牆 回第二冊 R-13 開輸入規則

    模擬器驗不到的只有三件事：螢幕固定、開機自動啟動的實機行為、實體 Wi-Fi 的穩定度。 其餘全部可以在平板到貨前驗完——這就是「下次去只做最少工作」的實際做法。

    K-08 決定平板採購規格¶

    做什麼

    把這張表交給採購或資訊室（Q-11）：

    項次 要求 理由
    Android 版本 5.0 以上，建議 10 以上 螢幕固定需 5.0；新版 WebView 才跟得上 PWA
    螢幕 10 吋以上 病人端字級與觸控目標的下限是照透析病人族群訂的
    數量 15 台（首波先佈建 2～3 台） 一床一台
    側載 必須允許「安裝不明來源應用程式」 沒有這一條，整條路線走不通
    Wi-Fi 支援院內透析區的頻段與認證方式 Q-12
    週邊 床邊支架、充電線與固定位置、可消毒的保護殼 Q-22 消毒 SOP
    WebView 出廠版本盡量新 院內離線環境無法更新 WebView，買到的是哪一版就是哪一版

    可能怎麼壞、怎麼處理

    症狀 處置
    院方已經有一批舊平板要沿用 先問 Android 版本與 WebView 版本。低於 5.0 就沒有螢幕固定，整個 Kiosk 方案要重想
    院方資安不允許側載 這是 Q-11 第 2 題。不允許的話只剩 Chrome 路線（要公開網域）或 Device Owner（兩三週開發），兩條都要重新決策

    2. 平板到貨之後（每台一次）¶

    首波只佈建實際會用到的兩三台（DEP-36）。跑完一個完整班次沒問題，再做其餘。 15 台一次做完，等於把佈建的錯誤一次放大 15 倍。

    K-10 護理端先註冊這台裝置¶

    做什麼

    護理端 → 裝置管理 → 註冊，填序號（英數字與連字號，3–32 字元，例如 TB-01）。

    怎麼知道成功了

    畫面顯示一組金鑰。金鑰只顯示一次，當場抄下來。

    可能怎麼壞、怎麼處理

    症狀 處置
    金鑰沒抄到 解除佈建後重新註冊一次即可，不必重發 APK
    序號要怎麼編 建議與床號對應（TB-01 對 1 號床），並在紙上記下對應表

    K-11 平板基本設定¶

    做什麼

    1. 設定裝置 PIN（護理師才知道的那一組）
    2. 關閉「新增使用者」
    3. 開啟「允許安裝不明來源應用程式」
    4. 連上透析區 Wi-Fi
    5. 關閉自動更新、關閉自動休眠（或把螢幕逾時拉到最長）

    可能怎麼壞、怎麼處理

    症狀 處置
    找不到「允許安裝不明來源」 Android 8 起改成按 App 授權：從檔案管理員或瀏覽器安裝時才會跳出來
    平板要求登入 Google 帳號 不需要，跳過。整條路線刻意不依賴任何 Google 服務
    Wi-Fi 連不上或訊號弱 記下床位與訊號強度（Q-12）。這是要帶回來的情報之一

    K-12 側載 APK¶

    做什麼

    用隨身碟或 USB 線把 APK 複製到平板，點開安裝。

    可能怎麼壞、怎麼處理

    症狀 原因 處置
    「未安裝應用程式」 簽名衝突（之前裝過 debug 版）或架構不符 先解除安裝舊的再裝
    系統的安全掃描擋下 部分機型內建 依提示選擇仍要安裝。擋死就換方式傳檔
    平板沒有檔案管理員 部分精簡韌體 用 adb install（要開啟開發人員選項與 USB 偵錯）

    K-13 首次啟動與佈建¶

    做什麼

    開啟 App → 輸入主機位址、序號、金鑰。

    怎麼知道成功了

    進入病人端畫面，沒有網址列，沒有憑證警告。

    可能怎麼壞、怎麼處理

    症狀 原因 處置
    憑證警告 pem 沒打包、網域對不上、主機沒開 TLS 見開頭警告框
    「裝置尚未佈建」 序號或金鑰打錯 重新輸入。注意大小寫
    一直轉圈 連不到主機 在平板的瀏覽器直接開 http(s)://<主機>:<PATIENT_PORT> 試，分清楚是網路問題還是 App 問題

    K-14 開啟螢幕固定¶

    做什麼

    設定 → 安全性 → 螢幕固定 → 開啟，勾選「解除固定前要求 PIN」 → 回到 App 並釘住。

    怎麼知道成功了

    病人退不出去；要解除必須輸入 PIN。

    可能怎麼壞、怎麼處理

    症狀 處置
    找不到螢幕固定 Android 版本太舊（需 5.0 以上），或廠商改了選單名稱（可能叫「應用程式鎖定」）
    沒勾「要求 PIN」 一定要勾。不勾的話長按導覽列的上一頁鍵就解得開，Kiosk 形同虛設
    重新開機後固定不見了 已知取捨。App 會自動啟動，但螢幕固定不會自動恢復——列入每日交班檢查

    K-15 核對護理端¶

    做什麼

    護理端 → 裝置管理，看這一台的「固定狀態」。

    怎麼知道成功了

    15 秒內變成固定中。把平板切走，30 秒內變成已跳出；關機等 90 秒，變成失去回報。

    三種狀態要分得開：尚未回報＝還沒裝 App；已跳出＝平板自己說它離開前景了； 失去回報＝它不說話了（多半是關機或斷網）。護理師要做的處置完全不同。

    K-16 記錄對應關係¶

    做什麼

    在紙上填一列（同時填進演練紀錄 §6.1）：

    序號 床號 Android 版本 側載完成 序號金鑰輸入 螢幕固定＋PIN 護理端清單核對 備註

    3. 如果這次進院時平板還沒到¶

    那就把佈建整段跳過，改成蒐集情報。要帶回來的（詳見第五冊）：

    要問到 為什麼
    平板的採購進度與預計到貨日 決定下一次進院的時間
    最後決定的型號與 Android 版本 決定螢幕固定可不可行、WebView 版本
    院方允不允許側載 不允許的話整條路線要重新決策
    透析區各床位的 Wi-Fi 訊號 用手機在每個床位測一次，記下格數
    Wi-Fi 的認證方式（是否需要帳號、憑證、MAC 登記） 平板連不上網就全盤皆輸
    床位編號與實際位置 序號與床號的對應表
    平板要放哪裡、怎麼充電、怎麼消毒 支架與電線的採購（Q-22）

    這幾題問到了，下一次進院平板佈建就是純執行，不再有任何未知。

    4. 交給護理師的一頁（每日）¶

    印一張貼在護理站：

    1. 前一天有重新開機的平板要重新釘選：開啟 App → 最近使用 → 長按釘選圖示。App 會自己起來，但螢幕固定不會自動恢復
    2. 交班時看護理端裝置清單的「固定狀態」，不必逐台目視
    3. 顯示已跳出 → 去把螢幕固定釘回來
    4. 顯示失去回報 → 去看看那台平板還在不在、有沒有沒電
    5. 治療結束照既有流程解除綁定，系統會自動清除該台的本地暫存

    5. 守不住什麼（要先講清楚，不要等人發現）¶

    破口 處置
    重新開機後螢幕固定解除 人工重釘，已列入每日交班檢查
    病人自己解開固定 靠前景回報變成「看得見」，不是「防得住」
    還原原廠設定、改 Wi-Fi 設定 擋不住。屬物理接觸風險，治療區全程有護理師在場
    keystore 或 CA 私鑰遺失 無法補救，只能換套件名重新側載 15 台
    WebView 版本凍結 離線環境無法更新。已知取捨，與零連外一起接受

    6. 這一冊的完成條件¶

    平板到貨前：

    • K-01 主機位址定下來，且不會再變
    • K-02 CA 與伺服器憑證已產生，主體別名涵蓋該位址
    • K-03 CA 私鑰已異地備份並驗證過
    • K-06 keystore 已建立並備份，release APK 編得出來
    • K-07 模擬器上九項全過（離線那一項要等 HTTPS 缺口處理完）
    • K-08 採購規格已交出
    • HTTPS 缺口有結論（本冊開頭的警告框）

    平板到貨後，每台：

    • K-10～K-16 七步，逐台記錄
