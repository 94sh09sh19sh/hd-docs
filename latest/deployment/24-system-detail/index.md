## 1. 讀之前

### 1.1 三種結果

| 結果     | 條件                                                                                  |
| -------- | ------------------------------------------------------------------------------------- |
| **A 級** | 第一階段成功、換版成功、啟用讀檔第一輪對得上、平板走完一次、交接完成                  |
| **B 級** | 第一階段或換版成功，但停在 SY-09 之前或之後某一步（防毒、病人告知沒答案，床號對不上） |

### 1.2 什麼時候當場停手

| 情形                                                   | 處理                                         | 結果 |
| ------------------------------------------------------ | -------------------------------------------- | ---- |
| 第二十一冊沒做成                                       | 本系統不換版                                 | C 級 |

| 第一輪床號或療程不對                                   | 第二十三冊附錄二停用讀檔，記下實況           | B 級 |

停手時做三件事：服務維持在一個說得清楚的狀態（`v0.4.0` 或 `<新 tag>`、讀檔開或關）、把現況寫進紀錄、當場講清楚下一次需要什麼。

## 2. 各步驟

### SY-01 確認 tag、答案、人與時段

- 沒有照第二十三冊 🧪 整輪演練過、判定通過的 tag **不准帶**
- 演練中發現程式要修：修好、跑過驗收、**打下一個 tag**（例如 `v0.5.1`）重新演練。推上去的 tag 不移動、不刪掉重打（院內與紀錄都靠 tag 名字對版本）
- 「到時候看看」當成沒約到

### SY-02 看現況

| 症狀                                             | 處置                                                                                           |
| ------------------------------------------------ | ---------------------------------------------------------------------------------------------- |
| `git describe` 不是 `v0.4.0`，或 repo 有改動     | 有人動過。**停手**，問資訊室                                                                   |
| 有服務不是 `Up`                                  | `docker compose --env-file $cfg logs <服務> --tail 30` 抄下來，打電話給開發端                  |
| `failed to connect to the docker API at npipe:…` | Docker Desktop 沒開。開始選單開啟，等左下角變綠                                                |
| `backups\keys` 是空的                            | 金鑰備份不見了。記下來，SY-12 平板若要重新佈建會受影響，打電話給開發端                         |
| Docker Desktop 的設定是灰的                      | 院方鎖住了，記下來，不要繞過                                                                   |
| 使用統計取消勾選後按的是 **Apply & restart**     | Docker 會重新啟動，服務中斷約一分鐘後自己回來；沒回來就 `docker compose --env-file $cfg up -d` |

順便抄下 Docker Desktop 另外三項（SY-07、交接要用）：General → Start Docker Desktop when you sign in（應該勾，沒勾先不改、交資訊室）；Software updates（只看不改；找不到就是市集裝的）；Resources → Advanced → Disk image location（SY-03 要用的路徑）。

### SY-03 防毒排除

想知道防毒有沒有在跑（系統管理員身分）：

```
Get-CimInstance -Namespace root/SecurityCenter2 -ClassName AntivirusProduct | Select-Object displayName, @{n='hex';e={'{0:X6}' -f $_.productState}}
```

`hex` 中間兩碼 `10` 或 `11` 是正在運作，`00`、`01` 是裝了沒在跑。1001 是 `061100`（Defender 正在運作）。

| 症狀                                          | 處置                                                                                       |
| --------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `Must be an administrator to view exclusions` | 不是系統管理員身分，重開一個（開始 → 打 `powershell` → `Ctrl+Shift+Enter`）                |
| `Invalid namespace`                           | 這台是 Windows Server，改打 `Get-MpComputerStatus`，看 `AMRunningMode`、`AntivirusEnabled` |
| 資訊室當天加不了                              | **不啟用讀檔**；換版照做，寫進交接紙的已知限制：誰、什麼時候加                             |

為什麼：資料庫所在的 Docker 資料夾被即時掃描，會造成間歇性、很難重現的錯誤，一個月後才爆開也沒人會聯想到今天。**加上排除之前不得輸入真實病人資料。**

### SY-04 換版

| 症狀                                           | 處置                                                                                                                                    |
| ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `Permission denied (publickey)`                | 部署金鑰被拿掉了。`ssh -T github-hd-tablet-care` 看一下，打電話給開發端                                                                 |
| `error: pathspec '<新 tag>' did not match`     | tag 沒推上去或打錯字                                                                                                                    |
| `git describe` 後面有尾巴（例如 `-3-gabc123`） | 不在 tag 上，重打 `git checkout <新 tag>`                                                                                               |
| `no such host`（建置時）                       | 再打一次 → 工作列 Docker 圖示右鍵 Restart → 找資訊室看 DNS                                                                              |
| 每個 `docker compose` 都說「請設定 HD\_…」     | `.env` 少了必填的那一行，照範本補                                                                                                       |
| `更新中止：後端服務還在執行`                   | 再打一次 `stop api`。**不要加 `--allow-running`**                                                                                       |
| 其他任何「中止」                               | 資料庫沒被動到。整段抄下來，`HD_IMAGE_TAG` 改回 `v0.4.0`、`git checkout v0.4.0`、`docker compose --env-file $cfg up -d`，打電話給開發端 |

- 3 個遷移（迭代 30.4 連點成畫、32 院方資料讀檔、32.1 未更新提示時段）都只做加法
- `.env` 的四行先留空，是因為讀檔要等 SY-09 四條都過才開
- `db-update.mjs` 會先做一份更新前備份，檔名與 SHA-256 是附錄一退回時唯一的依據，一定要抄

### SY-05 啟動確認

| 症狀                                   | 處置                                                                                           |
| -------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `api` 一直 `Restarting`                | `docker compose --env-file $cfg logs api --tail 30` 抄最後幾行。看不懂就照第二十三冊附錄一退回 |
| 放行檢查什麼都沒印                     | 照附錄三                                                                                       |
| 護理站 `Failed to fetch`               | Ctrl＋F5；仍不行照附錄三                                                                       |
| 護理站 `工作ID 或密碼錯誤`             | 有連到後端，帳號或密碼不對；換版不會改密碼                                                     |
| 有功能開關是開的                       | 關掉，記下是哪一個，回來告訴開發端                                                             |
| 「院方床位轉床號的方式」不是 `0`       | 改回 `0`，記下原本是多少                                                                       |
| 日誌的「伺服器時區」不是 `Asia/Taipei` | 後端會拒絕啟動。不要自己改主機時區，找資訊室                                                   |

「版本更新紀錄」的版本欄 `0.1.0 → 0.1.0` 是 `package.json` 的號碼，不是 tag，正常。

### SY-06 備份還原

- **一律用 PowerShell**：Git Bash 會把 `/backups/…` 改寫成 Windows 路徑，還原就找不到檔
- `✗ 與備份歷程上的紀錄不符`：雜湊抄錯，重抄 `.sha256` 那一份；還是不符就打電話給開發端
- 刪測試檔那一條印「No such file」：前一條沒寫出測試檔，看前一條的錯誤原文
- 為什麼要送往另一台機器：備份只放在同一台主機，主機壞了就一起沒了（DEP-06）；由誰送、多久送是資訊室的事，寫進交接紙

### SY-07 重新開機

- 為什麼：`restart: unless-stopped` 只管 Docker 起來之後；Docker Desktop 要有人登入 Windows 才會啟動。院方的答覆是斷電後由護理長到主機重新登入，不設自動登入，這一步就是在模擬護理長
- 三分鐘後服務沒回來：記下 Docker Desktop 有沒有隨登入起來、SY-02 抄的「Start Docker Desktop when you sign in」有沒有勾；手動開 Docker Desktop、等變綠、`docker compose --env-file $cfg up -d`。**不要改院方的登入或開機設定**，寫進交接紙的已知限制，交資訊室決定
- 順便看第一階段的排程：`Get-ScheduledTaskInfo -TaskName hd-hospital-fetch` 的 `LastRunTime` 有往前跳（排程也是登入後才跑）
- 🧪 開發機驗不出「沒人登入」的情形，所以只 Quit Docker Desktop；量到的分鐘數只當參考

### SY-08 密碼移交、建帳號

- 為什麼護理長自己改：開發端知道管理者密碼的狀態不能延續到上線之後（信任邊界是「能登入這台主機的人」）
- 臨時密碼建帳號時由管理者設，當場請對方改掉；不寫在紙上

### SY-09 啟用前確認

- 為什麼是分界線：讀檔一開，每 3 分鐘就把當天清單上所有病人的主檔、床位、療程寫進資料庫；床位只新增、不會自己消失。停用不會刪掉已寫進去的（附錄二）
- 床號轉換方式 `0` 是原樣顯示；`1A`～`3D` 與 `99` 這幾種的對應還在問（D-1），先不改

### SY-11 第一輪怎麼驗

- 病人數差很多：讀檔檢查算的是整個月份檔，卡片同步的是今天；差幾位正常，差一半以上就抄下兩個數字，停用也可以（B 級）
- 稽核軌跡有「整次透析被擋下」：抄原因（不含病歷號）。多半是床號或療程欄位對不上，回來看
- 🏥 卡片最上面出現「目前接的是模擬院方 API」：掛到模擬的資料，**馬上停用**（第二十三冊附錄二）
- 等 3 分鐘時間沒往前跳：看第一階段的排程是不是還在跑（`Get-ScheduledTaskInfo`）；23:00 後抓取腳本不抓，正常

### SY-M1 驗院內設定擋得住模擬（🧪）

- 卡片沒有「拒收」、資料庫多了模擬病人：保險沒生效。**這個 tag 不能帶**，抄日誌回去修
- 為什麼：院內主機的 `HD_SIMULATION_DEPLOYMENT` 永遠空白，萬一有人把模擬的檔掛過去，後端整次作廢，而不是把假病人寫進院內的資料庫

### SY-M2 三支驗收（🧪）

- 某一項 ✗：抄原文。是驗收腳本跟不上新版，還是新版真的有問題？前者修腳本、後者修程式，**兩種都要打新 tag 重新演練**
- 這是整輪唯一准用 Node.js 的地方；部署本身只用 Git 與 Docker

### SY-M3 退回演練（🧪）

- 退回後登不進去、`Failed to fetch`：第二十三冊附錄一寫錯了，抄下附錄三第 3 步的結果，回去改附錄一再演練
- 平板或帳號不見了：它們是更新之後才建的，跟著資料一起退回去，是對的

### SY-M4 判定（🧪）

## 附錄二：停用讀檔之後，已經寫進主機的資料

停用不會刪掉。病人主檔、床位、療程留在資料庫裡，床位只新增、不會自己消失。要整個清掉只有兩條路，**都要開發端判斷後再做**：

1. 退回 SY-04 的更新前備份：做第二十三冊附錄一的第 2 步，但版本留在 `<新 tag>`（第 1 步只清空 `HD_DIALYSIS_LIST_DIR`、註解 `COMPOSE_FILE`，不改 tag）。之後的改密碼與建帳號也會一起消失
1. 撤除整套：要院方書面同意，會刪掉整個透析中心在本系統的紀錄

現場不要自己刪。

## 附錄三：護理端開得起來卻登不進去

**先認清網址**：`http://<IP>:18080` 可以；`http://localhost:18080` 與舊的主機名稱都**登不進去**（放行名單上只有 `<IP>`）。

**第 1 步：看登入鈕下面的訊息**

| 訊息                | 意思                                             | 接著                 |
| ------------------- | ------------------------------------------------ | -------------------- |
| `工作ID 或密碼錯誤` | 有連到後端，帳號或密碼不對                       | 換帳號或請護理長重設 |
| `Failed to fetch`   | 瀏覽器沒拿到後端的回應：位址錯，或被放行名單擋掉 | 第 2 步              |

**第 2 步：網址列**：把網址原文抄下來。不是 `http://<IP>:18080` 就改用這個網址開，Ctrl＋F5，再登入一次。

**第 3 步：在主機上查**（照順序，結果全部抄下來，包括正常的）：

```
Select-String -Path $cfg -Pattern '^(HD_PUBLIC_API_URL|CORS_ORIGINS)='
docker compose --env-file $cfg exec nurse-web grep -rhoE 'https?://[A-Za-z0-9.-]+:[0-9]+' apps/nurse-pwa/dist/assets
curl.exe -s http://<IP>:13000/api/health
curl.exe -s -i -H "Origin: http://<IP>:18080" http://<IP>:13000/api/health | Select-String Access-Control-Allow-Origin
[Console]::OutputEncoding = [Text.Encoding]::UTF8; docker compose --env-file $cfg logs api | Select-String '允許的前端來源' | Select-Object -Last 1
```

| 結果                                                        | 意思                       | 處置                                                                                   |
| ----------------------------------------------------------- | -------------------------- | -------------------------------------------------------------------------------------- |
| 第二條的位址與第一條的 `HD_PUBLIC_API_URL` 不一樣           | 網頁是在改 `.env` 之前建的 | `build`、`up -d`，Ctrl＋F5                                                             |
| 第三條沒有 `{"status":"ok",…}`                              | `<IP>:13000` 連不到後端    | `docker compose --env-file $cfg logs api --tail 30` 看原因                             |
| 第四條印出 `Access-Control-Allow-Origin: http://<IP>:18080` | 後端有放行                 | 問題不在名單：回第 2 步，或按 F12 → Network 再按一次登入，抄下請求送去的網址與錯誤原文 |
| 第四條什麼都沒印，第五條不是 `http://<IP>:18080`            | 名單寫錯，或改完沒 `up -d` | 改 `.env` 的 `CORS_ORIGINS`，`docker compose --env-file $cfg up -d`，再打第四條        |

試了一小時仍然不通：**停手**，不再改任何東西；新版剛換上去的話照第二十三冊附錄一退回 `v0.4.0`（1029 時 `v0.4.0` 用 `<IP>` 登得進去），紀錄帶回。

## 附錄四：平板要重新佈建時

1029 已佈建過，正常不必做。SY-12 出現空白頁或固定不回來才做；要 1 小時左右，時間不夠就交接寫「平板未佈建」。

1. 平板：**不要原廠重設**（會把 WebView 退回舊版，院內沒辦法再更新）。設定 → 應用程式 → 透析照護平板 → 儲存空間 → 清除資料
1. 護理站的電腦：護理端 → **新增裝置** → **註冊新平板**。畫面出現佈建 QR code 與一行網址，**只顯示一次**，做完第 4 步再關。網址要以 `https://<IP>:18081` 開頭，不是的話 `.env` 的 `MDM_KIOSK_BASE_URL` 不對
1. App 不見了才要重裝：平板瀏覽器開 `http://<IP>:18081/shell/` →「下載 App」→ 安裝（允許瀏覽器安裝不明來源的 App）。「套件與現有套件衝突」是裝過開發版，先解除安裝再裝；「應用程式未安裝」是下載不完整，重下載
1. 開「透析照護平板」→「掃描 QR code」→ 允許相機 → 對準 QR code（第一次開會先跳三星的手勢提示，按「確定」）→ 核對序號與平板背面的標籤 →「儲存並啟動」→ 系統問要不要固定 →「確定」
1. 護理端「新增裝置」等 15～30 秒，變成「固定中」。釘選要 PIN：設定 → 安全性與隱私權 → 其他安全性設定 → 釘選應用程式，勾「解除固定前要求 PIN」（One UI 5.1.1 的路徑）

「主機位址不是 https:// 開頭」：回第 2 步看網址。平板畫面要是橫的、沒有任何憑證警告；有憑證警告就是 `<IP>` 跟憑證不符，打電話給開發端。
