    第二十四冊 · 本系統換版上線（詳細版）¶

    版本：v0.1　文件狀態：草案（1116 由第二十冊、第十八冊與第十七冊 0.6 節整理）　編號：沿用第二十三冊的 SY-xx

    上層手冊：《第二十三冊 · 本系統換版上線（簡易版）》

    照第二十三冊做，畫面跟「成功」不一樣時翻這一冊同一個編號。 這裡寫：什麼時候停手、時間怎麼排、每一步的出錯處置、登不進去怎麼查、平板重新佈建、交接紙。

    指令與訊息綁在根目錄的 docker-compose.yml、docker-compose.dialysis-files.yml、docker-compose.hospital-files-sim.yml、deploy/hospital.env.example、db-update.mjs、restore-backup.ts、hospital-api-probe 上：那幾份的訊息或參數改了，回頭核對這一冊與第二十三冊。規則的真本是《部署規範》。

    公開範圍：一律用代稱（第二十三冊第 0 節）。院內主機名稱、IP、帳號、.env 的值、照片只進私人 repo 的 deploy/records/。

    1. 讀之前¶

    1.1 三種結果¶

    結果 條件
    A 級 第一階段成功、換版成功、啟用讀檔第一輪對得上、平板走完一次、交接完成
    B 級 第一階段或換版成功，但停在 SY-09 之前或之後某一步（病人告知沒答案，床號對不上）。防毒排除沒加不算（1116 改，見 SY-03）
    C 級 第一階段沒成功：本系統不動，維持 v0.4.0

    1.2 什麼時候當場停手¶

    情形 處理 結果
    第二十一冊沒做成 本系統不換版 C 級
    換版後 api 起不來、主線壞掉，現場解不開 第二十三冊附錄一退回 v0.4.0，抓取腳本照跑 B 級
    病人告知沒答案 不啟用讀檔，做到 SY-08 B 級
    防毒排除當天加不了 照樣往下；交接紙寫誰、什麼時候加，以及 SY-03 那四種現象 不影響等級
    第一輪床號或療程不對 第二十三冊附錄二停用讀檔，記下實況 B 級
    平板到不了位、Wi-Fi 不通 護理端照用、病人端不開；求助照舊用床邊呼叫鈴 B 級
    離下班不到 45 分鐘 停在目前這一步，直接做 SY-14、SY-15 —
    有人說「把網路開一下」「手動開個容器把整顆磁碟掛進去」 不做 —

    停手時做三件事：服務維持在一個說得清楚的狀態（v0.4.0 或 <新 tag>、讀檔開或關）、把現況寫進紀錄、當場講清楚下一次需要什麼。

    SY-01 確認 tag、答案、人與時段¶

    • 沒有照第二十三冊 🧪 整輪演練過、判定通過的 tag 不准帶

    • 「到時候看看」當成沒約到

    SY-02 看現況¶

    症狀 處置
    git describe 不是 v0.4.0，或 repo 有改動 有人動過。停手，問資訊室
    有服務不是 Up docker compose --env-file $cfg logs <服務> --tail 30 抄下來，打電話給開發端
    failed to connect to the docker API at npipe:… Docker Desktop 沒開。開始選單開啟，等左下角變綠
    backups\keys 是空的 金鑰備份不見了。記下來，SY-12 平板若要重新佈建會受影響，打電話給開發端
    Docker Desktop 的設定是灰的 院方鎖住了，記下來，不要繞過
    使用統計取消勾選後按的是 Apply & restart Docker 會重新啟動，服務中斷約一分鐘後自己回來；沒回來就 docker compose --env-file $cfg up -d

    順便抄下 Docker Desktop 另外三項（SY-07、交接要用）：General → Start Docker Desktop when you sign in（應該勾，沒勾先不改、交資訊室）；Software updates（只看不改；找不到就是市集裝的）；Resources → Advanced → Disk image location（SY-03 要用的路徑）。

    SY-03 防毒排除¶

    第四條印出 Access-Control-Allow-Origin: http://<IP>:18080 後端有放行 問題不在名單：回第 2 步，或按 F12 → Network 再按一次登入，抄下請求送去的網址與錯誤原文
    第四條什麼都沒印，第五條不是 http://<IP>:18080 名單寫錯，或改完沒 up -d 改 .env 的 CORS_ORIGINS，docker compose --env-file $cfg up -d，再打第四條

    試了一小時仍然不通：停手，不再改任何東西；新版剛換上去的話照第二十三冊附錄一退回 v0.4.0（1029 時 v0.4.0 用 <IP> 登得進去），紀錄帶回。

    附錄四：平板要重新佈建時¶

    1029 已佈建過，正常不必做。SY-12 出現空白頁或固定不回來才做；要 1 小時左右，時間不夠就交接寫「平板未佈建」。

    1. 平板：不要原廠重設（會把 WebView 退回舊版，院內沒辦法再更新）。設定 → 應用程式 → 透析照護平板 → 儲存空間 → 清除資料
    2. 護理站的電腦：護理端 → 新增裝置 → 註冊新平板。畫面出現佈建 QR code 與一行網址，只顯示一次，做完第 4 步再關。網址要以 https://<IP>:18081 開頭，不是的話 .env 的 MDM_KIOSK_BASE_URL 不對
    3. App 不見了才要重裝：平板瀏覽器開 http://<IP>:18081/shell/ →「下載 App」→ 安裝（允許瀏覽器安裝不明來源的 App）。「套件與現有套件衝突」是裝過開發版，先解除安裝再裝；「應用程式未安裝」是下載不完整，重下載
    4. 開「透析照護平板」→「掃描 QR code」→ 允許相機 → 對準 QR code（第一次開會先跳三星的手勢提示，按「確定」）→ 核對序號與平板背面的標籤 →「儲存並啟動」→ 系統問要不要固定 →「確定」
    5. 護理端「新增裝置」等 15～30 秒，變成「固定中」。釘選要 PIN：設定 → 安全性與隱私權 → 其他安全性設定 → 釘選應用程式，勾「解除固定前要求 PIN」（One UI 5.1.1 的路徑）

    「主機位址不是 https:// 開頭」：回第 2 步看網址。平板畫面要是橫的、沒有任何憑證警告；有憑證警告就是 <IP> 跟憑證不符，打電話給開發端。
