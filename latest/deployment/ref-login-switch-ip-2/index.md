# 護理站登不進去與主機位址之二：換主機位址（T-08～T-14、第 3～6 節）

上層文件：《[護理站登不進去與主機位址](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-login/index.md)》　接在《[護理站登不進去與主機位址之一：換主機位址（T-01～T-07、第 1 節）](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-login-switch-ip/index.md)》之後

> - 狀態：**現行**（常備參考）；1117 由舊的第十五冊之四（主機位址從名稱改成 IP）改寫，1029 照做時（舊第十八冊 J-07～J-14）的現場經驗收在各步；編號 `T-xx`（沿用第十五冊之四）
> - 第 1 節與 T-01～T-07 在之一；代稱（`<IP>`、`<名稱>`、`<主機>`）與開工三行見《[護理站登不進去與主機位址](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-login/index.md)》第 0 節

## 摘要

- `shell-builder` 重簽伺服器憑證，新產生的只能有伺服器憑證，看到院內 CA 或簽章金鑰就停手（T-08）
- 重新備份金鑰（T-09）、`restart patient-web` 讓病人端換上新憑證（T-10）
- 主機與護理站各登入一次、平板連得到、下載頁換過（T-11～T-13）；收尾記下 T-02 抄的五樣、每一步的時間、金鑰備份檔名、三個 SHA-256（T-14）
- 換不成照第 3 節換回名稱，**不要換來換去**
- 平板已佈建（1029 起 `TB-00`）：每一台清除資料、重新佈建（第 4 節）
- 第 5 節是各步的症狀與處置；第 6 節是帶進去的一張紙

## 2. 換位址（接之一）

### T-08 重跑 `shell-builder`，重簽伺服器憑證

**做什麼**（記下開始時間）

```
docker compose --env-file $cfg --profile shell run --rm shell-builder
```

它會重建一次 APK（離線建置，不必下載）。

**成功**：「這一次新產生：」後面**只有**「伺服器憑證（`<IP>`）」一項，接著是 APK 檔名與三個 SHA-256。**再打一次同一條指令**，這次要看到「**金鑰全部沿用，這一次沒有產生任何新的金鑰**」。記下結束時間。

| 「這一次新產生：」後面出現                          | 怎麼辦                                                                                                                                                                                                                 |
| --------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 只有「伺服器憑證（`<IP>`）」                        | **對的**                                                                                                                                                                                                               |
| 「伺服器憑證（`<名稱>`）」                          | `.env` 的 `MDM_KIOSK_BASE_URL` 沒改到，回 T-06                                                                                                                                                                         |
| 「院內 CA」或「APK 簽章金鑰」                       | **停手。** 金鑰資料卷不是原本那一個，或指令少了 `--env-file $cfg`。不要往下做，打電話問開發端；照《[平板與外殼 App](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-tablet-2/index.md)》第 7 節從備份還原 |
| `這個金鑰資料卷是「dev」用的，設定卻是「hospital」` | **停手**                                                                                                                                                                                                               |

### T-09 重新備份金鑰

伺服器憑證換了，舊的那份備份裡是舊的。

**做什麼**

```
docker compose --env-file $cfg --profile shell run --rm shell-builder keys-backup
docker compose --env-file $cfg --profile shell run --rm shell-builder keys-verify
```

**成功**：第一條印出「已備份：備份目錄/keys/hd-keys-\<時間>.tar.gz」；第二條每一項都 ✓，最後「還原得回來」。

- **新的備份檔名記進演練紀錄**（1029 沒抄到），並告訴負責把備份送往另一台機器的人：這一份要送
- **舊的那份（1001 的 `hd-keys-20261001-173347.tar.gz`）不要刪。** 院內 CA 與簽章金鑰兩份是同一把；萬一要從舊的那份還原，`shell-builder` 發現伺服器憑證的名字對不上，一樣會自己重簽
- 金鑰備份裡有私鑰，**不得出院、不得寄給開發端**

### T-10 讓病人端換上新的憑證

**做什麼**

```
docker compose --env-file $cfg restart patient-web
docker compose --env-file $cfg logs patient-web --tail 5
docker compose --env-file $cfg --profile shell run --rm shell-builder keys-info
```

**成功**

| 看什麼                                                | 應該是                                   |
| ----------------------------------------------------- | ---------------------------------------- |
| 日誌**最後一次**出現的「靜態資源已提供於連接埠 8081」 | 後面是「（HTTPS；HTTP 只留外殼下載頁）」 |
| `keys-info` 的「伺服器憑證」那一行                    | `IP Address:<IP>`                        |
| `keys-info` 的院內 CA 與簽章金鑰指紋                  | 與 T-02 抄的**一模一樣**                 |

| 症狀                                                                   | 處置                                                                                                                   |
| ---------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `restart patient-web` 停在 `Restarting`、沒有 `Started` 就回到提示字元 | 畫面沒畫完，不是錯。看下一條日誌**最後一次**是不是 HTTPS；`docker compose --env-file $cfg ps patient-web` 是 `Up` 就好 |
| 日誌裡「找不到伺服器憑證」和「HTTPS」同時出現                          | `--tail 5` 跨到了重新啟動之前那一次，以**最後一次**啟動的那幾行為準                                                    |
| 日誌寫 `8081`、`http://api:3000`，不是 `18081`、`13000`                | **正常**，那是容器裡面的埠                                                                                             |
| 院內 CA 或簽章金鑰指紋與 T-02 不一樣                                   | **停手**，有新的金鑰產生了；T-08 那張表應該已經擋下來，回頭看是哪一步漏看                                              |

### T-11 在主機上登入

**做什麼**：主機的瀏覽器開 **`http://<IP>:18080`**——不要用 `localhost`，**也不要再用 `<名稱>`**。用管理者登入；第一次部署、還沒改過密碼的話，用 `.env` 的 `SUPER_ADMIN_WORK_ID` 與 `SUPER_ADMIN_INITIAL_PASSWORD`：

```
Select-String -Path $cfg -Pattern '^SUPER_ADMIN_(WORK_ID|INITIAL_PASSWORD)='
```

**成功**：登得進去（第一次是被要求改密碼；新密碼由**護理長**決定、自己保管，你不要記在任何地方）。用 `http://<名稱>:18080` 開，頁面還是開得起來，**按登入一定 `Failed to fetch`**：放行名單上現在只有 `<IP>`。這不是壞掉，是位址換過了。

### T-12 在護理站的電腦上登入

**做什麼**：**護理站的電腦**開 `http://<IP>:18080`，登入（請護理長自己輸入密碼）。🏥 護理站的電腦要 Windows 密碼才進得去、螢幕會休眠，休眠後要重新輸入（1029 實測）：先找好會在場、能幫忙輸入的護理師。

**成功**：登入成功。**這一步過了，換位址才算數。** 記下時間（1029 是 15:34）。

做完之後：

- 護理站瀏覽器裡的書籤、桌面捷徑，有用 `<名稱>` 的**全部改成 `http://<IP>:18080`**
- **告訴護理站的人**：網址換了，舊的網址頁面開得起來，但登不進去

### T-13 平板連得到，下載頁換過了

**做什麼**：平板（或手機）連上**平板實際要用的那個 Wi-Fi**，瀏覽器開 `http://<IP>:18081/shell/`。

**成功**：看得到下載頁；安裝步驟第 2 點寫的主機位址是 **`https://<IP>:18081`**，不是 `<名稱>`；「版本資訊」的三個 SHA-256 **抄下來**，交接文件要用（E-10 那一項）。檔案 SHA-256 每建一次 APK 就會變，以 T-08 最後一次之後的為準；簽章憑證與院內 CA 兩個 SHA-256 與換之前相同。

### T-14 收尾

**做什麼**

```
Remove-Item "$root\config\.env.before-ip"
Get-ChildItem "$root\config"
```

**成功**：`config` 裡只剩 `.env`（與 `ai-gateway` 資料夾，做過的話）；演練紀錄寫了下面幾格：

| 記什麼                    | 從哪一步                                      |
| ------------------------- | --------------------------------------------- |
| 改用 IP，由誰確認、哪一天 | T-01                                          |
| T-02 抄的五樣             | 拿回來判斷之前為什麼登不進去（E-13）          |
| 每一步的開始與結束時間    | T-07 的建置、T-08 的 `shell-builder` 特別要記 |
| 新的金鑰備份檔名          | T-09                                          |
| 三個 SHA-256              | T-13                                          |

**IP 本身只寫演練紀錄**，不寫進任何會上站的文件。接著回到當趟進院冊的下一步（1029 是接著換版）；從零部署時，備份還原（V-18）往下照做，登入確認（V-17）已在 T-11、T-12 做完，`shell-builder` 那幾步（V-20～V-24）T-08～T-10 已經補上。

## 3. 換回名稱

T-04 之後、T-12 之前任何一步發現 `<IP>` 行不通（例如資訊室改口說 IP 不能固定），而資訊室確認名稱查得到，就換回去。**步驟一樣、代價一樣**：

```
Copy-Item "$root\config\.env.before-ip" $cfg
docker compose --env-file $cfg build
docker compose --env-file $cfg up -d
docker compose --env-file $cfg --profile shell run --rm shell-builder
docker compose --env-file $cfg --profile shell run --rm shell-builder keys-backup
docker compose --env-file $cfg --profile shell run --rm shell-builder keys-verify
docker compose --env-file $cfg restart patient-web
```

`.env.before-ip` 的 `CORS_ORIGINS` 要先確認是 `http://<名稱>:18080`（1001 填錯的就是這一行）。`shell-builder` 這次會寫「這一次新產生：伺服器憑證（`<名稱>`）」，是對的。之後照 T-07 的表、T-10 的表、T-11～T-13 同樣驗一次，只是 `<IP>` 都換成 `<名稱>`。

**不要換來換去。** 每換一次都要重建、重簽，T-02 抄下來的線索也會一次比一次遠。決定之前先拿到資訊室的書面答覆（T-01）。

## 4. 平板已經佈建了的話

1029 起 `TB-00` 已佈建，**之後再換位址，這一節一定要做**。除了第 2 節，還要：

| 要做什麼                                                                                                                                                                                  | 為什麼                                               |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| **先約好停機時段**，在護理端確認那段時間沒有平板綁著病人                                                                                                                                  | 換位址的那一刻起，所有平板都連不上，直到各自重新佈建 |
| 每一台平板的 App **清除資料**，照《[平板與外殼 App](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-tablet-2/index.md)》第 5 節重新佈建，主機位址填 `https://<新位址>:18081` | App 裡記的是舊位址，而舊位址的伺服器憑證已經不存在   |
| App **不必重裝**                                                                                                                                                                          | 院內 CA 與簽章金鑰都沒換（第 1 節）                  |

平板越多，這一節越貴——這就是「`<主機>` 擇一之後不要再換」的原因（`deploy/hospital.env.example` 的 `MDM_KIOSK_BASE_URL` 說明也這樣寫）。

## 5. 可能怎麼壞

| 在哪一步   | 症狀                                                          | 處置                                                                                                                                                   |
| ---------- | ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| T-03       | 主機上的 IP 與資訊室給的不一樣                                | **停手**，問清楚再做                                                                                                                                   |
| T-04       | 護理站或平板開不到 `<IP>`                                     | 防火牆或網段，**找資訊室，不要往下改**。不要自己關防火牆                                                                                               |
| T-06       | 第二條印出來的三行，主機部分不一樣（例如有一行還是 `<名稱>`） | 回記事本，三行改成一字不差                                                                                                                             |
| T-07       | `failed to resolve source metadata`，後面有 `no such host`    | Docker 查不到 Docker Hub 的網域。依序：同一條再打一次 → 工作列 Docker 圖示右鍵 Restart、等變綠再打 → 請資訊室看院內 DNS；用了哪一個辦法才過，寫進紀錄  |
| T-07       | `npm error code ETIMEDOUT` 或 `ECONNRESET`                    | 網路不穩，再打一次；已下載的部分會沿用                                                                                                                 |
| T-07       | 網頁裡的後端位址還是 `<名稱>`                                 | `build` 沒有吃到新的 `.env`：多半是少了 `--env-file $cfg`，或 `$cfg` 沒設（開工三行）。補上再 `build`、`up -d`                                         |
| T-07       | 放行檢查什麼都沒印                                            | `CORS_ORIGINS` 還不是 `http://<IP>:18080`，或改完沒有 `up -d`。日誌最後一行「允許的前端來源」會告訴你後端手上是哪一份                                  |
| T-07       | 日誌那一條什麼都沒印                                          | 那一行開頭的 `[Console]::OutputEncoding = [Text.Encoding]::UTF8;` 漏打了，補上整行再打                                                                 |
| T-07       | `api` 一直是 `Restarting`                                     | `docker compose --env-file $cfg logs api --tail 30`，最後幾行寫是哪一條設定被拒，照著改 `.env` 再 `up -d`                                              |
| T-08       | `MDM_KIOSK_BASE_URL 要以 https:// 開頭`                       | 第三行改的時候把 `https://` 改掉了，改回來                                                                                                             |
| T-08       | 新產生的清單裡有「院內 CA」或「APK 簽章金鑰」                 | **停手**（T-08 那張表）                                                                                                                                |
| T-10       | **最後一次**啟動的日誌是「找不到伺服器憑證…暫以 HTTP 提供」   | T-08 沒成功，或做完沒有 `restart patient-web`                                                                                                          |
| T-10       | `keys-info` 的伺服器憑證還是 `DNS:<名稱>`                     | T-08 沒有讀到新的 `.env`，回 T-06 的第二條確認，再重跑 T-08                                                                                            |
| T-11、T-12 | 頁面開得了，按登入 `Failed to fetch`                          | 網址列是不是 `http://<IP>:18080`（不是 `<名稱>`、不是 `localhost`）；是的話按 Ctrl＋F5 強制重新整理，舊網頁可能還留在瀏覽器裡。仍不行照上層文件第 2 節 |
| T-11       | `工作ID 或密碼錯誤`                                           | 有連到後端了（名單已修好），帳號密碼的事，見上層文件第 2 節第 1 步                                                                                     |
| T-12       | 主機上登得進去，護理站的電腦開不到頁面                        | T-04 應該已經擋下來。找資訊室                                                                                                                          |
| T-13       | 下載頁上的主機位址還是 `<名稱>`                               | T-08 沒成功，或瀏覽器顯示的是舊頁面（重新整理）                                                                                                        |
| 任何一步   | 試了一小時仍然不通                                            | **停手**，照第 3 節換回名稱，把每一步的結果與錯誤原文抄回來                                                                                            |

## 6. 一張紙帶進去

1. **資訊室說 IP 已經固定，才換**（T-01）
1. **改之前先從護理站與平板連一次 `<IP>`**，連不到就不要改（T-04）
1. **改之前先抄**：五樣（T-02）
1. **三個位址一起改，一字不差**（T-06）
1. **`build` → `up -d` → `shell-builder` → `keys-backup` → `restart patient-web`**，一步都不能少（T-07～T-10）
1. **`shell-builder` 新產生的只能有伺服器憑證**，看到 CA 或簽章金鑰就停手（T-08）
1. **之後一律開 `http://<IP>:18080`**，護理站的書籤一起改（T-12）
1. 平板已佈建：每一台清除資料、重新佈建（第 4 節）
1. 登不進去：訊息 → 網址列 → 主機上五條，全部抄下來（上層文件第 2 節）
