    進院通則¶

    狀態：現行（常備參考）。每一趟進院都適用；那一趟自己的停手條件、時間、要帶的東西寫在那一趟的詳細版。

    1117 由舊總覽（index.md）第 0、0.1、2、3、6、7 節與舊第五冊（05-carry-in-out.md）不屬於隨身碟的部分改寫：情報蒐集表、離院前十問、回家 24 小時，以及不分路線的帶進帶出規則。第五冊的隨身碟、交付單、寫在紙上的三組值、安裝包時代的實體清單收在《安裝包路線（歷史）》。

    編號沿用第五冊的 C-xx：這一份有 C-01（不分路線的列）、C-03（紙上的值，安裝包時代的寫法加註現況）、C-04～C-48；C-01 的隨身碟列與 C-02（隨身碟裡放什麼）在《安裝包路線（歷史）》。

    摘要¶

    • 《部署規範》寫必須怎樣，部署手冊寫手指要按什麼；兩者衝突以部署規範為準（第 0 節）
    • 三種結果先講好：A 完全成功、B 部分成功（最可能）、C 失敗；C 只要紀錄做滿就不是白跑（第 1 節）
    • 整套最重要的一句：離開醫院之後拿不到任何院內資訊，沒問到的就是真的沒有了
    • 有系統管理員權限的資訊室同仁沒約到就不要去；「到時候看看」當成沒約到（第 2 節）
    • 當場停手：有人要開對外網路、手動開容器掛整顆磁碟、資料庫只能放雲端同步或共用目錄、時區錯而沒人能改、冒煙測試沒過就要下班；防毒排除加不了 1116 起不停手（第 3 節）
    • 現場五條原則：一次一件、每步計時、錯誤抄原文、不確定先不按、紙本比螢幕可靠（第 4 節）
    • 帶進帶出：紀錄可以帶、資料不能帶；照片只進私人 repo，.env、密碼、病人資料的畫面不拍（第 5 節）
    • 情報蒐集表 C-08～C-42 是失敗時真正的交付物，已知答案標在表上（第 6 節）；離院前十問（第 7 節）、回家 24 小時內（第 8 節）

    0. 部署手冊是什麼¶

    《部署規範》寫的是必須怎樣，部署手冊寫的是你的手指要按什麼。

    規範會告訴你「資料庫目錄必須加入防毒排除清單」；手冊會告訴你，在哪一台機器、按哪個選單、加完之後怎麼確認它真的生效了、加不成的時候現場還有什麼辦法。（這個例子在容器路線已改：1116 起防毒排除不加也能跑、出現現象再加，見《交接紙》「防毒」那一列。）

    手冊假設你是第一次做這件事。 1117 起整套分成三類：

    類 寫什麼
    演練並進院 一趟一個任務一冊：主文件每一步只寫做什麼（一條指令或一個動作，照抄即可）與成功（螢幕上應該出現什麼——看不到它就是沒成功，不要「看起來沒出錯就往下」）；為什麼、會看到的原文、可能怎麼壞、怎麼處理在同一個編號的詳細版
    離院紀錄 一趟一冊，只記錄不改寫
    常備參考 之後還會用到的做法與院內現況；這一份是其中之一

    已知的每一種失敗方式都寫進手冊，不留到現場查。院內主機對外連線是常態（0930 Q-32 答覆），手冊可以開在主機的瀏覽器上；但你用的那台未必查得到東西，現場也不該花時間查，所以照那一趟的規定印出來或開好。

    1. 三種結果，先想清楚哪一種算數¶

    先把成功的定義寫下來，人在現場才不會被氣氛牽著走。 每一趟的詳細版會把 A、B、C 寫成那一趟的具體條件；下表是通則。

    等級 達成什麼 離院前一定要做完的事
    A 完全成功 服務在院內主機上跑起來、護理站電腦連得進來、冒煙測試通過；那一趟的目標全做到（含交接） 交接文件、帳號密碼保管（親手移交，不寫在紙上）、紀錄填完
    B 部分成功（最可能的一種） 服務起得來，但平板沒到位、某幾項設定要等資訊室或院方 把卡在哪、要等誰、要什麼逐項寫下來（第 6 節）
    C 失敗 那一趟的第一件事沒做成，或主機根本不讓你動 情報全部帶回來。這時候紀錄是唯一的產出，而它決定下一次會不會再失敗

    舊總覽 0923 寫這張表時是安裝包路線：B 原本寫「安裝包進去了、服務起得來」，C 寫「安裝包進不去」；0926 起改容器路線，條件照上表。到 1116 五趟的結果：0922 C、1001 B、1029 B、1109 做到 B-15、1116 B（各趟紀錄見部署手冊目錄的「離院紀錄」）。

    C 不是白跑一趟，前提是紀錄做滿。 假設這次會失敗，要帶回哪些資訊，才能讓下一次一定成功——第 5～8 節整段在講這件事。

    最重要的一句話：離開醫院之後，你拿不到任何院內的資訊——院內的檔案、資料庫、畫面一樣都不能帶出來，下一次進院又要等時段。沒問到的，就是真的沒有了。

    3. 什麼情況下當場停手¶

    硬幹的代價比擇日重來高得多，而且當下通常看不出來。下列任一情形出現，停手、記錄、擇日：

    情形 為什麼不能硬幹
    有人說「把網路開一下就好了」 零院外連線是整套系統的前提。第一天就自己破壞它，之後沒有人會再認真看待這條
    ~~拿不到系統管理員權限，有人提議用他的帳號跑服務~~ 0926 作廢：DEP-12 已作廢，信任邊界改為「能登入這台主機的人」（DEP-38）
    有人提議手動開一個容器、把整顆磁碟掛進去「比較方便」 0922 就是這樣失敗的（《第一次進院紀錄》F-01、F-02）。容器一律由 docker compose 產生，繫結掛載只准兩個（DEP-37；第 3 條的例外是讀檔的唯讀掛載，見《讀檔：啟用、檢查、停用》）
    資料庫目錄只能放在「文件」或某個共用目錄 那多半是雲端同步資料夾或人人讀得到的位置，等於把病人資料攤開（DEP-21、DEP-37）
    ~~防毒排除清單當天加不了，有人說「先跑跑看」~~ 1116 起不停手：容器路線的資料庫在 Docker 的虛擬磁碟裡，Defender 看不到 SQLite 的檔，原本擔心的間歇性鎖定不會因防毒發生（照架構推論，未實測）。照樣請資訊室加，加不了寫進交接紙；現象與處置見《交接紙》「防毒」那一列與《第五次進院（1116）任務二之一：詳細版》SY-03
    主機時區不是 Asia/Taipei，而沒有人有權限改 後端會拒絕啟動（DEP-15）。這一條擋得住，硬繞過去只會讓班表整張錯開
    冒煙測試沒過，但已經到了下班時間 半成品留在現場比沒有東西更糟：護理師會開始用它，然後把問題當成系統的正常行為

    停手的時候要做的三件事：把服務維持在一個說得清楚的狀態（若已啟動又要停，照《備份、還原與關服務》做到「停用」；換版中途就照《本系統換版與退回》退回）、把現況寫進演練紀錄、當場講清楚下一次需要什麼。不要留一個「好像可以用」的狀態給別人。

    4. 現場的基本原則（五條）¶

    1. 一次只做一件事，做完看結果再做下一件。 連下三個指令再一起看輸出，出事時分不出是哪一個。
    2. 每一步都計時。 耗時是下次估時間的唯一依據。
    3. 錯誤訊息抄原文，不要抄大意。 「連不上」沒有用，getaddrinfo ENOTFOUND binaries.prisma.sh 有用。
    4. 不確定就先不要按。 尤其是任何會刪東西、覆蓋東西、改權限的動作。
    5. 紙本比螢幕可靠。 院內主機雖然連得出去，你用的那台未必能查——所以那一趟規定要印的冊與交接紙一定印出來帶進去（舊總覽寫的是「第十一、十二冊要印」，現在照每一趟詳細版「要帶的東西」）。

    5. 帶進去與帶出來（不分路線）¶

    前提是：假設這次會失敗。 不是消極，是算術。進院有太多事不在你手上——權限、防毒、連接埠、變更流程、平板、位址——其中任何一項不成立，今天就做不完。所以要回答的不是「怎麼成功」，而是：萬一失敗，要帶回哪些東西，才能讓下一次不可能再失敗。 判準只有一句：離開醫院之後，院內的任何資訊你都再也拿不到。

    未經掃毒的任何檔案 DEP-26

    5.4 絕對不帶出來的（C-06）¶

    不帶 包含
    任何檔案 備份、資料庫、紀錄檔、設定檔、匯出的表格
    含病人資料或祕密的截圖、照片 病歷、白板、床位標示上的姓名；.env 的內容、密碼、病人資料的畫面
    任何真實病人資料 姓名、病歷號、床號對應到的人、任何一筆症狀回報

    0923 原文寫的是「任何截圖或照片都不帶」；1116 起改成可以拍照，照片只進私人 repo，.env 的內容、密碼、病人資料的畫面不拍（第五次進院兩冊的公開範圍）。

    紀錄可以帶，資料不能帶。 兩者的分界線是：紀錄描述系統與流程（「服務在第 137 分鐘啟動成功」），資料描述病人（「3 號床的王先生回報頭暈」）。

    手抄也一樣受這條規範約束。筆記本上出現任何一個真實姓名或病歷號，那本筆記本就成了要管制的東西。私人紀錄也不寫密碼、PIN、.env 的祕密值與病人的值。

    A 級：沒有它，下一次一定會再失敗。 B 級：沒有它，下一次會卡住但救得回來。

    離院前逐條看一次：A 級有任何一項空白，就回頭去問，不要離開。

    印出來，一題一題填。 空白的格子比錯誤的答案更危險——錯的答案會被發現，空白的會被遺忘。

    6.1 主機與權限（A 級）¶

    # 要問到 為什麼沒有它會再失敗 已知（到 1116） 答案
    C-08 主機的固定位址（DNS 名稱或 IP） 憑證、APK、護理端建置時寫進去的 API 位址都靠它（安裝包路線時還寫死在安裝包裡）。不知道就只能再跑一趟 IP 是固定的（1007 Q-27）；1029 起改用 IP
    C-09 本專案可用的三個連接埠，且已登記 正式環境沒填埠就拒絕啟動 13000、18080、18081（0930）；1029 與同機專案沒衝突；有沒有正式登記沒有書面
    C-10 服務執行帳號的名稱與網域、密碼由誰保管、多久到期 密碼到期那天服務會停，而沒有人知道為什麼 容器路線不另設服務帳號（DEP-12 0926 作廢）；主機登入用的是醫師的帳號，由知道密碼的人輸入
    C-11 有沒有系統管理員權限、由誰代為操作 註冊服務、改權限、改防毒都要它 1116 抓取腳本用一般 PowerShell（不是系統管理員）；防毒、Docker 設定請資訊室
    C-12 防毒是哪一套、誰能加排除清單、流程多久 原本擔心沒有排除清單會出現間歇性的資料庫鎖定失敗（容器路線 1116 起推論不會，第 3 節） Defender 正在運作（1001）；排除清單 1029 是空的；1116 定不加、出現現象再加，由資訊室加
    C-13 資料庫與備份的指定路徑（哪一顆磁碟、哪個資料夾） 路徑決定了 .env，也決定了 DEP-08 成不成立 設定、備份、匯出在 C:\hd\hd-tablet-care；資料庫在 Docker 的具名資料卷
    C-14 備份的院內第二台機器：位址、存取方式、誰保管 備份只落在同一台機器等於沒有備份 還沒問（《上線準備清單》A-05）
    C-15 磁碟保留空間的門檻、誰監看 磁碟寫滿時 SQLite 是直接寫入失敗，不會先變慢 沒議定；開發端建議剩 50 GB 就通知

    6.2 交付流程（A 級）¶

    # 要問到 為什麼 已知（到 1116） 答案
    C-16 隨身碟政策：允不允許、要不要報備、有沒有指定加密碟 這是唯一一種「全部做對了還是進不去」的失敗 0926：不准用隨身碟，改容器＋git clone（部署規範 v3.0）
    C-17 指定掃毒站的位置、經手人、結果留存方式 下次可以直接約時間，不必現場找人 不用隨身碟後不適用
    C-18 變更申請流程：要不要、多久、誰核准 要走申請的話，下次要提前兩週送件 —
    C-19 日後每次更新都要重走一次嗎 決定更新的節奏是「隨時」還是「每季一次」 —
    C-20 可接受的部署與更新時段 要避開透析班次（DEP-32） 三班 08:00～12:00、13:30～17:30、18:00～22:00（1111）；1116 DEP-32 例外：首波開始用之前不必避開透析
    C-21 外來筆記型電腦：能不能帶、能不能接院內網路 位址不如預期時唯一的補救路徑（安裝包路線） —

    C-22 護理站電腦連得到主機嗎（實測） 在護理站電腦上開主機網址 1029 換成 IP 後 15:34 登得進去
    C-23 護理站電腦的瀏覽器與版本 說明 → 關於 —

    C-25 Wi-Fi 的 SSID 與認證方式（開放／密碼／企業級／要登記 MAC） 問資訊室 —
    C-26 透析區與護理站是不是同一個網段 問資訊室 還沒問（Q-12）
    C-27 常駐總覽螢幕的位置與硬體現況（Q-10） 現場看一眼 還沒指定（《上線準備清單》A-10）

    6.4 平板（A 級，若平板尚未到貨）¶

    # 要問到 為什麼 已知（到 1116） 答案
    C-28 採購進度與預計到貨日 決定下一次進院的時間 首波用 1 台暫用平板 TB-00；正式 15 台未決（Q-33）；尺寸 10 吋（0930）
    C-29 決定的型號與 Android 版本 低於 5.0 就沒有螢幕固定，整個方案要重想 TB-00 是三星、One UI 5.1.1
    C-30 院方允不允許側載 APK 不允許的話整條路線要重新決策（Q-11） 1029 已從院內主機的下載頁裝到 TB-00；院方正式答覆（Q-11 第 2 題）仍在待問
    C-31 自簽 CA 符不符合院方資安規範；院方要不要自己簽發 決定 APK 裡打包哪一張憑證 —（憑證由院內主機產生，見《平板與外殼 App》）
    C-32 床位編號與實際位置、平板放哪、怎麼充電、怎麼消毒 序號對床號的表、支架採購（Q-22） 院方床號 1116 看到 A1～E9（沒有 4）、I1、I2、1A～3D、99；消毒 SOP 未答（Q-22）

    7. 離院前的十個自我提問¶

    站在門口，一題一題問自己。答不出來就回頭。

    1. 主機的固定位址是什麼？（C-08）
    2. 我拿到三個連接埠了嗎？（C-09）
    3. 防毒排除清單加了沒？沒加的話誰要加、什麼時候？（C-12；1116 起沒加也可以，但交接紙要寫「出現現象再加」與現象）
    4. 備份會落在院內哪一台機器？（C-14）
    5. 下次要不要再走一次變更申請？（C-19）
    6. 平板什麼時候到、是哪一款？（C-28、C-29）
    7. 每個床位的 Wi-Fi 我測過了嗎？（C-24）
    8. 手機裡含院內資料的照片移出了嗎、PowerShell 關了嗎、瀏覽器登出了嗎、下載的 zip 與無痕視窗清掉了嗎？（0923 原文問「隨身碟清乾淨了嗎」，安裝包路線的 H-23，見《安裝包路線（歷史）》）
    9. 第 11 章 26 條清單有沒有任何一條是空白的？
    10. 如果今天完全失敗，我帶回去的東西夠不夠讓下一次一定成功？

    第 10 題答「不夠」的話，回頭去把 A 級那幾張表補完。 補完要花 20 分鐘；不補，就是再花一整天跑一趟。

    8. 回到家之後 24 小時內¶

    # 做什麼 為什麼是 24 小時內
    C-43 把筆記本打進《部署演練紀錄》，院內的值與照片放進私人 repo 的 deploy/records// 錯誤原文與耗時，過一天就變成「大概」
    C-44 把 A 級答案回填進《尚待確認事項清冊》的 Q-27、Q-29、Q-11、Q-12、Q-10（與那一趟相關的其他題） 那份清冊是所有待確認事項的總表，答案不回填等於沒問到
    C-45 把位址、連接埠、路徑與主機現況改進《院內主機現況與未完成事項》（0923 原文寫的是寫進《平板與外殼 App》K-01 與《安裝包路線之四》R-08） 下次直接照抄，不必重想
    C-46 把「卡住的事」（C-40）逐項排成下一次的準備工作；寫那一趟的離院紀錄 這張表就是下一次的 D-14 清單
    C-47 銷毀寫著密碼的那張紙（如果有）
    C-48 把手冊沒寫到、但你現場才發現要帶的東西補進那一趟的詳細版與第 5.1 節 手冊是這樣長大的
