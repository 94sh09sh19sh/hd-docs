    .env 怎麼填¶

    狀態：現行（常備參考）。 這一份只做一件事：院內主機上那一份 .env，每一行要填什麼。從零部署時接在《從零部署本系統》V-12（＝W-11、Y-03）；院內主機上已經有一份，核對照第 6 節。開發機演練的填法不同，看《.env 怎麼填之一：開發機演練》。

    從哪幾份舊冊改寫（1117）：第十五冊之一全部，逐項對到 v0.5.0 的 deploy\hospital.env.example（讀檔的四行寫進「填好的樣子」、院方 API 的位址改成院內一律留空、範本第 98 行斷掉的註解）。

    編號：沒有步驟編號；節號沿用第十五冊之一（1.1～1.12），舊紀錄寫的「之一 1.12」就是這裡的 1.12。

    分成幾份（1118 拆，每份 300 行內）：本份是第 0～1 節（開始之前、逐項填）；《.env 怎麼填（第 2 份，第 2～6 節）》是第 2～6 節（填好的樣子、填完之後核對、保管、日後改值、院內主機上已經有一份）。子文件：《.env 怎麼填之一：開發機演練（第 0～1 節）》（🧪 開始之前、逐項填）、《.env 怎麼填之二：開發機演練（第 2～5 節）》（🧪 填好的樣子、核對、開發機的 IP 變了、與院內的差異總表）。

    變數的真本是 repo 裡的 deploy\hospital.env.example（每一項上面都有註解），規則的真本是《部署規範》v3.0。這一份與範本不一致時，以範本為準；範本加、刪、改變數，這一份與之一都要跟著改。範本的註解裡還寫著 hd-server 當例子，那一樣只是例子。

    1001 起這一份取代第十四冊之一（《第二次進院（1001）· 從零部署本系統之七、之八：.env 怎麼填》），依 1001 帶回來的資料（《第二次進院紀錄》）改寫：

    改了什麼 為什麼
    根目錄改成 C:\hd\hd-tablet-care 1001 實際放在這裡（M-03）
    範例不再寫 hd-server，一律寫 <主機> 1001 現場問過「hd-server 要照寫嗎」（M-04）
    <主機> 怎麼決定，移到《從零部署本系統》V-08 它要在填 .env 之前定下來，而且要資訊室確認
    填完之後多一條「有沒有照抄範例」的檢查 同上
    新增第 6 節：主機上已經有一份 .env 時怎麼核對 1001 已經填過一份，之後不要蓋掉它

    0. 開始之前¶

    0.1 有三份很像的檔案，只有一份是對的¶

    檔案 給誰用 這次要不要碰
    repo\deploy\hospital.env.example 部署用的範本 複製它，不要直接改它

    Copy-Item $root\repo\deploy\hospital.env.example $cfg

    ⚠️ 院內主機上已經有一份（1001 填的，1029、1116 換版時補過）。Copy-Item 會直接蓋掉它，不會問。在院內主機上不要打第一行，改照第 6 節核對。

    ⚠️ v0.5.0 的範本第 98 行是一行斷掉的註解「aw_txt 與 hb-status.json）」，開頭沒有 #（迭代 32 寫範本時 hospital_dataset\raw_txt 的 \r 被當成換行）。整份複製後 compose 會停在 failed to read …\.env: line 98: unexpected character … in variable name …。複製完在記事本裡刪掉那一行（或在開頭加 #）。master 已修（8c12505），v0.5.0 之後的 tag 沒有這一行。在已經有 .env 的主機上只補缺的幾行時，只貼那幾行、不要整段複製範本（1116 模擬實測）。

    0.2 寫法的四條規矩¶

    規矩 對 錯
    一行一個，等號前後不要空格 HD_API_PORT=13000 HD_API_PORT = 13000
    值不要加引號 HD_BACKUP_DIR=C:\hd\hd-tablet-care\backups HD_BACKUP_DIR="C:\hd\hd-tablet-care\backups"（雙引號裡的 \ 會被當成跳脫字元）
    密碼類的值不要含 $、#、空白、引號 Hd-Init-2026x Hd$Init#2026（$ 會被當成變數、# 之後會被當成註解）
    # 開頭的行是說明，不要刪，也不要把值寫在它後面

    例外：讀檔的資料夾路徑（1.12）有空白與中文時照寫、不加引號——compose 檔用長語法掛載，一個值就是一個路徑，不會被空白拆開。

    存檔時用記事本預設的 UTF-8 即可。

    1. 逐項填¶

    照範本由上往下的順序（範本順序：1.1～1.8、1.12、1.10、1.9；1.11 範本裡已經沒有）。每一項都寫：填什麼、範例、填錯會怎樣。

    1.1 版本¶

    變數 填什麼 範例
    HD_IMAGE_TAG 與 V-11 git describe --tags 印出來的完全相同 v0.5.0
    • 映像檔的名字會帶這個值（hd-tablet-care:v0.5.0；ai-gateway、shell-builder 的映像檔也帶它）。舊版映像檔不刪，回退時才找得到。
    • 填錯：與 checkout 的 tag 不同 → 建出來的映像檔名字和內容對不上，日後沒人說得清它是哪一版。
    • 之後只在更新或回退時改它（《本系統換版與退回》W-19、W-20）。

    1.2 主機目錄¶

    變數 填什麼 範例
    HD_BACKUP_DIR 備份資料夾的完整路徑 C:\hd\hd-tablet-care\backups
    HD_CONFIG_DIR 這份 .env 所在的資料夾 C:\hd\hd-tablet-care\config
    HD_EXPORT_DIR 研究與後續計畫的資料取出寫在這裡（1027 迭代 28 起，DEP-47） C:\hd\hd-tablet-care\export
    • 前兩個資料夾都要先存在（V-09 建的）。填錯：bind source path does not exist。
    • 不准放在雲端同步資料夾、網路磁碟機、RAM 磁碟（院內主機的 E 槽就是）、C:\Users\<帳號>\ 底下的桌面／文件／下載（DEP-21、DEP-37）。
    • HD_CONFIG_DIR 不能是 repo 底下：某一次「整個刪掉重新 clone」會把設定一起刪掉（DEP-08）。AI 閘道的 config.yaml 放在它底下的 ai-gateway\。
    • HD_EXPORT_DIR 與備份資料夾分開：不能是同一個、也不能一個在另一個裡面（備份會送往院內另一台機器，取出檔不該跟著走）；不准放的地方與上面相同，也不在 clone 目錄裡。只掛給一次性的 data-export，api 碰不到。資料夾不必先建，第一次取出時自動建立；沒有填的話，每一個 docker compose 指令都會停在「請設定 HD_EXPORT_DIR」。怎麼取資料見《取出資料》。

    1.3 連接埠¶

    變數 填什麼 範例
    HD_API_PORT 資訊室給的後端埠 13000
    HD_NURSE_PORT 資訊室給的護理端埠 18080
    HD_PATIENT_PORT 資訊室給的病人端埠 18081
    • 三個都必填、沒有預設值。填之前照 V-07 確認沒人在用。
    • 填錯：與別的專案撞到 → address already in use；更糟的是現在沒撞、某次重新開機兩邊啟動順序對調才撞。所以一定要登記，不是「看起來沒人用」就好。

    1.4 位址¶

    這三項最容易填錯，填錯的症狀都是「頁面開得了，但登不進去或資料打不回來」——1001 就是卡在這裡（《第二次進院紀錄》M-01）。

    變數 填什麼 範例
    HD_PUBLIC_API_URL 護理站電腦連得到的後端位址：http://<主機>:<後端埠> http://<主機>:13000
    CORS_ORIGINS 護理站瀏覽器網址列上的護理端來源：http://<主機>:<護理端埠> http://<主機>:18080
    MDM_KIOSK_BASE_URL 平板要連的病人端位址，一律 https://：https://<主機>:<病人端埠> https://<主機>:18081
    • 三項的 <主機> 是同一個值，寫法一字不差（名稱就都寫名稱、IP 就都寫 IP；有 DNS 尾碼就三項都有）。1029 起院內是固定 IP。
    • HD_PUBLIC_API_URL 會在建置時寫進護理端的網頁檔案裡。事後改它，要重新 build 再 up -d，只重新啟動沒有用。寫進去的是什麼，可以用 V-17 第二段那條 grep 直接看。迭代 12 起病人端經病人端自己的埠轉送呼叫後端，不用這個值。
    • CORS_ORIGINS 的主機與埠要與護理站瀏覽器網址列上看到的一字不差（名稱與 IP、有沒有尾碼，都算不同的來源）。所以護理站一律用 http://<主機>:18080 開，不要用 localhost 或另一種寫法。病人端與後端同一個來源，不必列。
    • 真的需要在主機上用 localhost 開，才用逗號多列一個：http://<主機>:18080,http://localhost:18080。
    • MDM_KIOSK_BASE_URL：
    • 開頭一定是 https://。寫成 http://，shell-builder 會拒絕、平板的外殼也會拒收 QR code。
    • 不能是 localhost：平板上的 localhost 是平板自己。
    • 埠與 HD_PATIENT_PORT 相同。
    • 結尾不要加 /。
    • shell-builder 以這裡的主機名稱或 IP 簽伺服器憑證（平板管控方案 6.1）：兩者擇一之後不要再換。

    1.5 外殼 App¶

    變數 填什麼 範例
    HD_SHELL_SRC_DIR 外殼 repo 的 clone 位置（V-20 會 clone 到這裡） C:\hd\hd-tablet-care\hd-kiosk-shell
    HD_SHELL_SIGNING hospital（範本預設就是，不要改） hospital
    KIOSK_SHELL_MIN_VERSION 留空 （空白）
    • HD_SHELL_SRC_DIR 還沒 clone 也要先填好路徑：每一條 docker compose 指令都會檢查它有沒有填。不必自己 checkout：shell-builder 會從這份 clone 取出本系統釘住的那一版（services/shell-builder/shell.pin，v0.5.0 釘外殼 v0.3.0）；換外殼版本前在那個目錄執行 git fetch --tags。
    • HD_SHELL_SIGNING：院內主機一律 hospital。金鑰第一次產生時會記下它，之後填別的值 shell-builder 會拒絕執行。看到「這個金鑰資料卷是『dev』用的」就是有人把模擬部署的設定搬過來了——停手。
    • KIOSK_SHELL_MIN_VERSION：留空就用程式內建的預設值。低於它的平板在護理端標為「外殼過舊」。等所有平板都換上新版外殼才調高（《平板與外殼 App》Y-15）；調高只要改這裡並重新啟動 api，不必重建映像檔。

    1.6 身分驗證¶

    變數 填什麼 範例
    JWT_SECRET 用下面的指令產生的一串亂碼 k3Jd…（64 個字元）
    JWT_EXPIRES_IN 維持 8h 8h
    SUPER_ADMIN_WORK_ID 第一個最高權限帳號的工號 護理長給的
    SUPER_ADMIN_INITIAL_PASSWORD 第一次登入用的臨時密碼 自己訂，遵守 0.2 節第三條
    SUPER_ADMIN_DISPLAY_NAME 這個帳號顯示的名字 護理長給的

    產生 JWT_SECRET（Windows 內建的 PowerShell 就做得到，不必裝 Node.js，也不必下載任何映像檔）：

    $b = New-Object byte[] 48; [Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($b); [Convert]::ToBase64String($b).TrimEnd('=').Replace('+','-').Replace('/','_')

    印出一行 64 個字元、只有英數字與 -、_ 的字串。把那一整串貼在 JWT_SECRET= 後面。

    舊版手冊與範本的註解（到 v0.5.0 都還是）用 docker run --rm node:20-bookworm-slim … 產生。1001 在院內主機上用那條，兩次都因為 Docker 查不到 Docker Hub 的網域而失敗 （《第二次進院紀錄》M-06、M-07）。上面這一行不必連網，沒有這個問題。

    • JWT_SECRET 是登入憑證的簽章金鑰。每次部署產生新的，不要沿用模擬部署那一串，也不要寫在任何別的地方。事後換掉它，所有人會被登出，要重新登入。
    • SUPER_ADMIN_* 只在資料庫裡一個使用者都沒有時才用得到：第一次啟動時建立這個帳號，第一次登入強制改密碼。改完密碼之後，這兩行可以清空（清空後 docker compose --env-file $cfg up -d）。
    • 填錯：沒填 SUPER_ADMIN_WORK_ID 或密碼 → 沒有任何帳號能登入。補上再 up -d，資料庫不必重建。帳號已經建立之後才改這幾行，不會改到已建立的帳號。

    1.7 備份與磁碟¶

    變數 填什麼 範例
    BACKUP_DAILY_AT 每日自動備份的時間（24 小時制 HH:MM），挑沒有透析的時段 03:00
    DB_DISK_MIN_FREE_MB Docker 資料所在磁碟的保留空間下限（MB），資訊室議定前維持 1024（Q-27） 1024

    • 填錯：時間寫成 3:00 或 3點 → 後端拒絕啟動，日誌會說「格式須為 HH:MM」。

    1.11 判斷規則的書面確認閘門（1010 新增，同日迭代 18.1 拿掉）¶

    .env 裡沒有這一項了。 迭代 18 時它是 HIGH_RISK_WRITTEN_CONFIRMATION；1010 使用者指示改放進系統管理，迭代 18.1 起後端不讀它，範本也拿掉了。

    • 法務／資訊室對 TFDA 分類的書面確認（清冊 Q-02）拿到之後，由系統管理者在護理端系統管理「判斷規則」按「登記書面確認」，填文號與理由；每一次登記與取消登記都寫進稽核軌跡。不必動設定檔、不必重新啟動。
    • 沒登記之前，風險分層提示、療程中預警、劑量調整參考、透析適足性趨勢推估只對合成資料病人執行，真實病人一律擋下並寫進稽核軌跡；這四項的功能開關預設也都是關的。只登記還不夠，每一條規則另要在畫面上附出處、標為生效（清冊 Q-03）。
    • 照舊版範本填過的設定目錄，那一行留著也不會生效（後端啟動時提醒一聲），刪掉即可。

    1.12 院方資料：讀抓取腳本存下的檔（1111 迭代 32 新增）¶

    1110 起院內不打院方 API，讀主機上抓取腳本 hd-hospital-fetch 存下的檔（實作規格書 4.32）。範本裡這一段在 1.8 AI 之後、1.10 院方 API 之前。從零部署時四行都先留空、COMPOSE_FILE 那一行維持註解，病人、床位與療程照護理師的人工操作；啟用、檢查、停用照《讀檔：啟用、檢查、停用》。

    變數 從零部署時 啟用之後（1116 起院內現況）
    HD_DIALYSIS_LIST_DIR （空白） 透析清單的指定資料夾（寫 YYYY-MM.txt 的那一個）的完整路徑：C:\API_Fetch\IDH_interface。有空白與中文照寫、不加引號；用檔案總管網址列複製貼上最不會錯。抓取腳本的 status_file 要指到這個資料夾裡的 fetch-status.json
    HD_LAB_DIR （空白） （空白）——1111 學長答 hb 不用這邊處理（《院方 API 介接之二》A-5），檢驗資料先不讀。日後要讀才填 Hb_API_Fetch 的完整路徑（底下有 hospital_dataset\raw_txt 與 hb-status.json），填之前先重問《院方 API 介接之二之一》第 3.4 節的 I-9、I-12、I-13（《檢驗資料（hb）抓取（未採用）》）
    COMPOSE_FILE 維持範本那一行的註解（開頭有 #） 把開頭的 # 拿掉，只留有填的那幾個檔：docker-compose.yml;docker-compose.dialysis-files.yml
    HOSPITAL_LAB_FIELD_MAP （空白） （空白）——用暫定的對照表；之二 I-9（白蛋白用哪一欄）、I-12（Kt/V 公式）答覆後才填，例如 HOSPITAL_LAB_FIELD_MAP=ALBUMIN=ALB;KT_V=Kt/V(Daugirdas)
    • COMPOSE_FILE 用分號隔開，第一個一定是 docker-compose.yml；填了 HD_DIALYSIS_LIST_DIR 才加 docker-compose.dialysis-files.yml，填了 HD_LAB_DIR 才加 docker-compose.lab-files.yml。HD_LAB_DIR 空白卻放了 docker-compose.lab-files.yml，compose 會停在 docker-compose.lab-files.yml 要配 HD_LAB_DIR（整段複製範本那一行最容易帶進來）。不能留成空白的一行（COMPOSE_FILE=，compose 會讀不到設定檔）。
    • 範本那一行（註解）的原文是 # COMPOSE_FILE=docker-compose.yml;docker-compose.dialysis-files.yml;docker-compose.lab-files.yml，三個檔都列著；院內只用前兩個。
    • 兩個資料夾都以唯讀掛進 api，本系統不搬、不刪、不改任何留底檔（DEP-37 第 3 條的例外）。路徑寫錯時 Docker Desktop 會替它建一個空資料夾（create_host_path: false 在 Docker Desktop＋WSL2 上沒有效，1111 實測），後端讀到空資料夾，護理站出現「看不到抓取腳本的狀態」與「院方資料已 N 分鐘未更新」。
    • HOSPITAL_API_BASE_URL 維持空白——與 HD_DIALYSIS_LIST_DIR 兩個都填，後端拒絕啟動（1.10）。
    • 讀檔頻率、檢驗資料讀檔頻率、「未更新」提示時段（迭代 32.1 起預設 8～23 時）在護理端「系統管理 → 營運參數與選項清單」調，不在 .env。
    • 範本的註解寫「路徑不進 repo、不寫進公開文件，現場值記在私人紀錄」。C:\API_Fetch\IDH_interface 是 1116 起抓取腳本的固定位置，已寫在進院冊與維運文件裡；其他院內路徑（例如舊的 D 槽路徑）照舊只記在私人 repo 的 deploy/records/。
