🏥 與 🧪 相同：

## 1. 逐項填

照範本由上往下的順序。每一項寫 🏥 與 🧪 各填什麼；「🧪 不同」那一欄打勾的，就是模擬部署要特別留意的地方。

### 1.1 版本

| 變數           | 🏥 填什麼                                                         | 🧪 填什麼                 | 🧪 不同 |
| -------------- | ----------------------------------------------------------------- | ------------------------- | ------- |
| `HD_IMAGE_TAG` | 與 N-10 `git describe --tags` 印出來的**完全相同**，例如 `v0.2.0` | 要測的 tag，例如 `v0.2.0` |         |

- 映像檔的名字會帶這個值（`hd-tablet-care:v0.2.0`）。舊版映像檔不刪，回退時才找得到。
- **填錯**：與 checkout 的 tag 不同 → 建出來的映像檔名字和內容對不上，日後沒人說得清它是哪一版。
- 之後只在**更新或回退**時改它（[《本系統換版與退回》](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-upgrade/index.md) W-19、W-20）。
- 🧪 要測更新演練時，會另打一個測試 tag（容器路線原冊第 7 節，[《從零部署本系統之一：容器路線的原冊》](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-fresh-install-detail/index.md)），那時照 W-19 把 `HD_IMAGE_TAG` 改成測試 tag。

### 1.2 主機目錄

| 變數            | 🏥 填什麼                                                  | 🧪 填什麼           | 🧪 不同      |
| --------------- | ---------------------------------------------------------- | ------------------- | ------------ |
| `HD_BACKUP_DIR` | 備份資料夾的**完整路徑**，例如 `D:\hd-tablet-care\backups` | `C:\hd-sim\backups` | ✓ 根目錄不同 |
| `HD_CONFIG_DIR` | 這份 `.env` 所在的資料夾，例如 `D:\hd-tablet-care\config`  | `C:\hd-sim\config`  | ✓ 根目錄不同 |

- 兩個資料夾都要先存在（N-08 建的）。**填錯**：`bind source path does not exist`。
- 不准放在雲端同步資料夾、網路磁碟機、RAM 磁碟、`C:\Users\<帳號>\` 底下的桌面／文件／下載（DEP-21、DEP-37）。🧪 一樣不要放在 OneDrive 或這些地方，模擬部署要練的就是院內那套規矩。
- `HD_CONFIG_DIR` **不能是 `repo` 底下**：某一次「整個刪掉重新 clone」會把設定一起刪掉（DEP-08）。
- 🏥 1001 實際填的是 `C:\hd\hd-tablet-care` 底下的資料夾（紀錄 M-03）。

### 1.3 連接埠

| 變數              | 🏥 填什麼                            | 🧪 填什麼 | 🧪 不同            |
| ----------------- | ------------------------------------ | --------- | ------------------ |
| `HD_API_PORT`     | 資訊室給的**後端**埠，例如 `13000`   | `13000`   | ✓ 自己挑，不必登記 |
| `HD_NURSE_PORT`   | 資訊室給的**護理端**埠，例如 `18080` | `18080`   | ✓                  |
| `HD_PATIENT_PORT` | 資訊室給的**病人端**埠，例如 `18081` | `18081`   | ✓                  |

- 三個都必填、沒有預設值。**填之前照 N-07 確認沒人在用**。
- 🏥 **填錯**：與別的專案撞到 → `address already in use`；更糟的是現在沒撞、某次重新開機兩邊啟動順序對調才撞。所以一定要**登記**，不是「看起來沒人用」就好。
- 🧪 故意**不用** `3000`、`5173`、`5174`：那是平常 `npm run dev` 用的，兩者同時開會撞。N-07 查到被佔用時，自己換一個，後面所有用到那個埠的地方跟著改。

### 1.4 位址

這三項最容易填錯，填錯的症狀都是「頁面開得了，但資料打不回來」。

| 變數                 | 🏥 填什麼                                                                                                  | 🧪 填什麼                                       | 🧪 不同                  |
| -------------------- | ---------------------------------------------------------------------------------------------------------- | ----------------------------------------------- | ------------------------ |
| `HD_PUBLIC_API_URL`  | **護理站電腦**連得到的後端位址：`http://<主機>:<後端埠>`，例如 `http://hd-server:13000`                    | `http://localhost:13000`                        | ✓ 實際部署是院內主機名稱 |
| `CORS_ORIGINS`       | **護理端**的位址：`http://<主機>:<護理端埠>`，例如 `http://hd-server:18080`                                | `http://localhost:18080`                        | ✓                        |
| `MDM_KIOSK_BASE_URL` | **平板**要連的病人端位址，**一律 `https://`**：`https://<主機>:<病人端埠>`，例如 `https://hd-server:18081` | `https://192.168.1.23:18081`（**換成你的 IP**） | ✓ 用開發機的區網 IP      |

- `HD_PUBLIC_API_URL` **會在建置時寫進護理端的網頁檔案裡**。事後改它，要重新 `build` 再 `up -d`，只重新啟動沒有用。
- `CORS_ORIGINS` 的主機與埠要與護理站瀏覽器網址列上看到的**一字不差**（`hd-server` 與 `hd-server.hospital.local` 算兩個不同的來源）。病人端與後端同一個來源，**不必列**。
- `MDM_KIOSK_BASE_URL`：
- 開頭**一定是 `https://`**（🧪 也一樣）。寫成 `http://`，`shell-builder` 會拒絕、平板的外殼也會拒收 QR code。
- **不能是 `localhost`**：平板（🧪 手機）上的 `localhost` 是平板自己。
- 埠與 `HD_PATIENT_PORT` 相同。
- 結尾不要加 `/`。
- 🧪 護理端只在開發機自己的瀏覽器開，所以用 `localhost`。想從**另一台電腦**開護理端時，`HD_PUBLIC_API_URL` 與 `CORS_ORIGINS` 也要改成區網 IP，而且 `HD_PUBLIC_API_URL` 改了要重新 `build`（它寫在網頁檔案裡）。一般模擬部署不需要。
- 🏥 1001 填的是**主機名稱**（`hostname` 印出的那一個，紀錄 M-04 的 1005 補記）；1029 改成 IP。

### 1.5 外殼 App

| 變數                      | 🏥 填什麼                                                                                | 🧪 填什麼                  | 🧪 不同                                        |
| ------------------------- | ---------------------------------------------------------------------------------------- | -------------------------- | ---------------------------------------------- |
| `HD_SHELL_SRC_DIR`        | 外殼 repo 的 clone 位置（N-19 會 clone 到這裡），例如 `D:\hd-tablet-care\hd-kiosk-shell` | `C:\hd-sim\hd-kiosk-shell` | ✓ 根目錄不同                                   |
| `HD_SHELL_SIGNING`        | **`hospital`**（範本預設就是，不要改）                                                   | **`dev`**                  | ✓ 範本預設是 `hospital`，**🧪 這一項一定要改** |
| `KIOSK_SHELL_MIN_VERSION` | **留空**                                                                                 | 留空                       |                                                |

- `HD_SHELL_SRC_DIR` 還沒 clone 也要**先填好路徑**：每一條 `docker compose` 指令都會檢查它有沒有填。
- 🏥 `HD_SHELL_SIGNING`：院內主機一律 `hospital`。金鑰第一次產生時會記下它，**之後填別的值 `shell-builder` 會拒絕執行**。看到「這個金鑰資料卷是『dev』用的」就是有人把模擬部署的設定搬過來了——**停手**。
- 🧪 `HD_SHELL_SIGNING=dev` 讓 `shell-builder` 產生「開發用」的簽章金鑰，N-21 會印出「APK 簽章金鑰（開發用）」。這把金鑰簽出來的 APK 與院內版**不能互相覆蓋安裝**，這正是要的效果：開發用的東西不會混進院內。忘了改、留著 `hospital` 跑下去的話，資料卷會記成院內用。撤除重來即可（N-31），**不要事後才改成 `dev`**——`shell-builder` 會拒絕。
- `KIOSK_SHELL_MIN_VERSION`：留空就用程式內建的預設值。等所有平板都換上新版外殼才調高（[《平板與外殼 App》](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-tablet-2/index.md) Y-15）。

### 1.6 身分驗證

| 變數                           | 🏥 填什麼                                             | 🧪 填什麼        | 🧪 不同    |
| ------------------------------ | ----------------------------------------------------- | ---------------- | ---------- |
| `JWT_SECRET`                   | 用下面的指令產生的一串亂碼，例如 `k3Jd…`（64 個字元） | 用下面的指令產生 |            |
| `JWT_EXPIRES_IN`               | 維持 `8h`                                             | `8h`             |            |
| `SUPER_ADMIN_WORK_ID`          | 第一個最高權限帳號的工號（護理長給的）                | `sim-admin`      | ✓ 虛構即可 |
| `SUPER_ADMIN_INITIAL_PASSWORD` | 第一次登入用的臨時密碼，自己訂，遵守 0.2 節第三條     | `Sim-Init-2026`  | ✓ 虛構即可 |
| `SUPER_ADMIN_DISPLAY_NAME`     | 這個帳號顯示的名字（護理長給的）                      | `模擬部署管理員` | ✓ 虛構即可 |

產生 `JWT_SECRET`（Windows 內建的 PowerShell 就做得到，不必裝 Node.js，也不必下載任何映像檔；🧪 **跟院內用同一行 PowerShell，不要用開發機上的 Node.js**，這一輪要驗的就是「只靠 Git 與 Docker」）：

```
$b = New-Object byte[] 48; [Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($b); [Convert]::ToBase64String($b).TrimEnd('=').Replace('+','-').Replace('/','_')
```

印出一行 64 個字元、只有英數字與 `-`、`_` 的字串。把那一整串貼在 `JWT_SECRET=` 後面。

舊版手冊用 `docker run --rm node:20-bookworm-slim …` 產生。那條指令要先從 Docker Hub 下載映像檔，第一次跑會先印出 `Unable to find image 'node:20-bookworm-slim' locally`，網路不通就停在那裡（1001 現場兩次都下載失敗，紀錄 M-07，當天改成上面這一行）。改用上面這一行就沒有這個問題。

- `JWT_SECRET` 是**登入憑證的簽章金鑰**。🏥 每次部署產生新的，**不要沿用模擬部署那一串，也不要寫在任何別的地方**。事後換掉它，所有人會被登出，要重新登入。🧪 每一輪模擬部署都重新產生，**不要把這一串帶到院內**。
- `SUPER_ADMIN_*` **只在資料庫裡一個使用者都沒有時**才用得到：第一次啟動時建立這個帳號，第一次登入強制改密碼。改完密碼之後，這兩行可以清空（清空後 `docker compose --env-file $cfg up -d`）。
- **填錯**：沒填 `SUPER_ADMIN_WORK_ID` 或密碼 → 沒有任何帳號能登入。補上再 `up -d`，資料庫不必重建。
- 🧪 N-16 用 `sim-admin` ／ `Sim-Init-2026` 登入，會被要求改密碼，改成什麼都可以，撤除時一起消失。

### 1.7 備份與磁碟

| 變數                  | 🏥 填什麼                                                               | 🧪 填什麼 | 🧪 不同 |
| --------------------- | ----------------------------------------------------------------------- | --------- | ------- |
| `BACKUP_DAILY_AT`     | 每日自動備份的時間（24 小時制 `HH:MM`），挑沒有透析的時段，例如 `03:00` | `03:00`   |         |
| `DB_DISK_MIN_FREE_MB` | 磁碟保留空間的下限（MB），資訊室議定前維持 `1024`                       | `1024`    |         |

- 低於保留空間時，護理端的資料庫狀態會亮紅、更新指令會直接停下。主機是共用的，磁碟不是本系統一個人在寫。
- **填錯**：時間寫成 `3:00` 或 `3點` → 後端拒絕啟動，日誌會說「格式須為 HH:MM」。
- 🧪 開發機半夜多半關機，排程備份不會跑到，沒關係：N-17 是手動按「立即備份」驗的。

### 1.8 AI

**首波 AI 關閉**，這一段 🏥 與 🧪 都照下表填，不必多想：

| 變數                         | 填什麼   |
| ---------------------------- | -------- |
| `LLM_PROVIDER`               | `mock`   |
| `LLM_ENDPOINT`               | （空白） |
| `LLM_API_KEY`                | （空白） |
| `LLM_MODEL_ID`               | （空白） |
| `LLM_TIMEOUT_SECONDS`        | `150`    |
| `LLM_HEALTH_TIMEOUT_SECONDS` | `5`      |

- **絕對不要填 `lab`**。實驗室在院外，後端看到 `lab` 會直接拒絕啟動（DEP-40）——那是刻意擋的，不是壞掉。
- 🧪 **模擬部署也不准填 `lab`**。compose 把後端固定成正式環境設定，填 `lab` 會拒絕啟動——與院內一模一樣，這正是 N-30 驗收要驗的一條。想用實驗室的真模型試 AI，那不是模擬部署，是[《AI 閘道》](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-ai-gateway/index.md)的開發端做法（走 `npm run dev` 與 SSH 通道，另一套設定）。
- 🏥 日後接上院內正式 GPU API 時才改成 `onprem`，做法在《AI 閘道》Z-23。
