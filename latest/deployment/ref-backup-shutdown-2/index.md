# 備份、還原與關服務（第 2 份，第 3～6 節，S-03～S-09）

上層文件：《[備份、還原與關服務](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-backup-shutdown/index.md)》

> - 狀態：**現行**（常備參考），**要印出來帶進去**；1117 由舊的第八冊（把服務關乾淨）與舊第十一冊第 8 節（容器版的關服務指令）改寫；編號 `S-xx`（沿用第八冊），各步的「安裝包（歷史）」是 0926 以前的路線
> - 第 0～2 節（四條判準、三種深度怎麼選、備份與還原、S-01～S-02）與開工三行在第 1 份

## 摘要

- 深度一暫停：S-03 停止服務、S-04 驗證四條判準，恢復只要 `up -d` 再確認
- 深度二停用：先做完 S-01～S-04 再 `down`，資料卷還在；停手撤退一定用停用
- 深度三撤除要院方書面指示；先讓平板補傳（S-07）、做最後一次備份並驗證（S-06），才收東西（S-08）、交資料（S-09）
- **三種都不刪資料庫與備份**，資料去向是院方的決定
- 不管哪一種深度都寫下來（第 6 節）：沒有寫下來的停機，下一個人只會看到「系統壞了」

## 3. 深度一：暫停

### S-03 停止服務

**做什麼**（容器路線）：

```
docker compose --env-file $cfg stop
```

只停後端（換版、還原時）是 `docker compose --env-file $cfg stop api`。

**成功**：每個容器印 `Stopped`；接著做 S-04。

| 症狀                                            | 處置                                                              |
| ----------------------------------------------- | ----------------------------------------------------------------- |
| 有人想用 `docker stop $(docker ps -q)` 一次關掉 | **不要**，會關到同機別人的容器                                    |
| 想先把 `.env` 改壞讓它起不來                    | 不要。那是讓它一直失敗、一直重新啟動，不是停止；要它不起來用 S-05 |

**安裝包（歷史）**：一般情形 `.\scripts\service-stop.ps1`；共用主機、S-02 看到別人的行程會被誤收時，只收這一包底下的：

```
$pkg = (Get-Location).Path
Stop-ScheduledTask -TaskName HD-TabletCare
Start-Sleep -Seconds 2
Get-CimInstance Win32_Process -Filter "Name = 'node.exe'" | Where-Object { $_.CommandLine -like "*$pkg*" } | ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
```

腳本印出「已停止」只是開始。`Stop-Process` 說存取被拒：不是系統管理員身分，行程屬於服務帳號。**不要在工作管理員裡結束 `node.exe`**：只結束其中一個，啟動器會把其餘兩個一起收掉並以失敗結束，排程工作一分鐘後就重試——等於重新啟動。

### S-04 驗證四條判準

**做什麼**（容器路線，對第 0.1 節的四條；1117 改寫、還沒實測）：

```
# 1. 本系統的服務
docker compose --env-file $cfg ps

# 2. 一次性容器（名字有 -run- 的就是）
docker ps --filter "name=hd-tablet-care" --format "{{.Names}}  {{.Status}}"

# 3. 三個連接埠
Get-NetTCPConnection -State Listen -LocalPort 13000, 18080, 18081 -ErrorAction SilentlyContinue

# 4. 有沒有容器掛著資料卷
docker ps --filter "volume=hd-tablet-care-data" --format "{{.Names}}"
```

| #   | 應該看到               |
| --- | ---------------------- |
| 1   | 只有表頭，沒有任何一列 |
| 2   | 什麼都沒印             |
| 3   | 什麼都沒印             |
| 4   | 什麼都沒印             |

**安裝包（歷史）**：`<…>` 換成 `.env` 裡的值：

```
# 1. 排程工作
Get-ScheduledTask -TaskName HD-TabletCare | Select-Object TaskName, State

# 2. 本安裝包底下的行程
$pkg = (Get-Location).Path
Get-CimInstance Win32_Process -Filter "Name = 'node.exe'" | Where-Object { $_.CommandLine -like "*$pkg*" } | Select-Object ProcessId, CommandLine

# 3. 三個連接埠
Get-NetTCPConnection -State Listen -LocalPort <API_PORT>, <NURSE_PORT>, <PATIENT_PORT> -ErrorAction SilentlyContinue

# 4. 資料庫檔案能否獨占開啟
$db = "<資料目錄>\<資料庫檔名>"
try { $fs = [IO.File]::Open($db, 'Open', 'ReadWrite', 'None'); $fs.Close(); "沒有人開著它" } catch { "仍被佔用：$($_.Exception.Message)" }
```

應該看到：1 `State` 是 `Ready`（停用過則是 `Disabled`），不是 `Running`；2、3 什麼都沒印；4 `沒有人開著它`。

兩條路線都一樣：再到護理站電腦重新整理護理端，**畫面可能還出得來**（PWA 會用快取的頁面），但登入或讀資料會失敗，畫面出現斷線紅框。這是對的。

| 症狀                                              | 原因                                                          | 處置                                                                                                                                                                                                      |
| ------------------------------------------------- | ------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 容器：第 1、2 條還有一列                          | 一次性容器還在跑，或 `stop` 沒成功                            | 再打一次 S-03；是 `-run-` 的就等它跑完                                                                                                                                                                    |
| 第 3 條有東西，但第 1、2 條是空的                 | 那個埠被**別的程式**佔著                                      | 看它的 `OwningProcess` 是誰。**不是本系統的就不要動它**，記下來，下次啟動時會撞埠                                                                                                                         |
| 安裝包：第 1 條還是 `Running`                     | 排程工作沒停成                                                | 再跑一次 `Stop-ScheduledTask`；還是一樣就到工作排程器裡對它按「結束」                                                                                                                                     |
| 安裝包：第 2 條有行程、第 1 條是 `Ready`          | 子行程沒跟著收掉                                              | 照 S-03 共用主機那一段，只收這一包底下的                                                                                                                                                                  |
| 安裝包：過一兩分鐘又冒出行程                      | 有人在工作管理員裡結束過行程，失敗重試被觸發了                | 做 S-05，再回頭做 S-03                                                                                                                                                                                    |
| 安裝包：第 4 條「仍被佔用」，但第 2、3 條都是空的 | 防毒即時掃描、備份軟體，或有人用其他工具開著資料庫            | 《[現場疑難排解](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-troubleshooting/index.md)》X-14。安裝包時代**九成是防毒**；容器路線的資料庫在 Docker 的虛擬磁碟裡，防毒看不到，這一條不成立 |
| 資料庫旁邊還有 `-wal`、`-shm` 兩個檔              | **正常。** 最後一段寫入還在 `-wal` 裡，下次啟動會自動併回主檔 | **不要刪。** 要搬、要備份，三個檔一起（DEP-09）                                                                                                                                                           |

### 恢復（暫停之後）

容器路線：

```
docker compose --env-file $cfg up -d
docker ps --format "{{.Names}}  {{.Image}}  {{.Status}}"
curl.exe -s http://localhost:13000/api/health
```

三個服務 `Up`、health 是 `{"status":"ok",…}`，**再告訴病房已經恢復**。安裝包（歷史）：`.\scripts\service-start.ps1`、`.\scripts\service-status.ps1`，排程工作 `Running`、3 個行程、存活檢查 HTTP 200。

## 4. 深度二：停用

### S-05 停用

**做什麼**：先做完 S-01～S-04，再：

```
docker compose --env-file $cfg down
docker compose --env-file $cfg ps -a
```

**成功**：第二條只有表頭（容器已刪掉；資料卷 `hd-tablet-care-data`、`hd-tablet-care-keys` 還在，`docker volume ls --filter name=hd-tablet-care` 看得到兩個）。重新開機後再跑一次 S-04，四條仍然成立。

**安裝包（歷史）**：

```
Disable-ScheduledTask -TaskName HD-TabletCare
Get-ScheduledTask -TaskName HD-TabletCare | Select-Object TaskName, State
```

`State` 是 `Disabled`。

| 症狀                                     | 處置                                                                                                   |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 主機要重新開機，但來不及驗證開機後的狀態 | 至少在紀錄裡寫「已停用，重新開機後未驗證」，並請資訊室開機後代跑 S-04（安裝包是 `service-status.ps1`） |
| 停手撤退、下一次不知道什麼時候           | **一定用停用，不要只暫停。** 你走之後主機一重新開機，一個半成品可能就自己跑起來                        |

### 恢復（停用之後）

容器路線：`docker compose --env-file $cfg up -d`，再照「恢復（暫停之後）」確認。安裝包（歷史）：

```
Enable-ScheduledTask -TaskName HD-TabletCare
.\scripts\service-start.ps1
.\scripts\service-status.ps1
```

## 5. 深度三：撤除

**撤除要有院方的書面指示**（誰要求、哪一天、資料怎麼處理）。口頭說「這個不用了，拆掉吧」不夠：撤除之後就沒有回頭路，而資料的去向必須有人負責。

順序：**S-07（平板補傳）→ S-06（最後一次備份，服務還在跑時做）→ S-01、S-03～S-05（停用）→ S-08 → S-09**。舊第十一冊第 8 節寫「`down` 之後先做最後一次備份」：`down` 之後護理端的「立即備份」就按不到了，所以改成先備份再 `down`。

### S-06 撤除前的最後一次備份

**做什麼**：服務還在跑的時候，照第 1.2 節（安裝包時代是 H-17）做一次備份，**還原到另一個檔案驗證過**，並確認它（連同 `.sha256` 與 `keys\` 的金鑰備份）落在院內另一台機器（DEP-06）。

**成功**：還原後雜湊相符、完整性檢查 ok、筆數對得上。這一份就是交給院方的最終版本。

| 症狀                 | 處置                                                                         |
| -------------------- | ---------------------------------------------------------------------------- |
| 備份失敗             | **撤除停在這裡。** 沒有驗證過的最終備份，不要往下走                          |
| 院方說「資料不要了」 | 仍然要做這一份。「不要了」要寫進書面指示，由院方決定銷毀，不是由你決定不備份 |

### S-07 撤除前先讓平板把資料送完

**做什麼**：平板上暫存、還沒補傳的症狀回報，服務一撤除就再也送不出去。**最後一次備份之前**，讓每一台還在用的平板都連上過一次，等它自動補傳。

**成功**：每一台平板都在連線狀態下停留過幾分鐘，護理端看得到那段期間的回報。

| 症狀                   | 處置                                                   |
| ---------------------- | ------------------------------------------------------ |
| 某一台平板找不到或沒電 | 記下平板編號，寫進交接：**那一台上可能有沒送出的回報** |
| 平板已經先被收走了     | 同上。之後就算找回來，也沒有伺服器可以收               |

求助不會暫存（送不出去就當場告訴病人），所以這一步只跟症狀回報有關。

### S-08 移除主機上的東西

**做什麼**：依序做完 S-07、S-06、S-01、S-03～S-05，然後（容器路線；1117 改寫，第 3、4、6 列的指令還沒實測）：

| #   | 要收的東西                                          | 誰做                         | 怎麼做                                                                                                                                                                              |
| --- | --------------------------------------------------- | ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 容器與網路                                          | 你                           | S-05 的 `down` 已經收掉                                                                                                                                                             |
| 2   | 資料卷 `hd-tablet-care-data`、`hd-tablet-care-keys` | 你，院方書面同意後           | S-06 的最終備份與金鑰備份確認已送到另一台機器，才 `docker volume rm hd-tablet-care-data hd-tablet-care-keys`。**刪了就沒有了**                                                      |
| 3   | 映像檔                                              | 你                           | `docker images --filter "reference=hd-tablet-care*"` 列出本系統的映像檔（本體、`-ai-gateway`、`-shell-builder` 各版），逐一 `docker image rm <名稱>:<標籤>`。同機別人的映像檔不要動 |
| 4   | `$root\repo`、`$root\hd-kiosk-shell`（兩份 clone）  | 你                           | 資料卷刪掉之後才刪                                                                                                                                                                  |
| 5   | `$root\config`（`.env`、AI 閘道的 `config.yaml`）   | 你                           | 刪除。**`.env` 裡有密碼與金鑰**（`JWT_SECRET`、初始密碼）；改 IP 時留的 `.env.before-ip` 也一樣                                                                                     |
| 6   | 部署金鑰（主機的 `.ssh` 裡給 GitHub 用的那一把）    | 你＋開發端                   | 主機上的私鑰刪除；開發端在 GitHub 把它從 repo 的部署金鑰拿掉                                                                                                                        |
| 7   | `$root\backups`、`$root\export`                     | **不刪**，交給院方           | S-09                                                                                                                                                                                |
| 8   | 連接埠的防火牆輸入規則                              | **資訊室**（當初由他們開的） | 請他們關掉，並當場確認                                                                                                                                                              |
| 9   | 防毒排除清單（Docker 資料夾、`backups`，有加的話）  | 資訊室                       | **資料交出之後才移除**。排除清單留著一個已經不用的目錄，是給別人留了一個防毒不看的地方                                                                                              |
| 10  | Docker Desktop 本身、休眠與系統更新時段             | 資訊室                       | 整台主機的設定，同機還有別的專案在用，**要不要改由資訊室決定**，不要自己改                                                                                                          |
| 11  | 院方 API 抓取腳本 `hd-hospital-fetch`               | 另外決定                     | 不是本系統的一部分，APP 組也在讀它的留底檔；要停照《[院方 API 抓取腳本的維運](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-fetch-script/index.md)》                 |

**成功**：`docker compose --env-file $cfg ps -a` 只有表頭（`$cfg` 刪掉之前打）；`docker volume ls --filter name=hd-tablet-care` 什麼都沒有；S-04 第 3 條什麼都沒印；`$root` 底下只剩交給院方的 `backups`、`export`；上表每一列都有人、有時間，寫進紀錄。

| 症狀                                     | 處置                                                                                     |
| ---------------------------------------- | ---------------------------------------------------------------------------------------- |
| `docker volume rm` 說 `volume is in use` | 還有容器掛著它，回 S-04 第 4 條                                                          |
| 刪目錄時說檔案被使用中                   | 還有東西開著它（PowerShell 停在那個目錄、檔案總管開著），換到別的目錄再刪                |
| 資訊室當天沒空關防火牆                   | 記下來，約好時間，**寫進交接文件的待辦**。埠開著但沒人聽不危險，帳號、金鑰留著不用才危險 |

**安裝包（歷史）**：

| #   | 要收的東西                     | 誰做                                                                                                                                                                                  | 怎麼做                                                                                       |
| --- | ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| 1   | 排程工作                       | 你                                                                                                                                                                                    | `.\scripts\service-uninstall.ps1`，再 `Get-ScheduledTask -TaskName HD-TabletCare` 應該找不到 |
| 2   | 三個埠的防火牆輸入規則         | **資訊室**（當初由他們開的，《[第一次進院（0922）· 部署本系統之二：進院當天詳細版](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/visit-1-system-onsite-2/index.md)》H-15） | 請他們關掉，並當場確認                                                                       |
| 3   | 防毒排除清單裡的資料庫目錄     | 資訊室或你（H-14 ①）                                                                                                                                                                  | **資料目錄清空或交出之後才移除**                                                             |
| 4   | 服務帳號                       | **資訊室**（H-12）                                                                                                                                                                    | 請他們停用或刪除                                                                             |
| 5   | `.env`                         | 你                                                                                                                                                                                    | 刪除。裡面有密碼與金鑰，它在安裝包目錄的上一層，刪安裝包不會帶走它                           |
| 6   | 安裝包目錄（含改名保留的舊版） | 你                                                                                                                                                                                    | 排程工作移除之後才刪；刪時說檔案被使用中，表示還有行程沒收掉，回 S-04 第 2 條                |
| 7   | 休眠、系統更新時段（H-14 ④⑤）  | 資訊室                                                                                                                                                                                | 整台主機的設定，要不要改回來由資訊室決定                                                     |

成功：`Get-ScheduledTask -TaskName HD-TabletCare` 找不到；S-04 第 3 條什麼都沒印；安裝包目錄與 `.env` 都不在了。

### S-09 資料與備份交給院方

**做什麼**：備份資料夾（`$root\backups`，含 `keys\`）、匯出資料夾（`$root\export`）、S-06 那一份最終備份，**一律不在現場刪除**。照書面指示交給院方指定的人，當面說清楚：

1. 檔案在哪裡、哪一份是最終版、雜湊是多少（`.sha256`）
1. `-wal`、`-shm` 與主檔是一組，要搬三個一起搬（DEP-09）；容器路線的資料庫在資料卷裡，交出去的是備份檔
1. 要銷毀的話，由院方人員執行，並依院方的病歷資料銷毀規定留紀錄

**成功**：交接文件上有對方簽名，寫明收下了哪些目錄、最終備份的雜湊。

| 症狀                     | 處置                                               |
| ------------------------ | -------------------------------------------------- |
| 「你幫我們刪一刪就好」   | 不行。請院方人員自己按刪除，你在旁邊確認路徑對不對 |
| 想帶一份回去「以防萬一」 | **絕對不可以。** 病人資料不得離院（DEP-14）        |

## 6. 關完要寫下來

不管哪一種深度，都寫進《[部署演練紀錄](https://94sh09sh19sh.github.io/hd-docs/latest/notes/deployment-drills/index.md)》或更新紀錄（院內的值進私人 repo 的 `deploy/records/<MMDD-主題>/`）：

- 哪一種深度、為什麼要關、誰同意的
- 開始與結束的時間；告知了病房的誰（S-01）
- S-04 四條判準的結果，**有任何一條不是一次就過的，寫下原因**
- 誰負責恢復、預計什麼時候恢復（暫停與停用）
- S-08 那張表的每一列、S-09 交給了誰（撤除）
- 院內主機的狀態變了，同時改《[院內主機現況與未完成事項](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-status/index.md)》

**沒有寫下來的停機，下一個人只會看到「系統壞了」。** 半年後有人重新開機發現它沒起來，紀錄是唯一能告訴他「這是故意停用的，要先問過誰」的東西。
