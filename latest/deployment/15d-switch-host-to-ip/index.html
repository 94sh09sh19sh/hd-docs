    第十五冊之四 · 主機位址從名稱改成 IP¶

    版本：v0.1　文件狀態：草案（1005 新增）　編號：T-xx　要改的話，與第十五冊一起印出來帶進去

    這一冊給誰：院內主機的 <主機> 已經填成名稱（1001 就是），之後決定改用 IP 的人。

    第十五冊 V-08 說「<主機> 擇一之後不要再換」，那是因為平板佈建之後再換，每一台平板都要重新佈建。 1001 卡在登入，平板還一台都沒佈建，所以現在換的代價最小：不用動資料庫、帳號、院內 CA、APK 簽章金鑰，也不用重裝任何平板。 這一冊把要做的事從頭排一次，照順序做就能換完，也能換回去。

    什麼時候用這一冊（任一條成立）：

    • 1005 使用者已決定改用 IP，第三次進院照這一冊換（《實作規格書》4.19）。下面「什麼時候不要用」那一條仍然有效：資訊室沒把 IP 固定下來就不換。
    • 資訊室書面答覆（Q-27 第 12 題）是「用固定 IP」。
    • 第十五冊 V-08 第 2 步，護理站的電腦 Resolve-DnsName 查不到這個名稱。
    • 第十五冊 V-17 第四段或 V-25：護理站或平板說「找不到主機」，而資訊室說名稱沒有登記、也不打算登記。

    什麼時候不要用：資訊室還沒答應把 IP 固定下來。IP 會變，就是把「名稱查不到」換成「IP 哪天變了」，更難查。

    指令都是從第十五冊與第十五冊之一第 5 節抄來的，兩邊不一致時以第十五冊為準。 文中的 V-xx 是第十五冊的步驟、E-xx 是第十五冊之三的待辦。

    公開範圍：文件站是公開的。主機名稱、IP、.env 裡的值一律不寫進這一冊，下面用兩個代稱：

    代稱 指的是
    <名稱> 現在 .env 三個位址裡寫的那個名稱（1001 現場用 hostname 決定的那一個）
    <IP> 要換成的那個 IP，資訊室確認、而且固定下來的那一個

    打指令時連同 <、> 一起換掉。

    0. 三十秒看完¶

    問題 答案
    要改什麼 .env 的三個位址（HD_PUBLIC_API_URL、CORS_ORIGINS、MDM_KIOSK_BASE_URL）的主機部分，從 <名稱> 一起換成 <IP>
    改完要做什麼 重建網頁、重新啟動服務、重跑 shell-builder（重簽伺服器憑證）、重新備份金鑰、重新啟動病人端
    不會動到的 資料庫、帳號、三個埠、防火牆規則、院內 CA、APK 簽章金鑰
    要多久 約 40～60 分鐘（建置約 10 分鐘；資訊室確認的時間不算）
    平板 1001 還沒有佈建任何一台，不必管。已經佈建了的話看第 6 節
    換不成怎麼辦 照第 5 節換回名稱，步驟一樣、代價一樣
    最重要的一條 改之前先從護理站連一次 <IP>（T-04）。連不到就不要改，那是網路的問題，換位址解決不了

    1. 先懂兩件事¶

    1.1 名稱與 IP，各自要什麼才會通¶

    用 IP 不是一定成功，兩種寫法各有前提：

    用名稱 用 IP
    前提 院內 DNS 登記過這個名稱 這個 IP 固定不變（資訊室在 DHCP 保留，或設成靜態）
    護理站 要查得到這個名稱 要連得到這個 IP
    平板 要查得到這個名稱。平板常常查不到 Windows 電腦的名稱，這是最常出問題的地方 平板的 Wi-Fi 網段要連得到這個 IP（路由、防火牆）
    會怎麼壞 「找不到主機」 主機重新開機或換網卡後 IP 變了，所有東西突然都連不上，而且當下看不出原因

    所以第十五冊 V-08 才說「拿不準就用資訊室固定下來的 IP」。重點是「固定」，不是「IP」。

    1.2 主機位址寫在哪裡、改了之後各要做什麼¶

    <主機> 不只寫在 .env 裡。改了 .env，下面每一處都要跟著換，少一處就會有一個地方還在用 <名稱>：

    主機位址出現在哪裡 是怎麼放進去的 換成 <IP> 要做什麼 在哪一步
    .env 的三個位址 人填的 用記事本改 T-06
    護理端網頁檔案裡的後端位址 建置（build）時把 HD_PUBLIC_API_URL 寫死進去 build 再 up -d T-07
    後端的放行名單 後端容器建立時讀一次 CORS_ORIGINS up -d T-07
    平板 QR code 裡的位址 後端容器建立時讀一次 MDM_KIOSK_BASE_URL up -d T-07
    伺服器憑證 1001 跑 shell-builder 時，以 <名稱> 簽的 重跑 shell-builder。它發現憑證上的名字和 MDM_KIOSK_BASE_URL 對不上，會自己重簽一張，院內 CA 與簽章金鑰不動 T-08
    金鑰備份 1001 的 hd-keys-20261001-173347.tar.gz 裡是舊的伺服器憑證 重新 keys-backup T-09
    病人端用的憑證 patient-web 啟動時讀一次 restart patient-web T-10
    下載頁上寫的主機位址 shell-builder 寫的 跟著 T-08 換掉 T-08
    護理站瀏覽器的網址列、書籤 人打的 改成 http://<IP>:18080，並告訴護理站的人 T-12
    平板上 App 填的主機位址 佈建時填的 1001 還沒佈建，不必管 第 6 節

    💡 為什麼院內 CA 與簽章金鑰不用換：平板上的 App 只認院內 CA（APK 裡內建的那一張），伺服器憑證只要是這把 CA 簽的、上面寫的位址對，平板就收。 所以換位址只換「伺服器憑證」這一張，APK 不必換簽章、已經裝了 App 的平板也不必重裝。

    2. 動手之前¶

    T-01 拿到資訊室的書面確認¶

    做什麼：問資訊室三件事，要文字答覆（訊息、郵件都可以）：

    1. 院內主機要用的 IP 是哪一個？能不能固定下來（DHCP 保留或靜態）？
    2. 護理站的電腦連得到這個 IP 嗎？
    3. 平板要用的那個 Wi-Fi 連得到這個 IP 嗎？

    這就是 Q-27 第 12 題（E-01），答覆要回填清冊。

    怎麼知道做完了：三題都有答案，第 1 題是「已固定」。演練紀錄寫「<主機> 改用 IP，由＿＿確認，＿＿月＿＿日」——IP 本身不寫進演練紀錄以外的任何文件。

    資訊室的答覆 怎麼辦
    IP 不能固定 不要換。 留在名稱，請資訊室在院內 DNS 登記這個名稱，並確認平板的網段查得到
    護理站或平板的網段連不到 不管用名稱或 IP 都不會通，先請資訊室處理網路，這一冊先不做
    「先用用看」 當成沒有答覆。改位址的代價會隨著佈建的平板數量一起變大

    T-02 先確認主機還是 1001 離開時的樣子，並先抄下現況¶

    做什麼

    1. 照第十五冊 0.5 節檢查一次（E-05）。
    2. 照第十五冊之三 E-06 先抄三樣：.env 的 CORS_ORIGINS 與 HD_PUBLIC_API_URL、日誌最後一行「允許的前端來源」、網頁裡寫死的後端位址。 改成 IP 之後就再也看不到了，而它們是判斷 1001 為什麼登不進去的唯一線索。
    3. 再抄一樣，改完要拿來對照：
    docker compose --env-file $cfg --profile shell run --rm shell-builder keys-info

    怎麼知道成功了：0.5 節的表格每一列都對得上；四樣都抄進演練紀錄。keys-info 印出的「伺服器憑證」那一行應該是 DNS:<名稱>。

    ⚠️ keys-info 印出的「伺服器憑證」那一行如果已經是 IP Address:…，表示 1001 填的其實是 IP，這一冊不用做，停下來先問。

    T-03 在主機上確認 IP¶

    做什麼

    ipconfig /all

    找實體網卡（「乙太網路」或「Wi-Fi」，不是 vEthernet (WSL)、vEthernet (Default Switch)，也不是 172. 開頭的）：

    看什麼 應該是
    IPv4 位址 與資訊室給的 <IP> 一字不差
    DHCP 已啟用 否（靜態）；或 是，但資訊室說已經在 DHCP 保留了這個 IP

    不一樣的話：資訊室給的 IP 與主機上看到的不同，停手，問清楚再做。

    T-04 先從護理站連一次 <IP>（不改任何東西）¶

    這一步最重要。 服務現在就在跑，13000、18080、18081 三個埠用 IP 一樣連得到。先證明連得到，再改設定。

    做什麼

    1. 在護理站的電腦上，瀏覽器開 http://<IP>:13000/api/health。
    2. 同一台電腦開 http://<IP>:18080，看得到登入頁就好，先不要按登入（還沒改放行名單，一定是 Failed to fetch）。
    3. 有平板或手機的話，連上平板實際要用的那個 Wi-Fi，瀏覽器開 http://<IP>:18081/shell/。

    怎麼知道成功了：第 1 條看到 {"status":"ok",…}；第 2 條看到登入頁；第 3 條看到下載頁（下載頁上寫的主機位址還是 <名稱>，現在是對的，T-08 之後才會換）。

    症狀 怎麼辦
    護理站開不到 防火牆或網段的問題。找資訊室，不要自己關防火牆，也不要往下改設定——改成 IP 也不會通
    護理站開得到，平板開不到 平板的 Wi-Fi 網段到不了主機，找資訊室。沒解決之前，換成 IP 一樣佈建不了平板
    主機自己開得到，別台都開不到 同上，防火牆

    3. 改¶

    T-05 留一份改之前的 .env¶

    做什麼（先輸入第十五冊 V-09 的開工三行）

    Copy-Item $cfg "$root\config\.env.before-ip"
Get-ChildItem "$root\config"

    怎麼知道成功了：看得到 .env 與 .env.before-ip 兩個檔。

    ⚠️ 這一份裡有登入簽章金鑰與初始密碼，與 .env 一樣只留在這個資料夾，不複製到別處、不拍照。T-14 成功之後就刪掉；要換回名稱時（第 5 節）才用得到它。

    T-06 把三個位址改成 <IP>¶

    做什麼

    notepad $cfg

    只改這三行的主機部分，http://、https:// 與埠都不動：

    HD_PUBLIC_API_URL=http://<IP>:13000
CORS_ORIGINS=http://<IP>:18080
MDM_KIOSK_BASE_URL=https://<IP>:18081

    1001 的 CORS_ORIGINS 如果用逗號多列了別的來源（例如 localhost），這次一起拿掉，只留 http://<IP>:18080（第十五冊之一 1.4 節）。存檔，關掉記事本。

    怎麼知道成功了

    docker compose --env-file $cfg config --quiet
Select-String -Path $cfg -Pattern '^(HD_PUBLIC_API_URL|CORS_ORIGINS|MDM_KIOSK_BASE_URL)='
Select-String -Path $cfg -Pattern '^[^#].*<名稱>'
Select-String -Path $cfg -Pattern '^[^#].*(<|>|hd-server|localhost)'
    哪一條 應該是
    第一條 什麼都沒印
    第二條 三行，主機部分都是 <IP>、一字不差；前兩行 http://、第三行 https://
    第三條（<名稱> 換成舊的那個名稱） 什麼都沒印——舊名稱一處都不剩
    第四條 什麼都沒印（第十五冊之一第 3 節的「有沒有照抄範例」檢查）

    T-07 重建網頁，再啟動¶

    HD_PUBLIC_API_URL 寫死在網頁檔案裡，只 up -d 沒有用，一定要先 build（第十五冊之三 1.3 節）。

    做什麼（記下開始時間）

    docker compose --env-file $cfg build
docker compose --env-file $cfg up -d
docker compose --env-file $cfg ps

    怎麼知道成功了：build 最後出現 Image hd-tablet-care:<tag> Built；ps 三個服務都是 Up。記下結束時間。

    接著照第十五冊 V-17 第一段與第二段確認（在主機上打）：

    curl.exe -s http://localhost:13000/api/health
docker compose --env-file $cfg exec nurse-web grep -rhoE 'https?://[A-Za-z0-9.-]+:[0-9]+' apps/nurse-pwa/dist/assets
curl.exe -s -i -H "Origin: http://<IP>:18080" http://<IP>:13000/api/health | Select-String Access-Control-Allow-Origin
docker compose --env-file $cfg logs api | Select-String '允許的前端來源' | Select-Object -Last 1
    哪一條 應該是
    health {"status":"ok",…}
    網頁裡的後端位址 http://<IP>:13000，沒有 <名稱>
    放行檢查 Access-Control-Allow-Origin: http://<IP>:18080
    日誌最後一行「允許的前端來源」 http://<IP>:18080

    💡 這一步同時把 1001 登不進去的兩種可能（第十五冊之三 3.2 節）都修掉了：名單換成新的、也 up -d 過了。所以 T-02 一定要先抄，不然就永遠不知道 1001 是哪一種。

    T-08 重跑 shell-builder，重簽伺服器憑證¶

    做什麼

    docker compose --env-file $cfg --profile shell run --rm shell-builder

    它會重建一次 APK（離線建置，不必下載；1001 沒有計時，記下耗時）。

    怎麼知道成功了：「這一次新產生：」後面只有「伺服器憑證（<IP>）」一項。接著是 APK 檔名與三個 SHA-256。

    再打一次同一條指令，這次要看到「金鑰全部沿用，這一次沒有產生任何新的金鑰」。

    「這一次新產生：」後面出現 怎麼辦
    只有「伺服器憑證（<IP>）」 對的
    「伺服器憑證（<名稱>）」 .env 的 MDM_KIOSK_BASE_URL 沒改到，回 T-06
    「院內 CA」或「APK 簽章金鑰」 停手。 金鑰資料卷不是 1001 那一個，或指令少了 --env-file $cfg。不要往下做，照第十二冊第 6 節從備份還原
    這個金鑰資料卷是「dev」用的，設定卻是「hospital」 停手（第十五冊 V-22）

    T-09 重新備份金鑰¶

    伺服器憑證換了，1001 那份備份裡的是舊的。

    做什麼

    docker compose --env-file $cfg --profile shell run --rm shell-builder keys-backup
docker compose --env-file $cfg --profile shell run --rm shell-builder keys-verify

    怎麼知道成功了：第一條印出「已備份：備份目錄/keys/hd-keys-<時間>.tar.gz」；第二條每一項都 ✓，最後「還原得回來」。

    • 新的備份檔名記進演練紀錄，並告訴負責把備份送往另一台機器的人：這一份要送。
    • 1001 那份 hd-keys-20261001-173347.tar.gz 不要刪。 院內 CA 與簽章金鑰兩份是同一把；萬一要從舊的那份還原，shell-builder 發現伺服器憑證的名字對不上，一樣會自己重簽。

    ⚠️ 金鑰備份裡有私鑰，不得出院、不得寄給開發端（第十五冊 V-23）。

    T-10 讓病人端換上新的憑證¶

    做什麼

    docker compose --env-file $cfg restart patient-web
docker compose --env-file $cfg logs patient-web --tail 5
docker compose --env-file $cfg --profile shell run --rm shell-builder keys-info

    怎麼知道成功了

    看什麼 應該是
    日誌最後一次出現的「靜態資源已提供於連接埠 8081」 後面是「（HTTPS；HTTP 只留外殼下載頁）」
    keys-info 的「伺服器憑證」那一行 IP Address:<IP>
    keys-info 的院內 CA 與簽章金鑰指紋 與 T-02 抄的一模一樣

    院內 CA 或簽章金鑰的指紋與 T-02 不一樣，停手——那表示有新的金鑰產生了，T-08 那張表應該已經擋下來，回頭看是哪一步漏看。

    4. 驗證¶

    T-11 在主機上登入¶

    做什麼：主機的瀏覽器開 http://<IP>:18080——不要用 localhost，也不要再用 <名稱>。 用 .env 的 SUPER_ADMIN_WORK_ID 與 SUPER_ADMIN_INITIAL_PASSWORD 登入（第十五冊 V-17 第三段）。

    怎麼知道成功了：被要求改密碼。

    ⚠️ 用 http://<名稱>:18080 開，頁面還是開得起來，按登入一定 Failed to fetch：放行名單上現在只有 <IP>。這不是壞掉，是位址換過了。

    T-12 在護理站的電腦上登入¶

    做什麼：護理站的電腦開 http://<IP>:18080，登入（第十五冊 V-17 第四段）。

    怎麼知道成功了：登入成功。這一步過了，換位址才算數。

    做完之後：

    • 護理站瀏覽器裡的書籤、桌面捷徑，有用 <名稱> 的全部改成 <IP>。
    • 告訴護理站的人：網址換了，舊的網址頁面開得起來，但登不進去。

    T-13 平板連得到，下載頁換過了¶

    做什麼：平板（或手機）連上平板實際要用的那個 Wi-Fi，瀏覽器開 http://<IP>:18081/shell/（第十五冊 V-25）。

    怎麼知道成功了：

    • 看得到下載頁。
    • 安裝步驟第 2 點寫的主機位址是 https://<IP>:18081，不是 <名稱>。
    • 「版本資訊」的三個 SHA-256 抄下來，交接文件要用（第十五冊之三 E-10 那一項就補齊了）。 檔案 SHA-256 每建一次 APK 就會變，以 T-08 最後一次之後的為準；簽章憑證與院內 CA 兩個 SHA-256 與 1001 相同。

    T-14 收尾¶

    做什麼

    Remove-Item "$root\config\.env.before-ip"
Get-ChildItem "$root\config"

    怎麼知道做完了：config 裡只剩 .env（與 V-29 放的 ai-gateway 資料夾，做過的話）；演練紀錄寫了下面幾格：

    記什麼 例
    改用 IP，由誰確認、哪一天 T-01
    T-02 抄的四樣 拿回來判斷 1001 是第十五冊之三 3.2 節的可能 A 還是 B（E-13）
    每一步的開始與結束時間 T-07 的建置、T-08 的 shell-builder 特別要記
    新的金鑰備份檔名 T-09
    三個 SHA-256 T-13

    IP 本身只寫演練紀錄，不寫進任何會上站的文件。

    接著回第十五冊 0.5 節的表，從 V-18（備份與還原）往下做。V-17 已經在 T-11、T-12 做完了；V-20～V-24 也不必重做，T-08～T-10 已經補上。

    5. 換回名稱¶

    T-04 之後、T-12 之前任何一步發現 <IP> 行不通（例如資訊室改口說 IP 不能固定），而資訊室確認名稱查得到，就換回去。步驟一樣、代價一樣：

    Copy-Item "$root\config\.env.before-ip" $cfg
docker compose --env-file $cfg build
docker compose --env-file $cfg up -d
docker compose --env-file $cfg --profile shell run --rm shell-builder
docker compose --env-file $cfg --profile shell run --rm shell-builder keys-backup
docker compose --env-file $cfg --profile shell run --rm shell-builder keys-verify
docker compose --env-file $cfg restart patient-web

    shell-builder 這次會寫「這一次新產生：伺服器憑證（<名稱>）」，是對的。之後照 T-07 的表、T-10 的表、T-11～T-13 同樣驗一次，只是 <IP> 都換成 <名稱>。

    ⚠️ 不要換來換去。 每換一次都要重建、重簽，T-02 抄下來的線索也會一次比一次遠。決定之前先拿到資訊室的書面答覆（T-01）。

    6. 如果平板已經佈建了¶

    1001 還沒佈建任何平板，這一節現在用不到。日後平板已經在用時才要換位址，除了第 3、4 節，還要：

    要做什麼 為什麼
    先約好停機時段，在護理端確認那段時間沒有平板綁著病人 換位址的那一刻起，所有平板都連不上，直到各自重新佈建
    每一台平板的 App 清除資料，照第十五冊 V-26～V-28 重新佈建，主機位址填 https://<IP>:18081 App 裡記的是舊位址，而舊位址的伺服器憑證已經不存在
    App 不必重裝 院內 CA 與簽章金鑰都沒換（1.2 節方框）

    平板越多，這一節越貴——這就是第十五冊 V-08 說「擇一之後不要再換」的原因。

    7. 可能怎麼壞¶

    在哪一步 症狀 處置
    T-04 護理站或平板開不到 <IP> 防火牆或網段，找資訊室，不要往下改。不要自己關防火牆
    T-06 第二條印出來的三行，主機部分不一樣（例如有一行還是 <名稱>） 回記事本，三行改成一字不差
    T-07 failed to resolve source metadata，後面有 no such host Docker 查不到 Docker Hub 的網域，照第十五冊 V-06 第二段那一列處理
    T-07 網頁裡的後端位址還是 <名稱> build 沒有吃到新的 .env：多半是少了 --env-file $cfg，或 $cfg 沒設（開工三行）。補上再 build、up -d
    T-07 放行檢查什麼都沒印 CORS_ORIGINS 還不是 http://<IP>:18080，或改完沒有 up -d。日誌最後一行「允許的前端來源」會告訴你後端手上是哪一份
    T-08 MDM_KIOSK_BASE_URL 要以 https:// 開頭 第三行改的時候把 https:// 改掉了，改回來
    T-08 新產生的清單裡有「院內 CA」或「APK 簽章金鑰」 停手（T-08 那張表）
    T-10 最後一次啟動的日誌是「找不到伺服器憑證…暫以 HTTP 提供」 T-08 沒成功，或做完沒有 restart patient-web
    T-10 keys-info 的伺服器憑證還是 DNS:<名稱> T-08 沒有讀到新的 .env，回 T-06 的第二條確認，再重跑 T-08
    T-11、T-12 頁面開得了，按登入 Failed to fetch 網址列是不是 http://<IP>:18080（不是 <名稱>、不是 localhost）；是的話按 Ctrl＋F5 強制重新整理，舊網頁可能還留在瀏覽器裡。仍不行照第十五冊附錄
    T-12 主機上登得進去，護理站的電腦開不到頁面 T-04 應該已經擋下來。找資訊室
    T-13 下載頁上的主機位址還是 <名稱> T-08 沒成功，或瀏覽器顯示的是舊頁面（重新整理）
    任何一步 試了一小時仍然不通 停手，照第 5 節換回名稱，把每一步的結果與錯誤原文抄回來

    8. 一張紙帶進去¶

    1. 資訊室說 IP 已經固定，才換（T-01）。
    2. 改之前先從護理站與平板連一次 <IP>，連不到就不要改（T-04）。
    3. 改之前先抄：E-06 那三樣、keys-info（T-02）。
    4. 三個位址一起改，一字不差（T-06）。
    5. build → up -d → shell-builder → keys-backup → restart patient-web，一步都不能少（T-07～T-10）。
    6. shell-builder 新產生的只能有伺服器憑證，看到 CA 或簽章金鑰就停手（T-08）。
    7. 之後一律開 http://<IP>:18080，護理站的書籤一起改（T-12）。
