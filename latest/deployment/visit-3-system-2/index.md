## 4. 換到新版

### J-15 下載新版的程式碼，先下載基底映像

**做什麼**：`git fetch --tags`、`git checkout <新 tag>`、`git describe --tags`、`docker pull node:20-bookworm-slim`。

**成功**：`describe` 正好是 `<新 tag>`、沒有尾巴；`pull` 最後是 `Status: Downloaded newer image for …` 或 `Status: Image is up to date for …`。之後到 J-16 之前，`docker compose` 會停在「請設定 HD_EXPORT_DIR」，是對的。

🧪 `<新 tag>` 是 I-01 打的；打一次 `docker compose --env-file $cfg config --quiet`，確認那句真的會出現。

### J-16 補 `.env`

**做什麼**：`notepad $cfg`：`HD_IMAGE_TAG` 改成 `<新 tag>`；`HD_CONFIG_DIR=` 下面加 `HD_EXPORT_DIR=C:\hd\hd-tablet-care\export`；最後加 `HOSPITAL_API_BASE_URL=`、`HD_SIMULATION_DEPLOYMENT=`（都留空白）；存檔後打之四 J-16 的四條檢查。

**成功**：`config --quiet` 沒印東西；`HD_IMAGE_TAG` 與 `git describe` 一字不差；`HD_SHELL_SIGNING` 是 `hospital`；`LLM_PROVIDER` 是 `mock`；院方 API 兩行空白。

🧪 `HD_EXPORT_DIR=C:\hd-sim\export`；檢查表的 `HD_SHELL_SIGNING` 是 `dev`。

### J-17 建置新版的映像檔

**做什麼**：`docker compose --env-file $cfg build`，再 `docker images hd-tablet-care`。

**成功**：`Image hd-tablet-care:<新 tag> Built`；看得到 `v0.3.0` 與 `<新 tag>` 兩個映像檔（`v0.3.0` 不刪）。

🧪 記下耗時。

### J-18 停後端、更新資料庫

**做什麼**：先確認沒有透析、跟護理站講過，再打：

```
$tag = git describe --tags
docker compose --env-file $cfg stop api
docker compose --env-file $cfg run --rm --no-deps api node apps/api/scripts/db-update.mjs --note "v0.3.0 → $($tag)（第三次進院）"
```

**成功**：最後印出「更新完成。接下來的三件事是人要做的」；第 3 段更新前備份的檔名（`hd-before-update-<時間>.db`）與 SHA-256 抄下來。

🧪 第 [5] 段套用 19 個遷移（`iteration15_hospital_api`～`iteration31_connect_dots_norm`）；備份檔名與 SHA-256 之九 I-15 要用。

### J-19 啟動新版，確認還是登得進去

**做什麼**：`docker compose --env-file $cfg up -d`，打之四 J-19 的確認；護理站的電腦 Ctrl＋F5，用護理長的新密碼再登入，看系統管理 →「版本更新紀錄」與稽核軌跡。

**成功**：三個服務的映像檔是 `hd-tablet-care:<新 tag>`、`Up`；health 正常；網頁裡是 `http://<IP>:13000`；有放行；日誌有「已連線至 SQLite」、`Asia/Taipei`、「（正式環境設定）」、沒有 `ERROR`；登得進去。功能開關一個都不開。

🧪 手機沒有 Ctrl＋F5：關掉分頁重開，或清除這個網站的資料；用改過的密碼登得進去，就是資料留住了。

### J-20 AI 閘道換成新版

**做什麼**：J-07 第 5 條是 `False` 才複製設定檔範本（`True` 就不要蓋掉）；`--profile ai` 建置、啟動閘道，從後端打一次 health（之四 J-20）。

**成功**：建置最後 `全部通過`；印出 `503 {"status":"error","config":"error","detail":"base_url 尚未填寫（推論端點的位址）"}`。

🧪 之八 I-11 做過，J-07 第 5 條是 `True`，跳過複製設定檔；`docker ps` 裡 `ai-gateway` 的映像檔是新 tag。

### J-21 確認資料取出的指令在

**做什麼**：`docker compose --env-file $cfg --profile export run --rm data-export --help`，只打 `--help`。

**成功**：印出一大段說明，第一行是「研究與後續計畫的資料取出（部署手冊第十六冊「取出資料」）」。

## 5. 備份、防毒、重新開機

### J-22 備份一次，並證明還原得回來

**做什麼**：護理端 → 系統管理 →「立即備份」；讀 `.sha256`；還原到測試檔再刪掉（之五 J-22）；當場問資訊室備份資料夾誰、多久送往另一台機器。

**成功**：`✓ 與備份歷程上的紀錄相符`、`完整性檢查：ok`；`$root\backups\` 看得到那個檔和同名的 `.sha256`。

🧪 「立即備份」在開發機或手機的護理端都可以；第 4 步（問資訊室）跳過。

### J-23 Docker Desktop 的四項設定，關掉使用統計

**做什麼**：Docker Desktop → Settings，看開機自動啟動、使用統計、自動更新、Disk image location 四項並抄下；使用統計取消勾選、按 Apply。

**成功**：四項都抄了；使用統計已關；按的是 Apply & restart 的話，一分鐘後三個服務回到 `Up`。

🧪 只看不改；名稱和這裡寫的不一樣，就把實際的名稱寫在紙本上。

### J-24 防毒：查清楚，交給資訊室加排除

**做什麼**：系統管理員身分的 PowerShell 打之五 J-24 的兩條；排除清單沒有 J-23 第 4 項的路徑，就請資訊室加。

**成功**：紀錄寫「防毒＝＿＿；排除清單已加，由＿＿加」，或「未加，由＿＿於＿＿前加」。加上之前不得輸入真實病人資料。

🧪 只看不改；確認指令跑得動、看得懂 `hex`。

### J-25 重新開機測試

**做什麼**：資訊室同意、挑好時段才做：護理站看著護理端，主機重新開機、以平常登入的那個帳號登入，之後什麼都不碰，等三分鐘，再開工三行、`docker ps`、health。

**成功**：服務全部 `Up`、映像檔是 `<新 tag>`；health 正常；護理站紅框自己消失；記下從重新開機到紅框消失共幾分鐘。

🧪 開發機驗不出「沒人登入」：改成 Docker 圖示按右鍵 → Quit Docker Desktop，再從開始選單開啟，等三分鐘打同兩條；量從 Quit 到手機上紅框消失幾分鐘。

## 6. 院方 API：探測一次

### J-26 探測院方透析清單 API

**做什麼**：位址只在這裡當場輸入，不寫進 `.env`、紙上或紀錄：

```
$u = Read-Host '院方透析清單 API 的位址（含 dialysislist.php，不含 ?date=）'
docker compose --env-file $cfg exec -T -e HOSPITAL_API_BASE_URL=$u api node apps/api/dist/hospital-api-probe.js
```

做完 `Remove-Variable u`。

**成功**：「連線：成功」「模擬標頭：沒有」「解析：成功，data_list 共 N 列」，最後一行「以上可以整段抄進演練紀錄」；整段抄進演練紀錄。

🧪 先打 `docker compose --env-file $cfg --profile simulation up -d hospital-api-sim`；位址輸入 `http://hospital-api-sim:8090/dialysislist.php`；「模擬標頭：有」在這裡是對的。

## 7. 暫用平板（時間夠、院方准才做）

### J-27 平板的事前檢查

**做什麼**：不要原廠重設；USB 偵錯關掉；字型大小照醫師的答覆；連院內給平板用的 Wi-Fi，瀏覽器開 `http://<IP>:18081/shell/`。

**成功**：下載頁上的主機位址是 `https://<IP>:18081`；最下面「版本資訊」的三個 SHA-256 抄下來。

🧪 用暫用平板或手機；字型大小不要改。

### J-28 在護理端註冊、平板安裝 App

**做什麼**：護理端 → 新增裝置 → 註冊新平板（QR code 畫面先不關）；平板設 PIN、開「釘選應用程式」並勾解除前要 PIN；從下載頁「下載 App」安裝。

**成功**：佈建網址以 `https://<IP>:18081` 開頭；平板上多了「透析照護平板」。

🧪 用暫用平板的話，把「安裝不明來源」的提示長什麼樣寫在紙本上。

### J-29 第一次開啟並釘住

**做什麼**：App →「掃描 QR code」→「儲存並啟動」→ 固定；解除一次固定、再釘回去（之五 J-29）。

**成功**：平板在等待畫面、沒有憑證警告、離不開、畫面是橫的；護理端「固定中」→ 解除後「已跳出」→ 釘回後「固定中」；「外殼版本」正常。

🧪 用暫用平板時多做一件：I-13 開了模擬院方 API 之後，把一位模擬病人放到這台平板上，病人端首頁的頂列是一列、沒有被截斷，拍照（虛構病人，可以拍）。

## 8. 收尾

### J-30 冒煙測試（在護理站的電腦）

**做什麼**：在護理站的電腦（不是部署主機）走一次之六 J-30 的十列；不輸入真實病人資料、不開任何功能開關。

**成功**：每一列都打勾，或寫明為什麼沒做；沒出現的抄下畫面上的字，寫進交接的「已知限制」。

🧪 照做，「護理站」是手機。

### J-31 交接

**做什麼**：當場講一次、讓對方做一次，把之六 J-31 的交接表寫在一張紙上交給護理長與資訊室（第一行寫「首波試用前的準備，還不是正式上線」，不寫密碼與 `.env` 的值）。

**成功**：護理長與資訊室各拿到一張。

🧪 跳過。

### J-32 離院前

**做什麼**：演練紀錄每一格都填、每一步有起訖時間；補齊 1001 留下的空白；登入沒通就 `docker compose --env-file $cfg stop`；關掉所有 PowerShell、登出護理端；刪掉手機裡拍到 `.env`、病人資料、院方 API 位址的照片。

**成功**：五項都打勾。

🧪 跳過。

### J-33 回來之後

**做什麼**：當天晚上補完演練紀錄；三天內寫第三次進院紀錄、判斷 1001 是可能 A 還是 B、探測輸出交給開發端；有空時改回手冊。

**成功**：《[第三次進院紀錄（1029，部分成功）](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/record-3-1029/index.md)》寫好、掛進部署手冊。
