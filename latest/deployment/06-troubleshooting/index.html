    第六冊 · 現場疑難排解¶

    版本：v0.1　文件狀態：草案　編號：X-xx　這一冊要印出來帶進去

    院內沒有網路，你查不到任何資料。這一冊就是現場唯一的搜尋引擎。 照「症狀 → 先查什麼 → 怎麼處置」找，不要憑印象猜。

    0. 現場除錯的四個原則¶

    1. 先確認它在哪一層壞掉。 由下往上問四句： 機器活著嗎 → 服務行程在嗎 → 後端回不回應 → 瀏覽器連得到嗎。 從最底下開始問，不要從畫面開始猜。
    2. 一次只改一件事。 同時改三個設定再重新啟動，好了也不知道是哪一個。
    3. 錯誤訊息抄原文。 你要帶回去的是原文，不是「它說連不上」。
    4. 不要為了讓它動起來而破壞前提。 開對外連線、關防毒、用管理員帳號跑服務—— 這三件事當下都會「解決問題」，而代價要到幾個月後才付。

    五秒鐘的分層檢查：

    .\scripts\service-status.ps1                       # 行程幾個？存活檢查幾號？
curl.exe -i http://localhost:<API_PORT>/api/health  # 後端本身活著嗎

    A. 安裝包與雜湊¶

    X-01 雜湊值對不上¶
    你會看到 Get-FileHash 出來的字串與交付單上不同
    可能原因 複製時中斷；防毒「清理」過檔案；拿錯版本；解壓不完整
    先查 是不是拿錯壓縮檔（檔名裡的 commit）；隨身碟上那一份的雜湊對不對
    處置 重新複製、重新解壓、再比一次。還是不同就今天不要裝
    不要做 「差一點應該沒關係」——雜湊沒有「差一點」

    X-02 解壓失敗，說路徑太長¶
    可能原因 Windows 的路徑長度上限，加上 node_modules 本來就很深
    處置 解到極短的路徑，例如 C:\hd\。不要放在桌面或使用者資料夾深處

    X-03 驗收腳本第 5 項抓到對外連線¶
    你會看到 連線哨兵列出一個院外主機名稱
    處置 不得交付。記下那個主機名稱帶回去，用 npm run check:egress 對照
    不要做 當成誤判跳過。這一條是整套系統能放病人資料的前提

    X-04 掃描站把檔案刪掉或隔離了¶
    你會看到 雜湊對不上，或解壓後少了某個檔案
    處置 請對方加例外並重新複製一份；同時記下判定名稱與檔案路徑
    不要做 用被動過的包硬裝。那份包已經不是你驗收過的那一份

    B. 服務起不來¶

    X-05 service-install.ps1 說要系統管理員身分¶
    處置 以系統管理員身分重新開啟 PowerShell。註冊排程工作與改目錄權限都需要它

    X-06 PowerShell 執行原則擋下 .ps1¶
    你會看到 「因為這個系統上已停用指令碼執行」
    處置 Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass（只影響目前這個工作階段）。先問過資訊室

    X-07 註冊時說「資料目錄不得位於安裝包目錄之內」¶
    這是正確行為（DEP-08） 換一個安裝包目錄之外的路徑
    為什麼擋 某一次「把舊資料夾整個刪掉再解壓新版」會把資料庫一起刪掉

    X-08 排程工作是 Running，但行程數 0¶
    可能原因 啟動器一起來就死了，多半是 .env 有問題
    先查 用前景跑一次，直接看錯誤：.\runtime\node.exe .\scripts\run-all.mjs
    常見 .env 找不到（位置錯）、API_PORT 沒填、DATABASE_URL 是相對路徑、PRISMA_ENGINES_DIR 指錯

    X-09 只有 1 或 2 個行程¶
    設計上 任何一個倒下就三個一起停——壞掉要壞得看得出來
    處置 看到 1～2 個多半是正在收尾。等幾秒再查一次；還在的話看紀錄檔找真正的錯

    X-10 後端拒絕啟動，說時區不符¶
    這是正確行為（DEP-15） 主機時區必須是 Asia/Taipei
    處置 Set-TimeZone -Id "Taipei Standard Time"，重新啟動服務
    注意 主機時區對，不代表服務執行帳號取得的時區對。要從護理端「維運狀態」那一頁確認

    X-11 重新開機後服務沒起來¶
    先查 工作排程器 →「上次執行結果」
    常見原因 服務帳號密碼已變更或到期；帳號缺「以批次工作登入」的權限；開機時埠被別的專案先佔走
    處置 密碼問題請資訊室處理；埠被佔就換一個並重新登記
    記下來 這一類問題只在重新開機時發作，測試階段一次都不會出現

    C. 資料庫¶

    X-12 Error code 14: Unable to open the database file¶
    可能原因 目錄不存在；服務帳號沒有寫入權限；路徑打錯
    處置 先手動建出目錄，確認 icacls <目錄> 裡有服務帳號的修改權限

    X-13 後端拒絕啟動，說資料庫路徑在共用位置¶
    這是正確行為（DEP-37 第 3 項） 暫存、公用、桌面、文件、下載都會被擋
    處置 換到本系統自己的路徑，例如 D:\hd-data\

    X-14 database is locked¶
    可能原因 服務還在跑（有行程開著資料庫）；防毒即時掃描；有人用其他工具開著同一個檔案
    先查 .\scripts\service-status.ps1 行程數是不是 0
    處置 停服務再操作。若停了還是鎖著，九成是防毒——那就是 H-14 第 1 項沒做
    特徵 這一類錯誤間歇性、不固定重現，是最難查的一種。不要花時間猜，直接去看排除清單

    X-15 資料庫檔案不見了¶
    可能原因 更新時把整個安裝包目錄刪掉，而資料庫放在裡面（DEP-08 要擋的正是這件事）
    處置 從備份還原。這就是為什麼備份的第二落點必須在另一台機器上

    X-16 磁碟快滿，更新在備份之前就停下¶
    這是正確行為（DB_DISK_MIN_FREE_MB） 備份做到一半才寫滿，等於在最需要備份的時候沒有備份
    處置 清出空間再做。同時查清楚是誰把磁碟寫滿的——這台機器是共用的

    X-17 -wal 與 -shm 檔要不要一起處理¶
    要（DEP-09） 它們與主檔是一組，分開搬移或備份會毀損資料庫

    D. 網路、連接埠、連不進來¶

    X-18 護理站電腦連不到¶
    分層查 ① 主機上 curl.exe http://localhost:<API_PORT>/api/health 通不通 → ② 護理站 ping <主機> 通不通 → ③ 護理站瀏覽器開靜態站的埠
    ① 不通 服務沒起來，看 B 組
    ② 不通 網段或路由問題，找資訊室
    ③ 不通而 ② 通 防火牆。要開三個埠的輸入規則

    X-19 畫面出得來，但登入沒反應¶
    最可能的原因 PWA 裡的 API 位址是 localhost——護理端正在向護理站那台電腦自己要資料
    怎麼確認 瀏覽器開發者工具 → 網路，看請求打到哪個主機
    處置 沒有當場的設定可以改：那個位址是建置時寫死的。唯一的補救是用院內主機位址重新產生安裝包（要帶開發機）
    預防 第二冊 R-13 就是為了在家裡先抓到它

    X-20 瀏覽器主控台出現 CORS 錯誤¶
    原因 .env 的 CORS_ORIGINS 沒有列出護理端／病人端實際的來源
    處置 補上 http://<主機>:<NURSE_PORT> 與 http://<主機>:<PATIENT_PORT>，重新啟動服務

    X-21 連接埠被佔用¶
    先查 Get-NetTCPConnection -State Listen \| Where-Object LocalPort -eq <埠>
    處置 換一個埠，改 .env（API_PORT／NURSE_PORT／PATIENT_PORT 與 CORS_ORIGINS），重新啟動。同時請資訊室登記
    注意 這件事多半在某次重新開機、兩個服務啟動順序對調時才發作

    X-22 總覽一直顯示斷線¶
    原因 SSE 長連線被中斷（代理、閒置逾時、網路不穩）
    處置 超過約兩倍心跳沒收到訊息就會自動重連。持續斷線要查網路設備有沒有對長連線設逾時

    X-23 有人說「我開一下對外網路就好了」¶
    處置 婉拒，並記下這件事（C-41）
    怎麼說 「這套系統能放病人資料的前提就是它不連外。今天開了，之後每一次稽核都要重新解釋。真正缺的東西我們帶進來了。」

    X-37 git clone 竟然成功了¶
    意義 主機連得到程式碼來源，而且某個帳號的憑證被用上了（repo 是私有的）
    處置 先不要跑 npm install，翻第七冊從 G-01 做起

    E. 憑證與平板¶

    X-24 平板上出現憑證警告¶
    可能原因 CA 沒打包進 APK；network_security_config.xml 的網域與實際位址不符；主機根本沒開 TLS
    處置 前兩項要回開發機重編 APK；第三項見第三冊開頭的 HTTPS 缺口

    X-25 平板斷網後畫面一片空白¶
    原因 Service Worker 沒註冊。最常見的是因為連的是 HTTP（非安全來源，navigator.serviceWorker 根本不存在）
    處置 同 X-24 第三項
    為什麼嚴重 離線能力是選 PWA 而非純網頁的唯一理由。它不成立，這個選型就是假的

    X-26 護理端顯示「尚未回報」而不是「固定中」¶
    意思 外殼 App 還沒裝，不是故障、也不是跳出 Kiosk
    三種狀態要分開 尚未回報＝沒裝 App；已跳出＝平板說它離開前景了；失去回報＝它不說話了（關機或斷網）

    X-27 重新開機後螢幕固定不見了¶
    這是已知取捨 App 會自動啟動，螢幕固定不會自動恢復
    處置 人工重釘，列入每日交班檢查。護理端看得到哪一台跳出了，不必逐台目視

    X-28 APK 裝不上去¶
    可能原因 之前裝過 debug 簽名版；未開啟「允許安裝不明來源」；機型內建的安全掃描擋下
    處置 先解除安裝舊的；逐項開權限；必要時用 adb install

    F. 更新與回退¶

    X-29 更新腳本被擋下，說服務還在跑¶
    這是正確行為 更新期間的寫入會落在備份與遷移之間的空窗裡
    處置 .\scripts\service-stop.ps1，確認行程數 0 再重跑

    X-30 更新停在備份那一步¶
    這是正確行為 備份沒做成就不往下走，這是整支腳本的重點
    常見原因 備份目錄寫不進去；磁碟可用空間低於門檻

    X-31 更新後發現不對，要退回去¶
    順序 ① 停服務 → ② 還原更新前的備份 → ③ 把改名保留的舊版目錄換回來 → ④ 啟動 → ⑤ 記錄
    關鍵觀念 程式可以退版，資料庫不行退版。 回退是還原備份再換回舊版程式，不是把遷移倒回去
    前提 更新時第 3 步「舊版目錄改名，不要刪」有做到。沒做的話就沒有東西可以退

    X-32 不確定現在跑的是哪一版¶
    查哪裡 安裝包目錄的 VERSION.json；護理端「維運狀態」的版本標記；更新紀錄

    G. 人與流程¶

    X-33 資訊室的人中途離開，剩下的步驟需要他¶
    處置 把需要權限的步驟集中排在他在的時候。他不在時做不需要權限的（冒煙測試、文件、問答）
    預防 H-03一開始就問「您會全程在旁邊嗎」

    X-34 有人要求「先讓護理師開始用，其他的之後再說」¶
    判斷 防毒排除、備份、權限這三項只要有一項沒完成，就不要讓真實資料進去
    怎麼說 「可以先讓大家看畫面、練操作，但真實病人資料要等備份與防毒設定完成。沒有備份的系統不該收病人資料。」

    X-35 現場出現一個手冊沒寫到的問題¶
    處置 ① 照第 0 節分層 ② 抄下錯誤原文 ③ 若十分鐘內沒有頭緒，先跳過、做別的，不要卡在同一個地方 ④ 記進 C-40
    原則 現場不是除錯的地方。能帶回去查的就帶回去查

    X-36 今天做不完，要怎麼乾淨地撤退¶

    三件事，順序不能換：

    1. 把服務停掉（若已啟動）。不要留一個半成品在跑——護理師會開始用它，然後把問題當成正常行為
    2. 把現況寫下來：做到哪一步、卡在哪、已經在主機上留下了什麼（目錄、帳號、排程工作、資料庫檔案）
    3. 當場講清楚下一次需要什麼，並約好下一次的時間（C-37）

    還要做的：清除隨身碟（H-23）、 把 A 級情報補完（第五冊 第 3 節）。

    撤退不是失敗。 帶著完整情報撤退，下一次就會成功； 硬幹到一半留下半成品，下一次要先花時間清理現場。
