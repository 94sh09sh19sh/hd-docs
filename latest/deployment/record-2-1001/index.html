    3. 遇到的問題¶

    M-01 護理端登入出現 Failed to fetch¶

    發生了什麼：N-16 用瀏覽器開護理端，登入頁出得來，按下登入，登入鈕下面出現 Failed to fetch。

    Failed to fetch 的意思是瀏覽器根本沒拿到後端的回應——帳號密碼還沒被檢查到。原因只有兩類：網頁連的後端位址不對，或後端的 CORS 不放行這個來源。

    現場查到哪裡：照《第二次進院（1001）· 從零部署本系統之六：詳細版（附錄：查防毒排除清單、登不進去）》的附錄「護理端頁面開得起來卻登不進去」第 2 步打了三條指令：

    指令 結果 意思
    第一條：.env 裡的 CORS_ORIGINS、HD_PUBLIC_API_URL 沒有帶回來 —
    第二條：curl.exe -s http://<主機>:<後端埠>/api/health {"status":"ok",…} 用 .env 裡那個 <主機> 連得到後端 ✓
    第三條：帶 Origin: http://<主機>:<護理端埠> 看 Access-Control-Allow-Origin 什麼都沒印出來 後端沒有放行這個來源 ✗

    17:58 在現場曾回報第三條「印出 …rol-Allow-Origin」；回來後確認，第三條的結果是空的，以紀錄檔為準。

    1029 補記：第三次進院抄回第一條（.env 的 CORS_ORIGINS 與 HD_PUBLIC_API_URL）與執行中後端的名單，兩者都是 http://<主機>:<護理端埠>、網頁裡的位址也一致，名單沒有寫錯，也不是改完沒 up -d。第三條為什麼是空的已無法重現；1029 改成 IP 後護理站登得進去。見《第三次進院紀錄（1029，部分成功）》 O-01。

    這三條合起來的意思：後端活著、<主機>:<後端埠> 連得到（第二條），但後端的 CORS 名單裡沒有 http://<主機>:<護理端埠> 這個來源（第三條）。光這一點就足以讓登入出現 Failed to fetch。照附錄，原因只有兩種：

    1. .env 的 CORS_ORIGINS 寫的不是 http://<主機>:<護理端埠>——例如仍是範例的 hd-server、寫成 localhost、名稱與 IP 的寫法和第三條用的不同、埠不對。17:47 問過「hd-server 要照寫還是寫主機名稱」，照抄過範例的可能性不低。
    2. .env 是對的，但改完之後沒有 up -d：.env 只在容器建立時讀一次，執行中的後端還在用改之前的 CORS_ORIGINS。

    第一條沒帶回來，所以分不出是哪一種。兩種的處置都是改好 .env 之後 docker compose --env-file $cfg up -d，再打一次第三條，要印出 Access-Control-Allow-Origin: http://<主機>:<護理端埠>。

    CORS 修好之後還要確認的兩件事（現場沒查到這裡）：

    1. 瀏覽器網址列上的網址。17:45 問過「能不能用 localhost 開護理端」——實際部署用 localhost 開，網址列的來源與 CORS_ORIGINS 對不上，CORS 修好了照樣是 Failed to fetch。
    2. 網頁裡寫死的後端位址。HD_PUBLIC_API_URL 在 build 時寫進網頁檔案；若建置之後才把 .env 的位址改成真正的名稱，只 up -d 不會更新網頁裡的位址。

    下一次怎麼做：見第 7 節 M-14 第 2 項，《從零部署本系統》V-17 把這些都排進了步驟本身。白話的分析在《第二次進院紀錄（1001）之一：為什麼登不進去》。

    三次的錯誤裡都有一句 connecting to … via direct connection because Docker Desktop has no HTTPS proxy，那只是說明「沒有設代理、直接連」，不是錯誤本身。

    怎麼讀這三次：

    • 第 1、2 次查不到的是不同的網域（下載站、認證站），第 3 次又回到下載站，而第 3 次重跑就過——時好時壞，不是被擋掉。
    • 中間 N-13 的建置也要從 Docker Hub 下載 node:20-bookworm-slim，那一次成功了。
    • N-06 的連線實測這次沒有記到結果；而且 Test-NetConnection 是 Windows 去查名稱，docker pull 是 Docker Desktop 自己去查，兩條路不一定同時通。原本的 N-06 只測前者，也沒有列 production.cloudfront.docker.com 這個下載站。
    • 原因在院內 DNS 還是 Docker Desktop，這次沒有查到（沒有在出錯當下打 Resolve-DnsName）。

    N-20 這一步含出錯與重來，總共花了 27～33 分鐘。

    M-07 產生 JWT_SECRET 的 docker run 下載失敗¶

    發生了什麼：當時《之七》1.6 節的 docker run --rm node:20-bookworm-slim node -e … 先印出 Unable to find image 'node:20-bookworm-slim' locally（這一行本身不是錯誤，Docker 接著會自己下載），然後下載失敗；再打一次，換成另一個網域查不到（M-06 第 1、2 次）。

    手冊怎麼改：已改（1001 現場，05ebb61）。改用 Windows 內建的 PowerShell 產生，輸出格式相同（64 個字元、只有英數字與 -、_），不必下載任何映像檔，也就不受 M-06 影響。
