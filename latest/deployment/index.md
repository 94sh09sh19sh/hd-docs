## 0. 這本手冊是什麼

《[部署規範](https://94sh09sh19sh.github.io/hd-docs/latest/requirements/deployment-spec/index.md)》寫的是**必須怎樣**，這本寫的是**你的手指要按什麼**。

規範會告訴你「資料庫目錄必須加入防毒排除清單」；這本會告訴你，在哪一台機器、按哪個選單、 加完之後怎麼確認它真的生效了、加不成的時候現場還有什麼辦法。

**這本手冊假設你是第一次做這件事。** 每一步都寫成三塊：

| 塊                       | 內容                                                                   |
| ------------------------ | ---------------------------------------------------------------------- |
| **做什麼**               | 一條指令或一個動作，照抄即可                                           |
| **怎麼知道成功了**       | 螢幕上應該出現什麼。**看不到它就是沒成功**，不要「看起來沒出錯就往下」 |
| **可能怎麼壞、怎麼處理** | 這一步已知的每一種失敗方式。**現場沒有網路可以查**，所以全部寫在這裡   |

## 2. 三種結果，先想清楚哪一種算數

**先把成功的定義寫下來，人在現場才不會被氣氛牽著走。**

| 等級                               | 達成什麼                                                     | 離院前一定要做完的事                                                                                                                  |
| ---------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------- |
| **A 完全成功**                     | 服務在院內主機上跑起來、護理站電腦連得進來、冒煙測試通過     | 交接文件、帳號密碼保管、隨身碟清除、紀錄填完                                                                                          |
| **B 部分成功**（**最可能的一種**） | 安裝包進去了、服務起得來，但平板沒佈建／某幾項設定要等資訊室 | 把**卡在哪、要等誰、要什麼**逐項寫下來（[第五冊](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/05-carry-in-out/index.md)） |
| **C 失敗**                         | 安裝包進不去，或主機根本不讓你動                             | **情報全部帶回來**。這時候紀錄是唯一的產出，而它決定下一次會不會再失敗                                                                |

> **C 不是白跑一趟，前提是紀錄做滿。** [第五冊](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/05-carry-in-out/index.md)整本在講這件事： 假設這次會失敗，要帶回哪些資訊，才能讓下一次一定成功。
>
> **整本手冊最重要的一句話**：離開醫院之後，你拿不到任何院內的資訊—— 那台機器沒有對外連線，你也不能帶任何檔案出來。**沒問到的，就是真的沒有了。**

| 角色                                 | 為什麼需要                                 | 不在場會卡在哪                             |
| ------------------------------------ | ------------------------------------------ | ------------------------------------------ |
| **你**（FDE）                        | 執行                                       | —                                          |

## 6. 什麼情況下當場停手

**硬幹的代價比擇日重來高得多**，而且當下通常看不出來。下列任一情形出現，**停手、記錄、擇日**：

| 情形                                                 | 為什麼不能硬幹                                                                                         |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 有人說「把網路開一下就好了」                         | 零院外連線是整套系統的前提。第一天就自己破壞它，之後沒有人會再認真看待這條                             |
| ~~拿不到系統管理員權限，有人提議用他的帳號跑服務~~   | **0926 作廢**：DEP-12 已作廢，信任邊界改為「能登入這台主機的人」（DEP-38）                             |
| 有人提議手動開一個容器、把整顆磁碟掛進去「比較方便」 | 0922 就是這樣失敗的（第十冊 F-01、F-02）。容器一律由 `docker compose` 產生，繫結掛載只准兩個（DEP-37） |
| 資料庫目錄只能放在「文件」或某個共用目錄             | 那多半是雲端同步資料夾或人人讀得到的位置，等於把病人資料攤開（DEP-21、DEP-37）                         |
| 防毒排除清單當天加不了，有人說「先跑跑看」           | SQLite 被即時掃描鎖住的錯誤是**間歇性、不固定重現**的。它會在一個月後爆開，而那時沒有人會聯想到今天    |
| 主機時區不是 Asia/Taipei，而沒有人有權限改           | 後端會拒絕啟動（DEP-15）。這一條擋得住，硬繞過去只會讓班表整張錯開                                     |
| 冒煙測試沒過，但已經到了下班時間                     | **半成品留在現場比沒有東西更糟**：護理師會開始用它，然後把問題當成系統的正常行為                       |

停手的時候要做的三件事：**把服務停掉**（若已啟動，照[第八冊](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/08-shutdown/index.md)做到「停用」）、**把現況寫進演練紀錄**、 **當場講清楚下一次需要什麼**。不要留一個「好像可以用」的狀態給別人。

## 7. 現場的基本原則（五條）

1. **一次只做一件事，做完看結果再做下一件。** 連下三個指令再一起看輸出，出事時分不出是哪一個。
1. **每一步都計時。** 耗時是下次估時間的唯一依據。
1. **錯誤訊息抄原文，不要抄大意。** 「連不上」沒有用，`getaddrinfo ENOTFOUND binaries.prisma.sh` 有用。
1. **不確定就先不要按。** 尤其是任何會刪東西、覆蓋東西、改權限的動作。
1. **紙本比螢幕可靠。** 院內主機雖然連得出去，你用的那台未必能查——所以第十一、十二冊要印出來帶進去。
