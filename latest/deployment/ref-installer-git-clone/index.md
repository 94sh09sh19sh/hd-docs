# 安裝包路線之六：院方要求直接 git clone（G-01～G-08）

上層文件：[《安裝包路線（歷史）》](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-installer/index.md)

> **狀態：歷史**（路線 0926 撤除）。這一份處理的是安裝包路線時「院方叫你直接 `git clone`，而它真的成功了」的岔路；0926 起院方要求的正是容器＋`git clone`，現行做法照[《從零部署本系統》](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-fresh-install/index.md)（主機上用唯讀部署金鑰 clone、切 tag、`docker compose` 建置），這一份只當紀錄。出路二用到的 `npm run package:build`、`package:verify` 1117 時已不在 repo 裡。
>
> 1117 從舊的《院方要求直接 `git clone`，而且成功了》全部改寫。
>
> 編號：`G-xx`，沿用原編號。

## 摘要

- 安裝包路線的其餘各份都假設 H-08 的 `git clone` 會失敗；這一份處理相反的情形：**院方叫你直接 clone，而它真的成功了**——那是一筆預料之外的情報，接下來每一步都取決於它為什麼會成功
- clone 成功不改變規則：DEP-11 不在正式主機上建置、DEP-14 啟動時不連外、最後裝進去的一律是安裝包（第 0 節）
- 先弄清楚：停下來記下成功（G-01）、程式碼從哪來（直連、院內代理、院內鏡像，G-02）、**是誰的憑證**（G-03）、clone 到哪一版（G-04）、問資訊室這條連線的來歷六題（G-05）
- 三條出路（G-06）：一、記下來照走路線 B（預設）；二、院方堅持且書面同意例外，在主機上建置安裝包；三、停手
- 出路一：寫進紀錄、清掉 clone 與憑證，回 H-09（G-07、G-08）
- 出路二（G-09～G-18）與之後的更新、離院前多三條在之七、之八，見下表

> 手冊其餘各份都假設 [H-08](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-installer-3/index.md) 的 `git clone` 會失敗。這一份處理相反的情形：**院方叫你直接 clone，而它真的成功了。** 那不是好事也不是壞事——**是一筆預料之外的情報**，而你接下來的每一步都取決於它為什麼會成功。

## 0. 先講結論

**clone 成功不會改變規則，只會改變你知道的事。**

| 不變的                                                    | 為什麼                                                                                               |
| --------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| DEP-11：不得在正式主機上執行 `npm install` 或任何建置步驟 | clone 成功只證明「連得到程式碼來源」，不證明連得到套件來源與 Prisma 引擎來源，更不證明院方允許       |
| DEP-14：安裝包啟動時不得連往院外                          | 這台機器連得出去，正是這一條更要守住的理由                                                           |
| 最後裝進去的一律是**安裝包**                              | 不管程式碼怎麼進來，`H-10` 之後的步驟、腳本、目錄界線全部一樣。**不要從 clone 下來的目錄直接跑服務** |

因此只有三條出路，在 [G-06](#g-06-%E6%B1%BA%E5%AE%9A%E8%B5%B0%E5%93%AA%E4%B8%80%E6%A2%9D) 選一條：

| 出路                                         | 什麼情況                                                | 終點                                                                                                                                |
| -------------------------------------------- | ------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| **一、記下來，照走路線 B**（**預設，建議**） | 院方只是想試試看，或沒有堅持                            | 清掉 clone 與憑證，回到 [H-09](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-installer-3/index.md)                   |
| **二、在主機上建置安裝包**                   | 院方**堅持**以 clone 的方式部署，且願意**書面**同意例外 | 在主機上產出一份安裝包，驗收通過後從 [H-10](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-installer-3/index.md) 接回 |
| **三、停手**                                 | 查不出連線從哪來、或憑證是別人的、或沒有人能為例外負責  | [《進院通則》](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-visit-rules/index.md)（舊總覽第 6 節）的撤退三件事      |

> **出路二是把開發機的工作搬進院內做，不是把開發環境搬進院內跑。** 建置完、驗收完、連線關掉之後，主機上跑的仍然是一份離線安裝包，和隨身碟帶進來的那一份沒有兩樣。

## 1. 先弄清楚它為什麼會成功

### G-01 停下來，把成功記下來

**做什麼**

**先不要接著跑 `npm install`。** 把 clone 的輸出與耗時照 [H-08](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-installer-3/index.md) 的格式寫進筆記本，只是「錯誤原文」那一欄改寫成「成功的輸出」。

**怎麼知道成功了**

筆記本上有：執行的完整指令（含網址）、輸出的最後幾行、耗時、當時誰在旁邊、**是誰叫你 clone 的**。

**可能怎麼壞、怎麼處理**

| 症狀                                | 處置                                                                                            |
| ----------------------------------- | ----------------------------------------------------------------------------------------------- |
| 有人說「成功了就直接裝下去吧」      | 「好，我先花十分鐘確認它是怎麼連出去的，這會寫進交接文件。」然後做 G-02～G-05                   |
| 想順手把 `npm install` 也跑下去看看 | **不要。** 那一步會在主機上寫入數百 MB 的套件、執行安裝後腳本，而你還不知道它連去哪裡、誰允許的 |

______________________________________________________________________

### G-02 查出程式碼是從哪裡來的

**做什麼**

```
cd <clone 下來的目錄>
git remote -v
Test-NetConnection github.com -Port 443
netsh winhttp show proxy
git config --show-origin --get-regexp "http.*proxy"
Get-ChildItem Env: | Where-Object Name -Match "proxy"
```

**怎麼知道成功了**

你能回答下面這張表的其中一列：

| 情形                 | 怎麼認                                                                              | 意義                                                                                     |
| -------------------- | ----------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| **直連 GitHub**      | 遠端是 `github.com`，`Test-NetConnection` 的 `TcpTestSucceeded` 是 `True`，沒有代理 | 這台主機**可以直接上網**。零院外連線的前提在這台機器上不成立                             |
| **經院內代理伺服器** | 有 proxy 設定，`TcpTestSucceeded` 可能是 `False` 但 clone 成功                      | 院方有一條受管制的對外路徑。**要問白名單是什麼**，套件來源與 Prisma 引擎來源多半不在上面 |
| **院內程式碼鏡像**   | 遠端是院內主機名稱（GitLab、Gitea 之類），不是 `github.com`                         | 有人事先把程式碼搬進院內了。**問清楚是誰、從哪一版搬的**（G-04 會核對）                  |

**可能怎麼壞、怎麼處理**

| 症狀                         | 處置                                                                                                                                                  |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| 三種都對不上                 | **停手**（出路三）。連線從哪來都說不清，就沒有人能為接下來的事負責                                                                                    |
| 資訊室說「這台本來就能上網」 | 記下原話與說話的人。這是 [C-42](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-visit-rules/index.md) 那一類情報，也直接牴觸 Q-27 的前提 |

### G-03 查出是誰的憑證

**這一步最容易被忽略，而後果最嚴重。** 這個專案的 repo 是**私有的**，沒有憑證 clone 不會成功——所以一定有某個帳號的憑證被用上了。

**做什麼**

```
git config --show-origin --get-regexp "credential"
cmdkey /list | Select-String -Pattern "git"
```

回想一下剛才 clone 的時候：**有沒有跳出登入視窗？是誰輸入的？**

**怎麼知道成功了**

你知道用的是哪個帳號，以及它有沒有被**存在這台機器上**。

| 情形                           | 處置                                                                                                                                      |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------- |
| **是你自己的 GitHub 帳號**     | 你的憑證現在存在一台共用主機上，任何登入這台機器的人都能用它讀寫整個 repo。**離院前一定要清掉**（G-08），而且回去之後**把那一組權杖作廢** |
| 是院方的部署帳號或唯讀部署金鑰 | 最好的情形。記下帳號名稱、權限範圍、誰保管                                                                                                |
| 是院內鏡像的帳號               | 同上                                                                                                                                      |
| 不知道是誰的                   | **停手**（出路三）                                                                                                                        |

**可能怎麼壞、怎麼處理**

| 症狀                                                  | 處置                                                                                                  |
| ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| 網址裡直接寫著權杖（`https://<權杖>@github.com/...`） | 權杖已經寫進 `.git\config` 與命令歷程。**這一組權杖視同外洩**，離院前刪掉 clone 目錄，回去立刻作廢    |
| 有人提議「把你的權杖留在上面，以後更新方便」          | **不要。** 那等於把 repo 的存取權交給這台主機上的每一個人，而且你離職或換權杖的那天，院內的更新就斷了 |

### G-04 確認 clone 到的是哪一版

**做什麼**

```
git log -1 --oneline
git status --short
```

**怎麼知道成功了**

`git log -1` 的 commit 與[交付單](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-installer-build-2/index.md)上的**一模一樣**，`git status --short` 沒有輸出。

**可能怎麼壞、怎麼處理**

| 症狀                    | 處置                                                                                                                                                                                                                        |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| commit 比交付單新       | clone 拿的是分支最新一筆，而那一筆沒有經過 P-xx 與 R-xx（[《安裝包路線之一》](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-installer-build/index.md)）的驗收。出路二要先 `git checkout <交付單上的 commit>` |
| commit 比交付單舊       | 多半是院內鏡像沒同步。**不要用它**，問清楚鏡像多久同步一次                                                                                                                                                                  |
| 找不到交付單上的 commit | 鏡像只同步了部分分支，或根本是別的 repo。停下來查                                                                                                                                                                           |

______________________________________________________________________

### G-05 問清楚這條連線的來歷

**做什麼**

這一段要問資訊室，答案寫進筆記本：

| #   | 問題                                                                               | 為什麼要問                                                                   |
| --- | ---------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 1   | 這台主機的對外連線是**常態**開著，還是今天臨時開的？                               | 常態開著的話，Q-27 的前提要整個重談                                          |
| 2   | 誰開的、有沒有申請紀錄？                                                           | 沒有紀錄的連線，稽核時沒有人說得清                                           |
| 3   | 白名單上有哪些網域？（`github.com`、`registry.npmjs.org`、`binaries.prisma.sh`？） | 決定出路二做不做得完                                                         |
| 4   | **今天結束之後會關掉嗎？誰關？怎麼證明關了？**                                     | 出路二的最後一步（G-17）要靠這一題                                           |
| 5   | 連線有沒有被記錄或監看？                                                           | 日後有人問「那天主機連去哪裡」時要答得出來                                   |
| 6   | 院方想用 clone 的方式部署，理由是什麼？                                            | 常見的理由是「不想處理隨身碟」或「以後更新方便」。**知道理由才能談替代方案** |

**可能怎麼壞、怎麼處理**

| 症狀                            | 處置                                                                                                                                                                                                                           |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 答不出第 4 題                   | 出路二就不能走。**開了關不掉的連線，比沒開更糟**                                                                                                                                                                               |
| 第 6 題的理由是「以後更新方便」 | 說明更新的路線（[第 5 節](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-installer-git-clone-3/#5-%E4%B9%8B%E5%BE%8C%E7%9A%84%E6%9B%B4%E6%96%B0)）：就算用 clone，每次更新也都要開、建、驗、關一輪，省不了多少事 |

## 2. 決定

### G-06 決定走哪一條

**做什麼**

依 G-02～G-05 的答案，對照下表，**和資訊室一起**選一條，選完寫進筆記本並請對方確認。

| 條件                                                                   | 出路                                                                                                                                                                                                                                                                                                                                                           |
| ---------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 院方沒有堅持                                                           | **一**                                                                                                                                                                                                                                                                                                                                                         |
| 院方堅持，但答不出 G-05 第 4 題（誰關、怎麼證明關了）                  | **一**，並把「院方想用 clone」列為下一次要談的事                                                                                                                                                                                                                                                                                                               |
| 院方堅持，**有人願意書面同意例外**，白名單涵蓋三個來源，且今天之內會關 | **二**                                                                                                                                                                                                                                                                                                                                                         |
| 查不出連線來源、或憑證來源不明                                         | **三**                                                                                                                                                                                                                                                                                                                                                         |
| 院方要的其實是**以 Docker 部署**，不是安裝包                           | 不在這三條裡。那是容器備案的啟用條件（《部署規範》3.3），改翻[《第一次進院之五：git clone＋Docker 路線詳細版》](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/visit-1-system-docker-2/index.md)，從 D-05 做起（0926 起這正是現行路線，照[《從零部署本系統》](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-fresh-install/index.md)） |

> **預設選一，是因為隨身碟上那份安裝包已經走完了 P-xx 與 R-xx 的全部驗收。** 出路二要在現場把那些驗收重做一次，而且是在一台你不熟悉、也不能隨便重來的機器上。

## 3. 出路一：記下來，照走路線 B

### G-07 把這次 clone 寫進紀錄

**做什麼**

演練紀錄 §1.3 照填，「`git clone` 的錯誤原文」那一欄寫「**成功**」，並附上 G-02～G-05 的答案。 **`npm install` 不必跑**——它不會改變結論，只會在主機上多留一堆東西。

______________________________________________________________________

### G-08 清掉 clone 與憑證

**做什麼**

```
cd C:\
Remove-Item -Recurse -Force <clone 下來的目錄>
cmdkey /list | Select-String -Pattern "git"
cmdkey /delete:<上一行列出的目標名稱>
```

**怎麼知道成功了**

clone 目錄不在了，`cmdkey /list` 再也找不到任何 `git` 開頭的憑證。

**可能怎麼壞、怎麼處理**

| 症狀                                                  | 處置                                                                                          |
| ----------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| 院方要求保留 clone 目錄                               | 可以，但**憑證一定要清**，並在交接文件寫明：那個目錄**不是**安裝目錄，改了它不會影響服務      |
| 刪除時說檔案被佔用                                    | 多半是檔案總管或防毒還開著它。關掉檔案總管視窗再試                                            |
| 憑證是用 Git Credential Manager 存的，`cmdkey` 看不到 | `git credential-manager github list` 看帳號，再 `git credential-manager github logout <帳號>` |

然後回到 H-09（[《安裝包路線（歷史）》第 3 份](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-installer-3/index.md)），照原本的路線 B 做完。
