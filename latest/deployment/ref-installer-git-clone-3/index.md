## 4. 出路二：在主機上建置安裝包（續）

### G-15 五支盤點

**做什麼**

```
npm run check:all
```

**怎麼知道成功了**

與 [P-05](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-installer-build/index.md) 相同，五支全綠。

**可能怎麼壞、怎麼處理**

**在開發機上全綠、在這裡有紅字**，代表兩邊的程式碼或相依不一樣。先回頭看 G-04 的 commit，再看 `git status --short`——`npm ci` 不應該改動任何被追蹤的檔案。**查不出原因就回出路一。**

______________________________________________________________________

### G-16 建置安裝包並驗收

**做什麼**

```
npm run package:build -- --out C:\hd
Get-Content C:\hd\<安裝包目錄>\VERSION.json
npm run package:verify -- --dir C:\hd\<安裝包目錄>
```

不需要 `--zip`：包不必搬動，就在它要安裝的地方。

**怎麼知道成功了**

| 看什麼                     | 應該是                                                              |
| -------------------------- | ------------------------------------------------------------------- |
| `VERSION.json` 的 `commit` | 與 G-04、交付單一致                                                 |
| `commitClean`              | `true`（建置目錄的 `.env` 被 gitignore 排除，不會讓它變成 `false`） |
| `node`                     | G-10 記下的版本                                                     |
| 驗收五項                   | 全綠                                                                |

**把 `CHECKSUMS.txt` 的 SHA-256 抄下來**（`Get-FileHash -Algorithm SHA256 C:\hd\<安裝包目錄>\CHECKSUMS.txt`）。它對不上交付單上的值是**正常的**——執行期與建置時間不同，雜湊一定不同。 **從現在起，這一串才是這台主機上那份安裝包的身分**，寫進交接文件。

**可能怎麼壞、怎麼處理**

| 症狀                     | 處置                                                                                                     |
| ------------------------ | -------------------------------------------------------------------------------------------------------- |
| **第 5 項有連線紀錄**    | 在這台**真的連得出去**的機器上，這一項抓到的是真的對外連線。**不得安裝**，抄下哨兵記的主機名稱，回出路一 |
| `commitClean` 是 `false` | 建置過程改動了被追蹤的檔案。`git status --short` 看是哪些，**不得安裝**                                  |
| 其餘                     | 見 [P-09](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-installer-build-2/index.md) 的表  |

______________________________________________________________________

### G-17 關閉對外連線，並當場確認

**做什麼**

請資訊室依 G-09 那張紙上寫的方式關閉連線，然後**你自己**確認：

```
Test-NetConnection github.com -Port 443
Test-NetConnection registry.npmjs.org -Port 443
```

**怎麼知道成功了**

兩個 `TcpTestSucceeded` 都是 `False`。

**可能怎麼壞、怎麼處理**

| 症狀                         | 處置                                                                                                                                                                                          |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 還是 `True`                  | **服務可以裝，但不得開始輸入真實病人資料**，直到連線關閉。與 [H-14](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/visit-1-system-onsite-2/index.md) 防毒排除清單加不了時的處置相同 |
| 「這台本來就要上網，關不了」 | 記下原話與說話的人。**這已經不是部署的問題，是能不能在這台機器上放病人資料的問題**，回去要重新決策                                                                                            |

______________________________________________________________________

### G-18 請院方掃一次，然後接回 H-10

**做什麼**

1. 請資訊室用院方防毒掃**安裝包目錄**（DEP-26 的精神：隨身碟那一份掃過兩次，這一份一次都還沒掃過）
1. 清掉憑證（同 [G-08](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-installer-git-clone/#g-08-%E6%B8%85%E6%8E%89-clone-%E8%88%87%E6%86%91%E8%AD%89) 的 `cmdkey` 那兩行）
1. 處理建置目錄：G-09 寫了「以後的更新沿用」就留著，並把建置用的 `.env` 刪掉；沒有就整個刪掉

然後從 H-10（[《安裝包路線（歷史）》第 3 份](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-installer-3/index.md)）接著做。 **H-09 可以跳過**：G-16 的驗收第 1 項就是逐檔核對雜湊。

**怎麼知道成功了**

掃描結果乾淨並留存；`cmdkey /list` 沒有 `git` 開頭的憑證；你人在安裝包目錄，正要複製 `.env.範本`。

**可能怎麼壞、怎麼處理**

| 症狀                                                             | 處置                                                                                                            |
| ---------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| 想直接在建置目錄跑 `npm run dev` 或 `node apps\api\dist\main.js` | **不要。** 那是開發環境，不是安裝包：沒有低權限帳號、沒有目錄界線、沒有哨兵。後續的腳本也全都假設你在安裝包目錄 |
| 掃描報出 `runtime\node.exe`                                      | 那是主機自己的 Node.js 複製過來的。請對方掃原本那一支對照，結果應該相同                                         |

## 5. 之後的更新

**只有 G-09 寫了「以後的更新沿用」時才適用。** 否則之後的更新一律照路線 B，由隨身碟帶新版安裝包進來。

每一次更新都是**開、建、驗、關、換**一整輪，一步都不能省：

| 順序 | 做什麼                                                                                                              | 對應                                                                                                                  |
| ---- | ------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| 1    | 依 G-09 寫定的方式請資訊室開連線                                                                                    | G-09                                                                                                                  |
| 2    | `git fetch`，再 `git checkout <這次要交付的 commit>`。**不要 `git pull`**——它拿的是分支最新一筆，而那一筆沒人驗收過 | G-04                                                                                                                  |
| 3    | `npm ci` → `check:offline` → `build` → `check:all`                                                                  | G-11～G-15                                                                                                            |
| 4    | `package:build -- --out C:\hd` 產出**新的目錄**，驗收五項                                                           | G-16                                                                                                                  |
| 5    | 關閉連線並確認                                                                                                      | G-17                                                                                                                  |
| 6    | 照更新七步換版：停服務、備份並驗證、**舊版目錄改名不要刪**、切到新目錄、套用遷移、啟動、寫紀錄                      | R-20（[《安裝包路線之五》](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-installer-build-5/index.md)） |

> **這張表就是 G-05 第 6 題的答案**：用 clone 更新並沒有比較省事，它只是把「在開發機上建包、用隨身碟帶進來」換成「在院內開一次網路、在正式主機上建包」。每一次更新都多一次對外連線、多一次在正式主機上跑建置。**讓院方看完這張表再決定要不要沿用。**

## 6. 離院前多三條

在 H-22（[《第一次進院之三：進院當天詳細版》](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/visit-1-system-onsite-3/index.md)）的收尾清單之外，走過這一份的話再加：

- `cmdkey /list` 沒有任何 `git` 開頭的憑證；若用過你自己的權杖，**已記下回去要作廢**
- 對外連線已關閉，`Test-NetConnection` 當場確認過（出路二）
- G-02～G-05 的答案、G-09 那張紙的內容都抄進筆記本；**那張紙本身留給院方**

回去之後：

- 作廢用過的 GitHub 權杖
- 把 G-05 的答案回填《[尚待確認事項清冊](https://94sh09sh19sh.github.io/hd-docs/latest/requirements/open-questions/index.md)》Q-27
- 出路二的話，把這次例外寫進《[部署規範](https://94sh09sh19sh.github.io/hd-docs/latest/requirements/deployment-spec/index.md)》第 6 章
