# 護理站登不進去與主機位址之一：換主機位址

上層文件：《[護理站登不進去與主機位址](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-login/index.md)》

> - 狀態：**現行**（常備參考）。1029 已照這一份把院內主機從名稱換成 IP（舊第十八冊 J-07～J-14，結果見《[第三次進院紀錄（1029）](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/record-3-1029/index.md)》）；之後院內主機的 IP 要換、換一台主機、或要從 IP 換回名稱時照這一份
> - 1117 由舊的第十五冊之四（主機位址從名稱改成 IP）第 1～8 節改寫；1029 照做時（舊第十八冊 J-07～J-14）補上的現場經驗收在各步。按下登入時發生什麼、`.env` 何時生效、登不進去怎麼查在上層文件
> - 編號：`T-xx`（沿用第十五冊之四）

## 摘要

- 1029 起院內主機用資訊室固定下來的 IP；**資訊室說 IP 已經固定，才換**（T-01）
- **改之前先從護理站與平板連一次新位址**，連不到就不要改，那是網路的問題，換位址解決不了（T-04）
- 改之前先抄五樣（T-02），改了就再也看不到
- `.env` 三個位址（`HD_PUBLIC_API_URL`、`CORS_ORIGINS`、`MDM_KIOSK_BASE_URL`）一起改、一字不差 → `build` → `up -d` → `shell-builder` 重簽伺服器憑證 → `keys-backup` → `restart patient-web`，一步都不能少（T-06～T-10）
- `shell-builder` 新產生的只能有伺服器憑證，看到院內 CA 或簽章金鑰就停手（T-08）
- 不會動到的：資料庫、帳號、三個埠、防火牆規則、院內 CA、APK 簽章金鑰；約 40～60 分鐘
- 平板已佈建（1029 起 `TB-00`）：每一台清除資料、重新佈建（第 4 節）；換不成照第 3 節換回，**不要換來換去**

代稱（`<IP>`、`<名稱>`、`<主機>`）、公開範圍與開工三行見上層文件第 0 節；🧪 開發機的 `<主機>` 是開發機 Wi-Fi 網卡的 IPv4。

## 1. 先懂：名稱與 IP、位址寫在哪

**用 IP 不是一定成功**，兩種寫法各有前提：

|          | 用名稱                                                                        | 用 IP                                                                        |
| -------- | ----------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 前提     | 院內 DNS **登記過**這個名稱                                                   | 這個 IP **固定**不變（資訊室在 DHCP 保留，或設成靜態）                       |
| 護理站   | 要**查得到**這個名稱                                                          | 要**連得到**這個 IP                                                          |
| 平板     | 要**查得到**這個名稱。平板常常查不到 Windows 電腦的名稱，這是最常出問題的地方 | 平板的 Wi-Fi 網段要**連得到**這個 IP（路由、防火牆）                         |
| 會怎麼壞 | 「找不到主機」                                                                | 主機重新開機或換網卡後 IP 變了，**所有東西突然都連不上**，而且當下看不出原因 |

所以拿不準就用**資訊室固定下來的** IP。重點是「固定」，不是「IP」。

主機位址不只寫在 `.env` 裡。改了 `.env`，下面每一處都要跟著換，**少一處就會有一個地方還在用舊位址**：

| 主機位址出現在哪裡         | 是怎麼放進去的                                     | 換位址要做什麼                                                                                                     | 在哪一步 |
| -------------------------- | -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ | -------- |
| `.env` 的三個位址          | 人填的                                             | 用記事本改                                                                                                         | T-06     |
| 護理端網頁檔案裡的後端位址 | 建置（`build`）時把 `HD_PUBLIC_API_URL` 寫死進去   | `build` 再 `up -d`                                                                                                 | T-07     |
| 後端的放行名單             | 後端容器建立時讀一次 `CORS_ORIGINS`                | `up -d`                                                                                                            | T-07     |
| 平板 QR code 裡的位址      | 後端容器建立時讀一次 `MDM_KIOSK_BASE_URL`          | `up -d`                                                                                                            | T-07     |
| **伺服器憑證**             | `shell-builder` 以 `MDM_KIOSK_BASE_URL` 的主機簽的 | 重跑 `shell-builder`。它發現憑證上的名字和 `MDM_KIOSK_BASE_URL` 對不上，會**自己重簽一張**，院內 CA 與簽章金鑰不動 | T-08     |
| 金鑰備份                   | 舊的那份裡是舊的伺服器憑證                         | 重新 `keys-backup`                                                                                                 | T-09     |
| 病人端用的憑證             | `patient-web` 啟動時讀一次                         | `restart patient-web`                                                                                              | T-10     |
| 下載頁上寫的主機位址       | `shell-builder` 寫的                               | 跟著 T-08 換掉                                                                                                     | T-08     |
| 護理站瀏覽器的網址列、書籤 | 人打的                                             | 改成新位址，**並告訴護理站的人**                                                                                   | T-12     |
| 平板上 App 填的主機位址    | 佈建時填的                                         | 每一台重新佈建                                                                                                     | 第 4 節  |

**為什麼院內 CA 與簽章金鑰不用換**：平板上的 App 只認**院內 CA**（APK 裡內建的那一張），伺服器憑證只要是這把 CA 簽的、上面寫的位址對，平板就收。所以換位址只換「伺服器憑證」這一張，APK 不必換簽章、已經裝了 App 的平板也不必重裝。

## 2. 換位址

1029 已照這一節換成 IP（舊第十八冊 J-07～J-14）。之後要再用到的情形：院內主機的 IP 要換、換一台主機、或要從 IP 換回名稱（第 3 節）。

**什麼時候用**（任一條成立）：

- 資訊室書面答覆（Q-27 第 12 題）是「用固定 IP」；1005 使用者決定改用 IP（《[實作規格書](https://94sh09sh19sh.github.io/hd-docs/latest/requirements/implementation-spec/index.md)》4.19），1007 資訊室答覆院內主機的 IP 是固定的
- 護理站的電腦 `Resolve-DnsName` 查不到這個名稱
- 護理站或平板說「找不到主機」，而資訊室說名稱沒有登記、也不打算登記

**什麼時候不要用**：資訊室還沒答應把 IP 固定下來。IP 會變，就是把「名稱查不到」換成「IP 哪天變了」，更難查。

要多久：約 40～60 分鐘（建置沒有快取約 10 分鐘、有快取一分鐘內，1029 實測 19.8 秒；資訊室確認的時間不算）。**不會動到的**：資料庫、帳號、三個埠、防火牆規則、院內 CA、APK 簽章金鑰。

### T-01 拿到資訊室的書面確認

**做什麼**：問資訊室三件事，要文字答覆（訊息、郵件都可以）：

1. 院內主機要用的 IP 是哪一個？**能不能固定下來**（DHCP 保留或靜態）？——1007 已答：固定的。到場只要確認那個 IP 就是現在主機上的 IP（T-03）
1. **護理站的電腦**連得到這個 IP 嗎？
1. **平板要用的那個 Wi-Fi** 連得到這個 IP 嗎？

這就是 Q-27 第 12 題（《第二次進院紀錄（1001）之一》E-01），答覆要回填清冊。

**成功**：三題都有答案，第 1 題是「已固定」。演練紀錄寫「`<主機>` 改用 **IP**，由＿＿確認，＿＿月＿＿日」——**IP 本身不寫進演練紀錄以外的任何文件**。

| 資訊室的答覆             | 怎麼辦                                                                         |
| ------------------------ | ------------------------------------------------------------------------------ |
| IP 不能固定              | **不要換。** 留在名稱，請資訊室在院內 DNS 登記這個名稱，並確認平板的網段查得到 |
| 護理站或平板的網段連不到 | 不管用名稱或 IP 都不會通，先請資訊室處理網路，這一節先不做                     |
| 「先用用看」             | 當成沒有答覆。改位址的代價會隨著佈建的平板數量一起變大                         |

### T-02 先確認主機是上一次離開時的樣子，並先抄下現況

**做什麼**（1001 之後的待辦 E-05、E-06）

1. 照《[從零部署本系統](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-fresh-install/index.md)》的主機現況檢查看一次（1029 是 J-05：`git describe`、`git status --short`、`docker ps -a`、資料卷、`backups\keys`、C 槽、health）
1. **先抄五樣**，每一條的結果原文抄進演練紀錄，包括正常的。**改了位址之後就再也看不到了**，而它們是判斷之前為什麼登不進去的唯一線索：

```
Select-String -Path $cfg -Pattern '^(HD_PUBLIC_API_URL|CORS_ORIGINS|MDM_KIOSK_BASE_URL)='
[Console]::OutputEncoding = [Text.Encoding]::UTF8; docker compose --env-file $cfg logs api | Select-String '允許的前端來源' | Select-Object -Last 1
docker compose --env-file $cfg exec nurse-web grep -rhoE 'https?://[A-Za-z0-9.-]+:[0-9]+' apps/nurse-pwa/dist/assets
docker compose --env-file $cfg --profile shell run --rm shell-builder keys-info
Test-Path $root\config\ai-gateway\config.yaml
```

| #   | 在抄什麼                                                                                                               |
| --- | ---------------------------------------------------------------------------------------------------------------------- |
| 1   | `.env` 裡的三個位址（名單寫了什麼）                                                                                    |
| 2   | 執行中的後端**手上那份**放行名單                                                                                       |
| 3   | 護理端網頁裡寫死的後端位址                                                                                             |
| 4   | 院內 CA、伺服器憑證、簽章金鑰的指紋；「伺服器憑證」那一行應該是 `DNS:<名稱>`。只印指紋、到期日與位址，**不會印出私鑰** |
| 5   | AI 閘道的設定檔在不在（`True`／`False`）                                                                               |

值本身只寫演練紀錄的紙本；可以拍照，照片只進私人 repo。

| 症狀                                       | 處置                                                                                         |
| ------------------------------------------ | -------------------------------------------------------------------------------------------- |
| 第 2 條什麼都沒印                          | 日誌被清過（例如容器重建過）。寫「沒有」就好                                                 |
| 第 4 條「伺服器憑證」已經是 `IP Address:…` | 填的其實已經是 IP，**這一節不用做**，停下來先打電話問開發端                                  |
| 第 4 條等很久、開始下載東西                | 映像檔 `hd-tablet-care-shell-builder:<tag>` 不見了，正在重建。等它跑完（約 30 分鐘），記下來 |

1029 抄到的結果：1001 的放行名單、後端手上的名單、網頁裡的後端位址三者都正確，1001 登不進去不是名單寫錯、也不是沒 `up -d`（《[第三次進院紀錄（1029）](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/record-3-1029/index.md)》O-01）。

### T-03 在主機上確認 IP

**做什麼**

```
ipconfig /all
```

找實體網卡（「乙太網路」或「Wi-Fi」那一段，**不是** `vEthernet (WSL)`、`vEthernet (Default Switch)`，也不是 `172.` 開頭的）：

| 看什麼      | 應該是                                                     |
| ----------- | ---------------------------------------------------------- |
| IPv4 位址   | 與資訊室給的 `<IP>` **一字不差**                           |
| DHCP 已啟用 | `否`（靜態）；或 `是`，但資訊室說已經在 DHCP 保留了這個 IP |

**不一樣的話**：資訊室給的 IP 與主機上看到的不同，**停手**，問清楚再做。1029：IP 一致、DHCP 否。

### T-04 先從護理站連一次 `<IP>`（不改任何東西）

**這一步最重要。** 服務現在就在跑，`13000`、`18080`、`18081` 三個埠用 IP 一樣連得到。先證明連得到，再改設定。

**做什麼**

1. 在**護理站的電腦**上，瀏覽器開 `http://<IP>:13000/api/health`
1. 同一台電腦開 `http://<IP>:18080`，看得到登入頁就好，**先不要按登入**（還沒改放行名單，一定是 `Failed to fetch`）
1. 有平板或手機的話，連上**平板實際要用的那個 Wi-Fi**，瀏覽器開 `http://<IP>:18081/shell/`

**成功**：第 1 條看到 `{"status":"ok",…}`；第 2 條看到登入頁；第 3 條看到下載頁（上面寫的主機位址還是舊的，**現在是對的**，T-08 之後才會換）。

| 症狀                         | 怎麼辦                                                                                                          |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------- |
| 護理站開不到                 | 防火牆或網段的問題。**找資訊室，不要自己關防火牆，也不要往下改設定**——改成 IP 也不會通                          |
| 護理站開得到，平板開不到     | 平板的 Wi-Fi 網段到不了主機，找資訊室。沒解決之前，換成 IP 一樣佈建不了平板（換位址照做，平板先不做，交資訊室） |
| 主機自己開得到，別台都開不到 | 同上，防火牆                                                                                                    |

### T-05 留一份改之前的 `.env`

**做什麼**

```
Copy-Item $cfg "$root\config\.env.before-ip"
Get-ChildItem "$root\config"
```

**成功**：看得到 `.env` 與 `.env.before-ip` 兩個檔。這一份裡有登入簽章金鑰與初始密碼，與 `.env` 一樣**只留在這個資料夾**，不複製到別處、不拍照。T-14 成功之後就刪掉；要換回名稱時（第 3 節）才用得到它。

### T-06 把三個位址改成 `<IP>`

**做什麼**

```
notepad $cfg
```

只改這三行的**主機部分**，`http://`、`https://` 與埠都不動：

```
HD_PUBLIC_API_URL=http://<IP>:13000
CORS_ORIGINS=http://<IP>:18080
MDM_KIOSK_BASE_URL=https://<IP>:18081
```

`CORS_ORIGINS` 如果用逗號多列了別的來源（例如 `localhost`），**這次一起拿掉**，只留 `http://<IP>:18080`。存檔（記事本問編碼就選 UTF-8，不要改檔名），關掉記事本。

**成功**

```
docker compose --env-file $cfg config --quiet
Select-String -Path $cfg -Pattern '^(HD_PUBLIC_API_URL|CORS_ORIGINS|MDM_KIOSK_BASE_URL)='
Select-String -Path $cfg -Pattern '^[^#].*<名稱>'
Select-String -Path $cfg -Pattern '^[^#].*(<|>|hd-server|localhost)'
```

| 哪一條                              | 應該是                                                                                                                                                                                        |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 第一條                              | 什麼都沒印                                                                                                                                                                                    |
| 第二條                              | 三行，主機部分**都是 `<IP>`、一字不差**；前兩行 `http://`、第三行 `https://`                                                                                                                  |
| 第三條（`<名稱>` 換成舊的那個名稱） | 什麼都沒印——舊名稱一處都不剩。舊名稱照 T-02 第 1 條抄到的 `HD_PUBLIC_API_URL` 中間那一段（第 4 條 `DNS:` 後面應該是同一個）；照紙本抄，**不要重查 `hostname`**，當初填的可能是完整網域名稱    |
| 第四條                              | 什麼都沒印（沒有照抄範例、沒有 `localhost`、沒有忘了換掉的 `<`、`>`；《[`.env` 怎麼填](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-env/index.md)》的「有沒有照抄範例」檢查） |

### T-07 重建網頁，再啟動

`HD_PUBLIC_API_URL` 寫死在網頁檔案裡，**只 `up -d` 沒有用，一定要先 `build`**（上層文件 1.3 節）。

**做什麼**（記下開始時間）

```
docker compose --env-file $cfg build
docker compose --env-file $cfg up -d
docker compose --env-file $cfg ps
```

**成功**：`build` 最後出現 `Image hd-tablet-care:<tag> Built`（有快取時一分鐘內就跑完是正常的，看到 `Built` 就算有建）；`ps` 的 `api`、`nurse-web`、`patient-web` 都是 `Up`。記下結束時間。

接著在主機上確認：

```
curl.exe -s http://localhost:13000/api/health
docker compose --env-file $cfg exec nurse-web grep -rhoE 'https?://[A-Za-z0-9.-]+:[0-9]+' apps/nurse-pwa/dist/assets
curl.exe -s -i -H "Origin: http://<IP>:18080" http://<IP>:13000/api/health | Select-String Access-Control-Allow-Origin
[Console]::OutputEncoding = [Text.Encoding]::UTF8; docker compose --env-file $cfg logs api | Select-String '允許的前端來源' | Select-Object -Last 1
```

| 哪一條           | 應該是                                                                 |
| ---------------- | ---------------------------------------------------------------------- |
| health           | `{"status":"ok",…}`                                                    |
| 網頁裡的後端位址 | `http://<IP>:13000`，**沒有 `<名稱>`**                                 |
| 放行檢查         | `Access-Control-Allow-Origin: http://<IP>:18080`（只看得到後半段也算） |
| 日誌最後一行     | `允許的前端來源：http://<IP>:18080`                                    |

這一步同時把「名單寫錯」「改完沒 `up -d`」兩種可能都修掉了，**所以 T-02 一定要先抄**，不然就永遠不知道之前是哪一種。

### T-08 重跑 `shell-builder`，重簽伺服器憑證

**做什麼**（記下開始時間）

```
docker compose --env-file $cfg --profile shell run --rm shell-builder
```

它會重建一次 APK（離線建置，不必下載）。

**成功**：「這一次新產生：」後面**只有**「伺服器憑證（`<IP>`）」一項，接著是 APK 檔名與三個 SHA-256。**再打一次同一條指令**，這次要看到「**金鑰全部沿用，這一次沒有產生任何新的金鑰**」。記下結束時間。

| 「這一次新產生：」後面出現                          | 怎麼辦                                                                                                                                                                                                               |
| --------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 只有「伺服器憑證（`<IP>`）」                        | **對的**                                                                                                                                                                                                             |
| 「伺服器憑證（`<名稱>`）」                          | `.env` 的 `MDM_KIOSK_BASE_URL` 沒改到，回 T-06                                                                                                                                                                       |
| 「院內 CA」或「APK 簽章金鑰」                       | **停手。** 金鑰資料卷不是原本那一個，或指令少了 `--env-file $cfg`。不要往下做，打電話問開發端；照《[平板與外殼 App](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-tablet/index.md)》第 7 節從備份還原 |
| `這個金鑰資料卷是「dev」用的，設定卻是「hospital」` | **停手**                                                                                                                                                                                                             |

### T-09 重新備份金鑰

伺服器憑證換了，舊的那份備份裡是舊的。

**做什麼**

```
docker compose --env-file $cfg --profile shell run --rm shell-builder keys-backup
docker compose --env-file $cfg --profile shell run --rm shell-builder keys-verify
```

**成功**：第一條印出「已備份：備份目錄/keys/hd-keys-\<時間>.tar.gz」；第二條每一項都 ✓，最後「還原得回來」。

- **新的備份檔名記進演練紀錄**（1029 沒抄到），並告訴負責把備份送往另一台機器的人：這一份要送
- **舊的那份（1001 的 `hd-keys-20261001-173347.tar.gz`）不要刪。** 院內 CA 與簽章金鑰兩份是同一把；萬一要從舊的那份還原，`shell-builder` 發現伺服器憑證的名字對不上，一樣會自己重簽
- 金鑰備份裡有私鑰，**不得出院、不得寄給開發端**

### T-10 讓病人端換上新的憑證

**做什麼**

```
docker compose --env-file $cfg restart patient-web
docker compose --env-file $cfg logs patient-web --tail 5
docker compose --env-file $cfg --profile shell run --rm shell-builder keys-info
```

**成功**

| 看什麼                                                | 應該是                                   |
| ----------------------------------------------------- | ---------------------------------------- |
| 日誌**最後一次**出現的「靜態資源已提供於連接埠 8081」 | 後面是「（HTTPS；HTTP 只留外殼下載頁）」 |
| `keys-info` 的「伺服器憑證」那一行                    | `IP Address:<IP>`                        |
| `keys-info` 的院內 CA 與簽章金鑰指紋                  | 與 T-02 抄的**一模一樣**                 |

| 症狀                                                                   | 處置                                                                                                                   |
| ---------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `restart patient-web` 停在 `Restarting`、沒有 `Started` 就回到提示字元 | 畫面沒畫完，不是錯。看下一條日誌**最後一次**是不是 HTTPS；`docker compose --env-file $cfg ps patient-web` 是 `Up` 就好 |
| 日誌裡「找不到伺服器憑證」和「HTTPS」同時出現                          | `--tail 5` 跨到了重新啟動之前那一次，以**最後一次**啟動的那幾行為準                                                    |
| 日誌寫 `8081`、`http://api:3000`，不是 `18081`、`13000`                | **正常**，那是容器裡面的埠                                                                                             |
| 院內 CA 或簽章金鑰指紋與 T-02 不一樣                                   | **停手**，有新的金鑰產生了；T-08 那張表應該已經擋下來，回頭看是哪一步漏看                                              |

### T-11 在主機上登入

**做什麼**：主機的瀏覽器開 **`http://<IP>:18080`**——不要用 `localhost`，**也不要再用 `<名稱>`**。用管理者登入；第一次部署、還沒改過密碼的話，用 `.env` 的 `SUPER_ADMIN_WORK_ID` 與 `SUPER_ADMIN_INITIAL_PASSWORD`：

```
Select-String -Path $cfg -Pattern '^SUPER_ADMIN_(WORK_ID|INITIAL_PASSWORD)='
```

**成功**：登得進去（第一次是被要求改密碼；新密碼由**護理長**決定、自己保管，你不要記在任何地方）。用 `http://<名稱>:18080` 開，頁面還是開得起來，**按登入一定 `Failed to fetch`**：放行名單上現在只有 `<IP>`。這不是壞掉，是位址換過了。

### T-12 在護理站的電腦上登入

**做什麼**：**護理站的電腦**開 `http://<IP>:18080`，登入（請護理長自己輸入密碼）。🏥 護理站的電腦要 Windows 密碼才進得去、螢幕會休眠，休眠後要重新輸入（1029 實測）：先找好會在場、能幫忙輸入的護理師。

**成功**：登入成功。**這一步過了，換位址才算數。** 記下時間（1029 是 15:34）。

做完之後：

- 護理站瀏覽器裡的書籤、桌面捷徑，有用 `<名稱>` 的**全部改成 `http://<IP>:18080`**
- **告訴護理站的人**：網址換了，舊的網址頁面開得起來，但登不進去

### T-13 平板連得到，下載頁換過了

**做什麼**：平板（或手機）連上**平板實際要用的那個 Wi-Fi**，瀏覽器開 `http://<IP>:18081/shell/`。

**成功**：看得到下載頁；安裝步驟第 2 點寫的主機位址是 **`https://<IP>:18081`**，不是 `<名稱>`；「版本資訊」的三個 SHA-256 **抄下來**，交接文件要用（E-10 那一項）。檔案 SHA-256 每建一次 APK 就會變，以 T-08 最後一次之後的為準；簽章憑證與院內 CA 兩個 SHA-256 與換之前相同。

### T-14 收尾

**做什麼**

```
Remove-Item "$root\config\.env.before-ip"
Get-ChildItem "$root\config"
```

**成功**：`config` 裡只剩 `.env`（與 `ai-gateway` 資料夾，做過的話）；演練紀錄寫了下面幾格：

| 記什麼                    | 從哪一步                                      |
| ------------------------- | --------------------------------------------- |
| 改用 IP，由誰確認、哪一天 | T-01                                          |
| T-02 抄的五樣             | 拿回來判斷之前為什麼登不進去（E-13）          |
| 每一步的開始與結束時間    | T-07 的建置、T-08 的 `shell-builder` 特別要記 |
| 新的金鑰備份檔名          | T-09                                          |
| 三個 SHA-256              | T-13                                          |

**IP 本身只寫演練紀錄**，不寫進任何會上站的文件。接著回到當趟進院冊的下一步（1029 是接著換版）；從零部署時，備份還原（V-18）往下照做，登入確認（V-17）已在 T-11、T-12 做完，`shell-builder` 那幾步（V-20～V-24）T-08～T-10 已經補上。

## 3. 換回名稱

T-04 之後、T-12 之前任何一步發現 `<IP>` 行不通（例如資訊室改口說 IP 不能固定），而資訊室確認名稱查得到，就換回去。**步驟一樣、代價一樣**：

```
Copy-Item "$root\config\.env.before-ip" $cfg
docker compose --env-file $cfg build
docker compose --env-file $cfg up -d
docker compose --env-file $cfg --profile shell run --rm shell-builder
docker compose --env-file $cfg --profile shell run --rm shell-builder keys-backup
docker compose --env-file $cfg --profile shell run --rm shell-builder keys-verify
docker compose --env-file $cfg restart patient-web
```

`.env.before-ip` 的 `CORS_ORIGINS` 要先確認是 `http://<名稱>:18080`（1001 填錯的就是這一行）。`shell-builder` 這次會寫「這一次新產生：伺服器憑證（`<名稱>`）」，是對的。之後照 T-07 的表、T-10 的表、T-11～T-13 同樣驗一次，只是 `<IP>` 都換成 `<名稱>`。

**不要換來換去。** 每換一次都要重建、重簽，T-02 抄下來的線索也會一次比一次遠。決定之前先拿到資訊室的書面答覆（T-01）。

## 4. 平板已經佈建了的話

1029 起 `TB-00` 已佈建，**之後再換位址，這一節一定要做**。除了第 2 節，還要：

| 要做什麼                                                                                                                                                                                | 為什麼                                               |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| **先約好停機時段**，在護理端確認那段時間沒有平板綁著病人                                                                                                                                | 換位址的那一刻起，所有平板都連不上，直到各自重新佈建 |
| 每一台平板的 App **清除資料**，照《[平板與外殼 App](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-tablet/index.md)》第 5 節重新佈建，主機位址填 `https://<新位址>:18081` | App 裡記的是舊位址，而舊位址的伺服器憑證已經不存在   |
| App **不必重裝**                                                                                                                                                                        | 院內 CA 與簽章金鑰都沒換（第 1 節）                  |

平板越多，這一節越貴——這就是「`<主機>` 擇一之後不要再換」的原因（`deploy/hospital.env.example` 的 `MDM_KIOSK_BASE_URL` 說明也這樣寫）。

## 5. 可能怎麼壞

| 在哪一步   | 症狀                                                          | 處置                                                                                                                                                   |
| ---------- | ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| T-03       | 主機上的 IP 與資訊室給的不一樣                                | **停手**，問清楚再做                                                                                                                                   |
| T-04       | 護理站或平板開不到 `<IP>`                                     | 防火牆或網段，**找資訊室，不要往下改**。不要自己關防火牆                                                                                               |
| T-06       | 第二條印出來的三行，主機部分不一樣（例如有一行還是 `<名稱>`） | 回記事本，三行改成一字不差                                                                                                                             |
| T-07       | `failed to resolve source metadata`，後面有 `no such host`    | Docker 查不到 Docker Hub 的網域。依序：同一條再打一次 → 工作列 Docker 圖示右鍵 Restart、等變綠再打 → 請資訊室看院內 DNS；用了哪一個辦法才過，寫進紀錄  |
| T-07       | `npm error code ETIMEDOUT` 或 `ECONNRESET`                    | 網路不穩，再打一次；已下載的部分會沿用                                                                                                                 |
| T-07       | 網頁裡的後端位址還是 `<名稱>`                                 | `build` 沒有吃到新的 `.env`：多半是少了 `--env-file $cfg`，或 `$cfg` 沒設（開工三行）。補上再 `build`、`up -d`                                         |
| T-07       | 放行檢查什麼都沒印                                            | `CORS_ORIGINS` 還不是 `http://<IP>:18080`，或改完沒有 `up -d`。日誌最後一行「允許的前端來源」會告訴你後端手上是哪一份                                  |
| T-07       | 日誌那一條什麼都沒印                                          | 那一行開頭的 `[Console]::OutputEncoding = [Text.Encoding]::UTF8;` 漏打了，補上整行再打                                                                 |
| T-07       | `api` 一直是 `Restarting`                                     | `docker compose --env-file $cfg logs api --tail 30`，最後幾行寫是哪一條設定被拒，照著改 `.env` 再 `up -d`                                              |
| T-08       | `MDM_KIOSK_BASE_URL 要以 https:// 開頭`                       | 第三行改的時候把 `https://` 改掉了，改回來                                                                                                             |
| T-08       | 新產生的清單裡有「院內 CA」或「APK 簽章金鑰」                 | **停手**（T-08 那張表）                                                                                                                                |
| T-10       | **最後一次**啟動的日誌是「找不到伺服器憑證…暫以 HTTP 提供」   | T-08 沒成功，或做完沒有 `restart patient-web`                                                                                                          |
| T-10       | `keys-info` 的伺服器憑證還是 `DNS:<名稱>`                     | T-08 沒有讀到新的 `.env`，回 T-06 的第二條確認，再重跑 T-08                                                                                            |
| T-11、T-12 | 頁面開得了，按登入 `Failed to fetch`                          | 網址列是不是 `http://<IP>:18080`（不是 `<名稱>`、不是 `localhost`）；是的話按 Ctrl＋F5 強制重新整理，舊網頁可能還留在瀏覽器裡。仍不行照上層文件第 2 節 |
| T-11       | `工作ID 或密碼錯誤`                                           | 有連到後端了（名單已修好），帳號密碼的事，見上層文件第 2 節第 1 步                                                                                     |
| T-12       | 主機上登得進去，護理站的電腦開不到頁面                        | T-04 應該已經擋下來。找資訊室                                                                                                                          |
| T-13       | 下載頁上的主機位址還是 `<名稱>`                               | T-08 沒成功，或瀏覽器顯示的是舊頁面（重新整理）                                                                                                        |
| 任何一步   | 試了一小時仍然不通                                            | **停手**，照第 3 節換回名稱，把每一步的結果與錯誤原文抄回來                                                                                            |

## 6. 一張紙帶進去

1. **資訊室說 IP 已經固定，才換**（T-01）
1. **改之前先從護理站與平板連一次 `<IP>`**，連不到就不要改（T-04）
1. **改之前先抄**：五樣（T-02）
1. **三個位址一起改，一字不差**（T-06）
1. **`build` → `up -d` → `shell-builder` → `keys-backup` → `restart patient-web`**，一步都不能少（T-07～T-10）
1. **`shell-builder` 新產生的只能有伺服器憑證**，看到 CA 或簽章金鑰就停手（T-08）
1. **之後一律開 `http://<IP>:18080`**，護理站的書籤一起改（T-12）
1. 平板已佈建：每一台清除資料、重新佈建（第 4 節）
1. 登不進去：訊息 → 網址列 → 主機上五條，全部抄下來（上層文件第 2 節）
