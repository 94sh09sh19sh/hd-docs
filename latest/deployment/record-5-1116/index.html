    3. 發現¶

    SR-01 AF-03 又把路徑改進 Read-Host 的引號裡¶

    • 跟 1109 B-06（《第四次進院紀錄》BR-08）同一種錯：路徑寫進提示字串，畫面只把它當提示印出來，按 Enter 時沒貼東西，$old 是空的，Test-Path 兩個 False
    • 手冊已改：《任務一 · 抓取腳本上線》AF-03 寫「第一行原樣貼、引號裡的字不要改，提示出現才貼路徑」，《任務一之一：詳細版》列為「第一個 False」最常見的原因
    • 兩次都是同一種指令：之後要使用者輸入路徑的步驟，考慮改成先在檔案總管複製路徑、指令用 Get-Clipboard 讀

    SR-02 手冊的兩行指令被併成一行¶

    • 現場補 AF-03 的排程檢查時，開發端存檔的自動排版把「C 槽可用」與新加的那一行併成一行，已推上文件站；現場照貼出現 ParserError
    • 當場拆回兩行、重新推站。這是開發端的錯，不是現場操作的錯
    • 開發端之後改手冊裡的指令，推站前先看過那幾行

    SR-03 改名被拒，檔案總管改得動；舊資料夾被學長刪了¶

    • AF-04 robocopy 成功、兩邊一樣，Rename-Item 卻「拒絕存取路徑」；改在檔案總管按右鍵「重新命名」，沒有跳任何視窗就改好
    • 原因查不出來，多半是當時有東西短暫抓著它（例如防毒在掃剛讀過的 8 GB，或檔案總管開著它）。《任務一之一：詳細版》AF-04 已補三步處置
    • AF-11 三輪成功後，學長說不需要了，把 D 槽整個舊資料夾刪掉：退回步驟 R-2（改回原名，現收在《院方 API 抓取腳本的維運》）從此做不到，退回只能用 C 槽那一份
    • 學長的 hb_online_v2.py 與它的資料（Hb_API_Fetch）跟著搬到 C 槽、內容不動；AF-03 加了「有沒有別的排程指著 API_Fetch」的檢查，結果沒有，也沒有 Python 在跑
    • hb_online_v2.py 在這台主機上沒在跑：沒有排程、沒有程式在跑，資料停在 11/06（SR-04），跟學長 1114 答的「這台沒有別的程式在寫」一致，它是在正式 IDH 主機上跑的。所以搬 C 槽不會弄壞它，不必特別通知學長；傳給學長的路徑說明裡順帶一句「Hb_API_Fetch 也在 C 槽」就好

    SR-06 目標脫水量 3 次超過 8 公升¶

    • 稽核軌跡很多筆「院方 API：整批未寫入，共 1 處問題。第 1 列 value：目標脫水量超出可接受的範圍 0～8000 mL」

    • 74.6 公升不可能是一次的脫水量，研判院方那幾筆把體重填進目標脫水量欄。範圍檢查擋得對，不是本系統的錯，不必改範圍
    • 被擋的只有那 3 次的四個數值（理想體重、目標脫水量、結束體重、實際脫水量）；療程、床位、生命徵象照常寫
    • 每 3 分鐘重讀一次就再記一筆，一天會累積幾百筆同樣的稽核紀錄。要不要改成「同一次透析同一個原因只記一次」是開發端的候選改動，要先問使用者
    • 《任務二之二：詳細版》SY-11 已補處置與那一行只讀統計（那一行之後也收在《讀檔：啟用、檢查、停用》）
