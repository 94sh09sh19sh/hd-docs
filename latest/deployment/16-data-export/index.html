    第十六冊 · 取出資料：研究與後續計畫的資料取出¶

    版本：v0.1　文件狀態：草案（1027 新增，迭代 28）　編號：U-xx

    院方要求系統蒐集的資訊日後要全部取得出來，供後續計畫做資料分析與模型訓練。這一冊寫在院內主機上、照步驟手動取，不靠任何 AI：指令複製貼上就做得完。

    規則的真本是《部署規範》DEP-47 與《資料庫使用規範》第 20 條；為什麼這樣設計見《蒐集資料的完整取出》。同一份步驟另有兩個副本：指令的 --help、每一個輸出資料夾裡的 讀我.txt。

    摘要¶

    • 先有院方核准、核准文號、經手人，沒有院方核准不得執行（U-01）
    • 先 --list 看有哪些類與表，再選範圍：全部（--all）、某幾類（--category）、某幾張（--tables）；要合併分析的表要同一次取（U-02、U-03）
    • 等級二選一：完整（原值，只留主機）或假名化（姓名、病歷號等換成代號，仍屬個人資料）（U-03）
    • 可以從某一份備份取（--from-backup），雜湊對不上就不取（U-04）
    • 取完驗雜湊、用試算表或 SQLite 檢視工具開，不必寫程式（U-05、U-06）
    • 用完刪掉匯出檔，在護理端「系統管理 → 資料取出紀錄」確認有紀錄（U-08）
    • 指令本身壞了還有第二條路：直接開最新一份備份檔，另外手寫紀錄交給院方（U-09）
    • 公開手冊裡院內的值一律寫成佔位字：<用途>、<核准文號>、<經手人>；實際的值只留主機與院方紙本

    0. 讀之前¶

    0.1 這一冊做什麼¶

    步驟 在哪裡 產生什麼
    看有哪些資料 主機：data-export --list 只在畫面上列，不寫檔案、不算一次取出
    取出 主機：data-export（一次性容器，一條網路都沒有） 匯出目錄底下一個 hd-export-<日期時間>-<等級> 資料夾
    確認、開啟 主機：PowerShell、試算表、SQLite 檢視工具 —
    留紀錄 自動：取出紀錄寫進備份目錄的 export-log.jsonl，後端一小時內收進稽核軌跡 護理端「資料取出紀錄」多一列

    網路上沒有任何地方叫得動取出：後端沒有端點、護理端沒有按鈕，只有登入這台主機、在主機上下 docker compose 的人跑得動（DEP-38、DEP-47）。

    0.2 東西放在哪裡¶

    東西 位置 說明
    匯出目錄 .env 的 HD_EXPORT_DIR，例如 C:\hd\hd-tablet-care\export 與備份目錄分開（第十五冊之一 1.2 節）
    輸出資料夾 匯出目錄\hd-export-<日期時間>-full 或 -pseudonymized 每一次一個，取出不覆蓋任何既有檔案
    假名化金鑰與對照表 匯出目錄\假名化對照\<輸出資料夾名> 不在輸出資料夾裡；只留主機，不得隨資料搬走
    取出紀錄 備份目錄\export-log.jsonl 一行一次；不要手改（後端看得懂的才收）

    0.3 開工三行¶

    每一次開 PowerShell 先打（與第十五冊 V-09 相同）：

    $root = "C:\hd\hd-tablet-care"
$cfg  = "$root\config\.env"
cd $root\repo

    會怎麼壞：docker compose 停在「請設定 HD_EXPORT_DIR」→ .env 還沒有這一行，照第十五冊之一 1.2 節補上。

    1. 誰可以取、取之前要有什麼¶

    U-01 確認核准¶

    1. 院方的核准（核准流程與誰簽，待院方答覆，清冊 Q-39）；要倫理審查的，備妥文號
    2. 核准涵蓋哪些資料、完整級還是假名化級——核准只涵蓋部分資料時，用 U-03 的「某幾類」或「某幾張」，不要取全部再自己刪（個資法的最小必要原則）
    3. 經手人：在主機上執行這一次的人

    會怎麼壞：沒有核准文號 → 不要執行，指令也會停在「缺少 --approval」。系統不驗文號真偽，驗的是院方。

    2. 取出¶

    U-02 先看有哪些類與表¶

    docker compose --env-file $cfg --profile export run --rm data-export --list

    怎麼知道成功了：印出十二類（病人與療程、病人自述、臨床數值、護理紀錄、衛教與測驗、遊戲、AI、營運與績效、裝置與連線、稽核、系統設定、帳號），每一類底下每張表一列：英文表名、中文名稱、幾筆、最早與最晚的日期。

    會怎麼壞：

    看到 原因 處理
    DATABASE_URL 指向的資料庫檔案不存在 資料卷沒建或名字不對 第十五冊 V-13
    no such service: data-export 這一版 tag 比迭代 28 舊 先照第十一冊 W-19 換版

    U-03 選範圍與等級，取出¶

    三種範圍擇一（--category 與 --tables 可以合用，取兩者的聯集）：

    # 全部
docker compose --env-file $cfg --profile export run --rm data-export --all --level full --purpose "<用途>" --approval "<核准文號>" --operator "<經手人>"

# 某幾類表（類名用 U-02 印出來的中文）
docker compose --env-file $cfg --profile export run --rm data-export --category 病人自述,臨床數值 --level pseudonymized --purpose "<用途>" --approval "<核准文號>" --operator "<經手人>"

# 某幾張表（表名用 U-02 印出來的英文）
docker compose --env-file $cfg --profile export run --rm data-export --tables help_requests,clinical_values --level pseudonymized --purpose "<用途>" --approval "<核准文號>" --operator "<經手人>"
    參數 意思
    --level full 完整：原值，含一份 data.sqlite。只留主機；要搬到院內分析機器須院方核准
    --level pseudonymized 假名化：姓名、病歷號、工作識別碼、床號換成 ps- 代號；識別碼與指向別張表的欄位也換成這次專用的代號；自由文字欄（護理紀錄內文、AI 的提示與輸出、病人打的字）整欄不出。仍屬個人資料，不得稱為「去識別化」或「匿名」
    --keep-free-text 假名化級仍保留自由文字欄（核准涵蓋時才用）
    --with-parents 連同被指向的上一層表一起取（例如求助帶上病人、療程、平板），只往上一層

    要合併分析的表要在同一次取：假名化的代號每次取出都不同，分兩次取的表接不起來。

    指令先印摘要（等級、資料來源、寫到哪裡、哪幾張表、幾筆、預估大小、用途、核准文號、經手人），看清楚再輸入 yes；打其他任何字都會取消、不寫任何檔案。

    怎麼知道成功了：最後印「取出完成。」與資料夾名稱、檔案數、表數、筆數。

    會怎麼壞：

    看到 原因 處理
    沒有給範圍 三個範圍都沒寫 加 --all、--category 或 --tables
    沒有「…」這張表。最接近的是：… 表名打錯 照它列的改；完整清單見 U-02
    沒有「…」這一類 類名打錯 同上
    --all 不能與 --category、--tables 合用 寫了兩種範圍 擇一
    缺少 --purpose（用途）… 三個沒給齊 補上
    HD_EXPORT_DIR 與備份目錄重疊、位於雲端同步資料夾內、位於共用目錄 匯出目錄的位置不對 照第十五冊之一 1.2 節改 .env
    匯出目錄可用空間 … 不夠 磁碟快滿了 主機與其他專案共用，先查清楚是誰佔的，不要刪別人的東西
    取出中止：… 中途出錯 寫到一半的檔案已刪掉、失敗也記進了紀錄；照訊息排除後重跑

    3. 從某一份備份取出¶

    U-04 指定備份¶

    要回到某一天的狀態，或要取的資料在正本裡已經被刪掉時，改從備份目錄裡的某一份取：

    Get-ChildItem "$root\backups\*.db" | Sort-Object LastWriteTime | Select-Object Name, LastWriteTime
docker compose --env-file $cfg --profile export run --rm data-export --from-backup <備份檔名> --tables patients --level full --purpose "<用途>" --approval "<核准文號>" --operator "<經手人>"

    --from-backup 只給檔名、不給路徑。指令先比對備份旁邊的 .sha256 檔與備份歷程上的雜湊，對不上就不取。範圍照那一份備份的資料表判斷：那時還不存在的表列為「這份資料沒有」，不算失敗。

    會怎麼壞：旁邊沒有 .sha256 檔、雜湊…對不上 → 這份備份不可信，換一份；不要自己補 .sha256 檔。

    4. 確認取出成功¶

    U-05 看筆數、驗雜湊¶

    1. 開輸出資料夾的 讀我.txt：最後一段列了每張表幾筆，與 U-02 的筆數對一下
    2. 驗雜湊（在輸出資料夾裡）：
    cd "$root\export\<輸出資料夾名>"
Get-FileHash -Algorithm SHA256 tables\help_requests.csv
Select-String -Path SHA256SUMS.txt -Pattern 'tables/help_requests.csv'

    兩個 SHA-256 一樣（大小寫不計）就是檔案完整。搬到別台機器之後再驗一次。

    5. 開啟來看¶

    U-06 不必寫程式¶

    檔案 怎麼開
    tables\<表名>.csv 試算表直接開（UTF-8、第一列是欄名）
    data.sqlite（只有完整級） 任何 SQLite 檢視工具（例如 DB Browser for SQLite）
    data-dictionary.md 每一欄的意思，取出當時那一版的資料字典
    manifest.json 每張表的筆數、每一欄的匯出分類與處理方式、指向了但沒取的表

    時間：CSV 是台灣時間並標 +08:00；data.sqlite 裡是 UTC 的毫秒數。布林值寫成 1、0。

    6. 搬到院內分析機器¶

    U-07 院方核准之後才做¶

    • 只搬到院方指定、院內的那一台；完整級能不能搬、搬到哪一台，待院方答覆（Q-39 第 2 題）
    • 搬之前與搬之後各驗一次雜湊（U-05）
    • 假名化對照資料夾不跟著搬
    • 不得上傳雲端、寄電子郵件、放隨身碟帶回家；出院只能走院方另行核准的流程

    7. 用完之後¶

    U-08 刪掉匯出檔、確認紀錄¶

    1. 分析的人說用完了，刪掉輸出資料夾與它的假名化對照資料夾：
    Remove-Item -Recurse "$root\export\<輸出資料夾名>"
Remove-Item -Recurse "$root\export\假名化對照\<輸出資料夾名>"
    1. 護理端以系統管理者登入 → 系統管理 → 資料取出紀錄：這一次的時間、等級、範圍、用途、核准文號、經手人、筆數都在（後端啟動時與每小時收一次，剛取完最多等一小時）

    匯出檔在主機上可以留多久、誰負責刪，待院方答覆（Q-39 第 5 題）。

    會怎麼壞：一小時後還沒出現 → 確認後端在跑（docker compose --env-file $cfg ps）；還是沒有，把 export-log.jsonl 最後一行的時間抄給開發端，不要手改那個檔案。

    8. 指令本身壞了怎麼辦（第二條路）¶

    U-09 直接開備份檔¶

    取出指令跑不起來、又急著要資料時：

    1. 備份目錄裡最新一份備份（hd-backup-*.db），先驗雜湊：
    $b = Get-ChildItem "$root\backups\hd-backup-*.db" | Sort-Object LastWriteTime | Select-Object -Last 1
(Get-FileHash -Algorithm SHA256 $b.FullName).Hash
Get-Content "$($b.FullName).sha256"
    1. 一樣的話，複製到匯出目錄：Copy-Item $b.FullName "$root\export\"
    2. 用 SQLite 檢視工具直接開——備份就是一份完整的資料庫

    這條路缺兩樣東西：沒有假名化（是完整級的原值，密碼雜湊等也在裡面），也沒有取出紀錄。要另外手寫一筆紀錄交給院方：誰、何時、哪一份備份、什麼用途、核准文號；並把指令壞掉的訊息抄給開發端。

    9. 疑難排解¶

    狀況 處理
    指令停住不動 它在等 yes；確認摘要後輸入 yes 再按 Enter
    CSV 用試算表開出現亂碼 用試算表的「匯入文字檔」選 UTF-8
    想知道某一欄能不能給 看 manifest.json 那一欄的 class（匯出分類）與 treatment（處理方式），或資料字典每欄的「匯出分類」
    某張表 --list 有、取出說沒有 從比較舊的備份取時會這樣（那時還沒有那張表），不是錯誤
