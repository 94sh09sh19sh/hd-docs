## 3. 遇到的問題

### M-01 護理端登入出現 `Failed to fetch`

**發生了什麼**：N-16 用瀏覽器開護理端，登入頁出得來，按下登入，登入鈕下面出現 `Failed to fetch`。

`Failed to fetch` 的意思是**瀏覽器根本沒拿到後端的回應**——帳號密碼還沒被檢查到。原因只有兩類：網頁連的後端位址不對，或後端的 CORS 不放行這個來源。

**現場查到哪裡**：照第十四冊[附錄：護理端頁面開得起來卻登不進去](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/14-from-zero/#%E9%99%84%E9%8C%84%E8%AD%B7%E7%90%86%E7%AB%AF%E9%A0%81%E9%9D%A2%E9%96%8B%E5%BE%97%E8%B5%B7%E4%BE%86%E5%8D%BB%E7%99%BB%E4%B8%8D%E9%80%B2%E5%8E%BB)第 2 步打了三條指令：

| 指令                                                                           | 結果                | 意思                                   |
| ------------------------------------------------------------------------------ | ------------------- | -------------------------------------- |
| 第一條：`.env` 裡的 `CORS_ORIGINS`、`HD_PUBLIC_API_URL`                        | **沒有帶回來**      | —                                      |
| 第二條：`curl.exe -s http://<主機>:<後端埠>/api/health`                        | `{"status":"ok",…}` | 用 `.env` 裡那個 `<主機>` 連得到後端 ✓ |
| 第三條：帶 `Origin: http://<主機>:<護理端埠>` 看 `Access-Control-Allow-Origin` | **什麼都沒印出來**  | **後端沒有放行這個來源** ✗             |

> 17:58 在現場曾回報第三條「印出 `…rol-Allow-Origin`」；回來後確認，**第三條的結果是空的**，以紀錄檔為準。

**這三條合起來的意思**：後端活著、`<主機>:<後端埠>` 連得到（第二條），但後端的 CORS 名單裡**沒有** `http://<主機>:<護理端埠>` 這個來源（第三條）。 光這一點就足以讓登入出現 `Failed to fetch`。照附錄，原因只有兩種：

1. **`.env` 的 `CORS_ORIGINS` 寫的不是 `http://<主機>:<護理端埠>`**——例如仍是範例的 `hd-server`、寫成 `localhost`、名稱與 IP 的寫法和第三條用的不同、埠不對。 17:47 問過「`hd-server` 要照寫還是寫主機名稱」，照抄過範例的可能性不低。
1. **`.env` 是對的，但改完之後沒有 `up -d`**：`.env` 只在容器建立時讀一次，執行中的後端還在用改之前的 `CORS_ORIGINS`。

第一條沒帶回來，所以分不出是哪一種。**兩種的處置都是改好 `.env` 之後 `docker compose --env-file $cfg up -d`，再打一次第三條，要印出 `Access-Control-Allow-Origin: http://<主機>:<護理端埠>`。**

**CORS 修好之後還要確認的兩件事**（現場沒查到這裡）：

1. **瀏覽器網址列上的網址**。17:45 問過「能不能用 `localhost` 開護理端」——實際部署用 `localhost` 開，網址列的來源與 `CORS_ORIGINS` 對不上，CORS 修好了照樣是 `Failed to fetch`。
1. **網頁裡寫死的後端位址**。`HD_PUBLIC_API_URL` 在 `build` 時寫進網頁檔案；若建置之後才把 `.env` 的位址改成真正的名稱，只 `up -d` 不會更新網頁裡的位址。

**下一次怎麼做**：見[第 7 節](#7-%E4%B8%8B%E4%B8%80%E6%AC%A1%E9%80%B2%E9%99%A2) M-14 第 2 項，第十五冊 V-17 把這些都排進了步驟本身。

### M-03 根目錄改放 C 槽

### M-05 防毒排除清單是空的

**發生了什麼**：照第十四冊[附錄：查防毒軟體與排除清單](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/14-from-zero/#%E9%99%84%E9%8C%84%E6%9F%A5%E9%98%B2%E6%AF%92%E8%BB%9F%E9%AB%94%E8%88%87%E6%8E%92%E9%99%A4%E6%B8%85%E5%96%AE%E5%8F%AA%E7%9C%8B%E4%B8%8D%E6%94%B9)（這一段就是當天在現場寫進去的）查到：

| 查什麼              | 結果                                                             |
| ------------------- | ---------------------------------------------------------------- |
| 主機上的防毒        | Windows Defender，`hex` 是 `061100`——中間兩碼 `11`，**正在運作** |

**意思**：Docker Desktop 的虛擬磁碟（資料庫就在裡面）正被 Defender 即時掃描。這正是[總覽第 6 節](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/#6-%E4%BB%80%E9%BA%BC%E6%83%85%E6%B3%81%E4%B8%8B%E7%95%B6%E5%A0%B4%E5%81%9C%E6%89%8B)「防毒排除當天加不了，有人說先跑跑看」那一條： SQLite 被即時掃描鎖住的錯誤是**間歇性、不固定重現**的。
