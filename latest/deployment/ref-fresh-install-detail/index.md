## 摘要

- 0926 起唯一的部署路線：院方要求以容器部署、程式以 `git clone` 取得、院內連得出去但外面連不進來、**不准用隨身碟**、Administrator 不設密碼（《部署規範》v3.0 第 0.1 節）；離線安裝包路線撤除，不是降為備案

- 第 7 節：開發機實測（DEP-22）「從零」的定義與六項要驗的
- 第 9 節：這條路線特有的疑難排解；第 10 節：當初還沒到的元件（都已完成）
- 舊第 6 節更新與回退在《本系統換版與退回》、舊第 8 節關服務在《備份、還原與關服務》

主機上替本系統開一個自己的目錄。第十一冊當時的例子是 `D:\hd-tablet-care\`；**1001 起院內實際用 `C:\hd\hd-tablet-care\`**（D 槽 0922 只剩約 4.6%），🧪 開發機用 `C:\hd-sim\`。下表以 `<根目錄>` 表示：

| 東西                                 | 位置                                                                             | 為什麼                                                                                                                                                                                                                                |
| ------------------------------------ | -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 原始碼                               | `<根目錄>\repo\`（`git clone` 下來的）                                           | 建置映像檔用；**更新時還要用**                                                                                                                                                                                                        |
| 設定                                 | `<根目錄>\config\.env`（AI 閘道的 `config.yaml` 放在 `config\ai-gateway\`）      | **不在 clone 目錄裡**（DEP-08）：某一次「整個刪掉重新 clone」不能把設定一起刪掉                                                                                                                                                       |
| 備份                                 | `<根目錄>\backups\`                                                              | 資料卷裡的資料庫唯一看得見的出口，院方的備份軟體從這裡送往另一台機器（DEP-06）                                                                                                                                                        |
| 匯出（1027 迭代 28 起）              | `<根目錄>\export\`                                                               | 研究與後續計畫的資料取出寫在這裡，**與備份分開**（備份會送往另一台機器，取出檔不該跟著走）；只掛給一次性的 `data-export`（DEP-47，《[取出資料](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-data-export/index.md)》） |
| 資料庫                               | 具名資料卷 `hd-tablet-care-data`                                                 | **只能放資料卷，不得是 Windows 目錄**（DEP-23）。檔案總管看不到它是正常的                                                                                                                                                             |
| CA、伺服器憑證、APK 簽章金鑰、下載頁 | 具名資料卷 `hd-tablet-care-keys`                                                 | 私鑰不離開主機（DEP-35）。0927 起由 `shell-builder` 產生，見《[平板與外殼 App](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-tablet/index.md)》                                                                        |

| 🏥 院方資料（1110 迭代 32 起）       | 抓取腳本的留底資料夾（1116 起 `C:\API_Fetch\IDH_interface`），**唯讀**掛進 `api` | 本系統不打院方 API，只讀抓取腳本存下的檔；不搬、不刪、不改任何留底檔（DEP-37 第 3 條的例外，《[讀檔：啟用、檢查、停用](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-dialysis-files/index.md)》）                      |

**繫結掛載只有 `config` 與 `backups` 兩個**（DEP-37 第 3 項），`npm run check:container` 會在開發端擋住任何第三個。例外只有兩處：一次性的 `data-export` 另掛匯出目錄；讀檔模式由 `COMPOSE_FILE` 帶進 `docker-compose.dialysis-files.yml`（與 `docker-compose.lab-files.yml`），以 `read_only` 掛抓取腳本的資料夾。

### 0.3 開發機實測結果（0926）

第十一冊的每一條指令都在開發機上照順序跑過一次：**從 GitHub 全新 clone、全新資料卷、只用 Git 與 Docker**，接著走完一次更新（新 tag、備份並驗證還原、套用一個新遷移）與一次回退（舊 tag、舊映像檔、還原備份）。每一步的結果在《[部署演練紀錄](https://94sh09sh19sh.github.io/hd-docs/latest/notes/deployment-drills/index.md)》第 8 節。

實測抓到兩件事，都已處理：

| 問題                                                             | 不處理會怎樣                                           | 處理                                                                                                   |
| ---------------------------------------------------------------- | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------ |
| `db:update` 以一次性容器執行時，「服務是不是還開著」問的是它自己 | 服務沒停也照樣更新——**備份與遷移之間的寫入會補不回來** | compose 給它 `UPDATE_PROBE_URL=http://api:3000/api/health`，改問正在跑的 `api`；實測服務開著時確實拒絕 |
| 還原腳本在映像檔裡跑不起來                                       | 回退時沒有工具可以把備份放回資料卷                     | 映像檔一併帶入還原腳本需要的原始碼與設定                                                               |

**開發機驗不到、要在院內那台驗的**：主機的 Docker 版本與資料位置、登記過的連接埠、斷電重開後 Docker Desktop 會不會自己起來（DEP-21 第 4 項）、防毒排除（Q-27）。1116 為止，院內這幾項的現況在《[院內主機現況與未完成事項](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-status/index.md)》（重新開機仍沒驗過）。

| `failed to read …\.env: line N: unexpected character … in variable name …` | `.env` 第 N 行不是註解也不是「名稱=值」；`v0.5.0` 範本第 98 行就是這樣一行斷掉的註解 | 刪掉第 N 行（或開頭加 `#`），見上層 V-12                                                                                                |
| `docker-compose.lab-files.yml 要配 HD_LAB_DIR`                             | `COMPOSE_FILE` 多帶了 `docker-compose.lab-files.yml`，`HD_LAB_DIR` 卻是空的          | `COMPOSE_FILE` 只留有填的那幾個檔（《[`.env` 怎麼填](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-env/index.md)》1.12） |
