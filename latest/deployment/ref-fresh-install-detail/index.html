    從零部署本系統之一：容器路線的原冊（第 0～2 節，W-01～W-07）¶

    上層文件：《從零部署本系統》

    狀態：現行（常備參考）。 0926 起唯一的部署路線（git clone ＋ docker compose）的原冊：每一步的規範依據（DEP 條款）、為什麼、給資訊室的問題清單、開發機實測（DEP-22）、這條路線特有的疑難排解。照著做的步驟以上層的 V-xx 為準，這裡只留 W-xx 獨有的內容。

    從哪幾份舊冊改寫（1117）：第十一冊，除了第 6 節（W-19 更新、W-20 回退，移到《本系統換版與退回》）與第 8 節（關服務，移到《備份、還原與關服務》）。

    編號：W-xx（沿用第十一冊）。W-01～W-18 與上層 V-xx 的對照在上層《第 7 份》的附錄。

    ⚠️ 所有指令都在主機的 PowerShell 下。不要自己先開任何容器，也不要自己下 docker run -v、-p。 容器一律由 docker compose 依 repo 裡的 docker-compose.yml 產生。 0922 就是在一個手動開的容器裡照步驟做，還把整顆 C 槽掛了進去（《第一次進院紀錄（0922，失敗）》F-01、F-02）。

    0.1 這條路線取代哪些¶

    0.2 東西放在哪裡¶

    主機上替本系統開一個自己的目錄。第十一冊當時的例子是 D:\hd-tablet-care\；1001 起院內實際用 C:\hd\hd-tablet-care\（D 槽 0922 只剩約 4.6%），🧪 開發機用 C:\hd-sim\。下表以 <根目錄> 表示：

    東西 位置 為什麼
    原始碼 <根目錄>\repo\（git clone 下來的） 建置映像檔用；更新時還要用
    設定 <根目錄>\config\.env（AI 閘道的 config.yaml 放在 config\ai-gateway\） 不在 clone 目錄裡（DEP-08）：某一次「整個刪掉重新 clone」不能把設定一起刪掉
    備份 <根目錄>\backups\ 資料卷裡的資料庫唯一看得見的出口，院方的備份軟體從這裡送往另一台機器（DEP-06）
    匯出（1027 迭代 28 起） <根目錄>\export\ 研究與後續計畫的資料取出寫在這裡，與備份分開（備份會送往另一台機器，取出檔不該跟著走）；只掛給一次性的 data-export（DEP-47，《取出資料》）
    資料庫 具名資料卷 hd-tablet-care-data 只能放資料卷，不得是 Windows 目錄（DEP-23）。檔案總管看不到它是正常的
    CA、伺服器憑證、APK 簽章金鑰、下載頁 具名資料卷 hd-tablet-care-keys 私鑰不離開主機（DEP-35）。0927 起由 shell-builder 產生，見《平板與外殼 App》
    外殼 App 原始碼 <根目錄>\hd-kiosk-shell\（git clone 下來的） shell-builder 從這裡取釘住的那一版（Y-02）
    程式 映像檔 hd-tablet-care:<tag> 標籤就是 git tag，舊版不刪（DEP-19）
    🏥 院方資料（1110 迭代 32 起） 抓取腳本的留底資料夾（1116 起 C:\API_Fetch\IDH_interface），唯讀掛進 api 本系統不打院方 API，只讀抓取腳本存下的檔；不搬、不刪、不改任何留底檔（DEP-37 第 3 條的例外，《讀檔：啟用、檢查、停用》）

    繫結掛載只有 config 與 backups 兩個（DEP-37 第 3 項），npm run check:container 會在開發端擋住任何第三個。例外只有兩處：一次性的 data-export 另掛匯出目錄；讀檔模式由 COMPOSE_FILE 帶進 docker-compose.dialysis-files.yml（與 docker-compose.lab-files.yml），以 read_only 掛抓取腳本的資料夾。

    0.3 開發機實測結果（0926）¶

    第十一冊的每一條指令都在開發機上照順序跑過一次：從 GitHub 全新 clone、全新資料卷、只用 Git 與 Docker，接著走完一次更新（新 tag、備份並驗證還原、套用一個新遷移）與一次回退（舊 tag、舊映像檔、還原備份）。每一步的結果在《部署演練紀錄》第 8 節。

    實測抓到兩件事，都已處理：

    問題 不處理會怎樣 處理
    db:update 以一次性容器執行時，「服務是不是還開著」問的是它自己 服務沒停也照樣更新——備份與遷移之間的寫入會補不回來 compose 給它 UPDATE_PROBE_URL=http://api:3000/api/health，改問正在跑的 api；實測服務開著時確實拒絕
    還原腳本在映像檔裡跑不起來 回退時沒有工具可以把備份放回資料卷 映像檔一併帶入還原腳本需要的原始碼與設定

    開發機驗不到、要在院內那台驗的：主機的 Docker 版本與資料位置、登記過的連接埠、斷電重開後 Docker Desktop 會不會自己起來（DEP-21 第 4 項）、防毒排除（Q-27）。1116 為止，院內這幾項的現況在《院內主機現況與未完成事項》（重新開機仍沒驗過）。

    0.4 兩個前提，先接受¶

    前提 意思
    連得出去，不等於資料可以出去（DEP-14） 部署與更新要連 GitHub、Docker Hub、npm、Prisma、Debian 套件來源；執行期零院外連線由程式擋，建置階段不掛任何資料卷
    能登入這台主機的人一律可信任（DEP-38） 院方決定 Administrator 不設密碼。本系統不在作業系統層級另設防線；這一條要寫進交接文件，日後帳號政策改變要重新評估

    怎麼知道成功了：演練紀錄每一格都填了，而且沒有 ✗（0926 那一輪在演練紀錄第 8 節）。

    W-02 確認 tag 在 GitHub 上¶

    照做的步驟：上層 V-03。

    git ls-remote --tags origin

    怎麼知道成功了：要交的 tag 出現在清單裡，而且指向的 commit 與開發機實測的那一個相同（git rev-parse "<tag>^{commit}"；附註標籤直接 git rev-parse <tag> 拿到的是標籤物件，見上層 V-03）。

    2. 主機這一層¶

    W-04 確認 Git 與 Docker 可以用¶

    照做的步驟：上層 V-04（指令、應該看到什麼、沒有 Git 時的裝法）。

    本系統對主機的要求只有這兩樣（DEP-04）。不要求、也不准自己裝 Node.js、Python 或 Android SDK。

    docker compose version 要 v2 以上：0922 現場是 v5.1.1，是對的（《第一次進院紀錄》F-15）。

    上層沒寫的「原因」欄：

    症狀 原因 處置
    failed to connect to the docker API at npipe:////./pipe/dockerDesktopLinuxEngine Docker Desktop 沒在跑 從開始選單開 Docker Desktop，等它變綠再重試。記下來：斷電重開沒人登入時就是這樣
    OSType 是 windows 切到了 Windows 容器模式 系統匣 Docker 圖示按右鍵 → Switch to Linux containers
    git 找不到 主機沒裝 Git 問資訊室。不要自己裝，那是院方的變更流程（1001 起的做法：資訊室裝，或經同意後由你裝並記下誰同意，上層 V-04）
    只有 docker-compose（有連字號）能用 舊版 Compose v1 請資訊室處理。v1 不支援本系統用的 name:、profiles、外部資料卷寫法

    W-05 Docker Desktop 的設定與防毒排除¶

    照做的步驟：上層 V-05（四項設定、查防毒與排除清單的指令、1116 起不擋的理由）。

    做什麼：開 Docker Desktop → Settings，逐項看，同機有別的專案在用時只看不改，改動要先知會資訊室（DEP-21 最後一段）。

    # 位置 應該是 為什麼
    1 General → Start Docker Desktop when you sign in 勾 否則連有人登入都不會啟動
    2 General → Send usage statistics 不勾 院外連線（FR-S07）。院內主機 0922 是開著的，~~關不關等資訊室答覆（Q-27 第 9 題），答覆前只看不改~~ 1007 答覆可以關（Q-27 第 9 題）
    3 Software updates → Automatically check for updates 不勾 更新 Docker 是院方的變更。從 Microsoft Store 裝的，這一項改由市集的自動更新決定，要到市集設定看（《第一次進院紀錄》F-16）；能不能改成手動待資訊室答覆（Q-27 第 10 題）。1007 答覆：先不改，只看、記下現行設定
    4 Resources → Advanced → Disk image location 記下路徑 防毒排除要排的就是這個目錄

    然後請資訊室把第 4 項那個目錄加入防毒排除清單（DEP-21 第 1 項）。

    怎麼知道成功了：四項抄進演練紀錄；防毒排除清單裡看得到那個目錄（1116 起加不了也照樣往下，寫進交接紙）。

    症狀 處置
    設定是灰的 院方以管理原則鎖住，記下來，由資訊室決定
    資訊室不肯排除整個虛擬磁碟目錄 第十一冊當時寫「談到有結果。即時掃描正在被寫入的虛擬磁碟，會造成間歇性的鎖定與變慢」。1116 改：不擋上線，出現變慢、備份失敗這類現象再請資訊室加；只排 Docker 資料夾（是備份的現象再加 backups），不排整顆磁碟、不排 node.exe（《第五次進院（1116）任務二 · 本系統換版上線之一：詳細版》SY-03）

    W-06 對外連線實測¶

    照做的步驟：上層 V-06（多了外殼建置的三個網域、github.com 的 22 埠，以及 Docker 自己下載兩個基底映像的第二段）。

    第十一冊當時的八條：

    Test-NetConnection github.com -Port 443
Test-NetConnection registry-1.docker.io -Port 443
Test-NetConnection auth.docker.io -Port 443
Test-NetConnection production.cloudflare.docker.com -Port 443
Test-NetConnection production.cloudfront.docker.com -Port 443
Test-NetConnection deb.debian.org -Port 80
Test-NetConnection registry.npmjs.org -Port 443
Test-NetConnection binaries.prisma.sh -Port 443

    每個網域誰要用：

    網域 誰要用
    github.com git clone、git fetch（走 SSH 時另測 Test-NetConnection github.com -Port 22）
    registry-1.docker.io、auth.docker.io、production.cloudflare.docker.com、production.cloudfront.docker.com 下載基底映像（node:20-bookworm-slim；外殼建置另有 eclipse-temurin:17-jdk-jammy）。Docker Hub 會把下載轉到這兩個下載站其中之一，兩個都要通
    deb.debian.org（埠 80） 建置時安裝 openssl
    registry.npmjs.org npm ci
    binaries.prisma.sh Prisma 引擎（只在建置時）
    dl.google.com、services.gradle.org、maven.google.com 外殼的建置（shell-builder，上層 V-21），下載 Android SDK 與 Gradle

    怎麼知道成功了：全部 TcpTestSucceeded : True。

    症狀 處置
    經代理伺服器，Test-NetConnection 是 False 改用 curl.exe -I https://registry.npmjs.org 測；Docker 另外要在 Settings → Resources → Proxies 設代理
    22 不通、443 通 部署金鑰改走 443：~/.ssh/config 的 HostName 改成 ssh.github.com、加 Port 443
    有幾個不通 補齊再往下。建到一半才失敗更浪費時間

    W-07 連接埠¶

    照做的步驟：上層 V-07（直接查 13000、18080、18081）。
