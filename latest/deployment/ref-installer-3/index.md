# 安裝包路線（歷史）（第 3 份，H-08～H-13、X-01～X-04）

上層文件：[《安裝包路線（歷史）》](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-installer/index.md)

> **狀態：歷史**（路線 0926 撤除），只當紀錄、不再照做，指令照抄跑不起來；現行部署照[《從零部署本系統》](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-fresh-install/index.md)。改寫來源見[第 1 份](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-installer/index.md)開頭。編號：`H-xx`、`X-xx`，沿用原編號。

## 摘要

- 進院當天：路線 A 讓 `git clone`／`npm install` 失敗並記下（H-08），路線 B 解壓核對雜湊、建 `.env`、遷移、服務帳號、註冊啟動（H-09～H-13，第 3 節）
- 路線 A（H-08）：預期失敗，目的是取證據（DEP-25）；`git clone` 若成功，先不要往下跑，翻[《安裝包路線之六》](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-installer-git-clone/index.md)從 G-01 做起
- 路線 B：H-09 解壓並核對雜湊（DEP-27）、H-10 建立 `.env`、H-11 套用既有遷移（DEP-31）
- H-12 建立服務帳號（需要資訊室）、H-13 註冊服務並啟動
- 第 4 節 X-01 雜湊值對不上、X-02 解壓失敗說路徑太長、X-03 驗收腳本第 5 項抓到對外連線、X-04 掃描站把檔案刪掉或隔離
- 安裝包與雜湊的出錯處置（X-01～X-04，第 4 節）

## 3. 進院當天的安裝包步驟（`H-08`～`H-13`）

原本排在進院當天的第 60～75 分（路線 A）與第 75～150 分（路線 B）；之前的 H-01～H-07（出門前、報到、掃毒、認識這台機器）與之後的 H-14～H-24（Windows 五件事、防火牆、驗證、交接、離院）在[《第一次進院之一：進院當天詳細版》](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/visit-1-system-onsite/index.md)。**0926 起 H-08～H-13 由容器路線取代**（第 0.2 節）。

### 3.1 路線 A（預期失敗，目的是取證據）

### H-08 讓它失敗，並把失敗記下來（DEP-25）

**做什麼**（每一步都計時）

```
git clone https://github.com/<repo>.git
npm install
```

**怎麼知道「成功」了**

**每一步都失敗，而且你抄下了錯誤原文與耗時。**

要填的欄位（演練紀錄 §1.3）：

| 欄位                                       | 值  |
| ------------------------------------------ | --- |
| 日期／時間                                 |     |
| 執行者                                     |     |
| 主機                                       |     |
| `git clone` 的錯誤原文                     |     |
| 耗時                                       |     |
| `npm install` 的錯誤原文                   |     |
| 耗時                                       |     |
| 有沒有人提議「開一下網路就好」、怎麼回應的 |     |

**可能怎麼壞、怎麼處理**

| 症狀                                    | 處置                                                                                                                                                                                                                                                                                                                       |
| --------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`git clone` 成功了**                  | **先不要往下跑。** 翻[《安裝包路線之六》](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-installer-git-clone/index.md)，從 G-01 做起                                                                                                                                                                         |
| **院方指定要 clone 之後用 Docker 部署** | H-08～H-13 改照[《第一次進院之五：git clone＋Docker 路線詳細版》](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/visit-1-system-docker-2/index.md)走，從 D-05 做起；H-14 起再回到[《第一次進院之二：進院當天詳細版》](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/visit-1-system-onsite-2/index.md) |
| **有人說「我開一下網路給你」**          | **婉拒，並把這件事記下來。** 零院外連線是這套系統能放病人資料的前提，第一天就自己破壞它，之後沒有人會再認真看待這條                                                                                                                                                                                                        |
| 機器上連 git 都沒有                     | 更好——那本身就是證據。記下來                                                                                                                                                                                                                                                                                               |
| 錯誤訊息很長                            | **抄開頭那幾行就夠**，重點是錯誤碼與主機名稱。另外**一定要記耗時**：開發端量到的是 71 秒，而它連第一個套件的中繼資料都還沒拿到                                                                                                                                                                                             |
| 覺得這一步沒必要、想跳過                | 這份紀錄有兩個用途：向資訊室解釋「為什麼不能用一般方式部署」時它比任何說明都有效；日後有人提議「直接在主機上更新就好」時，它是現成的答案                                                                                                                                                                                   |

> 📍 **0926 之後**：院方要求的正是容器＋`git clone`，對外連線也是常態（0930 Q-32 答覆）；0922 實際的經過見[《第一次進院紀錄》](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/record-1-0922/index.md)。

### 3.2 路線 B（正式安裝）

### H-09 解壓並核對雜湊（DEP-27）

**做什麼**

```
Expand-Archive -Path <隨身碟>:\hd-tablet-care-<版本>-<commit>.zip -DestinationPath C:\hd\hd-tablet-care-<版本>-<commit>
cd C:\hd\hd-tablet-care-<版本>-<commit>
Get-FileHash -Algorithm SHA256 .\CHECKSUMS.txt
```

壓縮檔裡**沒有最上層資料夾**，`-DestinationPath` 要寫到有版本號的那一層。

與交付單上那一串**逐字比對**。

**可能怎麼壞、怎麼處理**

| 症狀                                      | 處置                                                                                  |
| ----------------------------------------- | ------------------------------------------------------------------------------------- |
| **雜湊不一樣**                            | **停下來。** 重新複製再比一次。還是不同就是路上壞了或被掃描站動過——今天不要裝（X-01） |
| `cd` 找不到路徑，檔案全散在 `C:\hd\` 底下 | 解壓目的地少寫了版本號那一層。清掉散出來的檔案，照上面的指令重解，不要用搬的          |
| 路徑太長導致解壓失敗                      | 解到很短的路徑（`C:\hd\`），不要放在桌面或使用者資料夾深處（X-02）                    |
| 解壓很慢                                  | 2 萬多個檔案，幾分鐘是正常的                                                          |
| 不知道要解到哪                            | 問資訊室指定的安裝路徑。**要記得它必須與資料庫、備份目錄分開**（DEP-08）              |

### H-10 建立 `.env`

**做什麼**

```
Copy-Item .\.env.範本 ..\.env
notepad ..\.env
```

照 R-08 那張表填（[《安裝包路線之四》](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-installer-build-4/index.md)）。**把你在演練時填的那份拿出來照抄**，只換四種值：主機位址、連接埠、路徑、密碼。

**可能怎麼壞、怎麼處理**

| 症狀                             | 處置                                                             |
| -------------------------------- | ---------------------------------------------------------------- |
| 忘了 `DEPLOYMENT_ENV=production` | 時區檢查不會擋、開發用遷移指令不會擋。**一定要填**               |
| `CORS_ORIGINS` 還是 localhost    | 護理站電腦一連就被擋，而且錯誤只在瀏覽器主控台看得到             |
| `API_PORT` 沒填                  | 正式環境會直接拒絕啟動。**這是刻意的**：逼出「埠要先登記」這件事 |
| 密碼裡有特殊字元                 | 整串加引號，或改用不含引號與 `#` 的密碼                          |

### H-11 套用既有遷移（DEP-31）

**做什麼**

```
.\runtime\node.exe .\app\api\scripts\prisma-cli.mjs migrate deploy --schema .\app\api\prisma\schema.prisma
```

**怎麼知道成功了**

列出套用了哪幾個遷移，資料庫檔案出現在你指定的目錄。

**可能怎麼壞、怎麼處理**

| 症狀                                              | 處置                                                                    |
| ------------------------------------------------- | ----------------------------------------------------------------------- |
| `ENOTFOUND binaries.prisma.sh`                    | `PRISMA_ENGINES_DIR` 沒指好。**注意：這不是網路問題，不要因此去要網路** |
| `Error code 14: Unable to open the database file` | 目錄不存在或沒有寫入權限。先建目錄                                      |
| 拒絕啟動，說路徑在共用位置                        | 換一個專屬路徑（DEP-37 第 3 項）                                        |
| 有人建議用開發用那支遷移指令「比較快」            | **絕對不可以**：它可能直接重建整個資料庫                                |

### H-12 建立服務帳號（**需要資訊室**）

**做什麼**

請資訊室建立一個專用的低權限帳號，並告訴你帳號名稱（密碼由他們輸入，你不要知道）。

**可能怎麼壞、怎麼處理**

| 症狀                   | 處置                                                                               |
| ---------------------- | ---------------------------------------------------------------------------------- |
| 「用我的帳號跑就好」   | 不行。那個人改密碼或離職的那天服務就停了                                           |
| 「用 SYSTEM 跑」       | 不行。權限過大，且違反 DEP-12                                                      |
| 網域帳號有密碼到期政策 | **當場問清楚多久到期、到期時誰來改**。這是日後服務突然停掉的頭號原因，寫進交接文件 |

______________________________________________________________________

### H-13 註冊服務並啟動

**做什麼**

```
.\scripts\service-install.ps1 -Account "<網域或機器名>\<服務帳號>" -DataDir "<資料目錄>" -BackupDir "<備份目錄>" -LockDownDataDir
.\scripts\service-start.ps1
.\scripts\service-status.ps1
```

**怎麼知道成功了**

排程工作 Running、**執行身分是服務帳號**、3 個行程、存活檢查 HTTP 200。

**可能怎麼壞、怎麼處理**

| 症狀                                     | 處置                                                                                             |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 執行原則擋下 `.ps1`                      | `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass`。**先問過資訊室**                   |
| 資訊室堅持要 `services.msc` 看得到的服務 | 目前是排程工作（Q-27 第 6 題）。**今天先用排程工作把系統跑起來**，把需求記下來，回去換那一支腳本 |
| 行程數 0                                 | 用前景跑一次看錯誤：`.\runtime\node.exe .\scripts\run-all.mjs`                                   |
| 資料目錄被擋（在安裝包目錄之內）         | **正確行為**（DEP-08）。換一個路徑                                                               |

服務起不來的其他情形（X-05～X-11）在[《現場疑難排解》](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-troubleshooting/index.md)。

## 4. 安裝包與雜湊的出錯處置（`X-01`～`X-04`）

舊《現場疑難排解》的 A 類；其餘各類在[《現場疑難排解》](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/ref-troubleshooting/index.md)。

### X-01 雜湊值對不上

|              |                                                                 |
| ------------ | --------------------------------------------------------------- |
| **你會看到** | `Get-FileHash` 出來的字串與交付單上不同                         |
| **可能原因** | 複製時中斷；防毒「清理」過檔案；拿錯版本；解壓不完整            |
| **先查**     | 是不是拿錯壓縮檔（檔名裡的 commit）；隨身碟上那一份的雜湊對不對 |
| **處置**     | 重新複製、重新解壓、再比一次。**還是不同就今天不要裝**          |
| **不要做**   | 「差一點應該沒關係」——雜湊沒有「差一點」                        |

### X-02 解壓失敗，說路徑太長

|              |                                                               |
| ------------ | ------------------------------------------------------------- |
| **可能原因** | Windows 的路徑長度上限，加上 `node_modules` 本來就很深        |
| **處置**     | 解到極短的路徑，例如 `C:\hd\`。不要放在桌面或使用者資料夾深處 |

### X-03 驗收腳本第 5 項抓到對外連線

|              |                                                                      |
| ------------ | -------------------------------------------------------------------- |
| **你會看到** | 連線哨兵列出一個院外主機名稱                                         |
| **處置**     | **不得交付**。記下那個主機名稱帶回去，用 `npm run check:egress` 對照 |
| **不要做**   | 當成誤判跳過。這一條是整套系統能放病人資料的前提                     |

### X-04 掃描站把檔案刪掉或隔離了

|              |                                                        |
| ------------ | ------------------------------------------------------ |
| **你會看到** | 雜湊對不上，或解壓後少了某個檔案                       |
| **處置**     | 請對方加例外並重新複製一份；同時記下判定名稱與檔案路徑 |
| **不要做**   | 用被動過的包硬裝。那份包已經不是你驗收過的那一份       |
