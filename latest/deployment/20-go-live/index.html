    第二十冊 · 第五次進院：抓取腳本、換版、首波上線（新手版）¶

    版本：v0.1　文件狀態：草案（1116 依第十八冊之二整理）　編號：GO-xx　只印這一冊；第十九冊照它自己的規矩開在主機的瀏覽器上（B-04），不印

    1116 起改照第二十一～二十四冊：抓取腳本看第二十一冊、本系統看第二十三冊，出錯翻各自的詳細版（第二十二、二十四冊）；本冊內容已全部收進去，不必再印。

    這一冊回答一件事：下一次進院，同一趟把透析清單抓取腳本跑起來、本系統從 v0.4.0 換到新 tag、啟用讀檔、首波上線，手指要按什麼。 它是第十八冊之二 A-14 的「紙本」，也收了 A-13（啟用讀檔）與 A-16（交接紙）。抓取腳本那一段的指令在第十九冊，這一冊只寫從哪一步接、停在哪裡。

    指令抄自第十八冊（1116 已改完 O-13 那 13 處）、第十一冊 W-19／W-20、第十五冊 V-30a 與第十五冊之一 1.12，對照表在附錄四。兩邊不一致時以原冊為準，規則的真本是《部署規範》。

    公開範圍：文件站是公開的。這一冊一律用代稱，值只寫在印出來的《部署演練紀錄》空白表與私人 repo 的 deploy/records/。可以拍照，照片只進私人 repo、離院前從手機刪掉；.env 的內容、密碼、病人資料的畫面不拍。

    代稱 指的是
    <IP> 院內主機的固定 IP（1029 換上的那一個）
    <新 tag> 這一次要換上去的版本，出發前打好、照第十七冊整輪演練過
    <指定資料夾> 透析清單抓取腳本寫 YYYY-MM.txt 的資料夾；1114 起搬到 C 槽（第十九冊 B-14a）

    打指令時連同 <、> 一起換掉。

    摘要¶

    • 三件事同一趟做（1111 開會定）：抓取腳本跑起來 → 本系統換版 → 啟用讀檔、首波上線；前一件沒成就不做後一件（第 0.2 節）
    • 首波＝1 台暫用平板 TB-00、1 床、護理長指定的少數護理師；功能開關全部維持關閉
    • 啟用讀檔是分界線：一啟用，當天清單上所有病人都會進主機。防毒排除（A-01）、病人告知（A-03）沒答案就停在 GO-10，B 級
    • 換版 v0.4.0 → <新 tag>：3 個遷移、都只做加法；.env 多四行院方資料的設定，換版時先留空；外殼不換、APK 不重建
    • 時段要沒有透析、資訊室同仁與學長在場；全部約 5～6 小時
    • 附錄：交接紙（A-16）、退回 v0.4.0、停用讀檔、步驟對照

    9 磁碟門檻：跟資訊室議定 Docker 資料所在磁碟剩多少就通知、誰監看 寫進交接紙（第 11 章第 12 條；開發端建議剩 50 GB 就通知，資訊室定）

    怎麼知道成功了：每一列打勾，或寫明為什麼沒做。

    GO-15 交接（＝J-31）¶

    做什麼：填好附錄一的交接紙，當場講一次、讓對方自己做一次「啟停」與「斷電之後」，交給護理長與資訊室各一份。

    GO-16 離院前、第一個班次¶

    做什麼

    1. 開發端留到第一個班次結束（DEP-32）：看「院方資料同步」卡每 3 分鐘有新的一列、平板面板有更新。
    2. PowerShell 關掉；瀏覽器登出；手機裡含院內資料的照片移進私人 repo 後刪掉。
    3. 當天晚上把演練紀錄補完，寫一本進院紀錄（照第十八冊之一的寫法）。

    附錄一：交接紙（A-16）¶

    第一行寫：「首波試用：1 台平板、1 床、少數護理師，不是全單位上線」。 不寫密碼、不寫 .env 的值。

    項次 寫什麼
    首波範圍 平板 TB-00 在＿床；首波護理師＿＿；其他床照舊用原本的方式
    網址 護理站一律開 http://<IP>:18080；不要用 localhost 或舊名稱開，會登不進去
    帳號 管理者與護理長帳號的工號；密碼由護理長自己保管，開發端不知道
    版本 本系統 <新 tag>；外殼 v0.3.0；透析清單抓取腳本 hd-hospital-fetch v0.3.0
    位置 C:\hd\hd-tablet-care 底下的 repo、hd-kiosk-shell、config、backups、export；兩個資料卷；抓取腳本在 <指定資料夾> 的上一層。這些都不能刪
    院方資料 抓取腳本每 3 分鐘、只在 07:00～23:00 抓（排程 hd-hospital-fetch）；本系統唯讀讀它存的檔。腳本怎麼停找學長（第十九冊 B-19）；本系統這邊看「系統管理 → 院方資料同步」卡

    磁碟 剩＿＿GB 就通知；監看人＿＿

    附錄二：新版出問題，退回 v0.4.0（＝W-20、第十八冊附錄二）¶

    什麼時候用：GO-05 之後，新版 api 起不來或主線壞掉，現場解不開。越早越好：退回會把資料庫換回 GO-05 的更新前備份，更新之後寫進去的資料（含啟用讀檔後同步進來的）會一起消失。

    做什麼（<備份檔名>、<雜湊> 是 GO-05 抄的 hd-before-update-<時間>.db）

    1. git checkout v0.4.0；notepad $cfg：HD_IMAGE_TAG 改回 v0.4.0，HD_DIALYSIS_LIST_DIR 清空、COMPOSE_FILE 那一行改回註解（v0.4.0 不認讀檔）。
    2. 停後端、把新版的資料庫移到旁邊、還原（第二、三條各是一整行）：
    docker compose --env-file $cfg stop api
docker compose --env-file $cfg run --rm --no-deps --entrypoint sh api -c "mkdir -p /data/before-rollback && mv /data/hd.db /data/hd.db-wal /data/hd.db-shm /data/before-rollback/ 2>/dev/null; ls -l /data/before-rollback"
docker compose --env-file $cfg run --rm --no-deps api node_modules/.bin/ts-node --project apps/api/tsconfig.json apps/api/scripts/restore-backup.ts --from /backups/<備份檔名> --to /data/hd.db --sha256 <雜湊>
docker compose --env-file $cfg up -d

    怎麼知道成功了：完整性檢查：ok；docker ps 三個服務是 hd-tablet-care:v0.4.0；護理站 Ctrl＋F5 後登得進去。抓取腳本不受影響、照跑。/data/before-rollback/ 那份先留著，帶回給開發端。

    附錄三：停用讀檔（＝A-13 第 6 條）¶

    什麼時候用：GO-11 的檢查不對、GO-12 床號或療程對不上，或院方要求先停。

    做什麼：notepad $cfg，HD_DIALYSIS_LIST_DIR 清空、COMPOSE_FILE 那一行改回註解，然後：

    docker compose --env-file $cfg up -d

    怎麼知道成功了：「院方資料同步」卡寫還沒設定資料夾；日誌沒有「院方資料同步已啟用」。之後病人、床位、療程回到護理師的人工操作。

    已經寫進主機的資料：停用不會刪掉。病人主檔、床位、療程留在資料庫裡，床位只新增、不會自己消失。要整個清掉只有兩條路，都要開發端判斷後再做：退回 GO-05 的更新前備份（附錄二的第 2 步，但版本留在 <新 tag>，之後的改密碼與帳號也會消失），或照第八冊撤除。現場不要自己刪。
