## 最近三週

### [1007 — 第二次進院部分成功，院方 API 取代手動輸入（迭代 15～17）](https://94sh09sh19sh.github.io/hd-docs/latest/weekly/2026-10-07/index.md) · 修訂中

進度：

- **1001 第二次進院：B 級部分成功**。服務在院內主機上起來、外殼 APK 建好，**護理端登不進去**（後端不放行護理端的來源）；部署手冊改寫成第十五冊，另寫之三（為什麼登不進去）、之四（主機位址改用 IP）
- **1004～1005 讀了同院 IDH 系統的程式**，使用者逐項決定：直接用院方透析清單 API、抽血數值暫定拿不到（相關功能預設關閉）、低血壓門檻與處置直接套用、主機位址改用 IP
- **1005 新版需求，同日完成迭代 15～17**：院方 API 判斷得出來的事不再要護理師做；病人平板中間改成血壓與脫水量的折線圖加一條跑馬燈；**跑馬燈內容由 AI 寫、護理師只核准**。規則引擎與管理儀表板順延為迭代 18、19
- **1006 迭代 17.1**：簡易版改成把病人拖到平板（每次透析配，床號由院方資料補）；平板停用移到系統管理；護理端改名「公告與院內衛教」「結束與離院衛教」；一條指令就看得到病人平板透析到一半的樣子
- **1007 迭代 17.2～17.5**：簡易版**中間改成平板**，把病人拖上去就配好、平板右上角自動出現床號，病人框多一顆重新整理、**剛上機的病人排最上面**；**系統裡所有 AI 生成的內容禁用簡體字與中國大陸用語**，查到就請 AI 重寫，最後一次仍不合格也照樣交出，畫面上看不出這道把關；**病人平板加回病人姓名與現在時間**（病歷號仍不上首頁）；院方資料沒有預計結束時間時，**護理端與病人端的進度都以開始後四小時計**（院方規定）
- **1007 待決事項有了答案**：院內主機的 **IP 是固定的**（Q-27 第 12 題，第三次進院照換）；斷電後由護理長重新登入；所有護理師都可以核准跑馬燈內容；院方資料沒有預計結束時間時一律以四小時計。新增 Q-36（衛教要不要維持三種）；跑馬燈開啟前仍要請長者在床上看過速度

### [0930 — 部署改為容器、介面極簡重設計（迭代 11～14.5）](https://94sh09sh19sh.github.io/hd-docs/latest/weekly/2026-09-30/index.md)

進度：

- **0926 依第一次進院的教訓重排四件事**：部署改為 Docker ＋ `git clone`、外殼 App 獨立 repo、AI 閘道、介面極簡，排成迭代 11～14；規則引擎與管理儀表板順延為迭代 15、16
- **迭代 11～14 完成**：開發機上從零部署、更新與回退各一次；外殼 APK 在主機上離線建置；**病人端首頁只剩三區、護理端新增簡易版並設為預設**
- **迭代 14.1～14.5**：凌晨畫面停在前一天、掃 QR code 佈建平板、簡易版修正；**斷線示警遍及每一個畫面，大量求助湧入時專業版不再被橫幅蓋掉；醫師說透析室很暗，病人端改白底；平板確定 10 吋，橫放直放字一樣大**
- **部署手冊新增第十一～十四冊**，第十四冊是第一次部署用的新手版；Q-32（對外連線）0930 已回覆，擋住第二次進院的剩 Q-27 未答的題（斷電重開誰登入、Docker Desktop 兩項設定）

### [0923 — 部署前的迭代 7～10 完成，第一次進院失敗](https://94sh09sh19sh.github.io/hd-docs/latest/weekly/2026-09-23/index.md)

進度：

- **0919 部署前改版**：正式主機改為院內共用的 Windows 工作站、平板免 MDM、臨床資料走院方 API；部署前的修正排成迭代 7～10，原迭代 7、8 順延為 11、12
- **迭代 7～10 完成**：共用主機隔離與備份驗證、兩端介面重做、功能與內容資料化、打包成全程不連外的離線安裝包；迭代 9 實機試用後另修十一項
- **部署手冊建立**：總覽加十冊，每一步都寫出會怎麼壞、怎麼處理
- **0922 第一次進院：C 級失敗**。在自己開的容器裡照第九冊做而全部對不上，容器修正也沒合回 `master`；主機電源不穩且無人看管，列為下次進院前第一個要院方回答的問題
