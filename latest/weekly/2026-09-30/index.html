    # 0919 0926 起 迭代

    2 外殼 App 在本 repo 另一個私人 repo，以帶版本號的契約整合；APK 在院內主機上建置 12
    3 AI 只用模擬模型驗過 AI 閘道（Python ＋ LangChain）；接實驗室 GPU 伺服器做實際測試，換正式 GPU 只改設定檔 13

    迭代 11：部署改為 Docker ＋ git clone（0926）¶

    • compose 改寫：專案名稱固定、繫結掛載只剩備份與設定兩個目錄、資料與金鑰兩個資料卷標為 external（down -v 刪不掉）、映像檔標籤必帶版本號
    • 新增 check:container，把「compose 不准怎麼寫」逐條變成檢查——0922 那個掛整顆 C:\ 的容器就是它要擋的
    • 正式環境設定下選用實驗室 AI，後端直接拒絕啟動
    • 實測抓到兩個只有在容器裡才會現形的缺陷：更新腳本在一次性容器裡以為服務已停（服務開著也照樣更新）；還原腳本在映像檔裡跑不起來。都已修正

    迭代 14：介面極簡重設計（0927）¶

    先改《介面設計基準》（極簡四條、圖示登記、狀態色配形狀），再動畫面。

    做了什麼
    病人端 首頁只剩基本資訊、輪播、緊急回報三區，不再顯示姓名與病歷號；問卷、心情、衛教到時點自動全螢幕出現一次，一題一頁
    護理端簡易版 床位圖加病人、護理師、平板、輪播內容四個框；九項日常任務各一個動作，拖曳與點選都可以；做錯 8 秒內可復原，下機與結案延後 8 秒才送
    紀錄 簡易版只呼叫專業版原有的端點，兩邊寫出的稽核軌跡不可能不同
    資料 系統裡原本沒有「床」：新增床位清單（預設 15 床）、輪播內容的播放床位、平板所在的床
    資源 圖示（Lucide）與中文字型（Noto Sans TC 子集）全部自帶，不經任何院外網站

    迭代 14.1～14.5：實際操作後的修正與院方回饋（0928～0930）¶

    迭代 發現的問題 處理
    14.1 台北 00:00～08:00 總覽與床位圖停在前一天（後端的「今天」用的是 UTC） 改以主機時區的日界線
    14.1 每台平板要手打主機位址、序號、金鑰 註冊時畫出佈建 QR code，外殼 v0.3.0 可掃描；契約不必加版號
    14.1 模擬 MDM 重新啟動後鎖不了、解不開已納管的平板 啟動時把資料庫的納管狀態交回去
    14.2 簡易版新增病人的按鈕、右側清單最後一列被切掉 表單超出畫面就往上或往左長；每頁幾格依實際大小算
    14.2 誤下機之後病人排不回床上 當天的療程可以重新開啟（沿用同一筆，寫稽核）
    14.2 求助類別被切掉；「其他」那一框要能關 依畫面大小分頁；新開關預設關閉，只決定按鈕數量、不擋後端
    14.3 主機斷電或 Docker 自己更新、重新啟動時，護理端畫面看起來一切正常 專業版每一頁與簡易版都加上閃爍紅框＋紅底橫幅，分連線中斷／本機沒網路／登入失效
    14.3 病人端請求沒有逾時上限，主機斷電時求助按鈕看起來還能用 每個請求 8 秒逾時，最慢約 11 秒改成「請按床邊呼叫鈴」
    14.4 大量求助同時湧入時，專業版的求助橫幅疊得比畫面還高，蓋掉整個畫面 最多三條，其餘收成一列「還有幾則」；緊急的排前面，別處接起來的不再佔位置
    14.5 醫師說透析室很暗，病人端背景改成白底 白底、框與按鈕淺灰；語意色換成深色系，白底上仍過 7:1，紅色仍只給求助。連帶補兩處：夜間輪播要有自己的底色才調得暗、按下去改成變暗
    14.5 平板確定為 10 吋（Q-33 部分回覆） 10 吋平板全螢幕後 CSS 短邊都是 800，字級改以短邊縮放：直放不再每一級小一號（內文 20 → 24px），橫式不變

    同日另補：每份資料庫備份旁邊另存同名 .sha256——資料庫壞掉、服務起不來時，備份歷程查不到，還原要的雜湊從這個檔拿。

    待決事項¶

    本週取得的答覆：

    • Q-27：主機的 Docker 版本 0922 進院時已記下（Docker 29.3.1、Compose v5.1.1）；連接埠定為後端 13000、護理端 18080、病人端 18081
    • Q-32：主機對外連線是常態，沒有限制
    • Q-33（部分）：平板是 10 吋。型號、橫放或直放、系統顯示大小仍待回覆
    • 醫師：透析室很暗，病人端改白底（迭代 14.5 已做）

    要問資訊室的兩項 Docker Desktop 設定（清冊記為 Q-27 第 9、10 題。這台 Docker 同時在跑別的專案，兩項都是整台主機的設定，要資訊室同意才能改）：

    • Send usage statistics 能不能關？（0922 看到是開著的）不關的影響：Docker Desktop 會持續把它自己的使用情形送往 Docker 公司，服務執行期間主機就多一條常駐的院外連線。本系統的程式不經過這條線，但送出什麼由 Docker 公司決定、會隨版本改變，開發端無法逐項擔保；文件裡「服務執行時沒有任何一條線跨出醫院」（FR-S07、DEP-39）也要改寫成「有一條 Docker Desktop 自己的例外」
    • Microsoft Store 的自動更新能不能改成手動？ 這台的 Docker Desktop 是從市集裝的，更新由市集決定（F-16）；市集的設定管的是整台主機的所有 App。不改的話，Docker Desktop 可能在透析班中自己更新、重新啟動，容器全部中斷——護理端會跳斷線紅框、病人端約 11 秒後改成「請按床邊呼叫鈴」（迭代 14.3），新版也可能改變 compose 的行為

    不擋進院，但要在首波試用前有答案：

    • Q-33：目標平板的型號（尺寸 0930 已確定 10 吋）、橫放或直放、系統顯示大小有沒有統一調過——型號定了要在實機上重驗「整頁不捲動」
    • Q-34：透析室幾床、床號怎麼編、三個療程時段各從幾點到幾點（目前 15 床、暫以 12 點與 17 點分界）
