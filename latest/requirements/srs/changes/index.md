### 0.3 1005 異動摘要（院方 API 全面取代手動輸入）

1004 取得同院 IDH 預警系統正在用的院方透析清單 API 與那套系統的程式（《[同院 IDH 系統參考調查](https://94sh09sh19sh.github.io/hd-docs/latest/notes/idh-reference-survey/index.md)》）。1005 使用者據此指示四件事，**判準只有一句：能用 API 判斷的，就不要求護理師操作。**

| #   | 項次                                 | 0926                                                                                  | 1005                                                                                                                                                                                                     |
| --- | ------------------------------------ | ------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 病人、床位、療程開始與結束、臨床數值 | 全部由護理師在護理端操作或匯入；院方 API 只預定給輪播第三層的四種數值，介接程式暫不寫 | **院方 API 全面取代手動輸入**：病人主檔、床位、病人在哪一床、療程開始與下機、四種數值、問卷與衛教的時點，一律由 API 判斷；護理師只做 API 判斷不了的事（FR-S15、FR-S16）                                  |
| 2   | 病人端首頁中間那一區                 | 三層輪播（系統既有資訊／靜態衛教／院方臨床數值）                                      | **「本次透析」面板**，以同院 IDH 系統護理端病人詳細資訊的第一頁為藍本，**只留病人想看、適合看的**：血壓與脫水量畫成折線圖、脈搏與體重等以數字呈現，**全部跟著 API 即時更新**；其餘捨棄（FR-P09、FR-P11） |
| 3   | 衛教與中心公告                       | 輪播第二層；護理師手寫種類、標題、一句話、內文                                        | **改為面板底部的跑馬燈**，以「標題：內容」整則慢速跑過，不必點開；標題與內容由 AI 生成，**護理師只核准**；「一句話」欄位拿掉（FR-P10、FR-N17）                                                           |
| 4   | 第三次進院                           | —                                                                                     | 處理 1001 登不進去的原因，並把主機位址從名稱換成 IP（《[實作規格書](https://94sh09sh19sh.github.io/hd-docs/latest/requirements/implementation-spec/index.md)》4.19）                                     |

**需求總數由 70 條增為 73 條**：新增 FR-N17、FR-S15、FR-S16；改寫 FR-P09～P11、FR-P13～P15、FR-N15～N16、FR-S05、FR-S08。

**功能邊界的變動只有兩處**，都是縮減：病人端不再顯示抽血數值與 Kt/V（原輪播第三層）；病人端不再顯示「今日已回報內容」與「衛教完成度」（原輪播第一層）。**新增的能力全部來自院方 API，沒有任何一項碰到臨床判斷**——面板只呈現量測值，不畫警戒線、不做判讀（FR-P11 補充說明）。

### 0.4 1010 異動摘要（護理紀錄接上現有作業、院方對病人端的兩項意見、遊戲化）

1010 使用者帶回院方的答覆與意見，加上 1009～1010 的遊戲化決定（《[透析中的遊戲化之一](https://94sh09sh19sh.github.io/hd-docs/latest/notes/dialysis-gamification-decisions/index.md)》），一次改齊：

| #   | 項次             | 1007                                                                       | 1010                                                                                                                                                                                                                                                                                                    |
| --- | ---------------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 護理紀錄（Q-37） | 簽核後只存在本系統，不匯出、不列印、不寫入院方系統；護理端導覽收在「更多」 | **不寫入院方資料庫，以護理師複製貼上的方式交給院內的正式紀錄**；格式 **DART（預設）或 SOAP**，系統管理切換；**事件時間與相關病人數值寫在格式原有的段落文字裡**，不另立欄位，貼過去就一起帶過去；**AI 沒接或沒開照樣完整可用**；導覽移到主列（FR-N04、FR-N05 改寫，新增 FR-N18）                         |
| 2   | 病人端血壓折線圖 | 不畫正常範圍、不畫警戒線                                                   | 院方建議比照脫水量那張加虛線標出血壓正常區間。**判斷不合理，不做**：透析中的血壓沒有公認的正常區間，理由與出處見 FR-P11 補充說明「1010：血壓不畫正常區間」                                                                                                                                              |
| 3   | 緊急回報的圖示   | 部分圖示是抽象符號（閃電代表抽筋、波浪代表想吐）                           | **改成不看字也認得出症狀的圖示**（附錄 C.2，《介面設計基準》4.6）                                                                                                                                                                                                                                       |
| 4   | 遊戲化           | 只有分析，沒有需求條文                                                     | **納入**：平板現有功能的小幅遊戲化、病友小撇步、被聽見的回覆、透析小花園與送花、麻將連連看、老台灣記憶相簿；九個功能開關（只有「現有功能的小幅遊戲化」預設開啟）；新增社工、醫師兩個角色（新增 FR-P16～P19、FR-N19～N20、FR-S17；改寫 FR-P08～P09、FR-P13～P15、FR-N12、FR-N17、FR-S08、3.1、附錄 C.7） |

**需求總數由 73 條增為 81 條**：新增 FR-P16～P19、FR-N18～N20、FR-S17。

**功能邊界的變動**：第 1 項是把既有的護理記錄接上院內作業，不寫入院方任何系統；第 4 項全部是病人端低刺激的遊戲與護理端的選擇性回應，**沒有一項碰到臨床判讀**——遊戲不拿血壓、體重、脫水量計分，遊戲資料的彙整只陳述事實（FR-N20），比照附錄 C.7 的五條界線。
