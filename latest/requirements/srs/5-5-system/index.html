    FR-S20 語音處理：新服務語音閘道（compose 的 ai profile、不對外開埠），照 AI 閘道的寫法（設定檔、相依鎖版本、紀錄檔不寫內容）。錄音停了才整段處理：切句 → 辨識 → 詞庫比對 → 語氣與聲音事件（FR-S21）→ 經 AI 閘道挑句子、標出每一句是不是護理師對病人說的；按住說話（FR-P20）要在幾秒內出來，其餘目標是結案後 2 分鐘內。辨識端點在院內，送的是可識別的原音，不得送院外（FR-S04）。原音以 BLOB 存在資料庫、轉寫完不刪（1110 醫師），逐字稿不刪；逐字稿推估「護理師最後一句」之後超過 60 秒的音訊與逐字稿刪掉，不進留存。逐字稿送 AI 前遮掉病人姓名，AI 呼叫紀錄不存逐字稿。語音閘道或辨識端點不通時，FR-P20、FR-P21 的開關開不起來，求助本身完全不受影響 P2 無
    FR-S21 語氣、聲音事件與推估的到床邊只存不顯示：每一句的情緒、聲音事件（哭、咳嗽、喘）、音量語速停頓，以及逐字稿推估的護理師到床邊與離開時間，只存進資料庫，任何畫面都不顯示；不進護理紀錄與草稿，不用在派遣、分級與排序（FR-N03），不得用於任何個人考核，獎勵制度與儀表板都讀不到。驗證過（實作規格書 4.35 的門檻）才另案決定顯示；推估的到床邊要護理師點選才寫入 FR-N10 的到達時間，那一步不在這一條 P2 無（只存不顯示、不參與分級）

    FR-S11 的三種版位（0919）：每個功能在導覽上只會是下列三者之一，切換不需要重新部署。

    版位 意思
    主列 出現在護理端上方導覽列，每日必用
    選單 收在「更多」下拉選單裡，用得到但不是每天
    關閉 不出現在任何入口，且後端端點一併擋下，不是只把連結藏起來

    FR-S12 的四條硬性規則（0919）：完整規則見《部署規範》與《資料庫使用規範》，此處只列需求本身。

    1. 更新作業在備份未成功完成前不得繼續；備份必須是可還原的，不是複製出一個檔案就算數
    2. 遷移一律前滾：已套用過的遷移檔不得修改，要改就新增一個
    3. 正式環境不得執行任何「偵測到差異就重建資料庫」性質的指令
    4. 舊版本在新版穩定前不得刪除；資料庫已遷移時，回到舊版的方式是還原備份，不是把遷移倒回去

    FR-S15 對照表（1005）：護理師原本要做的事，哪些改由院方 API 判斷

    API 的欄位與格式見《同院 IDH 系統參考調查》第 2、3 節。

    原本護理師要做的 API 判斷得出來嗎 1005 起
    新增病人（病歷號、姓名、性別、生日） 能：第 0～3 欄 自動建立與更新。簡易版拿掉「新增病人」；1007 起專業版的「病人」那一頁也拿掉（迭代 17.6），護理端沒有任何新增病人的入口（沒接院方 API 的開發環境，簡易版仍留著它）。1007 迭代 17.7 補回備援：「護理師自己新增病人」功能開關，預設關閉，開了之後專業版排班與指派、簡易版病人框同時出現新增病人，關著兩邊都沒有（開發環境也一樣）；院方資料缺人時才開，之後院方資料出現同一個病歷號以院方為準
    建立當日排班（哪位病人、哪一班） 能：當天出現在 API 的病人就是當天要透析；哪一班由透析開始時間判斷（三班起訖待 Q-34，先用暫代值。1111 開會答：早 08:00～12:00、午 13:30～17:30、晚 18:00～22:00，暫代值分得對、迭代 32.1 照留；病人一週三次、班別固定但會臨時變動，照當天院方資料判斷就跟得上，不另存固定班表） 自動
    建床位清單 能：第 10 欄床位 自動：API 出現過的床號就是床位；護理長仍可停用某一床。全新環境不再預設 15 床
    把病人放到哪一床 能：第 10 欄 自動，每次抓取都跟著 API 更新；病人換床時，他的平板在床位圖上跟過去
    療程開始（把病人拖上床、平板開始這次療程） 一半：開始時間判斷得出來；哪一台平板判斷不出來 ~~護理師每位病人配一次平板，系統記住；之後 API 判定透析開始，就自動建立療程並綁定那台平板~~ 1006 起護理師每次透析把病人拖到一台平板上；療程、開始時間與床號由 API 決定（配平板早於 API 判定開始時，開始時間以 API 的為準）
    下機（解除指派） 能，但判定方式要第三次進院確認：預定以「結束體重出現」為準 自動；護理師仍可提前結束。過了預計結束時間很久仍判定不了的，床位格標示「待確認下機」，由護理師點一下。1007：預計結束一律是開始後 4 小時（院方硬性規定），不看 API 的預計結束時間。1111 開會：四小時照班別（例如早班一律 12:00）還是照個別病人的開始時間不確定（清冊 Q-34 第 4 題），答覆前照舊。1118 開會答照病人上機開始算，不改；~~下機是護理師手動還是機器自動待問~~ 1125 開會答：時間快到護理師去床邊協助病人下機，實際的下機時間由院方系統決定，與「結束體重出現」判定相同，不改（Q-34 第 5 題）
    輸入或匯入理想體重、目標脫水量、結束體重、實際脫水量 能：第 14、15、20、21 欄 自動。人工輸入與檔案匯入只留在專業版當備援（FR-S05）
    輸入抽血數值（血紅素、白蛋白、Kt/V、BUN） 不能：API 沒有 照舊，功能預設關閉（「需要抽血數值的功能」）
    透析前問卷、心情問卷、衛教的時點 能：透析開始與預計結束時間 自動（FR-P15）
    事件記錄「低血壓處置」範本的當下血壓 能：最近一筆紀錄的血壓 自動帶入最近一筆血壓與它的時間，護理師可改
    接求助、結案、護理記錄簽核 不能 照舊
    護理師排班與床位分配 不能：API 沒有護理師資料 照舊
    跑馬燈內容 不是 API 的事 AI 生成，護理師只核准（FR-N17）

    FR-S15 的三條界線：

    1. 自動不等於不能改。 護理師在專業版改過的東西（例如提前結束療程、手動換床），之後的同步不得改回去。同步只補護理師沒動過的地方。
    2. API 判斷不了就不猜。 例如~~平板正在別人的療程中、~~病人還沒配平板、床號是床位清單裡停用的那一床、目的床的平板正在服務別人——這些情況一律不自動處理，在床位格標示出來，等護理師處理。 1006 起平板與病人的配對一律由護理師做，系統不自動接上；護理師解除配對（換平板、配錯了）不算更正院方資料，第 1 條不適用。
    3. 只讀不寫。 本系統不回寫院方任何資料（HIS 雙向寫入照舊排除，第 1 章）。

    FR-S16 的資料範圍（1005）：API 每次回傳全中心當天到目前為止的全部紀錄。病人主檔與床位收全部（床位圖才會與現場一致）；每一筆生命徵象紀錄只收「這次療程有綁定平板」的病人——面板只需要他們的，其餘病人的紀錄留在院方。這不會讓剛配平板的病人少掉前面幾點：下一次抓取本來就回傳當天全部紀錄。原始回應整段不存檔，只記抓取時間、筆數、結果與內容雜湊。
