# 實作規格書 4.28 迭代 28：蒐集資料的完整取出（1026 新增）

上層文件：《[實作規格書](https://94sh09sh19sh.github.io/hd-docs/latest/requirements/implementation-spec/index.md)》第 4 章

> **1026 規劃，1027 完成**（驗收現況與開發端判斷在本節最後）。院方要求系統蒐集的資訊日後要全部取得出來，供後續計畫做資料分析與模型訓練；使用者 1026 定三個前提：現在就寫好取法、照文件手動做得完不靠任何模型、只能在院內主機上操作。規劃全文在《[蒐集資料的完整取出](https://94sh09sh19sh.github.io/hd-docs/latest/notes/data-extraction-plan/index.md)》，需求是 SRS FR-S19，資料治理是《資料庫使用規範》第 20 條，部署是 DEP-47。切三次子迭代，每一步可單獨驗（規劃第 10 節）。

**目標**：院內主機上一支只讀的取出指令，三種範圍、兩個等級都做得到；網路上沒有任何地方叫得動它；任何迭代加表、加欄沒登記就過不了檢查；不會寫程式、沒有 AI 的人照手冊也取得出來。

**驗收標準**：

1. `--all` 的表數等於 schema 的表數，每張表筆數與快照一致
1. `--category` 只出那幾類的表、`--tables` 只出那幾張、兩者合用是聯集；不給範圍、表名或類名打錯、`--all` 與其他合用都被擋，打錯時列出最接近的名稱
1. `--with-parents` 帶到上一層，上一層照樣假名化、照樣清空刻意不取的欄
1. 假名化輸出裡找不到任何直接識別欄的原值；自由文字欄預設不在；憑證欄是空的；`SHA256SUMS.txt` 對得上；假名化金鑰只在匯出目錄、不在輸出包
1. 從某一份備份取出、api 停著時取出都成功；匯出目錄設在專案目錄、網路磁碟或雲端同步資料夾被擋
1. 跑的時候沒有任何網路連線；`check:egress` 照舊全綠；後端沒有任何取出端點
1. schema 多一張表或一個欄位沒登記，`check:all` 不過
1. api 下次啟動後，取出紀錄出現在稽核軌跡與系統管理頁；頁面上沒有取出按鈕
1. 一位沒做過的人照《取出資料》、不用任何 AI，在開發機上完成一次部分取出與一次第二條路（直接開備份檔）
1. `verify:acceptance` 與全部回歸照樣通過

**外部依賴**：不擋實作，全部用合成資料驗收。對真實資料取出要院方的核准流程；完整級能不能離開主機、假名化級的自由文字、留存到期前要不要封存、匯出檔留多久、出院的去識別化誰做，都在 Q-39。

**新增** `check:export`（納入 `check:all`）、`verify:iteration28`（不需要後端）、`verify:iteration28:api`（要 Prisma、不需要後端，真的跑取出指令）；`check:container` 准許 `data-export` 掛資料卷與匯出目錄、`check:egress` 核對映像檔多帶的資料字典（《實作規格書之一》第二十四次）。

**開發端判斷**（實作時定，使用者要推翻時改這幾條）：①**取出紀錄寫到備份目錄的 `export-log.jsonl`，不是匯出目錄**——DEP-47 要 api 的主機目錄仍只有備份與設定兩個，api 讀不到匯出目錄；收過沒有看紀錄的識別碼（`run_id`），檔案本身不改。②`data-export` 掛資料卷是**可寫**的（WAL 模式的資料庫讀也要寫 `-shm`），只讀由指令保證：對正本只下一道 `VACUUM INTO`（`query_only` 底下它會被擋，所以排在最前面），其餘全部讀快照；另掛備份目錄（從備份取出、附加紀錄）。③假名化級除了直接識別欄，**值裡的識別碼（UUID 樣式）一律換成代號**——不換的話同一個 UUID 在兩次取出裡相同，「分兩次取的表接不起來」就做不到；對照表只記病人、護理師、平板的識別碼與直接識別的原值，其餘拿金鑰重算。④時間欄不逐欄標「準識別」（兩百多欄、兩級都照留、處理相同，標了反而淹掉真正要留意的），準識別只標生日、性別、連線位址、瀏覽器資訊，資料字典第三十一章寫明。⑤刻意不取的欄在 `data.sqlite` 若是唯一鍵，**唯一索引一併拿掉**（清成空字串會撞；開發機的資料 1027 實際撞到），清完 `VACUUM`，檔案裡翻不到原值；`manifest.json` 寫明。⑥`--level` 也一定要給（規劃只寫用途、核准文號、經手人），`--keep-free-text` 只給假名化級。⑦容器裡看不到 clone 目錄，「不在 clone 目錄」改看匯出目錄本身是不是一份 clone（有 `docker-compose.yml`、`.git`、`package.json`）；開發機照舊比對專案目錄。⑧CSV 加 UTF-8 BOM（試算表直接開才認得中文）、時間寫成 Asia/Taipei 加 `+08:00`、布林 1／0；`data.sqlite` 的時間照原樣（UTC 毫秒）。⑨系統管理多一個分頁「資料取出紀錄」，看得到的人與「資料庫與備份」相同（備份管理權限）；範圍寫類名與表的中文名稱，不寫表名（FR-S10）。⑩取出紀錄多記每張表筆數與 `SHA256SUMS.txt` 的雜湊（《資料庫使用規範》20.3），`export_runs` 23 欄。⑪compose 的 `HD_EXPORT_DIR` 是必填（與 `HD_SHELL_SRC_DIR` 同一種寫法）：沒填每一個 compose 指令都會停，1001 院內那一份 `.env` 換版前要補一行（《`.env` 怎麼填》第 6 節已寫）。

**驗收現況（1027）**：`npm run verify:iteration28:api` 八步全部通過（全新資料庫加合成資料，真的跑 --all 完整級、--category 假名化、--tables 加 --with-parents、聯集、十一種擋下來的情況、從備份取出與雜湊不符、打了 yes 之後失敗、後端收紀錄；對應驗收 1～5、8）；`npm run verify:iteration28` 八步全部通過（check:export 擋新表與新欄、compose 與 check:container、沒有取出端點與按鈕、取出指令沒有網路模組、check:egress、--help、手冊、介面檢查；對應驗收 6、7）；開發機的資料庫副本（97 張表、44853 筆）實跑一次完整級 --all 成功；`verify:acceptance` 通過；回歸見 1028 週報。**1028 補**（1027 開發後端占著資料庫、Docker 沒開，以下當時沒做）：開發機 `hd-dev.db` 套上 27.1、28 的遷移；分冊 `al20`～`al22` 在開發機走過（`--tables help_requests --with-parents` 假名化取出一次，重新啟動後端後資料取出紀錄多一列、表名是中文、沒有按鈕；稽核 `DATA_EXPORT_RECORDED` 一筆，等級、範圍、經手人、核准文號、用途都在；再重新啟動一次筆數不變）；`al17`～`al19` 在獨立的 compose 專案實跑（預設 `up` 沒有 `data-export`；容器裡 `--list` 列出 101 張表、`--category 病人自述` 假名化取出成功、輸出在 `HD_EXPORT_DIR`；`/proc/net/route` 只有表頭、網路介面只有 `lo`、`/keys` 不存在；容器版 api 重新啟動後收進一筆），測完容器、資料卷、映像檔都刪掉。第一次用真的後端截系統管理「資料取出紀錄」，結果、等級、核准文號、經手人在窄欄位折成兩行、末字落單，改成這四欄不折行（`SystemPage.tsx`，錯誤訊息照常折行）；`check:ui`、`check:ui:design`、`verify:iteration14`、`verify:iteration28` 重跑通過。**還沒做**：驗收 9（一位沒做過的人照《取出資料》、不用 AI 做一次部分取出與第二條路，分冊 `al23`、`al24`）。
