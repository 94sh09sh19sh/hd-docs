# 實作規格書 4.33 迭代 33：求助一點送出與倒數自動送出（1123 新增，1124 完成）

上層文件：《[實作規格書](https://94sh09sh19sh.github.io/hd-docs/latest/requirements/implementation-spec/index.md)》第 4 章

> 來源：《[緊急求助的語音說明](https://94sh09sh19sh.github.io/hd-docs/latest/notes/emergency-voice-help/index.md)》第 2 節與第 8 節第 1 階段；SRS FR-P06 改寫、附錄 C.2 加 `SX_UNSPECIFIED`、FR-M05 補（0.12 第 1 列）。**與錄音無關**，不必等院內 GPU 或同意登記。**1124 使用者開口，程式做完**（做法與驗收現況在本節最後；院內還沒換版）。

**實作時要確認的**：

- 現行病人端求助是幾步、急迫度在哪一步選（《之四》第 1 節 1026 對過的現況），開關關著時要完全照舊
- 「更新同一則」對 SSE、稽核、再發標示（FR-N11）、獎勵計分（以結案為準）的影響；更新類別要記稽核
- 平板全程無聲（FR-P13）；倒數圈不閃、不加聲音；樣子先登記進《介面設計基準》與 `hd-uiux`，紅色照舊只給求助區
- 求助區在遊戲畫面版位不變，倒數同樣適用
- 驗收：`verify:iteration33`（不需要後端：倒數秒數上下限、狀態機）與 `verify:iteration33:api`（送出、更新同一則、開了又關不算件數、開關關著照舊）；測試手冊分冊 `aq`，病人端照 1280×800 橫放截圖

**排在哪裡**：沒有相依，使用者開口就能做；做好進下一個 tag。上線後每月看「還沒選」的結案結果（SRS 補充說明 1123）。

**做法（1124）**：

- 狀態機在 `@hd/shared` 的 `help-countdown.ts`（純函式）：點類別、點急迫度、每秒看時間、按回首頁各回「送出／更新／開了又關／什麼都不做」，畫面只照它做；驗收腳本不開瀏覽器就能把每條路走一次。開關關著（秒數是 null）一律什麼都不做，畫面照迭代 14.2
- 「病人還沒選」是系統類別 `HELP_CATEGORY_UNSPECIFIED`（臨床組、緊急），**不進 `help_categories`**：病人看不到這一格、護理部改不到；標籤快照與儀表板的類別清單一律補上它，護理部用這個代號建類別擋下（`RESERVED_HELP_CATEGORY_CODES`）。**開關關著也照收**：平板可能還停在切換前的畫面，不為開關擋求助（同迭代 14.2「其他」那一框的做法）
- 開關「求助倒數自動送出」（`HELP_COUNTDOWN`，病人端畫面那一組，預設關、隨時可開）；營運參數「求助倒數秒數」（`HELP_COUNTDOWN_SECONDS`，8、5～15）。平板從首頁資料的 `behaviour.helpCountdownSeconds` 拿秒數，關著是 null；快取的舊資料沒有這一欄當成關著
- 病人端（第 1、2 列）：類別頁上方一圈＋一句「還沒選也沒關係，N 秒後會自動通知護理站」，圈一秒短一格（不轉、不閃、一般色）；點類別就送出（急迫度用分派表預設），換到「已經通知護理站」＋三顆急迫度，現在那一級框線加粗、圓點換成勾；倒數跑完送出「還沒選」，類別頁照留、上方換成「已經通知護理站」，之後點類別更新同一則。送出之後不回首頁；按 ‹ 回類別頁換一類也是更新同一則。「其他」補的說明按送出才更新。同一次開啟只用一個 `clientRequestId`：送出其實到了、回應沒回來時，重送拿回同一則、類別不同就接著更新。自動送出失敗不一直重送（畫面照舊叫病人按床邊呼叫鈴），病人點類別照樣可以手動送
- 後端：`POST /device/help-requests` 多收 `openedAt`、`categoryChosenAt`；新增 `PATCH /device/help-requests/:id`（改類別、急迫度、說明）與 `POST /device/help-requests/dismissed`（開了又關，回 204）。更新只改這台平板這次綁定、還沒結案也沒取消的（條件寫在同一個 UPDATE）；換類別沒帶急迫度用新類別的預設；分派重算；點類別的時間只記第一次；記稽核「病人在平板上改了求助的類別或急迫度」，推療程狀態讓護理端換字，**不再推一次新求助**（總覽螢幕以 id 判斷新通報，不重響）。已結案的回「護理師已經處理完這一則了，還要幫忙請再按一次『我需要協助』」
- `help_requests` 加三欄（遷移 `20261124120000_iteration33_help_countdown`，只做加法）：`opened_at`、`category_chosen_at`、`auto_raised`（自動送出的「還沒選」，之後點了類別照樣是 1）；匯出分類都是「一般」
- 第 3 列：開了又關只記稽核「病人開了求助畫面又關掉（沒有送出）」，寫開了幾秒；不建求助、不推護理端、不進任何件數。閒置自動回首頁不算（倒數比閒置門檻短，正常情況下已經送出）
- 第 5、6 列：護理端類別欄讀的就是 `categoryLabel`，「病人還沒選」由標籤快照給；專業版頂端橫幅在狀態推送時換成最新的類別與急迫度，緊急通報頁件數不變、內容變了也重拉；示警與床邊前速覽不動。結案照臨床組建求助處置草稿（`shouldAutoCreate` 看組別，不必改）。再發標示照最後的類別算；獎勵計分以結案為準，不受影響
- 第 7 列：工作量（FR-M05）多 `unspecified`，**開關開著才有**：每月一列——求助件數、還沒選幾則與比例、之後點了類別、結案結果的大類、以非臨床結案的比例、開啟到點類別的第 90 百分位與筆數；護理端工作量頁多一張「病人還沒選的有多少？結案時是什麼？（每月）」（百分比堆疊＋看表格，同圖 4 的配色），說明裡寫檢討門檻（15%、過半非臨床）
- 介面樣子登記進《介面設計基準》2.4 與 `hd-uiux`

**驗收現況（1124）**：`npm run verify:iteration33` 八步全部通過（秒數上下限與夾回；點類別送出、改急迫度與改類別更新同一則、病人點過的急迫度照留；倒數跑完送「還沒選」、離線與在路上不送、失敗不重送；開了又關只在倒數期間；系統類別與保留代號、開關預設關；畫面開關關著照舊、倒數圈沒有動畫與紅色、現在那一級形狀不同、新字在自帶字型裡；更新不重推新求助、開了又關不建求助、儀表板跟著開關、護理端換字；`check:ui`、`check:ui:design`、`check:export`、`check:egress`、`verify:iteration8`、`14`、`14-2` 照樣通過）。`npm run verify:iteration33:api` 八步全部通過（自己起後端、接假院方 API：開關關著照舊送出、首頁沒有秒數；開著帶秒數、改參數跟著換、4 與 16 擋下；「還沒選」緊急、照緊急分派、護理端寫「病人還沒選」；點類別同一則、件數不變、急迫度與分派跟著換、點類別的時間只記第一次、沒改到不記稽核；選回還沒選、保留代號擋下、病人端清單沒有它；開了又關只多一筆稽核；一直沒選的結案建了草稿、結案後病人改不到；儀表板比例、之後點了、結案大類、第 90 百分位，關著沒有這一欄）。`demo:patient` 上用無頭 Chrome 截 1280×800：倒數、點類別送出、改急迫度、倒數跑完、之後點類別、開關關著六張，都不捲動。`verify:iteration14-5`、`16`、`17-4`、`25`、`26`、`27`、`32-3` 照樣通過。院內要換版後才有；換版後開關照舊關著，護理部決定何時開。
