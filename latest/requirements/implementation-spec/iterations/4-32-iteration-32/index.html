    4.32 迭代 32：院方資料改讀檔——透析清單與檢驗資料（1110 新增）¶

    1110 規劃，1111 完成（使用者 1110：規劃一個小迭代、先寫文件不實作；透析清單與檢驗資料兩支一起；1111 實作。驗收現況與開發端判斷在本節最後）。1108 定案本系統不再打院方 API，改讀主機上抓取腳本存下的檔（3.5 的 1108 段落；《院方 API 之一》第 4、7 節）。腳本在私人 repo hd-hospital-fetch（透析清單 v0.1.0 起、檢驗資料 v0.2.0 起），留底檔與狀態檔的格式以它 README 的「契約」為準，本節是摘要。

    目標：院內的本系統只讀兩個資料夾——透析清單的月份檔、檢驗資料（hb）的月份檔——不再呼叫任何院方 API。透析清單讀出來寫進資料庫的，與直接打 API 時一模一樣；檢驗資料第一次有來源。

    為什麼是小迭代：透析清單的解析、驗證與同步（parseHospitalApiBody() 之後）全部照用，換的只是「拿到回應」那一步；檢驗資料是 ClinicalDataSourcePort 底下多一個來源，寫入走既有的 ClinicalDataImportService；需要抽血數值的功能照舊關著，不碰任何畫面的判斷。

    子迭代 工作項 對應
    32.1 設定與掛載 新設定：透析清單資料夾、檢驗資料資料夾，各自的狀態檔路徑預設跟著資料夾；與 HOSPITAL_API_BASE_URL 二選一，兩種都填拒絕啟動，都不填照現在的人工模式；compose 把兩個資料夾以唯讀繫結掛進 api，沒填時不掛；院內路徑有空白與中文，在 Docker Desktop＋WSL2 上實測；日誌與錯誤訊息只說「透析清單資料夾」「檢驗資料資料夾」，不印路徑 之一 7.1；DEP-37、DEP-46
    32.2 透析清單讀檔 取代 fetchDialysisList() 那一步：讀當月 YYYY-MM.txt，當天（+08:00）所有段落合起來，同一個鍵（病歷號＋透析開始時間＋紀錄時間，與腳本的 dedup_key_columns 相同）以後面的為準；segment、row 兩種寫法都認；從檔尾往回讀到當天第一段就停，不整個讀進記憶體（單月最大 1.28 GB）；檔尾沒換行的那一段當成寫到一半、不讀；段落之間的空行略過（舊檔每段 3 行，之二 K-3）；解析不出的段落略過並計數，不擋其他段（K-4）；合起來的清單照原樣交給 parseHospitalApiBody()／validateRows()／apply()；與上一輪內容雜湊相同就不寫入，抓取紀錄照寫 之三第 6 節；README 契約
    32.3 狀態與時效 讀腳本的 fetch-status.json：failed、skipped 的原因寫進抓取紀錄（腳本保證不含位址與欄位值）；資料多舊看 last_success_at、不看最後一段的 Date:，沿用「院方資料多久沒更新就示警」的營運參數；狀態檔不在或讀不出時照樣讀留底，紀錄寫「看不到抓取腳本的狀態」；午夜後當天還沒有段落、或新月份檔還沒建立，不算失敗 之一 7.4 第 6、10 項
    32.4 檢驗資料讀檔 ClinicalDataSourcePort 的第四個實作：讀 hospital_dataset/raw_txt/YYYY-MM.txt（一行一筆 {"FetchedAt", "record"}；不讀 CSV，CSV 丟了單位與定性結果）；同一位病人同一個 ExecuteDate 有多筆時取 FetchedAt 最後那筆；五種抽血數值照對照表（Hb→血紅素、ALBUMIN／ALB→白蛋白、Kt/V→Kt/V、本次透析前BUN→透析前 BUN、本次透析後BUN→透析後 BUN），對照表寫成設定、答覆來了不必改程式；值帶的單位與本系統不同，那一筆退回並寫原因；只有日期、沒有採檢時間，量測時間記成那一天（幾點實作時定）；對不到本系統病人的略過、只計數，不記病歷號；檔案大小與修改時間沒變就不重讀；讀檔頻率是新的營運參數（預設 30 分鐘，腳本 6 小時抓一次）；讀 hb-status.json，partial 照樣讀、原因寫進紀錄 《參考調查之一》第 4、8 節；FR-N07
    32.5 護理站、工具與模擬 「抓取頻率」改叫「讀檔頻率」（營運參數的鍵不改）；病人框的「重新整理」改成馬上重讀一次檔；抓取紀錄多記來源（API／檔）與腳本狀態，檢驗資料另有自己的讀檔紀錄；探測工具改成只讀檢查兩個資料夾、只印結構（《從零部署本系統》V-30a）；模擬院方 API 多一種模式：照契約把兩種留底檔與狀態檔寫進一個具名資料卷，並在資料夾放一個模擬標記檔，正式環境設定下讀到標記檔整次作廢（取代 DEP-46 原本靠回應標頭的那一層） 之一 7.1、7.4 第 4、5、7、8 項
    32.6 驗收與文件 verify:iteration32（不需要後端）、verify:iteration32:api（全新資料庫）；手動測試分冊 ap；下方「文件」那幾份的正式改寫 —

    2. 掛載唯讀：容器裡寫入那兩個資料夾一律失敗；本系統不搬、不刪、不改任何留底檔
