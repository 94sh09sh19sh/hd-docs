## 4.32 迭代 32：院方資料改讀檔——透析清單與檢驗資料（1110 新增）

> **1110 規劃，1111 完成**（使用者 1110：規劃一個小迭代、先寫文件不實作；透析清單與檢驗資料兩支一起；1111 實作。驗收現況與開發端判斷在本節最後）。1108 定案本系統不再打院方 API，改讀主機上抓取腳本存下的檔（3.5 的 1108 段落；《[院方 API 之一](https://94sh09sh19sh.github.io/hd-docs/latest/notes/hospital-api-fetch-methods-status/index.md)》第 4、7 節）。腳本在私人 repo `hd-hospital-fetch`（透析清單 v0.1.0 起、檢驗資料 v0.2.0 起），**留底檔與狀態檔的格式以它 README 的「契約」為準**，本節是摘要。

**目標**：院內的本系統只讀兩個資料夾——透析清單的月份檔、檢驗資料（`hb`）的月份檔——不再呼叫任何院方 API。透析清單讀出來寫進資料庫的，與直接打 API 時一模一樣；檢驗資料第一次有來源。

**為什麼是小迭代**：透析清單的解析、驗證與同步（`parseHospitalApiBody()` 之後）全部照用，換的只是「拿到回應」那一步；檢驗資料是 `ClinicalDataSourcePort` 底下多一個來源，寫入走既有的 `ClinicalDataImportService`；需要抽血數值的功能照舊關著，不碰任何畫面的判斷。

**驗收標準**：

1. 設定二選一：兩種都填拒絕啟動；只填資料夾時，程式完全不連院方
1. 掛載唯讀：容器裡寫入那兩個資料夾一律失敗；本系統不搬、不刪、不改任何留底檔
1. **同一份院方回應，直接打 API 與經過腳本寫檔再讀，寫進資料庫的病人、床位、療程、生命徵象完全相同**；`segment`、`row` 兩種寫法各驗一次，一天分多輪、逐列去重後的段落也一樣
1. 2 GB 的合成月份檔，讀當天的部分在數秒內完成、記憶體不隨檔案大小成長（門檻實作時量了再定）
1. 檔尾寫到一半、段落之間的空行、一段壞掉、不是 UTF-8、檔案不在：各有固定的處理與紀錄原因，不讓同步整個停下
1. 狀態檔 `failed` 時護理站看得到腳本寫的原因；`last_success_at` 超過示警分鐘數就示警；透析室一陣子沒有新量測、腳本照常成功時**不**誤報
1. 檢驗資料：五種數值照對照表寫進臨床數值、來源標示為院方檢驗；同一天改過的取最後一筆；單位不符與超出範圍的退回並寫原因；「需要抽血數值的功能」開關關著時，任何畫面都不出現
1. 正式環境設定下讀到模擬標記檔，整次作廢、一筆都不寫
1. 路徑、病歷號、欄位值不進日誌、抓取紀錄與稽核
1. 迭代 15 的 HTTP 抓取驗收照樣通過（HTTP 模式保留，院內不用）；`verify:acceptance` 與全部回歸照樣通過

- 其他用到這四個值的地方逐一看過：透析適足性自己擋 0 與負數；體重增幅的判斷規則只要理想體重大於 0（錯的理想體重會讓增幅百分比算得很怪，照院方的值算，不另外擋）；床邊速覽、病人端面板照原樣顯示；`baseline.service.ts` 用的是成效基準自己的範圍，與這四個值無關；護理記錄草擬不直接讀這四個值
- 病人端面板（1280×800 實際量）：數字格寬 220px。`74.6`、`746.0`、`-528.6` 這種 6 個字以內都放得下；7 個字（整數 4 位，例如 `5900.0`）剛好貼邊；8 個字以上（整數 5 位，例如目標脫水量 74600 公升被寫成 `74600.0`）超出格子約 10px、蓋到格間距，整頁照樣不捲動。要院方把體重或脫水量差到一千倍才會出現，**不改版面**；真的遇到再議

**驗收現況（1124）**：`npm run verify:iteration32-2` 五步全部通過（只擋負數與讀不懂的值、不再用常見範圍；四個值分開送；人工輸入與檔案匯入照舊照範圍擋、範圍本身沒改、院方檢驗不在範圍；讀到 0 照舊不建立、用到這四個值的地方；介面檢查、零院外連線，`verify:iteration32`、`32-1` 照樣通過）。`npm run verify:iteration32-2:api` 五步全部通過（接假的院方 API：目標脫水量 74.6 公升照寫；理想體重 250 kg、結束體重 15 kg、實際脫水量 9.5 公升照寫，負數的目標脫水量擋下、另外三個照寫；300 萬公升擋下〔讀不懂〕、另外三個照寫；被擋的一位一筆稽核、不寫值；病人端面板顯示 74.6、參考線照舊用設定脫水量；人工輸入 74600 mL 與 250.0 kg 照舊被擋）。`npm run verify:iteration32:api`（`VERIFY_BIG_MB=0`）照樣全部通過。**還沒做**：平板上實際看一次 74.6 的面板（分冊 `ap` 新增那一項）。
