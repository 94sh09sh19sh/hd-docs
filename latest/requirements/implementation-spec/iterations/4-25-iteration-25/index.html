    25.2 床邊前速覽¶

    工作項 對應
    院方 API 多讀幾欄：每一筆紀錄的血流速（第 40 欄）、透析液流速（41）、靜脈壓（42）、透析液溫度（47）加進 dialysis_vital_records；每次透析一個值的體溫（11）、輸液量（16）、食物重量（17）、透析器（27）、透析液 Ca（30）、傳導度（31）、血管通路（32）、Heparin（33）放在療程那一層（實作時定表，只做加法）。帶小數的換整數最小單位（規範 6.2），文字照原樣；收的範圍照舊只有這次療程有配平板的病人 FR-S16、規範第 13 章
    背景端點：一次帶齊這一次求助、上面那些院方值與本次透析每一筆量測、本次療程的透析前問卷、本次與前 3 次療程的求助（時間、類別、處理方式、結果）、待追蹤事項；權限「看病人」 FR-N03
    速覽元件（兩版共用）：版面照規畫文件第 3.4 節；兩張折線圖照第 3.5 節，沿用 trend-chart.tsx 的自畫 SVG、不引入圖表套件，按下求助的時間標一條直的虛線；不上色、不畫門檻、讀到 0 不顯示 FR-N03
    簡易版：紅框與格子上還沒人接的求助，點下去開速覽、不確認；速覽裡「我接手」才呼叫確認端點；已接手的格子點下去照舊展開處理方式，格子上多一個 id-card 開速覽 FR-N16（1015 改寫）
    專業版：緊急通報頁每一筆多一顆「病人簡介」開同一份速覽 FR-N14（第四個例外）

    驗收標準：

    1. 簡易版點紅框只開速覽，求助仍是待處理、紅框照閃；按「我接手」才變已接手，確認時間是按下那一刻
    2. 速覽在 1366×768 不捲動、不蓋住紅框列；Esc、點外面、×、按完我接手都關得掉
    3. 速覽上的每一個數值與院方資料（模擬院方 API）逐欄一致；讀到 0 的不出現；畫面上沒有預測機率、風險分層、高中低分級、塗色或正常範圍
    4. 兩張折線圖：點數與本次透析的紀錄筆數一致，求助時間的虛線在對的位置；線與線之間不只靠顏色區分
    5. 近期求助只到前 3 次療程；沒有院方資料、沒填問卷、沒有求助時各自寫一句，不留空白區塊
    6. 專業版「病人簡介」開出來的與簡易版同一份內容
    7. 稽核軌跡照舊；確認通報的稽核時間是按「我接手」的時間

    25.3 護理紀錄連動¶

    工作項 對應
    nursing_records 加「來源求助」欄（可空、唯一），記錄類型多「求助處置」；只做加法 FR-N04、N05
    結案（簡易版點處理方式、專業版結案登記）與建立草稿同一個交易：附錄 C.2 臨床組才建；非臨床組、病人自行取消、取消的不建；事件時間取按下求助的時間；段落照規畫文件第 4.4 節組，SOAP 的 A 段留空；到達時間沒有就不寫 FR-N10、N18
    結果補改（簡易版 8 秒內、事後補改）時，未簽核的草稿跟著重組；已簽核的不動 FR-N10、規範第 14 條
    護理紀錄頁：卡片標「來自 HH:MM 的求助」並連到那一則；「依求助建立」列出這次療程已結案但沒有記錄的求助；手動事件記錄的事件時間提示改成「請改成發生的時間」；草稿可以改套既有範本，事件時間與量測保留 FR-N04、N05

    驗收標準：

    1. 臨床組求助結案後，護理紀錄頁那次療程多一筆草稿，事件時間等於按下求助的時間；非臨床組、病人自行取消、取消的沒有
    2. D／S 段的量測是按下前最近一筆，R 段只有按下之後的；換 DART、SOAP 各走一次，A（SOAP）段是空的
    3. 同一則求助不會有兩筆；結案交易失敗時草稿也不存在
    4. 補改結果後未簽核的草稿跟著改，已簽核的一個字都沒變
    5. 文字裡沒有姓名、病歷號、病名；到達時間關著時沒有任何「到達」字樣
    6. AI 總開關關著時整條照樣走完；開著時 AI 潤飾不得新增勾選以外的事實

    三次都做完時的文件收尾：資料字典（新欄位、新記錄類型）、手動測試分冊 ai、API 路由表子文件、兩份進度報告、架構圖，照維護指南（docs/weekly/AGENT.md）迭代收尾那一條逐項對。

    沒有外部依賴。 多收的院方欄位在真實資料裡是什麼格式，要等第三次進院的探測（4.19）；在那之前照模擬院方 API 驗。
