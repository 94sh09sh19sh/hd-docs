# 尚待確認事項清冊 Q-09 輪播第三層臨床數值的來源與欄位

上層文件：《[尚待確認事項清冊](https://94sh09sh19sh.github.io/hd-docs/latest/requirements/open-questions/index.md)》第 4 章

**背景**

新增任務二的輪播分三層。第三層是院方提供的臨床數值（理想體重、目標脫水量、最近一次抽血結果、Kt/V）。

**0919 回覆**：院方確認那份病人臨床資料的 Excel **可以透過 API 取得**。`HospitalApiAdapter` 因此成為正式來源，`FileImportAdapter` 退為備援。**介面層當初先定好，今天換來源一行業務邏輯都不用改**——這是 `ClinicalDataSourcePort` 第一次被真的兌現。

**形態確定之後，剩下的問題換了一批**（見下方「具體要問的」第 3′～5′ 題）：欄位定義、認證方式、抓取頻率、失敗時怎麼重試而不重複寫入。

**不確認的後果**

輪播只能做第一、二層。這不影響功能上線，但少掉對病人最有價值的那一層。

**現況／暫代做法**

`ClinicalDataSourcePort` 介面層已定，三個實作（手動輸入、檔案匯入、院方 API）共用同一組內部資料表。無論最後走哪一條，輪播與病人端程式碼都不需要改動。

**0912 更新（迭代 6 完成）**：`FileImportAdapter` 已完成，Excel 與 CSV 都收得進來，而且**欄位名稱不寫死在程式裡**——對應設定在「臨床數值 → 匯入欄位對應」，一列一個欄位。上面第 3、4 題的答覆回來時，改的是那幾列設定；第 5～7 題（哪些數值適合給病人看、要不要附正常範圍、資料多舊就不該播）仍待護理部回覆，目前第三層播的是 SRS FR-P11 所列的五種數值，每一筆都標示資料時間。

**1004 線索（同院 IDH 系統程式，不是院方答覆）**

同院另一套系統每幾分鐘就呼叫院方一支透析清單 API。從它的程式讀出的內容（細節與欄位表見《[同院 IDH 系統參考調查](https://94sh09sh19sh.github.io/hd-docs/latest/notes/idh-reference-survey/index.md)》第 2～5 節；院內位址不寫進公開文件）：

| 原題                      | 讀到的線索                                                                                                                                                                                         |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1 存在哪個系統            | 院內一台 PHP 伺服器，`dialysislist.php`                                                                                                                                                            |
| 3′ 位址、認證、格式、欄位 | HTTP `GET ?date=YYYY-MM-DD`，**參考程式沒有帶任何認證**；回應是一段 `<meta>` 加 JSON `{"data_list": [[51 個值], …]}`，**沒有欄位名稱、只能靠位置**；一列是一筆生命徵象紀錄，透析層級的欄位每列重複 |
| 4′ 病人識別               | 第 0 欄是 8 碼病歷號，可直接對 `patients.medical_record_no`                                                                                                                                        |
| 5′ 頻率、主動或推送、重試 | 可主動查詢；每次回傳當天到目前為止的全部紀錄（不是增量）；參考系統約每 3 分鐘抓一次；速率限制從程式看不出來                                                                                        |

**五種數值裡只有兩種在這支 API 裡**：理想體重、目標脫水量（單位公升，是不含輸液與食物的淨減重）。**血紅素、白蛋白、Kt/V 都沒有**。理想體重有時沒填、回 0。因此上表新增第 8～11 題。

**1005 使用者決定**（使用者對《[同院 IDH 系統參考調查](https://94sh09sh19sh.github.io/hd-docs/latest/notes/idh-reference-survey/index.md)》第 9 節的回應）：

| 事項           | 決定                                                                                                                                                                                               |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 院方來源       | **直接用這支透析清單 API**。`HospitalApiAdapter` 暫不寫，寫的時候照該篇第 4 節                                                                                                                     |
| 用詞           | 本系統的數值名稱一律沿用 API 的稱呼：理想體重（即乾體重）、目標脫水量、結束體重、實際脫水量                                                                                                        |
| 讀到 0         | 該項不顯示。輪播第三層已照辦：數值是 0 的一律不播                                                                                                                                                  |
| API 沒有的數值 | 血紅素、白蛋白、Kt/V、透析前後 BUN **暫定拿不到**。用到它們的功能（輪播第三層的抽血數值與 Kt/V、透析適足性）收進新的功能開關「需要抽血數值的功能」，**預設關閉**；開啟條件是院方提供這些數值的來源 |
| 抓取頻率       | 預設每 3 分鐘，護理站可調（介接程式寫的時候一併做成營運參數）                                                                                                                                      |

介接程式寫好之前，輪播第三層照舊走檔案匯入與人工輸入。延伸出來要使用者再決定的事，列在該篇第 9 節。

**1005 新版需求**（SRS 0.3、實作規格書 0.5）：使用者指示**院方 API 全面取代手動輸入**，判準是「能用 API 判斷的，就不要求護理師操作」。對這一題的影響：

| 原題                            | 1005 起                                                                                                                                                                                                                               |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 「`HospitalApiAdapter` 暫不寫」 | **要寫**，排在迭代 15，而且不只寫數值：病人主檔、床位、療程開始與下機都由它驅動（SRS FR-S15）                                                                                                                                         |
| 5 哪些數值適合直接給病人看      | **開發端判斷**（使用者指示）：輪播第三層拿掉，改為「本次透析」面板；給病人看的是血壓與脫水量的折線圖，加脈搏、理想體重與透析前體重、目標脫水量；抽血數值不給。逐項取捨見 SRS FR-P09～P11 補充說明。**請護理部看過**，有異議就改那張表 |
| 6 要不要附正常範圍或白話解釋    | **不附**：病人端只呈現量測值，不畫正常範圍與警戒線（判讀屬高風險範疇）                                                                                                                                                                |
| 7 資料多舊就不該顯示            | 面板只顯示這一次透析的資料，舊資料的問題不存在；每一張圖、每個數字照舊標示資料時間                                                                                                                                                    |
| 9 透析進行中的列長什麼樣        | **更要緊了**：下機判定預定用「結束體重出現」，要親眼看一次透析進行中的回應才算數。第三次進院以探測工具看一次（實作規格書 4.19），工具只印結構、不印值                                                                                 |

**1108**：第 9 題改先問負責 IDH 系統的學長（醫師已授權 API 相關事宜由學長決定），連同「IDH 怎麼判斷下機」「有沒有跨午夜的透析」一起問，見《[院方 API 之二](https://94sh09sh19sh.github.io/hd-docs/latest/notes/hospital-api-fetch-methods-questions/index.md)》E-1～E-3；學長不知道的再問資訊室。第 11 題（抽血數值在哪）有了 `hb` 那支收集程式的線索，缺的檔什麼時候補問在之二 I 組。

**1118 開會醫師說明**：院方資料的數值有些是護理師填的；1116 那 3 次目標脫水量超過 8000 mL 就是護理師填錯（院方 API 之二 E-5）。醫師建議不要擋：平板顯示錯的值，病人看到也會提醒護理師更正。擋不擋是開發端自己判斷，見實作規格書 0.11 第 3 列。**1120 使用者定放行**（院方資料的四個值分開判斷、只擋負數與讀不懂的值），排成迭代 32.2（實作規格書 4.32.2），**1124 程式做完**，院內換版前照舊擋。

API 能不能被本系統呼叫、要不要報備，另立 [Q-35](https://94sh09sh19sh.github.io/hd-docs/latest/requirements/open-questions/q-35/index.md)。

**如果最後走 Excel，要一併提醒院方的風險**

欄位名稱與順序會被人手動改動、日期格式不一致、同一份檔案被重複上傳。開發端的對策是欄位對應可設定、格式驗證、重複偵測，以及**任何一筆解析失敗就擋下整批**——臨床數值只對一半，比完全沒有更危險。
