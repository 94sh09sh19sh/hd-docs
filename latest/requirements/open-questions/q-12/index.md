# 尚待確認事項清冊 Q-12 透析區 Wi-Fi 覆蓋與穩定度

上層文件：《[尚待確認事項清冊](https://94sh09sh19sh.github.io/hd-docs/latest/requirements/open-questions/index.md)》第 4 章

|            |                  |
| ---------- | ---------------- |
| **問誰**   | 資訊室           |
| **急迫度** | C                |
| **卡住**   | 離線韌性要做多強 |
| **狀態**   | 待提出           |

**背景**

SRS 第 10 章的假設之一是「透析中心具備穩定之院內 Wi-Fi 網路覆蓋」。這是假設，不是已確認的事實。若實際覆蓋不佳，離線暫存與重送的設計強度要提高，輪播的靜態內容也要更積極地預先快取。

**具體要問的**

1. 透析治療區目前的 Wi-Fi 覆蓋如何？有沒有已知的死角？
1. 15 台平板同時連線會不會有頻寬或連線數問題？
1. 網路設備的維護時段是什麼時候？會不會落在透析班次中？
1. 平板要走哪一個網段？與護理站工作站是否同網段？防火牆規則有沒有限制？
1. 開發端會記錄「離線暫存後補傳」的筆數當作網路穩定度指標，資訊室要不要一起看這個數字？

**現況／暫代做法**

已實作離線暫存（IndexedDB）與恢復連線後同步，求助功能離線時明確提示限制。實測資料出來後再決定要不要加強。
