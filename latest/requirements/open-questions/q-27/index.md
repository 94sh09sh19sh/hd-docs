**背景**

0922 現場確認主機上已有 Docker，也看到別的專案的容器與被佔用的連接埠。本系統要在上面以 `docker compose` 跑起來，資料庫放具名資料卷（DEP-23），只繫結掛載備份與設定兩個目錄（DEP-37）。**Docker Desktop 是隨使用者登入才啟動的程式**：沒有人登入，容器就不會起來。

**不確認的後果**

服務第一天跑得起來，第一次斷電之後就沒回來，而且沒有人知道——0922 現場已經看到主機電源不穩、無人看管（部署手冊第一次進院紀錄）。

**具體要問的**

1. 主機上 Docker 與 Compose 的版本？**能不能沿用而不升級**（別的專案也在用）？
1. Docker 的資料（WSL2 虛擬磁碟）在哪一顆磁碟？那顆磁碟本系統可以用多少空間、快滿時誰監看？
1. 本系統可以用哪幾個連接埠？登記之後能不能確保別的專案不佔用？防火牆要怎麼開，護理站電腦與透析區平板才連得進來？
1. **斷電重開之後誰登入？** Administrator 沒有密碼，能不能設定開機自動登入並讓 Docker Desktop 隨登入啟動？BIOS 能不能設成恢復供電後自動開機？ **1007 答覆：斷電後出現警示，護理長會重新登入**（見上方答覆表）
1. 備份目錄與設定目錄放哪一顆磁碟的哪個路徑？備份要送到院內哪一台機器（DEP-06）？
1. 防毒軟體是哪一套？**能不能把 Docker 的資料目錄加入排除清單**、誰能加？
1. 系統更新的重新啟動時段、自動休眠設定，誰管？被別的專案改掉時誰通知本專案？可以接受的部署與更新時段是什麼時候（要避開透析班次，DEP-32）？——**原 Q-29 第 6 題併入此處**
1. 0922 看到的磁碟規格與 i7-14700／2TB ×2 對不上，**是不是同一台**？
1. （0930 追加）Docker Desktop 的 **Send usage statistics** 能不能關？0922 看到是開著的。不關的影響：Docker Desktop 會持續把它自己的使用情形送往 Docker 公司，服務執行期間主機就多一條常駐的院外連線。本系統的程式不經過這條線，但送出什麼由 Docker 公司決定、會隨版本改變，開發端無法逐項擔保；「服務執行時沒有任何一條線跨出醫院」（FR-S07、DEP-39）也要改寫成「有一條 Docker Desktop 自己的例外」 **1007 答覆：第三次進院關閉**
1. （0930 追加）**Microsoft Store 的自動更新能不能改成手動？** 這台的 Docker Desktop 是從市集裝的，更新由市集決定（第一次進院紀錄 F-16）；市集的設定管的是整台主機的所有 App。不改的話，Docker Desktop 可能在透析班中自己更新、重新啟動，容器全部中斷，新版也可能改變 compose 的行為。這一題是第 7 題「系統更新誰管」落到 Docker 本身的那一半。**1007 答覆：先不改**，實際使用發現嚴重影響再改
1. （1001 追加）**主機上有沒有 Git？沒有的話誰裝？** 本系統對主機的要求只有 Git 與 Docker 兩樣（DEP-04）。這一題原本在部署手冊第一次進院之四 D-03 第 8 題，0926 改寫本題時沒有搬過來，1001 到了現場才發現主機沒有 Git、當場裝上。要問的是：1001 那次安裝要不要補走變更流程；日後 Git 的更新由誰管
1. （1001 追加）**護理站電腦與透析區平板，用哪個名稱或 IP 連這台主機？IP 能不能固定？** `.env` 的三個位址（`HD_PUBLIC_API_URL`、`CORS_ORIGINS`、`MDM_KIOSK_BASE_URL`）都寫這個值，平板的伺服器憑證也簽這個名字，**定了之後換掉要每一台平板重新佈建**。 1001 沒有書面答案，現場自己決定了一個值（1005 補記：是主機名稱）；護理端登入的 `Failed to fetch` 可能與此有關（部署手冊第二次進院紀錄 M-01、M-04）。答覆若是改用固定 IP，換法在部署手冊《護理站登不進去與主機位址之一》；平板還沒佈建，現在換代價最小。**1005 使用者決定：改用 IP**，第三次進院照《護理站登不進去與主機位址之一》換（實作規格書 4.19）。這一題因此只剩一半：**資訊室能不能把那個 IP 固定下來**（DHCP 保留或靜態）。不能固定就不要換。**1007 答覆：IP 是固定的**，第三次進院照換
1. （1001 追加）**院內 DNS 查 Docker Hub 的網域穩不穩？** 1001 Docker 三次查不到（`production.cloudfront.docker.com` 兩次、`auth.docker.io` 一次），重跑才過。日後每次更新都要從 Docker Hub 下載基底映像，這個問題會再出現；是院內 DNS 的問題就要請資訊室處理（與 Q-32 對外連線相關）

**0926 作廢的題目**：服務帳號、密碼保管與定期更換、資料目錄權限（DEP-12、原 DEP-37 第 4 項；院方決定能登入者一律可信任，DEP-38）。

**現況／暫代做法**

連接埠、目錄、映像檔標籤全部由主機的 `.env` 提供；答覆回來改的是設定，不是程式。磁碟下限沿用 `DB_DISK_MIN_FREE_MB`。
