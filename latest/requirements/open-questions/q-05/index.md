# 尚待確認事項清冊 Q-05 資料留存期限

上層文件：《[尚待確認事項清冊](https://94sh09sh19sh.github.io/hd-docs/latest/requirements/open-questions/index.md)》第 3 章

|            |                                                                                                                                |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------ |
| **問誰**   | 法務、資訊室                                                                                                                   |
| **急迫度** | B                                                                                                                              |
| **卡住**   | 刪除與封存機制（《[資料庫使用規範](https://94sh09sh19sh.github.io/hd-docs/latest/requirements/database-policy/index.md)》8.2） |
| **狀態**   | 待提出                                                                                                                         |

**背景**

系統會累積稽核軌跡、病人自報紀錄、AI 呼叫紀錄、績效彙整結果。**無限期堆積本身就是風險**：資料越久，外洩時的損害越大，而多數舊資料早已沒有使用價值。

**不確認的後果**

只能一直堆。且日後真要清理時，會面臨「這些能不能刪」的爭議，而那時資料量已經很大。

**具體要問的**

1. 依《醫療法》的病歷留存規定，本系統的病人自報症狀與求助紀錄算不算病歷的一部分？要留幾年？
1. 稽核軌跡要留多久？醫院既有系統的慣例是多少？
1. AI 呼叫紀錄（提示與輸出）開發端建議留 12 個月，之後只留統計列。可以嗎？
1. 護理師績效彙整結果依人資規定要留多久？
1. 到期後是刪除、還是轉為離線封存？封存放在哪裡（必須仍在院內）？
1. 病人如果要求刪除自己的資料，醫院的處理方式是什麼？本系統要提供什麼介面配合？

**現況／暫代做法**

《資料庫使用規範》8.2 已列建議期限，但明確標示為建議值。**期限未定案前，系統一律只做「標記」不做實際刪除。**
