## 摘要

- 1106～1107 使用者與負責 IDH 系統的學長在 LINE 上談院方 API；這一份整理學長說了什麼、還缺什麼、接下來怎麼做
- **介接方式要改**：學長要求本系統**不要自己打院方 API**，改成讀主機上腳本抓下來的檔；腳本照原本的 `.py` 存檔、存在 Drive 文件寫的位置，另一組（APP 組）也讀同一份
- 學長要的兩件事：①本系統改成直接讀資料的形式；②改寫 IDH 的 `fetch_API`，不靠 Django、固定時間抓、頻率可調；使用者先用每 3 分鐘
- 主機上有一套 IDH 系統＋抓取腳本，**IDH 系統沒在用**，腳本是舊版；歷史 txt 學長已搬到指定位置，「再來只需要處理腳本」
- 下次進院：**1109（一）15:30 左右**部署；使用者預估分兩次進院完成
- **1108 使用者補充兩件已確定的事**：①上週開會醫師明確表示 **API 相關事宜授權學長決定**（U-1 解決，A-02／Q-35 改問學長）；②學長說的「那台主機」就是本系統的部署主機——**現場三台中最右邊那台**，使用者與學長已有共識（U-3 解決）
- 沒答案的：`hb` 那支 API 的範例（1109 晚上程式補齊，端點仍是佔位字）、腳本由誰維護、留底的格式與編碼、資料夾會不會被 OneDrive 同步、要不要知會資訊室（第 3 節）；1108 當天要問學長的整理成《[之二](https://94sh09sh19sh.github.io/hd-docs/latest/notes/hospital-api-fetch-methods-questions/index.md)》

- 建議：**週一只讓獨立腳本跑起來，本系統先不碰**（改本系統要換版、整輪重做第十七冊）；讀檔模式排到第二次進院（第 4、8 節）

- **1108 深夜新腳本寫好**：私人 repo `hd-hospital-fetch` v0.1.0，第 6 節改連過去；週一的現場步驟看部署手冊第十九冊

## 5. 資料夾與個資

- 指定位置是某台電腦 `OneDrive\Old data\桌面\API_Fetch\` 底下（完整路徑不寫進公開文件）
- 留底 txt 是**院方回應的原文**：全中心當天所有病人的姓名、病歷號、生日、生命徵象，明文
- 若那台電腦的 OneDrive 有登入且在同步，這個資料夾的內容就會**離開醫院**；週一要先看同步狀態
- **1108 晚間**：那台電腦用的是醫師的帳號，OneDrive 也是醫師的；學長說資料調整要跟醫師確認。有在同步的話，搬位置或留在 OneDrive 都由醫師決定（之二 W-1），沒答覆前不開排程
- 誰讀得到這個資料夾（Windows 權限）、留多久、誰刪，都沒有規定；本系統的《資料庫使用規範》管不到本系統以外的檔
- 本系統讀檔時只讀、不搬、不刪；讀完的內容照舊只進本系統資料庫
- 《部署規範》DEP-46 寫「院方 API 的原始回應不落在任何主機目錄」，腳本的留底檔正好是原始回應落在主機目錄；1108 起這一條要限定為「本系統不寫」，留底檔歸腳本與學長管（DEP-46 的「1108 待改」）
