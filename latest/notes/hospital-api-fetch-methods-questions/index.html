    5. B. 原本的程式丟掉的列¶

    原本的三份 fetch_API.py 在轉 temp.csv 時會丟掉兩種列，留底 txt 是原始回應、沒有丟。1029 探測時 601 列裡有 172 列是床位以數字開頭的（9A 90 列、99 82 列）；本系統現在全部都收。B-1、B-3 已答。

    # 問題 為什麼要問
    B-2 病歷號不是純數字的列（程式註解寫「同一病人有兩個 ID」）是什麼情況？兩個 ID 要怎麼對回同一個人？ 本系統檢查病歷號用的是 [A-Za-z0-9-]{4,32}，帶英文字母的 ID 會通過；同一位病人可能因此被建成兩位
    B-4 IDH 資料庫因此少掉的那些列，要補回來嗎？ refetch_from_txt.py 從 txt 補資料時也會照樣丟。這題跟本系統無關，只是讓學長知道有這件事

    6. C. 新腳本和原本不一樣的地方¶

    學長說「跟原本的 .py 一樣的方式存下來」。下表列出原本（成大版）的做法跟開發端建議不一樣的、還沒答的每一處；C-0、C-5、C-9、C-10、C-11、C-14 已答。除了 C-16，其餘都已照建議做進 v0.1.0，學長沒有異議就不必回；要改的請回那一列的題號。

    # 哪一處 原本（成大版） 開發端建議（v0.1.0 已照做） 會影響誰
    C-1 什麼時候抓 有人開儀表板、而且分鐘數是 3 的倍數時 固定頻率（已定） —
    C-2 逾時與重試 都沒有 30 秒逾時、重試 3 次 不影響檔
    C-3 同時只跑一次 沒有 上一輪還沒跑完就跳過這一輪 不影響檔
    C-4 「今天」怎麼算 照機器的時間 固定 +08:00；主機本來就設 +08 的話結果一樣 不影響檔
    C-6 時間戳 Date: YYYY-MM-DD HH:MM:SS 一行 跟原本一樣 —
    C-7 去掉開頭的 <meta> 用 strip 逐字刪 從第一個 { 開始；現在的回應兩種做法結果一樣 不影響檔
    C-8 抓到空資料 照樣附加留底 照原本，讀檔的人才知道「有抓、只是沒資料」 本系統判斷資料多舊
    C-12 寫在哪 執行時的目前目錄 用設定檔指定 不影響檔
    C-13 主控台 印出整包回應（全中心的姓名、病歷號） 只印成功、筆數、失敗原因 個資
    C-15 端點 寫死在程式裡 寫在設定檔，斗六搬過來時只改設定 不影響檔
    C-16 單一病人 45 天的查詢（斗六版有 ?case_number=） 成大版沒有 不抓；學長要就加（這一列要回） APP 組

    7. D. 床位¶

    床位的來龍去脈在《第十八冊之二》第 3 節。D-1 原本是要問護理長的 A-07，學長從 IDH 那邊知道的話就先問學長，再請護理長確認。

    # 問題 為什麼要問
    D-1 1A～3D 是哪一區的床？99 是什麼情況會填（還沒排床、床邊透析，還是別的）？ 決定本系統要不要顯示這些床；99 不是一張床，一天大約 10 次透析、同一時間會有好幾位病人
    D-2 床位欄的格式以前改過嗎？成大版留著一行被註解掉的「床號反轉」，是當年格式改過嗎？ 本系統是用床號原樣比對；院方格式一改，床位就全部對不上
    D-3 IDH 床位圖上的 A1～E9（沒有 4）、I1、I2，是現在透析室全部的床嗎？ 本系統的床位清單要以哪一份為準
    D-4 透析做到一半換床時，API 的床位欄會跟著變嗎？ 本系統把床位欄的變化當成換床，平板會跟著病人換床
    D-5 除了 99，同一床同時有兩位病人的情況會出現嗎？ 本系統的設計是一床同時只有一位

    8. E. 欄位與透析的判定¶

    # 問題 為什麼要問
    E-1 51 個欄位有正式的定義嗎？IDH 程式裡的欄名是從哪裡來的？（清冊 Q-09 第 9 題，原本是問資訊室） 兩組血壓欄位是開發端自己判斷的：第 22～25 欄是開始與結束、第 36～37 欄是每一筆紀錄
    E-2 IDH 怎麼判斷一位病人下機了？ 本系統預定用「結束體重大於 0」；1029 探測時有 2 次是「有結束時間、沒有結束體重」
    E-3 有沒有跨過午夜的透析？過了 00:00，前一天開始的那一次還會出現在 ?date=今天 的回應裡嗎？ 不會出現的話，本系統就判斷不了它下機，床位格會一直停在「待確認下機」
    E-4 生命徵象多久量一筆？是機器自動上傳，還是護理師輸入？ 決定面板的折線多久多一個點，也決定腳本的頻率要多快才有意義

    9. F. 本系統讀檔需要腳本配合的地方¶

    F-1 已答。

    # 問題 為什麼要問
    F-2 護理端病人框的「重新整理」原本會讓本系統馬上打一次院方 API；改成讀檔之後只能重讀一次檔。要讓腳本能被叫起來馬上抓一次嗎（例如本系統放一個觸發檔、腳本每分鐘看一次）？還是接受「重新整理只是重讀檔」？ 要用觸發檔的話，本系統就需要一個可以寫的位置，跟「唯讀掛載」衝突，要另外開一個小資料夾
    F-3 護理站原本可以自己調抓取頻率；改成腳本之後由誰調、怎麼調？護理站還要能調嗎？頻率多高算「過高」？院方 API 有沒有呼叫頻率或速率的限制？（清冊 Q-35 第 4 題） 改成腳本之後，護理站能調的只剩本系統多久讀一次檔；兩邊都設 3 分鐘時，資料最久會晚約 6 分鐘才出現
    F-4 3 分鐘抓一次、整天附加，檔案會一直變大；可以只在透析時段抓，或內容沒變就不附加嗎？ 只在透析時段抓：時段結束後出現的結束體重會收不到，下機判斷不了。後一半「內容沒變就不附加」已由 W-5 的逐列去重答了，只剩「只在透析時段抓」
    F-5 第二次進院時，本系統要用唯讀的方式讀那個資料夾，可以嗎？ 讀檔模式的前提，先講好
