    院方 API 的四種抓取方式之二：1108 給學長的問題清單¶

    版本：v0.1　文件狀態：草案（2026-11-08 開立）　適用讀者：負責 IDH 系統的學長、使用者本人

    上層文件：《院方 API 的四種抓取方式》　前一份：《之一：1107 學長答覆後的現況與應對》

    摘要¶

    1108 晚間學長的答覆¶

    使用者 21:51 請學長其餘只答標「週一前」的，所以 A-4～A-6、B-2、B-4、C 組其餘、D、E、F-2～F-5、G-2、G-4、H、I 組都還沒答，第二次進院前再問。原文截圖在私人 repo 的 deploy/records/1108-hospital-api/。

    題 學長的答覆（摘要） 結論
    A 組 資料夾裡現在就是以前的 .txt；IDH 系統搬過去了但沒在運行，舊腳本也沒在運行；預定把檔存在這個資料夾 A-1：現在沒有別的程式在寫，不會兩支寫同一個檔；週一仍看一下工作排程器有沒有舊任務。A-2：新腳本寫進同一個資料夾、沿用 YYYY-MM.txt 檔名
    B 組 丟列的做法是 IDH 系統留下來的；能直接用 .txt 就好；腳本就是持續去抓，「發現有重複的資料就不放入」 B-1、B-3：新腳本不丟列，本系統照舊全收。C-0：就是 .txt；C-14：不寫 temp.csv。「重複的不放入」指什麼要再確認（W-5）
    C-5 可以改 UTF-8，但要把過去的資料一併轉譯 新腳本寫 UTF-8；歷史 txt 要轉碼，誰轉、何時轉見 W-4。A-3 歷史的編碼仍由週一現場量
    C-11 先不用加密，但保留功能以後用 留底明文；腳本保留加密開關、預設關。以後要開，本系統要先拿到金鑰
    F-1 可以嘗試狀態檔；以前失敗時只是寫空字串進去，沒有特別管控 腳本每輪寫狀態檔；失敗時留底不寫、不再寫空字串（C-9 照建議）
    G-1、G-3 都是用醫師的帳號；OneDrive 的資料調整可能要跟醫師確認 那台電腦登入的是醫師的帳號，指定資料夾在醫師的 OneDrive 底下，工作排程器也會用這個帳號跑。醫師授權學長的是 API 相關事宜，OneDrive 要不要同步、能不能搬，要醫師決定（W-1）

    週一進院前還要知道的¶

    # 問誰 問題 沒答案的話週一怎麼做
    W-1 醫師（誰去問：學長或使用者，要先講定） 醫師帳號的 OneDrive 有沒有在同步 API_Fetch 那個資料夾？有的話，是搬到不同步的位置（學長與 APP 組都要改路徑），還是醫師同意留在 OneDrive？ 現場先自己看同步狀態（第四冊有指令）。沒在同步：照常。有在同步而醫師還沒回：腳本放上去，但 --once 不跑、排程不開，不產生新的留底
    W-2 學長 醫師的帳號平常一直登入著嗎？主機重開後會自動登入嗎？ 排程設「只在使用者登入時執行」，不碰醫師的密碼；帳號登出或重開沒登入就停抓，狀態檔與本系統的過期示警看得到。要改成「不論是否登入都執行」得輸入醫師密碼，由學長或醫師自己輸入，不經開發端
    W-3 學長 主機上的 Python 是哪一版、誰裝的、可以用嗎？（G-3 後半，沒答） 現場看 python --version；沒有 Python 就停在放腳本之前（DEP-04：本系統不替主機裝 Python）
    W-4 學長 歷史 txt 轉 UTF-8 由誰轉、什麼時候轉？APP 組現在有沒有在讀舊的 txt（轉完它們要改用 UTF-8 讀）？ 現場先量編碼。當月 YYYY-MM.txt 還不存在：新腳本直接開 UTF-8 的新檔，舊月份另外排時間轉，不擋週一。當月檔已存在且不是 UTF-8：先備份原檔、轉這一個檔，再開始附加
    W-5 學長 「發現有重複的資料就不放入」是指 ①這次抓到的整包跟上一段一模一樣就不附加；②逐列比對、只附加新的或有變的列；還是 ③以前從 txt 匯進 IDH 資料庫時跳過重複？ ①：照做，狀態檔記每一次抓取的時間，本系統用狀態檔判斷資料多舊，F-4 的誤報顧慮就沒有了。②：留底就不再是原始回應，refetch_from_txt.py 與本系統的讀法都要改，不建議。③：照原本每輪整段附加。沒答覆的話，去重做成設定開關、預設關（跟原本一樣）

    A. 同一個資料夾有誰在寫、誰在讀¶

    # 問題 為什麼要問
    A-1 週一前：主機上舊的成大版腳本與 IDH 系統，新腳本上線後要停用、移除，還是留著？有沒有人還會開 IDH 的儀表板？ 成大版只要有人開儀表板就會抓、附加到 YYYY-MM.txt。如果它的輸出位置也改到指定資料夾，兩支會寫同一個檔：同一分鐘出現兩段、兩邊同時附加時行會交錯、編碼可能不一樣，本系統與 APP 組都會讀到壞掉的段落
    A-2 週一前：新腳本要接著寫已經搬過去的那幾個月份檔（同樣是 YYYY-MM.txt），還是從新的檔名或子資料夾開始？ 接著寫的話，同一個檔裡前後的格式與編碼必須完全一樣；另外開的話，refetch_from_txt.py 要讀兩個地方
    A-3 週一前：已經搬過去的歷史 txt 是哪一版腳本寫的？知道是什麼編碼嗎？ API_script 版的留底把時間戳與 JSON 寫在同一行，refetch_from_txt.py 讀不回來；編碼不一樣，接著寫的檔就會混著兩種編碼。週一也會在現場量
    A-4 APP 組怎麼讀：多久讀一次、用什麼程式讀、讀的時候會不會一直開著檔、會不會把讀過的檔搬走或刪掉？ Windows 上只要有人用獨占的方式開著檔，腳本那一次附加就會失敗，那一次的資料就丟了；有人搬走檔，本系統就讀不到
    A-5 hb_online_v2.py 如果也排上，它的輸出是 Hb_API_Fetch，跟透析清單完全分開嗎？兩支共用一份設定、一個排程嗎？ 決定兩支腳本放在哪、會不會互相影響
    A-6 之後要改格式（換編碼、加欄位、改檔名）時，由誰決定？要先通知誰？ 學長、APP 組、本系統三方讀同一份檔，任何一方改了，另外兩方就會壞

    B. 原本的程式丟掉的列¶

    原本的三份 fetch_API.py 在轉 temp.csv 時會丟掉兩種列，留底 txt 是原始回應、沒有丟。1029 探測時 601 列裡有 172 列是床位以數字開頭的（9A 90 列、99 82 列）；本系統現在全部都收。

    # 問題 為什麼要問
    B-1 IDH 丟掉床位以數字開頭的列，是刻意的嗎？為什麼要丟？ 如果那些是別的單位、或本來就不該看的病人，本系統也應該不收；如果只是 IDH 當年不需要，本系統就照收
    B-2 病歷號不是純數字的列（程式註解寫「同一病人有兩個 ID」）是什麼情況？兩個 ID 要怎麼對回同一個人？ 本系統檢查病歷號用的是 [A-Za-z0-9-]{4,32}，帶英文字母的 ID 會通過；同一位病人可能因此被建成兩位
    B-3 新腳本如果要寫 temp.csv，還要照原本丟這兩種列嗎？ 只影響 APP 組；本系統讀的是留底，不受影響
    B-4 IDH 資料庫因此少掉的那些列，要補回來嗎？ refetch_from_txt.py 從 txt 補資料時也會照樣丟。這題跟本系統無關，只是讓學長知道有這件事

    C. 新腳本和原本不一樣的地方：哪些可以改¶

    學長說「跟原本的 .py 一樣的方式存下來」。下表列出原本（成大版）的做法跟開發端建議不一樣的每一處。「不影響檔」的，開發端直接照建議做，列出來只是讓學長知道；其他的請學長逐列回「照建議」或「照原本」。

    # 哪一處 原本（成大版） 開發端建議 會影響誰
    C-0 週一前：「跟原本一樣」指的是哪一份 — 成大版的 YYYY-MM.txt，一次抓取寫兩行（Date: 一行、JSON 一行） 所有讀的人
    C-1 什麼時候抓 有人開儀表板、而且分鐘數是 3 的倍數時 固定頻率（已定） —
    C-2 逾時與重試 都沒有 30 秒逾時、重試 3 次 不影響檔
    C-3 同時只跑一次 沒有 上一輪還沒跑完就跳過這一輪 不影響檔
    C-4 「今天」怎麼算 照機器的時間 固定 +08:00；主機本來就設 +08 的話結果一樣 不影響檔
    C-5 週一前：寫檔的編碼 沒有指定（繁中 Windows 會用 cp950，姓名有罕用字時那一次整個丟失） 明確指定，跟歷史 txt 一樣；歷史是 cp950 的話，要不要從下一個月份起改成 UTF-8 所有讀的人
    C-6 時間戳 Date: YYYY-MM-DD HH:MM:SS 一行 跟原本一樣 —
    C-7 去掉開頭的 <meta> 用 strip 逐字刪 從第一個 { 開始；現在的回應兩種做法結果一樣 不影響檔
    C-8 抓到空資料 照樣附加留底 照原本，讀檔的人才知道「有抓、只是沒資料」 本系統判斷資料多舊
    C-9 抓取失敗 丟例外、寫 log 留底什麼都不寫，另外寫狀態檔（F-1） 本系統
    C-10 每次都附加當天全部的列 是 照原本；或改成只在透析時段抓、內容沒變就不附加（F-4） 檔的大小、本系統判斷資料多舊
    C-11 週一前：加密 成大版沒有；斗六版把 temp.csv 的病歷號與姓名加密 留底不要加密：本系統要用明文病歷號對病人主檔；一定要加密的話，本系統就要拿到金鑰 本系統
    C-12 寫在哪 執行時的目前目錄 用設定檔指定 不影響檔
    C-13 主控台 印出整包回應（全中心的姓名、病歷號） 只印成功、筆數、失敗原因 個資
    C-14 temp.csv 會寫 不寫，除非 APP 組要 APP 組
    C-15 端點 寫死在程式裡 寫在設定檔，斗六搬過來時只改設定 不影響檔
    C-16 單一病人 45 天的查詢（斗六版有 ?case_number=） 成大版沒有 不抓；學長要就加 APP 組

    D. 床位¶

    床位的來龍去脈在《第十八冊之二》第 3 節。D-1 原本是要問護理長的 A-07，學長從 IDH 那邊知道的話就先問學長，再請護理長確認。

    # 問題 為什麼要問
    D-1 1A～3D 是哪一區的床？99 是什麼情況會填（還沒排床、床邊透析，還是別的）？ 決定本系統要不要顯示這些床；99 不是一張床，一天大約 10 次透析、同一時間會有好幾位病人
    D-2 床位欄的格式以前改過嗎？成大版留著一行被註解掉的「床號反轉」，是當年格式改過嗎？ 本系統是用床號原樣比對；院方格式一改，床位就全部對不上
    D-3 IDH 床位圖上的 A1～E9（沒有 4）、I1、I2，是現在透析室全部的床嗎？ 本系統的床位清單要以哪一份為準
    D-4 透析做到一半換床時，API 的床位欄會跟著變嗎？ 本系統把床位欄的變化當成換床，平板會跟著病人換床
    D-5 除了 99，同一床同時有兩位病人的情況會出現嗎？ 本系統的設計是一床同時只有一位

    E. 欄位與透析的判定¶

    # 問題 為什麼要問
    E-1 51 個欄位有正式的定義嗎？IDH 程式裡的欄名是從哪裡來的？（清冊 Q-09 第 9 題，原本是問資訊室） 兩組血壓欄位是開發端自己判斷的：第 22～25 欄是開始與結束、第 36～37 欄是每一筆紀錄
    E-2 IDH 怎麼判斷一位病人下機了？ 本系統預定用「結束體重大於 0」；1029 探測時有 2 次是「有結束時間、沒有結束體重」
    E-3 有沒有跨過午夜的透析？過了 00:00，前一天開始的那一次還會出現在 ?date=今天 的回應裡嗎？ 不會出現的話，本系統就判斷不了它下機，床位格會一直停在「待確認下機」
    E-4 生命徵象多久量一筆？是機器自動上傳，還是護理師輸入？ 決定面板的折線多久多一個點，也決定腳本的頻率要多快才有意義

    F. 本系統讀檔需要腳本配合的地方¶

    # 問題 為什麼要問
    F-1 週一前（寫腳本時就要定）：腳本每跑完一輪，可以再寫一個很小的狀態檔嗎？內容是最後一次嘗試的時間、成功或失敗、失敗原因、筆數，不放病人資料 留底只記成功的那幾次。沒有狀態檔，本系統分不出是院方 API 掛了、腳本沒跑，還是寫檔失敗，護理端只能顯示「院方資料已 N 分鐘未更新」
    F-2 護理端病人框的「重新整理」原本會讓本系統馬上打一次院方 API；改成讀檔之後只能重讀一次檔。要讓腳本能被叫起來馬上抓一次嗎（例如本系統放一個觸發檔、腳本每分鐘看一次）？還是接受「重新整理只是重讀檔」？ 要用觸發檔的話，本系統就需要一個可以寫的位置，跟「唯讀掛載」衝突，要另外開一個小資料夾
    F-3 護理站原本可以自己調抓取頻率；改成腳本之後由誰調、怎麼調？護理站還要能調嗎？頻率多高算「過高」？院方 API 有沒有呼叫頻率或速率的限制？（清冊 Q-35 第 4 題） 改成腳本之後，護理站能調的只剩本系統多久讀一次檔；兩邊都設 3 分鐘時，資料最久會晚約 6 分鐘才出現
    F-4 3 分鐘抓一次、整天附加，檔案會一直變大；可以只在透析時段抓，或內容沒變就不附加嗎？ 只在透析時段抓：時段結束後出現的結束體重會收不到，下機判斷不了。內容沒變就不附加：Date: 會變成「最後一次有變化」的時間，透析室一陣子沒量測，本系統就會誤報「未更新」。兩種都會改到「跟原本一樣」
    F-5 第二次進院時，本系統要用唯讀的方式讀那個資料夾，可以嗎？ 讀檔模式的前提，先講好

    G. 存放、執行與維護¶

    # 問題 為什麼要問
    G-1 週一前：指定資料夾在 OneDrive 底下，那台電腦的 OneDrive 有在同步嗎？有的話，可以換到不同步的位置嗎？ 留底是全中心病人的姓名、病歷號明文，一同步就離開醫院了；有在同步的話，週一停在放腳本之前。另外，OneDrive「只在線上」的檔，容器是讀不到的
    G-2 新腳本放在主機的哪個資料夾？之後由誰維護、出錯了找誰？ 腳本不進本系統的 repo，要有一個負責的人
    G-3 週一前：用工作排程器跑的話，用哪個 Windows 帳號？那個帳號登出後還會跑嗎？主機重新開機後會自己起來嗎？主機上的 Python 是哪一版、誰裝的？ 本系統的部署規範不准要求主機裝 Python（DEP-04），所以腳本的執行環境歸學長管
    G-4 留底檔要留多久、誰負責刪、誰讀得到（Windows 權限）？ 本系統的《資料庫使用規範》管不到本系統以外的檔

    H. 報備與改版¶

    # 問題 為什麼要問
    H-1 腳本呼叫院方 API、存成檔，本系統與 APP 組讀檔：要不要另外知會資訊室？存檔的位置與留存期限要不要院方核可？ 醫師已授權學長決定，這一題由學長定（清冊 Q-35）
    H-2 院方 API 改版或停機時，會有人通知嗎？通知誰？ 改版了沒人知道的話，病人、床位、療程會全部停在最後一次成功的樣子

    I. 另一支 API（hb）¶

    1106 學長說 hb 的 API 資料也可以放進來考量，會傳 .json 的例子；到 1108 為止還沒收到。光有 .json 不夠：hb_online_v2.py 真正做事的部分在缺少的 collector_common.py 裡，見《參考調查之一》第 4、9 節。

    # 問題 為什麼要問
    I-1 collector_common.py 什麼時候能補？ 端點、參數、回應怎麼解析都在這支裡面；少了它，hb_online_v2.py 跑不起來，也看不出它抓的是什麼
    I-2 config.json（位址可以先遮掉）與 active_patients.txt 的範本什麼時候能補？病人清單是誰維護的？ 決定要查哪些病人；本系統可以直接用透析清單帶進來的病歷號，不必再另外維護一份
    I-3 能給一份遮罩過的回應嗎（數字與中文換成佔位字元）？裡面有血紅素、白蛋白、BUN 嗎？單位與採檢時間呢？ 決定本系統關著的「需要抽血數值的功能」（透析適足性、抽血數值趨勢）有沒有機會開啟
    I-4 這是另一支端點，還是同一支 dialysislist.php 換成「查一位病人一段期間」的查法？ 如果是同一支，拿回來的還是 51 欄，不會有抽血數值
    I-5 這支是誰寫的？現在有在跑嗎？資料給誰用？V1 和 V2 差在哪？ 從 hospital_dataset/ 這個名字看，比較像研究用的資料集；要知道會不會跟本系統搶同一份資料
    I-6 要週一一起排程嗎？多久抓一次？ 抽血大多是一個月一次，每 6 小時查一次（它設定裡的預設）就夠了
    I-7 Word 檔寫的那台電腦，OneDrive 裡整個 Hb_API_Fetch 資料夾可以拿到嗎？ 這是最快把 I-1～I-3 一次拿齊的方法
