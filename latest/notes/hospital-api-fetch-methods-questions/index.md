## B. 原本的程式丟掉的列

原本的三份 `fetch_API.py` 在轉 `temp.csv` 時會丟掉兩種列，留底 txt 是原始回應、沒有丟。1029 探測時 601 列裡有 172 列是床位以數字開頭的（`9A` 90 列、`99` 82 列）；本系統現在全部都收。

| #   | 問題                                                                                            | 為什麼要問                                                                                        |
| --- | ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| B-1 | IDH 丟掉床位以數字開頭的列，是刻意的嗎？為什麼要丟？                                            | 如果那些是別的單位、或本來就不該看的病人，本系統也應該不收；如果只是 IDH 當年不需要，本系統就照收 |
| B-2 | 病歷號不是純數字的列（程式註解寫「同一病人有兩個 ID」）是什麼情況？兩個 ID 要怎麼對回同一個人？ | 本系統檢查病歷號用的是 `[A-Za-z0-9-]{4,32}`，帶英文字母的 ID 會通過；同一位病人可能因此被建成兩位 |
| B-3 | 新腳本如果要寫 `temp.csv`，還要照原本丟這兩種列嗎？                                             | 只影響 APP 組；本系統讀的是留底，不受影響                                                         |
| B-4 | IDH 資料庫因此少掉的那些列，要補回來嗎？                                                        | `refetch_from_txt.py` 從 txt 補資料時也會照樣丟。這題跟本系統無關，只是讓學長知道有這件事         |

| ---- | ------------------------------------------------ | ----------------------------------------------------------------- | ------------------------------------------------------------------------------------ | ---------------------------- |
| C-0  | **週一前**：「跟原本一樣」指的是哪一份           | —                                                                 | 成大版的 `YYYY-MM.txt`，一次抓取寫兩行（`Date:` 一行、JSON 一行）                    | 所有讀的人                   |
| C-1  | 什麼時候抓                                       | 有人開儀表板、而且分鐘數是 3 的倍數時                             | 固定頻率（已定）                                                                     | —                            |
| C-2  | 逾時與重試                                       | 都沒有                                                            | 30 秒逾時、重試 3 次                                                                 | 不影響檔                     |

| C-4  | 「今天」怎麼算                                   | 照機器的時間                                                      | 固定 +08:00；主機本來就設 +08 的話結果一樣                                           | 不影響檔                     |

## I. 另一支 API（`hb`）

| #   | 問題                                                                                               | 為什麼要問                                                                                     |
| --- | -------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| I-1 | `collector_common.py` 什麼時候能補？                                                               | 端點、參數、回應怎麼解析都在這支裡面；少了它，`hb_online_v2.py` 跑不起來，也看不出它抓的是什麼 |

| I-5 | 這支是誰寫的？現在有在跑嗎？資料給誰用？V1 和 V2 差在哪？                                          | 從 `hospital_dataset/` 這個名字看，比較像研究用的資料集；要知道會不會跟本系統搶同一份資料      |
| I-6 | 要週一一起排程嗎？多久抓一次？                                                                     | 抽血大多是一個月一次，每 6 小時查一次（它設定裡的預設）就夠了                                  |
| I-7 | Word 檔寫的那台電腦，OneDrive 裡整個 `Hb_API_Fetch` 資料夾可以拿到嗎？                             | 這是最快把 I-1～I-3 一次拿齊的方法                                                             |
