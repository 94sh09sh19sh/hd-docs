    介面設計基準：兩個族群，兩套設計¶

    版本：v0.1　文件狀態：草案　適用讀者：FDE 工程團隊、護理部、任何要動到介面的人

    0. 本文件的定位¶

    本文件不是需求文件，是一份設計基準：它規定「這套系統的介面長什麼樣、為什麼長這樣、下一次改的時候要遵守什麼」。

    • 功能需求來源是《軟體需求規格書》，介面相關的硬性要求在第 6 章非功能性需求與 FR-P13、FR-S10、FR-S11
    • 與需求文件衝突時，以需求文件為準
    • 待確認事項指回《尚待確認事項清冊》，本文件不另立清單

    這份文件不是一次性的改版說明。 使用者於 2026-09-19 指示：介面重新設計之後，日後所有介面工作都要依這份基準做。因此它寫的是可重複套用的規則，不是這一次改了哪幾個畫面。

    給 AI agent：對應的可執行版本在專案的 .claude/skills/hd-uiux/。動任何介面程式碼前先讀那一份；本文件是它的理由書與人類可讀版。兩者若有出入，以本文件為準並回報 skill 已過時。

    0.1 0926 方向變更：極簡¶

    使用者於 2026-09-26 指示介面完全重新設計，四條依序套用（SRS 第 6 章「可用性（極簡）」）：

    # 規則 在這份基準裡落在哪
    M-1 能用圖示就不要用文字 4.6 圖示表：每個圖示登記一次意思
    M-2 能用框線與顏色區隔功能，就不要用文字，也不要把不同功能混在一起 4.7 狀態色與形狀；2.4、3.5 的分區
    M-3 不影響功能的字全部刪掉 判準：刪掉之後使用者還能不能完成那個動作。法規要求的標示不得刪
    M-4 頁面能不上下捲動就不捲動 內容多時改分頁，不改捲動；4.10 目標解析度

    適用範圍：病人端全部畫面、護理端簡易版。護理端專業版維持 0919 版面，第 3.3 節的導覽列規則只適用於它。

    這四條與 0919 的原則怎麼相處：0919 的族群分析（第 1～3 章）一條都沒有被推翻——病人還是躺著、一隻手在打針， 護理師還是被切碎的時間。極簡是在同一群人身上再往前推一步：字級、對比、觸控目標的下限不動， 改的是「畫面上放什麼」。兩者衝突時，下限贏——不能為了不捲動把字縮到 20px 以下，要改分頁。

    1. 為什麼要先分析族群¶

    上一版介面的問題不是「不好看」，是沒有預設的使用者。兩端共用同一套版面假設：一樣的字級邏輯、一樣的卡片密度、一樣的資訊層級。但這兩群人的使用情境幾乎沒有一處相同：

    病人端 護理端
    姿勢 躺著，視線斜向上 站著或半坐，視線平視
    手 常常只有一隻手能動（另一隻在打針） 兩隻手，但常拿著東西
    時間 四小時，非常多 被切碎，每次幾十秒
    注意力 低，可能想睡、不舒服 高但被分散，同時盯多床
    動機 打發時間、身體不舒服時求救 完成手上的事，不漏掉任何一床
    熟悉度 每週三次，但多半不熟數位介面 每天用，會變得很熟
    犯錯的代價 按錯 → 護理師白跑一趟 看漏 → 病人沒有被處理

    同一套版面同時服務這兩群人，只會兩邊都做不好。 下面兩節分別描述它們。

    2. 族群一：透析病人（病人端平板）¶

    2.1 這群人的事實¶

    台灣血液透析族群的組成有幾項結構性事實，它們直接決定介面怎麼做：

    事實 對介面的意思
    年齡偏高，多數為中老年 老花是常態。字級不是偏好問題，是能不能看到的問題
    糖尿病腎病變是最大宗病因 糖尿病視網膜病變常見，對比度與色彩辨識能力可能下降。不得用顏色作為唯一的資訊載體
    每週固定三次、每次四小時 這個介面他們會看幾百次。一個小小的煩人之處會被放大幾百倍
    治療中一隻手固定不能動 所有操作必須單手可完成，而且是在畫面的下半部
    躺著，平板多半架在床邊支架上 視距約 40～70 公分，角度傾斜。畫面上半部反光最嚴重
    可能虛弱、想睡、注意力低 任何需要「讀完一段話才知道怎麼做」的設計都會失敗
    不舒服的時候才最需要它 求助這條路徑必須在最糟的狀態下也走得通

    2.2 六條設計原則¶

    # 原則 具體規則
    P-1 求助永遠在同一個地方，而且永遠在下半部 固定版位，任何畫面、任何狀態（1005 起含跑馬燈正在跑、沒有跑），位置與尺寸一律相同
    P-2 一個畫面一件事 0926 起首頁只有三區：基本資訊、~~輪播內容~~ 本次透析（1005）、緊急回報（見 2.4、2.5）。問卷與衛教不再是首頁的按鈕，改由療程時點帶出來。不要因為「還有空間」就多放東西
    P-3 字要大到躺著看得清楚 內文最小 20px，數值與按鈕文字更大；行高寬鬆
    P-4 顏色不是唯一線索 每一個用顏色區分的狀態都要同時有文字或圖形
    P-5 不要有需要精準的操作 觸控目標最小 64×64px，彼此間距至少 12px；沒有長按、沒有滑動手勢、沒有雙擊
    P-6 不確定的時候，說人話 不寫「已提交」寫「護理師收到了」；不寫「同步中」寫「正在送出」

    0920 調整（迭代 9.1）：首頁的動作由三個增為四個，加上求助區共五個目標。 新增的是「看今天的資訊」——輪播原本只有「靜置到門檻」一個入口，病人想主動看就沒有辦法， 而病人端不得有長按、滑動、雙擊（P-5），能做的入口只剩一顆看得見的按鈕。 同一次調整把首頁的求助狀態由最多六列收成一列，首頁在平板上因此不必捲動就看得完。 理由與完整清單見《迭代 9.1 修正清單》第 2.4、2.5 節。

    0926 再調整（迭代 14）：四個動作全部拿掉。「看今天的資訊」不需要了——輪播本來就在首頁上播； 問卷、衛教、心情改由療程時點帶出來（FR-P15），首頁只剩三區（FR-P14）。

    2.3 這一次修掉的具體問題：緊急按鈕蓋住輪播的字¶

    症狀：閒置輪播開始後，求助按鈕蓋住輪播卡片的文字。

    原因不是「按鈕太大」。 原本的做法是：輪播是一個覆蓋整個畫面的圖層，而求助按鈕在底下那個首頁版面的正常文件流裡，輪播開始時把它的堆疊層級抬高，讓它浮到輪播之上。

    這個做法有兩個問題：

    1. 按鈕的位置由首頁版面決定，不是由畫面決定。 它是首頁四個按鈕中的第二個，實際落在哪裡取決於上面有多少內容、螢幕多高。輪播那一層只能「猜」它在下半部，然後把卡片往上推——猜錯就蓋住。
    2. 「位置固定」被實作成「層級固定」。 FR-P13 要的是版位固定，兩者不是同一件事。

    修法：把求助按鈕從版面裡拿出來，做成整個應用程式共用的固定底部區域。

    ┌─────────────────────────┐
│                         │
│   內容區                 │  ← 首頁、問卷、衛教、輪播都畫在這裡
│   （輪播卡片也在這裡）     │     這一區的高度 = 畫面高度 − 求助區高度
│                         │
├─────────────────────────┤
│   ★ 我需要協助           │  ← 固定區。永遠在這裡，永遠一樣大
└─────────────────────────┘     內容區永遠畫不到這裡

    三個要點：

    • 求助區是版面的一部分，不是浮在上面的東西。 內容區的可用高度先扣掉它，因此「蓋住」在結構上不可能發生
    • 輪播卡片的高度以內容區為基準計算，不是以整個畫面為基準
    • 非輪播時求助區也在，位置與尺寸完全相同——這才是 FR-P13 所說的「位置固定」

    驗收方式：在輪播進行中截圖，量求助區的位置與尺寸；退出輪播再截一次。兩張圖上那塊區域必須一模一樣，而且輪播卡片的任何一個字都不得落在那塊區域裡。

    2.4 0926 起的病人端版面：首頁三區、任務依時點出現¶

    3. 族群二：透析室護理師（護理端）¶

    3.1 這群人的事實¶

    事實 對介面的意思
    忙，而且是被打斷的那種忙 每次看畫面只有幾十秒。要能一眼看出「現在有沒有事」
    同時負責多床 總覽的密度要高，但重要的東西要跳出來
    站著或走動中操作 目標不能太小；但不像病人端那麼極端
    每天用同一套介面 會變熟。熟了之後最在意的是「要點幾下」
    首波只有護理站的一兩台電腦 螢幕不小，但不是隨身的。需要走回護理站才能操作
    漏看一則通報的代價很高 通知不能只靠一個數字角標

    最重要的一條：護理師不是「使用者」，是在工作中順便用這個工具的人。介面每多一個步驟、每多一個要讀的字，都是從照顧病人的時間裡扣掉的。

    3.2 六條設計原則¶

    # 原則 具體規則
    N-1 一眼看出有沒有事 進畫面 2 秒內要能回答「現在需要我嗎」。待處理通報要用顏色＋數字＋位置三重強調
    N-2 每天用到的才放在主列 導覽列只放每日必用；其餘收進選單或關閉（FR-S11）
    N-3 順序照工作流程，不照功能分類 交班 → 指派 → 盯著 → 處理 → 收工。不是「病人相關／裝置相關／設定相關」
    N-4 不要讓護理師讀系統的內部用語 狀態一律中文，開關一律中文名稱（FR-S10）
    N-5 破壞性動作要有阻力，日常動作不要有 解除綁定要確認；標記已讀不要確認
    N-6 關掉的功能就是不存在 不放灰色按鈕、不放「敬請期待」（DEP-34）

    3.5.2 1006 起：把病人拖到平板；停用移到系統管理（迭代 17.1）¶

    使用者 2026-10-06 指示（《迭代 17.1 修正紀錄》）：

    • 配平板＝把病人拖到一台平板上。床位與病人已經由院方資料配好，護理師只需要配對平板與病人；床號由院方資料自動補上—— 配好之後後端把平板放到那位病人的床，護理師不必再把平板拖上床。每次透析都配：病人頁「配給的平板」（配一次、之後自動接上）拿掉， 院方資料同步也不再自己接上平板
    • 沒接院方資料的環境也一樣是「病人拖到平板」（使用者選的，不保留舊流程）：平板已經在某一床，病人就在那一床； 平板在平板框裡，配好之後格子上寫病人的名字，接著把平板拖上床。「＋」新增病人也是拖到平板上

    4. 共用的設計系統¶

    兩端各有各的版面，但底層的語彙要一致——同一個顏色在兩邊代表同一件事，否則維護的人會混亂。

    4.1 顏色¶

    只有四種語意色，而且每一種都必須搭配文字或圖形（P-4）：

    語意 用在哪 搭配
    一般 預設狀態、可點擊的東西 —
    注意 待處理、進行中 文字標籤
    警示 緊急通報、勞動條件違反、斷線 文字標籤＋圖形
    完成 已處理、成功 文字標籤

    求助按鈕用警示色，而且只有它用。 病人端畫面上不得有第二個紅色的東西，否則它就不再是「那顆紅色的」。

    兩端都必須通過對比度檢查：內文對背景至少 4.5:1，大字與圖形至少 3:1。病人端因為糖尿病視網膜病變常見，目標值提高到內文 7:1。

    病人端是白底（0930，迭代 14.5）：醫師說透析室很暗，病人端背景改成白底，框與按鈕是白底上的淺灰。 白底上要過 7:1，四種語意色都是同色相的深色系（深青、深褐、深紅、深綠）；疊在語意色上的字是白色。 紅色仍只給求助——求助區是深紅底白字，注意色是深褐而不是紅。 夜裡不另做一套深色主題，夜裡靠夜間模式調暗（4.5）。護理端維持原本的配色，常駐總覽螢幕仍是深色。

    折線圖的線不是語意色（1005，迭代 16）：「本次透析」面板的線一律用 --c-chart-line（深靛藍），參考線用框線灰 --c-line。 四種語意色都各有意思，拿來畫量測值就等於替數值下評語（2.5）。check:ui:design 會擋：圖的顏色與任何一種語意色相同、偏紅， 或面板、圖、跑馬燈的樣式與元件引用了語意色。 0919～0929 病人端是深色底，改版的理由與色碼對照見《迭代 14.5 修正紀錄》2.1。

    • 病人端不做任何會自己動的裝飾。 ~~閒置輪播的換卡是功能~~ 1005 起跑馬燈是病人端唯一會自己動的東西，它是功能，不是裝飾（2.5）；除此之外不要有呼吸燈、不要有位移動畫。 跑馬燈以程式控制的線性移動（Web Animations）實作，樣式表裡仍然沒有 @keyframes；開了「減少動態效果」時跑馬燈整條不出現

    直式 800 × 1280 同上
    護理站 1366 × 768 與 1920 × 1080 簡易版~~床位圖~~（1007 起中間是平板）不出現捲軸

    5. 這份基準怎麼被持續使用¶

    這是最重要的一節，因為一次性的改版三個月後就會被稀釋回去。

    時機 要做什麼
    動任何介面程式碼之前 讀 .claude/skills/hd-uiux/（本文件的可執行版）
    新增一個畫面或元件 對照第 4 章的設計系統；找不到對應的語彙就先在這裡補一條，不要就地發明
    改動導覽列 對照 3.3 的三條規則；主列超過 7 項要說明理由
    提交前 跑介面檢查腳本（技術識別字串、對比度、觸控目標尺寸）
    每次迭代結束 用瀏覽器自動化在兩種畫面尺寸下截圖，人工看一遍

    允許使用外部設計知識庫與前端視覺工具（使用者 2026-09-19 授權），但有兩條界線：

    1. 不得引入任何指向院外網域的執行期相依——字型、圖示、樣式表、分析工具一律自帶（FR-S07、零院外連線盤點會擋）
    2. 外部設計系統只當參考，實際採用的語彙一律落在第 4 章，不直接把整套元件庫搬進來

    6. 驗收清單¶

    介面改動要能逐條回答，不能只說「看起來比較好了」。

    • 求助區在所有畫面、所有狀態下的位置與尺寸完全相同
    • ~~輪播進行中~~ 跑馬燈正在跑時（1005），沒有任何一個字落在求助區裡
    • 內文字級 ≥ 20px，~~輪播主文~~ 跑馬燈 ≥ 40px，圖上的最新值 ≥ 36px
    • （1005）面板與跑馬燈沒有紅色、沒有警戒線、沒有正常範圍、沒有 Y 軸刻度；圖的線不是任何一種語意色
    • （1005）每一張圖、每一個數字都標了資料時間；讀到 0 的不出現；一筆都沒有時圖留著框
    • （1005）跑馬燈一次一則、整則跑完，碰它不跳出任何東西；沒有內容、夜間、減少動態效果時整條不出現
    • 所有可點擊目標 ≥ 64×64px，間距 ≥ 12px
    • 沒有長按、滑動、雙擊

    • （0926）首頁與每一個任務畫面在 4.10 的兩個尺寸下都沒有捲軸；（0930）兩個方向的字一樣大

    • 關閉的功能完全不出現入口，後端端點也擋下
    • 破壞性動作有確認，日常動作沒有
    • 內文對比度 ≥ 4.5:1
    • （0926）每次登入預設簡易版，一次點選切到專業版；專業版的畫面沒有被改動
    • （0926）簡易版的九項任務每一項都是一個動作，都有不拖曳的替代做法，都能一步復原（「接緊急通報」除外，理由見 3.5）

    兩個刻意的決定，寫下來免得日後被當成疏漏：

    1. 斷線時的紅框仍然持續閃爍（常駐總覽螢幕；0929 起護理端每一個畫面），雖然 4.4 說「不得持續閃爍到令人疲勞」。 那一條講的是新通報的進場強調——那種東西閃久了會被學會忽略。斷線不是通報， 是一個持續存在的故障狀態：它一直在，示警就應該一直在。畫面上另有一條「連線中斷」的橫幅， 顏色不是唯一線索；開了「減少動態效果」時閃爍會停，紅框仍然留著。
    2. 病人端未指派時沒有求助區。 平板還沒指派給任何人，求助送出去護理站不知道是誰按的。 那個畫面改成直接寫「需要護理人員時，請按床邊的呼叫鈴」—— 一顆按了會失敗的按鈕，比沒有按鈕更糟。
