### 3.1 抓取腳本的規格

**只用 Python 標準函式庫**（`urllib`、`json`、`hashlib`），不需要 `pip install`，主機上有 Python 3.8 以上就能跑。

| 事           | 做法                                                                                                                                                                                                                                                                                     |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 執行         | `--once` 跑一輪就結束，交給工作排程器每 3 分鐘叫一次；另有 `--config <路徑>`（預設是腳本旁的 `config.json`）、`--dry-run`（只印會寫幾列，不寫任何檔，連狀態檔都不寫）；結束碼 0 成功或跳過、1 失敗、2 設定錯誤                                                                           |
| 設定檔       | `config.json`：端點、輸出資料夾、狀態檔路徑、去重狀態資料夾、逾時、重試次數、`encrypt`（預設 `false`）、`dedup`（預設 `"row"`）、`dedup_key_columns`（預設 `[0, 6, 8]`）、`line_format`；相對路徑以設定檔所在資料夾為準；不認得的欄位拒絕啟動；預設不走系統 Proxy（院內位址不該繞出去）  |
| 抓什麼       | `?date=今天`，「今天」固定以 +08:00 算                                                                                                                                                                                                                                                   |
| 逾時與重試   | 30 秒、3 次                                                                                                                                                                                                                                                                              |
| 同時只跑一次 | 鎖檔；上一輪還沒結束就跳過這一輪，狀態檔記「跳過」                                                                                                                                                                                                                                       |
| 去 `<meta>`  | 從第一個 `{` 開始解析；解析不出 `data_list` 就算失敗                                                                                                                                                                                                                                     |
| 逐列去重     | 每一列算一個鍵＝病歷號＋透析開始時間＋紀錄時間，存「鍵 → 整列內容的雜湊」；鍵沒看過或內容變了才寫。同一個鍵在一次回應裡有多列時整組一起比；欄數不夠的列以整列內容當鍵（不丟）。狀態存在 `state/YYYY-MM-DD.json`，**只存雜湊，鍵加每台主機一份的隨機值再雜湊，不存病歷號明文**；保留 3 天 |
| 寫什麼       | 這一輪有要寫的列：附加 `Date: YYYY-MM-DD HH:MM:SS` 一行＋`{"data_list":[只有新的或變了的列]}` 一行；沒有就不寫。兩行組成一個字串一次寫入、`flush`。當月檔不是 UTF-8 就不附加、算失敗；檔尾缺換行先補                                                                                     |
| 編碼         | UTF-8，換行固定 `\n`                                                                                                                                                                                                                                                                     |
| 失敗時       | 留底不寫；狀態檔寫失敗原因；結束碼非零                                                                                                                                                                                                                                                   |
| 狀態檔       | 每輪覆寫：最後一次嘗試的時間、結果（`ok`／`failed`／`skipped`）、失敗原因、回應列數、寫入列數、當月檔名、最後一次成功的時間；不放病人資料。先寫暫存檔再改名，讀的人不會讀到一半。欄位逐一列在 README「契約」                                                                             |
| 主控台       | 只印時間、結果、列數；不印網址、不印回應                                                                                                                                                                                                                                                 |
| 加密         | 保留斗六版加密病歷號與姓名的寫法，`encrypt: false` 時不執行；金鑰不進 repo                                                                                                                                                                                                               |
| 不做的       | 不寫 `temp.csv`、不丟任何列、不碰 IDH 的資料庫                                                                                                                                                                                                                                           |
| 排程         | `install-task.ps1`：用目前登入的帳號建工作，「只在使用者登入時執行」、每 3 分鐘、上一個還在跑就不再開新的、單輪超過 10 分鐘就停；用 `pythonw.exe` 或 `fetch_dialysis_w.exe`，不會每 3 分鐘跳視窗；`uninstall-task.ps1` 移除。頻率是參數（`-IntervalMinutes 5 -Force`），之後學長自己改   |

**留底格式要學長在現場點頭（之二 W-6）**：上面的寫法保留「`Date:` 一行＋JSON 一行」，`refetch_from_txt.py` 照樣讀得回來，差別是 JSON 裡只有新的或變了的列。學長說的「逐行寫入」如果是指一列寫一行，現場把設定 `line_format` 改成 `"row"`：`Date:` 一行後每列一行 `{"data_list":[一列]}`，兩種讀法都讀得回來，兩種都先寫好。

**契約**（v0 讀檔模式依這個做）：留底檔與狀態檔的格式、讀的人怎麼把當天各段合起來，完整寫在私人 repo `hd-hospital-fetch` 的 README「契約」一節；本節是摘要，兩邊衝突以 README 為準，改契約時兩邊一起改。

### 3.2 轉碼工具的規格

| 事     | 做法                                                                                                                                                                                                           |
| ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 預設   | 預演：列出每個檔的大小、行數、`Date:` 段數、判斷出的編碼（先試 UTF-8，不行再試 cp950，都不行列出第一個出錯的行號），不改任何檔                                                                                 |
| 實轉   | `--apply`：先把整個資料夾的 txt 複製到 `_backup_YYYYMMDD-HHMM\`（複製完逐檔比對雜湊），再逐檔轉成 UTF-8；已經是 UTF-8 的跳過。每個檔先寫成暫存檔，比對全過才換掉原檔，比對不合的原檔不動                       |
| 比對   | 轉完每個檔的內容要逐字相同、行數與 `Date:` 段數要與原檔相同，每一行 JSON 要解析得出來（`API_script` 版的混寫行另外列出，不算失敗）；原檔就有解析不出的行時不轉、列出行號，學長同意才加 `--allow-bad-json` 照轉 |
| 還原   | `--restore <備份資料夾>`                                                                                                                                                                                       |
| 不做的 | 不刪備份、不改檔名、不改換行（CRLF 照原樣）；混到兩種編碼的檔不轉，列出來由學長決定；主控台不印任何一行的內容                                                                                                  |
| 結束碼 | 0 全部處理完、1 有檔沒轉（混合、無法判斷、比對不合）、2 參數或資料夾不對；報告存在備份資料夾的 `transcode-report.txt`                                                                                          |
