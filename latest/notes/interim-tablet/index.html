    暫用平板：Galaxy Tab S6 Lite（SM-P613）¶

    版本：v0.1　文件狀態：草案（2026-10-25 開立）　適用讀者：FDE 工程團隊、進院部署的人

    摘要¶

    • 醫院採購的 15 台平板還沒到，醫師先給一台舊平板：Galaxy Tab S6 Lite（2022 年版，Wi-Fi，SM-P613）。在使用者更新這份文件之前，正式使用只有這一台。
    • 結論：跑得了。外殼 App（minSdk 21、targetSdk 34）、螢幕固定、感應式橫向、院內自簽 CA 都沒有障礙（第 2 節）。
    • 畫面：面板 2000×1200（5:3），外殼全螢幕後預估 CSS 1333×800。短邊 800 不變，字級與觸控目標照舊；寬度比 1280 多約 53px，介面設計基準 4.10 早已列為「5:3 的面板約 1334×800」（第 2.2 節）。
    • 要在實機上確認四件事：WebView 版本 ≥ 105、實際 CSS 尺寸、顯示大小與字型大小是預設、平板沒有被院方的裝置管理鎖住側載（第 3 節）。
    • 這台的系統停在 2023 年 10 月的安全修補；院內封閉網路、只跑本系統，風險低。進院前在院外網路更新一次 WebView 與 Chrome，進院後就凍結（第 4 節）。
    • 只有一台的影響：同時只服務一床、沒有備品，壞了病人端就停；護理端不受影響（第 5 節）。

    0. 本文件的定位¶

    不是需求文件，是一份裝置紀錄與可行性判斷。2026-10-25 使用者轉達：

    醫院買的 15 台平板還沒來，醫生說先用一台舊的。在我更新資訊前，正式使用都是只有這一台平板。

    • 效力：部署、佈建、實機驗收、截圖，一律以這台為準，直到使用者更新本文件。
    • 15 台到貨後：改寫本文件（或另開一份），同時回頭改 Q-33 與 Q-11。

    2. 跑不跑得了：逐項對照¶

    需求 出處 這台 判斷
    外殼 App 能安裝 外殼 minSdk = 21、targetSdk = 34 Android 13（API 33） ✓
    螢幕固定（Kiosk 的依靠） Android 5.0 以上（SRS 名詞定義） Android 13 ✓ 選單名稱與位置以實機為準
    畫面鎖橫向 外殼兩個畫面都是 sensorLandscape（迭代 27） 一般平板 ✓ 兩個橫向都可以，轉直不跟著轉
    信任院內自簽 CA 外殼 network_security_config 的 trust-anchors（API 24 起有效） API 33 ✓
    病人端的 JS 語法 Vite 6 預設建置目標：Chrome 87 以上 看 WebView 版本 待實機（第 3 節）
    麻將牌桌的容器查詢單位（cqw、cqh） styles.css 的 .mj-board：Chrome 105 以上 看 WebView 版本 待實機（第 3 節）
    離線（Service Worker） 只在 HTTPS 底下註冊（第十二冊） WebView 支援 ✓ 前提是走 HTTPS
    效能 一頁 React，加上簡單的 SVG 折線圖與遊戲 4GB ✓ 不需要擔心
    允許側載 APK Q-11 第 2 題 看有沒有被裝置管理鎖住 待實機（第 3 節）

    2.1 WebView 為什麼是關鍵¶

    • 病人端跑在外殼的 WebView 裡，WebView 的版本決定網頁功能能不能用。
    • 這台的「Google Play 系統更新」停在 2023-05，代表它可能很久沒連外更新；WebView 透過 Play 商店獨立更新，實際版本只能在實機上看。
    • 院內離線環境無法更新 WebView（第三冊 K-08），進院後是哪一版就是哪一版。

    2.2 畫面尺寸¶

    • 面板 2000×1200。三星這一型預設的縮放倍率若是 1.5，外殼全螢幕後 CSS 是 1333×800；倍率要在實機上量（第 3 節第 2 項）。
    • 短邊 800：字級、選項圖示、邊距都以 vmin 縮放，跟 1280×800 一模一樣。
    • 寬 1333：橫向多約 53px。病人端版面是流動的，多出來的寬度只會讓進度條或空白略寬，不會出現捲軸。
    • 截圖驗收原本只在 1280×800 做；這台量到實際尺寸後，在那個尺寸重跑一次（介面設計基準 4.10、《迭代 14.5 分冊》x150）。

    3. 實機要確認的四件事¶

    帶進院、拿到平板當場做。前三項不必裝外殼就能看。

    # 檢查 在哪看 合格 不合格怎麼辦
    1 WebView 版本 設定 → 應用程式 →（顯示系統應用程式）→ Android System WebView → 版本 105 以上（越新越好） 在院外網路從 Play 商店更新 Android System WebView 與 Chrome，再進院
    2 實際 CSS 尺寸 平板橫放，Chrome 網址列輸入 data:text/html,<h1 id=o></h1><script>o.textContent=innerWidth+' x '+innerHeight+' @ '+devicePixelRatio</script> 寬約 1333、倍率 1.5（高會因 Chrome 網址列而小於 800，正常） 倍率不是 1.5：記下來，回來改介面設計基準 4.10 的表，在那個尺寸重拍截圖
    3 顯示大小與字型大小 設定 → 顯示 → 螢幕縮放；字型大小與樣式 都在預設 調回預設。螢幕縮放大一級，CSS 短邊會小於 800；字型大小可能讓 WebView 裡的字跟著放大，版面被撐開（Q-33 第 3 題）
    4 有沒有被裝置管理鎖住 設定 → 安全性與隱私權（或「關於平板」）是否寫「此裝置由貴機構管理」；從瀏覽器下載 APK 時是否跳出「允許此來源安裝」 沒有被管理，且跳得出允許安裝 問資訊室能不能解除，這就是 Q-11 第 2 題；不能側載，整條外殼路線要重新決策（第三冊 K-08）

    4. 進院前要做的事¶

    1. 確認舊資料可以清：這台是舊平板，先問醫師裡面的帳號與資料可不可以清掉。
    2. 原廠重設（醫師同意之後）：重設前先在「帳戶」移除 Google 帳號，否則重設後會卡在原帳號驗證（三星的重設保護）。
    3. 在院外網路更新一次：Play 商店更新 Android System WebView 與 Chrome。系統更新（升到 Android 14）可做可不做；要做就在實機驗收之前做完，驗收之後不再更新。外殼的 targetSdk = 34 就是 Android 14，升上去不會有相容問題。
    4. 量第 3 節的四項，結果寫回本文件第 6 節。
    5. 看電池與螢幕：舊平板的電池可能衰退。插電使用不受影響，但若要拔電撐一整個療程（四小時加輪播），先充飽試一次。

    進院後照第十二冊從院內下載頁安裝外殼、佈建，只做這一台。

    5. 只有一台的影響¶

    原本的假設 現在 影響
    15 台，一床一台 1 台 同一時間只服務一床；護理端「平板管理」與簡易版中間的平板區只會有一台
    首波先佈建 2～3 台（第三冊 K-08） 1 台 佈建、憑證核對、逸出偵測都只驗一台
    壞了換一台 沒有備品 這台壞掉或被拿走，病人端整個停；求助改回床邊呼叫鈴（原本的流程），護理端照常
    實機驗收在型號確定的平板上做 先在這台做 15 台到貨若是不同型號，要再驗一次
