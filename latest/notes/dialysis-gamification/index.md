版本：v0.1　文件狀態：草案（2026-10-09 開立）　適用讀者：院方（護理部、社工、醫師）、FDE 工程團隊

## 0. 本文件的定位

院方提出：病人透析很無聊，希望在平板上放 3 個遊戲給病人玩。本文件是這件事的**分析**，不是需求文件，也還沒有任何一行程式。

- **「遊戲」在本文件的意思是「透過平板達到遊戲化」**。3 款遊戲只是遊戲化的一種實作方式；遊戲化本身也會放進平板現有的功能裡（第 4 節）。
- 分析工具是**八角框架**（Octalysis，周郁凱提出）。每一個設計決定都要說得出它用到哪一角、為什麼用、為什麼不用。
- **本文件沒有改動任何現有文件。** 要實作時會碰到的現有需求條文（例如 FR-P14「首頁不放任何其他功能的常駐入口」）列在第 11 節，等院方與使用者決定後再一次改齊。
- 與需求文件衝突時，以需求文件為準。
- **1010 使用者已對第 11 節逐題決定**，並定了範圍（先不做暗棋與換位拼圖）與實作順序。決定、技術代價、功能開關與實作順序寫在子文件《[透析中的遊戲化之一：決定、開關與實作順序](https://94sh09sh19sh.github.io/hd-docs/latest/notes/dialysis-gamification-decisions/index.md)》；本文件的分析不改，兩者不一致時以子文件為準。

閱讀順序建議：第 1～3 節是前提（目的、限制、框架），第 4～5 節是**平板現有功能怎麼遊戲化**，第 6～7 節是**3 款遊戲怎麼挑、5 款候選的細節**，第 8～9 節是共通設計與狀態評估的界線，第 10 節是建議。

## 1. 院方的四個目的

依院方給的重要程度排序。**後面每一個取捨，衝突時都照這個順序裁決。**

| 順位 | 目的                                 | 院方描述的處境                                               | 做到了是什麼樣子                                                     | 怎麼知道有沒有做到（第 12 節）                                                              |
| ---- | ------------------------------------ | ------------------------------------------------------------ | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| 1    | **心理支援**                         | 長期透析痛苦、生活不便；長輩可能孤獨，可能覺得自己是家中負擔 | 病人在透析室裡**有事可做、有人互動、覺得自己還有用**；被聽見、被記得 | 回饋問卷的心情與「被好好照顧」分數（附錄 C.7 `FB_MOOD`、`FB_CARE`）、每月加問的 `FB_BURDEN` |
| 2    | **狀態評估**                         | 想從遊玩過程與意願得知病人生理與心理的狀況與趨勢             | 護理師與社工多一組**長期、每次都有、病人不覺得是在被測驗**的觀察資料 | 資料完整率；與護理師、社工的臨床印象對照（需另做驗證，第 9 節）                             |
| 3    | **提高使用平板的意願**               | 平板對病人很陌生，年長病人使用意願低                         | 病人**主動碰平板**；問卷、衛教、求助的使用率跟著上來                 | 任務完成率、主動開啟次數、求助功能被用過的比例                                              |
| 4    | **提高來此透析的意願、配合度與體驗** | 每週二到三次、每次四小時，非常痛苦                           | 四小時**過得比較快**、有一點期待；對這家醫院的印象變好               | 回饋問卷的 `FB_COMFORT`；病人與家屬的口頭回饋                                               |

**四個目的的關係**：心理支援是主軸，其他三個是它的副產品或觀察的窗。 **如果某個設計對目的 3 或 4 很有效，卻傷到目的 1（例如用「沒來透析花就會枯」逼病人出席），一律不做。**

## 2. 使用情境與限制

### 2.1 玩家是誰

承接《[介面設計基準](https://94sh09sh19sh.github.io/hd-docs/latest/notes/uiux-design-baseline/index.md)》2.1 的族群事實，加上遊戲才會碰到的幾件事：

| 事實                                                   | 對遊戲的意思                                                                                               |
| ------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------- |
| 多數是中老年人，老花是常態；糖尿病視網膜病變常見       | 牌面、棋子、拼圖塊都要大；對比度照病人端標準（內文 7:1）；**不能只靠顏色分辨**（例如紅黑棋只靠顏色就不行） |
| 治療中一隻手固定不能動；**空著的那隻手不一定是慣用手** | 只能點一下；目標要大、要能在畫面下半部完成；不能要求精準                                                   |
| **空著的那隻手常常就是量血壓的那一隻**                 | 量血壓時那隻手要靜止。遊戲必須**隨時停得下來、停多久都沒有損失**                                           |
| 躺著，平板架在床邊支架上，視距 40～70 公分             | 手要伸出去才點得到，**點多了手會痠**：點擊次數要少、節奏要慢                                               |
| 每週三次、每次四小時，**一做好幾年**                   | 遊戲要能玩好幾年不膩；終局設計比開局重要（第 5 節）                                                        |
| 可能虛弱、想睡、注意力低；過程中會頭暈、抽筋、噁心     | 不能有「輸」；累了隨時放下；**不舒服時求助永遠比遊戲優先**                                                 |
| 教育程度與識字程度差異大；有人只講台語                 | 規則不能靠讀說明；圖比字重要                                                                               |
| 人生經驗豐富，多數是家裡的長輩                         | **不能把長輩當小孩**：不用幼稚的卡通、不用「好棒棒」式的稱讚                                               |
| 鄰床看得到螢幕                                         | 成績、輸贏、認知表現不能公開；跟名字放在一起的東西要很小心                                                 |
| 平板每次療程重新配給病人，不是固定一人一台             | **存檔跟著人走，不跟著平板**                                                                               |

### 2.2 硬性限制

以下每一條都是**過不了就不做**的門檻。第 6 節剔除遊戲種類、第 7 節檢查每款遊戲，用的都是這張表。

| 編號 | 限制                       | 具體規則                                                                                                                                | 出處                                         |
| ---- | -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------- |
| H-1  | **單手、只有點一下**       | 沒有拖曳、滑動、長按、雙擊、雙指；任何動作都由「點一下」組成                                                                            | 介面設計基準 P-5、4.3                        |
| H-2  | **目標夠大**               | 每個可點的東西至少 64×64px、彼此間距至少 12px；以 10 吋平板 1280×800、扣掉求助區之後的內容區為準；**整頁不捲動**                        | 介面設計基準 4.3、4.10，M-4                  |
| H-3  | **完全無聲**               | 不只是「預設靜音」——**遊戲裡根本沒有聲音檔**，也不用震動（平板架在支架上，震動一樣吵）。所有回饋都是畫面上的                            | 院方要求；FR-P13「全程靜音」                 |
| H-4  | **低刺激，不讓血壓衝上去** | 沒有倒數計時、沒有時間限制、沒有「遊戲結束」；不閃爍、沒有快速移動、沒有爆炸或灑花；動畫 0.3 秒以內、只做一次；不用紅色（紅色只給求助） | 院方要求；介面設計基準 4.1、4.4              |
| H-5  | **隨時可中斷，中斷零懲罰** | 回合制；每一步都自動存檔；放下一小時再回來，畫面跟離開時一模一樣，沒有任何扣分或過期                                                    | 量血壓、護理處置、睡著、不舒服               |
| H-6  | **求助永遠在、永遠優先**   | 遊戲只畫在內容區，求助區版位不變；透析前問卷等任務照常依時點出現                                                                        | 介面設計基準 P-1、FR-P13、FR-P15             |
| H-7  | **不碰臨床判讀**           | 遊戲不拿血壓、體重、脫水量當分數或獎勵；狀態評估的輸出只陳述事實、不下結論、不自動觸發任何動作                                          | FR-P11 補充說明、附錄 C.7、5.6 節 FR-R       |
| H-8  | **一個人就能完整地玩**     | 分享、合作、競爭都是加分的選項；**沒有配對到人，遊戲照樣完整**                                                                          | 使用者要求（配對困難）                       |
| H-9  | **夜間不打擾**             | 晚班照首頁的規則調暗；不主動邀請；沒有任何自己動的畫面                                                                                  | 介面設計基準 4.5                             |
| H-10 | **鄰床看得到**             | 成績、輸贏、認知表現不出現在首頁，也不跟姓名一起顯示給別人                                                                              | FR-P14 補充說明                              |
| H-11 | **存檔跟人走**             | 存在伺服器、以病人為準；換平板、換床都接得上                                                                                            | 平板每次重新配給病人（迭代 17.1）            |
| H-12 | **離線照樣能玩**           | 遊戲的程式與圖檔都在平板的離線快取裡；斷線時照常玩，紀錄恢復連線後補送                                                                  | SRS 第 6 章「離線韌性」                      |
| H-13 | **不增加護理師的工作**     | 護理端沒有任何「一定要做」的事；可以做的事（例如回一張貼圖）都是一兩下就好                                                              | 前提：護理師的時間被切碎（介面設計基準 3.1） |
| H-14 | **不破壞現有功能**         | 首頁三區、面板、跑馬燈、問卷、衛教、求助的行為與版位都不變                                                                              | FR-P13、FR-P14                               |
| H-15 | **尊重「減少動態效果」**   | 作業系統開了這個設定，連 0.3 秒的動畫也不做                                                                                             | 介面設計基準 4.4                             |

### 2.3 為什麼「時間壓力」與「競爭」是血壓的主要風險

研究上要刻意讓人血壓上升時，常用的就是「限時心算」「在別人面前比賽」這類**時間壓力加上評價壓力**的心智作業。 反過來說，**遊戲裡只要沒有計時、沒有輸、沒有公開排名，刺激就很低**。所以 H-4 的重點不在「遊戲種類溫和」，而在這三樣東西一律拿掉。

透析中更常見的其實是**低血壓**（附錄 C.2 的 `SX_DIZZY` 排第一）。遊戲該小心的另一面是：**病人頭暈時不要因為想把這盤玩完而忍著不按求助**。所以：

- 遊戲裡沒有任何「再一下就好」「快完成了」之類催人繼續的字
- 求助區在遊戲中照樣在原位，一樣大（H-6）
- 第 12 節的試辦要回頭比對：遊戲中與非遊戲中的血壓量測，有沒有可見的差別

## 3. 八角框架與這裡的取捨原則

### 3.1 八個核心驅動力

中文譯名各版本不一，本文件以英文原名為準。

| 角  | 名稱             | 英文原名                             | 一句話                                   |
| --- | ---------------- | ------------------------------------ | ---------------------------------------- |
| 1   | 重大使命與呼召   | Epic Meaning & Calling               | 我做的事比我自己更大、有意義             |
| 2   | 進步與成就感     | Development & Accomplishment         | 我在進步、我做到了                       |
| 3   | 創意授權與回饋   | Empowerment of Creativity & Feedback | 我能自己選、自己決定，而且馬上看得到結果 |
| 4   | 所有權與擁有感   | Ownership & Possession               | 這是我的，我想把它照顧好、收集起來       |
| 5   | 社會影響與關聯性 | Social Influence & Relatedness       | 跟別人有關：被看見、陪伴、互相幫忙、比較 |
| 6   | 稀缺性與迫切     | Scarcity & Impatience                | 得不到、要等，所以更想要                 |
| 7   | 不確定性與好奇心 | Unpredictability & Curiosity         | 不知道接下來會怎樣，所以想看下去         |
| 8   | 損失與避免心態   | Loss & Avoidance                     | 怕失去已經有的、怕錯過                   |

框架裡有兩組分法，直接決定這裡怎麼用：

- **白帽與黑帽**：上面三角（1、2、3）是白帽，讓人覺得充實、有掌控感；下面三角（6、7、8）是黑帽，讓人有急迫感，但用多了會覺得被操控、不舒服。4、5 介於中間。
- **左腦與右腦**：左邊（2、4、6）偏外在動機——為了得到什麼；右邊（3、5、7）偏內在動機——事情本身好玩。外在獎勵一停，左腦的動機就跟著停。

### 3.2 套到透析室的五條原則

| #   | 原則                                                   | 理由                                                                                                                              |
| --- | ------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| O-1 | **以白帽為主，黑帽只用最溫和的形式，第 8 角幾乎不用**  | 目的 1 是心理支援。黑帽的急迫感對一群本來就痛苦、焦慮的人是加重負擔；而且黑帽的副作用（被操控感）正好打在「覺得自己是負擔」的痛處 |
| O-2 | **右腦優先（3、5、7），左腦當輔助**                    | 透析一做好幾年。靠點數、徽章撐的動機撐不了好幾年；事情本身有趣、跟人有連結，才撐得久                                              |
| O-3 | **第 1 角與第 5 角是心理支援的主力**                   | 「我是負擔」的反面是「我有貢獻」（第 1 角）；「我很孤單」的反面是「有人跟我有關」（第 5 角）                                      |
| O-4 | **獎勵的是「做了」，不是「做得好」，更不是「身體好」** | 獎勵答題正確率，病人會亂猜；獎勵體重控制，就變成系統在評價病人的身體（H-7）。完成任務可以有獎勵，答案內容、臨床數值一律不影響獎勵 |
| O-5 | **沒來不罰，來了有一點期待**                           | 病人缺席多半是住院、生病，不是偷懶。可以讓「下次來」有一點期待（第 6、7 角的溫和形式），不可以讓「沒來」有任何損失（第 8 角）     |

### 4.2 明確不放的地方

| 功能                 | 不放什麼                                                                  | 為什麼                                                                                                    |
| -------------------- | ------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| F-3 本次透析面板     | **任何形式的分數、星星、顏色評語**（例如「血壓穩定 +1」「今天脫水達標」） | 面板只呈現量測值、不判讀（FR-P11 補充說明）；把血壓變成分數，就是系統在評價病人的身體，而且最容易引起焦慮 |

### 4.3 第 1 角：重大使命與呼召

| 放在哪                | 怎麼做                                                                                                                                                                         | 主要服務的目的                                | 界線                                                                                                               |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |

## 5. 玩家旅程：四個階段

八角框架把玩家的經歷分成四段，每一段要的驅動力不一樣。透析病人的特別之處是**終局非常長**——好幾年、幾百次。

| 上手 | 第一次玩的前 5 分鐘                    | 30 秒內成功一次；不必讀任何說明  | 第一盤只有 4～6 個目標、一定成功；用一個手指圖示指著「點這裡」，做一次就消失；護理師巡床時可以陪玩一步                                    |

## 7. 五款遊戲的細節

每一款都照同一個格式寫，方便比較。畫面草圖以 10 吋平板橫放為準，**最下方的求助區與首頁同一個版位，遊戲畫不到那裡**（H-6）。

### 7.1 老台灣記憶相簿（懷舊回憶）

**一句話**：一次看一張老台灣的生活圖——大同電鍋、柑仔店、灶腳、鐵馬、廟口戲台——點選「我用過」「我家也有」「想起某個人」，慢慢累積成一本自己的記憶相簿。

**對四個目的**：

| 目的       | 怎麼幫                                                                                                                                                                         |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1 心理支援 | 回想往事讓人有被肯定、有自我認同的感覺；**長輩在這裡是「懂的人」**，年輕護理師反過來向他請教（第 1 角）；護理端拿到聊天話題，巡床時多一句「聽說你以前開過柑仔店？」（第 5 角） |
| 2 狀態評估 | 對哪些主題有反應、反應的種類（「想起某個人」可能牽動情緒）；認物題的答對與否（語意記憶的粗略線索）                                                                             |
| 3 平板意願 | 只要點大大的圖卡，沒有規則；好奇心（第 7 角）讓人想看下一張                                                                                                                    |
| 4 透析體驗 | 一次 5 張、約 5 分鐘，可以和護理師、鄰床聊起來                                                                                                                                 |

**怎麼玩**：

1. 出現一張大圖，旁邊一行字：「這是什麼？」或「你家以前有沒有？」
1. 「這是什麼？」有 3 個大選項（圖＋字）；選了之後**不論對錯都翻出答案與一句短短的說明**，例如「灶腳：以前煮飯燒柴的地方」。答錯不打叉，只是溫和地把正確的那一個框起來
1. 「你家以前有沒有？」是三個選項：有／沒有／不記得——**沒有對錯**
1. 接著出現三個「回憶小貼紙」：我用過、我家也有、想起某個人，可以點一個、幾個或都不點，然後「放進相簿」
1. 一次 5 張，看完就回到相簿封面；想再看可以再看

**畫面**：

```
┌──────────────────────────────────────────────────────┐
│ 📷 記憶相簿                                ● ● ○ ○ ○  🏠 │
│ ┌────────────────────────┐                           │
│ │                        │   你家以前有沒有？          │
│ │      （大同電鍋的圖）    │   ┌──────┐┌──────┐┌──────┐ │
│ │                        │   │  有  ││ 沒有 ││不記得│ │
│ │                        │   └──────┘└──────┘└──────┘ │
│ └────────────────────────┘   ┌────────┐┌────────┐┌────────┐│
│                              │我用過  ││我家也有││想起某人││
│                              └────────┘└────────┘└────────┘│
├──────────────────────────────────────────────────────┤
│   🔔 我需要協助                                         │
└──────────────────────────────────────────────────────┘
```

**難度與不會輸**：沒有分數、沒有「錯」。認物題的難易靠圖片本身：常見的（電鍋）先出，少見的（粿印、碗粿模）後出。

**時間與中斷**：一張圖一個單位；中途離開，下次從那一張接著看。

**用到的角**：1（說故事的人）●、5（護理師話題、這一班的共同記憶）●、7（不知道下一張是什麼）●、4（自己的相簿）●、2（相簿越來越厚）○、3（自己選貼紙）○。

**分享、合作、競爭、存檔**：

|      | 做法                                                                                           | 一個人玩時       |
| ---- | ---------------------------------------------------------------------------------------------- | ---------------- |
| 存檔 | 每一張的選擇都存；相簿跟著人走                                                                 | —                |
| 分享 | 護理端看得到「對哪些主題有回應」；將來可經由離院衛教的手機管道把相簿頁帶回家給家人（第 11 節） | 照樣完整         |
| 合作 | 匿名的「這一班的共同記憶」：「今天這一班有 5 個人家裡也有大同電鍋」                            | 看不到這一句而已 |
| 競爭 | **刻意不做**                                                                                   | —                |

**狀態評估可以蒐集的**：

| 資料                                 | 可能反映           | 要小心                                 |
| ------------------------------------ | ------------------ | -------------------------------------- |
| 每次看幾張、主動看還是被邀請才看     | 參與意願           | 新鮮感會隨時間下降                     |
| 「想起某個人」被點的比例與主題       | 情緒牽動、思念     | **不是憂鬱指標**；有人想起的是開心的事 |
| 認物題的答對率（以自己的過去為基準） | 語意記憶的粗略線索 | 題目難度不一；只看本人長期趨勢         |

**內容來源與維護**：起始約 200 張圖，分成飲食、交通、家庭、遊戲、節慶、工作等主題，每季加一包。

- **圖要委託繪製或使用授權清楚的素材**，不用網路上撿來的照片；不用可辨識的真人
- **避開創傷與政治題材**（戰爭、重大歷史事件、選舉）；可能讓人難過的主題由社工協助篩選
- 說明文字由人寫、人審，不用 AI 即時生成（避免錯誤與用語問題；若用 AI 起草，照迭代 17.3 的用語把關，並由護理師核准）

**實作量與風險**：程式量中等偏低；**內容量是最大的成本**。風險是勾起傷心的回憶——每張卡片都有「跳過這張」，社工參與篩選主題。

**不做什麼**：不錄音、不讓病人打字（自由輸入對長輩困難，也可能寫出別人看得到的隱私）；不顯示「你記得的比別人少」之類的比較。

### 7.2 麻將連連看（配對消除）

**一句話**：一桌平鋪的麻將牌，點兩張一樣的就消掉，全部消完就完成這一桌——**沒有計時、沒有輸、卡住時自動洗牌**。

**對四個目的**：

| 目的       | 怎麼幫                                                                                               |
| ---------- | ---------------------------------------------------------------------------------------------------- |
| 1 心理支援 | 熟悉的東西帶來「我還行」的勝任感；專注地玩讓時間過得快                                               |
| 2 狀態評估 | **五款裡資料最乾淨的**：每一次點擊都記得到——找到一對要多久、點錯幾次、要不要提示、點的位置離牌心多遠 |
| 3 平板意願 | 麻將牌是長輩最熟的東西之一，一看就知道要做什麼                                                       |
| 4 透析體驗 | 一桌 5～15 分鐘，玩完一桌剛好量一次血壓                                                              |

**怎麼玩**：

1. 牌**只鋪一層**，不疊（疊起來的下層牌看不清）
1. 點一張，那張牌外框變粗；再點一張一樣的，兩張一起淡出消失（0.3 秒）
1. **前幾桌**：只要兩張一樣就能消
1. **熟練之後**：加上連連看的規則——兩張之間要能用最多轉兩個彎的線連起來；連的時候畫一條線停留 0.3 秒
1. 點錯（兩張不一樣）：第一張取消選取，不扣分、不出任何聲音或晃動
1. 「提示」按鈕無限次：把一對可以消的牌框起來
1. **沒有可以消的牌時，自動重新排列剩下的牌**，所以永遠不會卡死

**畫面**：

```
┌──────────────────────────────────────────────────────┐
│ 🀄 麻將連連看                          💡提示       🏠 │
│                                                      │
│   ┌──┐┌──┐┌──┐┌──┐┌──┐┌──┐┌──┐┌──┐                 │
│   │一││東││發││三││五││東││九││北│                 │
│   │萬││  ││  ││筒││條││  ││萬││  │                 │
│   └──┘└──┘└──┘└──┘└──┘└──┘└──┘└──┘                 │
│   ┌──┐┌──┐┌──┐┌──┐┌──┐┌──┐┌──┐┌──┐                 │
│   │  ...                                             │
│                                                      │
├──────────────────────────────────────────────────────┤
│   🔔 我需要協助                                         │
└──────────────────────────────────────────────────────┘
```

**牌的大小**：內容區扣掉頂列約 1200×520px。每張牌至少 80×104px（比 64px 下限再大一些，因為牌面上要畫字）、間距 12px，**一桌最多約 4 列 × 12 行**；起始一桌 4×4 = 16 張。

**顏色**：真實麻將的「萬」字與「紅中」是紅色，但**病人端畫面上紅色只給求助**（介面設計基準 4.1）。做法是把紅色改成深棕或深藍，牌面靠字與花樣分辨（本來就靠字），**要院方確認這個替換長輩接不接受**（第 11 節）。

**難度與不會輸**：難度階梯是「張數」與「有沒有連線規則」兩個旋鈕。系統依本人的表現悄悄調整：連續順利就加，連續要提示就退回。**不顯示「第幾級」**，避免「我退步了」的感受。

**時間與中斷**：每消一對就存檔；中斷後回來牌局一模一樣。**完成時只顯示「完成了」與一個完成記號，不顯示花了多久**。

**用到的角**：2（完成一桌）●、3（自己選難度、要不要提示）●、6（今天的一桌）○、7（洗牌後的新局面）○、5（這一班的共同目標）○。

**分享、合作、競爭、存檔**：

|      | 做法                                                                                                                                      | 一個人玩時 |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------- | ---------- |
| 存檔 | 每一步都存                                                                                                                                | —          |
| 合作 | 這一班每消一對都算進共同目標                                                                                                              | 照樣完整   |
| 競爭 | **非同步、而且不排名**：同一班當天拿到同一桌「今日牌局」，結束時顯示「今天這一班有 8 個人完成了今日牌局」——**只有完成人數，沒有誰快誰慢** | 照樣完整   |
| 分享 | 無                                                                                                                                        | —          |

**狀態評估可以蒐集的**：

| 資料                                 | 可能反映                   | 要小心                                                                           |
| ------------------------------------ | -------------------------- | -------------------------------------------------------------------------------- |
| 找到一對的平均時間、要提示的次數     | 注意力、視覺搜尋、處理速度 | 低血壓、低血糖、想睡、藥物都會影響；**越玩越熟**（前 10 桌只當練習，不列入基準） |
| 點錯的次數                           | 注意力、視覺辨識           | 牌面難度                                                                         |
| 點擊落點離牌心的距離、同一處連點兩次 | 手部穩定、顫抖、疲勞       | 平板角度、用哪一隻手、正在量血壓                                                 |
| 同一次療程前段與後段的差別           | 透析中的疲勞               | **只供研究分析**（第 9 節）                                                      |

**實作量與風險**：程式量低到中（連線判定與可解性檢查要寫好）；內容幾乎不用維護。風險是少數家庭對麻將有負面聯想——它只是自由選擇的其中一款。

**不做什麼**：不做胡牌、不做四人麻將、不出現任何錢或籌碼；沒有計時、沒有連擊加分。

### 7.3 換位拼圖（拼圖）

**一句話**：一張打散的圖，點兩塊就互換位置，換到全部歸位就拼好了；拼好的圖收進「我的明信片」。

**對四個目的**：

| 目的       | 怎麼幫                                                                                                      |
| ---------- | ----------------------------------------------------------------------------------------------------------- |
| 1 心理支援 | 拼好一張美麗的台灣風景有成就感；將來能拼**家人的照片**時，心理支援的力道會大很多（第 5 角，第 11 節待決定） |
| 2 狀態評估 | 用了幾次交換（最少要幾次是算得出來的）、看不看參考圖：空間規劃能力的線索                                    |
| 3 平板意願 | 規則一句話就懂；拼圖人人玩過                                                                                |
| 4 透析體驗 | 一張 3～10 分鐘；明信片收藏讓人期待下一張                                                                   |

**怎麼玩**：

1. 一張圖切成 2×3 = 6 塊起，最多 4×6 = 24 塊，打散
1. 點一塊（外框變粗），再點另一塊，兩塊互換
1. **放對位置的那塊外框變成完成色，並加上一個勾**（不只靠顏色，介面設計基準 4.7），之後不能再被換走，避免誤點
1. 「看原圖」按鈕：底下淡淡地顯示完整的圖，再點一下收起來
1. 全部歸位，整張圖出現，收進明信片

**畫面**：

```
┌──────────────────────────────────────────────────────┐
│ 🧩 拼圖                              🖼看原圖        🏠 │
│        ┌──────┬──────┬──────┬──────┐                  │
│        │  ✓   │      │      │  ✓   │                  │
│        ├──────┼──────┼──────┼──────┤                  │
│        │      │  ✓   │      │      │                  │
│        ├──────┼──────┼──────┼──────┤                  │
│        │      │      │  ✓   │      │                  │
│        └──────┴──────┴──────┴──────┘                  │
├──────────────────────────────────────────────────────┤
│   🔔 我需要協助                                         │
└──────────────────────────────────────────────────────┘
```

**難度與不會輸**：塊數是唯一的旋鈕；依本人表現悄悄調整。沒有步數限制。

**時間與中斷**：每交換一次就存檔；沒拼完的那張下次療程還在（第 8 角反向用法）。

**用到的角**：2（拼好了）●、4（明信片收藏）●、3（選要拼哪張）○、5（這一班的共同大圖）●、7（下一張是哪裡的風景）○。

**分享、合作、競爭、存檔**：

|      | 做法                                                                                                                         | 一個人玩時       |
| ---- | ---------------------------------------------------------------------------------------------------------------------------- | ---------------- |
| 存檔 | 每一步都存；明信片跟著人走                                                                                                   | —                |
| 合作 | **這一班的共同大圖**：每個人拼好一張，就在一張大圖上揭開一塊；這張大圖由大家一起慢慢完成，完成時這一班每個人都收到這張明信片 | 自己拼的照樣算數 |
| 分享 | 家人照片做成拼圖（待決定，第 11 節）                                                                                         | —                |
| 競爭 | 不做                                                                                                                         | —                |

**狀態評估可以蒐集的**：

| 資料                          | 可能反映 | 要小心                                               |
| ----------------------------- | -------- | ---------------------------------------------------- |
| 實際交換次數 ÷ 最少需要的次數 | 空間規劃 | 圖的內容影響很大（天空一大片藍色就難）；只看本人趨勢 |
| 看原圖的次數                  | 視覺記憶 | 個人習慣                                             |
| 每次交換之間的思考時間        | 處理速度 | 同上一款                                             |

**內容來源與維護**：起始約 60 張台灣風景、節令圖（委託拍攝或授權素材）；**院方自己的照片**（透析室的節慶活動、醫院的花園）最能拉近距離，但照片裡不能有可辨識的病人。

**實作量與風險**：程式量低；內容量中等。家人照片的路要先解決院外管道與隱私（鄰床看得到）。

**不做什麼**：不做拖曳拼圖；不顯示步數或時間。

### 7.4 暗棋（傳統棋類）

**一句話**：台灣人最熟的半副象棋玩法——32 顆棋子蓋著鋪在 4×8 的盤上，輪流翻棋或走棋，大吃小。可以跟電腦下，也可以**非同步地**跟同一班願意的病友下。

**對四個目的**：

| 目的       | 怎麼幫                                                                                       |
| ---------- | -------------------------------------------------------------------------------------------- |
| 1 心理支援 | **跟人有來有往**；對平常不愛參加團體活動的男性長輩特別有吸引力；翻棋有運氣成分，輸了也不太傷 |
| 2 狀態評估 | 走棋的品質（電腦可以評估每一步好不好）、思考時間；接不接受對弈邀請（社交意願）               |
| 3 平板意願 | 下棋是熟悉的事                                                                               |
| 4 透析體驗 | 一盤 10～20 分鐘；有一個「等對方下」的期待                                                   |

**怎麼玩**：

1. 點一顆蓋著的棋子：翻開
1. 點自己的一顆棋子（外框變粗），再點要去的格子：移動或吃子
1. 規則採台灣常見玩法：帥（將）最大、兵（卒）可以吃帥（將）、炮（包）要隔一顆才能吃；**開局可選「常見規則」或少數幾種「家裡的規則」**
1. **跟電腦下**：電腦有三種強度；預設的電腦會「讓一點」，讓病人的勝率大約落在一半多一點
1. **跟病友下（非同步）**：輪到你的時候，基本資訊區的遊戲圖示上出現一個小點；什麼時候下都可以。對方下機了，下次療程接著下；一方超過兩次療程沒下，詢問另一方要不要改由電腦接手

**畫面**：

```
┌──────────────────────────────────────────────────────┐
│ ♟ 暗棋         對手：電腦（溫和）        🏳和局      🏠 │
│  ┌────┬────┬────┬────┬────┬────┬────┬────┐           │
│  │ ▒▒ │ 帥 │ ▒▒ │ ▒▒ │ 卒 │ ▒▒ │ ▒▒ │ ▒▒ │           │
│  ├────┼────┼────┼────┼────┼────┼────┼────┤           │
│  │ ▒▒ │ ▒▒ │ 炮 │ ▒▒ │ ▒▒ │ 象 │ ▒▒ │ ▒▒ │           │
│  ├────┼────┼────┼────┼────┼────┼────┼────┤           │
│  │ ...                                              │
│  └────┴────┴────┴────┴────┴────┴────┴────┘           │
├──────────────────────────────────────────────────────┤
│   🔔 我需要協助                                         │
└──────────────────────────────────────────────────────┘
```

**棋盤與棋子大小**：4 列 × 8 行，每格約 140×120px，棋子直徑約 100px，字夠大。

**顏色**：傳統是紅黑兩方，但**紅色只給求助**。改成「深藍與黑」兩方，**兩方的字本來就不同**（帥／將、仕／士、相／象、俥／車、傌／馬、炮／包、兵／卒），再加上外框形狀（圓框與方框）區分，不靠顏色也分得出來。要院方確認（第 11 節）。

**難度與不會輸**：「輸」在對弈裡無法完全拿掉，所以：

- 預設對手是會讓一點的電腦；連輸兩盤自動調弱，不告訴病人
- 隨時可以按「和局」結束，不記成輸
- **沒有戰績、沒有勝率、沒有排名**；跟病友下的輸贏只有雙方自己看得到
- 跟病友下是**雙方都同意**才開始；預設只顯示「同一班的病友」，要顯示床號，雙方都要同意

**時間與中斷**：每一步都存；沒有步時限制。

**用到的角**：5（跟人下）●、7（翻棋的運氣）●、3（自己決定每一步）●、2（贏一盤）○。

**分享、合作、競爭、存檔**：

|      | 做法                                                           | 一個人玩時                 |
| ---- | -------------------------------------------------------------- | -------------------------- |
| 存檔 | 每一步都存，跨療程                                             | —                          |
| 競爭 | 非同步跟病友下（選擇性）                                       | **跟電腦下就是完整的遊戲** |
| 合作 | 可選「這一班 vs 電腦」：同一班的人輪流替這一方走一步（非同步） | 照樣完整                   |
| 分享 | 無                                                             | —                          |

**狀態評估可以蒐集的**：

| 資料                                   | 可能反映       | 要小心                                               |
| -------------------------------------- | -------------- | ---------------------------------------------------- |
| 每一步與電腦建議的差距（大失誤的次數） | 判斷力、注意力 | 運氣成分大；下棋程度本來就因人而異——**只看本人趨勢** |
| 思考時間                               | 處理速度       | 有人本來就慢慢下                                     |
| 接受、拒絕對弈邀請的比例               | 社交意願       | 跟對方是誰有關                                       |

**實作量與風險**：**五款裡程式量最大**：規則、電腦對手、非同步對弈的配對與通知。風險是對弈的輸贏還是會帶來情緒起伏——這是五款裡唯一有「輸」的遊戲，第 12 節的血壓比對要特別看這一款。

**不做什麼**：不做即時對弈；不做公開棋譜、排行；不做下注。**備案**：若院方覺得暗棋的輸贏風險太高，改成五子棋對電腦（規則更簡單，同一套非同步機制）。

### 7.5 透析小花園（養成與放置）

**一句話**：一座屬於自己的小花園，**每來透析一次，植物就長大一點**；做完問卷、衛教、玩遊戲會得到水和養分；開的花收進台灣花卉圖鑑，也可以送給護理師或放進這一班的共同花園。**花永遠不會枯。**

**它和另外四款不一樣**：另外四款是「玩一盤」的遊戲，小花園是**把整個平板串起來的一層**——現有的問卷、衛教與另外幾款遊戲都餵養它。所以它最適合當遊戲化的骨幹（第 10 節）。

**對四個目的**：

| 目的       | 怎麼幫                                                                                           |
| ---------- | ------------------------------------------------------------------------------------------------ |
| 1 心理支援 | 照顧一個會長大的東西帶來希望感；可以把花**送人**——從「被照顧的人」變成「給予的人」（第 1、5 角） |
| 2 狀態評估 | 弱：參與的頻率、送花的行為                                                                       |
| 3 平板意願 | **問卷、衛教做完都有一份養分**——給病人一個碰平板的小理由                                         |
| 4 透析體驗 | **「下次來，花就開了」**：五款裡最能讓人對下一次有期待的                                         |

**怎麼玩**：

1. 花園是 3×4 = 12 格；點一格空地，從 3 種種子裡選一種種下
1. 每次療程開始時，系統放一份「水」在花園門口；點一下澆水
1. 做完透析前問卷、心情問卷、衛教、玩任何一款遊戲，各得一份養分（**每次療程每種最多一次，與答案和輸贏無關**，O-4）
1. 植物照「療程次數」長大：大約三次療程開一朵花，有水有養分就長得**稍微**快一點，但沒有也照樣會長
1. 開的花收進「台灣花卉圖鑑」（油桐花、杜鵑、梅花、台灣百合、蝴蝶蘭……）；節令有應景的花
1. 開好的花可以：留在自己花園、**送給護理師**、放進**這一班的共同花園**

**畫面**：

```
┌──────────────────────────────────────────────────────┐
│ 🌱 我的花園                          📖圖鑑          🏠 │
│   ┌──────┐┌──────┐┌──────┐┌──────┐    ┌──────────┐   │
│   │ 🌸   ││ 🌱   ││      ││ 🌿   │    │ 💧 澆水   │   │
│   └──────┘└──────┘└──────┘└──────┘    └──────────┘   │
│   ┌──────┐┌──────┐┌──────┐┌──────┐    ┌──────────┐   │
│   │      ││ 🌼   ││ 🌱   ││      │    │ 🎁 送花   │   │
│   └──────┘└──────┘└──────┘└──────┘    └──────────┘   │
│   ...                                                │
├──────────────────────────────────────────────────────┤
│   🔔 我需要協助                                         │
└──────────────────────────────────────────────────────┘
```

**畫風**：**寫實、雅致的植物插畫**，像植物圖鑑，不是卡通；不能讓長輩覺得「這是給小孩玩的」。

**不會輸、不會失去**（第 8 角的禁區全部避開）：

- 缺席兩週、住院一個月回來，花園跟離開時一模一樣，**植物不會枯、不會倒退**
- 沒有「好幾天沒澆水」的提醒
- 沒有可以買的東西、沒有加速道具

**時間與中斷**：一次 1～2 分鐘；它本來就是「點一下就好」。

**用到的角**：4（我的花園）●、1（送花、共同花園）●、5（送給護理師）●、6（下次來就開花）●、7（種子開什麼花）●、2（圖鑑收集）○。

**分享、合作、競爭、存檔**：

|      | 做法                                                                                | 一個人玩時 |
| ---- | ----------------------------------------------------------------------------------- | ---------- |
| 存檔 | 花園與圖鑑跟著人走                                                                  | —          |
| 分享 | 送花給護理師；將來經由離院衛教的手機管道把花園帶回家給家人看（第 11 節）            | 照樣完整   |
| 合作 | **這一班的共同花園**：大家送進去的花；種滿一次可以連到院方的真實回饋（4.3，待決定） | 照樣完整   |
| 競爭 | 不做                                                                                | —          |

**狀態評估可以蒐集的**：

| 資料                               | 可能反映           | 要小心       |
| ---------------------------------- | ------------------ | ------------ |
| 每次療程有沒有點開花園、有沒有澆水 | 參與意願的長期趨勢 | 新鮮感會下降 |
| 送花的次數、送給誰                 | 社交連結           | 個性差異大   |

**要小心的設計風險**：問卷做完給養分，可能讓病人**為了養分亂按問卷**（附錄 C.7 擔心的「資料變髒」）。對策：養分與答案完全無關、每次療程每種只給一次，且第 12 節的試辦要比對問卷作答時間有沒有變短。

**實作量與風險**：程式量中等（要接上現有任務的完成事件）；插畫量中等。

**不做什麼**：不枯萎、不提醒、不排行、不比誰的花園大。

## 8. 共通設計

### 8.1 入口在哪裡

**這是要院方與使用者決定的第一件事**：FR-P14 規定首頁只有三區、「首頁不放任何其他功能的常駐入口」。遊戲一定要有個入口，可行的做法：

| 做法                                    | 說明                                                                                     | 對 FR-P14 的影響                  |
| --------------------------------------- | ---------------------------------------------------------------------------------------- | --------------------------------- |
| **A. 基本資訊區加一個遊戲圖示**（建議） | 跟「待完成任務的圖示」同一種東西：一個圖示，點了進遊戲選單；暗棋輪到你時圖示上有一個小點 | 要改 FR-P14：基本資訊區多一個圖示 |
| B. 只靠邀請                             | 療程中出現一次邀請卡，沒有常駐入口                                                       | 不改三區，但病人想玩時找不到      |
| C. A＋B                                 | 常駐圖示，加上每次療程最多一次的邀請                                                     | 同 A                              |

**邀請的規則**（若採 B 或 C）：

- 療程開始 30 分鐘後（營運參數）、沒有待完成任務時，出現一次；晚班不邀請
- 「好」「今天不要」一樣大；選「今天不要」就這次療程不再出現
- **連續三次療程都說「今天不要」，就不再主動邀請**，直到病人自己點開為止——不纏著人；而「連續不要」本身也是一筆資料（第 9 節）

### 8.2 遊戲畫面

沿用任務畫面的框（`TaskFrame`）：上方一列是遊戲圖示與回首頁，中間是遊戲，**最下方是不變的求助區**（H-6）。整頁不捲動（M-4）。

### 8.3 與現有功能的優先順序

| 情況                                               | 處理                                                                                                       |
| -------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 玩到一半，透析前問卷、心情問卷、衛教的時點到了     | 等這一步走完（回合制，最多幾秒）→ 存檔 → 照 FR-P15 全螢幕出現任務；任務做完，問一次「回到剛剛的遊戲？」    |
| 玩到一半按求助                                     | 求助區照常運作，跟首頁一樣；遊戲保持原狀                                                                   |
| 求助被處理（FR-P12）                               | 「已處理」照常顯示在原本的位置                                                                             |
| 任務畫面閒置太久會自動回首頁（FR-P09，預設 60 秒） | **遊戲另設一個閒置門檻（建議預設 3 分鐘）**：下棋想一分鐘很正常，60 秒就被送回首頁很煩；超過門檻存檔回首頁 |
| 晚班                                               | 照首頁調暗；不邀請；遊戲照樣能玩                                                                           |
| 斷線                                               | 照樣玩；紀錄放進現有的離線佇列，恢復連線後補送；非同步對弈與共同目標等連線恢復才更新                       |

### 8.4 低刺激的具體規格

| 條目       | 規格                                                                                                                                 |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 計時       | 沒有任何倒數、沒有任何「用了多久」的顯示                                                                                             |
| 動畫       | 只在點擊之後出現，0.3 秒以內，只做一次；**沒有自己動的東西**（介面設計基準 4.4：跑馬燈是病人端唯一會自己動的東西，遊戲不打破這一條） |
| 成功的回饋 | 完成色外框＋勾選圖示＋一句「完成了」；不灑花、不爆炸、不放大彈跳                                                                     |
| 失敗的回饋 | 沒有。點錯就是取消選取                                                                                                               |
| 顏色       | 不用紅色；不只靠顏色分辨（形狀、字、勾選）                                                                                           |
| 聲音、震動 | 沒有                                                                                                                                 |
| 稱讚的措辭 | 平實、像對長輩說話：「完成了」「拼好了」；不用「好棒棒」「太厲害了吧」                                                               |

### 8.5 存檔

- 存在伺服器，**以病人為準**（不是平板）；每一步都送
- 平板上留一份最近的，斷線時照樣能接著玩
- 病人換到另一台平板，點開就是自己的花園、自己的牌局

### 8.6 分享、合作、競爭的總原則

| 原則                           | 說明                                                                           |
| ------------------------------ | ------------------------------------------------------------------------------ |
| **全部非同步**                 | 不需要兩個人同時在線；同一班的人下機時間不同、睡覺時間不同，即時配對幾乎不可能 |
| **全部可選**                   | 一個人玩，每一款都完整（H-8）                                                  |
| **預設匿名，到「這一班」為止** | 要讓對方看到自己的床號，雙方都要先同意                                         |
| **沒有排行榜、沒有戰績**       | 4.7                                                                            |
| **跟護理師的互動不能變成工作** | 收到花、送貼圖都是選擇性的，沒有待辦清單（H-13）                               |
| **跟家人的連結等院方決定**     | 系統執行期連不出去；第 11 節                                                   |

### 8.7 功能開關

照 FR-S08 的做法，每一款一個開關，另外加兩個：「病人之間的互動」「狀態評估彙整（護理端顯示）」。**全部預設關閉**，試辦的那一班才開。

1010 起照子文件第 4 節：病友小撇步、護理師回貼圖、送花各加一個開關（送花跟著小花園開關），扣掉不做的兩款，共八個。

### 8.8 護理端會多什麼

只有三樣，全部選擇性：

1. 病人詳細資訊多一小格：最近幾次有沒有玩、懷舊相簿的回應主題（聊天話題）
1. 收到病人送的花（一則小訊息）
1. 對心情問卷的「想讓我們知道的事」回一張貼圖或一句預設回覆

## 9. 狀態評估：能看什麼、不能說什麼

### 9.1 可以蒐集的資料總表

| 面向             | 資料                                                                         | 從哪款來               | 可能反映                         | 主要干擾                                 |
| ---------------- | ---------------------------------------------------------------------------- | ---------------------- | -------------------------------- | ---------------------------------------- |
| **參與意願**     | 邀請的接受率、主動開啟的次數、每次療程玩多久、連續說「今天不要」             | 全部                   | 動機、情緒、疲勞                 | 新鮮感消退、睡眠、身體不舒服             |
| **認知**         | 找一對的時間、提示次數、點錯次數；拼圖的多餘交換；暗棋的大失誤；認物題答對率 | 麻將、拼圖、暗棋、相簿 | 注意力、處理速度、空間規劃、記憶 | 低血壓、低血糖、想睡、藥物、**練習效果** |
| **動作**         | 點擊落點離目標中心的距離、同一處連點、按住的時間                             | 全部（麻將最多）       | 手部穩定、顫抖、疲勞             | 平板角度、用哪一隻手、正在量血壓         |
| **情緒與社交**   | 「想起某個人」的比例、送花、接受對弈邀請                                     | 相簿、花園、暗棋       | 思念、社交連結的意願             | 內容主題、個性                           |

### 9.2 界線：沿用附錄 C.7 的五條

心情問卷的「趨勢偏離」已經有一套寫死的規則（附錄 C.7）。遊戲資料**照抄同一套**，不另立：

1. **只跟這位病人自己比**（自己過去的移動中位數），不跟別人比；前 10 次只當練習、不列入基準（排除練習效果）
1. **由固定算式判定，不經語言模型**
1. **輸出是事實陳述**：「近兩週麻將連連看找一對的時間比自己過去的中位數多 40%」。**不得寫成「疑似認知退化」「疑似憂鬱」**
1. **不自動觸發任何動作**，只在護理端顯示；病人端看不到任何比較
1. 門檻全部可調

**一旦要把遊戲資料變成主動警示、或跟血壓等臨床資料一起判斷**（例如「玩得變慢＋血壓下降 → 提醒護理師」），就進入 5.6 節 FR-R 的範圍，要先滿足那八條，包括法務對醫療器材分類的書面確認。**本文件建議第一階段不跨過這條線**：遊戲中的表現與院方 API 的血壓只在事後做研究分析，不做即時判讀。

### 9.3 遊戲資料不是量表

遊戲裡的表現受太多因素影響，**沒有經過驗證之前不能拿來當作認知或情緒的評估工具**。要讓它有臨床意義，要做的是：

- 由社工或護理人員對同一群病人施測**標準的認知與情緒量表**，看遊戲指標與量表結果有沒有一致的走勢
- 若要發表或系統性地分析，要先送**人體研究倫理審查**
- 遊戲資料是新的個人資料：要寫進資料字典與資料庫使用規範、決定留存多久、**事先告知病人並取得同意**

在這之前，遊戲資料的正確用法是「護理師多一扇觀察的窗」，不是「系統告訴護理師病人怎麼了」。

## 12. 怎麼知道有沒有用

### 12.1 試辦

一班、四週。前兩週不開遊戲（只蒐集基準）、後兩週開。比較同一群病人前後的差別。

| 目的       | 看什麼                                                                                            |
| ---------- | ------------------------------------------------------------------------------------------------- |
| 1 心理支援 | 回饋問卷 `FB_MOOD`、`FB_CARE` 的變化；每月的 `FB_BURDEN`；護理師與社工的觀察；病人的口頭回饋      |
| 2 狀態評估 | 資料完整率（多少病人每次都有遊戲資料）；指標的穩定度（同一個人兩次之間差多少）                    |
| 3 平板意願 | 主動開啟的次數；問卷與衛教的完成率；第一次自己按求助的時間點                                      |
| 4 透析體驗 | `FB_COMFORT` 的變化；「四小時過得快不快」一題口頭問                                               |
| **安全**   | **遊戲進行中與沒有在玩時的血壓量測**（院方 API 已經有），由醫師看有沒有可見的差別；暗棋另外單獨看 |
| **副作用** | 問卷作答時間有沒有變短（7.5 的亂按風險）；有沒有人因為玩遊戲延遲按求助（看求助紀錄與護理師觀察）  |

### 12.2 長者實際看過

照跑馬燈的做法（FR-P10）：**上線前要有長者在病床上實際玩過**，回答「看得清嗎、點得到嗎、玩了累不累或煩不煩、會不會覺得是給小孩玩的」四題；任一題有人說不行，就改了再試。
