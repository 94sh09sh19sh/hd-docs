## 摘要

- 1106 使用者在專案 repo 外放了一個 `API_script` 資料夾（兩支 Python、一份 Word）；它不是本系統的程式，是同院其他團隊的抓取程式
- `fetch_API.py` 是 IDH 系統抓透析清單 API 的第三個版本，跟上層文件第 2、5 節讀到的一致，**沒有新資訊**；迭代 15 的介接程式不用改
- `hb_online_v2.py` 是**新線索**：一支照病人逐一查詢、判斷「有沒有檢驗資料」的收集程式，資料夾名是 `Hb_API_Fetch`，是第一次看到院內有人在抓血紅素的跡象
- 但它依賴的 `collector_common.py`、`config.json` 都不在，**端點、參數、回應格式、認證全都不知道**
- 「需要抽血數值的功能」與劑量調整參考照舊關閉；要取得的東西列在第 5 節
- 本文件不寫院內位址與任何病歷號（第 6 節）

## 1. 資料夾裡有什麼

| 檔案                        | 是什麼                                                              | 來源（Word 檔寫的）       |
| --------------------------- | ------------------------------------------------------------------- | ------------------------- |
| `fetch_API.py`              | 抓某一天全中心的透析清單、轉成 CSV                                  | `API_Fetch\IDH_interface` |
| `hb_online_v2.py`           | 定期逐一查詢病人的檢驗資料、按月存檔                                | `API_Fetch\Hb_API_Fetch`  |
| `API raw data address.docx` | 只有兩行：上面那兩個資料夾在某台電腦 OneDrive「Old data」底下的路徑 | —                         |

- 位置：`lab_project/API_script/`，在專案 repo 外，與 `ref_project/` 同層；檔案時間都是 1106 下午
- Word 檔只寫路徑，沒有說明用途、作者與 API 位址

## 2. `fetch_API.py`：IDH 系統抓取程式的又一個版本

與 `ref_project/` 裡兩份參考程式逐行比對：

| 比對          | 成大版                         | 斗六版                       | 本資料夾                                |
| ------------- | ------------------------------ | ---------------------------- | --------------------------------------- |
| 端點          | 成大院內那一台                 | 斗六那一台                   | **與成大版同一台**                      |
| 逾時與重試    | 沒有                           | 30 秒、3 次                  | 沒有                                    |
| 原始回應留底  | 每月一個 `YYYY-MM.txt`         | 同成大版                     | 全部附加到同一個 `data_list_sucess.txt` |
| 病歷號與姓名  | 原樣                           | 存檔前加密（115/01/14 加的） | 原樣                                    |
| 丟掉的列      | 床位數字開頭、病歷號不是純數字 | 同左                         | 同左                                    |
| 去掉 `<meta>` | `strip`（上層第 5 節第 3 點）  | 同左                         | 同左                                    |

判斷：

- 留底寫法最簡陋、沒有逾時、沒有除錯輸出，**看起來比成大版更早**，不是更新的版本
- 51 欄的欄名清單與成大版相同，上層文件第 3 節的位置表不用改
- 「床位數字開頭整列丟掉」再確認一次：IDH 系統看不到 `9A`、`99` 這類床。本系統不跟著丟，處理以《[部署手冊第十八冊之二](https://94sh09sh19sh.github.io/hd-docs/latest/deployment/18b-go-live-prep/index.md)》第 3 節為準
- 對本專案的意義：**沒有新事**。透析清單 API 的用法、坑與介接程式（迭代 15）都不用改

## 3. `hb_online_v2.py`：血紅素的收集程式

### 3.1 程式做什麼

| 面向       | 內容                                                                                       |
| ---------- | ------------------------------------------------------------------------------------------ |
| 執行方式   | `--once` 只跑一輪（失敗就回非零結束碼，可交給排程器）；不加就在程式裡每隔一段時間跑一輪    |
| 間隔       | `config.json` 的 `interval_hours`，預設 6 小時                                             |
| 查誰       | `active_patients.txt` 裡的病歷號清單，**逐一查詢**，不是像透析清單那樣一次查全中心         |
| 查什麼期間 | 從 `config.json` 的 `start_date` 到今天                                                    |
| 判斷       | `has_lab_data()`：回應裡沒有檢驗資料就算「空」                                             |
| 存檔       | `MonthlyStore`：按月存到 `hospital_dataset/`，已有的不重複存（新、重複、空、錯誤各計一次） |
| 出錯時     | 只印錯誤種類，**刻意不印病歷號與網址**                                                     |

### 3.2 不知道的事

`call_api`、`has_lab_data`、`MonthlyStore` 都在 `collector_common.py`，設定在 `config.json`，兩個都不在資料夾裡。因此：

| 不知道               | 影響                                                                                                     |
| -------------------- | -------------------------------------------------------------------------------------------------------- |
| 端點是哪一台、哪一支 | 不知道是另一支檢驗 API，還是透析清單 API 的「某位病人一段期間」查法（上層第 2 節查詢二，只有斗六版用過） |
| 參數與認證           | 不知道要不要帳號、金鑰                                                                                   |
| 回應格式             | 不知道有哪幾種檢驗、單位、有沒有採檢時間；不知道除了血紅素還有沒有白蛋白、BUN                            |
| 名稱裡的 V2          | 有一個 V1，內容不明                                                                                      |

推論（未驗證）：寫法注意了個資（錯誤不印病歷號），而且只能逐一查病人，比較像**另一支照病人查詢的檢驗 API**，不像全中心的透析清單。

## 4. 對本專案的意義

| 面向           | 意義                                                                                                                                 |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 透析清單 API   | 無新事，介接不改（第 2 節）                                                                                                          |
| 抽血數值的來源 | 1005 決定「暫定拿不到」（上層第 10 節）。這是**第一個院內可能拿得到血紅素的線索**，不是院方答覆，也不知道端點                        |
| 功能開關       | 「需要抽血數值的功能」（`LAB_VALUE_FEATURES`）與劑量調整參考**照舊關閉**；開啟條件仍是院方提供來源，劑量調整參考另需 FR-R08 書面確認 |
| 清冊           | Q-09（臨床數值的來源）的第 11 題多一條線索；確定有這支 API 才回頭改清冊                                                              |
| 頻率           | 抽血大多每月一次，每 6 小時查一次已經夠；不需要像透析清單那樣每 3 分鐘                                                               |
| 如果之後要接   | 會是 `ClinicalDataSourcePort` 底下的另一個來源；病人清單可以直接拿透析清單 API 帶進來的病歷號，不用另外維護 `active_patients.txt`    |
| 報備           | 呼叫院方 API 的報備（Q-35）只講透析清單；要接這一支就要一起報                                                                        |

## 5. 要取得的東西

照優先順序：

1. `collector_common.py`：端點、參數、回應解析都在裡面
1. `config.json` 的範本（位址可以先遮掉，看欄位名就好）
1. 一份**遮罩後**的回應：只看結構，數字與中文換成佔位字元，跟上層第 1 節處理 2024 年回應的做法一樣
1. 誰寫的、現在有沒有在跑、V1 跟 V2 差在哪
1. 確認後問資訊室：這支 API 本系統能不能也呼叫、要不要另外報備

## 6. 公開界線

- `fetch_API.py` 裡有成大院內的 API 位址，**不寫進本文件**；要找位址看那支程式
- `API_script/` 留在 repo 外，不 commit 進專案 repo（專案 repo 的文件會同步到公開站）
- 之後拿到回應，照上層文件第 8 節的做法只看遮罩後的結構，不把任何一筆真實資料放進 `docs/`
