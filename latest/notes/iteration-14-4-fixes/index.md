# 迭代 14.4：專業版求助橫幅湧入時不蓋掉整個畫面

版本：v0.1　文件狀態：已完成（2026-09-29 開立）　適用讀者：FDE 工程團隊

## 0. 本文件的定位

本文件不是需求文件，是一份**修正紀錄**：2026-09-29 使用者回報，護理端專業版在**大量求助同時湧入**時， 求助橫幅會直接蓋掉所有介面，指示歸在迭代 14.4 處理。本文件記錄查出來的原因、決定怎麼改，以及影響到哪些既有規則。

- 功能需求來源仍是《[軟體需求規格書](https://94sh09sh19sh.github.io/hd-docs/latest/requirements/srs/index.md)》，本文件不新增任何功能需求
- 範圍與技術選型仍以《[實作規格書](https://94sh09sh19sh.github.io/hd-docs/latest/requirements/implementation-spec/index.md)》為準（4.12.4 節是本文件的摘要）
- 介面規則仍以《[介面設計基準](https://94sh09sh19sh.github.io/hd-docs/latest/notes/uiux-design-baseline/index.md)》為準；本次在 4.4 補一條，「專業版不動」多一個例外
- 與需求文件衝突時，以需求文件為準

**為什麼叫 14.4 而不是迭代 15。** 這是護理端專業版一個元件的顯示修正，後端一行都沒動，迭代 15（規則引擎）的內容一項都沒動。

## 1. 起因：橫幅沒有上限

專業版的求助橫幅（`App.tsx` 的 `HelpRequestAlerts`）從迭代 2 起就掛在主框架、黏在上緣，任何頁面都看得到（FR-N03）。問題有兩個：

| 問題                                                                  | 後果                                                                                                                       |
| --------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| **一則一條，沒有上限。** 每條約 70px，1366×768 扣掉導覽列只剩約 700px | 同時進來十則左右，整疊就比畫面還高。黏在上緣的東西不會被捲走，**每一頁都被蓋住**；最底下那幾則的「前往處理」捲不到、按不到 |
| **別處接起來的不會消失。** 橫幅只有按「前往處理」或「稍後」才拿掉     | 另一台護理站、或同一位護理師在簡易版接起來的求助，專業版上仍然一條一條留著，疊得更高                                       |

這不是 14.3 造成的：14.3 只是把「黏在上緣」從橫幅本身搬到外面那一層（和斷線示警一起黏），高度沒有上限這件事從迭代 2 就存在。 平常一次只進一兩則看不出來；**真的需要它的時候——很多床同時出狀況——它反而讓整個畫面不能用。**

## 2. 怎麼改

### 2.1 最多三則完整的，其餘收成一列

| 同時未處理的橫幅 | 畫面上                                                                                    |
| ---------------- | ----------------------------------------------------------------------------------------- |
| 1～3 則          | 照舊，一則一條                                                                            |
| 4 則以上         | 前三則照舊；其餘收成**一列**「還有 N 則求助」，附「全部查看」，一步到緊急通報頁的完整清單 |

- **三則的由來**：1366×768 下，導覽列、斷線示警（14.3）加三條橫幅與「還有」那一列，仍留得下大半個畫面給目前這一頁
- **不改成「限制高度加捲軸」**：黏在上緣的小框裡再捲一次，藏在捲軸後面的求助等於看不到；收成一列至少數字一定看得到
- 按「稍後」拿掉一條，下一條遞補上來，「還有」少一

### 2.2 緊急的不會被收掉

- 排序：**緊急的在前**，才輪到一般的；同一級照新到舊（原本就是新到舊）
- 緊急的超過三則時，「還有」那一列改用警示色，並寫出「其中 N 則緊急」——顏色不是唯一線索，字也寫出來

### 2.3 別處接起來的不佔位置

- 即時快照裡那一則的狀態**已經不是「待處理」**（另一台護理站或簡易版接起來了），就不再畫它
- **快照裡找不到的一律留著**：輪詢補的快照可能比求助事件還舊，找不到不代表已經處理。寧可多留一則，也不能漏掉一則
- 直接結案而沒有經過「接起來」的那一則，快照裡會找不到，因此仍然留著，要按「稍後」拿掉——和以前一樣，是安全的方向

### 2.4 這是「專業版不動」的第二個例外

FR-N14 與基準都寫「專業版即 0919 的完整介面，功能與版面不更動」，14.3 的斷線示警是第一個例外。 這次是使用者 0929 回報後指示的第二個，範圍同樣壓在最小：只改 `HelpRequestAlerts` 這一個元件，各頁本身與後端一行都沒改。 技能檔與基準 4.4 都已註明。

## 3. 驗收

| 驗什麼                                                            | 怎麼驗                                                                                               | 結果（0929）     |
| ----------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- | ---------------- |
| 有上限、緊急在前、別處接起來的不佔位置、14.3 的上緣那一層沒被動到 | `npm run verify:iteration14-4`（5 步，不需後端）                                                     | 全部通過         |
| 既有驗收沒有被動到                                                | `build`、`check:all` 六支、`verify:iteration8`、`verify:iteration14`、`verify:iteration14-1`～`14-3` | 全部通過         |
| 實際看過                                                          | 一次送出九則求助（含緊急），專業版 1366×768 與 1920×1080 各看一次；簡易版接起一則                    | **待做**（見下） |

**還沒有在瀏覽器實際看過**：做這次變更的那個 clone 沒有 `.env`、沒有資料庫。 要在手動測試的環境照《[迭代 14.4 分冊](https://94sh09sh19sh.github.io/hd-docs/latest/testing/iteration-14-4/index.md)》`x131`～`x140` 走一次，特別是：

- 1366×768 下四列橫幅加上斷線示警時，頁面還看得到多少（`x131`、`x138`）——腳本只驗得到上限，驗不到實際排出來的高度
- 簡易版接起來之後，專業版那一則幾秒內消失（`x137`）

**沒有改的**：常駐總覽螢幕與簡易版的求助顯示（簡易版是頂端一條緊急紅框，一床一個小方塊橫著排，不在這次範圍）； 導覽列「緊急通報」旁的未處理數照舊是全部的數字。
