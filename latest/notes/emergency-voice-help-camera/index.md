## 摘要

- 1026 院方除了麥克風，也強烈建議求助時配合使用鏡頭；使用者要求先查公信力與安全性等同 GitHub 千星的專案，確認鏡頭能做到什麼，再重新規畫整條流程（第 0 節）
- 1026 以 GitHub API 查了 48 個 repo：鏡頭能做的九件事裡，有 MIT、千星專案的是影像傳輸、人物偵測、人臉偵測與辨識；姿勢、遠端量心跳、表情疼痛的主流專案都是 Apache、GPL 或限制用途的授權（第 2 節）
- 判斷沿用之二的前提：鏡頭跟語音一樣**不放在派遣路徑上**，護理站不看即時影像、也不看送出當下的照片；連按都按不了的人，鏡頭要整場透析開著才幫得上，等於全程監看，不做（第 3 節）
- **採用一件**：求助送出到停止記錄之間，平板在本機每秒數一次「近處有幾個人」，推估護理師到床邊與離開的時間——補上一直空白的到床邊時間（Q-30），也讓錄音在護理師離開後早一點停；影像不離開平板、不存（第 4.1 節）
- **第 4 階段的選項**（上層第 8 節）：護理師在床邊用平板拍出血、腫脹的部位，回護理站在草稿旁點一下才附上；要不要做先問護理部（第 4.2 節）
- **不做**：即時影像與錄影、遠端量心跳呼吸（唯一的透析室研究顯示病人說話、跟護理師互動時就量不準）、表情與疼痛判讀（沒有長者的驗證）、姿勢與跌倒偵測、人臉辨識、手勢求助、視訊通話（第 5 節）
- 新增待決定兩題：床邊拍照要不要做（護理部）、院方希望鏡頭看到什麼（醫師，下週開會）；其餘由開發端定，理由寫在各節（上層第 9.2 節第 11、12 題）

## 0. 為什麼有這一份

1026 院方：求助時除了強烈建議配合使用麥克風，也強烈建議配合使用鏡頭。使用者要求：

1. 先到網路上查公信力與安全性等同 GitHub 千星以上的專案，確認鏡頭能做到哪些事
1. 再重新規畫病人按下求助到護理師完成護理紀錄的完整流程（寫在之四）
1. 只寫文件，不改程式

判斷的前提跟語音相同（之二第 0、1 節），這裡只列跟鏡頭有關的：

- 護理師手上沒有裝置（Q-30），看到通報幾秒內就出發，出發後什麼都看不到；在護理站多看一步就是延誤與工作量
- 分級只看病人自選急迫度與分派表（FR-N03），不得摻入模型推論；判讀病情的功能屬 FR-P05 那一類高風險
- 平板架在病人面前，**前鏡頭拍到的是臉與上半身**，打針那隻手臂多半不在畫面裡；透析室很暗（0930 醫師）
- 平板是暫用的 Galaxy Tab S6 Lite（4 GB 記憶體、WebView 155，《[暫用平板](https://94sh09sh19sh.github.io/hd-docs/latest/notes/interim-tablet/index.md)》）；正式的 15 台型號未定（Q-33）
- 外殼現在只在佈建畫面掃 QR code 時用相機，病人端網頁拿不到相機（《[外殼契約](https://94sh09sh19sh.github.io/hd-docs/latest/reference/kiosk-shell-contract/index.md)》第 2 節）

## 1. 篩選條件

照之一第 1 節，不另訂：

- 直接選用的 GitHub 專案：MIT、超過 1000 顆星
- 非 GitHub 的專案與權重：之一第 1.2 節「等同千星」五條判準（發布者、社群檢驗、安全格式、授權、硬體）
- 執行期零院外連線（DEP-14）；平板或院內 Windows 主機的 CPU 跑得動
- 近半年有推送（之一條件 7，開發端訂的）

授權、星數、最後推送都是 2026-10-26 以 `gh api repos/<名稱>` 查的；判讀不出授權的另外開 LICENSE 或 README 看。

### 2.2 文獻怎麼說

- **透析室的遠端量心跳**：唯一在透析室做的研究是牛津 Churchill 醫院（《Scientific Reports》2020）：40 位病人、84 次透析、約 304 小時影片；用的是研究級攝影機、距離 1 公尺、未壓縮影像。病人穩定時心跳平均誤差 2.8 次/分、呼吸 2.1 次/分；但因動作排除後只剩 72% 的影片可用，心跳又只在其中 65% 的時間算得出來。**病人醒著說話、用手機、跟醫護互動時，動作就讓訊號失效**；日光燈閃爍、醫護的影子也會干擾
- **非接觸量測的臨床整體**：系統性回顧收 12 篇、654 人，作者結論仍是需要更多臨床研究
- **表情判讀疼痛**：2015～2025 的系統性回顧收 25 篇，準確度約 70%～90% 以上，但**幾乎沒有外部驗證**；OpenFace 在長者與失智者身上的某些臉部動作單位，精確度只有 54%；疼痛資料集裡的長者很少，皺紋與中風後的面癱會改變表情
- **醫院的鏡頭跌倒偵測**：查到的是研究原型（Fraunhofer，影像先模糊化、或告警後才看得到畫面）與廠商自述的成效，沒有找到有對照組的護理人員評估；另一條路是不用鏡頭的毫米波雷達（富士通與和歌山醫大試驗中）

## 3. 根本判斷

### 3.1 派遣路徑：不放

| #   | 鏡頭能給護理站什麼                     | 為什麼不用                                                                                                                                                                                                                                                                                                             |
| --- | -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 即時影像                               | 護理師看到通報就出發，不會坐下來看；護理站沒人時沒有人看；手上沒有裝置，出發後看不到（Q-30）                                                                                                                                                                                                                           |
| 2   | 送出當下的一張照片（放在床邊前速覽裡） | 看一眼只要一秒，是鏡頭比語音強的地方，所以單獨評估：前鏡頭拍不到打針的手臂；透析室暗，臉色看不出來；一張「看起來還好」的照片會讓人慢下來，而分級只認病人自選（FR-N03）；類別本身已經告訴護理師要帶什麼；護理站螢幕旁人看得到。唯一說得通的是「還沒選」那一則，但它本來就是緊急、本來就馬上去，照片改變不了「立刻出發」 |
| 3   | 模型判讀（姿勢、表情、心跳）           | 沒有驗證；FR-N03 不得摻入模型推論；FR-P05 高風險                                                                                                                                                                                                                                                                       |

**開發端決定：第一版護理站看不到任何鏡頭的影像。** 照片的事若要重提，條件是試用中出現「護理師到床邊才發現要回頭拿東西或多叫一個人」的情形，而且是照片看得出來的——由護理部提出再議。

### 3.2 連按都按不了的人：不做

鏡頭要在按下之前就開著才看得到，等於整場透析（約四小時）都被看著；姿勢與跌倒偵測沒有 MIT 的千星專案；自動告警屬高風險規則（FR-R）。正解仍是之二第 3 節的 H（生理量測警示）、G（床邊呼叫鈴）、I（透析機警報與巡視）。

### 3.3 護理紀錄與資訊化：有一件值得做

- **護理師不會回看影片**，跟不聽原音同理；錄影看得到身體與鄰床，隱私代價遠大過錄音
- 紀錄裡真正缺的是**時間**：到床邊時間一直是空的（FR-N10「我到床邊了」跟著手持裝置開關關著，Q-30），儀表板「按下到到床邊」也一直空白。上層第 3.3 節原本想用「床邊對話開始的時間」推估，**鏡頭數人比聲音準**：護理師走到床邊不一定馬上開口，開口的也可能是病人或鄰床
- 傷口與血管通路的樣子，照片比文字清楚，但要護理師動手拍，值不值得要問護理部

## 4. 採用的兩件

### 4.1 數人：推估到床邊與離開的時間（第一版只存不顯示）

**什麼時候開**：跟錄音同一段——臨床組與「還沒選」的求助，送出那一刻開始，停止條件照上層第 3.1 節（結案或取消、按「結束記錄」、按「不要記錄」、10 分鐘上限、下機），再加本節的「推估離開後 60 秒」。倒數期間不開；非臨床組不開；病人沒同意鏡頭的不開。

**在哪裡跑：平板本機，影像不離開平板。**

1. 病人端以 `getUserMedia` 取前鏡頭，每秒取一張、縮成 320×320
1. 以 ONNX Runtime Web（WebAssembly）跑 YOLOv9 最小的 t 版，只取「人」這一類
1. 取完結果，影像立刻丟掉；不存檔、不上傳
1. 送到後端的只有每秒一筆「時間、近處人數、最大的人框占畫面的比例」，沿用錄音的裝置 Token 與重送規則

選平板而不選後端：影像不出平板，隱私最好；後端也不必收每床每秒一張圖。代價是平板耗電與發燙，第 6 節要量；量下來扛不住，退回「每 2 秒一張」，再不行才考慮改送後端（那時要另外評估影像傳輸與留存）。

**近處才算**：人框的高度超過畫面一半（約 1 公尺內）才算一個人，鄰床與走道上的人不算。門檻是起始值，用第 6 節的語料調。

**怎麼判斷**：

| 推估   | 條件                                                  | 起始值 |
| ------ | ----------------------------------------------------- | ------ |
| 到床邊 | 送出後，近處人數從 1（或 0）變成 2 以上，持續一段時間 | 3 秒   |
| 離開   | 到床邊之後，近處人數回到 1 以下，持續一段時間         | 60 秒  |

**拿來做什麼**：

1. **錄音早一點停**：推估離開後 60 秒停錄，比「3 分鐘沒有人說話」早，錄到的旁人對話更少。3 分鐘那一條保留（鏡頭沒同意、太暗偵測不到時靠它）
1. **到床邊時間存成「推估」**：第一版任何畫面都不顯示、不進護理紀錄、不進儀表板（跟語氣同一種做法）
1. **驗證過才顯示**（門檻見第 6 節）：求助處置草稿 A 段的時間線旁出現「鏡頭推估 14:06 到床邊」，**護理師點一下才寫進去**——當時在場的就是這位護理師，推估對不對最清楚；寫進去的才算到床邊時間。儀表板「按下到到床邊」只做單位層級、每月，不做個人
1. **不認人**：只知道「多了一個人」，不知道是哪位護理師；第 3 節的到床邊時間不得用於個人考核

**權重與相依**：

- MultimediaTechLab/YOLO 在 GitHub 發布的 `v9-t.pt` 是 PyTorch pickle，照之一第 1.2 節在隔離的開發機以 `weights_only=True` 載入、轉成 ONNX、記雜湊，平板只放轉好的檔案
- 這個 repo 最後推送是 2026-03-16，超過之一條件 7 的半年。**開發端決定照用**：它只在開發機上轉一次權重，系統執行期只有 ONNX Runtime（MIT、持續維護）；權重是定版的檔案，不會因為 repo 停更而變
- ONNX Runtime Web 與 YOLO 權重要在平板上載入，跟 DEP-16「不自行載入模型」相衝，併上層第 9.2 節第 4 題問

**平板上的畫面**：上層第 3.1 節「正在記錄對話，給護理紀錄用」改成「**正在記錄對話與到床邊時間（鏡頭只數人數，不拍照、不錄影）**」；「不要錄」改名「**不要記錄**」，按了錄音與數人一起停、這一則已收的一起刪。Android 鏡頭使用中的綠點會亮，病人與旁人看得出來。

**太暗或拍不到**：偵測漏掉的只是推估空白，不影響派遣、不影響錄音（3 分鐘那一條照舊）。

### 4.2 床邊拍照附進草稿（第 4 階段的選項，先問護理部）

- 錄音期間，平板的求助狀態那一塊多一顆「拍照給紀錄」（給護理師用）；按了開後鏡頭 → 拍 → 「用這張／重拍／不要」
- 照片掛在那一則求助底下；求助處置草稿旁多一欄「床邊照片」，護理師點「附上」才跟紀錄關聯；沒附上的照片，結案後 24 小時刪
- 複製到院方系統的是文字，照片留在本系統；紀錄文字只多一句「附照片 1 張（本系統求助紀錄）」
- 不用模型、不判讀
- 疑慮：要先把平板從支架取下、10 吋平板單手不好拍、照片進不了院方的正式紀錄；正式平板有沒有後鏡頭也還不知道（Q-33）。要不要做由護理部決定（上層第 9.2 節第 11 題）

## 5. 不做的事

| 不做                             | 理由                                                                                                                             |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 護理站看即時影像或送出當下的照片 | 第 3.1 節                                                                                                                        |
| 錄影（不論存不存）               | 護理師不回看；看得到身體與鄰床，隱私代價最大                                                                                     |
| 遠端量心跳、呼吸                 | 沒有符合授權的千星專案；透析機與院方本來就量；病人說話、跟護理師互動時量不準——求助時正好是這種時候（第 2.2 節）                  |
| 表情、疼痛、情緒判讀             | 沒有長者的驗證、權重授權不明；會被當成病情輕重（FR-P05）。語氣的「只存不顯示」不延伸到臉：存臉的判讀結果要先存臉的影像，代價不同 |
| 姿勢、跌倒、離床偵測             | 要整場開著；沒有 MIT 的千星專案；告警屬高風險（第 3.2 節）                                                                       |
| 人臉辨識                         | 生物特徵；理由同上層「不做聲紋」                                                                                                 |
| 舉手、揮手等手勢求助             | 要整場開著；理由同之二第 3 節 F（常開麥克風）                                                                                    |
| 病人與護理站視訊通話             | 護理師會坐下來講，而不是過去                                                                                                     |
| 影像模糊化後存檔                 | 不存影像就不需要；MIT 的兩個專案也多年沒維護                                                                                     |

## 6. 驗證

- **語料**：開發團隊與志工在模擬床位錄，只在開發機上用、不帶進院內：亮與暗兩種光線（含實際透析室的亮度）；平板不同角度；護理師站在病人左、右、床尾；鄰床有人、走道有人走過；**不用病人**
- **指標**：
- 推估到床邊與人工標註的時間差（中位數、第 90 百分位）
- 漏報：人到了沒偵測到；誤報：鄰床或走過的人被算進去
- 推估離開與實際離開的時間差
- 暫用平板 10 分鐘連續跑的耗電、溫度、每張的推論時間
- **顯示門檻**（開發端訂的起始值）：到床邊時間差第 90 百分位 15 秒內、誤報 5% 以下，才做第 4.1 節的第 3 步
- **試用時**：抽幾次求助，由觀察員記實際到床邊的時間對照；不用護理師另外按任何東西

## 7. 隱私與同意

- 影像在平板記憶體裡算完就丟，送出去的只有人數與時間；**但仍然是處理了病人與護理師的影像**，同意書要寫明
- **病人同意**：錄音與鏡頭分兩格勾，可以只同意一種；護理師在護理端登記一次（同上層第 7 節）
- **護理師**：要取得同意；到床邊時間只做單位層級，不得用於個人考核，獎勵制度與儀表板的個人頁都讀不到
- **旁人**：近處才算、不存影像；鄰床的人就算入鏡也只是「一個框」，不留任何東西
- **拍照**（第 4.2 節）：照片是健康資料、可能拍到身體；拍到臉的重拍；附上的照片留存期限照《資料庫使用規範》8.2 待院方定
- **軟體醫療器材**：數人不判讀病情、不參與分級；拍照不判讀
