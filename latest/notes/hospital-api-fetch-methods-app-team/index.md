## 摘要

- **1116 起，透析清單的留底檔在 `C:\API_Fetch\IDH_interface`**（院內部署主機），D 槽的舊位置已刪；請把讀檔路徑改過來
- 寫檔的是新的抓取腳本 `hd-hospital-fetch` v0.3.0：工作排程器每 3 分鐘抓一次院方透析清單 API，只在 07:00～23:00 抓
- 檔名、`Date:` 一行＋JSON 一行的寫法跟以前一樣；**不一樣的是每一段只放這一輪新的或變了的列**，不再是當天的整份清單
- 要某一天的完整清單：把那一天所有段落依序合起來，同一個鍵（第 0、6、8 欄：病歷號＋透析開始時間＋紀錄時間）以後面的為準（第 4 節）
- 資料多新看同一個資料夾的 `fetch-status.json` 的 `last_success_at`（第 5 節）
- 請只讀：不搬、不刪、不改、讀完就關（第 6 節）
- 這台主機 11/06～11/15 沒有資料（是正式 IDH 主機搬來的副本，那段期間這台沒人寫）；1116 有 3 次透析的目標脫水量明顯填錯（第 7 節）
- 請回第 8 節的一題

## 2. 資料夾裡有什麼

| 檔                  | 是什麼                                                                            |
| ------------------- | --------------------------------------------------------------------------------- |
| `YYYY-MM.txt`       | 每月一個留底檔，1116 時有 24 個（`2024-12.txt`～`2026-11.txt`）；月份以 +08:00 算 |
| `fetch-status.json` | 抓取腳本每一輪覆寫的狀態檔（第 5 節）                                             |

其他檔（例如 `state` 資料夾、鎖檔）是腳本自己用的，不要依賴，也不要動。

## 3. 檔案格式

- 一段＝一行 `Date: YYYY-MM-DD HH:MM:SS`（+08:00），下一行是 `{"data_list":[…列…]}`
- 一列是院方回應原樣的陣列，**51 個值、沒有欄位名稱，只能靠位置**；順序與意義見《[同院 IDH 系統參考調查](https://94sh09sh19sh.github.io/hd-docs/latest/notes/idh-reference-survey/index.md)》第 3 節，值的格式見同一份第 2.1 節
- 一列是一次透析中的一筆紀錄；體重、脫水量、設定值這類透析層級的欄，在同一次透析的每一列重複出現
- 腳本不丟列、不改值；JSON 是重新序列化的：中文不跳脫，數字照 Python 的寫法（`1.10` 會變 `1.1`，值相同）
- 時間欄（第 6～8 欄）是 `YYYY-MM-DD HH:MM`，沒有秒、沒有時區；缺值是空字串；理想體重沒填是 `0`
- 單位照院方：目標脫水量、實際脫水量是公升，體重是公斤
- 換行是 `\n`；檔尾沒有換行代表那一段還在寫

## 4. 怎麼讀出某一天的完整清單

1. 讀那個月的 `YYYY-MM.txt`，挑出 `Date:` 是那一天的段落
1. 照檔案裡的順序合起來；同一個鍵（第 0、6、8 欄）出現多次，**以後面的為準**
1. 同一位病人在比較後面的段落出現**有紀錄時間**的列，就把他在比較前面的段落裡**沒有紀錄時間**的列（預排列）拿掉：腳本不記「消失的列」，透析開始後預排列就不在回應裡了，留底卻還在，不拿掉會多算一次透析
1. 檔尾沒有換行的那一段當成寫到一半，下次再讀
1. 段落之間的空行略過（舊檔每段之間多一行空行）；某一段解析不出來，略過那一段就好，不影響其他段

為什麼同一個鍵會寫兩次：結束體重、結束血壓、實際脫水量、結束時間是整場共用的欄，下機後院方才回填到同一場已經出現過的每一列。腳本看到內容變了就再寫一次，所以要以後面的為準。這一點跟學長 1114 給的〈去重邏輯交接〉不同（那份是見過就跳過），原因相同，學長已知。

舊段落與新段落混在同一個檔：`2026-11.txt` 在 11/06 以前是舊腳本寫的整份清單，11/16 14:42 起是新腳本寫的變動。上面的讀法兩種都適用，不必分開處理。

規模：1116 當天合起來 514 列、95 次透析、89 位病人；`2026-11.txt` 當天約 90 MB，舊的月份檔最大約 1.28 GB。只要當天的話，從檔尾往回讀到那一天的第一段就可以停，不必整個讀進記憶體。

## 5. 資料多新、抓取有沒有在跑

看 `fetch-status.json`（每一輪先寫暫存檔再改名，不會讀到一半）：

| 欄位                            | 意思                                                                          |
| ------------------------------- | ----------------------------------------------------------------------------- |
| `last_success_at`               | 最後一次成功抓到的時間；**資料多新看這個**                                    |
| `last_attempt_at`               | 這一輪開始的時間                                                              |
| `result`、`reason`              | `ok`、`failed`、`skipped`（上一輪還沒跑完）；失敗或跳過時 `reason` 寫中文原因 |
| `response_rows`、`written_rows` | 院方回了幾列、這一輪寫進留底幾列                                              |
| `output_file`                   | 當月檔的檔名                                                                  |

- 不要用最後一段的 `Date:` 判斷資料多新：沒有新量測時腳本不寫段落，`Date:` 會停住，但抓取是正常的
- 23:00～07:00 狀態檔停在 23:00 前最後一輪，不是抓取停了

## 6. 讀的時候請注意

- **只讀**：不搬、不刪、不改、不改名，不要在這個資料夾放自己的檔；抓取腳本每 3 分鐘在寫這裡
- 讀完就關，不要讓程式一直開著檔
- 檔裡是全中心病人的明文姓名與病歷號
- 本系統（血液透析平板照護輔助系統）也讀同一份，唯讀掛載，不會改到檔
