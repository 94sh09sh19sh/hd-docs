    迭代 35 手動測試 — 床邊對話轉成護理紀錄的句子¶

    《完整手動測試手冊》的分冊之一，對應《實作規格書》4.35 節。共用的環境準備、啟動與疑難排解都在主手冊，這一冊只寫迭代 35 的部分。設計與理由在《緊急求助的語音說明》第 3.1、3.4、6、7 節與第 8 節第 3 階段；需求是 SRS FR-P21、FR-N05 與 FR-N10 補、FR-N22（護理人員那一半）、FR-S20、FR-S21。語音閘道、病人的錄音同意與外殼 0.4.0 在《迭代 34 分冊》，床邊對話接在它後面。對真實病人與護理師錄音前要有院內辨識端點（Q-07）、Q-41 第 1 題（遮名夠不夠）與第 2 題（護理人員同意）；之前只在開發機、對開發團隊照腳本錄的語料測。

    摘要¶

    這一冊驗六件事（項次 as1～as28，自動化另跑 npm run verify:iteration35 與 npm run verify:iteration35:api）：

    • 開關「床邊對話記錄」預設關；語音閘道不通開不起來；語氣端點只准院內位址、不通只留空
    • 錄音同意：系統管理者登記護理人員的同意與撤回；病人與那一床當班的負責護理師都登記了才錄（整台），沒排到人也不錄
    • 病人端：臨床組與「還沒選」送出後先問後端再開麥克風；內容區與求助區之間一條「正在記錄對話，給護理紀錄用」＋「結束記錄」「不要記錄」；停止條件取最早的那一個
    • 護理端：求助處置草稿旁「床邊對話裡可以用的句子」，按「加入」才進編輯框；AI 沒開只列含詞庫用語的原句
    • 只存不顯示：語氣、聲音事件、推估的到床邊只在資料庫；「不要記錄」連已收的一起刪；稽核與 AI 呼叫紀錄不寫字
    • 準度、整理時間與推估到床邊要院內端點與照腳本錄的語料；兩支驗收腳本
    標記 意思
    📱 病人端 已配給今天透析中病人的平板（或開發機瀏覽器 1280×800 開病人端，瀏覽器會問麥克風）；npm run demo:patient 最快
    🖥 護理端 以系統管理者登入；病人的錄音同意在專業版「排班與指派」最下面，護理人員的在系統管理「護理人員錄音同意」；負責護理師在「排班與指派」排班並指派床位
    🛠 開發機 遷移 iteration35_bedside_transcript（npm run prisma:deploy -w @hd/api，後端要先關）；.env 設 SPEECH_GATEWAY_URL；看資料表用 SQLite 檢視工具

    前置：一位今天透析中、配好平板的病人，透析前問卷已填，已登記錄音同意（迭代 34 §34.2 那張，標題改成「錄音同意（病人）」）；那一床此刻排了負責護理師（排班與指派建立涵蓋現在的班、指派這一床），而且這些護理師都已在 §35.2 登記同意。「求助倒數自動送出」開或關都會錄（兩種送出都從送出那一刻開始）。沒有院內辨識端點時，開發機可以接實驗室 3090 的辨識端點（迭代 34 ar19 那一套），或自寫一支照 services/speech-gateway/README.md「床邊對話」格式回固定幾句的假閘道走流程；準度另在 §35.6 用真模型測。

    §35.1 語音閘道與開關¶

    • as1 ［開發機］ 🛠 在 services/speech-gateway 建映像檔（docker compose --profile ai build speech-gateway）。 → 建置最後一步印「自我測試通過」，其中多一段「[12] 床邊對話整段處理（迭代 35）」；映像檔裡仍沒有任何模型檔與推論套件（SenseVoiceSmall 跟著辨識端點走，DEP-16 不開例外）。
    • as2 ［開發機］ 🛠 config.yaml 照 config.example.yaml 加 emotion_endpoint，base_url 先填一個公開網址。 → 閘道 /health 回 503「設定有誤」：語氣端點同樣只准院內位址。改成院內位址但那一台沒開。 → /health 回 200，多一項 emotion 寫不通（只回報、不擋）；/v1/bedside 照常回每一句的字，emotion、soundEvent、emotionModel 都是空的。
    • as3 ［護理端］ 🖥 系統管理 → 功能開關。 → 「病人端畫面」那一組多一列「床邊對話記錄（臨床的求助送出後錄床邊對話，整理成草稿旁可以加入的句子）」，預設關閉；開啟條件寫語音閘道健康檢查，以及只錄病人與那一床當班負責護理師都登記了同意的；畫面上沒有識別字與需求編號。
    • as4 ［護理端］ 🖥 SPEECH_GATEWAY_URL 空白（或閘道停掉）時開「床邊對話記錄」。 → 開不起來，說明寫「語音閘道健康檢查未通過」與原因；記一筆「開關切換遭拒」。閘道接上之後再開。 → 開得起來，不必先開「求助倒數自動送出」；說明寫「只錄病人與那一床負責護理師都登記了同意的。語氣與推估的到床邊只存不顯示」。

    §35.2 錄音同意（護理人員與整台）¶

    • as5 ［護理端］ 🖥 開關開著，系統管理。 → 多一個分頁「護理人員錄音同意」，卡片「護理人員的錄音同意（床邊對話記錄）」：說明寫負責護理師都登記了那一床才錄、沒排到負責護理師的床不錄、轉寫與句子不得用於任何個人考核；選護理人員（姓名與工號）、簽同意書的時間、同意書編號（選填）、「登記同意」；底下「還沒登記 N 位：…」。開關關著、或用沒有系統設定權限的帳號（一般護理師）登入，都沒有這個分頁。專業版「排班與指派」最下面病人那張改叫「錄音同意（病人）」，只開「床邊對話記錄」也會出現。
    • as6 ［護理端］ 🖥 登記一位護理師，再選她按「登記撤回」。 → 登記後寫「已登記 某某 的錄音同意」、選單裡她後面多「・已登記」，稽核多一筆「登記護理人員的錄音同意」。撤回跳確認，寫「撤回之後 某某 負責的床不再錄床邊對話；已經收下的照同意書寫的處理」，按「確定撤回」後記一筆「登記護理人員撤回錄音同意」；再選她寫「…撤回過；再登記要有新簽的同意書」。
    • as7 ［病人端］ 📱 病人沒有登記同意時點一個臨床的類別（例如「頭暈」）。 → 求助照常送出；沒有那一條、瀏覽器不問麥克風（先問後端，說不錄就不開麥克風）。
    • as8 ［病人端］ 📱 病人登記了，但（一）那一床此刻沒有排到負責護理師，（二）排到兩位、其中一位沒登記或剛撤回。 → 兩種都沒有那一條、不問麥克風（1125 定「整台」）；開發者工具看 POST /api/device/help-requests/:id/bedside 回 recording: false，原因分別是「這一床現在沒有排到負責護理師」「這一床的負責護理師還沒登記錄音同意」，平板畫面不顯示原因。兩位都登記之後再求助才有。

    §35.3 平板上的記錄與停止條件¶

    • as9 ［病人端］ 📱 條件都成立，點「頭暈」。 → 照常「已經通知護理站」；內容區與求助區之間多一條：麥克風圖示＋「正在記錄對話，給護理紀錄用」＋「結束記錄」「不要記錄」兩顆按鈕；求助區的位置與尺寸不變，只有內容區矮一條；沒有聲音、不閃、不用紅色；回首頁或去別的畫面那一條還在；1280×800 不捲動。這一條還沒在 1280×800 截圖確認過，要人實際截一張看。
    • as10 ［病人端］ 📱 點非臨床的類別（例如「我要上廁所」）。 → 沒有那一條。開著「求助倒數自動送出」時讓倒數跑完送出「病人還沒選」。 → 有那一條；之後點「口渴、肚子餓」，那一條幾秒內不見；資料庫那一列狀態「改成非臨床的求助，沒有整理」、原音照留、沒有轉寫。
    • as11 ［病人端］ 📱 說幾句之後按「結束記錄」。 → 那一條不見、首頁狀態寫「已停止記錄」；稽核「床邊對話記錄停止」寫「平板上按了結束記錄；收到 N 段」，不寫字。
    • as12 ［護理端］ 🖥 錄音中在護理端結案（處理結果「病人自行取消」以外）。 → 平板那一條幾秒內不見（後端每 5 秒巡一次）；停止原因「求助結案或取消」。
    • as13 ［病人端］ 📱 錄音中有人說幾句，之後連續 3 分鐘都不說話。 → 3 分鐘到就停，原因「連續 3 分鐘沒人說話」。另一則從頭到尾不說話。 → 不因沉默而停（「有人說過話之後」才算），錄滿 10 分鐘停，原因「錄滿 10 分鐘」。判斷用每秒音量（門檻 50），不是模型；病房背景聲大過門檻時不會停在 3 分鐘，照實記下。
    • as14 ［病人端］ 📱 錄音中（一）拔掉平板網路 30 秒再接回，（二）拔掉超過 90 秒，（三）護理端讓病人下機或解除配對。 → （一）那一條一直在，接回後補送，bedside_chunks 的序號連續不缺；（二）後端停下、原因「平板沒有再送音訊上來」，照已收的整理；（三）麥克風關掉、那一條不見，原因「下機或解除配對」。錄音中重新整理病人端的話，那一條不見、不會自己接著錄，90 秒後後端照（二）停（重問拿回同一則只在驗收腳本驗）。
    • as15 ［病人端］ 📱 「按住說話」也開著，點「身體其他地方不舒服」。 → 那一條與「按住說話」都在；按住說話照常轉寫進說明框，床邊對話那一條不中斷。
    • as16 ［病人端］ 📱 實機：外殼 0.3.0 的平板與 0.4.0 的平板各試一次（橫放 1280×800）。 → 0.3.0 沒有麥克風，不出現那一條、求助照常；0.4.0 不再跳任何系統框就開始錄。長者實際看那一條，知道正在記錄、找得到「不要記錄」。

    §35.4 草稿旁的建議句子¶

    • as17 ［護理端］ 🖥 結案後到護理紀錄頁開啟這一則的「求助處置」草稿。 → 草稿旁一塊「床邊對話裡可以用的句子」；還在整理時寫「正在整理床邊對話，好了會自己出現在這裡。」，每 10 秒重取、整理好自己出現，不必重新整理。記下結案到出現幾秒（目標 2 分鐘；開發機的數字只供參考，院內主機在 as26 量）。
    • as18 ［護理端］ 🖥 看建議並按其中一條的「加入」。 → 每一條是時間、「原句」、「症狀與感受／處置後的反應／衛教或叮嚀・建議放 D 資料」這類段落；上方寫「都是床邊對話裡的原句，按『加入』才會放進草稿；不加就跟平常一樣寫」。每一條對得到整段轉寫裡的句子（可刪字、不加字）。按「加入」字接在那一段編輯框原有的字後面（前面沒有句尾標點補句號），按鈕變「再加一次」；稽核「把床邊對話的句子加入草稿」只寫第幾條。沒按的不進草稿。SOAP 格式的草稿，段落換成 S 主觀與 P 計畫與措施。
    • as19 ［護理端］ 🖥 展開最下面的「整段轉寫（N 句）」，之後簽核這份紀錄再開啟。 → 每一句只有時間與字，沒有語氣、聲音事件、到床邊時間；簽核後建議欄只剩按過「加入」的那幾條。
    • as20 ［護理端］ 🖥 （一）AI 總開關關著時錄一次、結案；（二）結束記錄之前把語音閘道停掉；（三）把「床邊對話記錄」關掉再看草稿。 → （一）寫「AI 沒有開，只列出含症狀用語的句子」，只列含詞庫用語的原句、信心低的不列；資料庫沒有推估的到床邊與離開、沒有裁尾。（二）寫「床邊對話沒有整理出來，紀錄照平常寫」，求助與草稿照常、原音照留；稽核寫「整理失敗：…（原音照留）」。（三）整塊不出現。

    §35.5 只存不顯示、刪除與稽核¶

    • as21 ［開發機］ 🛠 AI 開著整理完一則（腳本裡護理師最後一句之後再多錄 2 分鐘），看 bedside_recordings、bedside_chunks、bedside_segments、bedside_suggestions、ai_invocations。 → 每一句有 emotion、sound_event、rms、chars_per_second、pause_before_ms、nurse_to_patient；那一列有 estimated_arrived_at、estimated_left_at、trimmed_from_ms；護理師最後一句之後超過 60 秒的句子與原音段都刪掉。用途「床邊對話挑句子」那一筆呼叫紀錄提示與輸出都是空的，只有發生過、用哪個模型。稽核「床邊對話整理完成」只寫幾句、挑出幾條、有沒有經 AI，不寫字。
    • as22 ［護理端］ 🖥 開發者工具看 GET /api/help-requests/:id/bedside-transcript 的回應，再逐頁看總覽、緊急通報、到達時間、工作量、獎勵、儀表板。 → 回應裡沒有語氣、聲音事件、推估的到床邊與離開那幾欄；任何畫面都讀不到；到達時間不會被推估值填進去（「寫入」是第 4 階段，不排）。
    • as23 ［病人端］ 📱 說幾句之後按「不要記錄」。 → 那一條不見、首頁狀態寫「錄音已刪掉」；bedside_recordings 只留一列（病人選擇不要記錄，已刪除），這一則的原音、逐字稿、建議都沒有了；稽核「病人選擇不要記錄床邊對話（已收的一併刪除）」寫已收幾段；護理端草稿旁寫「病人選擇不要記錄，這一則的床邊對話已經刪掉」。按的當下平板沒網路、一直送不上去時，平板寫「請告訴護理師」。
    • as24 ［開發機］ 🛠 資料取出看五張新表。 → 都登記了分類；bedside_chunks 的原音歸「直接識別」，假名化級裡換成代號。

    §35.6 準度、整理時間與自動化驗收¶

    • as25 ［開發機］ 🛠 院內辨識端點接上、辨識端點那一台另跑 SenseVoiceSmall 官方 api.py（emotion_endpoint 指過去）之後，在 GPU 上用照腳本錄的語料跑整段處理：病人說台語、華語、混著講，護理師用華語回應；小聲、有氣無力、邊喘邊說；背景有透析機、鄰床說話、機器警報；平板 50 與 100 公分。不用病人的錄音；床邊對話的錄音腳本還沒寫（語音說明第 6 節「之後另寫」），寫法照《語音說明之五》。 → 挑出的句子加了原句沒有的字 0 次；靜音與雜音段生出句子 0 次；症狀用語有沒有出現在建議裡（召回率）；語氣與腳本標好的情緒一致程度，台語與華語分開記（不是上線門檻）。真模型還沒在 GPU 量過，開發機的假閘道不算。
    • as26 ［開發機］ 🛠 院內主機的 CPU 與 GPU 各量一次結案到建議出現的時間。 → 目標 2 分鐘內；沒趕上的那幾次，草稿頁要自己補出來（as17）。
    • as27 ［開發機］ 🛠 語料加兩種情形：「護理師到了先看機器、不開口」「鄰床護理師對鄰床病人說話」，人工標註到床邊與離開的時間，再從資料庫讀推估值比對。 → 記差距的中位數與第 90 百分位、誤報比例；第 90 百分位 15 秒內、誤報 5% 以下才考慮第 4 階段的「寫入」。只決定日後要不要做，不是這一版的上線門檻。
    • as28 ［開發機］ 🛠 跑 npm run verify:iteration35（不需要後端，先 npm run build -w @hd/shared；八步：數字與「只刪字、不加字」、開關與首頁欄位與建議放哪一段、只存不顯示、病人端、護理端、後端、語音閘道、匯出登記與既有檢查）與 npm run verify:iteration35:api（要 Prisma，不需要開發機的後端，自己起後端、假院方 API、假語音閘道、模擬 AI；台北時間 01:00 以前不跑；九步：開關與首頁、開始錄的條件、一秒一段與重送、整理結果、護理端建議欄、停止條件、不要記錄、AI 沒開與閘道故障、撤回護理人員的同意）。 → 兩支都全部通過。
