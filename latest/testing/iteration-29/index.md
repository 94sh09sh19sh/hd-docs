# 迭代 29 手動測試 — 連點成畫之一：遊戲模式

> 《[完整手動測試手冊](https://94sh09sh19sh.github.io/hd-docs/latest/testing/manual-test-guide/index.md)》的分冊之一，對應《實作規格書》4.29 節。共用的環境準備、啟動與疑難排解都在主手冊，這一冊只寫迭代 29 的部分。設計與理由在《[透析中的遊戲化之五](https://94sh09sh19sh.github.io/hd-docs/latest/notes/dialysis-gamification-benchmark/index.md)》第 3.1、3.3、6.1 節。

## 摘要

這一冊驗五件事（項次 `am1`～`am21`，自動化另跑 `npm run verify:iteration29` 與 `npm run verify:iteration29:api`）：

- 開關「連點成畫」預設關；關著時遊戲選單沒有這一款、兩支端點回「此功能未啟用」
- 1280×800 下 25 個圓不捲動；每盤版面不同、難度大致一樣；點完揭開一張記憶相簿的圖
- 點錯什麼都不變；畫面沒有計時、分數、星等、排名，全程無聲、沒有動畫
- 點到一半斷線、關掉、換一台平板，回來畫面一樣；放下超過 30 秒的那一盤有標記
- 護理端病人詳細資訊只多「本月連點成畫 N 盤」

| 標記          | 意思                                                                                                                          |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 📱 **病人端** | 平板或開發機瀏覽器 1280×800；`npm run demo:patient` 最快（要先用 `.env` 的管理者帳號 `PUT /feature-flags/CONNECT_DOTS` 開啟） |
| 🖥 **護理端**  | 以系統管理者登入專業版                                                                                                        |
| 🛠 **開發機**  | 迭代 29 有一個遷移（`npm run prisma:deploy -w @hd/api`）；看資料表用 SQLite 檢視工具開開發資料庫                              |

## §29.1 開關

- `am1` **［護理端］** 🖥 系統管理 → 功能開關，「病人平板的遊戲化」那一組。 → 多一列「連點成畫」，預設關閉；說明寫得出點完揭開的圖沿用記憶相簿的預設圖卡、對真實病人收資料前要先有院方的答覆；畫面上沒有開關識別字與需求編號。
- `am2` **［病人端］** 📱 其他遊戲也都關著時，看基本資訊區。 → 沒有遊戲圖示（與迭代 17.7 一樣）。
- `am3` **［護理端→病人端］** 只開「連點成畫」，等平板下一次取資料（最多一分鐘）。 → 基本資訊區出現遊戲圖示；點開遊戲選單，只有「連點成畫」一顆（圖示是四個圓點連線）。
- `am4` **［病人端］** 開著時再關掉「連點成畫」，停在連點成畫的畫面等下一次取資料。 → 回到首頁、遊戲圖示不見；這時呼叫 `GET /api/device/games/connect-dots` 回 404「此功能未啟用」。
- `am21` **［護理端→病人端］** 📱 1028 補：小花園、麻將連連看、記憶相簿、連點成畫四款都開（「現有功能的小幅遊戲化」也開著），點開遊戲選單。 → 五顆排成上三下二，「老台灣記憶相簿」「我的衛教小本子」都是一行、沒有落單的字，整頁不捲動；關掉任一款剩四顆時排回一列。

## §29.2 一盤怎麼玩、版面與揭圖

- `am5` **［病人端］** 📱 1280×800 點「連點成畫」。 → 一句「從 1 開始，照順序點 1、2、3，點完會看到一幅畫」與「開始一盤」；沒有「越快越好」「計時」之類的字。
- `am6` **［病人端］** 點「開始一盤」，截一張。 → 25 個白底灰框的圓、各寫一個數字，散在內容區；**整頁不捲動**，求助區在下面、位置與尺寸跟首頁一樣；沒有計時器、倒數、分數、星等、排名。
- `am7` **［病人端］** 依序點 1、2、3。 → 點對的那一個變成深綠實心白字，和上一個之間直接出現一條深綠線（沒有動畫、沒有聲音）。
- `am8` **［病人端］** 該點 4 時故意點 9，再點已經點過的 2，再點兩個圓中間的空白。 → **畫面什麼都不變**：沒有「錯」、沒有晃動、沒有變暗、沒有聲音。
- `am9` **［病人端］** 點的時候稍微點偏（點在圓的外緣或圓外一點點）。 → 偏一點（不超過半格）照樣算點到；點在兩個圓正中間的空白不算。
- `am10` **［病人端］** 點完 25 個。 → 左邊整張出現一幅圖（記憶相簿的插畫），右邊一句「這是〇〇」與「開始一盤」；**沒有**「再一盤就好」、分數、花了多久。
- `am11` **［病人端］** 連開 5 盤，每盤截一張。 → 5 張版面都不同；相鄰兩號不會貼在隔壁、也不會一下跨過半個畫面；連線不會從別的圓上面穿過。
- `am12` **［病人端］** 開「減少動態效果」、夜間模式各看一次。 → 畫面一樣（本來就沒有動畫）；夜間只變暗，圓與線看得清楚。

## §29.3 斷線、中斷、換平板

- `am13` **［病人端］** 📱 點到第 10 個時拔網路，接著點到第 15 個，回首頁再點開連點成畫。 → 畫面一樣（下一個是 16）；接上網路後等一分鐘，在 🛠 資料表 `connect_dots_taps` 看得到這幾下，序號接得上。
- `am14` **［病人端］** 點到一半按回首頁、等閒置回首頁或關掉平板的瀏覽器分頁，再點開。 → 還是那一盤、點過的一模一樣。
- `am15` **［護理端→病人端］** 點到一半，在護理端把這位病人換到另一台平板，在新平板點開連點成畫。 → 還是那一盤、下一個號碼一樣。
- `am16` **［病人端→開發機］** 📱 🛠 開一盤，點到一半放著超過 30 秒再點完；再開一盤一口氣點完。看 `connect_dots_boards` 最新兩列。 → 第一盤 `interrupted` 是 1、`max_gap_ms` 超過 30000；第二盤是 0；兩盤都有 `completion_ms`、`session_minute`、`layout_code` R1、`path_tenths` 在 720～800；表裡沒有血壓、體重、脫水量的欄位。
- `am17` **［開發機］** 🛠 看 `am8` 那一盤在 `connect_dots_taps` 的三下。 → `kind` 分別是 WRONG（`expected_no` 4、`touched_no` 9）、REPEAT（`touched_no` 2）、EMPTY（`touched_no` 空）；`x`、`y`、`distance_px`、`interval_ms` 都有值。

## §29.4 護理端

- `am18` **［護理端］** 🖥 選單 →「病人詳細資訊」→ 選 `am10` 那位病人。 → 「最近幾次有沒有玩」那一格最上面一句「本月連點成畫 N 盤」（N 是這個月點完的盤數）；**沒有**完成時間、錯幾次、快慢、任何評估；只開「連點成畫」時這一頁照樣在。關掉開關再看一次，那一句不見。

## §29.5 給長者看

- `am19` **［人］** 📱 請兩三位長者看遊戲選單的圖示與名字「連點成畫」、點一盤。 → 記下看不看得懂名字、知不知道要從 1 開始點、點不點得到圓（之五第 8 節第 1 題）。
- `am20` **［人］** 同上，看點完揭開的圖。 → 記下同一張圖在相簿與這裡各出現一次是否在意（之五第 8 節第 2 題）。

## §29.6 自動化驗收

`npm run verify:iteration29`（不需要後端）：尺寸放得進 1280×800、一千個種子的版面（不重疊、連線不穿過別的圓、距離總和在範圍內、沒有保底版面）、點錯存檔不變、沒有計時與分數字樣、沒有聲音與動畫、先存本機再送、欄位與匯出登記、開關、揭開的圖都有圖檔、字型、圖示，加上介面檢查、零院外連線與迭代 8、14、21、22、23、27 的驗收。`npm run verify:iteration29:api`（要 Prisma，不需要開發機的後端）：在 repo 旁邊建全新的資料庫，腳本自己另起一個後端，走開關關著、玩完一盤、重送與衝突、換平板與中斷、本月幾盤。`verify:acceptance` 與全部回歸照樣通過。
