## 摘要

這一冊驗三件事（項次 `ak1`～`ak18`，自動化另跑 `npm run verify:iteration27`）：

- 平板轉成直的，畫面不跟著轉、倒過來架會轉正（外殼）

**外殼這一次沒有改版**：動手前讀外殼 repo，病人端與佈建兩個畫面從迭代 10 的第一版起就是感應式橫向（`sensorLandscape`），釘住的 v0.3.0 也是（實作規格書 4.27「實作結果」第一條）。所以 §27.1 驗的是**已經裝著的外殼**，不必重建 APK。

## §27.1 外殼：轉直不跟著轉

**開發手機的版面不算數**：手機鎖橫向之後短邊只有三百多 px，字會縮到下限、可能要捲。這一節在手機上只看**轉不轉**，版面只以 1280×800 驗（§27.2）。

- `ak1` **［病人端］** 📱 平板（或開發手機）的系統設定**開著自動旋轉**，病人端開著首頁，平板橫著拿。把平板轉成直的。 → 畫面**不跟著轉**：還是橫的排法（側著看），沒有閃一下、沒有重新載入。
- `ak2` **［病人端］** 📱 再轉回橫的，接著整個倒過來拿（另一個橫向）。 → 畫面**轉正**（兩個橫向都可以）；轉的那一下不會跳回首頁、不會掉出螢幕固定。
- `ak3` **［病人端］** 📱 回到設定畫面（佈建），平板轉直；按「掃描 QR code」，掃描畫面開著時也轉直一次。 → 佈建畫面不跟著轉；掃描畫面停在開啟時的方向（橫的）。
- `ak4` **［護理端］** 📱 轉過幾次之後，看裝置管理那一台。 → 前景回報照常（那一台沒有變成「已跳出」）、外殼版本仍是 0.3.0、沒有「版本不相容」的標記。

## §27.2 病人端只有橫放

- `ak5` **［終端機］** 在專案根目錄搜尋病人端的樣式：`grep -rn "orientation" apps/patient-pwa/src`。 → **沒有任何結果**（`verify:iteration27` 第 2 步也擋）。
- `ak6` **［病人端］** 📐 1280×800，依序看首頁、按「我需要協助」、遊戲選單、透析小花園、點一格空地（選種子）、相簿封面、翻開相簿的一張、麻將開一桌。 → 每一頁**都不捲動**；求助區在最下面、位置每一頁都一樣；可點的都至少 64px。跟迭代 26 的截圖比（或 1021 週報的附錄），**除了牌桌的大小，排法一模一樣**。
- `ak7` **［病人端］** 📐 瀏覽器切成 800×1280 看首頁。（**只是確認，不算驗收**：正式版不會出現這個尺寸） → 畫面是橫放的那一種排法擠在直的視窗裡（字照短邊縮小、可能要捲）——**這是預期的**，直放的排法已經拿掉。
- `ak8` **［終端機］** `npm run demo:patient -- --screenshot demo.png --portrait`。 → `--portrait` 沒有作用，截出來的是 1280×800（迭代 27 拿掉直式）。

## §27.3 麻將的新級數

難度是悄悄調的（連續兩桌沒按提示就加一級、連續兩桌各按兩次以上提示就退一級），畫面上沒有級數。要直接看到新的兩級，**把那位病人的級數改掉**（只在開發機或 `demo:patient` 的資料庫做）：

- `ak9` **［資料庫］** 🛠 找到那位病人的麻將存檔：`SELECT id, snapshot FROM game_saves WHERE game_code = 'MAHJONG';`。把 `snapshot` 裡的 `"level"` 改成 `6`、`"current"` 改成 `null`（JSON 其他欄位不動）。病人端的瀏覽器先清掉站台資料裡的 IndexedDB（或換一個無痕視窗重新佈建）。
- `ak10` **［病人端］** 📐 1280×800，遊戲 → 麻將連連看 → 開一桌。 → 一桌 **4 列 × 12 行**、48 張；每張約 88×115px（開發者工具量，至少 80×104）；**整頁不捲動**、求助區照舊在最下面；牌桌左右只留一點邊。
- `ak11` **［病人端］** 看這一桌的排法。 → 一樣的兩張**大多不在隔壁**（不是每一對都左右排在一起——那是放不下時的保險，迭代 27 起不會再在發牌時出現）。
- `ak12` **［病人端］** 玩完這一桌（可以按提示）。 → 每一對都消得掉、不會卡死；完成只說「完成了」，**沒有「升級」「第幾級」**。
- `ak13` **［資料庫］** 🛠 照 `ak9` 把級數改成 `5`，再開一桌。 → 4 列 × 10 行、40 張；每張約 95×123px；不捲動。
- `ak14` **［資料庫］** 🛠 照 `ak9` 把級數改成 `4`、`"smooth"` 改成 `1`，開一桌 4×8，**不按提示**玩完，再開一桌。 → 那一桌 4×8 照舊玩得完；下一桌變成 4×10（舊的進度接著算，連續第二桌順利就加一級）。
- `ak15` **［病人端］** 有今日牌局時（療程中、這一班的那一桌還沒做），在級數 `6` 的病人開「今日牌局」。 → 今日牌局**照舊是 4×6**，不跟著變大。
- `ak16` **［資料庫］** 🛠 做完把那位病人的級數改回原本的值（或在 `demo:patient` 做，結束就丟掉）。

## §27.4 長者看 4×12 的牌

- 🛏 由長者在病床上實際看一桌 4×12：每張 88px 寬，比 4×8 的 95px 小一點，看不看得清楚、會不會覺得太滿。看不清楚就把最大的一級退回 4×10（`MAHJONG_LEVELS` 拿掉最後一級；**只能拿最後一級**，前面的編號不能動）。**這一項不打勾，結果寫進遊戲化分析 12.2**

## §27.5 自動化驗收

- `ak17` **［終端機］** `npm run verify:iteration27`（不需要後端，要先 `npm run build:shared`；外殼 repo 放在本系統旁邊的 `hd-kiosk-shell`，或設 `HD_SHELL_SRC_DIR`）。 → 七步全部通過（釘住的外殼 tag 鎖橫向、病人端沒有直放的樣式、新的兩級放得進 1280×800、每一級一千次發牌都可解而且不落到保險、舊存檔照樣玩得完、升降一級一級走、基準兩份沒有直放的寫法，再跑 `check:ui`、`check:ui:design`、`check:egress` 與迭代 8、14.5、16、17.4、22 的回歸）。找不到外殼 repo 時第 1 步只驗契約版本、其餘略過。
- `ak18` **［終端機］** `npm run verify:iteration16`、`npm run verify:iteration17-4`、`npm run verify:iteration22`。 → 都通過（這三支的直放與 4×8 檢查隨需求改了，實作規格書之一第二十一次）。
