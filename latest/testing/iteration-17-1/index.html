    迭代 17.1 手動測試 — 停用統一、把病人拖到平板、一鍵展示病人端¶

    《完整手動測試手冊》的分冊之一，對應《實作規格書》4.15.1 節與《迭代 17.1 修正紀錄》。共用的環境準備、啟動與疑難排解都在主手冊，這一冊只寫迭代 17.1 的部分。操作端色籤（護理端／病人端／終端機／資料庫）的意思見主手冊 §00。項次接著迭代 17 分冊編（aa37 起；17 用到 aa36），小版沿用那個迭代的字母。

    1007（迭代 17.2）起簡易版中間是平板，沒有床位圖與平板框：aa42、aa43、aa46、aa47、aa49 看的「床位圖」「平板框」改看中間的平板格；aa46 那種院方資料說正在透析、還沒有平板的病人改在病人框最上面；§17.1.3 的「平板拖到床上」改成點平板右上角的床號設床（《迭代 17.2 分冊》§17.2.1、§17.2.3）。配平板、復原、停用、改名、一鍵展示各節照舊有效。

    摘要¶

    這一冊驗四件事（項次 aa37～aa66，自動化另跑 npm run verify:iteration17-1）：

    • 簡易版把病人拖到平板就配好、平板自己跑到院方資料的那一床
    • 「鎖定」都叫「停用」、只在系統管理、正在透析的平板停用不了
    • 護理端看得到「公告與院內衛教」「結束與離院衛教」兩個新名字
    • 不必進院，一條指令就看得到病人透析到一半的平板畫面
    標記 意思
    🎬 一鍵展示 npm run demo:patient 開出來的那一套（模擬院方資料、另一個全新的資料庫，埠 8091、3100、5184、5183）。這一冊大多在這裡做，不碰平常開發用的資料庫
    🖥 開發機 平常的開發環境，npm run dev，沒有接院方資料
    📐 目標尺寸 病人端 1280×800 與 800×1280；護理站 1366×768 與 1920×1080（1014 起正式版固定橫放，800×1280 不必再驗）

    17.1.1 · 一鍵展示 🎬 📐¶

    • aa37 ［終端機］ npm run demo:patient，等它印出「準備好了」。 → 依序出現「展示用的資料庫：…\demo」「三個服務都起來了」「已把『模擬戊』（B1 床）配給平板 DEMO-01」「核准了 3 則院內衛教」，最後印出一個 http://localhost:5184/?serial=DEMO-01&key=… 的網址與護理端的網址。平常開發用的資料庫（.env 的 DATABASE_URL）沒有被動到：開發機的護理端看不到「模擬戊」。
    • aa38 ［病人端］ 瀏覽器開啟那個網址，開發者工具切到 1280×800。 → 不是問卷、是首頁：上方床號 B1 與進度條；中間血壓圖與脫水量圖各有一段曲線（約十個點，最新值標在線尾），「預計 2.9」虛線；五格數字各帶資料時間；底部跑馬燈正在跑一則院內衛教；求助按鈕在最下方。沒有捲軸。
    • aa39 ［病人端］ 切到 800×1280。（1014 起不必驗：正式版固定橫放；迭代 27 起不適用：直放的排法已拿掉） → 兩張圖上下排、五格數字排兩列，跑馬燈與求助區仍在下方，沒有捲軸，字與橫式一樣大。
    • aa40 ［病人端］ 開著不動，等 3 分鐘以上。 → 圖上自己多出點（模擬資料每 10 分鐘一筆，同步每 3 分鐘一次），右上角的資料時間跟著變。
    • aa41 ［終端機］ Ctrl+C 結束，再跑 npm run demo:patient -- --screenshot demo.png；再跑一次加 --portrait。（1014 起不必驗：正式版固定橫放；迭代 27 起不適用：--portrait 拿掉了） → 各自印出「截圖存在 …」後自動結束；兩張圖與 aa38、aa39 看到的一樣（跑馬燈停在跑到一半的位置）。結束後 8091、3100、5184 三個埠都沒有程式佔著。

    17.1.2 · 把病人拖到平板（接了院方資料）🎬 📐¶

    npm run demo:patient 開著（不帶 --screenshot）。護理端開 http://localhost:5183，用 .env 的最高權限帳號登入（第一次會要求改密碼，改的只是展示用的那一份），瀏覽器 1366×768。

    • aa42 ［護理端］ 看簡易版。 → 床位圖上有院方資料的病人；B1 有一個平板圖示，其他有病人的床沒有平板；右側病人框是今天要透析、還沒配平板的病人；平板框有 DEMO-02～04 三台。沒有「新增病人」、平板框底下沒有「停用」。
    • aa43 ［護理端］ 拿起病人框裡的一位（拖起來，或點一下）。 → 平板框裡的三台平板亮起來；床位不亮（病人不再拖到床位）；「下機」亮起，「候床」不亮（他還沒有平板）。
    • aa44 ［護理端］ 放到 DEMO-02 上（拖過去，或再點 DEMO-02）。 → 那位病人從病人框消失；DEMO-02 從平板框消失、出現在那位病人的床上（護理師沒有把平板拖上床）；下方出現「○○ → 平板 DEMO-02」與「復原」。平板圖示旁有「不在線上」的圖示（展示用的平板沒有真的開著），這是對的。
    • aa45 ［護理端］ 換一位病人放到 DEMO-03，8 秒內按「復原」。 → 病人回到病人框，DEMO-03 回到平板框。等下一次同步（或專業版系統管理「立即同步」）之後，那位病人照樣畫在他的床上（治療中）——復原不算護理師更正院方資料。
    • aa46 ［護理端］ 拿起床位圖上一位還沒有平板的病人（院方資料說他正在透析），放到 DEMO-04。 → 同 aa44：床位圖上的病人也拖得到平板上。
    • aa47 ［護理端］ 拿起平板框裡的平板（沒配病人的），看床位。 → 床位不亮（接了院方資料時，沒在用的平板放上床沒有意義）。
    • aa48 ［護理端］ 專業版 → 排班與指派。 → aa44、aa46 配的兩位顯示已指派那一台平板，指派者是你的帳號；稽核軌跡有一筆「平板 DEMO-02：未放床位 → ○ 床（配平板，跟著這次療程的床位）」。
    • aa49 ［護理端］ 1920×1080 再看一次簡易版。 → 沒有捲軸；平板框的格子寫得下序號或病人名字（太長的以省略號收尾）。

    17.1.3 · 把病人拖到平板（沒接院方資料）🖥¶

    開發機（.env 沒有 HOSPITAL_API_BASE_URL），npm run dev。床位清單裡至少有兩床、平板至少兩台已佈建。

    • aa50 ［護理端］ 簡易版：把一台平板拖到空床 A，再把病人框裡的一位拖到床 A 上的那台平板（床位格裡的平板圖示）。 → 那位病人畫在床 A；床位本身不收病人（拿著病人時床位不亮，只有平板亮）。
    • aa51 ［護理端］ 把另一位病人拖到平板框裡的一台平板。 → 病人從病人框消失；那台平板留在平板框裡、格子上寫病人的名字、框線加粗。接著把它拖到空床 B：病人出現在床 B。
    • aa52 ［護理端］ 把「＋」拖到平板框裡的一台平板，填姓名與病歷號送出。 → 表單長在平板框上（不是床位格上）；送出後同 aa51，格子上寫新病人的名字。按「復原」：解除綁定、取消排班，病人資料留著。
    • aa53 ［護理端］ 把 aa50 的病人拖到「候床」，再把他拖到另一台平板。 → 候床後回到病人框；再配一次照常。

    17.1.4 · 停用 🎬¶

    • aa54 ［護理端］ 專業版 → 裝置管理。 → 每一列的操作只有「解除佈建」（或「登記佈建」）；沒有「遠端鎖定」「解除鎖定」；說明文字最後一句指到系統管理的「平板停用」。整頁找不到「鎖定」兩個字。
    • aa55 ［護理端］ 系統管理 → 「平板停用」分頁。 → 列出佈建好的平板；正在服務病人的那幾列寫「使用中（病歷號）」、操作欄寫「先下機才能停用」，沒有停用按鈕；空著的有「停用」。
    • aa56 ［護理端］ 停用一台空著的平板（要再按一次「確定停用」）。 → 「平板 ○○ 已停用」；那一列變成「已停用」、按鈕變成「解除停用」。回簡易版：那台平板不在平板框、也不在任何一床。
    • aa57 ［終端機］ 對一台正在服務病人的平板直接打停用端點（繞過畫面）：curl -X POST http://localhost:3100/api/devices/<平板 id>/mdm/lock -H "Authorization: Bearer <權杖>"。 → HTTP 409，「這台平板正在服務病人，不能停用。請先下機或解除配對」。
    • aa58 ［護理端］ 解除停用 aa56 那一台（按了就做，不必確認）。 → 回簡易版：它回到平板框，可以配病人。
    • aa59 ［護理端］ 稽核軌跡，動作篩「停用平板」「解除停用平板」。 → aa56、aa58 各一筆，名稱是「停用平板」「解除停用平板」，停用那一筆寫了從哪一床拿下（若原本在床上）。
