    迭代 16 手動測試 — 病人端「本次透析」面板與跑馬燈¶

    《完整手動測試手冊》的分冊之一，對應《實作規格書》4.14 節。 共用的環境準備、啟動與疑難排解都在主手冊，這一冊只寫迭代 16 的部分。 操作端色籤（護理端／病人端／終端機／資料庫）的意思見主手冊 §00。 項次用 z（迭代 15 用到 y47）。

    1006（迭代 17.1）起：z4、z14 的「把平板拖到病人身上」改成「把病人拖到平板上」（《迭代 17.1 分冊》§17.1.2）。不想自己準備模擬院方資料與平板，npm run demo:patient 一條指令就開出一台已經配給透析中病人的平板（§17.1.1）。

    這一冊驗一句話：病人端首頁中間那一區不再輪播，改成常駐的「本次透析」面板——血壓與脫水量兩張折線圖加五個數字， 病人不必碰螢幕就跟著院方資料更新；底部一條跑馬燈，「標題：內容」整則慢慢跑過，不必點、也點不開。 面板只呈現量測值：沒有紅色、沒有警戒線、沒有正常範圍。規則的真本是《介面設計基準》2.5。

    標記 意思
    🖥 開發機 平常的開發環境，npm run dev，加上模擬院方 API（npm run dev:hospital-sim）
    👵 長者試看 至少三位 65 歲以上的人，在病床的距離看跑馬燈（驗收 10）。院內還沒機會時先找同齡的人
    📱 實機 目標平板（10 吋，型號待 Q-33）。型號定了再做

    16.1 · 準備 🖥¶

    • z1 ［終端機］ 照迭代 15 分冊 y1、y2 開模擬院方 API、後端設好位址，npm run dev。
    • z2 ［護理端］ 專業版 → 系統管理 → 功能開關，找「病人端畫面」那一組。 → 有「病人端『本次透析』面板」（開啟）與「病人端跑馬燈」（關閉）兩個；沒有「輪播第一層／第二層／第三層」（1005 停用，切換紀錄在稽核軌跡裡照樣查得到）。
    • z3 ［護理端］ 專業版 → 系統管理 → 營運參數。 → 有「跑馬燈速度」120 字／分鐘、「跑馬燈每一則開頭靜止」3 秒、「跑馬燈兩則之間的空白」5 秒； 閒置門檻改名為「任務畫面閒置多久自動回首頁」；沒有「每張輪播卡片的停留時間」與「細節頁自動退回的時間」。
    • z4 ［護理端］ 簡易版：把那台開著的病人端平板拖到「模擬乙」（進行中那一組）身上（配平板）。 → 一個抓取週期內平板自動進入這次療程（迭代 15 y11 同一件事）。

    16.2 · 面板（驗收 3、5、8）🖥¶

    • z5 ［病人端］ 看首頁。 → 三區：上面是床號與療程進度；中間是「本次透析」——左邊「血壓」、右邊「脫水量（公斤）」兩張折線圖，下面一列五格數字；最下面是求助區。
    • z6 ［病人端］ 看血壓圖。 → 兩條線同色（深靛藍），線尾各有一個大圓點與數字（上面是收縮壓、下面是舒張壓），沒有圖例； 圖的右上角是最後一筆的時間（今天的只寫時分）；底下只在兩端標時間（透析開始、預計結束）。
    • z7 ［病人端］ 看脫水量圖。 → 一條從左下長起的線，線尾標著目前累計的公斤數；上方一條灰色虛線，左端寫「預計 2.9」這類字——那是設定脫水量。
    • z8 ［病人端］ 看五格數字。 → 脈搏（次／分）、透析前體重、理想體重、相差、目標脫水量（公斤，小數一位）；每一格底下都有資料時間。 相差寫 +2.4 這類，沒有「多」「少」「偏高」，沒有顏色、沒有橫條。理想體重不是今天的，時間前面會有月日。
    • z9 ［病人端］ 從頭到尾掃一遍畫面。 → 沒有姓名、沒有病歷號（床號在上面那一區）；沒有靜脈壓、血流速、透析液、體溫、肝素、透析器、血管通路、低血壓預測機率。
    • z10 ［病人端］ 瀏覽器開發者工具 → Network，找 device/home 那一筆的回應。 → panel 底下只有 startedAt、expectedEndAt、bloodPressure、ultrafiltration、plannedUltrafiltrationMl、numbers 六樣； 不顯示的東西根本不在回應裡，不是送來再藏。

    16.3 · 不碰螢幕，曲線自己多一點（驗收 1）🖥¶

    • z11 ［病人端］ 數一數血壓圖目前有幾個點，然後不要碰平板。
    • z12 ［護理端］ 等模擬資料過了 15 分鐘的下一筆紀錄時間，或在專業版「院方資料同步」卡片按「立即同步」。 → 病人端在一個抓取週期內（預設 3 分鐘；按立即同步就是當下）自己多出一個點，圖右上角的時間跟著變；整個過程沒碰平板。

    16.4 · 院方不通、剛上機、讀到 0（驗收 5）🖥¶

    • z13 ［終端機］ 把模擬院方 API 那個視窗 Ctrl+C 停掉，等兩個抓取週期。 → 病人端的圖與數字都還在，時間還是原本那一筆的時間（不是此刻），沒有變空白；護理端出現「院方資料已 N 分鐘未更新」（迭代 15 y30）。 做完再把模擬院方 API 開回來。
    • z14 ［護理端］ 把病人端平板配給「還沒開始」那一組的一位，等模擬資料的透析開始。 → 剛接上時兩張圖只有框與標題，沒有空白的座標軸、沒有兩端的時間；第一筆量測進來才開始畫。
    • z15 ［終端機］ 用迭代 15 分冊的方法（__sim/scenario 指定的列）讓某一筆紀錄的血壓與累積量是 0，按立即同步。 → 那一筆不畫（線直接連到下一個有值的點）；理想體重是 0 的病人，「理想體重」與「相差」兩格整格不出現。 也可以直接跑 npm run verify:iteration16:api，它的步驟 2、3 就是這一項。

    16.5 · 不判讀（驗收 4）🖥¶

    • z16 ［病人端］ 看整個首頁。 → 紅色只有最下面的求助按鈕；圖上沒有警戒線、沒有正常範圍的色帶、沒有 Y 軸刻度與格線；唯一的橫線是脫水量圖的「預計」虛線。
    • z17 ［終端機］ npm run check:ui:design → 「面板不做判讀」一組全過：線的顏色不是任何一種語意色也不偏紅、面板元件與樣式沒有引用語意色、原始碼沒有警戒線一類的字樣。

    16.6 · 不捲動、字級（驗收 2）🖥 📱¶

    • z18 ［病人端］ 開發者工具切到裝置模式，尺寸設 1280×800，重新整理。 → 整頁沒有捲軸；兩張圖左右並排、五格數字一列、跑馬燈一行、求助區在最下面，都看得完整。
    • z19 ［病人端］ 尺寸設 800×1280。 → 整頁沒有捲軸；兩張圖上下疊、數字分兩列（3＋2）；字的大小與橫放時一樣大。
    • z20 ［病人端］ 開發者工具量字級（Computed → font-size）。 → 線尾的數字與五格的數值 ≥ 36px；圖的標題、資料時間、兩端時間 ≥ 20px；跑馬燈 ≥ 40px（基準 4.2）。
    • z21 ［病人端］ 📱 型號確定後在實機上重做 z18～z20（迭代 14.5 分冊 x150 同一件事）。

    16.7 · 跑馬燈（驗收 6、11）🖥¶

    • z22 ［護理端］ 專業版「跑馬燈內容」頁上架一則公告：標題「國慶日停診」，內容「10 月 10 日停診一天，當天的透析改到 10 月 9 日，時間不變。」 （1005 迭代 17 起要上架就是「寫好存成待核准、再按核准」，或核准一則隨版本帶入的衛教草稿，見迭代 17 分冊 §17.2。）
    • z23 ［護理端］ 功能開關把「病人端跑馬燈」開啟，核准依據寫「手動測試，速度未經長者試看」。 → 開得起來（開啟條件是長者試看過，系統驗不到，所以把關在核准依據；稽核軌跡記下這句話）。
    • z24 ［病人端］ 看面板最下面，計時。 → 出現一行「國慶日停診：10 月 10 日……」，標題是粗體；先靜止約 3 秒，再等速往左移，直到整則離開畫面； 接著空白約 5 秒，換下一則（只有一則時再出現同一則）。移動平滑、不跳格、不閃爍、不變色、沒有聲音。 照預設速度，這一則從出現到離開約半分鐘。
    • z25 ［病人端］ 跑馬燈在跑的時候點它、點住不放、在上面滑。 → 什麼都沒發生：沒有跳出任何東西、跑馬燈不停也不重來。
    • z26 ［病人端］ 跑馬燈在跑的時候按「我需要協助」。 → 求助照常；求助區的位置與大小與沒有跑馬燈時一模一樣，跑馬燈的字一個都沒有落進求助區（截兩張圖比對）。
    • z27 ［護理端］ 簡易版把那則公告的內容卡拖到另一床。 → 這台平板的跑馬燈在下一次取資料（最多一分鐘）後不再播它。
    • z28 ［護理端］ 把所有在架上的衛教與公告下架。 → 病人端最多一分鐘後跑馬燈整條不見，不留一條空白；面板往下長滿那一塊。

    16.10 · 長者看跑馬燈的速度（驗收 10）👵¶

    速度不是開發端說了算（SRS FR-P10）。這一節做完、三題都過，才能在院內開啟跑馬燈；沒做完之前，院內的「病人端跑馬燈」開關保持關閉。

    • z36 👵 找至少三位 65 歲以上的人（首選透析病人，Q-31 第 6 題；院內還沒機會時先找同齡的人）， 平板架在病床邊的支架上（視距約 40～70 公分），請他們平躺或半躺。
    • z37 👵 開啟跑馬燈，讓每一位看完至少三則（預先上架三則長短不同的內容，標題 12 字、內容 60 字以內）。
    • z38 👵 逐人問三題，照下表記下來（只記代號與年齡層，不記姓名）：
    代號 年齡層 姿勢 速度（字／分鐘） 看得清嗎 跟得上嗎 看了累不累、煩不煩
    A 120
    B 120
    C 120
    • z39 👵 任一題有人說不行：營運參數把速度調慢（例如 120 → 90），三位重看一次，直到三題都過。 開頭靜止與兩則間隔若有人覺得太趕，一樣在營運參數調。
    • z40 ［護理端］ 三題都過之後，把最後採用的速度在營運參數再存一次（值不變也可以）， 修改理由寫試看結果，例如「1012 三位長者（70、74、81 歲）半躺看三則，每分鐘 90 字三題都過」——這就是速度的依據，稽核軌跡裡查得到。 然後才開啟「病人端跑馬燈」，核准依據寫同一句。
