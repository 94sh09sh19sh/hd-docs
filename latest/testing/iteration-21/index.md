# 迭代 21 手動測試 — 遊戲化之二：透析小花園、送花、匿名彙總

> 《[完整手動測試手冊](https://94sh09sh19sh.github.io/hd-docs/latest/testing/manual-test-guide/index.md)》的分冊之一，對應《實作規格書》4.21 節。 共用的環境準備、啟動與疑難排解都在主手冊，這一冊只寫迭代 21 的部分。 操作端色籤（**護理端**／**病人端**／**終端機**／**資料庫**）的意思見主手冊 §00。 項次用 `ae`（實作規格書 4.0.5：21 用 `ae`），從 `ae1` 起。

**這一冊驗六件事**： 三個開關全關時一切跟迭代 17.7 一樣、小花園帶著送花； 花園怎麼種、怎麼長（不枯、不倒退、不能加速，養分與答案無關）； 存檔跟著病人走、斷線照樣能玩； 送花到護理站的花瓶（有求助時讓位）； 同一班的共同花園（只看得到花、跨班的病人、跨月）； 遊戲中求助照常、任務時點到了先做任務。 花的清單與畫法照《[透析中的遊戲化之二：小花園的植物](https://94sh09sh19sh.github.io/hd-docs/latest/notes/dialysis-gamification-garden/index.md)》。

**前置**：一台已佈建的平板（或瀏覽器開病人端）、一位合成病人；一般護理師與護理長帳號。 三個開關在系統管理 → 功能開關的「病人平板的遊戲化」那一組。 花要好幾次療程才開：測試時替同一位病人在**之前的日期**多排幾班（排班與指派 → 建立排班，日期選上個月），點開花園時就照療程次數長大——**看的是來透析幾次，不是點開幾次**。

## §21.1 三個開關與連動

- `ae1` **［護理端］** 系統管理 → 功能開關。 → 「病人平板的遊戲化」那一組**六列**：迭代 20 的三列，加上透析小花園、送花、病人之間的互動（三個都是關）。畫面上沒有英文識別字。麻將連連看、記憶相簿**還沒有開關**。**1011 迭代 22 起**這一組多麻將連連看、狀態評估彙整兩列（共八列，見迭代 22 分冊 `af1`）；迭代 21 剛做好時是六列。
- `ae2` **［病人端］** 📐 三個都關著：看首頁、做一次問卷與衛教。**［護理端］** 看常駐總覽螢幕、專業版病人趨勢。 → 跟迭代 17.7（與迭代 20）一樣：首頁基本資訊區**沒有遊戲圖示**；總覽螢幕沒有花瓶；病人趨勢沒有「送給護理站的花」。
- `ae3` **［護理端］** 小花園關著時，試著開「送花」。 → 擋下：「要先開透析小花園」。
- `ae4` **［護理端］** 開「透析小花園」（寫理由）。 → 「送花」**跟著開**。到稽核軌跡看：兩筆開啟，送花那一筆的理由寫「隨透析小花園開啟（小花園的核准依據：…）」，操作者是你。
- `ae5` **［護理端］** 單獨關「送花」，再開回來；然後關「透析小花園」。 → 單獨關送花時花園照常；關小花園時送花**跟著關**，稽核寫「隨透析小花園關閉」。**［終端機］** 小花園關著時打 `GET /api/device/games/garden` 回 404「此功能未啟用」。做完把小花園與「病人之間的互動」開起來。

## §21.2 種、澆水、養分、長大

- `ae6` **［病人端］** 📐 首頁基本資訊區多一個遊戲圖示（手把）。點它。 → 遊戲選單：「透析小花園」，「現有功能的小幅遊戲化」開著時還有「我的衛教小本子」。點透析小花園：3×4 十二格空地，右邊（直放時在下面）是門口。**整頁不捲動、求助區在原位**。
- `ae7` **［病人端］** 點一格空地。 → 三個種子包：樹上開的花、田裡開的花、庭院與水邊的花。選「樹上開的花」→ 回到花園，那一格是剛種下的種子。**第一次種**之後開出來的會是梅花（最熟的那一種）。
- `ae8` **［病人端］** 點門口的「澆水」。 → 剛種下的那一棵**當場發芽**。「澆水」消失（這次透析的那一份用掉了），**沒有任何動畫、聲音**。
- `ae9` **［病人端］** 送出透析前問卷（全部答「沒有」），回到花園。 → 門口多一個「養分」（透析前問卷的圖示）；點了之後植物再長一點、按鈕消失。換一位病人、全部答「有」再做一次：一樣有那一份養分（**與答案無關**）。同一次透析再送一次問卷：**不會再多一份**。
- `ae10` **［護理端］** 替這位病人在上個月多排三班。**［病人端］** 回首頁再點開花園（不必做任何事）。 → 那一棵長到開花：格子變成加粗的綠框。點它：大圖、花名「梅花」、一句「冬天開的花，越冷越開」，底下「送給照顧我的護理師們」「種到大家的花園」。
- `ae11` **［病人端］** 把十二格都種滿。 → 門口底下一句「花園滿了，可以把開好的花送出去或種到大家的花園，再種新的」。**沒有紅點、沒有數字、沒有任何提醒**。
- `ae12` **［病人端］** 點右上角的圖鑑（相簿圖示）。 → 「台灣花卉圖鑑」：開過的花各一格，花、名字、一句說明；一頁六種，多了就翻頁。

## §21.3 存檔跟著病人走與斷線

- `ae13` **［護理端］** 解除這位病人的平板，排他的下一班、配**另一台**平板。**［病人端］** 在另一台點開花園。 → 就是自己的花園：同樣幾棵、同樣的位置，而且多長了一次療程的份。
- `ae14` **［病人端］** 拔掉網路（開發者工具切到離線），種兩棵、澆水。 → 照樣種得下去、澆得了水；開好的花那一頁**沒有**「送給照顧我的護理師們」「種到大家的花園」兩顆，寫「連上網路之後，可以送給護理師或種到大家的花園」。
- `ae15` **［病人端］** 接回網路，等幾秒，重新整理。 → 剛剛那幾步都在。**［資料庫］** `game_events` 這位病人最後幾筆的 `seq` 連續、照做的順序。
- `ae16` **［終端機］** 用平板的權杖對 `POST /api/device/games/garden/events` 送一筆 `seq` 比現在小的。 → 回 `conflict: true` 與伺服器那一份，不套用。

## §21.4 送花與花瓶

- `ae17` **［病人端］** 點一朵開好的花 → 「送給照顧我的護理師們」。 → 一頁：那朵花與「花已經放進護理站的花瓶了」。回花園：那一格變回空地。圖鑑裡那種花**還在**。
- `ae18` **［護理端］** 📐 常駐總覽螢幕（1920×1080），**沒有待處理的求助時**。 → 右下角「今天的花瓶」：花的圖加床號（「A5 床・梅花」）。新的一朵**直接出現**、不閃、不出聲。**沒有病人姓名、沒有收花的護理師**。
- `ae19` **［病人端］** 按一次求助（任一類）。**［護理端］** 看總覽螢幕。 → 有待處理的求助時花瓶**整塊不見**（求助永遠優先）；求助處理完花瓶回來。
- `ae20` **［護理端］** 📐 專業版病人趨勢 → 選這位病人，捲到最下面。 → 一格「送給護理站的花」：「今天送了一朵梅花」。「護理師回貼圖」開著時有一顆「謝謝你的花」（可以不回）；按下去那一格變成「謝謝你的花」與誰回的。**哪裡都沒有未讀數或提醒**。
- `ae21` **［資料庫］** 看 `flower_gifts` 的欄位。 → 只有病人、療程、哪一種花、時間；**沒有任何護理師欄位**。隔天（跨日）再看總覽螢幕：花瓶是空的。

## §21.5 共同花園

- `ae22` **［病人端］** 📱📱 第一台：點開好的花 → 「種到大家的花園」。 → 「這個月○班的花園」（○是這一次療程的班別），淡淡的月份背景；空地是綠框的格子，上面寫「點一格空地，把○○種下去」。點一格：種下去，那一格馬上出現花，上面寫「種好了」。自己花園的那一格變空地。
- `ae23` **［病人端］** 📱📱 第二台（同一班的另一位病人）點開「大家的花園」（花園右上角的樹圖示）。 → **看得到剛剛那一朵**。整個畫面**沒有人數、沒有床號、沒有是誰種的**。
- `ae24` **［病人端］** 📱📱 兩台各點一朵開好的花進「種到大家的花園」，**盡量同時點同一格**。 → 只有一台種下；另一台寫「這一格剛剛有人種了，換一格吧」，花還在自己的花園。
- `ae25` **［資料庫］** 看 `shared_garden_plots` 的欄位；再看 `game_events` 裡 `action = SHARE` 的那幾筆。 → 格子只有哪一座、第幾格、什麼花、時間，**沒有病人欄位**；誰種的只在 `game_events`。
- `ae26` **［資料庫］** 把這一班這個月剩下的空格都填上花（直接新增 `shared_garden_plots`），\*\*［病人端］\*\*再種一次。 → 「這個月○班的花園種滿了，下個月會多一些位置」，花留在自己的花園。做完把填的那幾列刪掉。

## §21.6 跨班的病人與跨月

- `ae27` **［病人端］** 同一位病人今天先上早班（配平板）種一朵到大家的花園；下機，再排午班、配平板種一朵。 → 早班那一次看到、種的是「這個月早班的花園」；午班那一次只看得到「這個月午班的花園」，**看不到早班當月的**。**［資料庫］** 兩筆 `SHARE` 的 `shared_garden_id` 一筆是早班那一座、一筆是午班那一座。
- `ae28` **［終端機］** 午班時對 `POST /api/device/games/garden/shared` 在請求裡多帶 `"shift": "MORNING"` 種一朵。 → 照樣種進**午班**（前端送來的班別被忽略，也不會因此出錯）。
- `ae29` **［資料庫］** 新增一列上個月晚班的 `shared_gardens`（`status = OPEN`、格數 18、背景 `M09-A`）並填滿 18 格；**［病人端］**晚班的病人點開大家的花園。 → 上個月那一列變成 `ARCHIVED`、背景照舊；這個月晚班是兩座各 18 格（上一座／下一座翻）——全部種滿就 ×1.5、超過一座 24 格就分座。圖鑑 → 以前的花園：只列這位病人**上個月去過的班別**。做完把新增的列刪掉。

## §21.7 遊戲中的求助與任務

- `ae30` **［病人端］** 📐 在花園裡按「我需要協助」。 → 求助畫面照常出現（位置、大小與首頁一樣）；送出後回首頁，再點開花園，花園跟剛剛一樣。
- `ae31` **［護理端］** 把「心情問卷出現時點」改成 0。**［病人端］** 在花園裡等下一次輪詢。 → 心情問卷**全螢幕出現**；做完之後出現一頁「回到剛剛的遊戲？」：「回到透析小花園」「回首頁」。點回到透析小花園：就是剛剛的花園。另外：花園擺著三分鐘不動才回首頁（不是一般任務畫面的 60 秒）。做完把時點改回。

## §21.8 長者試看

- `ae32` **［病人端］** 🛏 請一位長者在病床上看花園、開好的花、圖鑑、大家的花園。 → 問四題：認得出是什麼花嗎、會不會覺得是給小孩玩的、背景會不會太搶、知道下一步按哪裡嗎。記下回答與平板的型號、亮度；回答寫進植物子文件第 11 節與遊戲化分析 12.2 的試辦紀錄。

## §21.9 自動化驗收

- `ae33` **［終端機］** `npm run verify:iteration21`（不需要後端）；後端開著，再跑 `npm run verify:iteration21:api`。 → 兩支都全部通過（前一支會再跑 `check:ui`、`check:ui:design`、`check:egress`；後一支結束時四個開關改回原狀，這次種進共同花園、直接寫進資料庫的列都拿掉。驗收用的平板、病人留著、療程取消，與其他驗收腳本相同）。
