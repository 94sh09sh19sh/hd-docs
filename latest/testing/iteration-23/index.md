# 迭代 23 手動測試 — 遊戲化之四：老台灣記憶相簿

> 《[完整手動測試手冊](https://94sh09sh19sh.github.io/hd-docs/latest/testing/manual-test-guide/index.md)》的分冊之一，對應《實作規格書》4.23 節。 共用的環境準備、啟動與疑難排解都在主手冊，這一冊只寫迭代 23 的部分。 操作端色籤（**護理端**／**病人端**／**終端機**／**資料庫**）的意思見主手冊 §00。 項次用 `ag`（實作規格書 4.0.5：23 用 `ag`），從 `ag1` 起。

**這一冊驗六件事**： 開關全關時一切跟迭代 17.7 一樣、上架中不到 60 張時開不了； 翻一次相簿（一張大圖配三個大字選項、不論對錯都翻出答案、三個回憶小貼紙、每張都跳得過、沒有任何「錯」）； 出卡的順序與存檔跟著病人走、斷線照樣能看； 共同記憶的人數句照最低人數門檻，「想起某個人」不算； 護理端「可以聊的話題」與圖卡管理（改字就是新的一版、下架隨時可以）； 圖卡逐張檢查與長者試看。 圖卡的主題、避開的題材與每一張的文字在子文件《[透析中的遊戲化之三：記憶相簿的主題](https://94sh09sh19sh.github.io/hd-docs/latest/notes/dialysis-gamification-album/index.md)》。

## §23.1 開關與預設圖卡

- `ag1` **［護理端］** 系統管理 → 功能開關。 → 「病人平板的遊戲化」那一組**九列**（九個到齊）：最後一列是「老台灣記憶相簿」（關）。那一列的開啟條件寫「上架中的圖卡 60 張、6 個主題都有」。畫面上沒有英文識別字。
- `ag2` **［病人端］** 📐 九個遊戲化開關裡，除了「現有功能的小幅遊戲化」都關著：看首頁。**［護理端］** 看「更多」選單與系統管理 → 內容與選項。 → 跟迭代 17.7 一樣：首頁沒有遊戲圖示；「更多」沒有「病人詳細資訊」；內容與選項的分頁**沒有「記憶相簿的圖卡」**。**［終端機］** 打 `GET /api/content/album-cards` 回 404。
- `ag3` **［資料庫］** 看 `album_cards` 與 `album_card_versions`。 → 60 張、每張一版（第 1 版，建立者是空的＝系統寫入）。**［護理端］** 稽核軌跡動作選「寫入記憶相簿的預設圖卡」有一筆。重新啟動後端：**不會再多一筆、也不會多一版**。
- `ag4` **［資料庫］** 把任意一張的 `active` 改成 0（只為了這一項；做完改回）。**［護理端］** 開「老台灣記憶相簿」。 → 開不了，訊息寫「上架中的圖卡只有 59 張，要至少 60 張……才開得了」。改回 1 之後再開：開得起來，「更多」多一項「病人詳細資訊」（只開相簿也有），內容與選項多一個分頁「記憶相簿的圖卡」。

## §23.2 翻一次相簿

- `ag5` **［病人端］** 📐 點基本資訊區的遊戲圖示。 → 遊戲選單多「老台灣記憶相簿」（相簿圖示）。點它：相簿封面——標題、一句「一次幾張老東西，看看認不認得」、一顆大按鈕「翻開相簿」。**整頁不捲動、求助區在原位**。
- `ag6` **［病人端］** 點「翻開相簿」。 → 頂列五個圓點（第一個是實心的）；左邊（直放是上面）一張大圖、右邊題目「你家以前有沒有？」與三顆大字按鈕「有／沒有／不記得」，下面一顆「跳過這張」。**選項沒有配圖**；畫面上沒有計時、沒有分數。
- `ag7` **［病人端］** 點「有」。 → 立刻翻出名稱（電鍋）與一句說明；下面「想到什麼，可以點一下」與三個貼紙「我用過／我家也有／想起某個人」；右下角一顆「下一張」。沒有聲音、沒有翻牌動畫。
- `ag8` **［病人端］** 點「我家也有」，再點一次，再點一次。 → 點一下變成深綠底（選起來），再點一下取消；可以點一個、幾個或都不點。
- `ag9` **［病人端］** 按「下一張」，遇到「這是什麼？」的那一張，**故意選不是答案的那一個**。 → 照樣翻出名稱與說明；三個選項列在說明底下，**答案那一個用深綠的粗框框起來**，病人選的那一個**沒有任何記號**。畫面上**沒有「錯」「答錯」「不對」、沒有叉叉、沒有紅色**。
- `ag10` **［病人端］** 下一張按「跳過這張」。 → 直接換下一張，沒有任何追問。
- `ag11` **［病人端］** 看完五張（最後一張的按鈕是勾勾「完成」）。 → 回到相簿封面，上面一個完成色的框「這次的 5 張看完了」，下面多一句「已經翻過 N 張」（跳過的不算）。
- `ag12` **［病人端］** 📐 平板轉成直放（800×1280）重做 `ag6`～`ag9`。 → 圖在上、題目與選項在下，三個選項排成一列；翻開之後貼紙在下半部。**都不捲動**，字跟橫放一樣大。

## §23.3 出卡順序、存檔與斷線

- `ag13` **［病人端］** 連翻幾次，記下每一次的五張。 → 第一次的五張都是第一眼就認得的（電鍋、大灶、鐵馬、三輪車、有拉門的電視）；**同一次裡同一個主題最多兩張**；前十二次（60 張）**沒有重複**。
- `ag14` **［病人端］** 某一次的第一張跳過。之後繼續翻。 → 跳過的那一張要等**所有沒看過的都出完**才會再出現；同一張跳過兩次，之後就不再出現。
- `ag15` **［病人端］** 某一張點「想起某個人」。 → 60 張都看過、開始重來之後，那一張**不會主動再出現**。
- `ag16` **［病人端］** 看到第三張時按回首頁，再點進相簿。 → 直接回到剛剛那一次的第三張（不必再按「翻開相簿」）。
- `ag17` **［護理端］** 解除綁定，把同一位病人配到**另一台平板**（或另一班）。**［病人端］** 點進相簿。 → 還是剛剛那一次、從看到的那一張接著看。
- `ag18` **［病人端］** 拔掉網路，再看兩張；接回網路。**［資料庫］** 看 `album_responses`。 → 斷線時照樣翻得到、答得了（不顯示共同記憶）；接上之後兩張補送進來，`seq` 接續、沒有重複。
- `ag19` **［病人端］** 小花園也開著：這一次療程看完一次相簿，點開花園。 → 門口可以給「遊戲的養分」（只看了兩三張、還沒看完一次時沒有）。跳過的也算看過；**與選了什麼無關**。

## §23.4 共同記憶

- `ag20` **［病人端］** 📱📱📱 開「病人之間的互動」。同一班的病人 A、B、C 第一次翻開相簿，第一張（電鍋）都答「有」。病人 D 翻開第一張、答完。 → D 翻開答案之後，說明底下多一句「今天這一班有 3 個人家裡也有電鍋」。**沒有床號、沒有名字**；這一句**翻開答案之後才出現**。
- `ag21` **［病人端］** D 答「沒有」並點「想起某個人」。病人 E 翻開第一張。 → E 看**不到**那一句（沒說有的只有 1 人，會被認出來；點「想起某個人」也不算說有）。再有兩位答「沒有」或「不記得」之後，下一位看得到「今天這一班有 3 個人家裡也有電鍋」。
- `ag22` **［護理端］** 關「病人之間的互動」。**［病人端］** 再翻一張。 → 沒有那一句；相簿照樣完整。**［終端機］** 打 `GET /api/device/games/album/peers?card=RICE_COOKER` 回 404。

## §23.5 可以聊的話題

- `ag23` **［護理端］** 📐 一般護理師：更多 → 病人詳細資訊，選 `ag7`～`ag11` 那一位。 → 「最近幾次有沒有玩」多一欄「記憶相簿」（看了幾張）。下面一塊「可以聊的話題（記憶相簿）」：一列一個主題——看過幾張、說過家裡有的、用過的、想起某個人的（物件名）。**沒有答對率、沒有分數、沒有「錯」**。最下面一句「點了『想起某個人』的，病人願意說再聊，不追問」。
- `ag24` **［護理端］** 以社工帳號登入，看同一位病人。 → 看得到同一塊。**［護理端］** 有稽核權限的帳號看稽核軌跡，動作選「調閱記憶相簿的回應主題」：每一次選病人都有一筆（誰、哪一位病人）。

## §23.6 圖卡管理

- `ag25` **［護理端］** 📐 護理長：系統管理 → 內容與選項 → 記憶相簿的圖卡。 → 60 張一張一列：識別碼、主題、題型、名稱、選項（答案是粗體）、一句說明、第幾版、看過幾次、上架中。右上角可以只看某一個主題。**沒有新增、沒有刪除**。一般護理師看不到這一頁（端點 403）。
- `ag26` **［護理端］** 某一張按「改文字」：改說明，理由先不填。 → 那一列底下展開一整列輸入框；理由沒填「儲存」按不下去。填了理由儲存：版本變「第 2 版」。稽核軌跡「調整記憶相簿的圖卡」那一筆寫了改之前與改之後的字與理由。**［病人端］** 翻到那一張：翻開是新的說明。
- `ag27` **［護理端］** 「你家以前有沒有？」那種圖卡按「改文字」。 → 只有名稱與說明，沒有選項與答案。
- `ag28` **［護理端］** 某一張按「下架」，填理由確定。 → 狀態變「已下架」，平板之後不會再出這一張（已經翻開、還沒看完的那一次照樣看得完）。**開關照開著**；這時關掉開關，再開會因為只有 59 張而開不了（`ag4` 那一句）——重新上架之後才開得回來。做完把它重新上架。

## §23.7 圖卡逐張檢查與長者試看

- 🛠 照子文件第 6 節的表，把病人端 `src/assets/album/` 的 60 張逐張看過一次：沒有人（含剪影、手）、沒有商標與任何文字或數字、沒有第 3 節的題材、沒有紅色。（`ag29` 的腳本檢查白名單與顏色，**有沒有人、像不像要靠人看**）
- 🛏 請社工看主題與避開的題材、護理部看一句說明、長者在病床上實際翻一次：「這是什麼」認不認得、像不像給小孩玩的（子文件第 10 節）。**這一項不打勾，結果寫回子文件第 10 節**。

## §23.8 自動化驗收

- `ag29` **［終端機］** `npm run verify:iteration23`（不需要後端）；後端開著，再跑 `npm run verify:iteration23:api`。 → 兩支都全部通過（前一支實際跑出卡順序十二次與跳過、想起某個人的邊界、快照的格式與大小、門檻的組合，再跑 `verify:iteration23-2`、`check:ui`、`check:ui:design`、`check:egress`；後一支結束時六個開關改回原狀，改過的圖卡以資料庫改回。驗收用的平板、病人、帳號留著、療程取消，與其他驗收腳本相同）。
- `ag30` **［終端機］** `npm run verify:iteration23-1`、`npm run verify:iteration23-2`。 → 照樣通過（60 張的內容與圖檔沒有因為 23.3 而變）。
