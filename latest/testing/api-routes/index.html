    上層文件：《完整手動測試手冊》§09 · API 附錄（怎麼帶憑證、h1、h2 兩項仍在主手冊）

    收入方式：永久收入（1015 起）。路由表原本在主手冊 §09，整張搬來這裡，往後只在本頁維護。

    怎麼維護：新迭代加了端點就在下表補列，拿掉的加刪除線並註明哪個迭代拿掉；路由數照後端啟動時印出的清單重數（數 Mapped { 的行數），不要只累加。數字一改，下方說明、主手冊檔頭「對應版本」與 §09 第一段三處一起改。

    摘要¶

    • 主手冊 §09 路由表的永久收入（1015 起），往後只在本頁維護
    • 目前 221 條，逐條對齊後端啟動時印出的清單（數 Mapped { 的行數）；迭代 27 沒有增減
    • 每一列寫方法與路徑、需要的權限、說明；拿掉的端點加刪除線並註明哪個迭代拿掉
    • 新迭代加了端點就補列；數字一改，本頁說明、主手冊檔頭與 §09 第一段三處一起改
    • 怎麼帶憑證與 h1、h2 兩項仍在主手冊 §09

    表中各迭代的操作步驟分別在迭代 3～迭代 26 各分冊（索引見主手冊 §13）。本表逐條對齊後端啟動時印出的路由清單（目前 221 條；1018 迭代 27 沒有動到後端的路由，沒有增減；1018 迭代 26.3 加 6 條（/handlers）、26.2 加 1 條（可列印版），照清單重數過（Mapped { 221 行），與表一致；1018 迭代 25 加 4 條、照清單重數過（Mapped { 214 行），與表一致；1018 迭代 24.4 加 1 條、照清單重數過（Mapped { 210 行），與表一致；1011 迭代 23 加 6 條、照清單重數過（Mapped { 209 行），與表一致；1011 迭代 22 加 6 條、照清單重數過（Mapped { 203 行），與表一致；1010 迭代 21 加 8 條、照清單重數過（Mapped { 197 行），與表一致；迭代 20 加 8 條；迭代 19 加 23 條；迭代 18.1 加一條、迭代 18 加九條、迭代 17.8 加兩條；1010 迭代 18.1 收尾時照清單重數一次：之前寫的 146 條少算了 11 條，表裡也漏列迭代 15 的「確認下機」，已補上；1005 補齊迭代 10～17 新增的 22 條，1006 迭代 17.1 拿掉一條）；日後新增端點時，以那份清單為準回頭補這張表。

    GET /api/patient-detail/patients/:patientId/game-trends patient-detail:read （迭代 22）狀態評估彙整（讀的時候由固定算式算）；每一次調閱寫稽核（GAME_TREND_VIEWED）；「狀態評估彙整」關著時 404
    GET /api/patient-detail/patients/:patientId/album patient-detail:read （迭代 23）記憶相簿的回應主題（「可以聊的話題」：說過家裡有的、用過的、想起某個人的；沒有答對率）；每一次調閱寫稽核（ALBUM_TOPICS_VIEWED）；「老台灣記憶相簿」關著時 404
    GET /api/device/games/album 平板（Session Token） （迭代 23）相簿的存檔（還沒看完的那一次、序號）、上架中的圖卡、這一次的幾張（下架了也給）、伺服器排好的下一次；「老台灣記憶相簿」關著時 404；存檔格式不對 422
    POST /api/device/games/album/events 平板（Session Token） （迭代 23）看完一張（作答、貼紙、跳過；一次最多 50 張）：照序號套用、clientId 去重；序號接不上回 conflict；每一張寫 album_responses
    GET /api/device/games/album/peers?card= 平板（Session Token） （迭代 23）共同記憶的人數句：同一班說「有」或點「我家也有」的其他病人，照最低人數門檻，湊不到改這星期，再湊不到回 null；「想起某個人」不算；要「老台灣記憶相簿」與「病人之間的互動」都開著
    GET /api/device/games/album/collection 平板（Session Token） （迭代 24.4）相簿圖鑑「我的相簿」：照主題、照圖卡的固定順序，翻開過答案的每一張（目前那一版的名稱、說明、最後一次點的貼紙；「想起某個人」照收），還沒收到的格子是 null、連代號都不給；只算上架中的；沒有選了什麼與對錯。「老台灣記憶相簿」關著時 404
    GET /api/content/album-cards content:manage （迭代 23）記憶相簿的全部圖卡（目前的版本、上架狀態、看過幾次）；「老台灣記憶相簿」關著時 404
    PATCH /api/content/album-cards/:code content:manage （迭代 23）改名稱、說明、選項的字、答案（改了就是新的一版）或上架／下架；要理由、寫稽核（ALBUM_CARD_UPDATED）；代號不能改、沒有刪除
    GET /api/help-requests/:id/bedside patient:monitor （迭代 25.2）床邊前速覽：這一次求助、本次透析每一筆院方量測（讀到 0 的欄改成 null、全 0 的那一筆不送）、透析前與理想體重、目標與設定脫水量、每次透析一個值的設定、透析前問卷、本次與前 3 次療程的求助、待追蹤事項；只讀，不算確認通報；沒有預測、分級、正常範圍
    GET /api/nursing-records/help-candidates?treatmentSessionId= patient:monitor （迭代 25.3）「依求助建立」：這次療程已結案、還沒有記錄的求助
    POST /api/nursing-records/help-responses nursing-record:write （迭代 25.3）依一則已結案的求助建立求助處置記錄（規則同結案時自動建立的）；已經有一筆回 409、沒結案的回 400
    GET /api/handlers/candidates patient:monitor （迭代 26.3）名字名單：最近 12 小時被指名過的人（最多 6 位）與全部，都依姓名筆畫；不讀班表。整組 /handlers 跟著「獎勵制度」開關（關著時 404）
    POST /api/handlers/declarations patient:monitor （迭代 26.3）事後補選或更正處理者（原本已經有人的記成更正）；寫稽核
    POST /api/handlers/self-report patient:monitor （迭代 26.3）「我不在名單上」：姓名＋工作 ID；已經有帳號或名冊身分的直接指名那一位，沒有的建一筆待確認的名冊身分
    GET /api/handlers/roster nurse:approve （迭代 26.3）名冊身分與待確認的名冊身分（誰加的、被指名過幾筆）
    POST /api/handlers/roster nurse:approve （迭代 26.3）新增名冊身分（沒有密碼、登不進去）；工作 ID 已經有人回 409
    POST /api/handlers/roster/:id/decide nurse:approve （迭代 26.3）確認或不確認「我不在名單上」送來的；不能確認自己
    POST /api/nursing-records/:id/template nursing-record:write （迭代 25.3）求助處置草稿改套既有範本：事件時間與量測不動，D／S 段最前面留病人按下求助的那一句；寫稽核（NURSING_RECORD_TEMPLATE_APPLIED）；已簽核的回 409
