## 17.2.1 · 中間是平板、右上角是床號 🎬 📐

`npm run demo:patient` 開著。護理端開 `http://localhost:5183`，用 `.env` 的最高權限帳號登入（第一次會要求改密碼，改的只是展示用的那一份），瀏覽器 1366×768。

- `aa67` **［護理端］** 看簡易版。 → **中間是四格平板** DEMO-01～04，依序號排；右邊只有兩個框：病人（上）、公告與院內衛教（下）。**沒有平板框、沒有護理師框、沒有床位圖**。 DEMO-01 是實線框、左上是治療中的折線圖示，**右上角寫 B1**（床的圖示加床號），格子裡是「模擬戊」與進度條； DEMO-02～04 是虛線框、左上畫平板（滑鼠停著寫「空著」），**右上角沒有床號**；三台都帶「不在線上」的圖示（展示用的平板沒有真的開著）。
- `aa68` **［護理端］** 拿起病人框的第一位病人（拖起來，或點一下）。 → DEMO-02～04 **整格**亮起來（虛線外框），DEMO-01 不亮（正在服務模擬戊）；「下機」亮起（他正在透析），「候床」不亮。
- `aa69` **［護理端］** 放到 DEMO-02（拖過去，或點 DEMO-02 任何一處）。 → 那位病人從病人框消失；**DEMO-02 變成實線框、格子裡是他的名字，右上角馬上出現院方資料的床號**（護理師沒有選床）；下方出現「○○ → 平板 DEMO-02」與「復原」。 四格的位置都沒有動。
- `aa70` **［護理端］** 換一位放到 DEMO-03，**8 秒內**按「復原」。 → DEMO-03 回到虛線、右上角的床號消失；病人回到病人框，**位置照順序**（見 §17.2.2），不是排到最後。
- `aa71` **［護理端］** 把 DEMO-02 上的病人拖到「候床」，再把他拖回 DEMO-02。 → 候床後回到病人框、DEMO-02 右上角的床號消失；再配一次照常，床號又出現。
- `aa72` **［護理端］** 把公告與院內衛教框的草稿卡拖到 DEMO-01；另一張已核准的內容拿起來看 DEMO-03。 → 草稿卡放到 DEMO-01 即核准、只在 B1 播（格子底下出現喇叭圖示加 1）；拿著內容時**沒有床號的 DEMO-03 不亮**，DEMO-01、02 亮。
- `aa73` **［病人端］** 開 `aa37` 那個病人端網址，按「我需要協助」送一則緊急的。回護理端看。 → 上面一條紅框寫「**B1** 胸悶胸痛」之類（床號，不是平板序號）；DEMO-01 整格紅底、八角形。點一下確認、再選一個處理方式： 下方復原列寫「**B1 床結案**：…」。
- `aa74` **［護理端］** 以一般護理師的帳號登入（系統管理 → 帳號審核建一個、核准），看簡易版。 → 一樣看得到中間四台平板（17.1 時一般護理師看不到平板框）；拿起病人一樣能配。
- `aa75` **［護理端］** 1920×1080 再看一次。 → 沒有捲軸；右上角的床號與左上的序號都完整（序號太長的以省略號收尾，床號不被擠掉）。

## 17.2.2 · 病人框的順序與重新整理 🎬

接著上一節，`npm run demo:patient` 開著。

- `aa76` **［護理端］** 看病人框。 → **正在透析、還沒配平板的病人在最上面**，角落一個治療中的折線圖示；越晚開始的越上面（對照專業版排班與指派頁的開始時間）。 後面是還沒開始的，依姓名筆畫：第一個字筆畫少的在前（模擬資料的姓名都是「模擬」開頭，看第三個字：丁、子、己、丑…）。
- `aa77` **［護理端］** 看病人框左邊、人形圖示底下。 → 有一顆**雙箭頭繞圈**的按鈕（滑鼠停著寫「重新整理：立即抓一次院方資料，剛上機的病人排到最上面」）。
- `aa78` **［護理端］** 模擬院方資料的第三組（模擬壬、模擬癸、模擬子、模擬丑）在 `demo:patient` 啟動約 20 分鐘後開始，每 5 分鐘開始一位。 專業版排班與指派頁看得到他們的預計開始時間；**時間一到就回簡易版按重新整理**，不要等排程的 3 分鐘。 → 按下去按鈕先變灰、一兩秒後恢復；剛開始的那一位**立刻排到病人框第一個**，帶治療中的圖示。
- `aa79` **［護理端］** 系統管理 → 院方資料同步 → 最近幾次抓取。 → `aa78` 按的那一下有一筆抓取紀錄，與排程的那幾筆長得一樣。
- `aa80` **［終端機］** 讓模擬院方 API 一律回 503：`curl -X POST http://localhost:8091/__sim/scenario -H "content-type: application/json" -d "{\"mode\":\"down\"}"`，回護理端按重新整理。 → 上面出現一條「院方資料這次沒有抓到（…），畫面是上一次的資料」，8 秒後消失；病人框維持原樣。做完把 `mode` 改回 `live`。
- `aa81` **［護理端］** 讓一位沒有平板的病人過了預計結束很久（院方資料沒有結束體重）。 → 他在病人框的角落改標**待確認下機**的時鐘圖示；拖到「下機」，8 秒後送出、他從病人框消失。

## 17.2.3 · 沒接院方資料：點床號設床 🖥

開發機（`.env` 沒有 `HOSPITAL_API_BASE_URL`），`npm run dev`，用**有裝置管理權限**的帳號（護理站管理者以上）登入。

- `aa82` **［護理端］** 看簡易版。 → 中間是開發資料庫裡所有沒停用的平板；設過床的在右上角寫床號，沒設的只畫一個床的圖示。**病人框沒有重新整理的按鈕**（沒接院方資料）。
- `aa83` **［護理端］** 點一台平板右上角的床號（或床的圖示）。 → 格子上長出一排床號按鈕，目前那一床框線加粗；點另一床：右上角換成那一床、下方出現「平板 ○○ → ○ 床」與「復原」。按復原就換回去。
- `aa84` **［護理端］** 換成護理長帳號（沒有裝置管理權限）再看。 → 床號只是字，點了沒反應；平板照樣看得到、照樣能把病人拖上去配。
