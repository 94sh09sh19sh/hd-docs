# 迭代 26 手動測試 — 管理儀表板、獎勵制度與對外揭露的更新與修正

> 《[完整手動測試手冊](https://94sh09sh19sh.github.io/hd-docs/latest/testing/manual-test-guide/index.md)》的分冊之一，對應《實作規格書》4.26 節。 共用的環境準備、啟動與疑難排解都在主手冊，這一冊只寫迭代 26 的部分。 操作端色籤（**護理端**／**病人端**／**終端機**／**資料庫**）的意思見主手冊 §00。 項次用 `aj`（實作規格書 4.18：26 用 `aj`），從 `aj1` 起。

**這一冊驗四件事**： 成效與各班工作量**補齊漏掉的資料**——件數旁邊有每 100 次療程、算不出來寫原因不寫 0、班表關著時沒有「每位當班護理師」； 四頁都**改成圖**，每張圖右上角「看表格」、不用語意色、灰階分得出、不呈現的分組是淡斜線不是 0； 對外報表**互減算不回被拿掉的那一組**（次要遮蔽、跨報表比對、依月份），可列印版只有已核准的； 「獎勵制度」開著時**按名字就是接手**，計分算給指名的人、不是登入的帳號，名冊身分登不進去、未指名的不計分。 分析、每一張圖的選擇與七題答覆在《[管理儀表板、獎勵制度與對外揭露的更新與修正](https://94sh09sh19sh.github.io/hd-docs/latest/notes/management-rewards-disclosure-update/index.md)》。

## §26.1 成效：分母、每 100 次、算不出來的寫原因

- `aj1` **［護理端］** 🎭 📐 以展示環境的護理長登入，開「成效與工作量」→ 成效，期間選最近 30 天。 → 分頁與期間在同一列；下一行寫這段期間的療程數與有配平板的療程數；第一屏是五個數字方塊（平板覆蓋率、接手、建立到簽核、事後補寫、到床邊），各帶每週的小圖。
- `aj2` **［護理端］** 看「求助件數」等件數類的方塊與表。 → 每一個件數旁邊（或下一行）都有**每 100 次療程**的值；覆蓋率的分子分母對得上上面那一行。
- `aj3` **［護理端］** 看「到床邊」。 → 寫「開關關著」與原因（手持裝置的功能關著，這段期間沒有到達時間），**不寫 0、不寫樣本不足**。
- `aj4` **［護理端］** 看「病人最常為什麼按」。 → 身體不舒服那一組在前、由多到少；少於 5 件的類別只寫件數、不寫比例。
- `aj5` **［護理端］** 看「事後補寫」與「建立到簽核」。 → 事後補寫只算護理師自己新增的事件記錄（求助處置紀錄不算）；建立到簽核分成「護理師自己建的」與「求助處置紀錄」兩條。
- `aj6` **［護理端］** 把期間拉到展示資料的第一天以前。 → 平板連線與求助處置紀錄那幾條寫「還沒開始記」，不寫 0；跨過開始記那一天的加一句註記。
- `aj7` **［護理端］** 找「想起某個人」、遊戲分數、遊戲花了多久、回貼圖的護理師。 → 一個都找不到（不蒐集的不讀）；遊戲只有「有玩的療程比例」。

## §26.2 各班工作量：班表與到床邊兩個開關

- `aj8` **［護理端］** 🎭 「各班工作量」分頁，班表的版位照預設關著。 → 有熱圖（星期 × 鐘點）、接手時間分布、每天各班、每 100 次療程、同時在等、文書與審閱；**沒有「每位當班護理師」**（不是空白欄，是沒有那一組）。
- `aj9` **［護理端］** 系統管理 → 導覽版位，把「排班與指派」改成選單，回到工作量。 → 每 100 次療程那張圖多一組「每位當班護理師」。改回關閉。
- `aj10` **［護理端］** 看到床邊。 → 各班都沒有到床邊的中位數，寫「開關關著」。

## §26.3 平板連線紀錄

- `aj11` **［病人端］** 🛠 一台佈建好的平板（或瀏覽器開病人端）配著一位病人。**［終端機］** 把那個瀏覽器分頁關掉約 2 分鐘，再開回來。 → **［資料庫］** `device_connection_gaps` 多一筆：起＝最後一次連線、訖＝重新連上，療程是那時配著的那一次；斷線期間沒有寫任何一筆。
- `aj12` **［病人端］** 解除配對後再關掉 2 分鐘、開回來。 → 多一筆，療程是空的。**沒有病人欄位**。

## §26.4 圖：看表格、灰階、樣本少、不呈現的分組；簡報模式

- `aj13` **［護理端］** 🎭 📐 成效與工作量每一張圖右上角按「看表格」。 → 切成表格、數字與圖一致；再按一次切回圖。
- `aj14` **［護理端］** 列印預覽選黑白（或截圖轉灰階）。 → 兩條線線型不同、第二三個系列有花紋，每一條線、每一組柱子都直接標字，**不靠顏色分**。
- `aj15` **［護理端］** 找樣本少的點（某一週件數很少）。 → 空心的點、前後不連線。
- `aj16` **［護理端］** 全部的圖找紅、黃、綠的「好壞」顏色。 → 沒有：圖只用藍、橘、綠三色與灰（四種語意色只用在狀態，不畫資料）。
- `aj17` **［護理端］** 按「簡報模式」。 → 數字方塊、縮小的兩張圖、「還沒做到的」清單；開關關著、還沒開始記的指標**列在還沒做到的**，不列在對照基準。

## §26.5 對外報表：次要遮蔽、依月份、互減、附基準、可列印版

- `aj18` **［護理端］** 🎭 開「對外報表」，依班別產生一份求助件數。 → 晚班少於 5 件不呈現時，**樣本次小的一組一起不呈現**；不呈現的那一欄是淡斜線、寫原因（樣本少／一起拿掉），不畫 0。
- `aj19` **［護理端］** 分組選「依月份」產生一份。 → 月份寫「2026 年 10 月」，沒有時:分；某一個月少於 5 件的不呈現。
- `aj20` **［護理端］** 以另一個帳號核准 `aj18` 那一份；再產生同一段期間、全單位、同一個指標的一份。 → **整份不產生**，訊息寫出跟哪一份衝突（全單位減掉其他班就算得回晚班）、可以怎麼改；稽核有「對外報表產生遭拒」。
- `aj21` **［護理端］** 勾「附基準」產生一份有基準的指標。 → 全單位的數字方塊寫基準；依月份的直條畫基準虛線（量的是同一件事才畫）。
- `aj22` **［護理端］** 待核准的那一份按「可列印版」。 → 取不到（409），稽核記下擋下的那一次；核准之後取得到，每一個數字都在核准的那幾格裡、附不呈現的分組與原因、每一個指標的定義，**沒有產生者與核准者的工作 ID、沒有時:分**。

## §26.6 「獎勵制度」關著：與迭代 25 一模一樣

- `aj23` **［護理端］** 🛠 確認「獎勵制度」開關關著。簡易版點紅框開速覽；專業版緊急通報頁看卡片。 → 速覽上是一顆「我接手」，卡片上也是；**沒有任何名字按鈕**。
- `aj24` **［護理端］** 結案登記、護理紀錄簽核、衛教審閱、跑馬燈待核准、待追蹤事項「已完成」各看一次。 → 都沒有「處理者」那一排，與迭代 25 一樣。
- `aj25` **［護理端］** 選單找「獎勵制度」；網址列直接打 `/rewards`。 → 選單裡沒有；網址打進去是找不到這一頁。**［終端機］** `GET /api/rewards`、`GET /api/handlers/candidates` 都是 404。
- `aj26` **［護理端］** 護理長帳號在系統管理把「個人層級績效資料」開啟（開得起來的話），「獎勵制度」仍關著。 → 選單裡照樣沒有「獎勵制度」，`GET /api/rewards/individual` 是 404：**看不到別人的計分**。關回去。

## §26.7 按名字就是接手；名字名單

- `aj27` **［護理端］** 🛠 開啟「獎勵制度」開關。**［病人端］** 按一次緊急求助。**［護理端］** 簡易版點紅框。 → 速覽標題下一排「我接手：[名字]…[其他人…][先接手]」；這一班還沒有人被指名過時，名字那一段是空的、只有「其他人…」與「先接手」。
- `aj28` **［護理端］** 按「其他人…」，找到自己的名字按下去。 → 速覽關掉、那一則接起來；格子寫「○○ 接手」（按的那一位，**不是登入的帳號**）。專業版卡片的進度列也寫「○○ 接手」。
- `aj29` **［病人端］** 再按一次。**［護理端］** 簡易版點紅框。 → 名字那一段多了剛才那一位；**按他的名字一下就接手**（不必再開「其他人…」）。
- `aj30` **［病人端］** 再按一次。**［護理端］** 這次按「先接手」。 → 接起來了；格子不寫名字，專業版進度列寫「處理者未指名」。
- `aj31` **［護理端］** 連續讓三位不同的護理師接手（各按自己的名字）。 → 名單依姓名筆畫排、最多 6 位，**位置不跟著「最近一次」換**；不讀班表——把「排班與指派」版位開或關，名單一樣。
- `aj32` **［護理端］** 📐 專業版緊急通報頁，一則還沒人接的卡片。 → 原本的「我接手」換成同一排名字（字小一號）；按名字就是接手。1366×768 下速覽照樣不捲動（「其他人…」展開後名單太長時，那一塊自己捲）。

## §26.8 結案、簽核、審閱、完成追蹤的名字列

- `aj33` **［護理端］** 🛠 簡易版點一則**先接手**的求助、點一個處理方式。 → 8 秒改結果列上多一排名字（只列名單上的人）；點一位再等 8 秒，那一則的處理者就是他。接手時已經指名的不會出現這一排。
- `aj34` **［護理端］** 專業版：一則已指名的求助按「結案登記」。 → 一行「處理者：○○　[改]」；按「改」展開一排名字，最後一顆是「照舊（○○）」。不選就照舊送出。
- `aj35` **［護理端］** 一則先接手的求助按「結案登記」。 → 「處理者：未指名　[選]」；選一位送出，處理者記下。
- `aj36` **［護理端］** 護理紀錄頁簽核一份事件記錄，與一份求助處置紀錄。 → 事件記錄：「處理者」一排、可以「不指名」。求助處置紀錄：「處理者：○○／未指名」那一行——**指的是那一次求助的處理者**，在這裡補選就是補那一則。
- `aj37` **［護理端］** 衛教審閱（AI 總開關開著時）核可一份、跑馬燈待核准核准一則、待追蹤事項按「已完成」。 → 衛教與跑馬燈的確認處都有一排名字；跑馬燈審完一則那一排就清掉（不預選）。待追蹤按「已完成」先展開一排名字，再按「確認完成」。
- `aj38` **［終端機］** 稽核軌跡篩「指名處理者」。 → 每一筆寫得出「誰登入、指名誰、在哪一步：哪一種事」；改指名的那一筆寫原本是誰。

## §26.9 名冊身分與「我不在名單上」

- `aj39` **［護理端］** 🛠 護理長開「帳號審核」。 → 多一張「名冊身分」（開關開著才有）；「帳號與權限」那張表沒有名冊身分。
- `aj40` **［護理端］** 新增一筆名冊身分（工作 ID、姓名）。**［護理端］** 用那個工作 ID 隨便一個密碼登入。 → 登不進去。速覽的「其他人…」裡選得到他。
- `aj41` **［護理端］** 一則先接手的求助結案時按「我不在名單上」，填一個新的姓名與工作 ID，送出結案。 → 結案成功；帳號審核頁的名冊身分多一筆「待確認的名冊身分」，誰加的寫「我不在名單上」。那一則仍算未指名。
- `aj42` **［護理端］** 護理長按「確認」。 → 狀態改成名冊身分；之前指名到他的事從此算數（他本人照樣登不進來、不計分）。
- `aj43` **［護理端］** 🖥 用 `aj40` 那個工作 ID 走一次「註冊」，護理長核准。 → 待審核清單裡是同一位；核准後登得進去，**之前指名到他的事都在這個帳號底下**（獎勵制度 → 我的計分看得到）。

## §26.10 計分讀指名：A 登入指名 B、未指名、認領、觀察期與計分期

- `aj44` **［護理端］** 🛠 🖥 以 A 帳號登入，接手時按 B 的名字、結案；簽核一份事件記錄時也選 B。 → B 登入「獎勵制度」→ 我的計分，這兩件在 B 的原始事件裡；A 的沒有。**［資料庫］** `help_requests.resolved_by_id`、`nursing_records.signed_by_id` 照樣是 A。
- `aj45` **［護理端］** 護理長開「計分期間」，起日選「獎勵制度」開啟之前的一天。 → 擋下，寫出開啟的那一天。
- `aj46` **［護理端］** 還沒結算過觀察期（或沒有已公告的規則）時，看種類的選單。 → 只有「觀察期（只計算不計分）」；說明列寫還缺什麼。
- `aj47` **［護理端］** 開一個觀察期，看那一列。 → 「計分事件」幾筆、「未指名」幾筆與比例（全單位一個比例，不分人）。
- `aj48` **［護理端］** 一般護理師開「我的計分」。 → 多一塊「這一期沒有指名的事件」：只有時間與種類，**沒有病人、沒有誰登入**。按一筆「是我做的」寫說明送出。 → 那一筆寫「認領處理中」，還不算。
- `aj49` **［護理端］** 護理長「更正申請」接受那一件。 → 那一筆算進那位護理師、從「沒有指名的事件」拿掉；再認領一次有指名的事件會被擋。
- `aj50` **［護理端］** 看「獎勵制度」每一頁。 → **沒有總分、沒有排名、沒有圖**；計分一列一條規則，個人層級依工作 ID 排。
