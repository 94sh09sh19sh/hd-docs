    迭代 22 手動測試 — 遊戲化之三：麻將連連看、狀態評估彙整、社工與醫師¶

    《完整手動測試手冊》的分冊之一，對應《實作規格書》4.22 節。 共用的環境準備、啟動與疑難排解都在主手冊，這一冊只寫迭代 22 的部分。 操作端色籤（護理端／病人端／終端機／資料庫）的意思見主手冊 §00。 項次用 af（實作規格書 4.0.5：22 用 af），從 af1 起。

    這一冊驗六件事： 兩個開關全關時一切跟迭代 17.7 一樣； 麻將連連看怎麼玩（只鋪一層、點兩張一樣的就消、連線規則、提示、卡住時自動重排、沒有計時與級數）； 存檔跟著病人走、斷線照樣能玩； 今日牌局（同一班當天同一桌、完成人數照最低人數門檻）； 狀態評估彙整（前 10 桌不說、只陳述事實）； 社工與醫師只看得到病人詳細資訊、每一次調閱都在稽核軌跡。 牌面的來源與授權在病人端 src/assets/mahjong-tiles/SOURCE.md。

    標記 意思
    🛠 開發機 平常的 npm run dev（資料庫先套用新遷移：npm run prisma:migrate 或 db:update）。做完這一冊，兩個開關回到關閉
    📐 目標尺寸 病人端 1280×800 與 800×1280；護理端 1366×768
    🛏 病床距離 平板架在病床邊，由長者躺著看
    📱📱📱 三台平板 三台已佈建的平板（或三個瀏覽器分頁各開一台的病人端），各接一位病人、同一班

    前置：一台已佈建的平板（或瀏覽器開病人端）、一位合成病人；一般護理師與護理長帳號；另外註冊兩個帳號，由最高權限帳號在帳號審核把角色改成「社工（唯讀）」與「醫師（唯讀）」。 兩個開關在系統管理 → 功能開關的「病人平板的遊戲化」那一組。

    §22.1 兩個開關¶

    • af1 ［護理端］ 系統管理 → 功能開關。 → 「病人平板的遊戲化」那一組八列：迭代 20、21 的六列，加上麻將連連看、狀態評估彙整（護理端顯示）（兩個都是關）。畫面上沒有英文識別字。記憶相簿還沒有開關。
    • af2 ［病人端］ 📐 八個遊戲化開關裡，除了「現有功能的小幅遊戲化」都關著：看首頁。［護理端］ 看「更多」選單與系統管理 → 導覽版位。 → 跟迭代 17.7 一樣：首頁沒有遊戲圖示；「更多」選單沒有「病人詳細資訊」，導覽版位的清單裡也沒有這一列。［終端機］ 打 GET /api/patient-detail/patients 回 404。
    • af3 ［護理端］ 開「麻將連連看」（寫理由）。 → 開關中心那一列的說明寫「牌面 34 種已放進病人端」。「更多」選單多一項「病人詳細資訊」（放在「病人趨勢」後面）。主列不變，仍是 7 項。

    §22.2 玩一桌¶

    • af4 ［病人端］ 📐 點基本資訊區的遊戲圖示。 → 遊戲選單多「麻將連連看」（田字格圖示）。點它：標題、一句「點兩張一樣的牌，就會消掉」、下面兩顆大按鈕「開一桌」「今日牌局」。整頁不捲動、求助區在原位。
    • af5 ［病人端］ 點「開一桌」。 → 4×4 一桌、只鋪一層。每張牌至少 80×104px；畫面上沒有計時、沒有第幾級、沒有分數。「萬」字與紅中是深棕，整個畫面除了求助按鈕沒有紅色（筒子、一條上原本的紅點也是深棕）。
    • af6 ［病人端］ 點一張牌，再點同一張。 → 第一下外框變粗（深綠）；再點一下取消選取。沒有聲音、沒有震動。
    • af7 ［病人端］ 點一張，再點一張不一樣的。 → 第一張取消選取，第二張也不會被選起來。不扣分、不晃動、沒有任何「錯」的字。
    • af8 ［病人端］ 點兩張一樣的。 → 兩張 0.3 秒淡出、消失，位置留空（旁邊的牌不移動）。
    • af9 ［病人端］ 按頂列的「提示」，連按幾次。 → 一對可以消的牌被虛線框起來（跟選起來的實線不一樣）。按幾次都可以，沒有次數上限、沒有「用了幾次」。
    • af10 ［病人端］ 把這一桌消完。 → 只顯示「完成了」與一個完成記號，不顯示花了多久；下面「開一桌」（與今天還沒做過時的「今日牌局」）。
    • af11 ［病人端］ 再開幾桌，每桌都不按提示。 → 第三桌起（連續兩桌順利之後）牌變多，或開始要用連線規則：兩張一樣、而且能用最多轉兩個彎的線連起來才消；消的時候畫一條線，0.3 秒後拿掉。畫面上從頭到尾沒有出現「升級」「第幾級」。
    • af12 ［病人端］ 作業系統開「減少動態效果」（Android：協助工具 → 移除動畫；Windows：設定 → 協助工具 → 視覺效果 → 動畫效果關），再消一對。 → 兩張直接消失，沒有淡出、沒有線。
    • af13 ［病人端］ 📐 牌最多的一桌（4×8）分別在 1280×800 與 800×1280 看。 → 兩種方向都放得下、不捲動；直放時一張剛好 80×104px。
    • af14 ［病人端］ 有連線規則的一桌，一直消到牌剩下不多。 → 若剩下的牌一對都連不起來，自動重新排列，頂列寫「牌重新排過了，可以接著找」——永遠不會卡住。（不一定碰得到；腳本以刻意卡住的牌面驗過兩百次，見 af30）

    §22.3 存檔跟著病人走與斷線¶

    • af15 ［病人端］ 開一桌、消兩對，按回首頁；［護理端］ 解除綁定，把這位病人配到另一台平板、另一班，點開麻將連連看。 → 直接回到剛剛那一桌，牌與位置一模一樣。
    • af16 ［病人端］ 斷網（關 Wi-Fi 或開發者工具設離線），消幾對、按提示；再接回網路。 → 斷網時照樣能玩；接回之後［資料庫］ game_events 多出這幾步（game_code = 'MAHJONG'），序號接續、沒有重複。
    • af17 ［病人端］ 玩到一半時，讓心情問卷的時點到（營運參數「心情問卷在透析開始後幾分鐘」暫改 0）。 → 這一步走完之後問卷出現；做完問一次「回到剛剛的遊戲？」，按「回到麻將連連看」就是原來那一桌。做完把參數改回。

    §22.4 今日牌局¶

    • af18 ［護理端］ 開「病人之間的互動」。［病人端］ 📱📱📱 三台平板（同一班）各點「今日牌局」。 → 三台拿到同一桌（牌與位置一樣）。
    • af19 ［病人端］ 三台都把今日牌局做完。 → 完成畫面在「完成了」底下多一句「今天這一班有 3 個人完成了今日牌局」——只有人數，沒有床號、沒有誰快誰慢。
    • af20 ［病人端］ 第四台（同一班）開今日牌局但不做完；回到第一台，再開今日牌局。 → 第一台：今天這一班的那一桌做過了，選單沒有「今日牌局」。再讓第五台做完今日牌局：完成畫面不說人數（4 人完成、1 人開了沒做完——那一位會被凸顯，這星期也湊不到）。
    • af21 ［病人端］ 開著「透析小花園」，做完一桌之後點開花園。 → 門口多一份「遊戲的養分」（手把圖示）；同一次療程再完成一桌，不會再多一份。

    §22.5 病人詳細資訊與狀態評估彙整¶

    • af22 ［護理端］ 📐 一般護理師：更多 → 病人詳細資訊。 → 一開始沒有帶任何病人（寫「選一位病人。每一次調閱都會記在稽核軌跡」）。選一位：姓名、病歷號、今天的班別與床號；下面「最近幾次有沒有玩」——最近 10 次療程，透析小花園「有／沒有」、麻將連連看「開了幾桌、完成幾桌」。沒有成績、沒有排名。
    • af23 ［護理端］ 狀態評估彙整還關著：看同一頁。 → 沒有「狀態評估彙整」那一塊。開「狀態評估彙整」，重新選病人：多一塊，完成不到 11 桌的病人寫「前 10 桌只當練習，不列入比較，也不產生任何陳述」，沒有任何一句陳述。
    • af24 ［護理端］ 選一位玩過很多桌的病人。 → 四句，每一句都是「近 14 天完成的 N 桌，……中位數是……，比自己過去 M 桌的中位數（……）多／少……」或「和……一樣」。逐句看：沒有「退化」「疑似」「注意力」「情緒」「建議」這類結論字眼。差距達設定幅度的那一句，句尾只多一行灰字「（差距達設定幅度）」，不是紅色。最下面固定一句「不是評估工具，也不會通知任何人」。
    • af25 ［護理端］ 系統管理 → 營運參數。 → 有七個「狀態評估：……」的參數（前幾桌只當練習、近期幾天、門檻……）。「前幾桌只當練習」不能調到 10 以下。
    • af26 ［護理端］ 關「狀態評估彙整」，在平板上再玩一桌。［資料庫］ 看 game_events。 → 病人詳細資訊沒有彙整那一塊；但這一桌的每一步照樣寫進 game_events（elapsed_ms、tap_offset_a 都有值）。

    §22.6 社工與醫師¶

    • af27 ［護理端］ 以「社工」帳號登入。 → 不進簡易版，直接到「病人詳細資訊」；「更多」選單只有這一項，沒有系統管理。選一位病人看得到詳細資訊與狀態評估彙整，畫面上沒有任何會改資料的按鈕。以「醫師」帳號重做一次，一樣。
    • af28 ［終端機］ 用社工的權杖打幾支寫入端點（例如 POST /api/patients、PUT /api/feature-flags/MAHJONG）與其他頁（GET /api/patients、GET /api/audit-logs）。 → 全部 403「此帳號為唯讀角色，無權使用此功能」。以醫院管理層、稽核角色帳號打 GET /api/patient-detail/patients/<病人 id> 也是 403。
    • af29 ［護理端］ 以有稽核權限的帳號看稽核軌跡，動作選「調閱病人詳細資訊」「調閱狀態評估彙整（遊戲資料）」。 → 社工、醫師、護理師每一次選病人都各有一筆：誰、哪一位病人；彙整那一筆寫算式版本與幾句陳述。

    §22.7 牌面的來源與長者試看¶

    • 🛠 看病人端 src/assets/mahjong-tiles/：SOURCE.md 有來源網址、commit 26e127b…、改了什麼；旁邊 LICENSE.md（原檔照原樣）與 CC0-1.0-legalcode.txt（法律條文全文）。用文字編輯器開啟任何一張 .svg：只有 svg、g、path、circle、ellipse、rect，沒有 <script>、on…=、href。（af30 的腳本逐張檢查過）
    • 🛏 由長者在病床上實際看一桌 4×6 與 4×8：牌看不看得清楚、「萬」字改深棕認不認得出來、會不會覺得是給小孩玩的。看不清就照遊戲化決定 5.3 由 AI 照同一套牌面重畫。這一項不打勾，結果寫進遊戲化分析 12.2

    §22.8 自動化驗收¶

    • af30 ［終端機］ npm run verify:iteration22（不需要後端）；後端開著，再跑 npm run verify:iteration22:api。 → 兩支都全部通過（前一支每一級各發一千次牌加窮舉、亂玩一千桌、刻意卡住的牌面重排兩百次，再跑 check:ui、check:ui:design、check:egress；後一支結束時五個開關改回原狀，直接寫進資料庫的合成操作紀錄刪掉。驗收用的平板、病人、帳號留著、療程取消，與其他驗收腳本相同）。
