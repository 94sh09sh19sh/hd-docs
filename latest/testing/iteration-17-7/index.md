> 《[完整手動測試手冊](https://94sh09sh19sh.github.io/hd-docs/latest/testing/manual-test-guide/index.md)》的分冊之一，對應《實作規格書》4.15.7 節與《[迭代 17.7 修正紀錄](https://94sh09sh19sh.github.io/hd-docs/latest/notes/iteration-17-7-fixes/index.md)》。 共用的環境準備、啟動與疑難排解都在主手冊，這一冊只寫迭代 17.7 的部分。 操作端色籤（**護理端**／**病人端**／**終端機**／**資料庫**）的意思見主手冊 §00。 項次接著迭代 17.6 分冊編（`aa131` 起；17.6 用到 `aa130`），小版沿用那個迭代的字母。

## 17.7.1 · 新增病人：開關關著兩邊都沒有、開著兩邊都有 🎬 📐

- `aa131` **［護理端］** 開 `http://localhost:5183`，專業版右上角「系統管理」→「功能開關」，捲到最下面。 → 最後一組叫「院方資料以外的人工輸入」，裡面一項「護理師自己新增病人（專業版排班與指派、簡易版病人框）」，狀態「關閉」，「目前是否符合」是 ✓。
- `aa132` **［護理端］** 開關關著，看專業版「排班與指派」與簡易版病人框。 → 排班與指派「建立排班」底下**沒有**新增病人那一列；簡易版病人框**沒有**「＋」（人形加號那一格）。
- `aa133` **［護理端］** 回功能開關，把「護理師自己新增病人」開啟（理由隨便寫），等一分鐘內或切一下視窗。 → 專業版排班與指派「建立排班」的下一列出現「院方資料裡沒有的病人」、病歷號、姓名、「新增病人」；滑鼠停在那幾個字上看得到「以院方資料為準」的說明。
- `aa134` **［護理端］** 病歷號填 `HD-TEST-1771`、姓名填「人工新增甲」，按「新增病人」。 → 綠色提示「已新增病人 人工新增甲，已在病人選單選好」；上一列的病人選單已經選著他，接著按「建立排班」就排好了。
- `aa135` **［護理端］** 切到簡易版看病人框。 → 病人框多了「＋」（展示環境接了模擬院方資料照樣有）。把「＋」拖到一台空著的平板（或點「＋」再點平板），填姓名與病歷號、按建立。 → 那台平板配上這位病人，復原列寫「新增 … → 平板 …」。
- `aa136` **［護理端］** 回功能開關把它關掉。 → 專業版那一列與簡易版的「＋」都不見了（不是變灰）。剛才建的兩位病人照樣在病人選單與病人框裡。

## 17.7.2 · 系統管理的平板管理 🎬

- `aa137` **［護理端］** 專業版右上角「系統管理」，看上面那一排分頁。 → 分頁叫「**平板管理**」，沒有「平板停用」；點進去，卡片標題也是「平板管理」，停用、解除停用、解除佈建、登記佈建都在這張表（與 17.6 相同）。
- `aa138` **［護理端］** 「新增裝置」那一頁看底下的說明；「排班與指派」在沒有可指派平板時看清單下方的提示。 → 提到的都是系統管理的「平板管理」。

## 17.7.3 · 簡易版手選床位的床號 🛠 📐

這一節要**全新的開發資料庫**：已經在用的開發資料庫是改動之前 seed 的，床號仍是 01～15（改動只在 seed，不會自己換）。 不想重建的話，可以到專業版系統管理的床位清單把床號換成 `A1 A2 A3 A5 A6 A7 A8 A9 B1 B2 B3 B5 B6 B7 B8`，效果相同。

- `aa139` **［終端機］** 照主手冊 §01 的步驟建一個空的開發資料庫，跑 `npm run db:seed`。 → 輸出有一行「已建立開發用的 15 床（A1～B8）」。
- `aa140` **［護理端］** `npm run dev` 開起來（沒接院方資料），簡易版點任何一台平板右上角的床號（還沒設的是一個床的圖示）。 → 列出來的是 A1、A2、A3、A5、A6、A7、A8、A9、B1、B2、B3、B5、B6、B7、B8：**區碼＋數字、沒有 4 號床**，不是 01～15。選一床，平板右上角就是那個床號。

## 17.7.4 · 公告與院內衛教拖到平板 🎬 📐

- `aa141` **［終端機］** 讓 DEMO-01（配著模擬戊）暫時沒有床號：用最高權限帳號登入取得權杖後，`POST http://localhost:3100/api/devices/<DEMO-01 的 id>/bed`，內容 `{"bedNo": null}`。 → 簡易版 DEMO-01 那一格右上角的床號不見了，病人照樣在格子上。（模擬院方資料每 3 分鐘同步一次會把它放回原本的床，這一節要在那之前做完；放回去了就再拿下來一次。）
- `aa142` **［護理端］** 簡易版公告與院內衛教框，點一則已核准的內容（例如「每天量體重」），再點 DEMO-01 那一格。 → **放得上**（17.6 以前沒有床號的平板不亮、點了沒反應）。復原列寫「「每天量體重」→ 平板 DEMO-01」；DEMO-01 格子左下角的喇叭數字加一，滑鼠停上去是「只在這台平板播的內容 N 則」。
- `aa143` **［病人端］** 開 DEMO-01 的平板畫面（`demo:patient` 啟動時印出來的網址），等跑馬燈跑一輪。 → 跑馬燈有「每天量體重」。回護理端點同一則再點「全部」，它回到全部床位；DEMO-02（空著、沒有床號）點了**不會亮**、放不上。
- `aa144` **［護理端］** 把一張草稿卡拖到 DEMO-01（或點草稿卡、再點 DEMO-01）。 → 核准的就是那一則，只在 DEMO-01 播；專業版「公告與院內衛教」頁上它的播放範圍寫「平板 DEMO-01」，稽核軌跡裡寫的也是「平板 DEMO-01」。

## 17.7.5 · 自動化驗收 🖥

- `aa145` **［終端機］** `npm run build:shared` 之後跑 `npm run verify:iteration17-7`（不需後端、不需資料庫）。 → 5 個步驟全部 ✓。步驟 5 會順便跑 `verify:iteration14`、`14-2`、`15`、`17`、`17-1`、`17-6`，也都要通過。
- `aa146` **［終端機］** 開發用的後端開著（`npm run dev:api`，資料庫先套用新遷移），跑 `npm run verify:iteration14:api` 與 `npm run verify:iteration17:api`。 → 兩支都通過（只帶床號的舊請求照樣可用）。
