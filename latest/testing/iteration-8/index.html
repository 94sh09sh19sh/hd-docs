    迭代 8 手動測試 — 介面重新設計¶

    《完整手動測試手冊》的分冊之一，對應《實作規格書》4.6 節。 共用的環境準備、啟動與疑難排解都在主手冊，這一冊只寫迭代 8 的部分。 操作端色籤（護理端／病人端／終端機／資料庫）的意思見主手冊 §00。

    依據是《介面設計基準》，不是這一冊。 這裡只寫「怎麼確認它做到了」。

    這一冊大半要用眼睛看，而且最好用手指碰。 腳本驗得了對比度的數值、觸控目標有沒有寫出下限、 求助區的版面結構還在不在；但「躺著看得不看得清楚」「從護理站走過來兩秒內知不知道有事」， 腳本一句話都說不出來。⚠️ 標記的那幾項請不要用滑鼠在開發機上帶過。

    8.1 · 求助區的版面契約（基準 2.2、FR-P13）¶

    這一節是整個迭代的重點。 0919 之前求助按鈕會蓋住輪播的字，原因不是按鈕太大， 是它的位置由首頁內容多寡決定：按鈕待在首頁版面的文件流裡，輪播是覆蓋整個畫面的圖層， 輪播開始時把按鈕的堆疊層級抬高讓它浮上來，輪播那一層只能「猜」它在哪。

    新做法是把畫面切成兩塊：上面是內容區，下面是求助區，內容區的高度＝畫面高度減掉求助區。 輪播畫在內容區裡，因此它的下緣就是求助區的上緣——「蓋住」在結構上不可能發生。

    • r1 ［病人端］ 主畫面。→ 畫面最下方是一整條紅色的「我需要協助」， 底下一行小字「按一下就會通知護理站」。它不是首頁四個按鈕之一，是固定的一區。
    • r2 ［病人端］ 依序進「填寫透析前症狀問卷」「衛教與小測驗」「心情與滿意度」。 → 每一個畫面上，求助區都在完全相同的位置、完全相同的大小。內容多到要捲動時， 捲的是上面那一區，求助區不會被推走。
    • r3 ［病人端］ 按求助區進入求助畫面。 → 求助區還在原位、還是一樣大，但變成灰色的「正在填寫求助」加一行「請在上面選好再送出」。 不是消失，也不是變成第二顆一模一樣的紅色按鈕。
    • r4 ［病人端］ 拔掉平板的網路。 → 求助區變成黃框的「請按床邊呼叫鈴」加一行「目前無法通知護理站」。 位置與大小仍然完全相同。按下去進得了求助畫面，畫面上會把替代做法寫清楚。
    • r5 ⚠️ ［病人端］ 放著不動等到輪播開始，拍一張照；碰一下螢幕回主畫面，再拍一張。 → 兩張照片上求助區的位置與大小一模一樣。這是驗收標準第 1 條。
    • r6 ⚠️ ［病人端］ 看 r5 那張輪播中的照片。 → 沒有任何一個字落在求助區裡，連一個標點符號都沒有。這是驗收標準第 2 條。 卡片最下面那行字和求助區之間看得到明顯的空隙。
    • r7 ［病人端］ 輪播進行中，直接按求助區。 → 立刻進求助畫面，不必先碰一下退出輪播再按。在最需要它的時候，它是一步。
    • r8 ［病人端］ 平板還沒被指派時（解除綁定後）看等待畫面。 → 這個畫面上沒有求助區，取而代之的是一行「需要護理人員時，請按床邊的呼叫鈴」。 這是刻意的：平板還沒指派給任何人，求助送出去護理站不知道是誰按的； 一顆按了會失敗的按鈕比沒有按鈕更糟。

    8.2 · 病人端字級與觸控目標（基準 4.2、4.3）¶

    數字的來源是族群事實，不是美感：年齡偏高、糖尿病視網膜病變常見、躺著看斜上方的平板。

    • r9 ⚠️ ［病人端］ 把平板架在床邊支架上，自己躺下來看（或請一位同事躺下來）。 → 主畫面上每一個字都看得清楚，不必瞇眼、不必把頭抬起來。
    • r10 ⚠️ ［病人端］ 同樣躺著，看輪播的卡片。 → 「已進行 4 分鐘」這類數值特別大，從躺著的距離一眼就讀得到。
    • r11 ⚠️ ［病人端］ 把一隻手背在身後，只用另一隻手，從主畫面走完： 填問卷 → 送出 → 回主畫面 → 按求助 → 取消回主畫面。 → 全程做得到，而且所有要碰的東西都在畫面下半部——透析中另一隻手在打針。
    • r12 ［病人端］ 問卷的選項按鈕。 → 每一顆都大到不用瞄準，彼此之間有明顯的空隙，不會按到隔壁那一顆。
    • r13 ［終端機］ npm run check:ui:design → 「全部通過」。它算的是對比度與觸控目標尺寸的設定值；r9–r12 驗的是實際繪製出來的樣子， 兩者不能互相取代。

    8.3 · 顏色不是唯一線索（基準 P-4）¶

    糖尿病視網膜病變會影響色彩辨識。每一個用顏色表示的狀態，都要同時有文字說明。

    • r14 ［病人端］ 問卷裡選一個選項。 → 選中的那一顆除了換顏色，前面還多一個「✓」。把畫面轉成灰階看也分得出來。
    • r15 ［病人端］ 送出問卷後回主畫面。 → 綠色的那條訊息前面寫著「已完成」四個字，不是只有一句綠色的話。
    • r16 ［病人端］ 拔網路。 → 黃色那條前面寫著「目前沒有網路」。
    • r17 ［病人端］ 請護理師結案一筆求助後回主畫面。 → 清單上寫著「已處理」，後面才是結果與時間。
    • r18 ［病人端］ 掃一遍整個病人端。 → 畫面上只有求助區是紅色的，沒有第二個紅色的東西。測驗答錯的提示是黃色的，不是紅色—— 紅色一旦不只一個，它就不再是「那顆紅色的」。

    8.4 · 說人話（基準 P-6）¶

    • r19 ［病人端］ 讀過主畫面、問卷、求助、衛教、回饋的每一句話。 → 沒有「已提交」「同步中」「載入失敗」這類字眼。離線時說的是 「您照樣填就好，送出後會先存在這台平板，有網路時自動送給護理站」， 不是「離線暫存，恢復連線後自動重送」。
    • r20 ［病人端］ 等待畫面。 → 「這台平板目前還沒有指派給任何人」，不是「裝置未綁定」。

    8.5 · 沒有手勢、沒有裝飾性動畫（基準 2.3、4.4）¶

    • r21 ⚠️ ［病人端］ 在主畫面上試著長按一個按鈕、左右滑、快速點兩下。 → 三種都沒有任何特殊反應。長按不會跳出選單，滑動不會換頁，雙擊等同點兩次。
    • r22 ［病人端］ 看等待畫面。 → 沒有那顆會呼吸的圓圈了（0919 移除）。它不傳達任何資訊，只是會動。
    • r23 ［病人端］ 輪播進行中。 → 卡片換卡是唯一會動的東西，那是功能不是裝飾；沒有任何呼吸燈、沒有位移動畫。
    • r24 ［病人端］ 在作業系統裡開啟「減少動態效果」後重新載入。 → 畫面一切正常，該有的資訊一項不少。
    • r25 ［病人端］ 夜間時段看輪播（或把夜間起訖時刻暫時調到現在）。 → 整體變暗，但版面一模一樣、字一樣大。調暗不是把字縮小。

    8.6 · 護理端：一眼看出有沒有事（基準 N-1）¶

    • r26 ⚠️ ［護理端］ 讓一位同事先按幾筆求助，你從護理站走過來看即時總覽， 自己計時：兩秒內答得出「現在需要我嗎」嗎？ → 畫面最上面一條橫幅直接寫著「有 3 筆求助等著處理」或「目前沒有待處理的求助」。 不必先讀完四個數字方塊才知道哪一個重要。
    • r27 ［護理端］ 把所有求助結案。 → 那條橫幅變成綠色的「目前沒有待處理的求助」。沒事的時候它也要說話， 不然護理師分不清「沒事」和「還沒載入完」。
    • r28 ［護理端］ 有一筆病人標示「非常緊急」時。 → 橫幅變成紅底，而且把「其中 N 筆病人標示非常緊急」寫出來，不是只變色。
    • r29 ［護理端］ 站在離螢幕一步遠的地方看那條橫幅。 → 字夠大，不必湊近。

    8.7 · 護理端：破壞性動作有阻力（基準 N-5）¶

    阻力只加在會讓東西消失的動作上。 每個動作都要確認，等於沒有任何動作被確認過。

    • r30 ［護理端］ 裝置管理 →「手動解除」。 → 第一下不會解除，按鈕換成一句「解除後這台平板會立刻回到等待畫面， 本次療程留在平板上的資料一併清除。」加上「確定解除」與「取消」。
    • r31 ［護理端］ 按「取消」。→ 回到原樣，什麼都沒發生。
    • r32 ［護理端］ 再按一次「手動解除」，然後放著不動。 → 約 8 秒後自己收回去。護理師常常按到一半被叫走，回來時不該有一顆待確認的破壞性按鈕在那裡。
    • r33 ［護理端］ 「遠端鎖定」與「解除註冊」。→ 同樣是兩段式，而且各自說出自己的後果。
    • r34 ［護理端］ 已鎖定的平板按「解除鎖定」。 → 一下就做完，沒有確認。解除鎖定是把限制拿掉，不是破壞性動作。
    • r35 ［護理端］ 「重新整理」「標記已讀」這一類。→ 都是一下就做完。
    • r36 ［護理端］ 上面每一個確認過程中，瀏覽器都沒有跳出自己的對話框。 那種對話框會凍住整個分頁，即時總覽的串流也跟著停。

    8.8 · 常駐總覽螢幕的字級倍率（FR-N12）¶

    觀看距離還沒有人量過（Q-10），所以做成一個可設定的倍率：距離確定後改一個數字，整面牆一起變。

    • r37 ⚠️ ［護理端］ 開總覽螢幕模式，站到護理師實際會站的位置看。 → 病人姓名、求助內容、時間都讀得到。讀不到就是倍率要調大，不是要把內容刪掉。
    • r38 ［護理端］ 在瀏覽器的開發者工具裡把 --wall-scale 改成 1.5。 → 整面牆的字一起變大，包含標題、時鐘、卡片、頁尾，沒有任何一處漏掉。 版面跟著重排，不會有字被切掉。
    • r39 ［護理端］ 把後端停掉。 → 整個畫面出現紅框並閃爍，同時有一條寫著「連線中斷」的橫幅。 閃爍是給持續存在的故障用的，不是給新通報用的；顏色也不是唯一線索。
    • r40 ［護理端］ 開啟作業系統的「減少動態效果」後重新載入，再停掉後端。 → 紅框還在，但不閃了。示警沒有消失，只是不再動。

    8.9 · 自動化驗收¶

    • r41 ［終端機］ npm run verify:iteration8 → 7 個步驟全部 ✓，最後顯示「驗收結果：全部通過」。 這一支不需要後端在跑——迭代 8 一張表都沒動、一個端點都沒加。
    • r42 ［終端機］ 依序重跑 verify:acceptance、verify:iteration2～iteration7。 → 七支全綠。迭代 8 沒有改動任何後端行為，既有腳本一行都沒有改。
    • r43 ［終端機］ npm run check:all → 五支盤點腳本全部跑完，最後一張總表列出每一支的結果。 零院外連線 0 筆、介面設計基準全部通過、離線可部署性無阻擋。 介面技術識別仍有既有的 22 筆——那一批的清除排在迭代 9，本迭代只確保沒有變多。
