# 迭代 17.3 手動測試 — 所有 AI 生成內容禁用簡體字與中國大陸用語

> 《[完整手動測試手冊](https://94sh09sh19sh.github.io/hd-docs/latest/testing/manual-test-guide/index.md)》的分冊之一，對應《實作規格書》4.15.3 節與《[迭代 17.3 修正紀錄](https://94sh09sh19sh.github.io/hd-docs/latest/notes/iteration-17-3-fixes/index.md)》。 共用的環境準備、啟動與疑難排解都在主手冊，這一冊只寫迭代 17.3 的部分。 操作端色籤（**護理端**／**病人端**／**終端機**／**資料庫**）的意思見主手冊 §00。 項次接著迭代 17.2 分冊編（`aa87` 起；17.2 用到 `aa86`），小版沿用那個迭代的字母。

**這一冊驗一件事**：AI 寫出來的內容只要含簡體字、中國大陸用語或台灣不這樣寫的字形，**系統就退回請它重寫**；最後一次仍不合格也照樣交出。 沒違規的照舊，一次就好。**兩端畫面上任何時候都看不出這道把關**——退回的紀錄只在資料庫裡。

**怎麼讓模擬模型寫出不合格的內容**：模擬模型寫公告時，會把護理師輸入的**事由照抄進內容**。 所以在事由裡夾一個詞庫裡的詞，模擬模型每一次都會寫出那個詞，正好用來看「一直不合格」那條路。 詞從 `packages/shared/zh-tw/words.txt` 挑：**沒有 `#` 開頭的任一行，Tab 左邊那個詞**（右邊是台灣的說法）。

## 17.3.1 · 不合格就退回重寫，最後一次照樣交出，前端看不出來 🖥

護理端開 `http://localhost:5173`，用有「公告與院內衛教」權限的帳號登入，進**專業版 → 公告與院內衛教**。

- `aa87` **［護理端］** 公告事由輸入「10/10 停診」，按要一份。 → 幾秒後「待核准」多一則「中心公告」，內容是事由加上模擬輸出的尾巴。**與迭代 17 時完全相同**——沒違規的不受影響。
- `aa88` **［護理端］** 公告事由輸入「10/10 停診，」再接一個從 `words.txt` 挑的詞，按要一份。 → 幾秒後（比 `aa87` 稍久）「待核准」照樣多一則，內容含那個詞（第 3 次仍不合格，照樣交出）。**畫面上沒有「產生失敗」，也沒有任何提到簡體字、用語或重寫的文字**。
- `aa89` **［護理端］** 系統管理 → AI 呼叫紀錄；再到稽核軌跡，篩「AI 模型呼叫」。 → 兩處都只多**一筆成功**，與 `aa87` 那一筆長得一樣；沒有任何失敗列、錯誤訊息或說明提到用語。點開那一筆的提示，**最後沒有重寫附註**。
- `aa90` **［資料庫］** `npm run prisma:studio`，開 `AiInvocation`，看最新的三筆（依 `invokedAt` 排）。 → 資料庫裡三筆都在：前兩筆 `FAILURE`、`errorMessage` 以「輸出含簡體字或中國大陸用語：」開頭，第三筆 `SUCCESS`；三筆的 `outputText` 都留著原文。 **第二、三筆的 `promptText` 最後多一段**「上一次的輸出用了簡體字或中國大陸用語：…。請改用台灣的繁體中文與台灣的說法重寫，其餘要求不變。」，第一筆沒有。
- `aa91` **［資料庫］** 同一個畫面開 `AuditLog`，看最新的三筆「AI 模型呼叫」（`action` 是 `AI_INVOKED`）。 → 三筆都在：前兩筆 `FAILURE`，說明寫「第 1 次（第 2 次）輸出含簡體字或中國大陸用語（…），已退回重寫」；第三筆 `SUCCESS`，說明與 `aa87` 那一筆的格式相同。 終端機跑後端的那個視窗會有一行 `WARN [AiGatewayService] …第 3 次仍輸出含簡體字或中國大陸用語（…），照樣交出`。

## 17.3.2 · 實驗室模型實際會不會寫出大陸用語 🧪

`.env` 設 `LLM_PROVIDER=lab`，照部署手冊第十三冊開好通道，`npm run dev`。**只送合成資料**——這一節只用跑馬燈的衛教主題與公告事由，本來就不帶病人資料。

- `aa92` **［護理端］** 專業版 → 公告與院內衛教，連續要 10 份衛教草稿（主題不指定，系統會輪流挑），再要 3 份公告（事由自己寫，用台灣的說法）。 → 每一份都進「待核准」（超過字數重寫三次仍超過的才會「產生失敗」），不會卡在「產生中」。**逐字看一次**：沒有簡體字、沒有大陸用語、沒有台灣不這樣寫的字形（`packages/shared/zh-tw/variants.txt` 左邊那一欄）。 有的話，表示那一份重寫到最後一次仍不合格、照樣交出了——記下來，核准前請護理師改掉。
- `aa93` **［資料庫］** `npm run prisma:studio`，開 `AiInvocation`，數一下這 13 份總共送了幾次、其中幾次的 `errorMessage` 以「輸出含簡體字或中國大陸用語」開頭（**護理端的 AI 呼叫紀錄不列這幾筆**，只能看資料庫）。 → 記下來回填修正紀錄第 5 節（「沒有驗的」那一段）。**被退回的比例偏高**（例如超過三成）就要回頭看系統提示或換模型，不是放寬詞庫。

## 17.3.3 · 改詞庫 🖥

- `aa94` **［終端機］** 在 `packages/shared/zh-tw/words.txt` 最後加一行 `測試詞<Tab>測驗詞`，**不重新產生**，直接 `npm run verify:iteration17-3`。 → 步驟 1 第一項 ✗「zh-tw-data.ts 與 … 的三個 txt 一致」。接著 `npm run zh-tw:data` 再跑一次 → 全部 ✓。 做完把那一行刪掉、再跑一次 `npm run zh-tw:data`，`git status` 看兩個檔案回到原樣。

## 17.3.4 · 自動化驗收 🖥

- `aa95` **［終端機］** `npm run verify:iteration17-3`（不需後端、不需資料庫）。 → 7 個步驟全部 ✓。步驟 3 會寫出掃了幾份既有的文件與程式（1007 是 181 份），一處都不能查到。
- `aa96` **［終端機］** `npm run dev:api` 開著，跑 `npm run verify:iteration3`、`npm run verify:iteration4`、`npm run verify:iteration17:api`。 → 全部通過（這三支會實際呼叫模擬模型，系統提示多了一條規則不影響它們）。
