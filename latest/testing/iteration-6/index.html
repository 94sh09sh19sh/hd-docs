    迭代 6 手動測試 — 閒置輪播與檔案匯入¶

    《完整手動測試手冊》的分冊之一，對應《實作規格書》v2.0 4.4 節。 共用的環境準備、啟動與疑難排解都在主手冊，這一冊只寫迭代 6 的部分。 操作端色籤（護理端／病人端／終端機／資料庫）的意思見主手冊 §00。

    FR-P09 閒置輪播、FR-P10 卡片細節頁、FR-P11 三層內容、FR-P13 主線保護、FR-S05 檔案匯入。

    本冊有四項是自動化腳本驗不到、只能用手指確認的（p7～p16、p28～p29 標了 ⚠️）。輪播對病人開啟前請先走過那幾項：輪播是加在病床旁的東西，它可以沒用，但不能擋住求助按鈕。

    6.1 · 開關關閉時，輪播完全不存在（FR-S08）¶

    • p1 ［護理端］ 確認三個輪播開關都是關的（系統管理 → 功能開關）。
    • p2 ［病人端］ 放著不要碰，等超過閒置門檻。 → 什麼都不會發生，畫面停在主畫面。不是「輪播了但沒有內容」，是後端一張卡片都不送。
    • p3 ［護理端］ 嘗試開啟「輪播第二層」。 → 被擋下，訊息「未符合開啟條件：尚無上架中的衛教或公告內容⋯⋯」。沒有內容卻開著，病人只會看到空白的輪播。

    6.2 · 第一層：閒置後自動開始（FR-P09）¶

    ⚠️ 這台平板必須已經填過一次症狀問卷，否則等到天亮也不會開始輪播。 本次綁定一次都沒回報過症狀時，後端判定問卷到期，輪播依 FR-P13 全面讓路 —— 平板會安安靜靜停在主畫面，沒有訊息、沒有錯誤，看起來就像壞了。 這是 §6.8 p26 要驗的設計，不是故障。剛指派好的平板直接等門檻，一定卡在這裡。

    • p4 ［護理端］ 開啟「輪播第一層」，理由欄填「迭代 6 驗收」。 → 第一層的開啟條件永遠成立（內容取自系統既有資料，不依賴外部）。
    • p64 ［病人端］ 先填一次透析前症狀問卷並送出（主手冊 d1–d4）。 → 回到主畫面，問卷按鈕副標變成「今天已送出 1 次」。這一步做完輪播才輪得到。
    • p5 ［病人端］ 放著不要碰，等超過門檻。 → 輪播自動蓋上來，第一張是「本次療程」，顯示開始時間、已進行、預計剩餘。
    • p6 ［病人端］ 等卡片自動換過一輪。 → 卡片依序換，左下角的圓點跟著移動。全程沒有任何聲音（把平板音量開到最大再測一次）。
    • p49 ［病人端］ 數一下第一層總共有幾種卡片。 → 三種：療程進度、今日已回報內容（送過問卷才有）、衛教完成度（讀過衛教內容才有）。三種都取自系統既有資料，不依賴任何外部來源。
    • p50 ［病人端］ 逐張看有沒有出現「還剩幾分鐘就結束」以外的判讀。 → 沒有。第一層只呈現事實與進度，不提醒、不建議、不預警 — 那些屬於迭代 7 的高風險功能。

    6.3 · 觸碰立即中止，沒有確認視窗（FR-P13）⚠️ 腳本驗不到¶

    • p7 ［病人端］ 輪播進行中，用手指碰畫面正中央（不是碰卡片）。 → 立刻回到主畫面。沒有「確定要離開嗎」之類的對話框，沒有動畫延遲。
    • p8 ［病人端］ 再等到輪播開始，這次碰畫面最邊角。 → 一樣立刻回到主畫面。任何一處都算。
    • p9 ［病人端］ 回到主畫面後不要動，等門檻時間。 → 輪播重新開始 — 中止不是關掉，是回到計時。

    6.4 · 求助按鈕位置與尺寸不變（FR-P13）⚠️ 腳本驗不到¶

    • p10 ［病人端］ 輪播開始前，記住「我需要協助」按鈕在畫面上的位置與大小（可以拍一張照）。
    • p11 ［病人端］ 等輪播開始。 → 那顆按鈕仍在原位、同樣大小，浮在輪播之上，其餘內容被蓋住。位置沒有位移、沒有縮小、沒有變成小圖示。
    • p12 ［病人端］ 輪播進行中直接按那顆按鈕。 → 直接進入求助畫面，不需要先退出輪播，也不會多一次點擊。
    • p13 ［護理端］ 確認那筆求助進到「緊急通報」。 → 與平常按下求助沒有任何差別。反應時間的量化比較由 verify:iteration6 步驟 11 每次執行時重測。

    6.5 · 細節頁與自動退回（FR-P10）⚠️ 腳本驗不到¶

    • p14 ［病人端］ 輪播進行中點卡片本身（不是卡片以外的地方）。 → 展開細節說明，輪播暫停不換卡（病人正在讀，換掉等於把字抽走）。
    • p15 ［病人端］ 放著不動，等超過「細節頁自動退回的時間」（預設 45 秒；照本冊開頭調成 15 秒的話等 15 秒）。 → 自動收合回卡片正面，輪播繼續。
    • p16 ［病人端］ 點一張沒有細節說明的卡片（例如只有一句話的公告）。 → 沒有反應，也不會出現「點一下看說明」的提示字。
    • p51 ［病人端］ 細節頁開著時，按「我需要協助」。 → 一樣直接進入求助畫面。細節頁不是另一層畫面，擋不住主線。

    6.6 · 第二層：靜態衛教與公告（FR-P11）¶

    • p17 ［護理端］ 進「輪播內容」，新增一則公告：標題、一句話、說明，排序 100，勾「啟用」。 → 清單出現該則，狀態「啟用」。
    • p18 ［護理端］ 回功能開關，開啟「輪播第二層」。 → 這次開得起來，開啟條件顯示「目前有 1 則在架上的衛教或公告」。
    • p19 ［病人端］ 等輪播開始。 → 剛才那則公告出現在輪播中，點開看得到說明。
    • p20 ［護理端］ 把那則公告「下架」。 → ［病人端］ 下一輪起不再出現（平板每分鐘重新取一次內容，或重新整理）。
    • p21 ［護理端］ 新增一則，上架時間設在一小時後。 → 現在不會播；清單上看得到，狀態欄顯示期間。

    6.7 · 第三層：臨床數值與資料時間（FR-P11）¶

    • p22 ［護理端］ 進「臨床數值」，為這位病人以人工輸入建立一筆乾體重。
    • p23 ［護理端］ 開啟「輪播第三層」。 → 開啟條件顯示「目前有 N 筆有效的院方臨床數值」。
    • p24 ［病人端］ 等輪播播到臨床數值卡片。 → 數值下方一定看得到「資料時間：⋯⋯」。病人看到三週前的體重卻以為是今天的，比看不到更糟。
    • p25 ［病人端］ 看完整輪輪播，逐張檢查。 → 沒有任何一張出現病人姓名或病歷號。卡片由後端組好再送到平板，這條規則只在一處判定。
    • p52 ［護理端］ 把那筆臨床數值覆蓋成新的值（保留前一版），回到平板等下一輪。 → 卡片顯示的是現行版本與它的資料時間，被覆蓋的舊值不會出現在病人面前。

    6.8 · 問卷優先於輪播（FR-P13）¶

    • p26 ［病人端］ 找一台還沒填過透析前問卷的已綁定平板，放著不動等門檻。 → 輪播不會開始 — 問卷到期時，問卷優先。
    • p27 ［病人端］ 填完問卷送出，再放著不動。 → 這次輪播開始，而且第一層多了一張「今天您回報的內容」。 → 等待時間就是閒置門檻本身（門檻調成 10 秒就是 10 秒）。平板在問卷送出的當下 重取一次輪播內容，不必等下一輪的定期輪詢。

    6.9 · 夜間模式 ⚠️ 腳本驗不到¶

    • p28 ［護理端］ 把「夜間模式起始時刻」改成現在這個小時、「結束時刻」改成兩小時後。
    • p29 ［病人端］ 重新整理後等輪播開始。 → 整體明顯調暗，但版面與字級不變（不是改成另一套畫面，只是不刺眼）。測完把兩個時刻改回 18 與 7。
    • p53 ［病人端］ 夜間模式下按「我需要協助」。 → 求助按鈕沒有跟著調暗到看不清楚，按下去的流程與白天完全相同。

    6.10 · Session 解除後，第三層數值不留在平板上（SRS 4.4）¶

    • p30 ［護理端］ 解除這台平板的綁定。
    • p31 ［病人端］ 平板回到中性等待畫面。用瀏覽器開發者工具看 localStorage。 → 沒有任何 hd.session. 開頭的鍵，輪播快取（含第三層的臨床數值）已隨之清除。
    • p32 ［病人端］ 放著不動等門檻。 → 等待畫面不會開始輪播。

    6.11 · 檔案匯入：全有或全無（FR-S05）¶

    • p33 ［護理端］ 進「臨床數值 → 匯入欄位對應」，記下「病歷號」「資料時間」「乾體重」三欄目前的名稱。
    • p34 ［終端機／試算表］ 做一份 Excel：第一列用上述欄位名稱，兩列資料，其中一列的乾體重故意漏打小數點（例如 625）。
    • p35 ［護理端］ 在「檔案匯入」上傳這份檔案。 → 紅色錯誤表格逐列列出問題，明確指出第 3 列的「乾體重」欄與原因。
    • p36 ［護理端］ 回到上方的數值清單。 → 一筆都沒有寫進去，包括格式正確的那一列。臨床數值只對一半，比完全沒有更危險。
    • p37 ［護理端］ 把那一列改成 62.5，重新上傳。 → 成功，顯示批次編號與寫入筆數。
    • p38 ［護理端］ 把同一份檔案再上傳一次（可以先改個檔名）。 → 被擋下：「同一份內容已於 ⋯⋯ 匯入過（批次 ⋯⋯）」。比對的是內容，不是檔名。
    • p39 ［護理端］ 上傳一份與既有資料同一病人、同一資料時間但數值不同的檔案。 → 被擋下並要求確認；勾選「覆蓋並保留前一版」後重送，成功，舊值在清單上標「已被覆蓋（保留前一版）」而不是消失。
    • p54 ［護理端］ 把同一份內容另存成 CSV 再上傳一次（先改一個數值避免撞到重複比對）。 → Excel 與 CSV 都吃得下，逐列檢查的規則完全相同。
    • p55 ［護理端］ 上傳一份查無病歷號的檔案。 → 逐列指出是哪一列的病歷號查不到；整批不寫入。
    • p56 ［護理端］ 看「最近的匯入批次」表。 → 每一批列出批次編號、來源、筆數、匯入時間與匯入者。人工輸入與檔案匯入寫進同一組資料表，來源欄分得出是哪一種。

    6.12 · 欄位對應可設定（Q-09）¶

    • p40 ［護理端］ 把「乾體重」的檔案欄位名稱改成 乾重(kg)，按儲存。
    • p41 ［護理端］ 上傳一份標頭寫 乾重(kg) 的檔案。 → 匯入成功。院方改了欄位名稱，改的是這一列設定，不是程式，也不必重新部署。
    • p42 ［護理端］ 再上傳一份標頭仍寫舊名稱的檔案。 → 被擋下：「標頭中找不到『乾重(kg)』這一欄⋯⋯」。舊名稱不會被默默接受。
    • p43 ［護理端］ 試著把「資料時間」的欄位名稱改成與「病歷號」相同。 → 被擋下：「⋯⋯已對應到『病歷號』，同一個檔案欄位不能同時對應兩種數值」。測完把名稱改回原值。
    • p57 ［護理端］ 看對應表的「是否必填」欄，試著停用「病歷號」那一列。 → 病歷號與資料時間標「必填」，停不掉；其餘標「選填」，停用之後檔案裡有那一欄也不會匯入該種數值。

    6.13 · 輪播內容管理與瀏覽事件¶

    • p44 ［護理端］ 進「輪播內容」下方的「最近 7 天的輪播瀏覽狀況」。 → 看得到哪一類卡片被播了幾次、平均停留多久、被點開幾次；表頭是層、卡片種類、播放次數、停留時間、點開細節次數。
    • p45 ［資料庫］ 開 Prisma Studio 看 carousel_view_events。 → 全表只有時間、層、卡片種類、停留毫秒、點開次數、是否夜間模式。 沒有病人、沒有綁定、沒有平板序號、沒有卡片內容 — 這張表回答的是「哪一類內容有人看」， 那個問題不需要知道是誰在看。
    • p59 ［護理端］ 在「輪播內容」新增第二則，種類選「靜態衛教」，排序填 10。 → 清單依排序由小到大排列，種類欄分得出「靜態衛教」與「中心公告」。
    • p60 ［護理端］ 編輯 p17 那一則的「一句話」，儲存。 → 清單即時更新；［病人端］ 下一輪起播的是新文字。
    • p61 ［護理端］ 新增一則只有標題與一句話、不填說明的內容。 → 存得起來；病人端播到它時點下去沒有細節頁（對應 p16）。
    • p62 ［護理端］ 以一般護理師 N001 進「輪播內容」與「系統管理 → 功能開關」。 → 輪播內容上得了架（衛教內容管理，護理師以上皆可）；功能開關看不到，輪播三層的開關要護理長以上。
    • p63 ［病人端］ 把第二層開關關掉後再等一輪。 → 第二層的卡片一張都不出現，但「輪播內容」清單上那幾則還在，開回來就照播。關開關不是刪內容。
