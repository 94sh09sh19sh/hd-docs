    迭代 17 手動測試 — 跑馬燈內容由 AI 生成、護理師核准¶

    《完整手動測試手冊》的分冊之一，對應《實作規格書》4.15 節。 共用的環境準備、啟動與疑難排解都在主手冊，這一冊只寫迭代 17 的部分。 操作端色籤（護理端／病人端／終端機／資料庫）的意思見主手冊 §00。 項次用 aa（單一字母到迭代 16 的 z 用完了，1005 起改兩個字母，迭代 16 用到 z43）。

    這一冊驗一句話：護理師不再寫衛教與公告，只核准 AI 生成的「標題：內容」；核准即上架，沒核准的病人端一個字也收不到。 標題 12 字、內容 60 字以內，超過的核准不了；「一句話」在兩端都不見了。院內還沒有 AI 時，衛教草稿隨版本帶入、公告由護理師在專業版寫，一樣要核准。 畫面規則的真本是《介面設計基準》3.5。

    標記 意思
    🖥 開發機 平常的開發環境，npm run dev；模型供應者用預設的模擬（LLM_PROVIDER=mock）即可
    🧪 實驗室模型 開發機的 .env 接實驗室的模型（第十三冊）。實驗室連得上時再做

    17.1 · 準備 🖥¶

    • aa1 ［終端機］ npm run dev。後端啟動時多一行「隨版本帶入的跑馬燈草稿已匯入 14 則」——只在第一次啟動時出現，之後重新啟動就沒有這一行。
    • aa2 ［護理端］ 專業版 → 系統管理 → 功能開關：「AI 輔助功能」關閉（正式環境的樣子）、「病人端跑馬燈」開啟（核准依據寫「手動測試」）。
    • aa3 ［病人端］ 病人端接上一次療程、在首頁。 → 跑馬燈整條不出現（還沒有任何一則核准過；1005 以前上架過內容的開發資料庫例外，那些遷移時一律算已核准、照播）。

    17.2 · 沒有 AI（驗收 6、7、8）🖥¶

    • aa4 ［護理端］ 專業版 → 跑馬燈內容。 → 上面寫「院內目前沒有 AI」，有一組「公告標題／公告內容／上下架時間」與「存成待核准」；沒有「要一份衛教草稿」「要一份公告草稿」。 → 「待核准」那一塊有 14 則衛教，七個主題各兩則，「從哪裡來」寫「隨版本帶入（主題：…）」，建立者「隨版本帶入」。
    • aa5 ［護理端］ 整頁找「一句話」三個字。 → 找不到。表單沒有「一句話」欄位，清單也不顯示（驗收 7）。
    • aa6 ［護理端］ 公告標題打 13 個字。 → 欄名旁的字數變成「13／12 字，超過」，存成待核准按不下去。刪到 12 字以內、內容打一句「10 月 10 日停診一天，當天的透析改到 10 月 9 日。」，按存成待核准。 → 出現在「待核准」，從哪裡來寫「護理師撰寫」；病人端沒有任何變化（驗收 1）。
    • aa7 ［護理端］ 在剛寫的那則按核准。 → 移到「已核准」，核准欄寫時間與你的帳號；病人端的跑馬燈在一分鐘內出現這一則（不碰平板；它每分鐘重取一次）。
    • aa8 ［護理端］ 在任一則「隨版本帶入」的草稿按核准。 → 一樣上架、病人端播得到（驗收 6：沒有 AI 也能核准、上架）。

    17.3 · 簡易版（驗收 1、2）🖥¶

    • aa9 ［護理端］ 切到簡易版，看右下的跑馬燈框。 → 框的上方是一張草稿卡：書本或喇叭的圖示，後面是整則「標題：內容」，字會換行、沒有省略號；旁邊一直排：一個數字（還有幾張在等）、✓、⊘。 → 下面一排是已核准的內容格子（aa7、aa8 那兩則）。 → AI 關閉時沒有「＋」。
    • aa10 ［護理端］ 按草稿卡上的 ✓。 → 草稿卡換成下一張；下面多一格剛核准的、帶「全部床位」圖示；畫面下方出現一條復原列「核准「…」→ 全部床位」。 → 病人端一分鐘內播得到它。
    • aa11 ［護理端］ 按復原列的復原。 → 那一則回到草稿卡（待核准）、從下面的格子消失；病人端下一次重取之後不再播它。
    • aa12 ［護理端］ 把草稿卡拖到某一床（病人端那台平板所在的床）。 → 核准；下面那一格沒有「全部床位」圖示、那一床的格子上多一個跑馬燈的數字。病人端播得到它；別床的平板播不到（有第二台時看）。
    • aa13 ［護理端］ 不拖曳：點一下草稿卡（框線加粗）、再點一床。 → 與 aa12 相同。
    • aa14 ［護理端］ 按草稿卡上的 ⊘（退回）。 → 草稿卡換成下一張；復原列「退回「…」」。按復原，那一則回來。
    • aa15 ［護理端］ 把待核准的都處理掉（核准或退回）。 → 草稿卡整塊消失，下面的格子往上長；框裡沒有空白的一塊。

    17.4 · 專業版（驗收 5、8）🖥¶

    • aa16 ［護理端］ 專業版 → 跑馬燈內容，在一則待核准的按修改後核准。 → 那一列展開成標題、內容（各帶字數）、上下架時間，「核准修改後的版本」與「取消修改」。
    • aa17 ［護理端］ 內容改到超過 60 字。 → 字數寫「…／60 字，超過」，核准修改後的版本按不下去（驗收 8）。
    • aa18 ［護理端］ 改回 60 字以內，標題也小改幾個字，下架時間設明天，按核准修改後的版本。 → 綠色訊息「…修改的地方已留稿」；「已核准」那一列的標題是改過的、上下架期間寫到明天。
    • aa19 ［護理端］ 在「已核准」那一列按上下架時間，清掉下架時間，按儲存時間。 → 期間回到「不限」。再按下架。 → 播放順序寫「已下架」、整列變淡；病人端下一次重取之後不再播它。按上架恢復。
    • aa20 ［護理端］ 退回一則。 → 出現在最下方「最近退回的…則」，退回時間與帳號都有。

    17.5 · 開啟 AI（驗收 1、2、4）🖥¶

    • aa21 ［護理端］ 系統管理把「AI 輔助功能」開啟，回到跑馬燈內容。 → 表單換成「衛教主題」下拉（第一項「由系統挑最久沒寫過的」，其餘是附錄 C.6 的七個主題）＋「要一份衛教草稿」，與「公告事由」＋「要一份公告草稿」；護理師寫公告的表單不見了。
    • aa22 ［護理端］ 按要一份衛教草稿（不選主題）。 → 「待核准」多一列「產生中」，幾秒後自己變成一則「標題：內容」，從哪裡來寫「AI 生成（主題：…）」——主題是七個之一（驗收 4）。 → 模擬供應者寫的內容開頭是「【模擬輸出】」。這一列待核准時，病人端沒有任何變化（驗收 1）。
    • aa23 ［護理端］ 公告事由打「10/10 停診」，按要一份公告草稿。 → 幾秒後出現一則公告草稿，從哪裡來寫「AI 生成（事由：10/10 停診）」。
    • aa24 ［護理端］ 簡易版：跑馬燈框的格子最前面多了一個「＋」。點它。 → 框上蓋一塊表單：書本（預設選著）、喇叭、＋、✕。直接按＋。 → 草稿卡位置先出現沙漏（AI 正在寫），三秒左右換成整則草稿。復原列「衛教草稿」，按復原那一份就被退掉。
    • aa25 ［護理端］ 簡易版點「＋」，選喇叭。 → 多一格「公告事由」；空著時＋按不下去。打一句事由，按＋。
    • aa26 ［護理端］ 把待核准的衛教草稿全部退回，只留最後一張；再退回那一張（驗收 2）。 → 退回之後沒有別的衛教草稿在等，系統自己要下一份：草稿卡先變沙漏、幾秒後換成新的一張，主題與剛才那張不同。

    17.6 · 稽核軌跡與 AI 呼叫紀錄（驗收 3、5）🖥¶

    • aa27 ［護理端］ 專業版 → 稽核軌跡，動作篩「核准跑馬燈內容（上架）」。 → 每一筆寫核准者、核准了哪一則、播放範圍、上下架時間、來源；aa18 那一筆另有「修改留稿：標題「…」→「…」；內容「…」→「…」」。
    • aa28 ［護理端］ 動作篩「匯入隨版本帶入的跑馬燈草稿」。 → 每一則一筆，寫「生成：開發端／模型 …／…（隨版本帶入 2026-10-05.1）」；另有一筆整批的；還有一筆「建立代表『隨版本帶入』的系統帳號」。
    • aa29 ［護理端］ 動作篩「跑馬燈內容草稿生成完成」。 → aa22～aa26 生成的每一則一筆，寫模型與「生成 N 次」（驗收 5：查得到生成的模型）。
    • aa30 ［護理端］ 系統管理 → AI 呼叫紀錄，看功能是「跑馬燈內容草稿」的幾筆。 → 資料類別都是「合成資料」、去識別化「否」（本來就沒有東西可以去識別）。
    • aa30a ［資料庫］ 看那幾筆的提示原文： SELECT prompt_text, patient_id FROM ai_invocations WHERE purpose = 'MARQUEE_CONTENT' ORDER BY invoked_at DESC LIMIT 5; → 提示只有「任務、主題、主題重點」或「任務、事由」與寫作要求；沒有任何病人的姓名、病歷號、症狀或背景；patient_id 是空的（驗收 3）。 逐筆比對全部病人的那一步由 verify:iteration17:api 第 8 步做。
    • aa31 ［護理端］ 帳號審核與帳號清單。 → 看不到「隨版本帶入」這個帳號（它登入不了，也不算人）。

    17.7 · 實驗室模型寫的草稿 🧪¶

    實驗室連得上時才做。連線資訊只放開發機的 .env，不進 repo（DEP-42）。

    • aa32 🧪 ［終端機］ 開發機 .env 接實驗室（第十三冊 Z-xx），npm run dev:api，系統管理開啟 AI。 執行 npm run marquee:bundle -- --per-topic 2。 → 每個主題印兩行 ✓「標題：內容」；最後寫「已寫入 N 則（版本 …）」。模型是模擬時腳本會拒絕執行。
    • aa33 🧪 ［終端機］ git diff apps/api/src/modules/carousel/marquee-bundle.ts，逐則讀過。 → generator 寫的是實驗室的供應者與模型，沒有任何位址或金鑰；每一則都是一般衛教，沒有具體數值目標（要寫的地方都是「請依醫療團隊的建議」）。 讀不下去的就刪掉那一則再 commit；這一份會隨版本進院，護理師核准前看到的就是這些字。

    17.8 · 自動化驗收 🖥¶

    • aa34 ［終端機］ npm run verify:iteration17（不需後端） → 8 個步驟全部通過：先改基準、病人端只收已核准的、沒有一句話、簡易版、專業版、生成只送主題或事由、隨版本帶入的草稿、Schema 只做加法與介面檢查。
    • aa35 ［終端機］ 後端開著（模型用模擬即可），npm run verify:iteration17:api → 9 個步驟全部通過。腳本會暫時關閉 AI、開啟跑馬燈、取消夜間時段，跑完全部改回；借來核准的那一則隨版本帶入草稿撤回成待核准。 隨版本帶入的草稿全部被核准或退回過時，腳本先把一則撤回成待核准來借，跑完還原成原本的狀態（終端機會印一行說借了哪一則）。
