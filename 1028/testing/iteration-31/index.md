# 迭代 31 手動測試 — 連點成畫之三：常模對照

> 《[完整手動測試手冊](https://94sh09sh19sh.github.io/hd-docs/1028/testing/manual-test-guide/index.md)》的分冊之一，對應《實作規格書》4.31 節。共用的環境準備、啟動與疑難排解都在主手冊，這一冊只寫迭代 31 的部分。設計與理由在《[透析中的遊戲化之五](https://94sh09sh19sh.github.io/hd-docs/1028/notes/dialysis-gamification-benchmark/index.md)》第 4、5、6.3 節；標準版本身在《[迭代 30 分冊](https://94sh09sh19sh.github.io/hd-docs/1028/testing/iteration-30/index.md)》，規則引擎與書面確認閘門在《[迭代 18 分冊](https://94sh09sh19sh.github.io/hd-docs/1028/testing/iteration-18/index.md)》。**這一項是高風險功能**：書面確認（清冊 Q-02）、常模來源（Q-40 第 1 題）與病人告知（Q-40 第 3 題）都還沒有，只對合成資料病人（病歷號 `HD-TEST-` 開頭）執行。

## 摘要

這一冊驗五件事（項次 `ao1`～`ao16`，自動化另跑 `npm run verify:iteration31` 與 `npm run verify:iteration31:api`）：

- 開關「連點成畫常模對照」在臨床判斷輔助那一組、預設關閉；「連點成畫」也開著才看得到
- 系統管理「判斷規則」多一條 NORM-TMTA-01：草稿、沒有出處、常模表是示範值；建版本時一行一組貼常模表，重疊、結論字眼、300 秒切點都擋下
- 病人趨勢「判斷輔助」那張卡：年齡、教育年數（在這裡登記）；最近一次標準版的一則常模對照，附施測條件、常模出處與「僅供參考，非診斷結果。」
- 真實病人：書面確認沒登記、或只有沒有出處的草稿時一律不比對
- 檢視與採納寫進稽核；病人端完全不變

| 🖥 **護理端** | 以系統管理者登入專業版；要「連點成畫」「連點成畫常模對照」兩個開關都開著                                                       |

## §31.1 開關與規則

- `ao1` **［護理端］** 🖥 系統管理 → 功能開關。 → 「臨床判斷輔助（開啟前需書面確認）」那一組多一列「連點成畫常模對照」，預設關閉；說明寫書面確認尚未登記、生效中 0 個、草稿 1 個；畫面上沒有識別字與需求編號。
- `ao2` **［護理端］** 兩個開關都關著時看病人趨勢。 → 「判斷輔助」那張卡不出現（其他四項也關著時）；只開「連點成畫常模對照」、不開「連點成畫」也一樣不出現。
- `ao3` **［護理端］** 系統管理 →「判斷規則」。 → 多一張卡「NORM-TMTA-01 連點成畫 A 部分的常模對照」：第 1 版草稿、門檻「前幾盤只當練習、不比對 10 盤」「最近一次標準版最多幾天內 35 天」、常模表 8 組（18～54 歲不分教育程度……85～110 歲）、書面依據出處「未附」、備註以「【合成資料示範用，不是常模】」開頭；沒有「標為生效」按鈕。說明那一句寫「五項判斷輔助」。
- `ao4` **［護理端］** 「以此版為底建立新版本」。 → 多一格「常模表」，一行一組（`18-54, 不分, 30.0, 10.0`）；出處那一格的說明改叫「常模出處」。把第 2 行改成 `55-70, 0-12, 36.0, 12.0`（與 65～74 歲重疊）送出。 → 擋下並寫哪兩組重疊；把某一行刪成三格 → 寫「第幾行要有四格」，沒有送出。
- `ao5` **［護理端］** 同一張表單，符合時的文字加「執行功能受損」或「超過 300 秒的切點」。 → 擋下（結論式的字、不引用切點）；🛠 稽核軌跡「判斷規則版本的變更遭拒」各一筆。

## §31.2 合成資料病人的一則常模對照

- `ao6` **［護理端］** 🖥 選單 →「病人趨勢」→ 選前置那位病人。 → 「判斷輔助」那張卡在「比對結果」上面多「連點成畫常模對照的分組」：年齡（依出生日期）、教育年數「未填」、一句說明、「登記教育年數」。沒有出生日期的病人寫「院方資料沒有出生日期，不比對」。
- `ao7` **［護理端］** 這位病人 55 歲以上時，先按「立即比對」。 → 沒有新的常模對照（那幾個年齡組分教育程度，教育年數沒填就不比）。
- `ao8` **［護理端］** 「登記教育年數」→ 填 31。 → 「儲存」按不下去；填 6 → 儲存，那一行變「教育年數：6 年」，底下一行寫誰、什麼時候登記；🛠 稽核軌跡「登記病人的教育年數」寫「未填 → 6 年」。
- `ao9` **［護理端］** 再按「立即比對」。 → 多一則，標籤「連點成畫常模對照」、「合成資料」、「待檢視」：「〇〇〇〇/〇〇/〇〇的標準版（透析開始後第 N 分鐘開始，平板、自製版面 A?）點完用了 X 秒，約在「65～74 歲、教育 0～12 年」紙本常模的第 P 百分位（該組平均…、標準差…，假設常態分布換算）。常模出處：未附書面出處（草稿，只對合成資料病人執行）；常模是紙本、不在透析中施測。」底下一條「僅供參考，非診斷結果。」；沒有紅色、沒有「疑似」「受損」「退化」、沒有 300 秒。
- `ao10` **［護理端］** 「看依據」。 → 常模表 8 組、三種偏差那一段（紙本、不在透析中；平板；方向相反、大小不明）、「常模出處（書面依據）」、引用的資料四列（標準版點完的時間、開始時是透析開始後第幾分鐘、那一天的年齡、教育年數）。
- `ao11` **［護理端］** 「已檢視・未採納」填原因送出。 → 標籤變「已檢視・未採納（你的名字）」，即時總覽的「判斷輔助：待檢視」少一則；🛠 稽核軌跡「檢視判斷輔助輸出」寫 NORM-TMTA-01 與未採納的原因。沒有其他動作（沒有通知、求助的順序不變）。
- `ao12` **［開發機→護理端］** 🛠 把一位病人的出生日期改成 16 歲，補一盤標準版後「立即比對」。 → 一則「……常模表裡沒有 16 歲（教育年數 未填）的組別，沒有對照。」，標「沒有對照（不必檢視）」、沒有檢視按鈕、不進待檢視。

## §31.3 真實病人擋下

- `ao13` **［護理端］** 🖥 對一位病歷號不是 `HD-TEST-` 開頭的病人（開發機用模擬院方資料的病人）登記教育年數、補一盤標準版，按「立即比對」。 → 錯誤訊息「書面確認尚未登記：判斷規則只對合成資料病人執行，這位病人不比對」；🛠 稽核軌跡「判斷規則比對遭擋下：真實病人」。
- `ao14` **［護理端］** 系統管理登記一個測試用的書面確認文號，再對同一位病人按「立即比對」。 → 沒有新的一則（常模表只有沒有出處的草稿）；🛠 稽核軌跡記下 NORM-TMTA-01 沒有生效中的版本。**做完一定要取消登記**（登記紀錄只增不改）。

## §31.4 版面與用字給人看

- `ao15` **［人］** 🖥 請護理師或醫師看 `ao9` 那一則與 `ao10` 的依據。 → 記下：讀得懂「第幾百分位」嗎、三種偏差那一段要不要更短、教育年數放在這張卡是否合適（院方要不要另一個地方登記）。

## §31.5 自動化驗收

- `ao16` **［開發機］** 🛠 跑 `npm run verify:iteration31`（不需要後端，八步：第五項與預設草稿、常模表的寫法與檢查、分組年齡與百分位、用字、閘門、護理端與病人端、遷移匯出與資料字典，加上介面檢查、零院外連線與迭代 18、18.1、30 的驗收）與 `npm run verify:iteration31:api`（要 Prisma，不需要開發機的後端，七步：預設草稿與 404、合成資料病人的一則、不比對的情形與「沒有對照」、真實病人的閘門與出處、稽核與定時比對、建版本的把關、「連點成畫」關著時不在）。 → 兩支都全部通過。
