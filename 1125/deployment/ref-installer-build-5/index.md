# 安裝包路線之五：建置與開發端彩排（R-13～R-24）

上層文件：[《安裝包路線（歷史）》](https://94sh09sh19sh.github.io/hd-docs/1125/deployment/ref-installer/index.md)　接在[《安裝包路線之四：建置與開發端彩排（R-06～R-12）》](https://94sh09sh19sh.github.io/hd-docs/1125/deployment/ref-installer-build-4/index.md)之後

> **狀態：歷史**（路線 0926 撤除），只當紀錄、不再照做，指令照抄跑不起來；現行部署照[《從零部署本系統》](https://94sh09sh19sh.github.io/hd-docs/1125/deployment/ref-fresh-install/index.md)。改寫來源見[之一](https://94sh09sh19sh.github.io/hd-docs/1125/deployment/ref-installer-build/index.md)開頭。編號：`R-xx`，沿用原編號。

## 摘要

- R4 安裝與啟動後半（接之四的 R-10～R-12）：R-13 從另一台機器連進來（最容易被跳過、也最會出事的一步）、R-14 權限反向測試、R-15 重新開機、R-16 在服務執行帳號底下確認時區與執行身分
- R5 功能面的冒煙測試：R-17 走一次主線、R-18 病人端斷網仍開得出畫面
- R6 更新與回退各做一次：R-19 停止服務並確認停乾淨、R-20 更新演練、R-21 回退演練
- R7 收尾：R-22 記下每一步花了多久、R-23 把結果寫進演練紀錄、R-24 留著這台機器
- R8 第二部的完成條件（整個第二部 R-01～R-23 的勾選清單）

## R4. 安裝與啟動（續）

### R-13 ⚠ 從另一台機器連進來（**最容易被跳過、也最會出事的一步**）

**做什麼**

用**另一台**電腦（不是主機本身）的瀏覽器開 `http://<主機 IP>:<NURSE_PORT>`，試著登入。

**怎麼知道成功了**

畫面出得來，**而且登得進去**。

**可能怎麼壞、怎麼處理**

| 症狀                             | 原因                                                               | 處置                                                                                                                                                  |
| -------------------------------- | ------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| 畫面出得來，但登入沒反應／一直轉 | **`VITE_API_BASE_URL` 是 localhost**，護理端在向那台電腦自己要資料 | 見 R-08 的警告框。要用院內主機位址重新產生安裝包                                                                                                      |
| 瀏覽器主控台出現 CORS 錯誤       | `.env` 的 `CORS_ORIGINS` 沒填院內位址                              | 補上護理端與病人端兩個來源，重新啟動服務                                                                                                              |
| 整個連不上                       | Windows 防火牆                                                     | 要開三個埠的輸入規則。在演練機上先練一次： `New-NetFirewallRule -DisplayName "HD API" -Direction Inbound -LocalPort <埠> -Protocol TCP -Action Allow` |
| 只有主機自己開得起來             | 同上                                                               | **院內的護理端是開在護理站的電腦上，不是主機上。主機自己開得起來完全不代表能用**                                                                      |

______________________________________________________________________

### R-14 權限反向測試

**做什麼**

用**一般登入者**的帳號（不是管理員、也不是 `svc-hdcare`）開啟 `D:\hd-data\`。

**怎麼知道成功了**

**拒絕存取。**

**可能怎麼壞、怎麼處理**

| 症狀                 | 處置                                                                                              |
| -------------------- | ------------------------------------------------------------------------------------------------- |
| 看得到裡面的檔案     | `-LockDownDataDir` 沒生效。重跑 R-11，或手動收權限：`icacls D:\hd-data /inheritance:r` 再逐一授權 |
| 沒有第二個帳號可以測 | 建一個臨時的：`net user tester <密碼> /add`。**測完刪掉**                                         |

______________________________________________________________________

### R-15 重新開機

**做什麼**

把機器重新啟動，**不要登入**，等兩分鐘，再登入查狀態。

**怎麼知道成功了**

`.\scripts\service-status.ps1` 顯示 Running、3 個行程、存活檢查 200。

**可能怎麼壞、怎麼處理**

| 症狀           | 原因                                               | 處置                                                                              |
| -------------- | -------------------------------------------------- | --------------------------------------------------------------------------------- |
| 服務沒起來     | 排程工作的觸發條件是「開機時」，但帳號密碼可能失效 | 到工作排程器看「上次執行結果」。常見原因是服務帳號沒有「以批次工作登入」的權限    |
| 要登入才會起來 | 註冊時的設定不對                                   | 重跑 R-11                                                                         |
| 起來了但連不上 | 開機時另一個專案先佔走了埠                         | **這正是 DEP-37 第 2 項在講的事**，而且它只會在重新開機時發作。記下來，回報資訊室 |

______________________________________________________________________

### R-16 在服務執行帳號底下確認時區與執行身分

**做什麼**

護理端 → 系統管理 → 維運狀態。

**怎麼知道成功了**

四件事都對：

| 看什麼             | 應該是                                                       |
| ------------------ | ------------------------------------------------------------ |
| 伺服器時區         | `Asia/Taipei`                                                |
| **執行身分**       | `svc-hdcare`，**不是你現在登入的帳號**                       |
| 連接埠             | 你在 `.env` 填的那個，且標示為「來自主機設定」而非程式預設值 |
| 資料庫磁碟可用空間 | 綠的，高於 `DB_DISK_MIN_FREE_MB`                             |

> **主機時區正確，不代表服務執行帳號取得的時區正確**（DEP-15）。這一頁是唯一看得到後者的地方。

## R5. 功能面的冒煙測試

### R-17 走一次主線

**做什麼**

照《[完整手動測試手冊](https://94sh09sh19sh.github.io/hd-docs/1125/testing/manual-test-guide/index.md)》§02 冒煙測試與 §03 主線 A：登入 → 改密碼 → 建病人 → 建排班 → 指派平板 → 病人端顯示 → 解除綁定 → 稽核查得到。

**怎麼知道成功了**

每一步都如手冊所述。**這一段走不完，就不要進醫院。**

**可能怎麼壞、怎麼處理**

| 症狀                       | 原因                       | 處置                                                                       |
| -------------------------- | -------------------------- | -------------------------------------------------------------------------- |
| 登入頁出得來但沒有任何帳號 | `SUPER_ADMIN_*` 沒填       | 補進 `.env`，重新啟動服務。**資料庫不必重建**                              |
| 平板端顯示「裝置尚未佈建」 | 正常。那是給佈建用的畫面   | 在護理端「新增裝置」（1007 以前叫裝置管理）註冊一台，拿到金鑰再連          |
| 某個功能整個不見           | 首波功能開關關閉（DEP-29） | **這是正確行為**：關閉的功能連後端端點一起擋下，不以灰色按鈕呈現（DEP-34） |

### R-18 病人端斷網仍開得出畫面

**做什麼**

用另一台裝置開病人端、等畫面出來之後，**把那台裝置的網路斷掉**，重新整理。

**怎麼知道成功了**

畫面照樣出得來；求助區在原來的位置、原來的大小，**而且明確顯示現在通知不到護理師**。

**可能怎麼壞、怎麼處理**

| 症狀                           | 原因                      | 處置                                                                                                                                                                                                                |
| ------------------------------ | ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 斷網後一片空白                 | Service Worker 沒註冊成功 | 看 [P-04](https://94sh09sh19sh.github.io/hd-docs/1125/deployment/ref-installer-build/#p-04-%E5%BB%BA%E7%BD%AE%E4%B8%89%E5%80%8B%E7%94%A2%E7%89%A9)：產物裡有沒有 `sw.js`。**這一條不成立，選 PWA 的唯一理由就沒了** |
| 求助按鈕按得下去但沒有任何提示 | 離線狀態沒顯示            | 記成缺陷。**能按而沒有回應是最糟的那一種**                                                                                                                                                                          |

詳細項次見[迭代 10 分冊](https://94sh09sh19sh.github.io/hd-docs/1125/testing/iteration-10/index.md) `t16`–`t22`。

## R6. 更新與回退，在這台機器上各做一次

### R-19 停止服務並確認停乾淨

**做什麼**

```
.\scripts\service-stop.ps1
.\scripts\service-status.ps1
```

**怎麼知道成功了**

行程數 **0**。

**為什麼要確認「都」停了**：剩下任何一個還開著資料庫檔案，接下來的備份就是在一個還在被寫入的檔案上做的（DEP-10）。

______________________________________________________________________

### R-20 更新演練

**做什麼**

用一個新版本的安裝包（可以只是把 [P-06](https://94sh09sh19sh.github.io/hd-docs/1125/deployment/ref-installer-build/#p-06-%E5%BB%BA%E7%BD%AE%E5%AE%89%E8%A3%9D%E5%8C%85) 再跑一次），照這七步：

| 順序 | 動作                         | 跳過會怎樣                               |
| ---- | ---------------------------- | ---------------------------------------- |
| 1    | 停止服務                     | 資料庫還有寫入時做的備份不可靠           |
| 2    | 備份，**並驗證它還原得起來** | 「有備份」和「備份能用」是兩件事         |
| 3    | **舊版目錄改名，不要刪**     | 沒有可以退回去的東西                     |
| 4    | 解壓新版到新目錄             |                                          |
| 5    | 套用遷移（R-10 那一支）      |                                          |
| 6    | 啟動，確認主線功能           |                                          |
| 7    | 寫進更新紀錄                 | 半年後沒有人答得出資料是哪一次更新弄壞的 |

**可能怎麼壞、怎麼處理**

| 症狀                     | 處置                                                                                  |
| ------------------------ | ------------------------------------------------------------------------------------- |
| 想直接把舊目錄刪掉再解壓 | **不要。** 第 3 步是回退唯一的依靠                                                    |
| 新版的 `.env` 要重寫嗎   | 不用。`.env` 在安裝包目錄之外，整包換掉也不會被蓋掉——**這正是 DEP-08 那條界線的用處** |

______________________________________________________________________

### R-21 回退演練

**做什麼**

把 R-20 那次更新前的備份還原到另一個檔案，再把舊版目錄換回來。

**怎麼知道成功了**

雜湊相符、完整性檢查 ok、筆數與更新前一致；還原出來的那份**沒有**這次遷移新增的欄位。

> **程式可以退版，資料庫不行退版。** 動過 schema 的版本要回退，是**還原備份再換回舊版程式**，不是把遷移倒回去。

## R7. 收尾

### R-22 記下每一步花了多久

**做什麼**

填這張表。它是你在院內的時間預算，也是回答「大概要多久」時唯一誠實的依據。

| 步驟           | 演練耗時 | 院內預估（×1.5） |
| -------------- | -------- | ---------------- |
| 解壓           |          |                  |
| 核對雜湊       |          |                  |
| 驗收五項       |          |                  |
| 建 `.env`      |          |                  |
| 套用遷移       |          |                  |
| 註冊服務並啟動 |          |                  |
| 冒煙測試       |          |                  |
| **合計**       |          |                  |

> **×1.5 不是保守，是經驗值**：現場有人在旁邊、鍵盤不順手、權限要等人、還會被問問題。

### R-24 留著這台機器

**不要急著把它刪掉。** 它之後還有三個用處：

1. 下一次更新之前，先在這裡演練一次
1. 現場遇到怪問題時，回來這裡重現
1. 交接給別人時，讓對方在這裡練一次，而不是在院內練

## R8. 第二部的完成條件

- `R-01` 機器確定是乾淨的（`node -v` 失敗）
