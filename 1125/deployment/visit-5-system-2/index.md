## 4. 啟用讀檔、首波上線

### SY-08 密碼移交、建帳號

**做什麼**：

1. 護理長在護理站的電腦用管理者登入，**自己改掉管理者密碼**；開發端從此不知道
1. 用管理者替護理長與首波護理師各建一個帳號，請他們各自登入一次、改掉臨時密碼
1. 🏥 平板 PIN 交給護理長

🧪 第 1 項自己改；第 2 項建一個測試護理師帳號、登入一次。

**成功**：稽核軌跡查得到改密碼與建帳號。

### SY-09 啟用前再確認一次

四條**全部**成立才往下，有一條不成立就停在這裡（B 級），跳到 SY-13：

| #   | 條件                                                                               | 🧪 開發機                |
| --- | ---------------------------------------------------------------------------------- | ------------------------ |
| 1   | SY-03 有結論：排除已加，或沒加（出現現象再加，1116 定）                            | 寫「院內要問」，照樣往下 |
| 2   | 病人告知有答案（涵蓋，或已補公告）                                                 | 同上                     |
| 3   | 《任務一》AF-11 三輪都成功                                                         | 《任務一》的 🧪 做過就算 |
| 4   | 「院方床位轉床號的方式」是 `0`；首波還沒開始用（透析時段也可以，DEP-32 1116 例外） | 只看前半                 |

> 🏥 **一啟用，當天清單上所有病人的主檔與療程都會進主機**，護理端會看到整個透析室，不是只有首波那一位。先讓首波護理師知道。

### SY-10 接上院方資料、讀檔檢查

**🏥 只做 A。🧪 不做 A，改做 B1、B2。** 兩邊都是改 `.env` 的同五行（`HD_DIALYSIS_LIST_DIR`、`HD_LAB_DIR`、`COMPOSE_FILE`、`HOSPITAL_API_BASE_URL`、`HD_SIMULATION_DEPLOYMENT`），各自改成下面方框的樣子；其他行不動。

讀檔檢查（A、B1、B2 都用這一條）：

```
docker compose --env-file $cfg exec -T api node apps/api/dist/hospital-api-probe.js
```

#### A（🏥）接上抓取腳本的資料夾

1. `notepad $cfg`，五行改成這樣（`COMPOSE_FILE` 開頭沒有 `#`，後面**沒有** `;docker-compose.lab-files.yml`；路徑照寫、不加引號；院內 `.env` 本來就沒有後兩行的話不用補）：

```
HD_DIALYSIS_LIST_DIR=C:\API_Fetch\IDH_interface
HD_LAB_DIR=
COMPOSE_FILE=docker-compose.yml;docker-compose.dialysis-files.yml
HOSPITAL_API_BASE_URL=
HD_SIMULATION_DEPLOYMENT=
```

1. `docker compose --env-file $cfg up -d`，再跑讀檔檢查

**成功**：標題「院方資料讀檔檢查（只讀、只印結構……）」；「透析清單資料夾」寫「在、讀得到」「唯讀：是」「**模擬標記檔：沒有**」；狀態檔「讀得到」、結果「成功」；有當天段落數與列數；「檢驗資料資料夾」沒有設定是正常的。**整段抄進紀錄**（工具不印路徑、姓名、病歷號）。日誌有「院方資料同步已啟用（讀透析清單資料夾）」。

#### B1（🧪）接上模擬院方資料

1. `notepad $cfg`，五行改成這樣：

```
HD_DIALYSIS_LIST_DIR=
HD_LAB_DIR=
COMPOSE_FILE=docker-compose.yml;docker-compose.hospital-files-sim.yml
HOSPITAL_API_BASE_URL=
HD_SIMULATION_DEPLOYMENT=yes
```

1. `docker compose --env-file $cfg --profile simulation up -d`，等 3 分鐘，再跑讀檔檢查

**成功**：「模擬標記檔：有」（模擬是對的）。

#### B2（🧪）練院內那種掛法：路徑帶空白與中文

1. 把模擬的檔複製一份出來：

```
New-Item -ItemType Directory -Force "C:\hd-sim\院方 資料" | Out-Null
docker compose --env-file $cfg cp api:/hospital-sim/dialysis-list "C:\hd-sim\院方 資料\透析清單"
```

1. `notepad $cfg`，五行改成這樣（跟 A 一樣的掛法，只是路徑換成上面那個、`HD_SIMULATION_DEPLOYMENT` 留 `yes`）：

```
HD_DIALYSIS_LIST_DIR=C:\hd-sim\院方 資料\透析清單
HD_LAB_DIR=
COMPOSE_FILE=docker-compose.yml;docker-compose.dialysis-files.yml
HOSPITAL_API_BASE_URL=
HD_SIMULATION_DEPLOYMENT=yes
```

1. `docker compose --env-file $cfg up -d`，再跑讀檔檢查

**成功**：「在、讀得到」「唯讀：是」「模擬標記檔：有」。這份是複製出來的、不會再更新，之後出現「未更新」提示是正常的。

### SY-11 第一輪怎麼驗

**做什麼**（護理站的電腦；🧪 手機）：

1. 系統管理 →「院方資料同步」卡：「資料來源：抓取腳本的檔」「每 3 分鐘讀一次」「抓取腳本最近一輪：成功」。按「立即同步」，卡片上方出現綠色的「已同步：N 次透析……」或「已重讀：內容與上一次相同，沒有要寫入的」，下面表格最上面多一列「成功」（內容沒變的會標「內容沒變」）。兩種都算成功。🧪 B2 的資料夾不會再變，一定是「內容沒變」
1. 對數字（不抄病人的值）：
1. 透析次數：卡片表格「透析次數」那一欄，跟 SY-10 讀檔檢查的當天段落數、列數差不多
1. 床號：系統管理 →「床位清單」卡，院方資料出現的床號會自動加在最後面，是 `A1`～`E9` 這種字母開頭（`1A`～`3D` 與 `99` 原樣出現，不要改設定）。簡易版只顯示平板編號與病人姓名，看不到床號
1. 療程：切到專業版，首頁「即時總覽（日期）」列出今天的療程。🏥 問護理師「現在在透析的有幾床、今天排了幾床」，跟即時總覽對得上
1. 系統管理 → 稽核軌跡，看有沒有動作是「院方資料格式不符，該次透析未寫入」的紀錄（卡片表格的「格式不符」欄也是這個數）。🏥 應該沒有；有的話抄原因（不含病歷號）。🧪 每一輪都會有 1 筆，是模擬資料故意放的壞資料（模擬辛），正常
1. 等 3 分鐘，卡片表格最上面一列的時間往前跳

**成功**：四項都對。🏥 卡片最上面**沒有**「目前接的是模擬院方 API」；床號或療程對不上就照《[讀檔：啟用、檢查、停用](https://94sh09sh19sh.github.io/hd-docs/1125/deployment/ref-dialysis-files/index.md)》停用，記下實況（B 級）。🧪 **有**這一行才對，簡易版的病人是模擬甲、模擬乙……這些虛構病人（沒有模擬辛）。

### SY-12 平板帶回指定的床

**做什麼**：

1. 🏥 `TB-00` 放到指定的床、插電（不必重新註冊）。🧪 用開發端佈建好的那台
1. 護理端「新增裝置」看得到它、「固定中」、外殼版本正常
1. 🏥 Wi-Fi 實測：床邊與透析區另一頭都開得到等待畫面
1. 功能開關把「本次透析」面板開啟（SY-11 四項都對了才開；沒啟用讀檔就維持關，這一步只看平板固定）
1. 在護理端把平板指派給一位病人（🏥 首波那一床；🧪 一位模擬病人）→ 療程進行中面板有數字。🏥 跟著真實療程，等不到就留到第一個班次

**成功**：平板顯示病人端首頁、本次透析面板有數字；護理端看得到平板在那一床。🏥 Wi-Fi 不通：護理端照用、病人端不開，寫進交接紙。

## 5. 收尾

### SY-13 冒煙測試

**不輸入任何真實病人資料、不開任何功能開關。** 在護理站的電腦（🧪 手機）：

| #   | 做什麼                                        | 應該是                                       |
| --- | --------------------------------------------- | -------------------------------------------- |
| 1   | 用護理長的帳號（🧪 測試護理師）登入           | 登得進去，預設開「簡易版」                   |
| 2   | 簡易版、專業版切換一次                        | 兩邊都開得起來                               |
| 3   | 系統管理 → 備份歷程                           | 有 SY-06 那一份                              |
| 4   | 「院方資料同步」卡                            | 啟用了：最近一輪成功；沒啟用：還沒設定資料夾 |
| 5   | 稽核軌跡                                      | 查得到今天的改密碼、建帳號、備份、版本更新   |
| 6   | 🏥 總覽螢幕：在護理長指定的那台開護理端總覽   | 開得起來、不休眠                             |
| 7   | SY-07 的紅框                                  | 看過就打勾；沒做寫「未驗」                   |
| 8   | 平板                                          | 在指定的床、「固定中」                       |
| 9   | 🏥 磁碟門檻：跟資訊室議定剩多少就通知、誰監看 | 寫進交接紙（開發端建議剩 50 GB）             |

**成功**：每一列打勾，或寫明為什麼沒做。

### SY-14 交接

**做什麼**：🏥 填好《[交接紙](https://94sh09sh19sh.github.io/hd-docs/1125/deployment/ref-status-handover/index.md)》，當場講一次、讓對方自己做一次「啟停」與「斷電之後」，交給護理長與資訊室各一份。

🧪 不交接，但把交接紙從頭到尾讀一遍，看不懂的圈起來。

**成功**：🏥 護理長與資訊室各拿到一份、各自做過一次。🧪 圈起來的地方都記下來（SY-M4 第 11 項）。

### SY-15 離院前、第一個班次（🏥）

**做什麼**：

1. 開發端**留到第一個班次結束**：「院方資料同步」卡每 3 分鐘有新的一列、平板面板有更新
1. PowerShell 關掉、瀏覽器登出；手機裡含院內資料的照片移進私人 repo 後刪掉
1. 當天晚上補完紀錄，照詳細版 SY-15 寫離院紀錄

**成功**：第一個班次結束時同步卡仍每 3 分鐘更新；主機上沒有開著的 PowerShell 與登入中的瀏覽器；紀錄寫好。

## 6. 🧪 開發機才做：驗收與判定

### SY-M1 驗院內的設定擋得住模擬，再停用讀檔

**做什麼**：`notepad $cfg`，`HD_SIMULATION_DEPLOYMENT` 清空（等號後面什麼都不留），然後 `docker compose --env-file $cfg up -d api`，等一輪（3 分鐘）看「院方資料同步」卡。接著照《[讀檔：啟用、檢查、停用](https://94sh09sh19sh.github.io/hd-docs/1125/deployment/ref-dialysis-files/index.md)》停用讀檔。最後 `HD_SIMULATION_DEPLOYMENT` 改回 `yes`，`docker compose --env-file $cfg up -d`。

**成功**：卡片最新一列是「拒收（正式環境收到模擬資料）」、資料庫一筆都沒多；停用後卡片回到還沒設定資料夾。

### SY-M2 跑三支驗收

**做什麼**：在**平常寫程式的工作目錄**（不是 `C:\hd-sim\repo`）：

```
git switch --detach <新 tag>
npm run verify:iteration11 -- --live --env-file C:\hd-sim\config\.env
npm run verify:iteration12 -- --live --env-file C:\hd-sim\config\.env
npm run verify:iteration13 -- --live --env-file C:\hd-sim\config\.env
git switch master
```

**成功**：三支都全部 ✓。第一支會 `down -v` 再 `up -d`，是刻意的（驗資料卷不會被刪）。

### SY-M3 退回 `v0.4.0` 演練

**做什麼**：照《[本系統換版與退回](https://94sh09sh19sh.github.io/hd-docs/1125/deployment/ref-upgrade/index.md)》真的退一次，`<備份檔名>`、`<雜湊>` 用 SY-04 抄的。

**成功**：`完整性檢查：ok`；三個服務是 `hd-tablet-care:v0.4.0`；手機重開分頁後登得進去。SY-04 之後註冊或建的東西不見了，是對的。
