# 平板與外殼 App（第 2 份，Y-09～Y-15）

上層文件：[《平板與外殼 App》](https://94sh09sh19sh.github.io/hd-docs/1125/deployment/ref-tablet/index.md)

> **狀態：現行**（常備參考）。改寫來源見[第 1 份](https://94sh09sh19sh.github.io/hd-docs/1125/deployment/ref-tablet/index.md)開頭。編號：`Y-xx`（外殼 App 與平板佈建），沿用原編號。

## 摘要

- 平板每台一次：護理端註冊（QR code 只顯示一次）、系統設定、下載頁安裝、掃 QR code 佈建、釘住、護理端核對（Y-09～Y-13）；已佈建的平板出問題時照第 5 節重新佈建，**不要原廠重設**
- 換外殼版本是開發端的事，院內重建 APK 後平板逐台覆蓋安裝；只改網頁不必動平板（Y-14、Y-15）
- 金鑰每年核對一次備份；資料卷壞了從備份還原，**不要重新產生**（第 7 節）
- 開發機實測（第 8 節，DEP-22）：`shell-builder` 從零建出 APK、金鑰備份核對、開發手機從下載頁安裝並釘住、護理端 30 秒內看得到、`verify:iteration12` 驗收
- 外殼與平板特有的疑難排解（第 9 節）：建置久停、平板「網頁無法使用」、按求助沒反應、外殼版本未回報或不相容、面板沒數字
- 主機這一層（Y-01～Y-08）在第 1 份；平板盤點、採購與到貨後（`K-xx`）在[第 3 份](https://94sh09sh19sh.github.io/hd-docs/1125/deployment/ref-tablet-3/index.md)

## 4. 平板（每台各做一次）

照《部署規範》8.2。**首波只佈建實際會用到的兩三台**（DEP-36）；院內現況只有一台暫用平板（第 0.1 節）。

### Y-09 在護理端註冊平板

護理端 → **新增裝置**（1007 以前叫裝置管理） → **註冊新平板**。畫面出現**佈建 QR code** 與文字網址（迭代 14.1 起）， **兩者只顯示一次**：這個畫面先不要關，拿著平板照 Y-10～Y-12 做完、掃完再離開。平板沒有相機、或這一頁非關不可時，才把序號與金鑰抄在佈建單上，佈建完就銷毀那張單子。顯示的網址要以 `https://` 開頭（🏥 `https://<IP>:18081`）；不是的話回 Y-03（外殼會拒收 `http://` 的 QR code），改好後 `up -d api` 再重新註冊。

序號建議與床號對應（例如 `TB-01` 對 1 號床），英數字與連字號，3–32 字元；暫用平板是 `TB-00`。

### Y-10 平板的系統設定

1. 設定裝置 PIN（**護理師才知道的那一組**），關閉「新增使用者」。🏥 暫用平板（One UI 5.1.1）的設定裡**找不到**「關閉新增使用者」（1029），找不到就跳過：平板只有一個使用者，解除螢幕固定要 PIN，佈建不受影響
1. 設定 → 安全性 → 螢幕固定：開啟，勾選「解除固定前要求 PIN」。🏥 One UI 5.1.1 的路徑是：設定 → 安全性與隱私權 → 其他安全性設定 → 釘選應用程式
1. 允許瀏覽器安裝不明來源的應用程式（安裝時系統會問）
1. 🏥 字型大小：系統預設不是 1.0 時，WebView 會跟著放大字，病人端可能被撐破。暫用平板是 1.1，醫師答覆維持 1.1、1029 看過等待畫面沒有被截斷；要調回就到「設定 → 顯示螢幕 → 字體大小與樣式 → 字型大小」（《[暫用平板](https://94sh09sh19sh.github.io/hd-docs/1125/notes/interim-tablet/index.md)》第 3 節）

### Y-11 從下載頁安裝

平板的瀏覽器開 `http://<主機>:<病人端埠>/shell/`（🏥 `http://<IP>:18081/shell/`），按「下載 App」，安裝。

| 症狀                                     | 處置                                                               |
| ---------------------------------------- | ------------------------------------------------------------------ |
| 「應用程式未安裝」「套件與現有套件衝突」 | 這台平板裝過**另一把金鑰簽的版本**（例如開發用的）。先解除安裝再裝 |
| 「應用程式未安裝」，而且沒裝過           | 版本往下覆蓋，或下載不完整。重新下載一次                           |

### Y-12 首次啟動與釘選

1. 開啟「透析照護平板」，按「**掃描 QR code**」（外殼 0.3.0 起），允許相機，對準 Y-09 畫面上的 QR code（🏥 暫用平板第一次開 App 會先跳三星的全螢幕手勢提示，按「確定」）。三欄一次填好，**核對序號與這台平板的標籤一致**（沒貼就現在貼一張，寫序號）。沒有相機時照舊手動輸入：主機位址填 `https://<主機>:<病人端埠>` （與 `MDM_KIOSK_BASE_URL` 相同），序號與金鑰填 Y-09 的
1. 按「儲存並啟動」，系統跳出「要固定這個應用程式嗎」，按「確定」

**怎麼知道成功了**：畫面是病人端的等待畫面，橫的，沒有任何憑證警告；按上一頁、首頁、多工鍵都離不開。

| 症狀                                            | 處置                                                                                                                                                                                        |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 「主機位址要以 https:// 開頭」                  | 照填                                                                                                                                                                                        |
| 掃了 QR code 出現「主機位址不是 https:// 開頭」 | `MDM_KIOSK_BASE_URL` 還是 `http://`。回 Y-03 改好，重新註冊這一台（舊的那張 QR code 已經不能用）                                                                                            |
| 掃了 QR code 出現「這不是平板佈建用的 QR code」 | 掃到別的東西了。對準 Y-09 畫面上那一張                                                                                                                                                      |
| 佈建畫面沒有「掃描 QR code」                    | 裝的是 0.3.0 以前的外殼。手動輸入照樣可以；要掃描就照 Y-14 換成 0.3.0（重建 `shell-builder` 映像檔，Y-04、Y-05）再從下載頁重裝                                                              |
| 一片空白或「網頁無法使用」                      | 位址打錯、或 Y-07 沒做。到系統設定 → 應用程式 → 透析照護平板 → 儲存空間 → **清除資料**，重新填                                                                                              |
| 有憑證警告                                      | 主機位址跟伺服器憑證不符（🏥 `<IP>` 跟憑證對不上）。打電話給開發端；位址換過的話照[《護理站登不進去與主機位址》](https://94sh09sh19sh.github.io/hd-docs/1125/deployment/ref-login/index.md) |
| 畫面上方出現琥珀色提示列「……版本不相容」        | 下載頁上的 APK 與系統的契約版本對不上。見第 6 節；抄下原文回開發端，平板先解除固定、交給護理長保管                                                                                          |

### Y-13 核對護理端

護理端 → 新增裝置，15～30 秒內：

| 欄位     | 應該是                   |
| -------- | ------------------------ |
| 固定狀態 | 固定中                   |
| 外殼版本 | 版本正常，底下一行版本號 |

把序號與床號的對應記下來。**解除一次固定**（輸入 PIN），30 秒內護理端要變成「已跳出」。

**釘回去**：解鎖後 App 還停在畫面上，但已經沒有釘住，直接點它沒用。按多工鍵把「透析照護平板」**從多工畫面滑掉**，再從桌面開啟，系統再問一次「要固定這個應用程式嗎」，按「確定」。護理端 15～30 秒內回到「固定中」（1029 暫用平板量到約 11 秒）。沒跳出確認框就重新開機，App 開機後會自己起來並詢問。

## 5. 平板要重新佈建時（已經佈建過的平板）

`TB-00` 1029 已佈建過，正常不必做。護理端看不到平板或「已跳出」，先在平板上把 App 從多工畫面滑掉、從桌面重開，系統問要不要固定選「確定」；仍不行、或出現空白頁、或固定不回來，才做這一節。要 1 小時左右，時間不夠就交接寫「平板未佈建」。

1. 平板：**不要原廠重設**（會把 WebView 退回 2023 年的出廠版本，院內沒辦法再更新）。設定 → 應用程式 → 透析照護平板 → 儲存空間 → 清除資料
1. 護理站的電腦：護理端 → **新增裝置** → **註冊新平板**。畫面出現佈建 QR code 與一行網址，**只顯示一次**，做完第 4 步再關。網址要以 `https://<IP>:18081` 開頭，不是的話 `.env` 的 `MDM_KIOSK_BASE_URL` 不對
1. App 不見了才要重裝：平板瀏覽器開 `http://<IP>:18081/shell/` →「下載 App」→ 安裝（允許瀏覽器安裝不明來源的 App）。「套件與現有套件衝突」是裝過開發版，先解除安裝再裝；「應用程式未安裝」是下載不完整，重下載
1. 開「透析照護平板」→「掃描 QR code」→ 允許相機 → 對準 QR code（第一次開會先跳三星的手勢提示，按「確定」）→ 核對序號與平板背面的標籤 →「儲存並啟動」→ 系統問要不要固定 →「確定」
1. 護理端「新增裝置」等 15～30 秒，變成「固定中」。釘選要 PIN：設定 → 安全性與隱私權 → 其他安全性設定 → 釘選應用程式，勾「解除固定前要求 PIN」（One UI 5.1.1 的路徑）

「主機位址不是 https:// 開頭」：回第 2 步看網址。平板畫面要是橫的、沒有任何憑證警告；有憑證警告就是 `<IP>` 跟憑證不符，打電話給開發端。

## 6. 換外殼版本、調高最低可用版本

### Y-14 換外殼版本（改 APK 的時候）

外殼改版是**開發端**的事：外殼 repo 打新 tag，本系統的 `shell.pin` 改成它，本系統打新 tag。主機上：

```
git -C $root\hd-kiosk-shell fetch --tags
# 本系統照《本系統換版與退回》換到新 tag（shell.pin 跟著換）
docker compose --env-file $cfg --profile shell build shell-builder
docker compose --env-file $cfg --profile shell run --rm shell-builder
```

本系統換版的步驟在[《本系統換版與退回》](https://94sh09sh19sh.github.io/hd-docs/1125/deployment/ref-upgrade/index.md)（W-19）。下載頁換成新版之後，**平板要逐台重新安裝**（覆蓋安裝即可，序號與金鑰會留著）。排在非透析時段（DEP-32）。 **只改網頁不必做這一段**——那是絕大多數的更新，平板下次載入就是新版。換版前先看新 tag 的 `shell.pin` 有沒有變；沒變就不必做（`v0.3.0` 到 `v0.5.0` 都沒變）。

### Y-15 調高最低可用版本

所有平板都換上新版之後，把舊版標成「外殼過舊」，下次有人沒換到就看得出來：

```
notepad $cfg          # KIOSK_SHELL_MIN_VERSION=<新版本>
docker compose --env-file $cfg up -d api
```

**不必重建映像檔。** 護理端「新增裝置」的平板清單 15 秒內就會標出版本低於它的平板。

## 7. 金鑰：每年一次，以及遺失時

| 什麼時候                   | 做什麼                                                                                                                                                                                                                                                               |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 每年                       | `keys-verify <那一份備份的檔名>`，對院內另一台機器上取回的那一份做（DEP-35）；不給檔名就核對最新的一份                                                                                                                                                               |
| 伺服器憑證快到期（825 天） | 直接再跑 Y-05，它會自己重新簽，然後 Y-07                                                                                                                                                                                                                             |
| 主機位址換了               | 同上：Y-05 發現位址變了會重簽伺服器憑證，然後 Y-07、Y-06 重新備份；CA 沒變，平板不必重裝，但 `MDM_KIOSK_BASE_URL` 變了平板要重新佈建（第 5 節）。完整步驟在[《護理站登不進去與主機位址》](https://94sh09sh19sh.github.io/hd-docs/1125/deployment/ref-login/index.md) |
| 金鑰資料卷壞了或被刪了     | **不要重新產生**。`docker volume create hd-tablet-care-keys` 建一個空的，再 `docker compose --env-file $cfg --profile shell run --rm shell-builder keys-restore hd-keys-<時間>.tar.gz`（只准還原到沒有金鑰的資料卷，還原完自動核對），然後 Y-05、Y-07                |
| 備份也沒了                 | CA 與簽章金鑰都補不回來：重新產生、**每一台平板解除安裝後重裝**。這就是 DEP-35 說的「遺失即無法補救」                                                                                                                                                                |

## 8. 開發機實測（DEP-22）

照[《從零部署本系統之二：容器路線的原冊》](https://94sh09sh19sh.github.io/hd-docs/1125/deployment/ref-fresh-install-detail-2/index.md)第 7 節那一輪，加上這一份：

| #   | 驗什麼                                                            | 步驟                                               |
| --- | ----------------------------------------------------------------- | -------------------------------------------------- |
| 1   | `shell-builder` 從零建出 APK，第二次不重新產生金鑰                | Y-04～Y-05                                         |
| 2   | 金鑰備份並核對                                                    | Y-06                                               |
| 3   | 開發手機從下載頁安裝、輸入序號與金鑰、釘住                        | Y-09～Y-12                                         |
| 4   | 手機跳出螢幕固定，護理端 30 秒內看得到                            | Y-13                                               |
| 5   | `npm run verify:iteration12 -- --live --env-file <設定目錄>\.env` | 唯一允許用 Node 的一步，**它是驗收，不是部署步驟** |

🧪 開發機上 `HD_SHELL_SIGNING=dev`、`MDM_KIOSK_BASE_URL` 用開發機的區網 IP（手機要連得到，`localhost` 不行）。手機上的每一項見[迭代 12 測試分冊](https://94sh09sh19sh.github.io/hd-docs/1125/testing/iteration-12/index.md) §12.5～§12.7。

## 9. 疑難排解（外殼與平板特有的）

| 症狀                                                  | 原因                                                   | 處置                                                                                                          |
| ----------------------------------------------------- | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------- |
| `shell-builder` 建置很久停在 `gradle` 或 `sdkmanager` | 第一次要下載約 1.5 GB                                  | 等。之後改版只重跑外殼那幾層，快很多                                                                          |
| 平板顯示「網頁無法使用」，主機的瀏覽器開得了          | 平板連不到主機，或 `MDM_KIOSK_BASE_URL` 是 `localhost` | Y-08；位址改成平板連得到的那一個，重跑 Y-05（憑證會重新簽）與 Y-07，平板清除資料重新佈建（第 5 節）           |
| 平板上病人端載入了，但按求助沒反應                    | `/api/` 轉送不通                                       | `docker compose --env-file $cfg logs patient-web`，看有沒有「/api/ 轉送至 http://api:3000」；`api` 有沒有在跑 |
| 護理端「外殼版本」一直是「未回報版本」                | 平板上裝的是迭代 12 之前的外殼，或用瀏覽器開的         | 從下載頁重裝                                                                                                  |
| 護理端「版本不相容」                                  | 平板的外殼與系統的契約版本不同                         | 從下載頁重裝目前這一版                                                                                        |
| 平板面板一直沒數字                                    | 療程還沒開始                                           | 🏥 等真實療程，等不到留到第一個班次                                                                           |

上線當天在護理端驗平板時的處置（看不到平板、空白頁、琥珀色提示、Wi-Fi）也在[《第五次進院任務二之二：詳細版》](https://94sh09sh19sh.github.io/hd-docs/1125/deployment/visit-5-system-detail-2/index.md) SY-12；現場其他症狀見[《現場疑難排解》](https://94sh09sh19sh.github.io/hd-docs/1125/deployment/ref-troubleshooting/index.md)。
