## 7. 驗證

### H-16 冒煙測試

**做什麼**

在護理站的電腦上走一次主線：登入 → 強制改密碼 → 建病人 → 建排班 → 指派平板 → 解除綁定 → 稽核查得到。

**怎麼知道成功了**

每一步都如《[完整手動測試手冊](https://94sh09sh19sh.github.io/hd-docs/1125/testing/manual-test-guide/index.md)》§02、§03 所述。

**可能怎麼壞、怎麼處理**

| 症狀                         | 處置                                                                                                                   |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 沒有任何帳號可登入           | `SUPER_ADMIN_*` 沒填。補進 `.env` 重新啟動，**資料庫不必重建**                                                         |
| 建病人時猶豫要不要用真實資料 | **首波試用可以用真實病人資料**（這是正式環境），但今天的測試資料要用虛構的，並在交接時說明哪幾筆是測試資料、誰負責清掉 |
| 某個功能不見了               | 首波功能開關關閉（DEP-29），**正確行為**                                                                               |

🧪 彩排對應 R-17（多一步「病人端顯示」）與 R-18（病人端斷網仍開得出畫面）。

### H-17 備份與還原實測（**這一條最常被跳過**）

**做什麼**

1. 執行一次備份到指定的備份目錄
1. **把它還原到另一個檔案，確認還原得起來**
1. 確認備份的最終落點是**院內另一台機器**（DEP-06）

**怎麼知道成功了**

還原後雜湊相符、完整性檢查 ok、筆數對得上。

**可能怎麼壞、怎麼處理**

| 症狀                     | 處置                                                                                 |
| ------------------------ | ------------------------------------------------------------------------------------ |
| 備份目錄寫不進去         | 權限或路徑。**現在不修，第一次要用備份的時候才發現就來不及了**                       |
| 沒有第二台機器可以放備份 | 記下來，並明講：**同一台機器上的兩顆磁碟不是備援**，整機故障或被勒索軟體加密時一起沒 |
| 「之後再設定備份」       | **不要接受。** 沒有備份的系統不該開始收病人資料                                      |

🧪 彩排對應 R-19～R-21（停服務、更新、回退各做一次）。容器路線：D-23 做了還原驗證，真的還原一次見《git clone＋Docker 路線詳細版》第 10 節。

### H-18 常駐總覽螢幕（FR-N12）

**做什麼**

在指定位置的螢幕上開啟護理端總覽，確認它**不會進入休眠**。

**可能怎麼壞、怎麼處理**

| 症狀           | 處置                                                    |
| -------------- | ------------------------------------------------------- |
| 螢幕還沒到位   | 記下位置與硬體需求（Q-10），列入帶回情報                |
| 螢幕會自己暗掉 | 調整該台電腦的電源設定                                  |
| 總覽顯示斷線   | 看 SSE 心跳。超過約兩倍心跳沒收到訊息就會判定斷線並重連 |

### H-19 平板（**這次多半跳過**）

平板到位且 APK 備妥時，照 K-10～K-16（側載 K-12 在《[安裝包路線](https://94sh09sh19sh.github.io/hd-docs/1125/deployment/ref-installer-2/index.md)》，其餘佈建步驟在《[平板與外殼 App](https://94sh09sh19sh.github.io/hd-docs/1125/deployment/ref-tablet-3/index.md)》），**只佈建兩三台**。

沒到位的話，這一段改成情報蒐集（平板還沒到時要問的，《[平板與外殼 App](https://94sh09sh19sh.github.io/hd-docs/1125/deployment/ref-tablet/index.md)》），並**用手機在每個床位測一次 Wi-Fi 訊號**——這件事不需要平板就能做，而且非到現場不可。

現行的外殼 App 建置與平板安裝在《[平板與外殼 App](https://94sh09sh19sh.github.io/hd-docs/1125/deployment/ref-tablet/index.md)》（0927 起）。

## 8. 交接

### H-20 現場教學

| 教誰       | 時間    | 講什麼                                                         |
| ---------- | ------- | -------------------------------------------------------------- |
| 護理長     | 10 分鐘 | 怎麼登入、怎麼建帳號與審核、哪些功能首波是關的、出事找誰       |
| 值班護理師 | 5 分鐘  | 總覽怎麼看、求助怎麼處理、平板怎麼指派與解除綁定               |
| 資訊室     | 5 分鐘  | 服務在工作排程器的哪裡、怎麼啟停、紀錄檔在哪、重開機後怎麼確認 |

**講完要當場讓對方自己做一次。** 「聽懂了」和「做得出來」是兩件事。

### H-21 交接文件

**當場寫、當場交**，至少包含：

| 項次           | 內容                                        |
| -------------- | ------------------------------------------- |
| 安裝位置       | 安裝包目錄、資料庫目錄、備份目錄            |
| 服務           | 排程工作名稱、執行帳號、啟停腳本位置        |
| 連接埠         | 三個埠與登記狀況                            |
| 帳號           | 初始管理員工作 ID（**密碼由院方自行變更**） |
| 首波關閉的功能 | 哪些、為什麼、什麼時候開                    |
| 環境設定       | 防毒排除、休眠、更新時段**分別是誰設的**    |
| 聯絡方式       | 出事找誰、怎麼找                            |
| **已知限制**   | 平板尚未佈建、AI 功能關閉、成效基準尚未量測 |

**「首波試用、不是全單位上線」這句話要寫在第一行**（DEP-33）。

容器路線多寫四件事：clone 目錄的位置、映像檔標籤、`docker-users` 名單、重新開機後的啟動方式（D-27）。

## 9. 離院前

### H-22 收尾清單（離院前 30 分鐘，**一定要留這段時間**）

- 服務是啟動的，狀態檢查過
- 護理站電腦上實際登入過
- 備份做過一次並還原成功
- 《部署規範》第 9 章那 26 條**每一條都有結果**（通過／未通過／不適用，不要留空白）
- 交接文件已交付並有人簽收
- H-04 的問題清單**每一題都有答案**（答不出來的要寫「未答覆」與對方是誰）
- 筆記本上的每一頁都有時間與步驟編號
- 沒有任何病人資料被寫在筆記本上

容器路線再加五條，在《git clone＋Docker 路線詳細版》第 12 節。

### H-23 清除隨身碟（DEP-28）

**做什麼**

當場格式化隨身碟，在部署紀錄寫明「已清除」、時間與執行者。

**可能怎麼壞、怎麼處理**

| 症狀                           | 處置                                                                            |
| ------------------------------ | ------------------------------------------------------------------------------- |
| 想把紀錄檔拷出來「回去慢慢看」 | **不行。** 不是備份、不是紀錄檔、不是截圖。要帶的資訊用手抄，而且不得含病人資料 |
| 想留著安裝包「以防下次要用」   | 開發機上有一模一樣的一份，雜湊值也在交付單上                                    |
| 忘了清除就離開                 | 回去補不了。**所以它要排在離院前 30 分鐘那段，不是最後一分鐘**                  |

### H-24 當天晚上就寫紀錄

**做什麼**

回到開發機，把筆記本上的東西**當天**打進《[部署演練紀錄](https://94sh09sh19sh.github.io/hd-docs/1125/notes/deployment-drills/index.md)》：

| 節         | 填什麼                                         |
| ---------- | ---------------------------------------------- |
| §1.3       | 路線 A 的失敗紀錄（H-08）                      |
| §2.3       | 路線 B：兩次掃描、雜湊核對、隨身碟清除、總耗時 |
| §3.2       | 乾淨機器啟動測試（若院內那台就是）             |
| §4.2／§5.2 | 更新與回退（這次若有做）                       |
| §6.1       | 平板佈建（若有）                               |

**為什麼是當天**：隔一天你會記得「大概三點多的時候遇到一個錯誤」，而**紀錄要的是錯誤原文與確切耗時**。那些東西今晚還在你腦子裡，明天就不在了。

🧪 彩排對應 R-22（每一步耗時，院內預估 ×1.5）與 R-23（演練紀錄 §3.2）。0922 實際：錯誤原文與耗時都沒記到（《第一次進院紀錄》1.2）。

## 10. 隨時可以停手

《[進院通則](https://94sh09sh19sh.github.io/hd-docs/1125/deployment/ref-visit-rules/index.md)》列的當場停手情形，任何一種出現就停。停手時做三件事：**把服務停掉**（《[備份、還原與關服務](https://94sh09sh19sh.github.io/hd-docs/1125/deployment/ref-backup-shutdown/index.md)》，做到「停用」）、**把現況寫進紀錄**、**當場講清楚下一次需要什麼**。

**不要留一個「好像可以用」的狀態給別人。** 半成品比沒有東西更糟：護理師會開始用它，然後把問題當成系統的正常行為。
