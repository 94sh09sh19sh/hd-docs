## 1. 現場除錯的四個原則

1. **先確認它在哪一層壞掉。** 由下往上問：機器活著嗎 → 服務在嗎 → 後端回不回應 → 瀏覽器連得到嗎。**從最底下開始問，不要從畫面開始猜。** 容器路線多一層：機器活著 → **Docker Desktop 在跑嗎** → 容器 `Up` 嗎 → health → 瀏覽器
1. **一次只改一件事。** 同時改三個設定再重新啟動，好了也不知道是哪一個
1. **錯誤訊息抄原文。** 你要帶回去的是原文，不是「它說連不上」
1. **不要為了讓它動起來而破壞前提。** 開對外連線、關防毒、用管理員帳號跑服務——這三件事當下都會「解決問題」，而代價要到幾個月後才付。容器路線再加兩件：手動開一個容器把整顆磁碟掛進去（0922 第一次進院就是這樣，《[第一次進院紀錄（0922）](https://94sh09sh19sh.github.io/hd-docs/1125/deployment/record-1-0922/index.md)》F-01、F-02）、在主機上改 compose 檔

**五秒鐘的分層檢查**

容器路線（先輸入開工三行，見《[從零部署本系統](https://94sh09sh19sh.github.io/hd-docs/1125/deployment/ref-fresh-install-3/index.md)》V-09）：

```
docker ps --format "{{.Names}}  {{.Image}}  {{.Status}}"
curl.exe -s http://localhost:13000/api/health
```

第一條印 `failed to connect to the docker API at npipe:…` 是 Docker Desktop 沒在跑（開始選單開啟，等左下角變綠）；有服務不是 `Up` 就看 `docker compose --env-file $cfg logs <服務> --tail 30`；health 應該是 `{"status":"ok",…}`。

安裝包（歷史）：

```
.\scripts\service-status.ps1                       # 行程幾個？存活檢查幾號？
curl.exe -i http://localhost:<API_PORT>/api/health  # 後端本身活著嗎
```

## B. 服務起不來

### X-05 `service-install.ps1` 說要系統管理員身分

|              |                                                                                                                                                                                                                                                                     |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **處置**     | 以系統管理員身分重新開啟 PowerShell。註冊排程工作與改目錄權限都需要它                                                                                                                                                                                               |
| **容器路線** | ✗ 不適用（沒有 `service-install.ps1`）。容器路線要系統管理員身分的是看防毒排除（`Get-MpPreference`，`Must be an administrator to view exclusions`）；開法：開始 → 打 `powershell` → `Ctrl+Shift+Enter`。1116 院內是一般身分的 PowerShell，`docker compose` 照樣能用 |

### X-06 PowerShell 執行原則擋下 `.ps1`

|              |                                                                                                                                                                                         |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **你會看到** | 「因為這個系統上已停用指令碼執行」                                                                                                                                                      |
| **處置**     | `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass`（只影響目前這個工作階段）。**先問過資訊室**                                                                                |
| **容器路線** | 本系統的步驟不跑 `.ps1`，✗ 不適用。院方 API 抓取腳本的排程是另一回事，見《[院方 API 抓取腳本的維運](https://94sh09sh19sh.github.io/hd-docs/1125/deployment/ref-fetch-script/index.md)》 |

### X-07 註冊時說「資料目錄不得位於安裝包目錄之內」

|                            |                                                                                                                                                        |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **這是正確行為**（DEP-08） | 換一個安裝包目錄之外的路徑                                                                                                                             |
| **為什麼擋**               | 某一次「把舊資料夾整個刪掉再解壓新版」會把資料庫一起刪掉                                                                                               |
| **容器路線**               | 同一個原則換了形式：資料庫只放具名資料卷（DEP-23）、`.env` 放在 clone 目錄外的 `config\`（DEP-08），「整個刪掉重新 clone」不會帶走它們。沒有這一條訊息 |

### X-08 排程工作是 Running，但行程數 0

|              |                                                                                                                                                                                                                                           |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **可能原因** | 啟動器一起來就死了，多半是 `.env` 有問題                                                                                                                                                                                                  |
| **先查**     | 用前景跑一次，直接看錯誤：`.\runtime\node.exe .\scripts\run-all.mjs`                                                                                                                                                                      |
| **常見**     | `.env` 找不到（位置錯）、`API_PORT` 沒填、`DATABASE_URL` 是相對路徑、`PRISMA_ENGINES_DIR` 指錯                                                                                                                                            |
| **容器路線** | 對應的症狀是 `api` 一直 `Restarting`：`docker compose --env-file $cfg logs api --tail 30` 最後幾行會說是哪一條設定被拒（時區、連接埠、`lab`…），照訊息改 `.env` 再 `up -d`。`.env` 找不到是 `couldn't find env file`（`$cfg` 沒設或打錯） |

### X-09 只有 1 或 2 個行程

|              |                                                                                                                                     |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------- |
| **設計上**   | 任何一個倒下就三個一起停——**壞掉要壞得看得出來**                                                                                    |
| **處置**     | 看到 1～2 個多半是正在收尾。等幾秒再查一次；還在的話看紀錄檔找真正的錯                                                              |
| **容器路線** | ✗ 不適用：三個服務各自一個容器，各自重新啟動（`restart: unless-stopped`），不會一起停。`docker ps` 看哪一個不是 `Up`，看它的 `logs` |

### X-10 後端拒絕啟動，說時區不符

|                            |                                                                                                                                                                                                                                                                      |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **這是正確行為**（DEP-15） | 主機時區必須是 Asia/Taipei                                                                                                                                                                                                                                           |
| **處置**                   | `Set-TimeZone -Id "Taipei Standard Time"`，重新啟動服務                                                                                                                                                                                                              |
| **注意**                   | 主機時區對，不代表**服務執行帳號**取得的時區對。要從護理端「維運狀態」那一頁確認                                                                                                                                                                                     |
| **容器路線**               | 時區由 compose 的 `TZ: Asia/Taipei` 寫死，主機時區不影響後端。看到「時區…不是正式環境要求的 Asia/Taipei」是 compose 檔的 `TZ` 被改過：還原 compose 檔，不在主機上改，要改回開發端改、打新 tag。日誌的「伺服器時區」不是 `Asia/Taipei` 時不要自己改主機時區，找資訊室 |

### X-11 重新開機後服務沒起來

|              |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **先查**     | 工作排程器 →「上次執行結果」                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| **常見原因** | 服務帳號密碼已變更或到期；帳號缺「以批次工作登入」的權限；開機時埠被別的專案先佔走                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| **處置**     | 密碼問題請資訊室處理；埠被佔就換一個並重新登記                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| **記下來**   | 這一類問題**只在重新開機時發作**，測試階段一次都不會出現                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| **容器路線** | 仍然只在重新開機時發作，原因換了：Docker Desktop 是隨使用者登入啟動的程式，**沒人登入 Windows，容器就不會起來**（院方答覆：斷電後由護理長以平常的帳號重新登入）。1116 模擬實測：Quit Docker Desktop 再開，容器全是 `Exited`、沒有自己回來（`unless-stopped` 把它們當成手動停的）；院內真的重開機會不會一樣還沒驗過（1116 沒做重新開機）。處置：記下 Docker Desktop 有沒有隨登入起來、「Start Docker Desktop when you sign in」有沒有勾；手動開 Docker Desktop、等變綠、`docker compose --env-file $cfg up -d`。**不要改院方的登入或開機設定**，寫進交接的已知限制，交資訊室決定。下一個 tag 預定改 compose 的 `restart`。步驟見《[從零部署本系統之二：容器路線的原冊](https://94sh09sh19sh.github.io/hd-docs/1125/deployment/ref-fresh-install-detail-2/index.md)》W-18 |

## C. 資料庫

### X-12 `Error code 14: Unable to open the database file`

|              |                                                                                                                                                                                                                                                                                  |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **可能原因** | 目錄不存在；服務帳號沒有寫入權限；路徑打錯                                                                                                                                                                                                                                       |
| **處置**     | 先手動建出目錄，確認 `icacls <目錄>` 裡有服務帳號的修改權限                                                                                                                                                                                                                      |
| **容器路線** | 訊息一樣、原因不同：資料卷不是由 compose 掛上，或手動開的容器以 root 建了檔。只用手冊的指令；手動開過的容器全部刪掉，重新 `up -d`（《[從零部署本系統之二：容器路線的原冊](https://94sh09sh19sh.github.io/hd-docs/1125/deployment/ref-fresh-install-detail-2/index.md)》第 9 節） |

### X-13 後端拒絕啟動，說資料庫路徑在共用位置

|                                    |                                                                                                                                                                                                                                                                                                                                                 |
| ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **這是正確行為**（DEP-37 第 3 項） | 暫存、公用、桌面、文件、下載都會被擋                                                                                                                                                                                                                                                                                                            |
| **處置**                           | 換到本系統自己的路徑，例如 `D:\hd-data\`                                                                                                                                                                                                                                                                                                        |
| **容器路線**                       | 資料庫固定在容器裡的 `/data/hd.db`（資料卷），不會出這一條。同類的位置檢查還在：`db-update` 對備份目錄（不得是相對路徑、網路路徑、專案目錄內、雲端同步資料夾、共用目錄），資料取出對匯出目錄（不在網路磁碟、雲端同步資料夾，與備份目錄分開，見《[取出資料](https://94sh09sh19sh.github.io/hd-docs/1125/deployment/ref-data-export/index.md)》） |

### X-14 `database is locked`

|                         |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **可能原因**            | 服務還在跑（有行程開著資料庫）；防毒即時掃描；有人用其他工具開著同一個檔案                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| **先查**                | `.\scripts\service-status.ps1` 行程數是不是 0                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| **處置**                | 停服務再操作。**若停了還是鎖著，九成是防毒**——那就是 H-14 第 1 項沒做                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| **特徵**                | 這一類錯誤**間歇性、不固定重現**，是最難查的一種。不要花時間猜，直接去看排除清單                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| **容器路線（1116 補）** | 上面是安裝包時代的判斷。容器路線的資料庫在 Docker 的虛擬磁碟裡（`ext4.vhdx`），Defender 只看得到那一整個檔、看不到 SQLite 的檔，「九成是防毒」不成立（照架構推的，沒在開著即時掃描的主機上實測過）。**先看有沒有換版、還原或資料取出的一次性容器還在跑**：`docker compose --env-file $cfg ps -a`。防毒沒排除時的現象見《[第五次進院（1116）任務二 · 本系統換版上線之一：詳細版](https://94sh09sh19sh.github.io/hd-docs/1125/deployment/visit-5-system-detail/index.md)》SY-03；1116 起的決定是不加也能跑、出現現象再請資訊室加 |

### X-15 資料庫檔案不見了

|              |                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **可能原因** | 更新時把整個安裝包目錄刪掉，而資料庫放在裡面（DEP-08 要擋的正是這件事）                                                                                                                                                                                                                                                                                                                                                                     |
| **處置**     | 從備份還原。**這就是為什麼備份的第二落點必須在另一台機器上**                                                                                                                                                                                                                                                                                                                                                                                |
| **容器路線** | 資料卷 `hd-tablet-care-data` 標成 external，compose 不會建立它、`docker compose down -v` 也刪不掉；會不見只有人下了 `docker volume rm`。`db-update` 遇到時會說「DATABASE_URL 指向的資料庫檔案不存在，這不是一次更新，是一次全新安裝」。**停手**，`docker volume ls --filter name=hd-tablet-care` 抄下來；從備份還原照《[備份、還原與關服務](https://94sh09sh19sh.github.io/hd-docs/1125/deployment/ref-backup-shutdown/index.md)》第 1.3 節 |

### X-16 磁碟快滿，更新在備份之前就停下

|                                           |                                                                                                                                                                                                                                                                                              |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **這是正確行為**（`DB_DISK_MIN_FREE_MB`） | 備份做到一半才寫滿，等於在最需要備份的時候沒有備份                                                                                                                                                                                                                                           |
| **處置**                                  | 清出空間再做。同時查清楚是誰把磁碟寫滿的——這台機器是共用的                                                                                                                                                                                                                                   |
| **容器路線**                              | ✓ 適用。訊息是 `更新中止：備份目的地可用空間 … MB，不足以完成這次更新。需要 … MB＝備份與驗證複本各一份（資料庫 … MB ×2）＋保留下限 … MB`；預設下限 1024 MB。不要自己刪別人的東西，問資訊室（DEP-37）。1116 時 C 槽剩約 754 GB；磁碟門檻與監看人還沒跟資訊室議定（開發端建議剩 50 GB 就通知） |

### X-17 `-wal` 與 `-shm` 檔要不要一起處理

|                  |                                                                                                                                                                                                                                                                  |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
